# 新規プロジェクトの作成（vs new）

:::{.chapter-lead}
本章では、`vs new` のオプション、生成されるディレクトリ、プロジェクト名の規則を説明します。最初の一冊を作るときは、必要な項目だけを参照してください。
:::

## 基本的な使い方

:::{.section-lead}
プロジェクト名を指定して `vs new` を実行すると、書籍情報を対話形式で入力できます。
:::

```bash
vs new mybook
```

実行すると、次の質問が順に表示されます。何も入力せずに Enter を押すと、既定値を使います。

```
Vivlio Starter へようこそ！新しい書籍プロジェクトを作成します。

書籍名を入力してください（例: はじめての技術書づくり）: はじめての技術書づくり
副題を入力してください（任意。Enter でスキップ）:
著者名を入力してください（原稿を書いた人。例: 早乙女 遙香）: 早乙女 遙香
発行者・サークル名を入力してください（本を世に出す主体。お一人なら著者と同じでも可。例: アトリヱ未來）: アトリヱ未來

以下の設定でプロジェクトを作成します。

  プロジェクト名: mybook
  書籍名:         はじめての技術書づくり
  副題:           （なし）
  著者:           早乙女 遙香
  発行者:         アトリヱ未來

よろしいですか？ [Y/n]:
```

確認で Enter（または `Y`）を押すとプロジェクトを作成し、`n` を入力すると中断します。

:::{.column}
**著者と発行者の違い**

- **著者** — 原稿を書いた人（執筆者）。奥付の著者欄と著作権表示（&copy; …）に使われます。
- **発行者** — その本を世に出す主体（刊行の責任者）。商業出版なら出版社、同人・自費出版ならサークル名や屋号にあたります。

一人で発行する場合は、著者と発行者を同じ名前にできます。「著者＝本名・ペンネーム、発行者＝サークル名」のように分けることもできます。印刷を依頼する印刷所は、発行者には当たりません。
:::

## 生成されるプロジェクトの構成

`vs new mybook` を実行すると、次のディレクトリ構造が生成されます。

```
mybook/
  contents/       ← 原稿（Markdown ファイル）
  images/         ← 画像ファイル
  covers/         ← 表紙・裏表紙用の画像ファイル
  data/           ← 本文へ展開するデータ（YAML 形式）
  templates/      ← 章の雛形とデータ展開テンプレート
  sources/        ← 執筆資料や PDF ファイル置き場
  codes/          ← 本文へ取り込むサンプルコード
  stylesheets/    ← CSS スタイルシート
  config/         ← 各種設定ファイル
    book.yml      ← 書籍の設定
    catalog.yml   ← 章構成
    scaffold.lock ← 雛形マニフェスト（自動生成）
  README.md
  Gemfile
  package.json
  .gitignore
```

入力した書籍名と著者名は `config/book.yml` に書き込まれます。後から `book.yml` を直接編集して変更できます。

`config/scaffold.lock` は、展開した雛形の内容を記録する自動生成ファイルです。`vs upgrade` はこのファイルを使い、著者が変更したファイルか、雛形のままのファイルかを判定します。手で編集せず、Git にはコミットしてください。

## 各ディレクトリの役割

:::{.section-lead}
各ディレクトリの役割を説明します。すべてを最初に使う必要はありません。各ディレクトリには `_README.md` があり、必要になったときに詳しい説明を確認できます。本書の後半でも、それぞれの機能を扱います。
:::

### contents/

書籍の本文となる Markdown ファイルを置くディレクトリです。ファイル名は `NN-slug.md` 形式（例: `01-quickstart.md`）で、先頭の数字が章の並び順を決めます。

| 範囲 | 用途 |
|------|------|
| `00` | 前書き・はじめに |
| `01-89` | 通常の章 |
| `90-98` | 付録 |
| `99` | 後書き・おわりに |

```bash
vs create 11-intro     # 章ファイルと画像ディレクトリを生成
vs delete 11-intro     # 章を削除
vs rename 11 12        # 章番号を変更
vs renumber            # 章番号を一括で整列
```

ビルド対象になるのは、`config/catalog.yml` に登録した章だけです。`catalog.yml` は本の**目次（章立て）を定義するファイル**で、ファイル、順番、部への配置を指定します。登録していない Markdown はビルド・lint・metrics の対象外になるため、下書きや退避用のファイルも `contents/` に置けます。

`catalog.yml` には `PREFACE`（前書き）、`CHAPTERS`（本文）、`APPENDICES`（付録）、`POSTFACE`（後書き）の四つの欄があります。各章は、拡張子 `.md` を除いたファイル名で登録します。`CHAPTERS` の下に末尾が半角コロン `:` のタイトルを置くと、配下の章が一つの「部」となり、部扉ページが生成されます。

```yaml
PREFACE:
  - 00-preface

CHAPTERS:
  - 第一部 はじめる:        # 末尾の「:」で「部」になる
      - 11-workflow
      - 12-quickstart
  - 第二部 書く:
      - 21-markdown-tutorial

APPENDICES:
  - 91-install

POSTFACE:
  - 99-postface
```

通常は手で編集する必要はありません。`vs create` / `vs delete` / `vs rename` で章を操作すると、`catalog.yml` も更新されます。章の順番や部の名称を変えるときは、直接編集できます。

### images/

書籍で使う画像ファイルを置くディレクトリです。章ごとにサブディレクトリを作って管理します。`vs create` で章を作ると、対応する画像ディレクトリも生成されます。

原稿で使う画像には `.webp` 形式を推奨します。PNG/JPG は `vs resize` で WebP へ変換できます。`vs build` の実行時にも WebP へ変換されます。

```bash
vs resize              # images/ 全体を標準品質で WebP 変換
vs resize --high       # 高品質で変換（quality=90）
```

### covers/

書籍の表紙・裏表紙に使う画像を置くディレクトリです。`vs cover` または `vs build` で生成されます。

`config/book.yml` の `output.cover` でテーマ名を指定します。`light` / `dark` には gem 同梱のテンプレートを使います。独自の PNG/SVG を使う場合は、`covers/frontcover_<theme>.png` を配置してください。

```bash
vs cover               # book.yml の設定に従ってカバー画像を生成
vs clean --cover       # 生成されたカバー画像を削除
```

### data/

原稿内へ展開する外部データ（YAML 形式）を置くディレクトリです。QueryStream 記法と組み合わせて使います。

```markdown
= books                    # 全件展開
= books | tags=ruby        # タグで絞り込み
= books | -year | 3        # 年度降順・3件
```

データを展開するテンプレートは `templates/` に置きます（`data/books.yml` → `templates/_book.md`）。

### templates/

章ファイルの雛形と、QueryStream 用のデータ展開テンプレートを置くディレクトリです。`vs create` は章番号の範囲に応じて `chapter.md`・`preface.md`・`appendix.md`・`postface.md` を選びます。テンプレート内の `{{TITLE}}` は章のスラッグに置き換えられます。

`markdown_snippet.md` は雛形ではなく、使える記法を実例とともに並べた見本です。記法を確認するときに開き、必要な箇所をコピーできます。

章テンプレートのカスタマイズと QueryStream テンプレートの詳細は、「ユーティリティ・コマンド集」と「データ展開機能の使い方」で説明します。

### sources/

執筆の参考資料や素材を置くディレクトリです。ビルド対象にはなりません。`vs pdf:read` で PDF から Markdown を抽出するときは、入力ファイルの置き場所にもなります。

```bash
vs pdf:read reference        # sources/reference.pdf を自動探索
```

### codes/

書籍に掲載するサンプルコードを置くディレクトリです。原稿から `include` 記法で参照できます。

`codes/sample.rb` 全体を取り込むには、次のように書きます。

````markdown
```include:sample.rb```
````

`codes/ruby/hello.rb` の 10〜20 行目だけを取り込むこともできます。

````markdown
```include:ruby/hello.rb:10-20```
````

書き方の詳細は「拡張記法リファレンス」の「コードインクルード」で説明します。

### stylesheets/

書籍のレイアウトとデザインを定義する CSS ファイルを置くディレクトリです。テーマカラーや扉絵は、`config/book.yml` の `theme` セクションで設定します。`theme.css` はビルド時に生成され、直接編集しても次回のビルドで上書きされます。カスタム CSS は `custom.css` に書いてください。

### config/

書籍プロジェクトの設定ファイルを置くディレクトリです。主なファイルを次に示します。詳細は `config/_README.md` を参照してください。

| ファイル | 役割 |
|----------|------|
| `book.yml` | 書籍のメタデータ・ビルド設定（最重要） |
| `catalog.yml` | ビルド対象の章リスト（章の順序を定義） |
| `page_presets.yml` | 用紙サイズ等のプリセット定義 |
| `index_glossary_terms.yml` | 索引・用語集の登録済み用語 |
| `.textlintrc.yml` | textlint の校正ルール設定 |

## オプションとカスタマイズ

`vs new` には次のオプションがあります。

| オプション | 説明 |
|------------|------|
| `--yes` / `-y` | 対話をスキップし既定の設定で作成する |
| `--log <level>` | ログレベル（`debug` など）を指定する |

### 対話をスキップする（--yes）

`--yes` を付けると、質問を省略して既定値でプロジェクトを作成します。`book.yml` は後から編集できます。

```bash
vs new mybook --yes
```

既定値は以下のとおりです。

| 項目 | 既定値 |
|------|------------|
| 書籍名 | 新しい本 |
| 副題 | （空） |
| 著者名 | （空） |
| 発行者 | （空） |

### 同名のディレクトリがすでにあるとき

同名のディレクトリがすでにある場合は、エラーになります。`vs new` は新規プロジェクトを作るコマンドであり、既存のプロジェクトは変更しません。

```
エラー: ディレクトリ "mybook" はすでに存在します。
既存プロジェクトへ雛形の改良を取り込むには vs upgrade を使ってください（不足ファイルの追加もできます）。
  cd mybook && vs upgrade
```

`vs upgrade` は、本体 gem、プロジェクトの雛形、外部ツールをまとめて更新するコマンドです。不足しているファイルも追加できます。使い方は「環境の診断と更新」で説明します。

### プロジェクト名のルール

プロジェクト名には**英数字・ハイフン・アンダースコア**のみ使用できます。

```bash
# OK
vs new mybook
vs new my-book
vs new my_book_2

# NG（エラーになります）
vs new "my book"
vs new my/book
```

### デバッグログ（--log=debug）

トラブルシューティングでは、コピー中のファイルパスやコマンドの詳細を表示できます。

```bash
vs new mybook --yes --log=debug
```

## 作成後の次のステップ

プロジェクトの作成後、`vs doctor --fix` が実行されます。npm パッケージなど、執筆に必要な環境を導入します。

`vs doctor --fix` が失敗した場合も、プロジェクトは残ります。警告を確認し、手動で再実行してください。

```bash
cd mybook
vs doctor --fix
```

環境が整ったら、次のコマンドで書籍をビルドできます。

```bash
cd mybook
vs build
```

`contents/` のサンプルファイルを参照しながら、原稿を書いてください。書籍の設定を変える場合は `config/book.yml` を編集します。詳しくは「config/book.yml リファレンス」を参照してください。
