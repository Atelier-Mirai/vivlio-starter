# 相互参照（クロスリファレンス）

:::{.chapter-lead}
図や表を増やし、章の順番を入れ替えていくと、原稿に直接書いた「図 3-2」のような番号は変わってしまいます。相互参照（クロスリファレンス）を使えば、原稿では図・表・コードへ変わらない名前を付け、読者に見せる番号はビルド時に決められます。本章では、図表への番号の付け方から、見出し・章の参照、ページ番号を添える方法までを説明します。
:::

## 図・表・コードに番号を付ける

相互参照は、参照される要素に名前（ラベル ID）を付ける「定義」と、その名前を本文から呼ぶ「参照」の二つで使います。

1. **定義**: 図・表・コードの直前の行に、太字のキャプションを書き、末尾に半角空白と `@ラベルID` を付ける
2. **参照**: 本文に `@ラベルID` と書く

ビルド時には、図・表・リスト（コード）のそれぞれに「章番号-連番」の番号が振られ、本文の `@ラベルID` は「図 3-2」「表 4-1」「リスト 5-3」のような番号へのリンクに置き換わります。図表を追加したり章を並べ替えたりしても、次のビルドで番号と参照が追随します。ラベルは本書全体から探すので、別の章の図表も同じ書き方で参照できます。

番号の種類は、キャプションの直後にあるものから決まります。ラベル ID に `fig-` のような接頭辞を付ける必要はありません。

| キャプションの直後 | 番号 |
| :--- | :--- |
| 画像（`![]()`） | 図 |
| 表 | 表 |
| コードブロック | リスト |

### 図

画像の直前にキャプションを書きます。キャプションと画像の間は、空行を入れても構いません。

```markdown
** アインシュタインの写真 @einstein **
![](Einstein.png){width=40% align=center}
```

:::{.output}
** アインシュタインの写真 @einstein **
![](Einstein.png){width=40% align=center}
:::

本文に `@einstein` と書くと、図番号へのリンクになります。

::::{.side-by-side}
```markdown
@einstein は、研究するアインシュタインのイメージ画像です。
```

:::{.output}
@einstein は、研究するアインシュタインのイメージ画像です。
:::
::::

画像の大きさや配置の指定は @chapref:ch-figures で説明しています。

### 表

表の直前にキャプションを書きます。

```markdown
** 基本的な表 @basic-table **
| 名前 | 年齢 | 職種         |
| :--: | :--: | :----------: |
| 太郎 |  25  | エンジニア   |
| 花子 |  30  | デザイナー   |

@basic-table は、基本的な表の一例です。
```

:::{.output}
** 基本的な表 @basic-table **
| 名前 | 年齢 | 職種         |
| :--: | :--: | :----------: |
| 太郎 |  25  | エンジニア   |
| 花子 |  30  | デザイナー   |

@basic-table は、基本的な表の一例です。
:::

### コード（リスト）

コードブロックの直前にキャプションを書きます。

````markdown
** Ruby のサンプルコード @ruby-sample **
```ruby
def hello(name)
  puts "Hello, #{name}!"
end
```

@ruby-sample は、名前を添えて挨拶を表示します。
````

:::{.output}
** Ruby のサンプルコード @ruby-sample **
```ruby
def hello(name)
  puts "Hello, #{name}!"
end
```

@ruby-sample は、名前を添えて挨拶を表示します。
:::

外部ファイルから取り込んだコード（@chapref:ch-extensions）にも、同じようにキャプションを付けられます。

````markdown
** 素数を列挙する @prime-range **
```include:prime.rb:14-17```
````

:::{.output}
** 素数を列挙する @prime-range **
```include:prime.rb:14-17```
:::

本文の `@prime-range` は @prime-range になります。

### 番号だけを付ける・番号を付けない

本文から参照しない図表には、ラベル ID の代わりに `@auto` を書くと、番号だけが付きます。名前を付けたラベルは、どこからも参照しないと 🟡 で警告されます（@pageref:label-warnings）。`@auto` の図表は警告されません。

```markdown
** 実験装置の外観 @auto **
![](apparatus.webp)
```

`@` を書かなければ、番号の付かないキャプションになります。本文から指し示す必要のない短い例まで、すべてに番号を付ける必要はありません。

````markdown
** CSS の例 **
```css
h1 { color: red; }
```
````

## 見出しを参照する @heading-label

見出しの行末に半角空白と `@ラベルID` を書くと、その見出しも参照先にできます。行末の `@ラベルID` は紙面・目次・柱には表示されません。

```markdown
## インストール @install
```

本文に `@install` と書くと、見出しの文字を鉤括弧で括った形（「インストール」）のリンクになります。図表の参照が番号になるのに対し、見出しの参照は見出しの文字になります。

### ページ番号を添える `@pageref:`

紙の本で離れた箇所を参照するときは、ページ番号が添えられていると探しやすくなります。`@pageref:ラベルID` と書くと、参照の後ろにページ番号が付きます。

```markdown
詳しくは @pageref:install を参照してください。
```

| 出力 | 表示 |
| :--- | :--- |
| PDF | 詳しくは**「インストール」（p.200）**を参照してください。 |
| EPUB / Kindle | 詳しくは**「インストール」**を参照してください。 |

ページ番号は組版した結果から決まるので、原稿の増減で参照先のページが変わっても追随します。EPUB と Kindle は文字の大きさや画面によってページの区切りが変わるため、ページ番号を付けずに見出しへのリンクだけを表示します。

`@pageref:` は図表のラベルにも使えます（`@pageref:einstein` → @pageref:einstein）。この節の見出しには `@heading-label` を付けているので、`@heading-label` は @heading-label に、`@pageref:heading-label` は @pageref:heading-label になります。同じ見開きや直前の箇所なら `@ラベルID`、離れたページから案内するなら `@pageref:ラベルID` のように、読者が参照先を探す距離に応じて選べます。

同じ段落で同じラベルを二度 `@pageref:` で参照すると、二度目以降はページ番号を省きます。段落の組み立てを気にせず、離れた箇所を参照するときは毎回 `@pageref:` と書いて構いません。

見出しと章の参照は鉤括弧で表示されるので、和文と接する側の半角空白を紙面に出しません。原稿では、参照の前後に半角空白を置いて区切って書けます。

## 章を参照する

章には、ラベルを書かなくてもファイル名からラベルが付きます。ファイル名の番号を除いた部分（スラッグ）の前に `ch-` を付けたものが、その章のラベルです。

| ファイル | ラベル |
| :--- | :--- |
| `44-build.md` | `@ch-build` |
| `90-notation-cheatsheet.md` | `@ch-notation-cheatsheet` |

章の参照は、見出しと同じ二通りに、章番号を添える `@chapref:` を加えた三通りで書けます。

```markdown
詳しくは @chapref:ch-build を参照してください。
設定の書き方は @pageref:ch-book-yml の章にまとめています。
次の章 @ch-new では、プロジェクトを作ります。
```

| 書き方 | PDF | EPUB / Kindle |
| :--- | :--- | :--- |
| `@chapref:ch-build` | 第17章「ビルド」（p.123） | 第17章「ビルド」 |
| `@pageref:ch-build` | 「ビルド」（p.123） | 「ビルド」 |
| `@ch-build` | 「ビルド」 | 「ビルド」 |

章番号は章扉と同じ形で、付録なら「付録 A」、前書き・後書きには付きません。章題を書き換えたり章を並べ替えたりしても、次のビルドで参照の表示が追随します。

三つは次のように使い分けます。

- 「〜を参照してください」のように章そのものへ案内するときは `@chapref:`
- 「「ビルド」の章で説明した手順」のように章題を文に組み込むときは `@pageref:`
- 「前の章」「次の章」のように、ページ番号がなくても読者がめくって探せるときは `@ch-`

:::{.note}
**章ラベルの注意**

- `前の章 @ch-new`・`次章 @chapref:ch-lint` のように、隣の章を指す言葉のすぐ後ろの参照は、`catalog.yml` で本当に隣の章かどうかを確かめます。章を並べ替えると、章題は追随しても「前の」という言葉は追随しないからです。違っていれば、正しい章のラベルを添えて 🟡 で警告します。
- `vs rename 12-new 12-project` のようにスラッグを変えると、本文の `@ch-new` なども新しいラベルへ書き換わります。番号だけを変える改名では、ラベルは変わりません。
- スラッグのない章（`11.md`）には、ラベルが付きません。番号でラベルを作ると、改番のたびに参照が切れるためです。
- `@chapref:` に指定できるのは章のラベルだけです。見出しや図表には `@pageref:` を使います。
:::

## ラベル ID の決まり

ラベル ID の付け方は、プログラムやファイル名で名前を付けるときの一般的な決まりと同じです。半角の英字（a〜z・A〜Z）・数字（0〜9）・ハイフン（`-`）・アンダースコア（`_`）だけで書き、日本語・空白・そのほかの記号は使えません。使えない文字を含む ID（`@図の例`）はラベルにならず、🟡 で警告されます。書籍全体で、英小文字・数字・ハイフンでつなぐ形（`@ruby-sample`・`@basic-table`）に揃えると、ID から参照先を推測しやすくなります。ID は対象の内容から名付けます。図表の順番や章番号を含めると、並べ替えたときに名前と実際が食い違います。

次の名前は、ラベル ID に使えません。

- `auto`・`id`（番号だけを付ける指定。`@id` は `@auto` と同じ）
- `ch-` で始まる名前（章のラベル）
- `vspace`・`hspace`・`pagebreak`・`pageref`・`chapref`・`version`・`title`・`today`・`qr`（ビルド時に置き換わる記法。@chapref:ch-extensions）

`auto`・`id` 以外をキャプションや見出しのラベル ID に使うと、ビルド時に 🔴 で報告されます。

### 一意性

ラベル ID は、図・表・リスト・見出しをまたいで、本書全体で一意でなければなりません。同じ ID を二箇所以上で定義すると、定義したすべての行番号を添えて、ビルド時に 🔴 で報告されます。

:::{.output}
```text
🔴 12-data.md:42 - ラベルID '写真 @photo' は重複しています
        重複箇所: 12-data.md: 42, 88
        → どちらかの ID を、対象を区別できる別の名前に変えてください。
```
:::

報告されてもビルドは最後まで進みますが、後の定義にも先の定義と同じ番号が付き、参照はすべて先の定義を指します。

### 参照の警告 @label-warnings

参照の誤りは 🟡 で警告されます。

- **未定義のラベル**: 参照先が見つからない `@ラベルID` は、紙面に文字のまま残ります。綴りの近いラベルがあれば「もしかして」として添えます
- **孤立ラベル**: 定義したのに、どこからも参照されていないラベル
- **参照先のない `@pageref`**: `@pageref:install` のように、`:` に続けて ID を書きます

:::{.output}
```text
🟡  12-data.md: 参照の問題を 1 件検出
🟡     - contents/12-data.md:9 - 未定義のラベルID: @insatll（もしかして: @install）
```
:::

重複・未定義・孤立は、`vs preflight` でビルドの前に確かめられます（@chapref:ch-utility）。
