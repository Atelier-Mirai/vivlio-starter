# 執筆ワークフローとクイックスタート

:::{.chapter-lead}
Vivlio Starter は、CSS 組版で本を作るための道具です。本章では「プロジェクト作成 → 執筆 → 整える → ビルド → 入稿・配布」という五つの工程を見渡し、インストールから最初の PDF を作るまでを説明します。工程ごとの詳しい手順は、対応する章で扱います。
:::

## CSS 組版という方法

本づくりには、目的に応じてさまざまな方法があります。

- **ワープロソフト**（Word・Pages） — 画面で見たとおりが紙になります。手軽な反面、長い本では図表の位置や改ページが崩れやすくなります。
- **DTP ソフト**（InDesign） — 紙面を自由に設計でき、商業出版の現場で使われています。習得にも費用にも相応の負担があります。
- **組版システム**（LaTeX） — 数式と相互参照に強く、学術書で長く使われてきました。独自の記法を覚える必要があります。
- **CSS 組版**（Vivliostyle） — Web の技術で紙面を設計します。原稿は Markdown で書けます。

Vivlio Starter が採っているのは、いちばん下の **CSS 組版**です。

### Web の技術で、紙の本を組む

CSS は本来、Web ページの文字の大きさ、色、余白といった見た目を指定する言語です。Web ページには固定されたページがなく、文章はスクロールに合わせて続きます。

紙の本では、決まった大きさの紙面に文字を流し込み、収まらない部分を次のページへ送ります。ページの下にはノンブル（ページ番号）、上には柱（章題）を置きます。脚注も、参照した箇所と同じページの下に組みます。

このような紙面用の指定を CSS に加える仕様は、Web の標準化団体 W3C が定めています。その仕様を解釈して紙面を組むソフトウェアが **CSS 組版エンジン**です。Vivlio Starter では、日本発の CSS 組版エンジン **Vivliostyle** を使います。

### 原稿が本になるまで

Vivlio Starter では、原稿を **Markdown → HTML → CSS 組版 → 出力** の順に処理します。

- **Markdown（原稿）** — 見出しや箇条書きを簡単な記号で書く記法です。著者が直接編集するのはこのファイルです。
- **HTML（構造に変換）** — 「ここは見出し」「ここは本文」という構造を持った形式へ変換されます。
- **CSS 組版（紙面を設計）** — その構造に、判型・余白・書体・ノンブルといった紙面の設計を当てはめます。
- **出力（読者に届く形）** — 閲覧用 PDF・印刷入稿用 PDF・EPUB・Kindle が生成されます。

この流れを使うと、一つの原稿から複数の形式を出力できます。紙の本と電子書籍で、原稿を書き分ける必要はありません。

### Vivlio Starter は、その全部をまとめる道具

Vivliostyle は組版エンジンなので、原稿の前処理、目次の生成、表紙の作成までは扱いません。これらを補い、一冊の本を作る工程としてまとめるのが Vivlio Starter です。

Vivlio Starter は **CLI ツール**です。ターミナルからコマンドを実行して使います。操作が文字として残るため、同じ手順を繰り返しやすい点が特長です。本書で使う `vs` が、そのコマンドです。

```bash
vs new mybook   # プロジェクトを作る
vs build        # 本を組み上げる
```

:::{.memo}
**CLI と GUI**

CLI は Command Line Interface の略で、文字で命令を伝える方式です。マウスで操作する画面は GUI（Graphical User Interface）と呼びます。CLI は、原稿を直してはビルドする作業を繰り返す書籍制作に向いています。
:::

## 各ステップの概要

### (1) プロジェクト作成

`vs new` で書籍プロジェクトの雛形を生成します。書籍名と著者名を対話形式で入力すると、必要なファイル一式が作られます。続いて `vs doctor --fix` が実行され、Vivliostyle や ImageMagick など、書籍制作に必要な外部ツールを導入します。

```bash
vs new mybook   # 雛形生成 + 必要ツールの自動セットアップ
cd mybook
```

**参照:** 「インストール詳細」「新規プロジェクトの作成（vs new）」「環境の診断と更新」

### (2) 執筆

原稿は `contents/` ディレクトリ内の Markdown ファイルに書きます。章ファイルの追加、削除、番号の振り直しには専用コマンドを使えます。

```bash
vs create 10-intro   # 新しい章を追加
vs build  10-intro   # その章だけ素早くビルドして確認
```

章を指定してビルドすると、書籍全体を組むより短い時間で結果を確認できます。執筆中は `vs build <章名>` を使い、変更した章の体裁を確認します。

**参照:** 「Markdown 執筆チュートリアル」「章の管理」

### (3) 整える

原稿を書いたら、文章を点検します。

`vs lint` は textlint を使い、表記揺れや冗長な表現を検出します。`vs metrics` は文字数、漢字比率、語彙多様度などを数値で示します。

```bash
vs lint       # 文章を校正する
vs metrics    # 原稿の統計を確認する
```

**(2) と (3) は必要に応じて繰り返します。** 執筆と推敲を往復しながら、原稿を仕上げます。

**参照:** 「文章校正（vs lint）」「Metrics」

### (4) ビルド

執筆を終えたら、`vs build` で書籍全体を組版します。閲覧用 PDF、印刷入稿用 PDF、EPUB、Kindle 用ファイルを、一度のコマンドで生成できます。

```bash
vs build   # 書籍全体をビルドする
```

カバー画像がなければ、`vs build` が内部で `vs cover` を実行します。カバーのデザインを調整するときや、カバーだけを生成して確認するときは、`vs cover` を直接実行します。

```bash
vs cover   # カバーを個別に生成・調整したい場合
```

出力形式は `config/book.yml` の `output.targets` で指定します。技術書典向けには `pdf`、印刷所への入稿には `print_pdf`（トンボ・塗り足し付き）、電子書籍の配信には `epub` または `kindle` を指定します。

**参照:** 「ビルド（vs build）」「カバー画像の生成」「config/book.yml リファレンス」

### (5) 入稿・配布

生成した PDF や EPUB を、頒布先に合わせて提出・アップロードします。

| 頒布先 | 使用するファイル |
| :--- | :--- |
| 技術書典・ダウンロード販売・PDF 配布 | `pdf`（閲覧用） |
| コミケ（印刷所入稿） | `print_pdf`（トンボ付き） |
| Apple Books, Kobo | `epub`|
| Kindle | `kindle`（専用） |

## やってみる — 最初の PDF ができるまで

:::{.section-lead}
ここからは、インストールから最初の PDF を開くまでを実行します。入力するコマンドは数個です。
:::

### Ruby を用意する

Vivlio Starter は Ruby で動作します。まず、Ruby が入っているか確認します。

```bash
ruby -v
```

`ruby 4.0.6` のようにバージョンが表示されれば、次の「Vivlio Starter をインストールする」へ進めます。

表示されない場合は、同梱のスクリプトで必要なものを導入します。Xcode コマンドラインツール、Homebrew、rbenv、Ruby 本体、bundler を順に導入します。

```bash
bin/install-ruby.zsh
```

:::{.column}
**💡 ターミナルの開き方（macOS）**

- Spotlight から: `Cmd + Space` →「Terminal」と入力 → `Enter`
- Finder から: アプリケーション → ユーティリティ → Terminal.app
:::

完了したらシェルを読み込み直し、もう一度バージョンを確認します。

```bash
exec zsh -l
ruby -v
```

:::{.output}
```text
ruby 4.0.6 (2026-07-14 revision 03b6d3f889) +PRISM [arm64-darwin25]
```
:::

macOS 以外へ導入する場合や、導入内容を確認したい場合は、付録「インストール詳細」を参照してください。Ruby を更新するときも、同じスクリプトにバージョンを指定します（`bin/install-ruby.zsh -v 4.1.0`）。

### Vivlio Starter をインストールする

Ruby の準備ができたら、gem を入れます。

```bash
gem install vivlio-starter
```

### プロジェクトを作る

新しい書籍プロジェクトを作成します。`mybook` はプロジェクト名なので、任意の名前に置き換えてください。

```bash
vs new mybook
cd mybook
```

次のような雛形が生成されます。

```
mybook/
  contents/          ← 原稿（Markdownファイル）
  images/            ← 画像ファイル
  covers/            ← 表紙・裏表紙用の画像ファイル
  data/              ← 書籍内で展開したいQueryStream用データ（YAML形式）
  templates/         ← 各種雛形ファイル置き場
  sources/           ← 執筆資料やPDFファイル置き場
  codes/             ← 書籍内で掲載するサンプルコード
  stylesheets/       ← CSSスタイルシート
  config/
    book.yml         ← 書籍の設定ファイル
    catalog.yml      ← 章構成
    page_presets.yml ← ページレイアウト設定
    index_glossary_terms.yml     ← 用語集
  package.json
  Gemfile
```

原稿となる Markdown ファイルは `contents/` に置きます。最初からサンプルの章が入っているため、記法と紙面の対応を確認できます。各ディレクトリの役割とオプションは、次章「新規プロジェクトの作成（vs new）」で説明します。

### はじめてのビルド

PDF を生成します。

```bash
vs build
```

しばらくすると、`mybook_v0.1.0.pdf` が生成され、自動的に開きます。これで最初の PDF ができました。

### 新しい章を作る

続けて、章を追加します。

```bash
vs create 10-awesome
```

`contents/10-awesome.md` と `images/10-awesome/` が生成されます。原稿を書いたら、その章だけをビルドして確認します。

```bash
vs build 10-awesome
```

章を指定すると、書籍全体を組むより速く結果を確認できます。執筆中はこの操作を繰り返し、すべて書き終えたら最後に `vs build` を実行してください。表紙、目次、索引、奥付を含む書籍全体が生成されます。

```bash
vs build
```

## コマンド早見表

コマンドをすべて把握する必要はありません。まずは各工程の中心となるコマンドを使えば十分です。

| ステップ | 主なコマンド | 内容 |
| :--- | :--- | :--- |
| (1) プロジェクト作成 | `vs new` | 雛形生成＋必要ツール自動セットアップ |
| (2) 執筆 | `vs create` | 章ファイルを追加 |
| | `vs build <章名>` | 章単位で素早く確認 |
| (3) 整える | `vs lint` | 文章を校正 |
| | `vs metrics` | 原稿の統計を確認 |
| (4) ビルド | `vs build` | 書籍全体をビルド（カバー未生成時は自動生成） |
| | `vs cover` | カバーを個別に生成・調整したい場合 |
| (5) 入稿・配布 | — | 生成済みファイルを提出 |

このほかに、章の削除、番号の振り直し、索引の作成、PDF の圧縮といったコマンドがあります。一覧は `vs --help`、個々の使い方は `vs <コマンド> --help` で確認できます。

```bash
vs --help
vs build --help
```
