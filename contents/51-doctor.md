# 環境の診断と更新

:::{.chapter-lead}
Vivlio Starter で本を作るには、組版や画像処理などに使う外部ツールが必要です。新しい環境を用意したときや、ビルドが急に通らなくなったときは、`vs doctor` で不足しているツールを調べられます。必要なら `--fix` で導入もできます。現在お使いの環境を新しいバージョンへ更新するには `vs upgrade` を使います。この章では、それぞれの役割と使いどころを見ていきます。
:::

** 本章で扱うコマンド **

| コマンド | 目的 |
| :--- | :--- |
| `vs doctor` | 必要なツールと設定ファイルを診断する |
| `vs doctor --fix` | 診断で見つかった問題を修正する |
| `vs upgrade` | 本体・雛形・外部ツールをまとめて更新する |

## vs doctor とは

:::{.section-lead}
`vs doctor` は、Vivlio Starter に必要なツールや設定ファイルを調べるコマンドです。ビルドや lint が失敗したときも、まず環境に不足がないかを確かめられます。
:::

新しい Mac を整えるときは、@chapref:ch-install の導入スクリプトを使います。Homebrew・Ruby・Vivlio Starter と、`vs doctor --fix` の対象のツールをまとめてインストールします。

### 診断の対象

`vs doctor` は、PDF を組む Vivliostyle をはじめ、PDF の加工・画像の変換・文章の校正・索引・数式・図に使う外部ツールと、Google Fonts 用の SSL 証明書を調べます。ツールごとの用途とインストール方法は、@ch-install の章の @pageref:install-tools にまとめてあります。

### Node.js の版

Node.js が Vivliostyle の求める版より古いと、ツールの一覧の後に次の警告が表示されます。`vs upgrade` を実行すると、Vivliostyle CLI と一緒に更新されます。

:::{.output}
```text
🟡 Node.js 20.19.0 は Vivliostyle CLI 11.3.3 の要求を満たしません（22.12.0 以上が必要です）
        → vs upgrade
          Homebrew 以外（nvm など）でインストールした場合は、そのツールで 22.12.0 以上へ更新してください。
```
:::

### 設定ファイルの診断

書籍プロジェクト内で実行した場合は、外部ツールに加えて `config/` 内の設定ファイルも診断します。

- **必須設定ファイル**（`config/book.yml` / `config/catalog.yml` / `config/page_presets.yml`）が存在し、YAML として正しく読み込めるかを確認します。
- **任意設定ファイル**（textlint の設定や辞書ディレクトリなど）の有無を確認します。

必要なファイルが揃っていれば、次のように表示されます。

:::{.output}
```text
✅ config/ 設定ファイル: OK
```
:::

`--fix` を付けると、不足している設定ファイルや辞書を `vs new` の雛形から補います。

必須設定ファイルが破損して読み込めない場合は、雛形から作り直します。`book.yml` は**書名や著者名など、取り出せる値をできるだけ残し**、`catalog.yml` は `contents/` の原稿から章の並びを組み立てます。元のファイルは `config/book.yml.bak.<日時>` のような名前で残るので、作り直した内容と見比べられます。

## 基本的な使い方

:::{.section-lead}
まず `vs doctor` で診断結果を見てから、必要に応じて `--fix` を付けて実行します。どのツールを導入するのか確認してから進められます。
:::

### 診断のみ実行

```bash
vs doctor
```

ツールの状態を一覧で表示します。このコマンドだけではインストールや設定の変更は行いません。

:::{.output}
```text
🔎 環境診断を開始します…
✅ config/ 設定ファイル: OK
✅ Xcode Command Line Tools: OK
✅ node: OK
✅ textlint: OK
✅ vivliostyle: OK
✅ vfm: OK
✅ qpdf: OK
🔴 pdfinfo: 見つかりません
🔴 pdftoppm: 見つかりません
🔴 pdftotext: 見つかりません
✅ gs: OK
…
✅ Google Fonts 用 SSL 証明書: OK
❗ 不足しているツール: pdfinfo (poppler), pdftoppm (poppler), pdftotext (poppler)（3 件）
ヒント: macOS の場合は `vs doctor --fix` で自動インストールを試行できます
```
:::

### 自動修正（--fix）

```bash
vs doctor --fix
```

診断で見つかった問題を修正します。不足しているツールをインストールし、不足や破損のある設定ファイルを雛形から復元します。Homebrew 自体や Xcode Command Line Tools がインストールされていない場合は、その導入前に確認を求められます。

:::{.output}
```text
🔎 環境診断を開始します…
…
❗ 不足しているツール: pdfinfo (poppler), pdftoppm (poppler), pdftotext (poppler)（3 件）
🛠 不足しているツールをインストールします…
…
🔁 インストール後の再診断…
✅ すべてのツールがインストールされました
```
:::

## vs upgrade — 環境をまとめて最新化する

:::{.section-lead}
`vs upgrade` は、使っている執筆環境をまとめて更新するコマンドです。プロジェクトの直下で実行すると、Vivlio Starter 本体、プロジェクトの雛形、外部ツールの順に更新します。
:::

1. **`vivlio-starter` 本体の更新** — 新版があれば、確認後に `gem update vivlio-starter` を実行します。続きの処理は、新しい版で実行します
2. **プロジェクトの雛形追従** — 新しい版のスタイルシートやテンプレートを既存プロジェクトへ取り込み、最後に `Gemfile.lock` が指す版も合わせます
3. **外部ツールの一括更新** — Homebrew・npm・gem でインストールしたツールの更新計画を示し、確認後にまとめて更新します。Kindle Previewer は、アプリの更新機能で更新します

```bash
vs upgrade            # 計画を表示し、確認してから適用
vs upgrade --dry-run  # 計画を表示するだけで、何も変更しない
```

プロジェクトの外で実行すると、雛形の追従を省き、本体と外部ツールだけを更新します。

### 雛形の追従

雛形の各ファイルは、変更の状態に応じて分類されます。実際に適用する前に、次のような計画表で確認できます。

| 分類 | 意味 | 動作 |
|------|------|------|
| 追加 | 雛形の新規ファイル | コピーします |
| 更新 | 雛形は変更され、手元では未変更 | 新しい雛形で置き換えます |
| 合流 | 雛形と手元で**別の箇所**を変更 | 両方の変更を取り込みます |
| 競合 | 雛形と手元で**同じ箇所**を変更 | diff を示し、1 件ずつ確認します（y/n/d） |
| 整理 | 今の版に合わせて直す設定など | 示した箇所だけを直します |

:::{.output}
```text
🔍 雛形との差分を確認しています…（gem 1.0.0 の雛形）
📋 更新計画:
   追加   covers/templates/frontcover_a4.png        （雛形の新規ファイル）
   更新   stylesheets/chapter-common.css            （著者は未変更）
   合流   stylesheets/preface.css                   （別の場所を変更 → 両立）
   競合   stylesheets/custom.css                    （同じ場所を変更 → 確認）
   整理   config/book.yml
            廃止キーを削除します（index.max_sub_references）
            新しい設定キーを追加します（theme.lead_size ほか 8 件）
```
:::

競合のほかは、計画を示したあとに 1 回だけまとめて確認します。競合は 1 件ずつ確認します。

たとえば、自分でスタイルシートの末尾に規則を加え、新しい雛形では先頭が改良された場合は「合流」です。**変更箇所が離れていれば、両方を残して取り込めます。** 同じ箇所を変更していた場合は「競合」となり、差分を見て適用するか選びます。適用すると自分の変更が失われることも、その場で示されます。元のファイルは退避されるため、必要なら戻せます。

:::{.note}
**原稿と辞書は雛形で上書きしません**

`contents/`・`images/`・`covers/`（`bundled/`・`templates/` を除く）・`codes/`・`data/` と、`README.md`・`book.yml`・`catalog.yml`・`talk.yml`・索引と用語集の辞書・スペルチェックのユーザー辞書・`textlint_allowlist.yml` は「著者データ領域」です。`vs upgrade` はこれらを雛形で上書きしません。

著者データ領域に手を入れるのは、`book.yml` への新しい設定の追加など、更新計画に「整理」として示したものだけです。

書き換えるファイルは、その前に `.vs-backup/upgrade/<日時>/` へ退避します。変更を戻したいときは、そこから元の内容を確認できます。不要になったら `.vs-backup/` フォルダを削除してください。
:::

同梱の素材は著者データ領域の外にあり、新しい雛形に合わせて更新されます。表紙のテンプレート（`covers/bundled/`）、自作の表紙の雛形（`covers/templates/`）、扉絵・装飾画像（`stylesheets/images/bundled/`）、テーマ色（`stylesheets/theme.css`）です。新しく同梱された素材も追加されます。

著者が雛形のファイルを変更したかどうかは、`vs new` が作る `config/scaffold.lock` で判定します。このファイルは手で編集せず、Git にコミットしてください。

### 雛形の更新の通知

`gem update` だけで本体を更新すると、スタイルシートの改良はプロジェクトへ届きません。そこで、全章の `vs build` と `vs preflight` は、雛形のスタイルシートや `book.yml` に書ける設定が新しくなっていれば、最後に 💡 で案内します。

:::{.output}
```text
💡 雛形が新しくなっています（CSS: colophon.css ほか 3 件・book.yml の設定: 2 件）
        vs upgrade で確かめられます
```
:::

`vs build 11` のように章を指定したときは案内しません。`vs upgrade` を実行すると、次に雛形が変わるまで表示されなくなります。競合を断ったスタイルシートも、次に雛形が変わるまで案内しません。

### 新しい設定の追加

増えた設定は、`vs upgrade` が `book.yml` へコメントごと追加します。更新計画に「整理」の行として示し、確認で「いいえ」と答えれば追加しません。値は既定値なので、組み上がりは変わりません。雛形の並びのとおりに差し込み、ほかの行は変更しません。変更前のファイルは `.vs-backup/upgrade/` に残ります。

:::{.output}
```text
✅ book.yml に新しい設定を 2 つ追加しました（値は既定値なので、組み上がりは変わりません）
        theme.lead_size
        index_glossary.exclude_chapters
        設定の詳細は vs config:book theme.lead_size として確認できます
```
:::

追加するのは、新しい設定につき 1 回だけです。追加された設定を削除しても、次の `vs upgrade` で戻ることはありません。`--dry-run` では、追加する行を表示するだけです。

`theme: { color: red }` のように 1 行にまとめて書いた区分には追加できません。その場合は追加する行を表示するので、使いたい設定だけを `config/book.yml` へコピーしてください。

### 外部ツールの一括更新

雛形を取り込んだあと、導入済みの外部ツールを調べます。更新計画には、対象のツール、現在と更新後の版、導入経路が表示されます。内容を確認してから更新を進めます。

:::{.output}
```text
🔍 外部ツールのバージョンを確認しています…
📋 更新計画:
   node                24.11.1    → 26.13.0  (brew)
   vivliostyle CLI     11.4.0     → 最新  (npm・node と連動)
   VFM                 2.7.2      → 変更なし  (npm・最新)
   …
   kindle-previewer    対象外（手動・アプリの更新機能で上がる）
❓ 更新を実行しますか？ [y/N]: y
⬆️  node を更新中…
✅ node: 更新しました
⬆️  vivliostyle CLI を更新中…
✅ vivliostyle CLI: 更新しました
🩺 更新後の診断を実行します…
…
✅ 更新完了: 2 件成功 / 0 件失敗
✅ vs upgrade が完了しました（雛形: 最新／外部ツール: 2 件を更新）
```
:::

外部ツールの更新には、次のような扱いがあります。

- 更新したあと、`vs doctor --fix` と同じように診断し、不足しているツールもインストールします。外部ツールがすべて最新で不足もないときは、診断を省きます。設定ファイルや証明書を確かめるときは、`vs doctor` を実行してください
- 一部のツールで更新に失敗しても、ほかのツールの処理は続けます。失敗したものには、手動での復旧コマンドを示します
- node を更新するときは、vivliostyle CLI も最新版へ更新します
- Ruby 本体は自動更新しません。新版がある場合は、実行の最後に「📣 お知らせ」として、rbenv など使用中の導入経路に合った手順を示します
- Homebrew がインストールされていないときは、外部ツールの更新を省きます
- ネットワークに接続できないときは、更新を始める前に処理を中止します

## vs doctor と vs upgrade の使い分け

二つのコマンドは、環境に問題があるかを調べたいのか、新しい版へ更新したいのかで選びます。

| | `vs doctor` | `vs upgrade` |
|------|------|------|
| 目的 | ツールが揃っているかを調べる | 環境を新しい版へ更新する |
| 変更 | 診断だけ（`--fix` で不足を補う） | 本体・雛形・ツールを更新する |
| ネットワーク | 診断には不要 | 必要（gem / brew / npm へ照会） |
| 所要時間 | 10 秒ほど | 数分 |
| 使いどころ | ビルドが失敗した・手動でインストールした | 動いている環境を定期的に更新する |

ビルドが失敗したときは、まず `vs doctor` で不足や設定の問題を確かめてください。原因が分からないまま `vs upgrade` を実行すると、複数のツールの版が変わり、かえって問題を切り分けにくくなることがあります。

## トラブルシューティング @doctor-troubleshooting

| 症状 | 原因 | 解決策 |
|------|------|--------|
| `brew` が見つからない | Homebrew 未インストール | `vs doctor --fix` で自動インストール、または[https://brew.sh](https://brew.sh)を参照 |
| `npm` が見つからない | node 未インストール | `vs doctor --fix` で node をインストール後、再実行 |
| Xcode CLT のインストールが完了しない | インストーラの画面で承認が必要 | インストーラの完了後に `vs doctor --fix` を再実行 |
| Google Fonts の SSL エラーが解消しない | 証明書の設定がシェルに反映されていない | 新しいターミナルを開き、`vs doctor` を再実行 |
