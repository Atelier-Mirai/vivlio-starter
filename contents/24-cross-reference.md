# クロスリファレンス（相互参照）の使い方

:::{.chapter-lead}
図や表を増やし、章の順番を入れ替えていくと、原稿に直接書いた「図 3-2」のような番号は変わってしまいます。相互参照（クロスリファレンス）を使えば、原稿では図・表・コードへ変わらない名前を付け、読者に見せる番号はビルド時に決められます。本章では、キャプションへのラベル付けから、本文中の参照、ページ番号を添える方法までを説明します。
:::

## ラベル付きキャプションの書き方

クロスリファレンスは、参照される要素に名前を付ける「定義」と、その名前を本文から呼ぶ「参照」の二段階で構成されます。

1. **定義側**: 図・表・リストに「ラベルID（`@id`）」を付けてキャプションを記述する
2. **参照側**: 本文中から `@id` を使ってその要素を参照する

ビルド時には、各章の図・表・リストへ「章番号＋連番」の番号が割り振られます。本文中の `@id` は、「図 3-2」「表 4-1」「リスト 5-3」のような番号付きテキストとリンクへ置き換わります。章や図表の順序を変えても、定義と参照が同じ ID で結ばれているかぎり、新しい番号が反映されます。

### 共通ルール

図・表・リストには、次のような**キャプション行**を付けます。

- 行頭に太字 (`**...**`) でタイトルを書く
- タイトルの末尾に `@ラベルID` を付ける
- 直後に続くブロック要素（コードブロック / テーブル / 画像）がその対象になります

ラベル ID は、本文中で参照するときに使う、著者向けの名前です（例: `@css-table-rotate`）。紙面にこの名前が表示されることはないので、後から見ても対象を判別できる名前を付けます。

### コード（リスト）の例

CSS コード例を「リスト」として扱い、相互参照したい場合は次のように書きます。

````markdown
** 回転テーブルのCSS定義 @css-table-rotate **
```css:table.css
table {
  border-collapse: collapse;
  /* 略 */
}
```
````

- キャプション行: `**回転テーブルのCSS定義 @css-table-rotate**`
- 直後のブロック: ```css:table.css ～ ``` →**コードブロック**なので「リスト」として扱われます。

### 表の例

テーブル（表）をナンバリングの対象にしたいときは、次のように書きます。

```markdown
** 回転テーブルのプロパティ一覧 @prop-list **
| プロパティ名 | 役割      |
| :----------- | :-------- |
| --scale      | 縮尺率    |
| --shift-y    | Y軸シフト |
```

- キャプション行の直後が Markdown テーブルなので、「表」として扱われます。

### 図の例

画像を図として扱い、参照できるようにしたい場合は、次のように書きます。

```markdown
** 回転テーブルのイメージ図 @table-rotate-image **
![回転テーブルのイメージ図](table-rotate.png)
```

- 直後が画像（`![]()`）なので、「図」として扱われます。

### 番号を付けない例（ただのコード例など）

`@id` を書かなければ、その要素は**番号や相互参照を持たない例**として扱われます。本文から指し示す必要のない短い例まで、すべて採番する必要はありません。

````markdown
** CSSの例 **
```css
h1 {
  color: red;
}
```
````

このように書くと、見出しとして太字にはなりますが、

- 「リスト 4-1」などの番号は付かない
- 本文から `@id` で参照することもできない

という扱いになります。

## 本文での参照方法

### `@id` による参照

本文では、定義したラベル ID を **`@id` の形で記述します**。その位置に、対象の種類と現在の番号を含むリンクが入ります。

次のように書きます。

```markdown
横長表の調整方法については、@css-table-rotate を参照してください。
ここで定義されているカスタムプロパティの一覧は、@prop-list にまとめています。
レイアウト全体のイメージについては、@table-rotate-image を参照してください。
```

ビルド結果は次のような形になります。

- `@css-table-rotate` → 「リスト 4-1」へのリンク
- `@prop-list` → 「表 4-2」へのリンク
- `@table-rotate-image` → 「図 4-3」へのリンク

### 表示されるテキスト

番号部分（リスト 4-1・表 3-2・図 1-5）は、**章番号**と**章内での連番**から計算されます。原稿には ID だけを残すので、図表を追加したり移動したりした後も、番号を一つずつ書き直さずに済みます。

### 見出しにラベルを付ける @heading-label

図・表・リストに加えて、**見出しそのもの**も参照先にできます。見出しの行末へ半角空白を置き、続けて `@id` を書きます。

```markdown
## インストール @install
```

行末の `@install` はビルド時に取り除かれ、**紙面・目次・柱には表示されません**。見出しの位置にはリンク先となるアンカーだけが残り、本文からは図表と同じように `@install` で参照できます。

```markdown
詳しくは @install を参照してください。
```

<!-- no-lint -->
→ 「詳しくは**「インストール」**を参照してください。」（見出しへのリンク）

図表の参照が「図 3」のような**番号**になるのに対し、見出しの参照は**見出しテキストを鉤括弧で括った形**になります。

### `@pageref:id` — ページ番号を添えて参照する

紙の本で離れた箇所を参照するときは、対象の名前にページ番号が添えられていると探しやすくなります。`@pageref:id` と書くと、参照先の**ページ番号も組版時に加えられます**。

```markdown
詳しくは @pageref:install を参照してください。
```

| 出力 | 表示 |
| :--- | :--- |
| PDF | 詳しくは**「インストール」（p.200）**を参照してください。 |
| EPUB / Kindle | 詳しくは**「インストール」**を参照してください。 |

ページ番号は組版後の位置から計算されるため、原稿の増減によって参照先が移動しても更新されます。EPUB と Kindle は画面や文字サイズによって改ページ位置が変わるリフロー型なので、ページ番号を省き、**タイトルへのリンク**として表示します。

`@pageref:` は見出しラベルだけでなく、図・表・リストのラベルにも使えます（`@pageref:fig-flow` → 「図 3（p.45）」）。

:::{.memo}
**`@install` と `@pageref:install` の違い**

どちらも同じ見出しを指し、違いは**ページ番号を添えるかどうか**です。同じ見開きや直前の箇所なら `@install`、離れたページから案内するなら `@pageref:install` のように、読者が参照先を探す距離に応じて選べます。

参照先を書き忘れた裸の `@pageref` は 🔴 で指摘されます（`@pageref:install` のように `:` に続けて ID を書いてください）。
:::

この章自身にも見出しラベルを付けています。一つ前の節は @heading-label のように参照でき、ページ番号を添えると @pageref:heading-label のように表示されます。原稿に残る ID と、紙面に現れる参照の違いを見比べられます。

## ラベルIDの扱い

### 手動ID（@id）

本文から参照する要素には、内容を表す ID をキャプション行へ直接書きます。番号が変わっても ID はそのまま使うため、章内の一時的な順番ではなく、対象の意味に基づいて名付けます。

```markdown
** 回転テーブルのCSS定義 @css-table-rotate **
```

- 本文では `@css-table-rotate` と書くだけで参照できます。
- ID は本書全体で一意である必要があります（同じIDを複数の図表リストに使うことはできません）。

### 自動ID（@auto / @omakase）

本文からは参照しないものの、紙面上の番号だけを付けたい場合は、キャプション行に `@auto` または `@omakase` を書きます。

````markdown
** 別のコード例 @auto **
```ruby
def prime?(n)
  # ...
end
```
````

- この場合は一意の ID が内部で割り当てられ、「リスト 4-4」のような図表番号が付きます。
- 内部 ID は原稿から参照できません。本文に**番号付きリンクを置く要素**には、`@css-table-rotate` のような意味のある ID を付けます。`@auto` は、番号は必要でも本文から指さない要素に使います。

### システム予約ID（予約語）

`@` で始まる記法は、クロスリファレンスだけでなく、システム組み込みの**ビルド時マクロ**にも使われます。次の名前は**システム予約語**なので、著者が付けるラベル ID とは区別されます。

#### 自動採番用の予約ID

| 予約ID | 用途 |
| :--- | :--- |
| `@auto` | 自動ID割り当て（前掲「自動ID」） |
| `@omakase` | 同上（別名） |
| `@id` | 同上（別名） |

#### 組み込みマクロの予約ID（完全一致）

| 予約ID | マクロの役割 |
| :--- | :--- |
| `@vspace` | 縦方向の余白挿入（`@vspace:1.5lh` / `@vspace:10`（単位省略時は mm）。負値で上に詰める） |
| `@hspace` | 水平方向のアキ（`@hspace:2` / `@hspace:10mm`。単位省略時は em） |
| `@pagebreak` | 改ページ（`@pagebreak` / `@pagebreak:recto` / `@pagebreak:verso`） |
| `@pageref` | ページ番号つき参照（`@pageref:install`。前掲） |
| `@version` | `config/book.yml` の `project.version` を差し込む |
| `@title` | `config/book.yml` の `book.main_title` を差し込む |
| `@today` | ビルドを実行した日付を差し込む |
| `@qr` | QR コード画像の挿入（`@qr:https://example.com/`） |

`@hspace` 以降のマクロは「拡張記法リファレンス」の章で解説しています。

:::{.tip}
**著者が新しいラベルIDを付けるときの注意**

上記の予約語と衝突する ID（例: `@auto` という図を定義する等）は使用しないでください。組み込みマクロの予約語（`@version` など）をラベルIDに使うと、ビルド時に 🔴 で指摘されます。
:::

### IDの一意性（重複禁止）

ラベルIDは、リスト・表・図をまたいで**本書全体で一意でなければなりません**。たとえば、リストと図の両方で `@css-table-rotate` を定義することはできません。

同じIDが複数箇所で定義されていると、ビルド時に重複エラーとして検出され、次のようなメッセージが表示されます。

```
🔴 71-install.md:42 - ラベルID 'CSS定義 @css-table-rotate' は重複しています
          重複箇所: 71-install.md: 42, 88
```

メッセージには、重複しているファイルと行番号が示されます。いずれかの ID を、対象を区別できる名前へ変更してください。重複があってもビルド処理は最後まで進みますが、意図した番号やリンクにならない{虞|おそれ}があります。配布前に重複を解消します。

意味のあるIDを種別ごとに分けて使いたい場合は、次のようにID自体を変えてください。

- `@css-table-rotate-css`（リスト用）
- `@css-table-rotate-fig`（図用）

対象の違いを ID に含めておくと、本文中の参照を見ただけで、どちらを指しているか判断できます。

### ラベルIDの命名規則（推奨）

ラベル ID（`@id`）には幅広い文字を使えますが、書籍全体で命名方法を揃えると、ID から参照先を推測でき、重複も避けやすくなります。

- **英小文字＋数字＋ハイフン**（kebab-case）で統一する
- 内容を表す英単語を選ぶ（コード例なら `@ruby-sample`、表なら `@basic-table`、図なら `@einstein` など）
- 同種のものが章をまたいで増える場合は、**章番号を末尾に添える**と整理しやすい

```markdown
# 図が多い章
@einstein-11, @diagram-11, @diagram-12

# 表が多い章
@basic-table, @data-table-25
```

どの種別（リスト／表／図）の番号になるかは、ID名ではなく**キャプション行の直後にあるブロックの種類**から自動で判定されます。そのため、ID自体に `fig-` や `table-` といった接頭辞を付ける必要はありません（付けても構いません）。

## 実践的な使用例

### 図の定義と参照

```markdown
**アインシュタインの写真 @einstein**

![](Einstein.png){width=40% align=center}
```

このように記述すると、次のように表示されます。

:::{.output}
**アインシュタインの写真 @einstein**

![](Einstein.png){width=40% align=center}
:::

この図を参照したいときは、`@einstein` という ID を使って次のように記述します。

```markdown
@einstein は、アインシュタインが自室で研究しているイメージ画像です。
```

このように記述すると、次のように表示されます。{.aki}

:::{.output}
@einstein は、アインシュタインが自室で研究しているイメージ画像です。
:::

`@einstein` は、現在の配置に応じて「図1-1」へ変換されています。図を前後へ追加すれば番号は変わりますが、本文の `@einstein` は変更せずに使えます。

```markdown
**テスト図（自動ID） @auto**

![](Einstein.png){width=30% align=right}
```

`@auto` または `@omakase` でも、図や表に番号を付けられます。本文から参照しない図であれば、個別の ID を命名せずに採番だけを利用できます。

### 表の定義と参照

```markdown
**基本的な表 @basic-table**
| 名前 | 年齢 |     職種     |
| :--: | :--: | :----------: |
| 太郎 |  25  |  エンジニア  |
| 花子 |  30  |  デザイナー  |
| 次郎 |  35  | マネージャー |

@basic-table は、基本的な表の一例です。
```

と記述すると、次のように表示されます。

:::{.output}
**基本的な表 @basic-table**
| 名前 | 年齢 |     職種     |
| :--: | :--: | :----------: |
| 太郎 |  25  |  エンジニア  |
| 花子 |  30  |  デザイナー  |
| 次郎 |  35  | マネージャー |

@basic-table は、基本的な表の一例です。
:::

### コード（リスト）の定義と参照

````
**Rubyサンプルコード @ruby-sample**

```ruby
def hello(name)
  puts "Hello, #{name}!"
end

hello("World")
```
````

このように記述すると、次のように表示されます。

:::{.output}
**Rubyサンプルコード @ruby-sample**

```ruby
def hello(name)
  puts "Hello, #{name}!"
end

hello("World")
```
:::

`@ruby-sample` が「リスト1-1」に自動で変換されています。ソースコードを元に解説をするとき、

```
@ruby-sample は、Ruby で画面表示を行うサンプルコードです。
```

と記述すると、次のように表示されます。

:::{.output}
@ruby-sample は、Ruby で画面表示を行うサンプルコードです。
:::

章の構成を変えてリスト番号が動いても、ID と参照の対応は保たれます。

### コード（リスト）の取り込みと参照

````markdown
**Prime @prime**
```include:prime.rb```

**Prime範囲指定 @prime-range**
```include:prime.rb:14-17```
````

外部ファイルから取り込んだコードにも、通常のコードブロックと同じようにキャプションと ID を付けられます。ビルドすると、次のように表示されます。

:::{.output}
**Prime @prime**
```include:prime.rb```

**Prime範囲指定 @prime-range**
```include:prime.rb:14-17```
:::

取り込んだコードも、定義した `@id` を本文へ書いて参照します。

```markdown
@prime は、Ruby で素数を表示するコードです。
@prime-range は、その一部を指定したコードです。
```

と記述すると、次のように表示されます。

:::{.output}
@prime は、Ruby で素数を表示するコードです。
@prime-range は、その一部を指定したコードです。
:::

### 章間参照

参照の書き方は、同じ章でも別の章でも変わりません。`@einstein`・`@basic-table`・`@prime`・`@prime-range` のような ID は、ビルド時に書籍全体から検索されます。参照元と定義先が離れていても、「図 2-3」「リスト 5-1」のように、現在の章番号を含むリンクになります。

## トラブルシューティング

### よくある問題

#### IDが見つからない
- 原因: タイプミス、または参照先のラベルが定義されていない
- 解決: 定義側のキャプション行（`@id`）のスペルを確認する

#### 重複エラー
- 原因: 同じIDを複数の要素で使用
- 解決: IDを一意になるように変更

#### 番号がおかしい
- 原因: ビルドのキャッシュ残留
- 解決: `vs clean` でクリーンアップ

### エラーメッセージの例

相互参照の問題は、`vs preflight` または `vs build` のメッセージから定義箇所をたどれます。主な表示と対処方法を次に示します。

#### ラベルIDの重複

```
🔴 25-querystream.md:25 - ラベルID '画像(左寄せ) @img-left' は重複しています
        重複箇所: 25-querystream.md: 25, 30
```

同じ `@id` が複数箇所で定義されています。IDは書籍全体で一意にする必要があります。いずれかのIDを変更してください。

#### 孤立ラベル（未参照の警告）

```
🟡 24-cross-reference.md:329 - 孤立ラベル 'Prime @prime' は未参照です
```

定義されたラベルが本文中のどこからも `@prime` で参照されていません。参照を追加するか、不要であればラベル定義を削除してください。これは警告（🟡）であり、ビルドは正常に完了します。

### デバッグ方法

1. **個別ビルド**: `vs build [章番号]` で特定章のみテスト
2. **事前チェック**: `vs preflight` でラベルの重複・未定義・孤立を検出

## まとめ

クロスリファレンスを使うと、原稿に安定した ID を残したまま、読者向けの番号とリンクを現在の章構成に合わせられます。

- **参照の一貫性**: 章番号付きで正確な参照
- **リンク機能**: PDF内でジャンプ可能な相互参照
- **自動管理**: 番号付けの自動化と重複防止
- **柔軟性**: 手動IDと自動IDの使い分け

図表を追加したり章を並べ替えたりしても、著者は内容を表す ID に集中でき、読者には正しい番号が届きます。構成が大きくなるほど、この分担が改稿を支えてくれます。
