# データ展開機能

:::{.chapter-lead}
参考書籍の一覧や各地の観測値のように、同じ形の情報が並ぶページを本文へ直接書くと、項目を追加するたびに書式まで繰り返すことになります。**QueryStream 記法**は、内容を YAML のデータへ、見せ方を Markdown のテンプレートへ分け、必要な項目を原稿へ展開する仕組みです。本章では、最小の例から、絞り込み・並べ替え・表示形式の切り替えへ進みます。データファイルとテンプレートを置けば利用でき、設定ファイルの編集は必要ありません。
:::

## 概要

QueryStream は、データ・テンプレート・原稿内の展開指示という三つの要素で構成されます。それぞれに役割を分けることで、情報を更新する作業と、紙面の見せ方を整える作業を独立して行えます。

| 要素 | 置き場所 | 役割 |
| --- | --- | --- |
| データファイル | `data/*.yml` | 展開するデータの実体（YAML の配列） |
| テンプレート | `templates/_[名前].md` | 一件分の表示の形 |
| QueryStream 記法 | `contents/*.md` の原稿内 | 展開の指示（1 行で完結） |

`vs build` を実行すると、原稿内の QueryStream 記法を起点に、対応するデータとテンプレートが読み込まれます。展開後の Markdown はビルド処理の中で生成され、`contents/` の原稿自体は書き換えられません。原稿には「どのデータを出すか」という短い指示だけが残ります。

## はじめかた

`vs new` で作った本には、書籍紹介のデータとテンプレートが入っています。この二つを例に、三つの要素のつながりを確かめます。

### 手順 1: データファイルを作る

内容を記録する YAML ファイルを `data/` ディレクトリへ置きます。一件分のデータを一つのハッシュで表し、それらを配列として並べます。各項目で同じキーを使うと、テンプレートから共通の名前で値を取り出せます。

```yaml:data/books.yml
- title: たのしいRuby
  author:
    name: 高橋征義
    bio: Rubyist。
  publisher: SBクリエイティブ
  year: 2019
  desc: Rubyを楽しく学べる入門書。
  tags: [ruby, beginner]
  cover: joyful_ruby.webp

- title: はじめてのC
  author:
    name: 椋田 實
    bio: C プログラマ
  publisher: 技術評論社
  year: 2008
  desc: C言語の定番入門書。
  tags: [c, beginner]
  cover: first_c.webp
```

著者の名前と経歴のように関連する値は、`author` の下へまとめられます。テンプレートや抽出条件からは、`author.name` のようにドットでつないで取り出します。

### 手順 2: テンプレートを作る

次に、一件分をどのように表示するかを Markdown のテンプレートへ書きます。ファイルは `templates/` ディレクトリへ置き、名前は先頭の `_`（アンダースコア）に続けてデータ名の**単数形**にします。`data/books.yml` のテンプレートは `templates/_book.md` です。

```markdown:templates/_book.md
:::{.book-card}
![](cover)
**= title**
= author.name 著／= publisher／= year 年

= desc
:::
```

`= title` のように、`=` に続けてキー名を書くと、その位置が各データの値に置き換わります。`![](cover)` には、`cover` に書いた画像ファイルが入ります。周りは通常の Markdown なので、前章までの記法と組み合わせられます。この例では、@ch-figures の章の `.book-card` で書籍を紹介するカードにしています。書名の後の 1 段落目が書誌、空行の後が説明になります。

### 手順 3: 原稿に記法を書く

最後に、データを展開したい位置へ QueryStream 記法を 1 行で書きます。

```markdown
= books
```

`= books` は、`data/books.yml` の全件を読み、`templates/_book.md` で一件ずつ整形する指示です。データ名の複数形 `books` から、単数形のテンプレート `_book.md` が選ばれます。ビルドすると、次のように展開されます。

::::{.output}
= books
::::

データを増やせばカードも増え、テンプレートを直せば全件の見た目がそろって変わります。表紙の画像の置き場所は @pageref:qs-image-location で説明します。

## QueryStream 記法

全件をそのまま出すだけでなく、条件に合うデータを選び、順番や件数、見せ方を指定できます。データ名に続けて、指定をパイプ `|` で区切って並べます。

:::{.diagram}
```text
= [源泉] | [抽出条件] | [並べ替え] | [件数] | [スタイル]
```
:::

源泉以外は省略できます。各指定は書き方から種類が判別されるため、使わない指定のために空のパイプを残す必要はなく、順番を入れ替えても構いません。書いた順番にかかわらず、絞り込み・並べ替え・件数の制限の順に処理します。

### 源泉

最初の指定では、読み込むデータファイルを拡張子なしで指定します。

```markdown
= books            <!-- data/books.yml -->
= prefectures      <!-- data/prefectures.yml -->
```

抽出条件の代わりに値だけを書くと、主キーでデータを一件探します。主キーとして調べるのは `id`・`no`・`code`・`slug`・`name`・`title` で、どれかが一致するデータを展開します。データの種類ごとに検索キーを設定する必要はありません。

```markdown
= book | たのしいRuby   <!-- title が一致するデータ -->
= prefecture | 13      <!-- code が 13 のデータ -->
```

一件を探すときは、データ名を単数形で書きます。`data/book.yml` がなければ、`data/books.yml` が読まれます。単数形にすると、`13` のような数も件数ではなく主キーの値として扱われます（複数形の `= prefectures | 13` は先頭 13 件の指示です）。一致するデータがないときと、複数あるときは 🟡 で警告されます。複数あるときは、一致したデータをすべて展開します。

### 抽出条件

`項目名=値` の形で絞り込みます。

```markdown
= books | tags=ruby                       <!-- タグが ruby のもの -->
= books | tags=ruby, javascript           <!-- ruby または javascript -->
= books | tags=ruby && tags=beginner      <!-- ruby かつ beginner -->
= books | tags=ruby && beginner           <!-- 2 件目以降の項目名を省略 -->
= books | tags=ruby OR year>=2020         <!-- どちらかを満たす -->
= books | author.name=高橋征義            <!-- ネストした値 -->
```

値をカンマで区切ると、同じ項目の値のどれかに等しいデータを選びます。別の項目の条件をつなげるときは、両方を満たすなら `&&`・`AND`・`and`、どちらかを満たすなら `OR`・`or` を使います。`AND` は `OR` より強く結び付きます。`&&` や `OR` の後では、前の条件と同じ項目なら項目名を省けます。`tags=ruby && beginner` は、`tags` に `ruby` と `beginner` の両方を含むデータを選びます。

データ側の値が配列やカンマ区切りの文字列のときは、要素のどれかが一致すれば条件を満たします（@pageref:qs-multi-value）。項目名は半角英数字と `_` で書き、ネストした値は `author.name` のようにドットでつなぎます。

**比較演算子**も使えます。

| 演算子 | 意味 | 例 |
| --- | --- | --- |
| `=` / `==` | 等しい | `region=関東` |
| `!=` | 等しくない | `category!=nonmetal` |
| `>` / `>=` / `<` / `<=` | 比較 | `temp_min_c>=20` |
| `項目=20..25` | 20 以上 25 以下 | `atomic_number=1..6` |
| `項目=20...25` | 20 以上 25 未満 | `temp_min_c=20...25` |
| `項目=20..` | 20 以上 | `population=9000000..` |
| `項目=..25` | 25 以下 | `atomic_number=..3` |
| `項目=...25` | 25 未満 | `year=...2020` |

数はアンダースコアで桁を区切れます（`population>=9_000_000`、万の位で区切る `900_0000`）。日付は西暦でも和暦でも書けます（@pageref:qs-date）。比較と範囲では、値のないデータと、比較できない値のデータ（数と比べるときの `不明` など）を除きます。

条件として読めない指定（`年=2019`・`tags=`）や、どのデータにもない項目（`tags` を `tag` と書いたもの）は、エラーになり、その行は展開されません（@pageref:qs-errors）。

### 並べ替え

並べ替えに使う項目名の前へ、昇順なら `+`、降順なら `-` を付けます。

```markdown
= books | -year                     <!-- 発行年の新しい順 -->
= weather_reports | +date           <!-- 日付の古い順 -->
= books | tags=ruby | +title        <!-- 絞り込み＋並べ替え -->
```

**符号は省略できません。** 符号のない `= books | title` は、`= book | たのしいRuby` と同じ形なので、`title` という値を主キーで探す指示として扱われます。該当するデータがないため 🟡 で警告され、何も展開されません。

値のないデータと、比較できない値のデータは、昇順でも降順でも末尾に置きます。並べ替えを指定しない場合は、YAML に書いた順に出力されます。

### 件数

正の整数で件数を制限します。並べ替えと組み合わせると、並べ替えた後の先頭から数えます。

```markdown
= books | 3                         <!-- 先頭 3 件 -->
= weather_reports | -date | 5       <!-- 新しい日付から 5 件 -->
```

### スタイル

同じデータを別のレイアウトで見せたいときは、`:スタイル名` の形でテンプレートを切り替えます。全件の一覧は表、個別の紹介はカードというように、データを複製せずに表示だけを変えられます。

```markdown
= books | :table                    <!-- _book.table.md を使用 -->
= book | たのしいRuby | :full       <!-- _book.full.md を使用 -->
```

新しいスタイルは、`templates/_book.my_style.md` のようなテンプレートを追加すると利用できます。原稿側では `= books | :my_style` と指定し、設定ファイルへの登録は行いません。

### 組み合わせ例

```markdown
<!-- タグで絞り込み、表で出す -->
= books | tags=ruby | :table

<!-- 複合条件＋並べ替え＋件数＋スタイル -->
= weather_reports | condition=晴, 曇 and temp_min_c>=20 | -date | 5 | :full

<!-- 元素の AND 絞り込み -->
= elements | category=nonmetal AND phase_at_stp=gas | :full
```

## テンプレートの書き方

テンプレートも通常の Markdown ファイルです。文章や装飾はそのまま出力され、`= key` と書いた箇所だけが値に置き換わります。`=` とキー名の間の空白は省いて、`=title` とも書けます。

### 値のない項目

値が設定されていない項目では、そのキーを含む行が省略されます。値のない項目のために空行や「著者:」だけが残らないので、同じテンプレートを情報量の異なるデータに使えます。

1 行に `= key` が二つ以上ある行では、**値のない項目の部分だけ**が省略されます。行は区切り（`／`・`・`・`、`・`，`・`,`、前後に空白のある ` / `）と、`= key` を含む括弧（`（…）`・`(…)`）で部品に分かれ、値のない項目を含む部品だけが、区切りとともに省略されます。`著` や `年` のように `= key` に付けた言葉も、値がなければ一緒に省略されます。手順 2 の `_book.md` の書誌の行は、次のように出力されます。

```markdown
= author.name 著／= publisher／= year 年
```

| データ | 出力 |
|:---|:---|
| すべてある | 高橋征義 著／SBクリエイティブ／2019 年 |
| 発行年がない | 高橋征義 著／SBクリエイティブ |
| 著者だけ | 高橋征義 著 |
| すべてない | 行ごと省略 |

表の行（`|` で始まる行）は列がずれないよう、値のない項目があれば行ごと省略されます。

### 画像の記法

画像の位置に `![](key)` と書くと、括弧の中のキーが、YAML に書いた画像ファイル名に展開されます。後ろに付けた属性はそのまま残ります。`cover` の値が `joyful_ruby.webp` のときは、次のように展開されます。

```markdown
![](cover){width=40% align=right}             <!-- テンプレート -->
![](joyful_ruby.webp){width=40% align=right}  <!-- 展開後 -->
```

`cover` の値がなければ、行ごと省略されます。拡張子を付けて書いた画像は、キーとしては扱わず、そのまま出力します。

| 記法 | 解釈 |
| --- | --- |
| `![](cover)` | キーの値に展開（値がなければ行を省略） |
| `![](= cover)` | 同上（キーであることを明示） |
| `![](author.avatar)` | ネストした値に展開 |
| `![](photo.png)` | 拡張子があるので、そのまま出力 |

### 画像ファイルの置き場所 @qs-image-location

`cover:` などで指定した画像ファイルは、次のいずれかに置きます。ビルド時にこの順で探し、最初に見つかった場所を使います。

1. `images/<章スラッグ>/` — QueryStream 記法を書いた章の画像ディレクトリ（章ごとに差し替えたいとき）
2. `data/<データ名>/` — データファイルと同じ名前のフォルダ（`data/books.yml` なら `data/books/`）。データと画像を一つのフォルダにまとめて、別の本へ持ち運べます
3. `data/images/` — 複数のデータで共有する画像の置き場

本章の例の表紙は、1 の `images/26-querystream/` に置いています。`data/` に置いた画像は、拡張子の違う `.webp`・`.png`・`.jpg`・`.jpeg` も探します（`.webp` を優先）。どこにも見つからないときは、探した 3 箇所を挙げて警告されます。

### 表のテンプレート

複数件を比べるときは、表の形のテンプレートも使えます。`= key` を含む行だけが件数分繰り返され、見出しと区切りの行は一度だけ出力されます。

```markdown:templates/_book.table.md
| 書名 | 著者 | 出版社 | 発行年 |
| --- | --- | --- | --- |
| = title | = author.name | = publisher | = year |
```

`= books | :table` と書くと、次のように展開されます。

:::{.output}
= books | :table
:::

### テンプレートの名前

テンプレートの名前は、次の決まりで付けます。

- 先頭に `_` を付けます
- データ名の**単数形**を使います（`books` → `_book.md`）
- スタイルはドットで区切ります（`_book.table.md`）

データ名の英語の複数形は、規則どおりに単数形へ変換されます（`books` → `book`、`categories` → `category`、`people` → `person`）。名前に `_` や数字を含むときは、複数形の部分だけが変換されます。

| データファイル | テンプレート |
| --- | --- |
| `data/books.yml` | `templates/_book.md` |
| `data/books.yml` と `:table` | `templates/_book.table.md` |
| `data/physics_books.yml` | `templates/_physics_book.md` |
| `data/books2.yml` | `templates/_book2.md` |

## データファイルの書き方

### 基本構造

`data/` ディレクトリに YAML ファイルを置きます。拡張子を除いたファイル名が、そのままデータ名になります。拡張子は `.yml` のほか、`.yaml` と `.json` も使えます。

```yaml:data/prefectures.yml
- name: 北海道
  capital: 札幌市
  region: 北海道
  code: 1
  population: 5224614

- name: 東京都
  capital: 新宿区
  region: 関東
  code: 13
  population: 14047594
```

### 複数の値を持つ項目 @qs-multi-value

タグのように複数の値を持つ項目は、YAML の配列でも、カンマ区切りの文字列でも書けます。抽出条件では、どちらも複数の値として同じように扱われます。

```yaml
# 配列形式
tags: [ruby, beginner]

# カンマ区切り形式（同じ結果）
tags: ruby, beginner
```

テンプレートに書いた `= tags` は、配列なら値を「、」でつないで `ruby、beginner` と表示されます。カンマ区切りの文字列は、書いたとおりに表示されます。空の配列（`[]`）は、値がないものとして扱われます。

### 日付 @qs-date

日付は `2024-01-01` のように書きます。引用符で囲んでも囲まなくても構いません。和暦でも書けます。元号は頭文字（`M` 明治・`T` 大正・`S` 昭和・`H` 平成・`R` 令和）で書き、年は 1 桁でも構いません。データでも抽出条件でも、どの書き方も同じ日付として比べ、並べ替えます。

```yaml
date: 2024-01-01
date: "2024-01-01"  # 同じ日付
date: R06-01-01     # 和暦（同じ日付）
```

## エラーメッセージ @qs-errors

データ名・スタイル名・キー名に誤りがあると、`vs build` の実行時に、直す場所を含むエラーが表示されます。エラーになった行は展開されず、記法のまま紙面に残ります。

### ファイルが見つからない場合

テンプレートやデータファイルが見つからないときは、探した場所が表示されます。スタイル名・データ名の打ち間違いか、ファイルの置き忘れを確かめてください。

:::{.output}
```text
🔴 05-references.md:12 - テンプレート '_book.fancy.md' が見つかりません（記法: = books | :fancy）
        テンプレートの場所: templates/_book.fancy.md
        ヒント: templates/_book.md は存在します。スタイル名を確認してください。
🔴 05-references.md:14 - データファイルが見つかりません（記法: = movies）
        データの場所: data/movies.yml
```
:::

### 抽出条件や並べ替えに誤りがある場合

どのデータにもない項目を使うと、近い名前の項目と、使える項目の一覧が表示されます。条件として読めない指定（`年=2019`・`tags=`）には、書き方の例が表示されます。

:::{.output}
```text
🔴 05-references.md:16 - データにない項目です: tag（記法: = books | tag=ruby）
        → もしかして: tag ではなく tags ではありませんか？
        このデータで使える項目: title, author, publisher, year, desc, tags, cover
```
:::

### テンプレートのキーに誤りがある場合

テンプレートに、どのデータにもないキーを書くと、直すテンプレートの場所と、近い名前のキーが表示されます。どれか 1 件のデータにあるキーは正しいキーとみなされるので、値を省いたデータがあっても、同じテンプレートを使えます。

:::{.output}
```text
🔴 05-references.md:18 - テンプレートにないキーが書かれています: =titel
        直す場所: templates/_book.md
        → もしかして: =titel ではなく =title ではありませんか？
        このテンプレートで使えるキー: title, author, publisher, year, desc, tags, cover
```
:::

`= author` のように、中に値を持つキーをそのまま書いたときも、エラーになります。どの値をどう並べるかを決められないためです。中のキーまで書いた形が表示されます。

:::{.output}
```text
🔴 05-references.md:20 - そのままでは表示できないキーです: =author
        直す場所: templates/_book.table.md
        → =author.name のように、中のキーまで書いてください。
        中のキー: name, bio
```
:::
