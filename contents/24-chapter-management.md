# 章の管理

:::{.chapter-lead}
執筆を進めていると、章を増やす、順番を変える、いったん外すといった構成の見直しが何度も起こります。Vivlio Starter では、章の作成・削除・名前の変更・番号の付け直しをコマンドで行えます。原稿と一緒に `catalog.yml` や画像ディレクトリも更新されるので、関連する箇所を探して直す必要はありません。本章では、まずコマンドで章を指定する方法を説明し、続いて構成を変える四つのコマンドを紹介します。
:::

## コマンドで章を指定する @chapter-targets

:::{.section-lead}
`vs build`・`vs preflight`・`vs lint`・`vs metrics`・`vs delete` など、章を受け取るコマンドは、どれも同じ書き方で章を指定できます。
:::

### 章の書き方

章のファイル名は、`11-intro.md` のように、2 桁の章番号と**スラッグ**をハイフンでつないだ形です。スラッグは、章の内容を表す短い英語の名前で、章のラベル（`@ch-intro`）にも使われます。章は、ファイル名のほか、番号だけ・スラッグだけでも指定できます。

| 書き方 | 例 | 指す章 |
| :--- | :--- | :--- |
| ファイル名 | `11-intro` | `contents/11-intro.md` |
| 番号だけ | `11` | 番号が 11 の章 |
| スラッグだけ | `intro` | スラッグが `intro` の章 |
| 範囲 | `11-13` | 11〜13 番の間にある章 |

番号は 2 桁にそろえて読むので、`vs build 1` は `vs build 01` と同じです。`contents/11-intro.md` のようにパスと拡張子を付けて書いても構いません。複数の章は、空白かカンマで区切って並べます（`vs build 11 12`・`vs build 11,12`）。

番号や名前で指定した章が見つからないときは、処理を中止します。綴りの近い章があれば、その名前を一つ表示します。

:::{.memo}
**スラッグの付け方**: 半角の英小文字・数字・ハイフンで付けます（例：`intro`、`setup`、`appendix-a`）。大文字・アンダースコア・点・空白・日本語を含む名前は使えません。`vs create` で作るときは、大文字とアンダースコアを小文字とハイフンに直して作ります。Finder で複製した `95-sample のコピー.md` のように手で付けた名前があると、ビルドの前に処理を中止し、使える名前に変更するコマンドを表示します。
:::

### 範囲で指定する

範囲は、その番号の間にある章を指します。章の番号は飛び飛びに振るので、`vs build 00-11` は、間にある章だけを組みます。`13-11` のように大きい番号から書いても同じです。範囲を指定すると、対象になる章が最初に表示されます。

:::{.output}
```text
💡 00-11 のうち、原稿のある 2 章（00-preface, 11-intro）をビルドします
```
:::

範囲に章が一つもないときは処理を中止し、範囲の手前と後ろにある章を表示します。

### 対象になるのは `catalog.yml` に載った章

章を指定しないと、`config/catalog.yml` に載っているすべての章が対象になります。コメントアウトした章や、載せていない章は対象外です。

```yaml
# config/catalog.yml
CHAPTERS:
  - 11-intro
  - 12-basics
  # - 13-advanced  # コメントアウトした章は対象外
```

`vs build`・`vs preflight` は、章を指定したときも `catalog.yml` に載っている章だけを組みます。範囲の中に載っていない原稿があれば除外し、範囲の 💡 の行にそのことを添えます。載っていない章を名指ししたときは、何もせずに処理を中止し、`catalog.yml` へ追加するよう案内します。`vs lint`・`vs metrics` は原稿を読むだけなので、載っていない原稿も対象にします。

`catalog.yml` の書き方（章の並べ方・分冊）は @pageref:catalog-yml で説明します。

## `vs create` — 章を作成する

:::{.section-lead}
`vs create` は、章の Markdown ファイルと画像ディレクトリを作り、`config/catalog.yml` に章を登録します。新しい章を書き始めるための準備が、一度の操作でそろいます。
:::

### 基本的な使い方

```bash
vs create 11-intro
```

`contents/11-intro.md` と `images/11-intro/` を作り、`config/catalog.yml` の番号順の位置に `11-intro` を追加します。複数の章も一度に作れます（`vs create 11-intro 12-basics 13-advanced`）。

ほかの章が使っている番号やスラッグは指定できません。番号やスラッグで章を指定したときに、どちらの章か決められなくなるためです。指定すると章を作らずに処理を中止し、空いている番号（同じ区分で、指定した番号の後ろの番号）やスラッグ（`-2` を付けたもの）で作るコマンドを表示します。

:::{.output}
```text
🔴 エラー: 以下の章は、番号かスラッグが既に使われています:
🔴   - 95-foo（95 番は 95-sample が使っています） → vs create 96-foo
🔴   - 02-sample（スラッグ sample は 95-sample が使っています） → vs create 02-sample-2
```
:::

`vs rename` で番号やスラッグを変えるときも、同じように確かめます。

### 番号やスラッグを省いて作る

スラッグがまだ決まっていないときは、番号だけで作れます。この場合、ファイル名は `11.md` になります。

```bash
vs create 11
```

反対に、番号を省いてスラッグだけを書くと、本文の最後の章の次の番号で作ります。

```bash
vs create advanced
```

`12-basics` まである本なら、`13-advanced` ができます。分冊の本では、最後の巻の末尾に入ります。最後の章が 89 番のときは、空いている番号のうちもっとも小さいものを使います。章と章の間に入れるときは、`vs create 12-basics` のように番号も書いてください。

### 章の種類に合った雛形を使う

章ファイルの初期内容は、`templates/` ディレクトリの雛形から作られます。前書き・本文・付録・後書きでは必要な構成が異なるので、章番号に応じて雛形を使い分けます。

| 章番号 | 雛形 | 用途 |
| :--- | :--- | :--- |
| 00 | `templates/preface.md` | 前書き・はじめに |
| 01〜89 | `templates/chapter.md` | 本文の章 |
| 90〜98 | `templates/appendix.md` | 付録 |
| 99 | `templates/postface.md` | 後書き・おわりに |

雛形の `{{TITLE}}` には、作成時に指定したスラッグ（番号だけで作ったときは番号）が入ります。雛形が見つからないときは、見出しと一行の本文だけのファイルを作ります。

本文の章の雛形 `templates/chapter.md` には、リード文・節・小見出し・箇条書き・コード・表・図・補足の囲みが並んでいます。不要な部分を削除し、見出しと本文を書き換えて使います。雛形はその本に合わせて編集できます。いつも置く節や章末の案内を加えておくと、以後 `vs create` で作る章に同じ構成が入ります。

### 記法の見本をコピーして使う

使える記法は、すぐに使える形で `templates/markdown_snippet.md` にまとめてあります。並びは @chapref:ch-notation-cheatsheet と同じで、早見表の各行の例がそろっています。使いたい記法を見つけたら、その例を原稿へコピーし、内容だけを書き換えてください。このファイルは `contents/` の外にあるので、ビルドの対象にはなりません。

## `vs delete` — 章を削除する

:::{.section-lead}
`vs delete` は、章の Markdown ファイル・画像ディレクトリ・`catalog.yml` の項目をまとめて削除します。削除する前に、ファイルとディレクトリごとに確認を求めます。
:::

```bash
vs delete 11-intro
```

`contents/11-intro.md` と `images/11-intro/` を、それぞれ確認してから削除します。

:::{.output}
```text
❓ 本当に 文書ファイル: contents/11-intro.md を削除しますか？ [y/N]: y
❓ 本当に 画像ディレクトリ: images/11-intro を削除しますか？ [y/N]: y
✅ 削除しました（文書 1 件・画像ディレクトリ 1 件）
```
:::

原稿を削除すると、`catalog.yml` の項目と、索引辞書の主要参照（`main:`）のうちこの章を指すものも削除します。原稿の削除に「いいえ」と答えたときは、どちらもそのまま残ります。原稿が無く `catalog.yml` にだけ載っている章は、項目を削除してよいかを確認します。

章は @pageref:chapter-targets の書き方で指定できるので、`vs delete 11` や、範囲を指定した `vs delete 11-13` も使えます。

削除した原稿は元に戻せないので、確認は省けません。`vs delete` は端末から実行してください。パイプで答えを渡すスクリプトからは実行できません。

## `vs rename` — 章のスラッグと番号を変更する

:::{.section-lead}
`vs rename` は、章の番号やスラッグを変更します。原稿のファイル名と一緒に、画像ディレクトリ名・`catalog.yml` の項目・本文の章参照なども書き換えます。
:::

```bash
vs rename 11-intro 12-introduction
```

変更の内容を表示して確認を求め、`contents/11-intro.md` を `12-introduction.md` に、`images/11-intro/` を `images/12-introduction/` に変更します。スラッグが変わるときは、本文の章参照も書き換えます。

:::{.output}
```text
章名・番号変更: 11-intro →  12-introduction
本文の章参照: @ch-intro の 1 箇所を @ch-introduction へ書き換えます
❓ 章名・番号変更を実行しますか？ [y/N]: y
✅ 本文の章参照 1 箇所を @ch-intro から @ch-introduction へ書き換えました
✅ 11-intro を 12-introduction に変更しました
```
:::

番号とスラッグの片方だけを変えるときは、変える側だけを書きます。

| 書き方 | 変更後 |
| :--- | :--- |
| `vs rename 11 12` | `12-intro.md`（番号だけ変える） |
| `vs rename 11-intro introduction` | `11-introduction.md`（スラッグだけ変える） |

変更できるのは、`catalog.yml` に載っている章です。スクリプトから実行するときは、`yes | vs rename 11 12` のように、確認の答えを標準入力から渡します。

### 章名の変更に合わせて書き換わるもの

`vs rename` と、次の節の `vs renumber` は、原稿のファイル名と一緒に、その章名を使っている次の箇所も書き換えます。

| 書き換わるもの | 内容 |
| :--- | :--- |
| `catalog.yml` | 章の並び |
| `images/<章名>/` | 章の画像ディレクトリ |
| 本文の章参照 | `@ch-intro` など（スラッグが変わるとき） |
| 索引辞書の主要参照 | `main:` が指す章名（→ @ch-index-glossary） |
| 索引から外す章 | `book.yml` の `index_glossary.exclude_chapters`（範囲は除く） |

変更先の画像ディレクトリがすでにあるときは、画像ディレクトリだけは移動せずに警告を表示します。二つのディレクトリの中身は、手作業でまとめてください。章のファイルをコマンドを使わずに移動・削除したときは、これらの箇所も手作業で直します。

## `vs renumber` — 章番号を一括で付け直す

:::{.section-lead}
`vs renumber` は、本文の章と付録の番号を、それぞれ連番に付け直します。章の追加や削除を重ねて、番号の間隔が不ぞろいになったときに使います。
:::

```bash
vs renumber
```

本文の章（01〜89）は先頭の章の番号から、付録（90〜98）は 90 から、順に番号を振ります。付け直す前に、番号が変わらない章も含めて新旧の対応を表示し、確認を求めます。

:::{.output}
```text
章の刻み幅: 1
対象ファイル:
通常の章:
  11-intro      →  11-intro
  13-basics     →  12-basics
  15-advanced   →  13-advanced
付録:
  91-appendix-b →  90-appendix-a
  93-appendix-d →  91-appendix-b
❓ 連番付け直しを実行しますか？ [y/N]:
```
:::

この例では先頭の章が `11` なので、`11, 12, 13` と振られます。`01` からではありません。付録のスラッグにある `appendix-a`〜`appendix-i` の記号も、新しい番号に合わせて付け替わります（90 が a、91 が b）。本に載せる順は `catalog.yml` に書いた順なので、番号を付け直しても変わりません。

### 刻み幅を指定する（`--step`）

```bash
vs renumber --step 2
```

章番号を `11, 13, 15, ...` のように二つずつ空けて振ります（短縮形は `-s 2`）。番号の間が空くので、後から章を挿入しても、後ろの章の番号を変えずに済みます。この刻み幅では 89 を超えるほど章が多いときは、刻み幅を自動で小さくします。

### 別の番号帯へ移す

`vs renumber` は、本文の章と付録の番号帯をまたいで番号を振らず、前書き（00）と後書き（99）も変更しません。別の番号帯へ移すときは、`vs rename` で移動先の番号を書きます。

```bash
vs rename 00-preface 11-preface   # 前書きを本文に移す
vs rename 45-utility 91-utility   # 本文を付録に移す
```
