# 章の管理

:::{.chapter-lead}
執筆を進めていると、章を増やす、順番を変える、いったん外すといった構成の見直しが何度も起こります。Vivlio Starter では、章ファイルの作成・削除・名前変更・連番整理をコマンドから行えます。原稿だけでなく、`catalog.yml` や画像ディレクトリも一緒に更新されるため、章立てを変えるたびに関連箇所を探して直す必要がありません。本章では、構成を育てていくための四つのコマンドを説明します。
:::

## vs create — 章ファイルを作成する

:::{.section-lead}
`vs create` は、章の Markdown ファイルと画像ディレクトリを同時に作り、`config/catalog.yml` へ章を登録します。新しい章を書くための置き場所が、一度の操作で揃います。
:::

### 基本的な使い方

```bash
vs create 11-intro
```

`contents/11-intro.md` と `images/11-intro/` が生成され、`config/catalog.yml` に `11-intro` が追記されます。

:::{.memo}
**「スラッグ」とは**、ファイル名のうち、章番号に続く短い識別名です。`11-intro` なら、`11` が章番号、`intro` がスラッグにあたります。半角英数字とハイフンを使い、章の内容を短い英単語で表すのが一般的です（例：`intro`、`setup`、`appendix-a`）。章題が後から変わっても扱いやすい、ファイル上の名前として使います。
:::

### 番号のみで作成

章の内容を表すスラッグがまだ決まっていないときは、番号だけでも作成できます。この場合は `11.md` のようなファイル名になります。

```bash
vs create 11
```

### 複数の章を一度に作成

```bash
vs create 11-intro 12-setup 13-advanced
```

### 番号を省略して作成

章番号を省略すると、既存の章と重複しない番号が割り当てられます。番号より先に章の役割だけが決まっているときに使えます。

```bash
vs create intro setup advanced
```

### テンプレートの自動選択

章ファイルの初期内容は、`templates/` ディレクトリにあるテンプレートから作られます。前書き・本文・付録・後書きでは必要な構成が異なるため、章番号の範囲に応じて使うテンプレートも切り替わります。

| 章番号の範囲 | 使用テンプレート | 用途 |
|-------------|----------------|------|
| 00 | `templates/preface.md` | 前書き・はじめに |
| 01-89 | `templates/chapter.md` | 通常の章 |
| 90-98 | `templates/appendix.md` | 付録 |
| 99 | `templates/postface.md` | 後書き・おわりに |

テンプレートはプロジェクト内の `templates/` ディレクトリにあり、その本の書き方に合わせて編集できます。`{{TITLE}}` には、作成時に指定したスラッグが入ります。章ごとに繰り返す構成があれば、原稿へ毎回書くのではなくテンプレートへまとめられます。

テンプレートが見つからない場合は、最小限の骨子が生成されます。

### 生成されるファイルの中身

通常章の雛形 `templates/chapter.md` には、一章分の骨組みが用意されています。リード文・節・小見出し・箇条書き・コードブロック・画像・まとめが並んでいるので、空のファイルから構成を考えず、章に必要な部分を残して書き始められます。

```markdown
# {{TITLE}}

:::{.chapter-lead}
各章の冒頭に置く短い導入文です。この章で扱うテーマと、読み終えたときに
何ができるようになるのかを伝えます。
:::

章の書き出しです。リード文で示したテーマを、もう少しだけ具体的に開いて
いきます。

## 節のタイトル

:::{.section-lead}
節の導入文です。この節で何を扱うのかを数行で示します。
:::
```

雛形は完成形を強制するものではありません。不要な部分を外し、章の内容に合わせて見出しと本文を書き換えていけば、その本に合った構成になります。

:::{.tip}
雛形は自由に編集できます。いつも置く節や注意書き、章末の案内などを `templates/chapter.md` に加えておくと、以後 `vs create` で作る章に同じ構成が入ります。複数の章に共通する型をここへ集めると、書籍全体の調子も揃えやすくなります。
:::

#### 記法の見本をコピーして使う

表・数式・図解注釈・会話文・ダイアグラム・相互参照・索引・データ展開の記法は、すぐに使える形で `templates/markdown_snippet.md` にまとめています。使いたい記法を見つけたら、その例を原稿へコピーし、内容だけを書き換えてください。囲みや属性を一から入力せずに済み、記号の抜けやクラス名の綴り違いも防げます。

このファイルは `catalog.yml` に登録されておらず、ビルドの対象にもなりません。原稿へ掲載されることはないので、必要な記法を取り出すための見本帳としてプロジェクトに残しておけます。

## vs delete — 章を削除する

:::{.section-lead}
`vs delete` は、章の Markdown ファイル・画像ディレクトリ・`catalog.yml` の登録をまとめて削除します。原稿と関連ファイルを一緒に扱う操作なので、削除前には確認が表示されます。
:::

### 基本的な使い方

```bash
vs delete 11-intro
```

`contents/11-intro.md`、`images/11-intro/`、`catalog.yml` のエントリが削除されます。

### 章番号で指定

```bash
vs delete 11
```

`11-` で始まるファイルを自動で特定して削除します。

### 範囲指定

```bash
vs delete 11-13
```

11〜13 番の章をまとめて削除します。

### 確認をスキップする（--force）

```bash
vs delete 11-intro --force
```

確認プロンプトをスキップして即座に削除します。

### オプション一覧

| オプション | 説明 |
|------------|------|
| `--force` / `-f` | 確認なしで削除 |
| `--yes` / `-y` | `--force` と同じ意味 |


## vs rename — 章のスラッグ / 番号を変更する

:::{.section-lead}
`vs rename` は、章の Markdown ファイル名・画像ディレクトリ名・`catalog.yml` の登録を一括で変更します。章番号とスラッグのどちらか一方だけを変えることもできます。
:::

### 基本的な使い方

```bash
vs rename 11-intro 12-introduction
```

`11-intro.md` → `12-introduction.md`、`images/11-intro/` → `images/12-introduction/` に変更し、`catalog.yml` も更新されます。

### 番号だけを変更する

```bash
vs rename 11 12
```

スラッグはそのままで、番号だけを変更します。`11-intro.md` → `12-intro.md` のように変換されます。

### スラッグだけを変更する

```bash
vs rename 11-intro introduction
```

章番号はそのまま保たれ、`11-intro.md` が `11-introduction.md` に変更されます。

### 確認をスキップする（--force）

```bash
vs rename 11-intro 12-introduction --force
```

### オプション一覧

| オプション | 説明 |
|------------|------|
| `--force` / `-f` / `-y` | 確認なしで変更を実行 |

### 章名の変更に追随するもの

`vs rename` と `vs renumber` は、章のファイル名だけでなく、その名前を参照している関連箇所も更新します。

| 追随するもの | 内容 |
| :--- | :--- |
| `config/catalog.yml` | 章の並び順の定義 |
| `images/<章名>/` | 章専用の画像ディレクトリ |
| 索引辞書の主要参照 | `main:` が指す章名（→「索引・用語集機能」） |

## vs renumber — 章番号を一括で付け直す

:::{.section-lead}
`vs renumber` は、通常章と付録の番号を、それぞれの範囲内で連続するように付け直します。章の追加や削除を重ねて番号の間隔が不揃いになったときに、書籍全体をまとめて整理できます。内部では `vs rename` と同じ仕組みを使います。
:::

### 基本的な使い方

```bash
vs renumber
```

`contents/` 内の通常章（01-89）を先頭章の番号から順に、付録（90-98）を 90 から順に振り直します。番号が変わらない章も含めて全件を並べたうえで、確認プロンプトが表示されます。

実行例：

```
章の刻み幅: 1
対象ファイル:
通常の章:
  11-intro      →  11-intro
  13-setup      →  12-setup
  15-advanced   →  13-advanced
付録:
  91-appendix-a →  90-appendix-a
❓ 連番付け直しを実行しますか？ [y/N]:
```

この例では先頭章が `11` なので、そこを起点に `11, 12, 13` と詰められます。`01` から振り直されるわけではありません。

### 刻み幅を指定する（--step）

```bash
vs renumber --step 2
# または短縮形
vs renumber -s 2
```

章番号を `1, 3, 5, ...` のように二つずつ空けて振り直します。番号の間に余地ができるため、後から章を挿入しても、その後ろをすぐに改番せずに済みます。

### 確認をスキップする（--force）

```bash
vs renumber --force
```

### オプション一覧

| オプション | 説明 |
|------------|------|
| `--force` / `-f` / `-y` | 確認なしで実行 |
| `--step <n>` / `-s <n>` | 章番号の刻み幅（既定: 1） |

## 注意事項

:::{.section-lead}
章管理コマンドは、原稿と `catalog.yml` を対応させたまま操作します。ファイルを手作業で移動・削除した場合は、その変更を `catalog.yml` にも反映してください。
:::

- `vs renumber` 実行後は、古い章番号で生成されたビルド中間ファイル（`.html` など）が `vs clean` と同じ処理で自動削除されます
- 画像ディレクトリが移動先にすでに存在する場合は、手動での統合が必要です
- 付録（90-98）の章番号を変更すると、`appendix-a` などのスラッグも自動で調整されます

### 章番号の種別と `vs renumber` の範囲

Vivlio Starter は章番号の範囲によって、前書き・本文・付録・後書きを区別します。`vs renumber` は、この区分を保ったまま、それぞれの範囲内で連番を振り直します。

| 番号帯 | 種別 | `vs renumber` の動作 |
|---|---|---|
| 00 | 前書き（preface） | 対象外（固定） |
| 01–89 | 本文（chapter） | 先頭章の番号を起点に連番を付与 |
| 90–98 | 付録（appendix） | 90 から連番を付与（スラッグも自動調整） |
| 99 | 後書き（postface） | 対象外（固定） |

前書き（00）と後書き（99）は位置が固定されているため、`vs renumber` では番号が変わりません。本文の章を増減しても、前書き・本文・付録・後書きの区分は保たれます。

章の役割そのものを変え、別の番号帯へ移す場合は、`vs rename` で移動先の番号を明示します。

```bash
# 前書きを本文に移す
vs rename 00-preface 11-preface

# 本文を付録に移す
vs rename 45-utility 91-utility
```
