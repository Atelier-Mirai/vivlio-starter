# 索引・用語集機能

:::{.chapter-lead}
著者にはよく分かっている本の構成も、必要な情報を探してページを開く読者には見えていません。索引は説明のある場所へ案内し、用語集は読み進めるために必要な意味を補います。本章では、`vs index` コマンドを使った、用語の登録から候補の抽出、レビュー、索引・用語集ページの生成までを紹介します。
:::

## 索引と用語集ができるまで

:::{.section-lead}
索引・用語集に載せる語は、二通りの方法で登録します。原稿に印を付けて登録する方法と、原稿から候補を拾い出して選ぶ方法です。どちらで登録した語も一つの辞書にまとまり、ビルドのたびに原稿から出現箇所を探して、索引・用語集のページが組まれます。
:::

### 作業の流れ

```bash
# 0. 原稿に [用語|読み] と書いて、必ず載せたい語を登録する（任意）

# 1. 索引語の数の目安を確かめる（任意）
vs index:plan

# 2. 原稿から候補を拾い、レビューファイルを作る
vs index:auto

# 3. レビューファイル _index_glossary_review.md をエディタで開き、
#    採用する語に [i]（索引）・[g]（用語集）・[ig]（両方）、外す語に [r] を付ける

# 4. レビューの結果を辞書へ反映する
vs index:apply

# 5. 索引・用語集ページを含めてビルドする
vs build
```

手順 2〜4 が中心です。`vs index:auto` が作る **`_index_glossary_review.md`** を、本章では「レビューファイル」と呼びます。候補の一覧に前後の文脈が添えてあり、著者はこのファイルに印を書き込んで採否を決めます。候補を拾うのは機械でも、どの語を読者への入口にするかを決めるのは著者です。

### 使うファイル

- `_index_glossary_review.md`: レビューファイル。`vs index:auto` が作り、著者が編集する
- `config/index_glossary_terms.yml`: 採用した語の辞書（索引・用語集共通）。`vs index:apply` が書く
- `config/index_glossary_rejected.yml`: 外した語の一覧。次からは候補に挙がらない
- `config/index_yomi_overrides.yml`: 読みの個人辞書（MeCab の推測より優先）
- `index_library.yml`: 別の本へ持ち運ぶための書き出し（後述）

## 原稿に印を付けて登録する

:::{.section-lead}
索引へ必ず載せたい用語は、原稿の中で明示できます。章の中心概念や、読者が別の呼び方から探しそうな語など、著者の判断を確実に反映したいときに使います。
:::

### 基本的な記法

原稿内で `[用語|読み]` または `[用語]` の形式で印を付けます。このように本文に印を付けて語を載せる方法を**手動登録**と呼びます。`vs index:auto` が候補を拾う**自動抽出**と対になる方法です。

```markdown
[Ruby|るびー]は素晴らしいプログラミング言語です。

[JavaScript]を使ってウェブページに動きを付けます。
```

- `[用語|読み]` - 用語と読み（ひらがな）を指定
- `[用語]` - 用語のみ（読みは MeCab で自動推測）

紙面では `[`・`|`・`]` が取り除かれ、用語だけが組まれます。たとえば次の文には、原稿に `[五十音順|ごじゅうおんじゅん]` と書いてあります。

索引の見出しは[五十音順|ごじゅうおんじゅん]に並びます。

巻末の索引で「五十音順」を引くと、このページの番号が載っています。印を付けた語は、自動抽出のスコアにかかわらず必ず索引に載り、あとで述べる「見直し候補」にも挙がりません。

:::{.note}
**読みを添える**

日本語の用語を五十音順に並べるには、読みが必要です。省略した読みは MeCab（形態素解析エンジン）で推測しますが、固有名詞や専門用語では正しく読めないことがあります。重要な用語には読みを添えておくと、意図した位置へ確実に並べられます。読みは並べ替えに使う欄なので、仮名で書きます。
:::

### 記号やタグを登録する

記号や HTML タグなども索引に登録できます。

```markdown
[!]は否定演算子です。
[&&]は論理積演算子です。
[||]は論理和演算子です。
[<h1>]は見出しタグです。
```

半角の英数字・記号だけで 2 文字以下の用語（`[g]`・`[eV]`・`[Hz]` など）は、単位やフラグの表記と紛れやすいので、`vs index:auto` では辞書に登録しません（登録しなかったことを知らせます）。辞書に登録して本文全体から拾いたいときは、`[eV|いーぶい]` のように仮名の読みを添えて書いてください。

### 索引記法として読まないもの

次の書き方は索引として扱いません。

- `[リンクテキスト](URL)` - Markdown のリンク
- `[^1]` - 脚注の参照
- コードブロックとインラインコードの中の `[...]`

## 候補を拾って選ぶ

:::{.section-lead}
すべての索引語を手で拾う代わりに、`vs index:auto` で原稿から候補を拾い出せます。結果はレビューファイルにまとまり、前後の文脈を見ながら採否を決められます。
:::

### `vs index:auto` — 候補を拾い出す

```bash
vs index:auto              # catalog.yml に載っている全章から
vs index:auto 21           # 21 章だけから
vs index:auto 21-23,25     # 範囲・複数指定も可
```

原稿から、定義の文（「〜とは」）に現れる語・カタカナ語や英語・名詞の連なり・節の見出しに現れる語を候補として拾い、重要そうな順に並べてレビューファイルへ書き出します。コード・実行結果・図解注釈の注釈行・画像の代替テキストは読みません。章を指定すれば、書き終えた範囲だけを見直せます。章を指定しても、ほかの章で登録済みの語が消えることはありません。

:::{.memo}
**候補の並べ方**

特定の章に集中して現れる語ほど、上に並びます（TF-IDF という、文書検索で使われる指標です）。定義の文に現れる語・カタカナ語や英語・名詞の連なりには点を足し、節の見出しに現れる語にはいちばん大きく足します。見出しは「この節は何を説明するか」を示すので、そこに出る語は索引の入口になりやすいためです。2 字の語（扉絵・脚注など）は、見出しに出るものだけを候補にします。

出現回数はそのまま点にならないので、「ファイル」「コード」のようにどの章にも大量に出る語が上位を占めることはありません。多くの章の見出しに出る語（「まとめ」「設定」）には、見出しの点を足しません。表の列に並ぶ値や、「表示結果は次のようになります」のような決まり文句の中の語も、候補から外します。
:::

### レビューファイルを読む

レビューファイル `_index_glossary_review.md` は四つのセクションに分かれています。

```markdown
# 索引・用語集レビュー
※ フラグ: [i]=索引のみ、[g]=用語集のみ、[ig]=両方、[r]=棄却、[-i]=索引から除外、[-g]=用語集から除外
※ 読みの修正は ( ) 内を編集。用語集の説明文は空行の後にインデントして記述。

## 1. 登録済み用語の確認 (Terms: N語)
- [ig] `Today` **Ruby** (るびー) - [手動登録]
  - 11-intro: Rubyは素晴らしい...

  まつもとゆきひろが作成したプログラミング言語。

## 2. 推奨候補 (High Candidates: N語)
- [ ] `NEW!` **JavaScript** (じゃばすくりぷと) - スコア: 250.5
  - 12-basics: JavaScriptを使って...

## 3. 一般候補 (Low Candidates: N語)
- [ ] `NEW!` **変数** (へんすう) - スコア: 150.2
  - 13-advanced: 変数とは...

## 4. 除外済みリスト (Rejected: N語)
※ 復帰させたいものは [i], [g], [ig] を入れると候補に戻ります。
- [ ] `Today` **フォー** (フォー) - スコア: 340.7
  - 00-preface: お問い合わせフォーム...
```

| 節 | 中身 | 確認のしかた |
|:---|:---|:---|
| 1. 登録済み用語 | すでに辞書にある語 | 誤りがないか流し読みする |
| 2. 推奨候補 | 目安の語数に入るほど重要なのに、まだ登録していない語 | ここを中心に採否を決める |
| 3. 一般候補 | 推奨には届かないが検討に値する語 | 余裕のあるときに見る |
| 4. 除外済みリスト | 過去に外した語 | 復帰させたいものだけ拾う |

用語の頭のラベルは、その語がいつ入ってきたかを示します。`NEW!` は今回はじめて挙がった候補、`Today` は今日辞書に登録した語、ラベルなしはそれ以前から辞書にある語です。

### フラグを付けて採否を決める

各行の先頭の `[ ]` に、次のフラグを書き込みます。

| フラグ | 説明 |
|:---|:---|
| `[i]` | 索引のみに登録 |
| `[g]` | 用語集のみに登録（説明文を記述可能） |
| `[ig]` | 索引と用語集の両方に登録 |
| `[r]` | 両方から外す（除外済みリストに追加） |
| `[-i]` | 索引からのみ外す |
| `[-g]` | 用語集からのみ外す |
| `[ ]` | 保留（次回のレビューまで保持） |

読みを直したいときは、`( )` の中を書き換えます。

```markdown
- [ig] **Ruby** (るびー)  →  - [ig] **Ruby** (ルビー)
```

用語集に載せる語には、出現箇所のリストの後に空行を入れ、字下げして説明文を書きます。空行が、出現箇所と説明文の区切りになります。

```markdown
- [g] `NEW!` **非同期処理** (ひどうきしょり) - スコア: 295.6
  - 11-intro: 非同期処理はJavaScriptを日々利用して
  - 12-basics: プログラミングでは非同期処理を行います

  処理の完了を待たずに*次のタスクを実行*する方式。
  `JavaScript`の`Promise`などで利用されます。
```

### `vs index:apply` — レビューの結果を辞書へ反映する

フラグと説明文を書き終えたら、辞書へ反映します。

```bash
vs index:apply
```

`[i]`・`[g]`・`[ig]` を付けた語は `config/index_glossary_terms.yml` に、`[r]` を付けた語は `config/index_glossary_rejected.yml` に書き込まれます。読みの修正と、あとで述べる主要参照の指定も反映されます。

### 推奨候補を自動で登録する

既定では、候補は辞書に自動登録されません。`auto_approve` を `true` にすると、推奨候補がレビューを経ずに登録されます。索引の骨格を先に作りたいときには便利ですが、読者を適切な場所へ案内できるかは、あとから必ず確認してください。

```yaml
index:
  auto_approve: false    # 既定。レビューファイルで著者が選ぶ
```

## 索引語の数を見積もる

:::{.section-lead}
索引語が少なすぎると引きたい語が見つからず、多すぎると引いても役に立たない項目が増えます。`vs index:plan` は、本文の分量からこの本に合う語数の目安を示し、登録済みの語と候補をその目安に照らして並べます。
:::

### `vs index:plan` — 目安を確かめる

```bash
vs index:plan          # 全章を対象に現況を表示
vs index:plan 21-23    # 章を絞ることもできる
```

`vs index:plan` は表示するだけで、辞書もレビューファイルも書き換えません。目安がすでに決まっているなら、省略して `vs index:auto` から始めても構いません。

:::{.output}
```text
■ いまの目安（index.target_terms: standard）
    244〜356 語 ＝ 約 362〜528 字に 1 語
    現在 153 語は目安を 91 語下回っています（約 843 字に 1 語）

■ 設定を変えるとこうなります
    light      132〜183 語      約 704〜977 字に 1 語
    standard   244〜356 語      約 362〜528 字に 1 語   ← 現在
    thorough   458〜468 語      約 275〜281 字に 1 語

    語数を直接決める場合は config/book.yml に:
      index:
        target_terms: 300        # 約 430 字に 1 語
```
:::

選ぶときは、**「約 N 字に 1 語」の欄**が手がかりになります。「500 字に 1 語ほどの密度で拾いたい」と考えているなら、その値に近い行を選び、`config/book.yml` の `index.target_terms` に書きます。

| 値 | 意味 |
| :--- | :--- |
| `light` | 控えめ。主要な語だけを拾う（既定） |
| `standard` | 標準 |
| `thorough` | 丁寧。初学者向けに広く拾う |
| 整数（例 `260`） | その語数を目安にする |

目安の数値は、刊行済みの技術書 10 冊の索引を実測して定めたものです。索引語は本文の分量に比例しては増えないので（分量が 3 倍でも約 2.3 倍）、目安もそのように算出しています。

### 推奨候補・一般候補・見直し候補

`vs index:plan` は、**登録済みの語と、まだ登録していない候補を同じ基準で**重要な順に並べ、目安の語数で区切ります。

:::{.output}
```text
登録済み 153 語と同じ土俵でスコア順に並べた結果:
  推奨候補   上位 357 位以内の未登録語      248 件
  一般候補   358〜1,071 位の未登録語   673 件
  見直し候補 357 位より下の登録済み語     43 件
  推奨候補の例: 拡張リファレンス / Mode / Step / Command / アバター …他 243 語
  見直し候補の例: オプション / 設定ファイル / セットアップ / ビルド / PDF …他 38 語
```
:::

| 帯 | 意味 |
| :--- | :--- |
| 推奨候補 | 目安の枠内に入るほど重要なのに、まだ索引にない語 |
| 一般候補 | 推奨には届かないが検討に値する語（目安の 3 倍の順位まで。`candidate_pool` で変更可） |
| 見直し候補 | 枠外へ押し出された登録済みの語。外すことを検討できる |

**語数が目安に達していても推奨候補は出ます。**語数の過不足ではなく重要度を見ているからです。推奨候補と見直し候補が同時に出ていれば、語数を変えずに入れ替えることもできます。原稿に `[用語|読み]` と書いて登録した語は、見直し候補に出ません。

### 本の広い範囲に散らばる語

レビューファイルの「1. 登録済み用語の確認」には、**本の広い範囲に散らばっている語**が別枠で並びます。既定では、半分以上の章に出る語です（`common_term_ratio` で変更可。全 6 章未満の本と、3 章未満にしか出ない語は対象外）。

```markdown
### 一般語（索引から外すことを推奨・16語）

- [-im?25] **ファイル** (ふぁいる) - スコア: 254.0 - 一般語: 23/27 章（85%）に出現
- [-im?24] **コード** (こーど) - スコア: 247.0 - 一般語: 20/27 章（74%）に出現
```

索引の役割は、出現箇所をすべて並べることではなく、**説明のある場所へ案内すること**です。「ファイル」で 23 章ぶんのページ番号が並んでも、読者はどこを読めばよいか判断できません。そこでこれらの語には、外す印 `[-i]` があらかじめ付いています。

**外すかどうかは著者が決めます。**そのまま `vs index:apply` すれば外れ、`[i]` に戻せば残ります。本の主題そのものである語（Markdown の解説書における「Markdown」など）は広く現れるのが自然なので、外さずに、次の節の主要参照で説明箇所を示してください。

## 頻出語に「まずここを読む」を示す

:::{.section-lead}
広く出てくる語でも、腰を据えて説明している場所は限られます。その場所を**主要参照**として指定すると、索引でその番号が太字で先頭に並び、「まずここを読めばよい」が読者に伝わります。
:::

### 主要参照を指定する

レビューファイルのフラグの後ろに、`m` と章番号を書き足します。

```markdown
- [im21] **Markdown** (まーくだうん) - スコア: 228.3 - 一般語: 22/27 章（81%）に出現
- [igm21,22] **拡張記法** (かくちょうきほう) - スコア: 310.5
```

複数の章で説明しているなら `m21,22` とカンマで並べます。指定した章での**最初の説明箇所**が主要参照になり、索引ページで太字になって先頭に並びます。

:::{.output}
```text
Markdown ……… 156, 12, 24, 38, 51, 66, 88, 102, …
             ↑太字（21 章の説明箇所）
```
:::

**候補は自動で下書きされます。** `vs index:auto` は、主要参照が未指定の語に、その語を見出しに含む章や、多く出てくる章を候補として `m?21` のように書き込みます。`?` は自動で選んだ印で、そのまま `vs index:apply` すれば採用されます。違う章なら数字を書き換え、指定したくなければ `m?21` ごと消してください。

主要参照は辞書に `main:` として保存されます。章の番号を変えても `vs rename` / `vs renumber` が追随するので、指定し直す必要はありません。

### 説明箇所を節まで絞る

章を指定すると、その章の中で最初にその語を説明している節が主要参照になります（章題は章の名前であって説明箇所ではないので、対象になりません）。自動で選ばれた節が違うときは、用語の下に子行を書いて節を名指しします。子行はフラグ欄の指定より優先されます。

```markdown
- [i] **Markdown** (まーくだうん)
  - 主要参照: 21#Markdown とは
```

見出しは、番号（`4-1` など）ではなく**文言**で書きます。その語を含まない見出しでも構いません。同じ文言の見出しが章内に複数あるときは、`21#リスト#箇条書きリスト` のように親の見出しを `#` でつないで絞ります（間の見出しは省略できます）。

見出しを書き換えて指定先が見つからなくなると、ビルド時に知らせます。組版は止まらず、章だけを指定したときと同じ動きになります。

:::{.output}
```text
🟡 「Markdown」の主要参照が指す見出しが見つかりません: 21#主な用途
        21-markdown-tutorial の見出し: Markdown とは / Markdown の概要 / …
        近いもの: さまざまな用途
```
:::

主要参照が未指定のまま広く散らばっている語があると、ビルドの最後に件数と、`vs index:auto` で候補付きの一覧を作れることを知らせます。

### 索引の出し方を選ぶ

主要参照を指定すると、それ以外の出現（副次参照）をどこまで載せるかを選べます。

```yaml
index:
  reference_style: main_and_sub   # 既定
  max_sub_references: 8           # 副次参照の上限（0 で無制限）
```

| 値 | 出力 |
|:---|:---|
| `main_and_sub` | 主要参照を太字で先頭に置き、副次参照を `max_sub_references` 件まで続けます（既定） |
| `main_only` | 主要参照だけを載せます。ページ数を詰めたい本向けです |
| `all` | 太字も並べ替えも間引きもしません。主要参照の候補の提示とビルド時の知らせも止まります |

主要参照が指定されていない語は、どの設定でも間引きません。「まずここ」を示せないまま出現箇所だけ削ると、その語は索引から実質消えてしまうためです。

### 連続するページを範囲でまとめる

同じ語が 3 ページ以上続けて出るときは、番号を並べる代わりに範囲で示します（`page_range_min` で変更可）。

:::{.output}
```text
ビルド ……… 105–107, 128–130, 213, 222, 223
```
:::

範囲表記は PDF だけの機能です。EPUB・Kindle ではページ番号が組版まで決まらないため、番号を範囲にまとめられません。

## 索引・用語集ページの見え方

:::{.section-lead}
`vs build` を実行すると、辞書の語を原稿から探し、索引ページと用語集ページが本の末尾に組まれます。ここでは、読者から見た紙面の姿を説明します。
:::

### 索引ページ

語は読みの五十音順に「あ行」「か行」などで分かれ、英字・数字・記号もそれぞれまとまって並びます。同じページに何度出てきても、番号は一つにまとめます。

### 用語集ページと本文の `†`

用語集ページには、登録した語と説明文が五十音順に並び、本文での出現ページが添えられます。番号はページ順で、同じページは一つにまとめます。番号をクリックすると、本文の該当箇所へ移動します。

:::{.output}
```text
CSS 組版
    HTML と CSS を使って書籍の紙面を設計・組版する手法。
    → p.307
```
:::

本文では、用語集に載せた語の右肩に `†`（ダガー）が付きます。クリックすると、用語集のその語へ移動します。`†` が付くのは**章ごとの最初の 1 箇所だけ**です。同じ章で何度出てきても繰り返さないので、紙面が記号で騒がしくなりません。章が変われば、その章の初出にまた付きます。途中の章から読み始めた読者にも、その章で最初に出会った時点で用語集への入口があるようにするためです。

### ページ番号は紙面のノンブルと一致する

索引と用語集に並ぶページ番号は、紙面に印字されるノンブル（ページ番号）と同じ数字です。前書きや目次などの前付けはローマ数字（`p.ii`）、本文はアラビア数字（`p.307`）で、紙面の表記そのままに並びます。

ただし、**PDF ビューアが数える「何枚目のページか」とは一致しません。**表紙・扉・権利ページ・前書き・目次が前に入るため、たとえば本書では紙面のノンブル 307 が、PDF ファイルとしては 356 枚目にあたります。ビューアのページ番号の入力欄に用語集の数字を打ち込むと違う場所へ移動するので、その場合はリンクをクリックしてください。リンクは正しい位置へ移動します。

単一の章だけをビルドしたとき（`vs build 12` のように章を指定した場合）は、その章を 1 ページ目として組むため、番号も章の中で数えた値になります。通し番号で確かめたいときは、書籍全体をビルドしてください。

## 索引ライブラリを別の本へ持ち運ぶ

:::{.section-lead}
用語集に書いた定義、候補から外した語、専門用語の読みは、同じ分野の次の本でも役立ちます。`vs index:export` / `vs index:import` を使うと、本に固有の出現箇所を持ち込まず、再利用できる判断だけを引き継げます。
:::

```bash
# 今の本から書き出す（既定は index_library.yml）
vs index:export

# 新しい本のプロジェクトで取り込む
vs index:import

# 別名で書き出す／共有ライブラリから取り込む
vs index:export mybook_library.yml
vs index:import ~/vivlio/shared_library.yml
```

書き出されるのは、用語集の語と読みと定義、外した語の一覧、読みの個人辞書だけです。出現箇所やバックリンクのような本に固有の情報は含みません。

取り込みは追記で、既存の語は残します（`--prefer-import` を付けるとライブラリ側で上書き）。すでに索引・用語集に採用している語は、外した語の一覧には加えません。取り込んだ読みは `config/index_yomi_overrides.yml` にたまり、MeCab の推測より優先して使われます。「碍子」を「がいし」と読ませる、といった補正を本ごとに登録し直す手間がなくなります。

## 設定のカスタマイズ

:::{.section-lead}
候補の量や索引の表示方法は、`book.yml` で書籍に合わせて調整できます。索引と用語集で共通の設定は `index_glossary` に、索引だけの設定は `index` に、用語集だけの設定は `glossary` に置きます。
:::

```yaml
index_glossary:
  enabled: true                  # 索引・用語集の両方を有効化（false で両方無効）
  use_mecab: true                # MeCab による読みの自動推測を使う
  timezone: 'Asia/Tokyo'         # タイムゾーン（レビュー時の新着判定に利用）
  context_width: 40              # 文脈の表示幅（キーワード前後の文字数）
  exclude_chapters: []           # 索引・用語集の対象から外す章

index:
  auto_discovery: true           # 自動抽出を有効化（false で手動登録の語のみ）
  title: '索引'                  # 索引ページのタイトル
  target_terms: light            # 索引語数の目安
  candidate_pool: 3.0            # 目安語数の何倍までを候補として提示するか
  auto_approve: false            # true: 推奨候補を自動で辞書へ登録する
  common_term_ratio: 0.5         # この比率以上の章に出る語は「一般語」として除外を推奨
  reference_style: main_and_sub  # 主要参照と副次参照の出し方
  max_sub_references: 8          # 副次参照の上限（0 で無制限）
  page_range_min: 3              # この数以上の連続ページを範囲にまとめる

glossary:
  title: '用語集'                # 用語集ページのタイトル
  require_definition: false      # true: [g] フラグで説明文がないとエラー
  max_definition_length: 500     # 説明文の最大文字数（超過したら警告）
```

上の値は、どれも書かなかったときの既定値です。索引語の数は、スコアの閾値ではなく `target_terms` の目安語数で決まります。いまの設定で何語が目安になるかは、`vs index:plan` で確かめられます。

記法の見本を集めた章のように、索引から読者を案内したくない章は `exclude_chapters` に書きます。書いた章は、候補の抽出にも索引・用語集のページにも使われず、本文に用語集の `†` も付きません。章は番号か範囲で書きます（本書は見本の章を `exclude_chapters: [97]` と外しています）。`vs rename` や `vs renumber` で章番号が変わると、ここに書いた番号も書き換わります。範囲（`93-97`）は番号帯として扱うので書き換わりません。

## トラブルシューティング

:::{.section-lead}
MeCab などのツールがない・動かないときは、`vs doctor --fix` で導入してください（導入されるツールは @chapref:ch-doctor にまとめています）。ここでは、ツールを入れても直らない症状を扱います。
:::

### 索引が五十音順にならない

読みが誤っていると、並び順も誤ります。レビューファイルで読みの `( )` を直し、`vs index:apply` を実行してからビルドし直してください。

### コード内の変数名が候補に挙がる

コードブロックやインラインコードの中は、候補を拾う対象から外れます。挙がるときは、フェンス（` ``` `）やバッククォートの閉じ忘れで、コードが地の文として読まれています。

### 用語が索引に載らない

原稿に頻出する語でも、辞書に登録するまでは索引に載りません。原稿に `[用語|読み]` と書いた語だけが載っている状態なら、`vs index:auto` → レビュー → `vs index:apply` の流れで語を登録してください。辞書がないまま `vs build` を実行すると、そのことを知らせます。

### 登録した用語が原稿から消えたとき

推敲で語を言い換えたり、節ごと削ったりすると、辞書に残った語が原稿のどこにも現れなくなることがあります。**その語が辞書から自動で消えることはありません。**著者が承認した登録を、出現の有無だけで取り下げないためです。代わりに、原稿から消えたことを二段階で知らせます。

`vs index:auto` を実行すると、その語はレビューファイルで `[原稿に出現しません]` と注記されます。用語集に載せていた語なら `vs build` でも警告が出ます。

:::{.output}
```text
🟡 用語集語がビルド対象章に出現しません: 電子ボルト（原稿のどこにも出現しません（語の変更・削除？））
```
:::

綴りを変えただけなら辞書の側を直し、本当に不要になったならレビューファイルで `[r]` を付けて外してください。索引だけに登録していた語は、出現がなければ索引ページに行が立たないので、紙面には影響しません。

### 章を `catalog.yml` から外したとき

ページ数の都合で見送るなど、`contents/` にファイルを残したまま章を `catalog.yml` から外すことがあります。その章は `vs index:auto` の対象から外れ、章の中に書いた `[用語|読み]` も登録されなくなります。すでに辞書へ入っている語は、そのまま残ります。

外した章にしか出てこなくなった語は、レビューファイルで注記されます。たとえば扉絵の章（`42-frontispiece`）を外すと、その章にしか出てこない「アスペクト比」は次のようになります。

:::{.output}
```text
- [ig] **アスペクト比** (あすぺくとひ) - [catalog 未登録の章に出現]
  - 42-frontispiece（catalog 未登録）: 推奨アスペクト比…
```
:::

その語には索引のページ番号が付かなくなります。章を `catalog.yml` へ戻すか、語を索引から外すかを決めてください。紙面での消え方は、登録先によって違います。

| 登録先 | 索引ページ | 用語集ページ |
| :--- | :--- | :--- |
| `[i]` 索引のみ | 消える | — |
| `[g]` 用語集のみ | — | 残る（`→ p.` は消える） |
| `[ig]` 両方 | 消える | 残る（`→ p.` は消える） |

用語集の説明文は、本文の何ページに出るかとは別に「その語が何か」を伝えるので、掲載を残し、ページ参照だけを落とします。このとき `vs build` が知らせます。

:::{.output}
```text
🟡 用語集語がビルド対象章に出現しません: アスペクト比（catalog 未登録の 42-frontispiece に出現）
```
:::

:::{.notice}
索引だけに登録した語は紙面に痕跡が残らないので、`vs build` は知らせません。章を外したあとに気づく手段は `vs index:auto` のレビューだけです。`catalog.yml` を編集したら一度実行しておいてください。
:::

消えるのは、**その語が出るすべての章を外したとき**です。`CLI` が 6 章に出ているなら、そのうち 1 章を外しても減るのはその章ぶんのページ番号だけで、項目も残りの参照もそのままです。

## まとめ

:::{.section-lead}
索引と用語集は、本文を書き終えたあとに機械的に付け足すものではなく、読者が本の中を行き来するための道筋です。自動抽出で候補を集めつつ、最後は読者の立場で入口を選びます。
:::

本章では、次の作業を見てきました。

- `[用語|読み]` による、原稿に印を付けた登録
- `vs index:auto` による候補の拾い出しと、レビューファイルでの採否の決定
- `vs index:apply` による辞書への反映
- `vs index:plan` による語数の見積もりと、主要参照による「まずここ」の指定
- `book.yml` による候補数や表示方法の調整

よい索引は、語が多い索引とは限りません。読者が探しそうな言葉から、読むべき説明へ迷わず届くことが大切です。レビューを適用したら `vs build` で書籍全体を組み、索引から本文を何語か引いてみてください。読者がたどる道筋を、自分でも確かめられます。索引ページの見た目は `stylesheets/index.css` で調整できます。
