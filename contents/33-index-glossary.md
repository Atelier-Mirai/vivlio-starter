# 索引・用語集機能

:::{.chapter-lead}
著者にはよく分かっている本の構成も、必要な情報を探してページを開く読者には見えていません。索引は説明のある場所へ案内し、用語集は読み進めるために必要な意味を補います。本章では、`vs index` コマンドを使った、用語の登録から候補の抽出、レビュー、索引・用語集ページの生成までを紹介します。
:::

** 本章で扱う記法とコマンド **

| 記法・コマンド | 目的 |
| :--- | :--- |
| `[用語\|読み]` | 原稿に印を付けて語を登録する |
| `vs index:auto` | 原稿から候補を抽出する |
| `vs index:apply` | レビューの結果を辞書へ反映する |
| `vs index:plan` | 索引語の数の目安を確かめる |
| `vs index:export` | 別の本で使えるよう、辞書の判断を書き出す |
| `vs index:import` | 書き出した判断を取り込む |

## 索引と用語集ができるまで

:::{.section-lead}
索引・用語集に載せる語は、二通りの方法で登録します。原稿に印を付けて登録する方法と、原稿から候補を抽出して選ぶ方法です。どちらで登録した語も一つの辞書にまとまり、ビルドのたびに原稿から出現箇所を探して、索引・用語集のページが組まれます。
:::

### 作業の流れ

```bash
# 0. 原稿に [用語|読み] と書いて、必ず載せたい語を登録する（任意）

# 1. 索引語の数の目安を確かめる（任意）
vs index:plan

# 2. 原稿から候補を抽出し、レビューファイルを作る
vs index:auto

# 3. レビューファイル _index_glossary_review.md をエディタで開き、
#    採用する語に [i]（索引）・[g]（用語集）・[ig]（両方）、外す語に [r] を付ける

# 4. レビューの結果を辞書へ反映する
vs index:apply

# 5. 索引・用語集ページを含めてビルドする
vs build
```

手順 2〜4 が中心です。`vs index:auto` が作る **`_index_glossary_review.md`** を、本章では「レビューファイル」と呼びます。候補の一覧に前後の文脈が添えてあり、著者は印を書き込んで、索引に載せるかどうかを決めます。

### 使うファイル

- `_index_glossary_review.md`: レビューファイル。`vs index:auto` が作り、著者が編集する
- `config/index_glossary_terms.yml`: 採用した語の辞書（索引・用語集共通）。`vs index:apply` が書く
- `config/index_glossary_rejected.yml`: 棄却した語の一覧。次からは候補に挙がらない
- `config/index_yomi_overrides.yml`: 読みの個人辞書（MeCab の推測より優先）
- `index_library.yml`: 別の本へ持ち運ぶための書き出し（後述）

## 原稿に印を付けて登録する

:::{.section-lead}
索引へ必ず載せたい用語は、原稿の中で明示できます。章の中心概念や、読者が別の呼び方から探しそうな語など、著者の判断を確実に反映したいときに使います。
:::

### 基本的な記法

原稿内で `[用語|読み]` または `[用語]` の形式で印を付けます。このように本文に印を付けて語を載せる方法を**手動登録**と呼びます。`vs index:auto` で候補を選ぶ**自動抽出**と対になる方法です。

```markdown
[Ruby|るびー]は素晴らしいプログラミング言語です。

[JavaScript]を使ってウェブページに動きを付けます。
```

- `[用語|読み]` - 用語と読み（ひらがな）を指定
- `[用語]` - 用語のみ（読みは MeCab で自動推測）

紙面では `[`・`|`・`]` が取り除かれ、用語だけが組まれます。たとえば次の文には、原稿に `[五十音順|ごじゅうおんじゅん]` と書いてあります。

索引の見出しは[五十音順|ごじゅうおんじゅん]に並びます。

巻末の索引で「五十音順」を引くと、このページの番号が載っています。

印を付けた語は、`vs index:auto` を実行すると辞書に登録され、自動抽出のスコアにかかわらず索引に載ります。辞書に入った語は、印のない箇所も含めて原稿から探されるので、印は語ごとに一箇所付ければ足ります。

印で辞書に入るのは、まだ辞書にない語だけです。辞書にある語は、印があっても辞書の登録に従います。

- レビューファイルで用語集だけ（`[g]`）にした語は、印の箇所も索引に載りません。用語集の語として扱われ、章の最初の 1 箇所に `†` が付きます
- 棄却した語は、印があっても登録されず、索引にも載りません。`vs index:auto` が場所を添えて報告します
- 印に添えた読みが辞書の読みと違うときは、辞書の読みを使い、違いを報告します。読みはレビューファイルの `( )` で直します

:::{.note}
**読みを添える**

日本語の用語を五十音順に並べるには、読みが必要です。省略した読みは MeCab で推測しますが、固有名詞や専門用語は誤ることがあります。重要な用語には読みを添えてください。

読みは並べ替えに使う欄なので、仮名で書きます。英字の部分は英字のまま、空白も語のとおりに残します（「Kindle Previewer」なら `Kindle Previewer`、「閲覧用 PDF」なら `えつらんよう PDF`）。英字で始まる語は A〜Z の行に入るので、読みを仮名にすると、同じ行の英字の語と並びが食い違います。

読みには語の意味を書きません。`[OS|オペレーティングシステム]` と書いても、索引では O の行に並びます。意味は用語集の説明文に書きます。
:::

### 記号やタグを登録する

記号や HTML タグなども索引に登録できます。

```markdown
[!]は否定演算子です。
[&&]は論理積演算子です。
[||]は論理和演算子です。
[<h1>]は見出しタグです。
```

### 索引の印として扱わないもの

次の書き方は、索引の印として扱わず、本文にそのまま残します。

- `[リンクテキスト](URL)` - Markdown のリンク
- `[^1]` - 脚注の参照
- コードブロック・インラインコード・数式・画像の代替テキストの中の `[...]`
- `[0, 1]` のように、カンマで区切った数の並び
- `[mm]`・`[px]` のように、読みを添えていない半角の英数字 2 文字以下 - 単位などの表記

表の見出しに `幅 [mm]` と単位を添える書き方は、角かっこごと紙面に組まれます。

2 文字以下の語を索引に載せたいときは、`[OS|OS]` のように読みを添えてください。読みを書いたことが、索引に載せる意思表示になります。読みを添えずに書いた語は、`vs index:auto` が登録しなかったことを報告します。

## 候補を抽出して選ぶ

:::{.section-lead}
すべての索引語を手で選ぶ代わりに、`vs index:auto` で原稿から候補を抽出できます。結果はレビューファイルにまとまり、前後の文脈を見ながら採否を決められます。
:::

### `vs index:auto` — 候補を抽出する

```bash
vs index:auto              # catalog.yml に載っている全章から
vs index:auto 21           # 21 章だけから
vs index:auto 21-23,25     # 範囲・複数指定も可
```

次の語を候補として抽出し、重要な順に並べてレビューファイルへ書き出します。

- 定義の文（「〜とは」）に現れる語
- カタカナ語・英語
- 名詞の連なり（「索引語」「主要参照」）
- 節の見出しに現れる語

コード・数式・実行結果・図解注釈・画像の代替テキストは、抽出の対象外です。

特定の章に集中して現れる語や、節の見出しに現れる語ほど上に並びます。「ファイル」のようにどの章にも大量に出る語は、上位を占めません。

章を指定すると、書き終えた章だけを見直せます。ほかの章で登録済みの語は、辞書から外れません。

### レビューファイルを読む

レビューファイル `_index_glossary_review.md` は五つの節に分かれています。

```markdown
# 索引・用語集レビュー
※ 印: [i]=索引、[g]=用語集、[ig]=両方、[ ]=未決定、[r]=棄却、[DELETE]=記録ごと削除する

## 1. 登録済みの語（188語）
- [-im?25] **ファイル** (ふぁいる) - スコア: 254.0 - 一般語: 23/27 章（85%）に出現
- [im?12] **Git** (Git) - スコア: 213.9
- [igm44] **トンボ** (とんぼ) - スコア: 251.4

  印刷物の裁断位置や見当合わせを示すマーク。

## 2. 推奨する語（96語）
- [m?14] `NEW!` **Re:VIEW Starter** (Re:VIEW Starter) - スコア: 413.8
  - 14-import: Re:VIEW Starter で書いた本を Vivlio Starter へ移すには…

## 3. 残りの語（353語）
- [m?21] `NEW!` **fancy list** (fancy list) - スコア: 315.4

## 4. 棄却した語（84語）
- [ ] `Today` **TeX** (TeX) - スコア: 179.2

## 5. 原稿に出てこない語（11語）
- [ ] **推奨候補** (すいしょうこうほ) - [原稿に出現しません] - いまの登録: [im33]
- [ ] **Step** (Step) - [原稿に出現しません] - 棄却した語
```

| 節 | 中身 | 確認のしかた |
|:---|:---|:---|
| 1. 登録済みの語 | すでに辞書にある語 | 印が変わる行（外す印・推測の `m?`）が先頭に並ぶので、そこを確かめる |
| 2. 推奨する語 | 目安の語数に入るほど重要なのに、まだ登録していない語 | ここを中心に採否を決める |
| 3. 残りの語 | 推奨には届かないが検討に値する語 | 余裕のあるときに眺める |
| 4. 棄却した語 | 次から候補に出さない語 | 戻したいものだけ拾う |
| 5. 原稿に出てこない語 | 原稿のどこにも出てこない語（登録済み・使っていない語・棄却した語） | 誤って登録した語を `[DELETE]` で削除する |

各行の先頭の印は、いまの辞書の登録を示しています。変えたい語だけ `[]` の中を書き換えて `vs index:apply` を実行します。ただし、次の印は `vs index:auto` が書き込んだ提案で、そのまま `vs index:apply` すると辞書に反映されます。

- 1 節の一般語に付く外す印（`[-i]`）と、推測の主要参照（`m?`）。どちらも後述します
- 5 節で、登録済みの語に付く `[ ]`（索引・用語集から外れます）

候補に添える文脈は、その語を含む 1 文です。強調やコードの記号は外してあり、長い文は語の前後だけを残して、省いた側に「…」を付けます。

用語の先頭のラベルは、その語がいつ追加されたかを示します。`NEW!` は今回はじめて挙がった候補、`Today` は今日辞書に登録した語、ラベルなしはそれ以前から辞書にある語です。

### 印を書き換えて採否を決める

各行の先頭の `[]` の中を、次の印に書き換えます。

| 印 | 意味 |
|:---|:---|
| `[i]` | 索引に載せる。主要参照は付けない |
| `[im21]` | 索引に載せる。主要参照は 21 章（後述） |
| `[g]` | 用語集だけに載せる（説明文を書く） |
| `[ig]` | 索引と用語集の両方に載せる |
| `[-i]` | 索引から外す。用語集にも載っていなければ棄却する |
| `[-g]` | 用語集から外す。索引にも載っていなければ棄却する |
| `[-ig]` | 索引から外し、用語集には残す |
| `[-i-g]` | 索引と用語集の両方から外して棄却する（`[r]` と同じ） |
| `[r]` | 棄却する。次からは候補に出さない |
| `[ ]` | 未決定。登録済みの語をこの印にすると、索引・用語集から外れて、次から候補に戻る |
| `[DELETE]` | 記録ごと削除する。誤って登録した語や、棄却した語の記録を残したくないときに使う |

マイナスは、直後の 1 文字にだけ掛かります。`[-ig]` は「`i` を外し、`g` は残す」と読むので、索引から外しても用語集には残ります。文字の順番は問わず、`[g-i]` と書いても同じです。両方から外すときは `[-i-g]` か `[r]` と書きます。

登録済みの語を `[ ]` で外すと、用語集の説明文を書いてある語は、索引にも用語集にも載せない「使っていない語」として説明文ごと辞書に残ります。原稿にもう一度書くと、以前の説明文を添えて候補に出るので、`[g]` にすれば書き直さずに戻せます。説明文のない語は辞書から外れます。どちらも棄却にはならないので、原稿に書けばまた候補に出ます。

`[DELETE]` にした語は、辞書からも棄却した語の一覧からも削除されます。原稿に `[語]` の印が残っている語を削除するときは、棄却と同じく、印も外すかを確かめます。

### 読み・綴り・説明文を書く

読みを直したいときは、`( )` の中を書き換えます。

```markdown
- [ig] **Ruby** (るびー)  →  - [ig] **Ruby** (ルビー)
```

見出し語の綴りを直したいときは、用語の行のすぐ下に、空行を挟まずに `- 綴り: 新しい綴り` と書きます。読み・印・説明文・主要参照はそのまま残ります。

```markdown
- [igm25] **ラベルID** (らべるID)
  - 綴り: ラベル ID
  - 25-cross-reference: 図・表・リストに「ラベルID」を付けてキャプションを記述する
```

原稿に古い綴りが残っていれば、`vs index:apply` は原稿も直すかを確かめます。「はい」と答えると、空白だけ違う書き方も含めて、コード以外の古い綴りを新しい綴りに直します。

「いいえ」と答えたときは、原稿を自分で直してください。古い綴りのままの箇所は、索引に載りません。索引は大文字と小文字も区別します（`ラベル ID` と `ラベル id` は別の綴りです）。

用語集に載せる語には、出現箇所のリストの後に空行を入れ、字下げして説明文を書きます。空行が、出現箇所と説明文の区切りになります。説明文には、インラインコードや強調を使えます。

```markdown
- [igm11] **CLI** (CLI) - スコア: 308.3
  - 11-workflow: Vivlio Starter は、ターミナルへコマンドを入力して使う CLI ツール…

  Command Line Interface の略。Vivlio Starter は `vs` コマンドとして提供されます。
```

### `vs index:apply` — レビューの結果を辞書へ反映する

印と説明文を書き終えたら、辞書へ反映します。

```bash
vs index:apply
```

索引・用語集に載せる語は `config/index_glossary_terms.yml` に、棄却した語は `config/index_glossary_rejected.yml` に書き込まれます。読みの修正と、あとで述べる主要参照の指定も反映されます。

原稿に `[語]` と書いた語を棄却するときは、原稿の印も外すかを確かめます。

:::{.output}
```text
❓ 11-workflow:321 ほか 2 箇所に [セットアップ] と書かれています。原稿の [] を外して棄却しますか？ [y/N]:
```
:::

`y` と答えると、原稿の印を外して語だけを残し、棄却します。Enter だけで済ませると、その語は原稿の印も辞書の登録もそのまま残ります。印を残したまま棄却すると、原稿と辞書の登録が食い違うためです。

### 推奨する語を自動で登録する

既定では、候補は辞書に自動登録されません。`auto_approve` を `true` にすると、推奨する語がレビューを経ずに登録されます。索引の骨格を先に作りたいときには便利ですが、読者を適切な場所へ案内できるかは、あとから必ず確認してください。

```yaml
index:
  auto_approve: false    # 既定。レビューファイルで著者が選ぶ
```

## 索引語の数を見積もる

:::{.section-lead}
索引語が少なすぎると引きたい語が見つからず、多すぎると引いても役に立たない項目が増えます。`vs index:plan` は、本文の分量からこの本に合う語数の目安と、いまの登録の状況を示します。
:::

### `vs index:plan` — 目安を確かめる

```bash
vs index:plan          # 全章を対象に現況を表示
vs index:plan 21-23    # 章を絞ることもできる
```

`vs index:plan` は表示するだけで、辞書もレビューファイルも書き換えません。目安がすでに決まっているなら、省略して `vs index:auto` から始めても構いません。

:::{.output}
```text
本文の分量: 27 章 / 152,478 字（コード・記法を除く地の文）
いまの登録: 索引 188 語・用語集 52 語・棄却 93 語
            主要参照が決まっていない索引語 2 語

■ いまの目安（index.target_terms: light ＝ 少なめ）
    150〜207 語 ＝ 約 736〜1,016 字に 1 語
    現在 188 語は目安の範囲内です（約 811 字に 1 語）

■ 設定を変えるとこうなります
    light（少なめ）   150〜207 語   約 736〜1,016 字に 1 語   ← 現在
    standard（標準）  277〜403 語   約 378〜550 字に 1 語
    thorough（多め）  519〜530 語   約 287〜293 字に 1 語

    語数を直接決める場合は config/book.yml に:
      index:
        target_terms: 180        # 約 847 字に 1 語

■ vs index:auto を実行すると
    推奨する語 96 語・残りの語 353 語をレビューファイルに並べます
    推奨する語の例: frontispiece / ornament / Re:VIEW Starter / 座標 / 話者 …他 91 語
```
:::

選ぶときは、**「約 N 字に 1 語」の欄**が手がかりになります。「500 字に 1 語ほどの密度で載せたい」と考えているなら、その値に近い行を選び、`config/book.yml` の `index.target_terms` に書きます。

| 値 | 意味 |
| :--- | :--- |
| `light` | 少なめ。主要な語だけを載せる（既定） |
| `standard` | 標準 |
| `thorough` | 多め。初学者向けに広く載せる |
| 整数（例 `260`） | その語数を目安にする |

目安の数値は、刊行済みの技術書 10 冊の索引を実測して定めたものです。索引語は本文の分量に比例しては増えないので（分量が 3 倍でも約 2.3 倍）、目安もそのように算出しています。

### 推奨する語と残りの語

`vs index:auto` は、**登録済みの語と、まだ登録していない候補を同じ基準で**重要な順に並べ、目安の語数で区切ります。目安の語数の内側に入る未登録の語が「推奨する語」、その外側の語が「残りの語」です。残りの語は、目安の 3 倍の順位までを並べます（`candidate_pool` で変更可）。

**語数が目安に達していても、推奨する語は出ます。**語数の過不足ではなく重要度で判定しているからです。

### 本の広い範囲に散らばる語

レビューファイルの「1. 登録済みの語」では、**本の広い範囲に散らばっている語**の行末に「一般語」と注記が付きます。既定では、半分以上の章に出る語です（`common_term_ratio` で変更可。全 6 章未満の本と、3 章未満にしか出ない語は対象外）。

```markdown
- [-im?25] **ファイル** (ふぁいる) - スコア: 254.0 - 一般語: 23/27 章（85%）に出現
- [-im?24] **コード** (こーど) - スコア: 247.0 - 一般語: 20/27 章（74%）に出現
```

索引の役割は、出現箇所をすべて並べることではなく、**説明のある場所へ案内すること**です。「ファイル」で 23 章ぶんのページ番号が並んでも、読者はどこを読めばよいか判断できません。そこでこれらの語には、外す印 `[-i]` があらかじめ付いています（用語集にも載っている語は `[-ig]` で、用語集には残ります）。ただし、主要参照（後述）を指定済みの語は、説明のある場所へ案内できるので `[i]` のまま並びます。

**外すかどうかは著者が決めます。**そのまま `vs index:apply` すれば外れ、`[i]` に戻せば残ります。本の主題そのものである語（Markdown の解説書における「Markdown」など）は広く現れるのが自然なので、外さずに、次の節の主要参照で説明箇所を示してください。

## 頻出語に「まずここを読む」を示す

:::{.section-lead}
広く出てくる語でも、詳しく説明している場所は限られます。その場所を**主要参照**として指定すると、索引でその番号が太字で先頭に並び、「まずここを読めばよい」が読者に伝わります。
:::

### 主要参照を指定する

レビューファイルの印の後ろに、`m` と章番号を追記します。

```markdown
- [im21] **Markdown** (Markdown) - スコア: 228.3 - 一般語: 22/27 章（81%）に出現
- [igm21,22] **拡張記法** (かくちょうきほう) - スコア: 310.5
```

複数の章で説明しているなら `m21,22` とカンマで並べます。指定した章での**最初の説明箇所**が主要参照になり、索引ページで太字になって先頭に並びます。

:::{.output}
```text
Markdown
    31, 12, 24, 38, 51, 66, 88, 102
    ↑太字（21 章の説明箇所）
```
:::

**候補は自動で下書きされます。** `vs index:auto` は、主要参照が未指定の語に、その語を見出しに含む章や、多く出てくる章を候補として `m?21` のように書き込みます。`?` は自動で選んだ印で、そのまま `vs index:apply` すれば採用されます。違う章なら数字を書き換え、付けないなら `m?21` ごと削除して `[i]` にしてください。付けないと決めた語には、次から推測を書き込みません。

まだ登録していない候補にも `[m?21]` の形で書き込み、その章の文脈を先頭に添えます。候補を採るときは、`[im21]` のように `i` を追記するだけで、主要参照も一緒に登録されます。

主要参照は辞書に `main:` として保存されます。章の番号を変えても `vs rename` / `vs renumber` が追随するので、指定し直す必要はありません。

### 説明箇所を節まで絞る

章を指定すると、その章の中で最初にその語を説明している節が主要参照になります（章題は対象になりません）。自動で選ばれた節が違うときは、用語の行のすぐ下に、空行を挟まずに `- 主要参照:` の行を書いて節を指定します。この行は印の中の指定より優先されます。

```markdown
- [i] **Markdown** (Markdown)
  - 主要参照: 21#Markdown とは
```

見出しは、番号（`4-1` など）ではなく**文言**で書きます。その語を含まない見出しでも構いません。同じ文言の見出しが章内に複数あるときは、`21#リスト#箇条書きリスト` のように親の見出しを `#` でつないで絞ります（間の見出しは省略できます）。

見出しを書き換えて指定先が見つからなくなると、ビルド時に 🟡 で警告します。組版は中断されず、章だけを指定したときと同じ動きになります。

:::{.output}
```text
🟡 「Markdown」の主要参照が指す見出しが見つかりません: 21-markdown-tutorial#基本の記法
        21-markdown-tutorial の見出し: Markdown とは / Markdown の概要 / …
        近いもの: 基本記法
```
:::

主要参照が未指定のまま広く散らばっている語があると、ビルドの最後に件数を表示します。`vs index:auto` を実行すると、主要参照の候補付きでレビューファイルに一覧できます。

### 索引の表示方法を選ぶ

主要参照を指定すると、それ以外の出現（副次参照）をどこまで載せるかを選べます。

```yaml
index:
  reference_style: main_and_sub   # 既定
```

| 値 | 出力 |
|:---|:---|
| `main_and_sub` | 主要参照を太字で先頭に置き、語を見出しに掲げた節の副次参照を、多くても 8 件続けます（既定） |
| `main_only` | 主要参照だけを載せます。ページ数を詰めたい本向けです |
| `all` | 太字も並べ替えも間引きもしません。主要参照の候補の提示とビルド時の通知も行いません |

`main_and_sub` で副次参照に載せるのは、その語を見出しに掲げた節です。節の見出しか、それを含む `##` の見出しに語がある節を選び、一つの節からは最初の出現だけを載せます。`##` の見出しに語があるときは、その下の `###` も含めて一つの節と数えます。索引から移動した先で、その語のまとまった説明を読めるようにするためです。

```markdown
## イベントで操作に反応する            ← 載せる（見出しに語がある）

### addEventListener で処理を登録する  ← 親の ## の 1 件にまとめる

## 入力を確かめる

### 送信のイベントを止める              ← 載せる（節の見出しに語がある）

## 画面を作り直す                      ← 載せない（本文に語が出るだけ）
```

「関数」のように広く使う言葉は、作例の見出し（「### 描画の関数を一つにする」）にも出てきます。見出しに語を掲げた節が 12 より多い語は、主要参照の章の外では、`###` の見出しの節を省きます。省いた語は、ビルドの最後に名前を表示します。

:::{.output}
```text
💡 索引の副次参照を、語を見出しに掲げた節に絞りました（212 語）
   見出しに出る節が多い 2 語は、主要参照の章の外の ### の節を省きました: 関数・状態
```
:::

主要参照が指定されていない語は、どの設定でも間引きません。「まずここ」を示せないまま出現箇所だけ削ると、その語は索引から実質消えてしまうためです。

分冊の本で、主要参照の章が別の巻にあるときは、ページ番号の後ろに、その巻の名前と章を太字で添えます。副次参照は、ほかの語と同じ選び方で絞ります。その巻だけを手にした読者にも、説明のある場所が伝わります。`main_only` なら案内だけを載せます。

:::{.output}
```text
コンソール
    12, 29, 42, 61, 77, 128, 141, 221, 上巻 第7章
```
:::

### 連続するページを範囲でまとめる

同じ語が 3 ページ以上続けて出るときは、番号を並べる代わりに範囲で示します。用語集のページ番号も同じです。何ページから範囲にするかは `page_range_min` で変えられます。

:::{.output}
```text
ビルド
    105–107, 128–130, 213, 222, 223
```
:::

範囲にまとめるのは PDF だけです。EPUB・Kindle には固定のページ番号がないため、範囲にまとめません。

## 索引・用語集ページの見え方

:::{.section-lead}
`vs build` を実行すると、辞書の語を原稿から探し、索引ページと用語集ページが本の末尾に組まれます。ここでは、読者から見た紙面の姿を説明します。
:::

### 索引ページ

語は、記号・数字・A〜Z・五十音（「あ」「か」…）の行に分かれて並びます。英字の語は、大文字と小文字を区別せずに A〜Z の順に並びます。同じページに何度出てきても、番号は一つにまとめます。索引ページの見た目は `stylesheets/index.css` で調整できます。

### 用語集ページと本文の `†`

用語集ページには、登録した語と説明文が五十音順に並び、本文での出現ページが添えられます。索引にも載せた語は、索引と同じページ番号を同じ並びで添えます（主要参照が太字で先頭）。用語集だけの語と、主要参照を指定していない語は、章ごとの最初の出現ページをページ順に添えます。同じページは一つにまとめます。番号をクリックすると、本文の該当箇所へ移動します。

:::{.output}
```text
CSS 組版
    HTML と CSS を使って書籍の紙面を設計・組版する手法。
    → 307
```
:::

本文では、用語集に載せた語の右肩に `†`（ダガー）が付きます。クリックすると、用語集のその語へ移動します。`†` が付くのは**章ごとの最初の 1 箇所だけ**です。同じ章で何度出てきても繰り返さないので、紙面が記号で煩雑になりません。章が変われば、その章の初出にまた付きます。途中の章から読み始めた読者でも、その章の初出から用語集へ移動できるようにするためです。

### ページ番号は紙面のノンブルと一致する

索引と用語集に並ぶページ番号は、紙面に印字されるノンブル（ページ番号）と同じ数字です。前書きや目次などの前付けはローマ数字（`p.ii`）、本文はアラビア数字（`p.307`）で、紙面の表記そのままに並びます。

ただし、**PDF ビューアが数える「何枚目のページか」とは一致しません。**表紙・扉・前書き・目次などが前に入るため、PDF の枚数のほうが大きくなります。ビューアのページ番号の欄に索引の数字を入力すると違うページへ移動するので、索引・用語集の番号をクリックして移動してください。

単一の章だけをビルドしたとき（`vs build 12` のように章を指定した場合）は、その章を 1 ページ目として組むため、番号も章の中で数えた値になります。通し番号で確かめたいときは、書籍全体をビルドしてください。

## 索引ライブラリを別の本へ持ち運ぶ

:::{.section-lead}
用語集に書いた説明文、棄却した語、専門用語の読みは、同じ分野の次の本でも役立ちます。`vs index:export` / `vs index:import` を使うと、本に固有の出現箇所を持ち込まず、再利用できる判断だけを引き継げます。
:::

```bash
# 今の本から書き出す（既定は index_library.yml）
vs index:export

# 新しい本のプロジェクトで取り込む
vs index:import

# 別名で書き出す／共有ライブラリから取り込む
vs index:export mybook_library.yml
vs index:import ~/vivlio/shared_library.yml
```

書き出されるのは、次の三つです。

- 説明文を書いた語（用語集の語と、使っていない語）の読みと説明文
- 棄却した語の一覧
- 読みの補正

索引に載せるかどうかや主要参照のような本ごとの判断と、出現箇所のような本に固有の情報は含みません。

棄却した語の一覧を持ち運べば、「項目」「目安」のような語を本ごとに棄却し直さずに済みます。判断は最初の 1 冊で済み、本を重ねるほど候補が絞られていきます。

取り込んだ説明文は、使っていない語として辞書に保存されます。用語集のページには載らず、原稿にその語を書くと、説明文を添えた候補としてレビューファイルに並びます。`[g]` か `[ig]` を付けて `vs index:apply` すれば、説明文を書き直さずに用語集へ載せられます。原稿に出てこない間は、レビューファイルの 5 節にも並びません。

取り込みは追記だけです。辞書にすでにある語、この本で棄却した語、すでにある読みは変えません。取り込んだ読みは `config/index_yomi_overrides.yml` に追記され、MeCab の推測より優先して使われます。「碍子」を「がいし」と読ませる、といった補正を本ごとに登録し直す手間がなくなります。

## 設定のカスタマイズ

:::{.section-lead}
候補の量や索引の表示方法は、`book.yml` で書籍に合わせて調整できます。索引と用語集で共通の設定は `index_glossary` に、索引だけの設定は `index` に、用語集だけの設定は `glossary` に置きます。
:::

```yaml
index_glossary:
  enabled: true                  # 索引・用語集の両方を有効化（false で両方無効）
  use_mecab: true                # MeCab による読みの自動推測を使う
  timezone: 'Asia/Tokyo'         # タイムゾーン（レビュー時の新着判定に利用）
  context_width: 40              # 文脈の表示幅（キーワード前後の文字数）
  exclude_chapters: []           # 索引・用語集の対象から除外する章

index:
  auto_discovery: true           # 自動抽出を有効化（false で手動登録の語のみ）
  title: '索引'                  # 索引ページのタイトル
  target_terms: light            # 索引語数の目安
  candidate_pool: 3.0            # 目安語数の何倍までを候補として提示するか
  auto_approve: false            # true: 推奨する語を自動で辞書へ登録する
  common_term_ratio: 0.5         # この比率以上の章に出る語は「一般語」として外す印を付ける
  reference_style: main_and_sub  # 主要参照と副次参照の表示方法
  page_range_min: 3              # この数以上の連続ページを範囲にまとめる

glossary:
  title: '用語集'                # 用語集ページのタイトル
  require_definition: false      # true: [g] の語に説明文がないとエラー
  max_definition_length: 500     # 説明文の最大文字数（超過したら警告）
```

上の値は、どれも書かなかったときの既定値です。

記法の見本を集めた章のように、索引から読者を案内したくない章は `exclude_chapters` に書きます。書いた章は、候補の抽出にも索引・用語集のページにも使われず、本文に用語集の `†` も付きません。章は番号か範囲で書きます（本書は見本の章を `exclude_chapters: [95]` と外しています）。`vs rename` や `vs renumber` で章番号が変わると、ここに書いた番号も書き換わります。範囲（`93-97`）は番号帯として扱うので書き換わりません。

## トラブルシューティング

:::{.section-lead}
MeCab などのツールがない・動かないときは、`vs doctor --fix` でインストールしてください（@chapref:ch-doctor）。ここでは、それ以外の症状を扱います。
:::

### コード内の変数名が候補に挙がる

コードブロックやインラインコードの中は、候補を抽出する対象から外れます。挙がるときは、フェンス（` ``` `）やバッククォートの閉じ忘れで、コードが地の文として解釈されています。

### 用語が索引に載らない

原稿に頻出する語でも、辞書に登録するまでは、印を付けた箇所しか索引に載りません。`vs index:auto` → レビュー → `vs index:apply` の流れで登録してください。

辞書にある語でも、原稿の書き方が空白だけ違う箇所（`Type 3 フォント` に対する `Type3 フォント`）は索引に載りません。`vs lint` が指摘し、`vs lint --fix` で辞書の綴りへ直せます（@ch-lint の章）。

### 登録した用語が原稿から消えたとき

推敲で語を言い換えたり節ごと削ったりしても、辞書に残った語は自動では消えません。`vs index:auto` のレビューファイルで `[原稿に出現しません]` と注記され、用語集に載せていた語なら、`vs build` も「用語集語がビルド対象章に出現しません」と警告します。

綴りを変えただけなら、レビューファイルの `- 綴り:` で辞書の綴りを直してください。不要になった語は 5 節に `[ ]` の印で並ぶので、そのまま `vs index:apply` すれば外れます。

### 章を足したとき・外したとき

章を足したら、`vs index:auto` を実行してください。実行するまで新しい章の語は候補に挙がらず、`vs build` が「索引候補の抽出が未実施の章があります」と警告します。

`catalog.yml` から外した章は、ファイルが残っていても索引の対象外です。その章にしか出てこない語は、レビューファイルで `[catalog 未登録の章に出現]` と注記され、索引にページ番号が付かなくなります。用語集の語は説明文だけが残り、`vs build` が警告します。索引だけの語は警告されないので、`catalog.yml` を編集したら `vs index:auto` でレビューファイルを確かめてください。
