# PDF のしおりの飛び先を、見出しの id から決める

> 関連: `catalog-written-order-spec.md`（しおりの章の並び）、`heading-numbering-spec.md`（しおりの「第N章」）、`multivolume-spec.md`（分冊の巻・合本・全巻目次）、`kindle-rotate-table-image-spec.md` §4（id を飛び先にして PDF からページを引く先例）

## 0. 背景

PDF のしおり（アウトライン）は、`OutlineExtractor` が作っている。見出しの文字を HTML から取り、その文字が PDF のどのページにあるかを `pdftotext` の文字から探す。

この探し方は、同じ文字が別の所にあると外れる。本文・柱・目次・図の中に見出しと同じ文字があれば、そちらのページを指してしまう。

- **spiral-ruby の合本（2026-10-26）**: しおり 1853 項目のうち 724 項目が、違うページを指していた。`7d53999b` で 3 件直して 60 項目まで減ったが、柱と節の見出しの行が混ざる課題の見出しが残っている。
- **本書の雛形から 4 章だけ組んだ試しの本（2026-10-26）**: 確かめられた見出し 45 件のうち 15 件が違うページを指していた。どれも項（`###`）の見出しで、本文の先のほうに同じ文字がある。
  - 「`contents/`」などの 9 件は、節の頭にあるディレクトリの一覧（27 ページ）を指していた。
  - 「(1) プロジェクト作成」などの 5 件は、前の節「全体の流れ」（14 ページ）を指していた。
  - 「プロジェクトを作る」は、20 ページにあるのに 13 ページを指していた。しおりの中で、前の項目より前のページへ戻っている。

文字の探し方をどれだけ直しても、同じ文字が別の所にある限り外れる。外れる形は本ごとに違う。

## 1. 調べてわかったこと（2026-10-26 実測）

試しの本（本書の雛形の `00`・`11`・`12`・`91` 章、47 ページ）で確かめた。

### 1.1 飛び先は、最終の PDF まで残っている

PLANNED.md には「Vivliostyle は見出しごとに飛び先を付けるが、最終の PDF には 1 件も残っていない」と書いていた。**これは誤りだった。** 飛び先には 2 つの置き場所があり、前の調べは名前の木（`/Names` の `/Dests`）だけを見ていた。Vivliostyle は、文書カタログの `/Dests` 辞書に書く（`PdfPageMapExtractor` は、すでにこちらを読んでいる）。

| PDF | 飛び先の数 |
| :--- | ---: |
| Vivliostyle が組んだ本文（`_sections.pdf`） | 55 |
| 結合した閲覧用 PDF | 55 |
| 入稿用 PDF（閲覧用から導出し、トンボ・塗り足し・隠しノンブルを入れた後） | 55 |

結合（qpdf）でも入稿用の導出でも、飛び先は落ちない。

### 1.2 飛び先が出るのは、リンクの飛び先になっている見出しだけ

`/Dests` に出るのは、どこかからリンクされている要素だけで、id を持つだけの要素は出ない。目次から指される章・節（`toc_depth` の深さまで）には出るが、目次に載らない見出しには出ない。

| 見出し | 飛び先が出た数 |
| :--- | ---: |
| 本文の章・節・項（`toc_depth: 3` で目次に載る） | 37 / 37 |
| 付録の節（目次に載る） | 6 / 6 |
| 付録の項（付録は目次に節までしか載らない） | 0 / 23 |
| 前書きの節（前書きの節は目次に載らない） | 0 / 6 |
| 目次ページの見出し「目次」 | 0 / 1 |

この性質は、前付・奥付の目印（`PdfBuilder.inject_matter_anchors!`）と回転テーブル（`inject_rotate_table_anchors!`）を作ったときにも確かめていて、どちらも自分を指す空のリンクを足して解いている。

本書は `toc_depth: 2` なので、本文の項（`###`）にも飛び先が出ない。spiral-ruby も `toc_depth: 2` である。

### 1.3 自分を指す空のリンクを `<body>` の直後に置けば、全部の見出しに出る

回転テーブルと同じ形で、見出しの id を指す空のリンクを `<body>` の直後へまとめて置き、組み直した。

```html
<body ...><a href="#コマンド一覧" style="position:absolute"></a>…
```

| 確かめたこと | 前 | 後 |
| :--- | ---: | ---: |
| 飛び先の数 | 55 | 90 |
| しおりに載せる見出しのうち、飛び先があるもの | 45 / 75 | 75 / 75 |
| ページ数 | 47 | 47 |
| リンクの注釈の数 | 212 | 212 |
| `pdftotext` で取り出した本文の差 | — | 0 行 |

空のリンクは注釈を作らず（クリックできる領域が増えない）、組版も変わらない。

飛び先のページに、その見出しの文字があるかも確かめた。80 件すべてで、見出しの文字が飛び先のページにあった。照合で一致しなかった 2 件は、見出しが 2 行に折り返し、間に「1-4」の番号が挟まっていただけだった。

### 1.4 しおりを付ける時点では、飛び先の名前はまだ元のまま

飛び先の名前には、Vivliostyle が文書の URL と id を入れている（`viv-id-http:003a…:002f11-workflow:002ehtml:0023:5168:4f53…`）。名前は仕上げで `vs1`・`vs2`…に付け替えるが（`DestinationNames.shorten!`）、閲覧用でも入稿用でも、しおりを付けるのはその前である。そのため、「どの文書のどの id か」で飛び先を引ける。

### 1.5 飛び先は、ページの中の位置も持っている

飛び先は `[ページ, /XYZ, x, y, 0]` の形で、見出しの左端（`x`）と上端（`y`）を持つ（例: `[17 ページ, /XYZ, 56.25, 353.37, 0]`）。そのため、ページだけでなく見出しの位置まで飛ばせる。

入稿用 PDF では、同じ飛び先が `x`・`y` とも 45.35 pt ずれていた（`[16 ページ, /XYZ, 101.60, 398.11, 0]`）。トンボ・塗り足しを付けたときに広がった版面の分（`TrimBox` の左下が `45.35, 45.35`）で、座標も一緒にずらされている。入稿用は表紙が無いので、ページも 1 つ前になる。

## 2. 指針

**しおりのページは、PDF の飛び先から引く。文字でページを探すのはやめる。**

- 見出しのページを、組み上がった PDF そのものから引く。推定をやめるので、本の組み方によって外れることがなくなる。
- しおりの項目と文字（「第1章 …」「付録A …」、`heading_numbering`）は今のまま変えない。変えるのは、各項目が指すページと、節・項ではページの中の位置である。
- 飛び先を出すための空のリンクは、`pdf/` の写しにだけ書く。`html/` の原本は触らないので、EPUB と Kindle には何も出ない。

## 3. 要件

### R1: しおりに載せる見出しへ、自分を指す空のリンクを足す

`PdfBuilder.stage_workspace_htmls!` で、`pdf/` へ写した HTML のうち、しおりの対象（`Utilities.outline_target_htmls` が選ぶもの）にある `h1`〜`h3` に、それぞれの id を指す空のリンクを足す。

- 置く場所は、回転テーブルと同じく `<body>` の直後である。リンクの位置は飛び先の位置に関係しないので、見出しの中には入れない（柱の `string-set` や見出しの CSS に関わらせないため）。
- `style="position:absolute"` を付けて、流れから外す（本扉・権利ページの `display: grid` で行がずれた先例がある）。
- 目次に載る見出しにも足す。足しても飛び先が重なるだけで、害がない。目次の深さによって、出たり出なかったりする分かれ目を作らない。
- id の値は HTML の属性として escape する。

### R2: ページは、結合した PDF の `/Dests` から「文書と id」で引く

`OutlineExtractor` は、結合した PDF（閲覧用は `output.pdf`、入稿用は `output_print.pdf`）の `/Dests` を読み、`{[文書の basename, id] => [ページ, 上端の y]}` を作る。各見出しのページと位置（R7）は、そこから引く。

- `PdfPageMapExtractor` に、文書と id の組でページと上端の `y` を返すメソッドを足す。名前の読み方（`decode_destination_name`）と、`/Dests` の走り方（`each_destination`）は、今のものをそのまま使う。
- 同じ id はほかの章にもありうるので（「概要」など）、id だけで引かない。今の `pages_for(ids)` は id だけで引くので、しおりには使わない。
- 結合した PDF から直接引くので、表紙のページ数を足す補正（`front_matter_offset`・`start_page:`）は要らない。

### R3: 飛び先が見つからない見出しは、直前の項目のページを指す

R1 で足しても飛び先が無い見出し（id が無い、組まれていないなど）は、しおりの直前の項目と同じページを指す。こうしておけば、しおりの中でページが前へ戻ることはない。先頭の項目なら、その文書の始まりのページを指す（`PdfPageMapExtractor#document_first_pages`）。

- 原稿の誤りではないので、著者には知らせない（🟡 にしない）。`--log=debug` で件数と見出しを出す。
- 実ビルドの確かめ（§7）では、この件数が 0 であることを見る。

### R4: しおりの項目と文字は変えない

今と同じものを、同じ順で、同じ文字で並べる。

- 対象は前書き・目次・本文・付録・後書き・用語集・索引・全巻目次（`outline_target_htmls`）、深さは `h1`〜`h3`（`max_level: 3`）。
- 章の文字（「第1章」「付録A」、`heading_numbering: none` なら番号なし）は `build_display_text` のまま使う。
- 「目次」の項目は、ほかの特別なページと同じく `_toc.html` の `h1` から作る。今の `add_toc_entry`（目次ページの文字を探す）は外す。

### R5: どの経路でも同じに動く

| 経路 | しおりを付ける所 | 確かめること |
| :--- | :--- | :--- |
| 閲覧用 PDF | `PdfMerger.add_outline_to_output_pdf!` | 結合の後・名前の付け替えの前に引く |
| 入稿用 PDF（導出） | `PrintPdfBuilder#add_outline!` | トンボ・隠しノンブルの後も飛び先が残る（§1.1 で確認済み） |
| 入稿用 PDF（`full_bleed: true` で組み直す経路） | 同上 | 組み直しも `pdf/` の HTML を読むので、R1 のリンクが効く |
| 分冊の巻・合本 | 同上（巻ごとに 1 本のビルド） | 文書の basename が巻の中で重ならない |
| 全巻目次 | `outline_target_htmls` が `_whole_toc` を選ぶ | 全巻目次の `h1` に飛び先が出る |

- **プラグイン**: `EnhancedProvider#add_outline!` に渡す項目は、今の `:level`・`:text`・`:page` に `:top` を足すだけである（R7）。
- **MIT 版**: `StandardProvider#add_outline!` は今と同じく、しおりを付けずに 💡 で入れ方を示す。ページと位置を決める処理は本体にあるので、どちらの経路でも同じものが渡る。
- **単章ビルド**: 今と同じく、しおりを付けない（`apply outline to output pdf` は全体だけの工程）。

### R6: 文字でページを探す仕組みを外す

R2 で要らなくなるものは、互換のために残さず外す。

- `pdftotext` で全ページの文字を読む処理（`read_page_texts`・`build_search_helpers`・`build_search_terms`）
- 章ごとのページの範囲を推定する処理（`calculate_chapter_ranges`・`detect_front_matter_spans`・`page_range_*` 一式・`clamp_all_ranges` など）
- しおりのための表紙のページ数の補正（`PdfMerger#front_matter_offset`・`compute_front_matter_offset`・`start_page:`）
- 使われていない `prepend_cover_item`
- `validate_inputs` の `pdftotext` の確認。`pdftotext` は `vs pdf:read` が使うので、`vs doctor` の確認は残す。
- デバッグ出力（`OutputHelpers#print_outline_debug_info`）は、章の範囲の代わりに、項目ごとの「文書・id・ページ・飛び先が見つかったか」を出す。

原稿の `contents/44-build.md` の「付与には `pdftotext`（poppler）が必要で、`vs doctor --fix` で導入できます。」を消す。

### R7: 節と項は、見出しの位置まで飛ぶ

飛び先の配列 `[ページ, /XYZ, x, y, 0]` の `y`（見出しの上端。§1.5）を、項目の `:top` として渡す。プラグインの `OutlineWriter` は、`:top` があれば `[ページ, :XYZ, nil, top, nil]` を書く。

- 左端（`x`）と倍率は `nil` にして、読者の今の横の位置と倍率を保つ。Vivliostyle の `x` は見出しの左端なので、そのまま使うと、拡大して読んでいる読者の画面が横へずれる。倍率の `0` も「変えない」の意味だが、`nil` にそろえる。
- **章（`h1`）と特別なページは、今と同じくページ全体を見せる**（`:top` を渡さない）。章扉は、見出しの上に扉絵や「第1章」の文字があるので、見出しの位置へ飛ぶとそれが画面の外へ出てしまう。
- `:top` が無い項目は、今と同じページへの飛び先を書く。R3 で直前の項目を借りた見出しにも `:top` を渡さない（別の見出しの位置へ飛ばさないため）。
- **版の組み合わせ**: 新しい本体と古いプラグイン（公開済みの 1.1.2）では、`:top` が読まれずページの頭へ飛ぶ。古い本体と新しいプラグインでは `:top` が来ないので、今と同じになる。どちらの組み合わせでも、しおりは壊れない。
- プラグインの変更は、まだ公開していない 1.2.0 に入れる。版は上げない。プラグインの CHANGELOG とテストも直す。
- 入稿用 PDF では、`y` を入稿用 PDF の飛び先から読む。トンボ・塗り足しを付けるときに飛び先の座標も一緒にずれているので（§1.5）、閲覧用の値を写さない。

## 4. やらないこと

- **部の中扉（`_partN`）をしおりに載せること**: 今も載せていない。載せるかどうかは、しおりの構成を変える別の話になる。
- **しおりの深さを `toc_depth` に合わせること**: しおりは今と同じく、常に `###` までである。

## 6. テスト

- **R1**: しおりの対象の HTML の `h1`〜`h3` ごとに空のリンクが 1 つずつ足され、対象でない HTML と `html/` の原本には足されない。id に `"`・`&` があっても、属性として壊れない。2 回走っても、リンクが増えない。
- **R2**: Prawn で 2 つの文書に同じ id の飛び先を持つ PDF を作り、文書と id の組で別々のページが引ける（`pdf_page_map_extractor_test.rb`。HexaPDF は使わない）。
- **R3**: 飛び先が無い見出しは直前の項目のページを指し、先頭なら文書の始まりのページを指す。
- **R4**: 章・付録・前書き・目次・用語集・索引の項目の文字が今と同じ（`outline_extractor_test.rb` の今の期待を保つ）。`heading_numbering: none` で「第N章」が付かない。
- **R6**: `pdftotext` が無くても、しおりの項目が作れる。
- **R7（本体）**: 節・項の項目には飛び先の `y` が `:top` として入り、章・特別なページと、R3 で直前を借りた項目には入らない。
- **R7（プラグイン）**: `:top` のある項目は `/XYZ` の飛び先に、無い項目は今と同じ飛び先になる。`:top` が数でないときは、ページへの飛び先に戻す（項目ごとに飛ばす今の作りに合わせる）。

テストを足したら、定義した数と実行された数が合うかを照らし合わせる。

## 7. 実ビルドで確かめる

しおりの各項目が指すページに、その見出しの文字があるかを数える。`pdftotext` でページの文字を取り、空白と改行を除いて照らし合わせる。飛び先とは別の手段で数えるので、作り直しの確かめになる。

| 本 | 組み方 | 見ること |
| :--- | :--- | :--- |
| 試しの本（本書の雛形の 4 章） | 閲覧用・入稿用 | 違うページを指す項目が 15 件から 0 件になる |
| 本書（`toc_depth: 2`） | 閲覧用・入稿用 | 違うページを指す項目が 0 件。項（`###`）もページ順に並ぶ |
| spiral-ruby | 合本・1 巻（全巻目次つき）・入稿用 | 1853 項目で、違うページを指す項目が 60 件から 0 件になる |
| 本書 | `full_bleed: true` の入稿用 | 組み直す経路でも 0 件 |

あわせて、次を確かめる。

- R3 の「飛び先が見つからない見出し」が、どの本でも 0 件である。
- 節・項のしおりで、見出しが画面の上端に出る。プレビュー（macOS）と Acrobat Reader で、閲覧用・入稿用の両方を目で見る。見出しが上端に貼り付いて読みにくければ、`:top` を本文 1 行分ほど上へずらすかを、そこで決める。
- 古いプラグイン（1.1.2）で組んでも、しおりがページの頭へ飛ぶ（壊れない）。
- ページ数・リンクの数・本文の文字が、作り直す前と同じである（R1 のリンクが組版を変えない）。
- EPUB・Kindle の HTML に、R1 のリンクが入っていない。
- 結合とアウトラインの工程の所要時間が延びていない（`pdftotext` の全ページ読みが無くなる分、縮むはず）。

## 8. 決めたこと

1. **節と項は、見出しの位置まで飛ぶ（2026-10-26 ユーザーと決定）。** ページの頭へ飛ぶだけだと、ページの下のほうにある節や項では、読者が見出しを目で探すことになる。プラグインを変える必要はあるが、1.2.0 はまだ公開していないので、版を上げずにその中へ入れられる（R7）。
   - ページの頭のままにして PLANNED.md に積む案もあったが、採らなかった。1.0 に入れる作り直しなので、読者に見える違いを先送りしない。
2. **この作り直しは 1.0（11/1）に入れる（同日ユーザーと決定）。** しおりが違うページを指したままでは公開できない。
