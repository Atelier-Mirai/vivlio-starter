### 1.2 語がとりうる状態

語の状態は、少なくとも次の軸の組み合わせで決まる。

| 軸 | とりうる値 | どこで決まるか |
| :--- | :--- | :--- |
| 辞書にあるか | 登録済み／未登録（候補）／除外済み | 辞書・除外済みファイル |
| 載せる先 | 索引（`i`）／用語集（`g`）／両方（`ig`） | 辞書の `flags` |
| 主要参照 | 確定（`main` あり）／推測（レビューファイルの `m?` だけ。辞書には無い）／なし | 辞書の `main`。「なし」と「まだ決めていない」は辞書の上で区別できない（#101） |
| 出どころ | 手動登録（`manual_markup`）／自動抽出（`auto_extracted`）／レビュー（`review`）／除外の解除（`unreject`）／ライブラリ（`imported`） | 辞書の `source` |
| 原稿の記法 | 本文に `[語]`・`[語|読み]` がある／ない | 原稿 |

レビューファイルでは、さらに表示上の仕分けが加わる。

| 節 | 仕分け | 決め方 |
| :--- | :--- | :--- |
| 1. 登録済み用語 | 一般語 | 半数以上の章に出る（`index.common_term_ratio`。6 章未満の本と 3 章未満の語は対象外） |
| | 見直し候補 | 未登録の候補と同じ土俵で並べると、目安の語数の外に出る（一般語と重なれば一般語を優先） |
| | 登録語 | 上のどちらでもない |
| 2. 推奨候補 | — | 目安の語数（`index.target_terms`）の内側に入る未登録語 |
| 3. 一般候補 | — | 目安の外側で、`index.candidate_pool` 倍までの未登録語 |
| | 見出しから拾った短い語 | 節の見出しに出る 2 字の語（推奨・一般の両方から集める） |
| 4. 除外済みリスト | — | 除外済みファイルの語 |

### 1.3 著者の操作の入口

**原稿の記法**

| 書き方 | 意味 |
| :--- | :--- |
| `[語|読み]`・`[語]` | 手動登録。その箇所を索引に入れ、`vs index:auto` が辞書に `i` を足す |
| 読みのない英数字 2 文字以下（`[mm]`） | 記法として扱わず、本文に角かっこごと残す。`vs index:auto` は「登録しません」と知らせる |
| 記号だけの語（`[!]`・`[&&]`） | 手動登録（索引語） |
| コード・リンク・脚注・タスクリストの中の `[...]` | 記法として扱わない |

**レビューファイルの印**

| 印 | 意味（`vs index:apply` での扱い） |
| :--- | :--- |
| `[i]`・`[g]`・`[ig]`（`[gi]`・`[x]` も可） | その先へ登録する。1 節では「載せたままにする」 |
| `[-i]`・`[-g]` | その先から外す。フラグが無くなった語は辞書から消え、除外済みへ |
| `[r]`（`[-ig]` も可） | 辞書から消して除外済みへ（定義文があれば警告） |
| `[ ]`・空欄 | 未決定。ただし 1 節の登録語では「載せない」と読まれる（§1.5） |
| `m21`・`m21,22` | 主要参照の指定（確定） |
| `m?21` | 機械の推測。そのまま採用される |
| 子行 `- 主要参照: 21#節` | 節まで指す主要参照（フラグ欄より優先） |
| `( )` の中 | 読みの修正 |
| 空行の後に字下げした行 | 用語集の説明文 |
| 4 節で `[i]`・`[g]`・`[ig]` | 除外を解いて登録 |

**コマンド**: `vs index:plan`（下見）・`vs index:auto`（候補の抽出とレビューファイルの生成）・`vs index:apply`（レビューファイルの反映）・`vs index:export` / `vs index:import`（ライブラリ）。ほかに `book.yml` の設定。

### 1.4 機械が自動でしていること

**`vs index:auto`**
1. 原稿の手動登録の語を辞書へ入れる。`flags` に `i` を足す——すでに `g` だけの語でも `ig` になる（#100）
2. 候補を抽出し、推奨・一般に分ける（登録済み・除外済みの語は除く）
3. 主要参照の推測を、未指定の登録語と候補に `m?` で付ける
4. 一般語・見直し候補を仕分ける。一般語には外す印 `[-i]` を付ける（主要参照が確定している語は `[i]`）
5. `index.auto_approve: true` なら推奨候補を自動で登録する（既定は `false`）
6. 走査した章を `scanned_chapters` に記録する

**`vs index:apply`**: §1.5 の表のとおり。あわせて、レビューファイルに `[i]` の行がない登録語から `i` を外し（`[g]` も同様）、フラグが無くなった語は辞書から消す（除外済みには入れない）。レビューファイルに表示しない登録語（自動抽出で入った、脚注参照やカラーコードの形をした語。`ReviewMarkdownGenerator#should_filter_term?`）も、行が無いので同じく外れる。4 節に残っている語が登録済みなら、除外済みから外す。

**`vs build`**
- 原稿の `[語]` の箇所は、辞書の `flags` に関係なく索引に入る——`g` だけの語でも、その箇所は索引に出る（2026-10-01 に確かめた。#100）
- 辞書の `i` の語は、本文のすべての出現を索引に入れる（英字の語は英字の語の境目を見る）
- 辞書の `g` の語は、章ごとの最初の 1 か所に `†` を付け、用語集にバックリンクを並べる
- 主要参照のある語は、索引でその箇所を太字・先頭にし、ほかの出現を `index.max_sub_references`（8）か所に絞る。主要参照のない語は絞らない
- `index_glossary.exclude_chapters` の章は、索引・用語集に使わない

### 1.5 レビューファイルを書き換えずに `vs index:apply` すると何が起きるか

著者がいちばん把握しにくいのはここである。欄ごとに既定の印が違い、結果も違う。

| 欄 | 既定の印 | 書き換えずに apply したとき |
| :--- | :--- | :--- |
| 1. 一般語（主要参照が未確定） | `[-i]`・`[-im?25]` | **索引から外れる**。`i` だけの語は辞書から消えて除外済みへ |
| 1. 一般語（主要参照が確定） | `[i]`・`[igm21]` | 変わらない |
| 1. 見直し候補・登録語（主要参照が確定） | `[i]`・`[igm44]` など | 変わらない |
| 1. 見直し候補・登録語（主要参照が未指定） | `[im?12]` など | **推測した主要参照が入る**（#101） |
| 2・3. 候補 | `[ ]`・`[m?61]` | 何も起きない |
| 4. 除外済み | `[ ]` | 何も起きない（登録済みと重なる語は除外から外す） |

著者が書き換えたときの結果も、欄によって違う。

| 書き換え | 1 節（登録済み） | 2・3 節（候補） | 4 節（除外済み） |
| :--- | :--- | :--- | :--- |
| `[ ]` にする・行を消す | フラグを失い、全部失えば辞書から消える（除外済みには入らず、次から候補に戻る） | 何も起きない | 何も起きない |
| `[-i]` | `i` を外す。`i` だけなら除外済みへ | — | — |
| `[r]` | 辞書から消して除外済みへ | 除外済みへ | — |
| `[i]` | そのまま | 登録 | 除外を解いて登録 |

## 2. 設計の意図と、そこからのずれ（2026-10-01 のユーザーの説明を受けて）

§1 の場合分けの多くは意図どおりに働いている。問題は、意図からずれた箇所に絞られる。

### 2.1 設計の意図

**印は「いま辞書にどう登録されているか」を示す。** レビューファイルの印は、辞書の現状をそのまま書き出したものである。そのまま `vs index:apply` すれば現状が保たれ、変えたいときだけ `[]` の中を書き換える。著者の編集の手間を減らすための形で、妥当である。

| 印 | 意味 |
| :--- | :--- |
| `[i]` | 索引に載せる。主要参照は付けない |
| `[im11]` | 索引に載せる。主要参照は 11 章 |
| `[g]` | 用語集だけに載せる |
| `[ig]`・`[igm11]` | 両方に載せる |
| `[m?11]`（候補）・`[im?11]`（登録済み） | 機械の推測。その推測でよければ、そのまま apply すれば採用される |
| `[ ]`（候補） | 未決定。`[i]`・`[ig]`・`[im11]` のどれにするかを著者が決める |
| `[-i]` | 索引から外し、次からは候補に出さない（棄却）。気が変わったら、除外済みの欄で `[i]` にすれば戻る |

欄ごとの既定の印も、この原則に沿っている。
- **一般語は `[-i]`**: 広く散らばる語は誤検出であることが多いので、外す印を推奨として付けておく。そのまま apply すれば索引に載らなくなる（現状を示す原則の、意図した例外）。主要参照が確定している語は、説明箇所がある語なので `[i]` で出す（改善案 #99 で直した）。
- **見直し候補・登録語は `[i]`**: そのまま apply すれば、次からも索引に載り続ける。
- **候補は `[ ]`**: 載せるか、どこに載せるか、主要参照を付けるかは著者が決める。
- **推測は `m?`**: その推測でよければ、そのまま apply すれば登録される。

**原稿の `[語]` が索引と用語集の記法を兼ねるのは妥当である。** 簡便な記法を 1 つだけ覚えればよい。`[語]` を索引に登録するなら、その決定を記録するために辞書にも入れるのも妥当である。

**外すことは棄却である。** 一度索引から外した語を、もう一度候補に挙げられても迷惑である。§1.5 の「`[-i]` で除外済みへ入る」は意図どおり（#97 で 55 語が除外済みに入ったのは、仕組みでなく選定の問題だった）。登録済みの行を `[ ]` にした場合は、外れるが候補には戻る。これは、最初から `[ ]` だった候補と見分ける手段がないためで、二度と出したくなければ明示的に `[-i]` を書いてもらう。

### 2.2 意図からのずれ

1. **著者の判断を、次の `vs index:auto` やビルドが上書きする。** 混乱はここから生じている。
   - `[i]`（主要参照を付けない）と決めても、辞書には「`main` が無い」としか残らず、「まだ決めていない」と区別できない。次の `vs index:auto` が `[im?12]` と推測を付け直し、そのまま apply すると採用される（#101）。
   - `[g]`（用語集だけ）と決めても、原稿に `[px|px]` が残っていると、`vs index:auto` が `i` を足し直して `ig` にする。ビルドも、その箇所を索引に入れる（#100）。
2. **仕分けが多い。** 1 節だけで一般語・見直し候補・登録語の 3 つ、候補も推奨・一般・見出しから拾った短い語の 3 つに分かれる。著者にとって分かりやすいのは、次の 4 つくらいである。
   - いま登録されている語
   - 推奨する語（目安の語数の内側に入る語）
   - 残りの語
   - 棄却した語
3. **そのほか**（§1 で見つかった細かいもの）: レビューファイルに表示しない登録語が apply のたびにフラグを外される。使われていない `config/index_review_queue.yml` のコードが残っている。

## 3. 整理の方針

### 3.1 著者の判断を記録し、上書きしない

**優先の順位**: 辞書（レビューファイルで著者が決めたこと）＞ 原稿の記法 ＞ 機械の推測。機械の推測は、まだ決まっていないところを埋めるだけにし、決まったことを書き換えない。

#### 3.1.1 主要参照を付けない（#101）

辞書の `main` に 3 つの状態を持たせる。

| 辞書の `main` | 意味 | レビューファイル | 推測 |
| :--- | :--- | :--- | :--- |
| キーなし | まだ決めていない | `[im?12]`（推測を添える） | 付ける |
| `[]`（空の配列） | 付けない（著者が決めた） | `[i]` | 付けない |
| `[21-markdown-tutorial]` など | その章 | `[im21]` | 付けない |

**記録のしかた**: `vs index:apply` で、登録済みの語の行に主要参照が書かれていなければ（`[i]`・`[ig]`）、`main: []` を記録する。`[im?12]` のまま apply すれば、推測した 12 章を記録する（いまと同じ）。著者が `m?12` を消して `[i]` にすれば、「付けない」が残り、次の `vs index:auto` は推測を付けない。

- 候補を `[i]` で採ったときも `main: []` になる（§2.1 の「`[i]` なら主要参照を付けずに索引登録のみ」のとおり）。`[m?61]` を `[im61]`・`[im?61]` にすれば 61 章。
- `vs index:auto` が原稿の手動登録から入れた語は、キーなし（まだ決めていない）で入る。次のレビューで推測が付き、そのまま apply すれば採用される。
- 用語集だけの語（`[g]`）は主要参照を使わないので、記録しない。`index.reference_style: all`（主要参照の機能を切った本）でも記録しない。
- 既存の辞書は移行しない。いま `main` の無い語（本書では Git・トラブルシューティングの 2 語）は「まだ決めていない」として推測が付き、次の apply で決まる。

**いまのコードで `main: []` がどう扱われるか**（2026-10-01 に確かめた）: 推測の対象から外れる（`suggest_main_references` は `main` があれば除く。空の配列も「ある」）。レビューファイルでは `[i]` と出る（`TermLine.build` は章番号が無ければフラグだけを書く）。ビルドの索引は主要参照なしとして扱い、ほかの出現を絞らない（絞るのは出現に `is_main` があるときだけ）。ビルド後の「主要参照が未指定の索引語があります」の警告にも数えない。`vs rename` の追随も空のまま残す。**直す必要があるのは `apply_main_references!` だけ**で、いまは行に主要参照が無いと `main` を消し（キーなしに戻す）、しかも `Array(nil) == []` のため「変化なし」と判定する箇所がある。

#### 3.1.2 用語集だけ（#100）

原稿の `[語]` は、**辞書に無い語を登録する入口**とする。辞書にすでにある語については、辞書の判断を変えない。

| 原稿の `[px|px]` の語が | `vs index:auto` | `vs build`（その箇所） |
| :--- | :--- | :--- |
| 辞書に無い | `i` で登録する（いまと同じ） | 索引に入れる |
| 辞書に `i`・`ig` で有る | フラグを変えない（いまは `i` を足す） | 索引に入れる（いまと同じ） |
| 辞書に `g` だけで有る | フラグを変えない（いまは `ig` にする） | 索引に入れず、用語集の語として扱う（章の最初なら `†`）。いまは索引に入れる |

- 読みを添えた `[px|ぴくせる]` で、辞書の読みと違うときも、辞書を変えない（読みはレビューファイルの `( )` で直す）。違いは知らせる。
- `vs index:auto` の「辞書を更新しました: 手動登録 N 語」は、新しく入った語だけを数える。

**棄却した語が原稿に `[語]` で書かれていたら**（決定 2026-10-01・案 2）: 辞書の判断（棄却）を優先する。

| | `vs index:auto` | `vs build`（その箇所） |
| :--- | :--- | :--- |
| 除外済みの語の `[語]` | 登録しない。「11-intro:321 に [セットアップ] がありますが、除外済みです。載せるなら除外を解いてください」と知らせる | 索引に入れず、角かっこを外した語だけを組む |

検討した案 1（原稿の記法を新しい意思表示とみなし、登録し直す。いまの動き）は採らない。棄却したことを忘れて書いた場合に気づけないため。この状態は、次の §3.1.3 によって、棄却の後に著者が新しく書き足したときにしか起きなくなる。

#### 3.1.3 棄却するとき、原稿の印も外す

原稿に `[語]` と書いた語を、レビューファイルで「やっぱり止めよう」と棄却する場面がある。辞書だけを棄却すると、原稿の印が残り、辞書と原稿が食い違う。そこで `vs index:apply` は、**辞書から消える語**（`i` だけの語の `[-i]`・`g` だけの語の `[-g]`・`[r]`）に原稿の印があれば、著者に確かめる（ユーザーの提案 2026-10-01）。

```text
❓ 11-intro:321 ほか 2 箇所に [セットアップ] と書かれています。原稿の [] を外して除外しますか？ [y/N]:
```

| 答え | 原稿 | 辞書 |
| :--- | :--- | :--- |
| `y` | 印を外し、語だけを残す（`[セットアップ]` → `セットアップ`、`[語|読み]` → `語`）。すべての箇所 | 棄却する（除外済みへ） |
| `N`・Enter・端末でない実行 | 触らない | 棄却しない（いまの登録のまま）。「原稿の [セットアップ] を残したので、除外しませんでした」と知らせる |

- 問い合わせは語ごとに 1 回。出現箇所はすべて並べる（多ければ先頭の数か所と件数）。確認には `Common.confirm?` を使う（Enter だけ・端末でない実行は「いいえ」）。
- 印を外す箇所の見分け方は、ビルド・lint と同じ `IndexMarkup`（コード・リンク・脚注・タスクリストの中は触らない）。`index_glossary.exclude_chapters` の章も対象にする（印が残ると、章を対象へ戻したときに食い違う）。
- 辞書に残る語（`ig` の語の `[-i]` で `g` が残るなど）は問い合わせない。§3.1.2 のとおり、原稿の印は用語集の語として扱われる。
- 書き換えたファイルと箇所の数は、apply の結果報告に添える。

すべての問い合わせに「はい」と答えるオプション（`--yes`）は付けない（決定 2026-10-01。原稿を書き換える操作で、棄却する語の多くは原稿に印が無いので、問い合わせが多く並ぶことはない）。
#### 3.1.4 レビューファイルに出ない語を消さない

`vs index:apply` は、レビューファイルに行の無い登録語からフラグを外している（§1.4）。表示しない登録語（脚注参照やカラーコードの形をした自動抽出の語）まで、apply のたびに外れる。フラグを外すのは、レビューファイルに行がある語に限る。その結果、著者がレビューファイルから行を消した語も、辞書はそのまま残る（外すなら `[-i]`、載せる先を減らすなら印を書き換える）。行を消すことを「外す」の意味に使う著者がいるかは、33 章の説明と合わせて確かめる。
### 3.2 仕分けを 4 つにする

レビューファイルの節を 4 つにし、小節（一般語・見直し候補・見出しから拾った短い語）は立てない。見直し候補は仕分けそのものをなくす（§5.2）。

- **一般語**: 「登録済み」の中に並べ、行末の注記で示す（`- 一般語: 20/27 章（74%）に出現`。いまと同じ）。印は §2.1 のとおり `[-i]`（主要参照が確定していれば `[i]`）。節の頭の案内文で印の理由を伝える（決定 2026-10-01）:

  > 外す印 `[-i]` が付いた語は、本の広い範囲に散らばっていて、索引から引いても説明箇所が分からない語です。次から候補に出さなくてよければ、このまま `vs index:apply` してください。索引に残したい語は `[i]` に（説明している章があれば `[im21]` に）してください。

  一般語は「スコアが低い語」ではなく「広く散らばる語」である（Markdown 273.7・PDF 265.8 のように推奨候補並みのスコアがある）。案内文でスコアの話にしない。
- **見出しから拾った短い語**: 小節をなくし、推奨・残りの中にスコアの順で並べる（決定 2026-10-01）。#98 で 1 か所にまとめたのは「判断を一度に済ませたい」ためだったが、本書で拾った 103 語のうち辞書に入っているのは 8 語（脚注・数式・ルビ・章扉・表紙・判型・扉絵・版面。どれも #97 の選定で手で入れた語）で、未判断の 95 語の大半は 目安・件数・項目・理由・対象 のような一般的な語だった。索引に入れてもよさそうなのは 書体・段組・雛形・図版・寸法 くらいで、まとめて見せる価値は小さい。2 字の語を見出しの経路で拾うこと自体（#98）は残す。

見出しから拾った語には、行末の注記を付けない（決定 2026-10-01。辞書に入った 8 語のほかは一般的な語ばかりで、注記があっても判断の助けにならない）。行は他の候補と同じ形になる。

#### 3.2.1 節と案内文

```markdown

（凡例）

※ 外す印 `[-i]` が付いた語は、……（§3.2 の決定の文面）
```

- **1 節の並び**: 小節を立てない代わりに、apply で変わる行を先に置く。外す印 `[-i]` の行 → 推測 `m?` の行 → それ以外、の順。各まとまりの中は、いまと同じ順（ラベルと出現順）。
- **行の書式は変えない**。注記は行末だけに置く（`TermLine::LINE` を変えると読み取りがすべて壊れる。§1 の 9 つの読み取りが 1 つの綴りを共有している）。
- **凡例**（冒頭の ※ の行）は、§2.1 の印の表を短くしたものにする。いまの 7 行のうち、主要参照の書き方（`m21`・`m?21`・子行）と除外済みの説明は、それぞれの節の案内文へ移す。

#### 3.2.2 呼び名をそろえる

著者が目にする呼び名を、4 つの節の名前にそろえる。

| いまの呼び名 | 新しい呼び名 | 出てくる場所 |
| :--- | :--- | :--- |
| 推奨候補 | 推奨する語 | レビューファイル・`vs index:auto` の結果報告・`vs index:plan`・33 章 |
| 一般候補 | 残りの語 | 同上 |
| 除外済み・除外リスト・リジェクト | 棄却した語・棄却 | レビューファイル・`vs index:auto` / `apply` の結果報告・33 章・41 章 |
| 見直し候補 | なくす（§5.2） | レビューファイル・`vs index:plan`・33 章 |
| 一般語 | 一般語（同上） | レビューファイル・33 章・`book.yml` のコメント（`common_term_ratio`） |

「棄却」にそろえるのは、凡例の `[r]=棄却` と、ユーザーの呼び方（棄却語）に合わせるため（決定 2026-10-01）。ファイル名（`index_glossary_rejected.yml`）と設定のキーは変えない。

`vs index:plan` の表示（推奨候補・一般候補の件数）も新しい呼び名に変える（決定 2026-10-01。plan は auto の下見なので、呼び名がそろう）。

### 3.3 原稿に出てこない語・使っていない語・削除（2026-10-02 に追加）

§3.2 の実装の後、本書のレビューファイルを確かめて出てきた論点（ユーザーとの検討）。

**きっかけ**: 33 章の書き直しで旧い呼び名（推奨候補・一般候補・見直し候補）が原稿から消え、辞書の 3 語が 1 節に `[im33] … - [原稿に出現しません]` と出た。原稿に出てこない棄却した語（Hz・Step など）は 4 節に出る。同じ性質の語がファイルの離れた 2 か所（本書では 862 行目と 1912 行目あたり）に散らばり、著者には分かりにくい。また、印が `[im33]` のままなので、書き換えずに apply すると、出現箇所のない語が辞書に残り続ける。

#### 3.3.1 5 節「原稿に出てこない語」

ファイルの最後に 5 節を立て、原稿に出てこない語を 1 か所にまとめる。1 節と 4 節には、原稿に出てくる語だけを残す。

| 語の出どころ | 5 節での既定の印 | 書き換えずに apply したとき |
| :--- | :--- | :--- |
| 登録済みの語 | `[ ]` | 索引・用語集から外す。棄却はしない（原稿に書き戻せば、また候補に出る） |
| 棄却した語 | `[ ]` | 棄却のまま（戻すときは `[i]` など） |
| 使っていない語（§3.3.2） | `[ ]` | そのまま |

- 最初から外す印 `[-i]` を付ける案は採らない。棄却になるので、著者が原稿に書き戻しても二度と候補に出なくなる（ユーザーの指摘）。
- 「原稿に出てこない」は、索引の対象の章（`index_glossary.exclude_chapters` を除く）のどこにも出てこないこと。いまの「[原稿に出現しません]」の判定と同じ。

#### 3.3.2 使っていない語（説明文を残す）

`[ ]` で外すと、いまは辞書から語ごと消え、用語集の説明文も失われる。説明文は著者が手で書いたもので、機械が作り直せない。かといって `[ig]` のまま残すと、原稿にない語が用語集のページに載り続ける（用語集は原稿に出てこない語も載せる作り）。`[ig]` は「索引・用語集として扱う」という印なので、意味が合わない（ユーザーの指摘）。

そこで、辞書に「使っていない語」の状態を足す。

- 辞書の `flags` を空にして、読み・説明文・主要参照ごと残す。索引にも用語集のページにも出ない。
- `[ ]` で外したとき、説明文のある語だけがこの状態になる。説明文のない語は、いまどおり辞書から消える。
- 原稿に書き戻すと、`vs index:auto` は候補として出し、行の下に以前の説明文を添える。`[g]`・`[ig]` にすれば、説明文を書き直さずに戻る。
- 原稿に出てこないあいだは、5 節に `[ ]` で並ぶ。

#### 3.3.3 `[DELETE]` — 記録ごと消す

棄却（`[r]`）は「二度と候補に出さない」という記録を残す操作で、誤って辞書に入った語（「Step」など）を消す手段がない。棄却したままにすると、ゴミの記録がずっと残る（ユーザーの指摘）。記録ごと消す印 `[DELETE]` を足す。

| 欄 | `[DELETE]` の動き |
| :--- | :--- |
| 1. 登録済みの語 | 辞書から消す（説明文も）。棄却はしない |
| 4. 棄却した語 | 棄却した語の一覧から消す。原稿に出てくれば、また候補に出る |
| 5. 原稿に出てこない語 | 登録済み・棄却・使っていない語のどれでも、記録ごと消す |
| 2・3. 候補 | 何も起きない（まだ記録がない） |

- 綴りは大文字の `[DELETE]`。ほかの印は短い小文字だが、取り返しのつかない操作なので目立たせ、うっかり書かないようにする（大文字・小文字は区別しない）。
- 説明文のある語を消したときは、「説明文ごと削除しました」と語の名前を添えて知らせる。
- 原稿に `[語]` の印が残っている語を消すと、次の `vs index:auto` で辞書に入り直す。§3.1.3 の棄却と同じく、「原稿の [] を外して削除しますか？」と確かめ、「いいえ」なら削除しない。
- 使い分けの例: 「Step」のような誤登録は `[DELETE]`。「画像最適化」（44 章に書き足せば戻りうる）や 97 章の語（Hz・eV・ニュートン・重力。97 章を対象に戻せば戻る）は、棄却のまま残す。

5 節の中は、apply で変わる登録済みの語を先に、使っていない語 → 棄却した語の順に並べる（決定 2026-10-02）。節の頭の案内文:

> 原稿のどこにも出てこない語です。登録済みの語は、そのまま `vs index:apply` すると索引・用語集から外れます（説明文のある語は、使っていない語として残ります）。誤って登録した語は `[DELETE]` で記録ごと消せます。

これで節は 5 つになる（§3.2 の「4 つ」に 5 節を足す）。

### 3.4 印の読み方 — マイナスは直後の 1 文字にだけ掛かる（2026-10-02 に追加）

**きっかけ**: 一般語の `ig` の語には外す印が `[-im?21]` と付き、用語集に載っていることが行から読めなかった（`g` が見えない）。そのまま apply すれば索引からだけ外れて用語集には残るが、著者には「用語集からも消えるのでは」と見える。用語集だけの語に一般語の印を当てていた不具合（§6.1）も、これが元で見落とした。ユーザーの提案で、印に `g` を残して `[-igm?21]` と出す。

そのため、いままで「両方外す（棄却）」だった `[-ig]` の読み方を改め、**マイナスは直後の 1 文字にだけ掛かる**とする（決定 2026-10-02）。文字の順番は問わない。

| 印 | 意味 |
| :--- | :--- |
| `[-ig]`・`[g-i]` | 索引から外し、用語集には残す |
| `[i-g]`・`[-gi]` | 用語集から外し、索引には残す |
| `[-i-g]`・`[r]` | 両方から外して棄却する |
| `[-i]`・`[-g]` | いまと同じ（その先から外す。どこにも載らなくなれば棄却） |

- 機械が出す印は、いまの登録の文字をすべて含める。一般語の `ig` の語は `[-igm?21]`、`i` だけの語は `[-im?21]`。
- 主要参照は索引の機能なので、索引から外れる語（`-i` の付いた語）には、印に `m?21` が書かれていても記録しない。
- いまの `[-ig]`（両方外す）は凡例にも 33 章の印の表にも載せていなかったので、読み方を変えても影響は小さい。両方外すには `[-i-g]` か `[r]` を書く。
- 判定は `TermLine` の 1 か所（`kept`・`removed` と、それに基づく `index?`・`glossary?`・`reject_*?`）。用語集の承認（`parse_glossary_approved`）も、文字列の比較をやめて同じ判定を通す。

## 4. 移行と原稿

### 4.1 既存のデータ

| データ | 扱い |
| :--- | :--- |
| 辞書の `main` が無い語 | 移行しない。「まだ決めていない」として推測が付き、次の apply で決まる（本書では Git・トラブルシューティングの 2 語） |
| 辞書の `g` だけの語と原稿の印 | 移行しない。§3.1.2 の新しい扱い（ビルドで用語集の語として扱う）が、そのまま効く |
| 除外済みファイル | 変えない（ファイル名もそのまま） |
| 古い形式のレビューファイル | 節の見出しが変わるので、古いファイルのまま `vs index:apply` すると読み違える。新しい見出しが見つからなければ、apply を止めて「レビューファイルが古い形式です。`vs index:auto` で作り直してください」と知らせる（古い見出しの読み替えは持たない） |

本書の原稿にある手動登録の印は、33 章の `[五十音順|ごじゅうおんじゅん]` の 1 か所だけで（辞書では `i`）、移行で困る箇所はない（2026-10-01 に数えた）。

### 4.2 33 章の書き直し

**書くのは、著者が使うために要る情報だけにする**（ユーザーの指示 2026-10-01）。外から見える振る舞いは RC3 から微調整に留まるので、「以前はこうだった」「内部ではこう苦労した」のような開発の経緯は書かない。経緯はこの仕様書と CHANGELOG に置く。

| 節 | 書き直すこと |
| :--- | :--- |
| 原稿に印を付けて登録する | `[語]` は辞書に無い語を登録する入口であること。辞書にある語は、印があっても辞書の登録（用語集だけ・棄却）に従うこと。用語集だけに載せる手順（印で登録 → レビューで `[g]`） |

41 章（`book.yml` の説明）と `config/book.yml` のコメントも、呼び名をそろえる。`config/book.yml` の `index.target_terms` のコメントは、プリセットの訳語（少なめ・標準・多め）に直し、誤って standard に付いていた「既定」を light へ移した（2026-10-02 に済み）。雛形は `copy_to_scaffold.rb` で同期する。

### 5.2 見直し候補は役に立っていない

見直し候補（登録語と候補を同じ土俵で並べ、目安の語数の外に出た登録語）を、本書で調べた（2026-10-02）。

- **登録済みの索引語 188 語のうち 78 語（4 割）が見直し候補になる**。数式・扉絵・版面・箇条書き・Markdown・PDF・電子書籍・Vivliostyle・トンボ・塗り足し・付録・奥付・前書き のような本の要語が並ぶ。
- **採点の仕方の違いは原因ではない**。登録語は候補より性質の加点が少ない（定義文・名詞連続を判定しない）が、同じ語を候補と同じ採点にかけても差は 10 点前後で、目安の内側に入るのは 78 語中 9 語だけだった。境目（207 位）は 298 点で、250〜300 点に多くの語が詰まっているため、わずかな点の差で順位が大きく動く。
- **原因は順位付けそのものの限界である**。#98 の物差し（`scripts/index_candidate_eval.rb`）で、著者が選んだ語のうち目安の語数までに入るのは約 54%。残りの約 46% は、構造上すべて見直し候補になる。見直し候補は「外したほうがよい語」ではなく「機械が当てられなかった著者の語」を並べている。

**決定（2026-10-02）**: 見直し候補をなくす。plan にもレビューファイルにも出さない（§3.2 の「1 節の行末の注記として残す」を改める）。帯の計算（`TermRanking`）は、推奨する語（目安の内側の未登録語）を決めるために残す。一般語の `[-i]` は「広く散らばる」という別の性質を見ていて、主要参照の有無で印も変えるので、残す。

### 6.1 §3.3 の実装（2026-10-02）

- **5 節**: `ReviewMarkdownGenerator::ABSENT_SECTION`・`build_absent_section`。4 節の読み取り（`term_lines_in_rejected_section`）は 5 節の手前で区切る——区切らないと、5 節の登録済みの語の `[ ]` を「棄却のまま」と読み、apply の 4 節の同期がその語を棄却してしまう。`UnifiedIndexManager#auto_process!` で、登録済みの語・棄却した語を文脈の有無（`contexts` が空か）で分け、使っていない語を足して 5 節へ渡す。
- **使っていない語**: 辞書の `flags` を空にした語。`UnifiedTermsManager#remove_flag!(…, keep_unused: true)` を apply の孤立除去（`[ ]` で外したとき）だけが使う。`[-i]`・`[-g]`・`[r]` の棄却は従来どおり語ごと消す。候補から除く「載せている語」は `listed_term_names`（flags が空の語を含まない）にし、使っていない語のうち原稿に出てくる語は `with_returning_unused_terms` で候補へ戻す（抽出の経路が拾わない語もあるので、辞書の語として採点して足す）。候補の行には以前の説明文を添える——残りの語の欄（1 行に詰める形）でも出す。出さないまま `[g]` にすると、空の説明文で残しておいた説明文を上書きするため。原稿の `[語]` が使っていない語に付いていれば、書き戻しとして登録し直す。
- **`[DELETE]`**: `TermLine#delete?`（大文字・小文字を区別しない）・`parse_deleted`・`delete_record!`（辞書と棄却した語の一覧の両方から消す）。原稿に印が残る語は `confirm_markup_removal(…, action: '削除')` で確かめる。承認（`[i]`・`[g]`）した語は、棄却した語の一覧に残っていれば外すようにした（5 節の棄却した語を `[i]` にしたときに、登録と棄却の両方に載らないように）。
- **テストの落とし穴**: 短い原稿では目安の語数が 0 語になり、推奨・残りのどちらの帯にも語が入らない。候補として戻ることは、帯分けの前の段（`with_returning_unused_terms`）で確かめる。

- **動作確認で見つかった不具合（2026-10-02）**: 一般語の外す印と主要参照の推測を、用語集だけの語にも当てていた。棄却した語から `[g]` で戻した「Vivlio Starter」（16/27 章に出る）が `[-im?00]` と出て、そのまま apply すると用語集から外れて使っていない語になるところだった。`enrich_terms_with_context` で、どちらも索引に載せている語だけに当てる。

**残り**: 雛形（`lib/project_scaffold/`）の同期（`copy_to_scaffold.rb`）。
- **§3.4（2026-10-02）**: `TermLine` の判定を、印の文字を 1 つずつ読む形に作り直した（`MARK`・`kept`・`removed`・`kept_flags`）。棄却した語から戻すときの登録先は `kept_flags`（i・g・ig）で渡す。一般語の `ig` の語は `base_flag` が `-ig` を返す。`apply_main_references!` は索引に載らない語を飛ばす。いままでの `[-ig]` を両方外す前提だったテスト 1 件を、新しい読み方に改めた。
- **綴りの子行（2026-10-02・改善案 #103）**: `- 綴り: 新しい綴り` で見出し語を直せるようにした（`parse_spelling_changes`・`rename_term!`・`apply_spelling_changes!`）。lint（改善案 #102）は辞書を正典とするので、辞書の側を直す入口として足した。
- **綴りを直したときの原稿（2026-10-03・改善案 #103 追補）**: 原稿に古い綴りが残っていれば、原稿も直すかを確かめる（`ManuscriptMarkup.spelling_places`・`respell!`・`UnifiedIndexManager#confirm_manuscript_respelling`）。索引の照合は大文字・小文字を区別し、lint は空白の違いしか見ないため、原稿を残すと黙って索引から外れていた。空白の揺れの照合は lint から `TermPattern.spacing_insensitive` へ移して共有し、前後の境目には `_` も数える（コードを伏せた目印 `__VS_CODE_SPAN__0__` の中に当てないため）。`index_glossary.exclude_chapters` の章は直さない。
- **索引の照合の境目（2026-10-03）**: 辞書の照合の綴りが語をそのまま写したもの（`/Type\ 3/`）なら、英数字で始まる・終わる語に英数字の境目を足して読む（`TermPattern.literal`）。これまで `\b` が付くのは英字だけの 1 語で、「Type 3」が「Type 30」にも当たっていた。lint・原稿の書き換えと同じ規則になる。本書の辞書 210 語のうち 20 語に境目が付き、原稿での照合の数は変わらなかった。
