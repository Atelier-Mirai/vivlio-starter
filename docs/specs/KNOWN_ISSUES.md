## 既知の制限（運用回避推奨）

### 長い見出しの折返し位置が PDF と EPUB / Kindle で一致しない
* **詳細:** PDF は CSS の `word-break: auto-phrase`（Chromium 119+）が日本語を**文節**で割るが、EPUB / Kindle の見出しは**飾りと文字を 1 枚に焼いた合成画像**なので、折返しを Ruby（`HeadingImageComposer#split_by_display_width`）が表示幅だけで決める。そのため同じ節題が PDF では「新規プロジェクトの／作成」、EPUB では「新規プロジェクトの作／成」のように違う位置で割れることがある。
* **原因:** 構造的なもの。合成画像の中では CSS のテキスト整形が働かない。
* **対応方針:** **「割らずに済ませる」**のが実用解。`theme.frontispiece.heading_chars` / `theme.ornament.heading_chars` を見出しの実長以上にすれば 1 行に収まり、差が現れない（1 行の字数は両ターゲットで一致するため、収まるかどうかの判断は共通）。Ruby 側に文節分割を実装して合わせる案は採らない——MeCab に依存させると同じ原稿が環境によって別の本になり、ルールベースの簡易実装では `auto-phrase` と結果が一致せず「揃えたつもりでずれる」ほうが悪い。詳細は `heading-metrics-spec.md` §5-5。
* **補足:** 合成画像は元々**ビルド機のフォントで文字を焼く**方式（`math-frontispiece-svg-spec.md` §B-7 で字形差は許容済み）なので、字形レベルの一致はもともと目標にしていない。

### `vs lint --fix` は文脈を見ないので、部分一致で文を壊すことがある
* **詳細:** 辞書の置換が語の途中に当たると、文として成立しない結果になる。実測（2026-09-17・22 章）：

  | 直す前 | `--fix` の結果 |
  | :--- | :--- |
  | 図はコードフェンスで囲むこと**をおす**すめします | ことを**押す**すめします |
  | 「上・右・下・左」の**時計**回り | 「上・右・下・左」の**とき計**回り |

  どちらも `vs lint` の表示では `をおす => を押す` / `時計 => とき計` として出ており、**著者が目で見れば誤検出と判断できる**。`--fix` だけがそれを通してしまう。
* **原因:** 構造的なもの。`--fix` は textlint に原稿を直接直させる別経路（`apply_textlint_fixes!`）で、解析パスが行う無効化・抑止の判断を経ない。prh は前方一致で置換するため、語の途中に当たったことを検知できない。
* **対応方針（運用）:** **`--fix` は章単位でかけ、直後に `git diff` を見る。** 全章へ一度にかけない。指摘を一覧してから直す語を選ぶなら、`--fix` を使わず手で直すほうが速い場合も多い。
* **対応方針（実装・未着手）:** 根治するなら「解析パスが残した指摘に対応する修正だけを当てる」作りへ変える必要がある。textlint の `--fix` に任せるのをやめ、`--format json` の `fix` 範囲を自前で適用することになるため、範囲の重なりの解決まで自前で持つことになる。なお、**著者の抑止指示（`<!-- vs-lint-disable-next-line -->`）と文体設定（`lint.trim_long_vowel`）が `--fix` に効かない問題は 2026-09-17 に解消済み**（CHANGELOG の Fixed を参照）。残るのはこの「部分一致」だけ。

### 本文の最初の章が 1 ページだけだと、次の章からノンブルがずれる
* **詳細:** 本文の最初の章が 1 ページに収まると、目次と参照ではその章が「1」ページになるのに、次の章からのノンブルが本の先頭から数えた番号のままになる（2026-09-29、前書き・本文 2 章・付録の試験用の本で第 2 章が「7」）。最初の章が 2 ページ以上あれば起きない（3 ページ＋白ページ・4 ページ・10 ページで確かめた）。
* **原因:** Vivliostyle 側の挙動とみられる。本文の最初のページで番号を 1 に戻す指定（`chapter.css` の `@page body-start:nth(1) { counter-reset: page 0; }`）を置いたページが、その文書の最後のページでもあると、次の文書へは戻す前の番号が引き継がれる。要素（`body.chapter-first`）に `counter-reset: page` を置く形は Vivliostyle が無視する。
* **対応方針:** 本文の最初の章が 1 ページだけの本は実際には書かれないので、既知の制限として残す（改善案.md #71、2026-09-29 に判断）。書き始めで最初の章が短いうちに目次や参照のページ番号が合わないときは、章が 2 ページ以上になれば直る。

### Kindle で、囲み枠の中の画像が枠の下へはみ出すことがある
* **詳細:** `.img-text` や `.book-card` を `:::{.output}` などの枠の中に置き、本文が画像より短いと、枠は本文の高さで閉じ、画像が枠の下へはみ出す。本書では 23 章の `.gap-l` と `.book-card` の例が当たる。本文が画像より長ければ起きない。枠の外に置いても起きない。
* **原因:** KFX は、中の float まで枠を伸ばさない。`::after` の clearfix・実体の `clear: both` の要素・`inline-block` のどれでも囲めなかった（2026-11-01、Kindle Previewer 4 で確認）。
* **対応方針:** 見た目だけの問題で、文字は読めるのでこのままにする。枠の中で使うなら、本文を画像より長くする。

### Kindle の表で、`--` や `.` で始まるコードだけのセルが 1 段左へずれる
* **詳細:** `--cover` や `.aki` のように、コードだけのセルの 1 行目がセルの余白の分だけ左へずれる。`--purge / -P` のように文字が続くセルや、`:recto` のセルはずれない。91 章の表で目に付く。
* **原因:** KFX の描画による。変換の時点ではセルの余白は保たれている。`white-space` を変えても直らなかった。
* **対応方針:** 読むのに支障はないので、このままにする。
