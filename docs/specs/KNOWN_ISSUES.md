## 既知の制限（運用回避推奨）

### Kindle でテキスト化できない複雑なインライン数式のサイズが不安定
* **詳細:** 2026-07-19 に **Kindle 限定のインライン数式テキスト化**を実装し、単純な式（`E=mc^2`・`1/299,792,458`・単位・ギリシャ・上下付き・記号など）は SVG 画像でなく HTML テキスト（`<i>`/`<sup>`/`<sub>`＋Unicode）へ変換されるようになった。テキストは定義上フォントサイズに 100% 追従するため、本文・表セル内とも崩れない（原稿 `contents/` の現行インライン数式はすべてこのサブセットに収まりテキスト化される）。
* **残る制限:** テキストで表現できない複雑な式（`\sqrt`・`\sum`・積分・2 段入れ子の上下付き・入れ子分数など）は従来どおり SVG 画像のまま残り、`px` 固定フォールバックが効くため巨大化はしないが、読者のフォント拡大には追従しない。
* **対応方針:** 複雑な式は**ディスプレイ数式（`$$…$$`）として行を占有させる**か、表セル内に置かないことを推奨（ディスプレイ数式は px 固定でも破綻しない）。詳細は `kindle-inline-math-textify-spec.md`。

### 長い見出しの折返し位置が PDF と EPUB / Kindle で一致しない
* **詳細:** PDF は CSS の `word-break: auto-phrase`（Chromium 119+）が日本語を**文節**で割るが、EPUB / Kindle の見出しは**飾りと文字を 1 枚に焼いた合成画像**なので、折返しを Ruby（`HeadingImageComposer#split_by_display_width`）が表示幅だけで決める。そのため同じ節題が PDF では「新規プロジェクトの／作成」、EPUB では「新規プロジェクトの作／成」のように違う位置で割れることがある。
* **原因:** 構造的なもの。合成画像の中では CSS のテキスト整形が働かない。
* **対応方針:** **「割らずに済ませる」**のが実用解。`theme.frontispiece.heading_chars` / `theme.ornament.heading_chars` を見出しの実長以上にすれば 1 行に収まり、差が現れない（1 行の字数は両ターゲットで一致するため、収まるかどうかの判断は共通）。Ruby 側に文節分割を実装して合わせる案は採らない——MeCab に依存させると同じ原稿が環境によって別の本になり、ルールベースの簡易実装では `auto-phrase` と結果が一致せず「揃えたつもりでずれる」ほうが悪い。詳細は `heading-metrics-spec.md` §5-5。
* **補足:** 合成画像は元々**ビルド機のフォントで文字を焼く**方式（`math-frontispiece-svg-spec.md` §B-7 で字形差は許容済み）なので、字形レベルの一致はもともと目標にしていない。

### インライン脚注 `^[短い補足]` が脚注にならない
* **詳細:** 本文に `^[補足]` と書くと、`^` が本文に残りブラケットだけが消えて、脚注の本体が本文へ流れ込む（`…あたります^この 49 ページ…安全です。。`）。`<a class="footnote-ref">` も生成されない。**VFM 自体はインライン脚注に対応している**（素の VFM に通すと参照形式と同じ HTML になる）ため、壊しているのは本プロジェクトの前処理。
* **原因:** 未特定。索引の手動マークアップ `[用語]` との綴りの衝突が疑わしいが、`IndexMatchScanner#process_term` を通ったなら `<dfn>`/`<span>` が出るはずで実際には出ていないため、別経路の可能性がある。切り分け手順は `inline-footnote-collision-notes.md` §3。
* **影響:** インライン脚注は `contents/21-markdown-tutorial.md` と記法早見表で「使える記法」として案内している。ただし 21 章の使用例はコードフェンス内で前処理を通らないため、現時点で原稿は壊れていない（フェンス外の実使用は 0 件）。
* **回避策:** 参照形式 `[^label]` を使う（正常に動作し、同一ページ下部の脚注として組まれる）。
* **ステータス:** 優先度低。h1/h2 の意匠作業を優先し、後日調査する。

## 要確認（軽微・検証待ち）

### EPUB の表紙画像が一回り小さく見える
* **詳細:** 表紙画像の埋め込み自体は解消済みだが、実機（あるいはビューア）によって表紙が一回り小さく表示されるケースがある。
* **原因:** EPUBカバーの想定アスペクト比（1600×2560, 比 1:1.6）と、本文のA4サイズ（比 1:1.414）の比率差による見え方の違い。カバー画像側の設計上の仕様とも言える。
* **ステータス:** 軽微。実機での確認を進め、実害がないと判断できればこのままチケットをクローズ（完了）とする。
