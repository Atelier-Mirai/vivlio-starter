## 進行中の不具合（要修正）

### `Common.current_log_level` が ARGV を直接走査している
* **詳細:** ログ出力の閾値だけは `common.rb` が `ARGV` をパターンマッチで独自解釈しており
  （`/^--log=(.+)$/` と `['--log', level]` の 2 形）、正規化済みトークンと二重管理になっている。
* **影響:** 実害は出ていないが、**Samovar が弾いた入力でもログレベルだけは効く**という捻れが残る。
* **判明した実態（2026-07-27 調査）:** `options[:log_level]` は**実質使われていない**（参照は
  `vs new` 専用の 2 箇所のみ）。ログ閾値は 16 箇所すべてが ARGV 走査で決まる。このため
  **`--log` を宣言していない 16 コマンドでも閾値だけは効く**（解析自体は 🔴 になる）。
  また `--log=DEBUG` は 3・`--log DEBUG` は 2 と**記法で大文字の扱いが違い**、`--log=verbose` の
  ような不正値は黙って info に倒れる。
* **対応方針:** `--log` は**宣言のあるコマンド（build / preflight / new）だけが受け付ける**ものとし、
  ログ閾値はその解析結果から 1 回だけ決めて保持する（ARGV 走査は廃止）。これで「宣言していない
  コマンドで打つと 🔴 なのに閾値だけ効く」捻れが構造的に消える。他コマンドの `log_info` は著者
  向けの情報ではないため、⑤ command-feedback-spinner の応答メッセージへ委ねる。
  仕様書 → `docs/specs/cli-argument-parsing-spec.md` Part 2（背景 →
  `docs/specs/cli-option-parsing-report.md` §4.3 ③）。

## 既知の制限（運用回避推奨）

### Kindle でテキスト化できない複雑なインライン数式のサイズが不安定
* **詳細:** 2026-07-19 に **Kindle 限定のインライン数式テキスト化**を実装し、単純な式（`E=mc^2`・`1/299,792,458`・単位・ギリシャ・上下付き・記号など）は SVG 画像でなく HTML テキスト（`<i>`/`<sup>`/`<sub>`＋Unicode）へ変換されるようになった。テキストは定義上フォントサイズに 100% 追従するため、本文・表セル内とも崩れない（原稿 `contents/` の現行インライン数式はすべてこのサブセットに収まりテキスト化される）。
* **残る制限:** テキストで表現できない複雑な式（`\sqrt`・`\sum`・積分・2 段入れ子の上下付き・入れ子分数など）は従来どおり SVG 画像のまま残り、`px` 固定フォールバックが効くため巨大化はしないが、読者のフォント拡大には追従しない。
* **対応方針:** 複雑な式は**ディスプレイ数式（`$$…$$`）として行を占有させる**か、表セル内に置かないことを推奨（ディスプレイ数式は px 固定でも破綻しない）。詳細は `docs/specs/kindle-inline-math-textify-spec.md`。

## 要確認（軽微・検証待ち）

### EPUB の表紙画像が一回り小さく見える
* **詳細:** 表紙画像の埋め込み自体は解消済みだが、実機（あるいはビューア）によって表紙が一回り小さく表示されるケースがある。
* **原因:** EPUBカバーの想定アスペクト比（1600×2560, 比 1:1.6）と、本文のA4サイズ（比 1:1.414）の比率差による見え方の違い。カバー画像側の設計上の仕様とも言える。
* **ステータス:** 軽微。実機での確認を進め、実害がないと判断できればこのままチケットをクローズ（完了）とする。
