### 2.3 Fable の後の設計の判断

### 4.5 Fable の後の設計の判断（問い 2.3 の 1・3）

「仕様に書かれていないので、次のように決める」と実装記録に書いて進める形は、S8〜S10 でも続けてよい。ただし、決めることの種類で扱いを三つに分ける。

| 扱い | 当てはまるもの | 進め方 |
| :--- | :--- | :--- |
| **Opus が決めて記録する** | 内部の名前（モジュール・メソッド・内部のクラス・ファイルの分け方）。仕様の決定を満たす作り方の選択。テストの作り方。著者に見えない定数と閾値。確かめの道具。ログの文面（`terminal-output-notes.md` の決まりに従う）。答えに「Opus が決めて記録する」「判断の軸」と書いてある点 | 実装記録の「仕様に無かったので決めたこと」に書いて進む |
| **決めて進め、ユーザーの了承を後で得る** | 著者から見える名前（`book.yml` のキーと値・コマンドとオプション・記法・保証するクラス・テーマとプリセットの名前）。新しい種類の本の既定値（プリセットの値・テーマの見た目）。lint の規則の向き（誤検出と見逃しのどちらを取るか。基準は「見逃すより検出して著者に委ねる」）。雛形の中身。マニュアルの章立て | 仕様の決まりと既にある名前に合わせて決め、**了承待ちの一覧**に載せて先へ進む。小段階の完了の報告で、一覧をまとめて見せる。名前は公開まで変えられるので、待たない |
| **止めて、ユーザーに選んでもらう** | 本書か既存の本の出力が変わること（基準との差に説明がつかない・説明はつくが見た目が変わる）。2.0 の範囲を変えること（機能や出力先を足す・外す・後へ回す）。外部の道具を新しく必須にすること。4 本の仕様書と相談の答えの決定を覆すこと。リポジトリの外に出ること（push・公開・KDP への登録）。著者のファイルを消す・書き換える振る舞い（`vs upgrade`）の新しい形 | その点に依らない作業を先に進め、依る作業は止める。選択肢・それぞれの結果・勧めを並べて示す |

- 了承待ちの一覧は、記憶に 1 件（`v2-pending-approvals`）で持ち、項目ごとに「決めたこと・決めた場所（仕様書の節）・変えるときに直す範囲」を書く。了承されたら消す。
- **迷ったら、一つ上の扱いにする**（「決めて記録する」か「了承を後で得る」か迷えば後者、「了承を後で得る」か「止める」か迷えば止める）。
- 答えの中の「相談する」「超えたら相談」は、上の表に読み替える。相手は Fable ではなくユーザーで、扱いは「止めて選んでもらう」とする。ただし、この答えで手を決めたもの（4.4 の 3）は相談しない。

### 4.7 基準の版と、確かめの重さ（問い 2.4）

- **版を上げる時点**は 4.2 の表の「基準」の列（r3〜r7）。このほか、見た目を変える変更を入れたとき（§4.1 の決まり）と、道具の版が上がったとき（4.4 の 13）に上げる。
- **残すものと消すもの。** 前の版を消さない決まりは保つが、残すのは出力だけにする。

  | 残す（版ごと） | 消してよい |
  | :--- | :--- |
  | 出力（PDF・EPUB・Kindle 用 EPUB・KPF・表紙）・`book.yml`・`build.log`・Kindle の変換の記録と中間生成物（`preprocessed/`）・画面・`VERSIONS.md`・比べた結果の記録（`check/*.txt`） | 写しのディレクトリ（`runs/`。`.cache/` を含む）・確かめで組んだ出力のうち、結果を記録し終えたもの（`check/` の下の PDF と EPUB）・二度組みの二度目の出力 |

  - 消す時点は、**次の版を作り終え、前の版との差を `VERSIONS.md` に書いた後**とする。それまでは、差の原因を調べるのに写しが要る。
  - r2 の `runs/`（21 GB）と直下の `runs/`・`check/`（r1 の時期）は、r3 を作り終えたら消してよい。直前の小段階の `--no-clean` の写しを 1 つだけ残す（ビルドなしで HTML を比べる道具の材料）。
  - これで、版ごとに増えるのは 2 GB 前後になる見込みである。空きが 100 GB を切ったら、ユーザーに知らせる。
- **全部の比べの回数を減らす決まり。** 変更の範囲で、比べる相手を決める。

  | 変更の範囲 | 小段階の中での比べ | 全部の比べ（B1〜B5・N1・P1 を組む） |
  | :--- | :--- | :--- |
  | 設定・段の表 | `Common::CONFIG` の書き出し・段の並びの書き出し | しない（段階の最後に 1 回） |
  | 前処理・後処理 | 契約 HTML がバイト単位で同じ | 同上 |
  | 出力先の変換（`transforms/`・`epub/`） | ビルドなしで HTML を比べる道具（`tools/prepare_pages_snapshot.rb`。1 分） | その小段階の最後に B1 の EPUB と Kindle |
  | CSS（読む順・字面） | 入口の CSS の差・計算値（`css_computed_diff.rb`）・`InversionCheck` | 触れた出力先だけを組む。PDF の画素は B1 と、触れた設定の Bn |
  | 固定レイアウトだけ・縦書きだけの経路 | その経路の材料の本 | しない（段の並びが前後で同じことだけを見る） |
  | 各答えの小段階の表で太字にした小段階・段階の最後 | — | 行う |

  - N1 と P1 は、それぞれの経路に触れた小段階と、段階の最後にだけ組む。
  - ビルドなしで HTML を比べる道具は、S8 の前に `scripts/` へ移して残す（今は基準のディレクトリの `tools/` にある使い捨て）。S8-4（縦中横の自動と括弧の段落の印）と S10-1（動画の置き換え）で繰り返し使う。
  - `rake test:release` は、段階の最後（S8-7・S9-7・S10-5・S11d）だけにする。

### 4.10 その他（問い 2.7）

1. **移していない 1.x の本を、2.0 の `vs` で組んだときの 🔴。** `config/scaffold.lock` の `scaffold_version` が 2.0 より前（か、lock が無く `stylesheets/` が 1.x の配置）の本で、`vs build`・`vs preflight`・`vs pdf` などの本を読むコマンドを走らせたら、最初に止める。文面は二つの道を示す: 「2.0 へ移すなら `vs upgrade`」「1.x のまま組むなら、`Gemfile` に `gem 'vivlio-starter', '~> 1.0'` と書いて `bundle exec vs build`」。`vs upgrade`・`vs doctor`・`vs --help` は止めない。S11a で作る。これが無いと、gem を上げただけの利用者の本が、エラーも出ずに崩れる。
