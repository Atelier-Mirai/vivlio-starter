# vs pdf:read の PDF の指定と章の名前 仕様書（案）

> **状態**: 叩き台（2026-10-10）。論点 4 件もすべて決定（2026-10-11）。§7 の 5 件（重なりと章のファイル名の決まり・`pdf:read` が壊れた章を作らないこと）は実装済み（2026-10-11）。`pdf:read` 本体（§2〜§5 の引数の読み方・飾り外し・番号の割り当て・`--force`）は未実装。
> 関連: `pdf-read-structure-spec.md`（読み取りの中身。本書は入口のファイル名と出口の章の名前だけを扱う）。

## 0. 結論（先出し）

- **PDF のファイル名と章の名前を切り離す。** PDF のファイル名は「どこから読むか」を指すだけで、自由な名前でよい。
  章の名前（`NN-slug`）は `vs create` と同じ決まりに従う。これまでは PDF のファイル名を章の名前へそのまま流し込んでいたので、
  点・日付・日本語の名前で壊れた章ができていた（§1）。
- **章の名前は、二つ目の引数で指定できる**（`vs pdf:read sources/講座.pdf 21-ai-course`）。
  省いたときは、整ったファイル名（`gitlab.pdf`）からだけ自動で作る。作れなければ止めて、そのまま打てるコマンドを示す（§3）。
- **ファイル名の飾りは外す。** Mac・Windows が複製やダウンロードで付ける「 (1)」「のコピー」「 copy」「 - コピー」は、章の名前に含めない（§3.2）。
- **番号の重なりは必ず止める**（§4.1）。番号を省いたときは、本文の最後の章の次の番号にする（§4.2）。
- **同じ章を読み直すときは止める。** `--force` を付けたときだけ置き換える（§5）。
- **名前だけの指定**（`vs pdf:read 97-sample`）は `sources/97-sample.pdf` だけを探す。
  パス（`vs pdf:read path/to/name.pdf`）は、そのパスだけを探す（§2）。
- 空白を含むファイル名を引用符なしで打ったときは読まない。シェルが止める（括弧）か、空白で分かれて届くので、不正なファイル名として止め、名前を変えるよう案内する（§2.3）。

## 1. 現状（2026-10-10 の洗い出し）

`vs new` で作った一時プロジェクトに、`docs/pdf-samples/` の 30 本を `sources/` へ置いて、4 通りの指定で試した。
問題の出た名前は、実際に変換して `vs build` まで通した。

| 指定の仕方 | 例 | 結果 |
|---|---|---|
| A. パス | `vs pdf:read sources/245.pdf` | 30 本とも読める |
| B. 絶対パス | `vs pdf:read ~/Downloads/245.pdf` | 30 本とも読める |
| C. 名前だけ | `vs pdf:read 245` | 11 本で止まる |
| D. 名前.pdf（`sources/` の中） | `vs pdf:read 245.pdf` | 10 本で止まり、1 本は壊れた章を作る |

見つかった不具合:

| # | 起きること | 例 |
|---|---|---|
| 1 | 点を含む名前で章を作ると、ほかのコマンドが点から後ろを拡張子と読む。`vs build` 全体が `Errno::ENOENT` で止まる | D で `Vol.53_09_482.pdf` → `01-vol.53_09_482.md`。以後は `01-vol` と読まれる |
| 2 | 名前だけの指定で、数字で始まる名前を整えずに使う。空白・日本語・4 桁の番号の章ができる | C で `2026-10-04 at 18-46-16 AI活用講座` → `contents/2026-10-04 at 18-46-16 AI活用講座.md` |
| 3 | 番号の重なりを確かめない。単章ビルドは「catalog.yml に登録されていません」と誤った案内で止まる。全体ビルドは片方の章をエラーにせず外して組む | `97-sample` があるところで `vs pdf:read 97-sample-ocr` |
| 4 | 同じ PDF を読み直すと、別の番号でもう一章作る。付録の番号を指定しても本文の 01 番になり、部のある目次では最後の部の頭に入る。名前が同じ 2 章は章のラベル ID が重なる（🔴） | `vs pdf:read 97-sample` → `01-sample.md`。`@ch-sample` が重なる |
| 5 | 名前だけの指定で、日本語・空白・括弧を含む名前が見つからない。案内に出る「探索パス」は整えた後の実在しない名前 | `GPUの育てかた` → `sources/gpu.pdf` を探す |
| 6 | 名前だけの指定で、大文字の名前を小文字にして探す。大文字と小文字を区別するファイルシステム（Linux・WSL）では見つからない（コードからの判断。実機は未確認） | `Network_no_Ehon` → `sources/network_no_ehon.pdf` |
| 7 | 数字だけの名前で、状況に合わない案内が出る | `245` → 「slug を含む章トークンを指定してください」 |
| 8 | 同じ PDF でも、指定の仕方で章の名前が変わる | `73-4-218` は C・D で `73-4-218`（73 番）、A・B で `01-pdf-73-4-218` |
| 9 | 日本語の名前から意味のある章の名前を作れない | `コンピュータネットワークのエッセンス` → `imported`、`データ解析に強くなるRustレシピ` → `rust` |
| 10 | 複製・ダウンロードの印が章の名前に残る。元の名前の PDF とは別の章になる | `IPSJ-MGN621105 (1).pdf`・`IPSJ-MGN621105 (1)のコピー.pdf` → どちらも `ipsj-mgn621105-1` |

原因は四つにまとまる。

1. **名前の整え方が二通りある。** `PdfReadCommand#normalize_slug` は英数字とハイフンだけを残す。
   名前だけの指定が通る `TokenResolver` は `.` と `_` も残す（1・8）。
2. **番号の重なりを確かめていない。** 確かめているのは、同じファイル名があるかだけ（3）。
3. **読み直したときの方針が無い**（4・10）。
4. **章の名前を著者が決める手段が無い**（2・9）。

## 2. 引数の読み方

```
vs pdf:read <PDF のパス | 章の名前> [<章の名前>] [--force] [--images-from DIR]
```

### 2.1 一つ目の引数：パスか、名前か

| 一つ目の引数 | 読み方 | 探す PDF |
|---|---|---|
| `/` を含むか、`.pdf` で終わる（大文字小文字を問わない） | パス | **そのパスだけ**（今いるディレクトリからの相対、または絶対パス） |
| それ以外 | 章の名前 | **`sources/<打ったとおりの名前>.pdf` だけ** |

- 名前だけの指定は、もともと「`sources/` に章と同じ名前で PDF を置く」使い方のためのもの。章の名前として読めない語（日本語・空白・点を含む語）は受け付けない。
  整えた後の名前で探すこと（`97-sample` → `sources/sample.pdf`、大文字を小文字にして探すこと）もやめる（§1 の 5・6）。
- パスの指定で見つからず、`sources/` に同じ名前の PDF があるときは、読まずに止めて正しいコマンドを示す。

```
🔴 PDF が見つかりません: IPSJ-MGN621105.pdf
   → sources/ にある PDF なら: vs pdf:read sources/IPSJ-MGN621105.pdf
```

- 名前だけの指定で、章の名前として読めないときも、`sources/` に同じ名前の PDF があれば、そのパスで打つコマンドを示す。

```
🔴 「データ解析に強くなるRustレシピ」は章の名前として使えません
   使える名前: 英字で始まる半角の英小文字・数字・ハイフン（-）・アンダースコア（_）（例: awesome、my-reference_2021）
   → sources/ にある PDF を読むなら: vs pdf:read sources/データ解析に強くなるRustレシピ.pdf 62-awesome
```

### 2.2 二つ目の引数：章の名前

- 形は `NN-slug`（番号を決める）か `slug`（番号は §4.2 で決める）。
  - `NN` は 2 桁の数字。
  - `slug` は英小文字・数字・ハイフンで、数字だけにはしない（`01-245` は章の範囲と読まれる）。
- 大文字と `_` は `vs create` と同じく整える（`Hajimete_no_Rust` → `hajimete-no-rust`）。整えて形が変わったときは、どの名前にしたかを知らせる。
- 点・空白・日本語を含む名前は、整えずに止める。案内には、使える名前の例を添える。
- 一つ目が章の名前でも、二つ目で別の名前を付けられる（`vs pdf:read gitlab 21-git` は `sources/gitlab.pdf` を `21-git.md` へ読む）。

### 2.3 シェルとの境目

- 括弧（`(1)`）を含む名前を引用符なしで打つと、zsh も bash も `vs` を起動せずに止める。**これは扱わない。**
  94 章では、使える名前に変えるよう案内する（§6）。名前を途中まで打って Tab で補えば `IPSJ-MGN621105\ \(1\).pdf` と書かれて読めるが、そちらは勧めない。
- 括弧の無い、空白だけの名前（`2026-10-04 at 18-46-16 AI活用講座.pdf`）は、シェルが空白で分けて `vs` に渡す。
  今は `Could not parse token "at"` と言って、コマンド一覧を丸ごと出している。
  **分かれた引数はつなぎ直さず、不正なファイル名として止める**（論点 1）。名前を変えれば、引用符も Tab も要らなくなる。
- 分かれて届いたと見なすのは、引数が 3 つ以上あるとき、または二つ目以降に `.pdf` で終わる引数があるとき。
  案内には、つなげた名前（どのファイルのことか分かるように）と、使える名前の決まりを示す（§3.1 と同じ文言）。

```
🔴 ファイル名に空白があるため、読み込めません: sources/2026-10-04 at 18-46-16 AI活用講座.pdf
   ファイル名を、英字で始まる半角の英小文字・数字・ハイフン（-）・アンダースコア（_）だけの名前に変えてから読んでください
   （例: awesome.pdf、my-reference_2021.pdf）
```

## 3. 章の名前の決め方

### 3.1 決める順

1. 二つ目の引数があれば、それ（§2.2）。
2. 一つ目が章の名前なら、それ。
3. 一つ目がパスなら、ファイル名から作る。
   - 拡張子を除き、飾りを外す（§3.2）。
   - 残りが**整った名前**なら、`vs create` と同じく整えて章の名前にする。
   - 整った名前でなければ、止めてコマンドを示す。

**整った名前**は、英字で始まり、英字・数字・`-`・`_` だけでできた名前。頭に `NN-` があればそれを番号とする（今の `CHAPTER_FILE_NAME`）。
日本語を落とすこと（`imported`・`rust`）や、数字で始まる名前に語を足すこと（`pdf-245`）は、自動ではしない。

手元の 30 本での分かれ方:

| 分類 | 本数 | 例 | 扱い |
|---|---|---|---|
| 整った名前 | 18 | `gitlab`・`heidelberg`・`IPSJ-MGN621105`・`Hajimete_no_Rust` | そのまま読める（`hajimete-no-rust` など） |
| 数字で始まる・点を含む | 3 | `245`・`73-4-218`・`Vol.53_09_482` | 止めて、名前の指定を案内する |
| 日本語・空白を含む | 9 | `GPUの育てかた`・`Exercise D エンジニア脳を鍛える究極の演習集` | 止めて、名前の指定を案内する |

案内には、名前を変える道と、章の名前を添える道の両方を示す。どちらも、**使える名前の決まりを言葉で書き、例を二つ添える**（論点 2）。
例は、いちばん短く分かりやすい `awesome` と、使える字（英小文字・数字・ハイフン・アンダースコア）を全部含む `my-reference_2021` の二つ。
ファイル名の英数字から候補を作ること（`データ解析に強くなるRustレシピ` → `rust`）はしない。中身を表さない名前を、そのまま打たせてしまうため。
大文字は案内には書かないが、受け付けて小文字にする（`IPSJ-MGN621105.pdf` → `ipsj-mgn621105`）。

```
🔴 ファイル名から章の名前を作れません: コンピュータネットワークのエッセンス.pdf
   使える名前: 英字で始まる半角の英小文字・数字・ハイフン（-）・アンダースコア（_）（例: awesome、my-reference_2021）
   → ファイル名を変える: sources/awesome.pdf にしてから vs pdf:read sources/awesome.pdf
   → 章の名前を添える:   vs pdf:read sources/コンピュータネットワークのエッセンス.pdf 62-awesome
   （番号を省くと 62 番になります）
```

章の名前ではアンダースコアをハイフンに整える（`vs create` と同じ）ので、`my-reference_2021.pdf` から作る章は `62-my-reference-2021` になる。

### 3.2 外す飾り

ファイル名の末尾から、次の印を外す（重なっていれば繰り返す。大文字小文字を問わない）。

| 付く場面 | 例 | 外した後 |
|---|---|---|
| ブラウザで同じファイルを二度ダウンロード（Mac・Windows） | `IPSJ-MGN621105 (1).pdf` | `IPSJ-MGN621105` |
| Finder で複製（日本語） | `IPSJ-MGN621105のコピー.pdf`・`IPSJ-MGN621105のコピー 2.pdf` | `IPSJ-MGN621105` |
| Finder で複製（英語） | `IPSJ-MGN621105 copy.pdf`・`IPSJ-MGN621105 copy 2.pdf` | `IPSJ-MGN621105` |
| エクスプローラーで複製（Windows） | `IPSJ-MGN621105 - コピー.pdf`・`IPSJ-MGN621105 - Copy (2).pdf` | `IPSJ-MGN621105` |
| 重なったもの | `IPSJ-MGN621105 (1)のコピー.pdf` | `IPSJ-MGN621105` |

- 外した結果、既にある章と同じ名前になることが多い。そのときは §5 の読み直しとして扱う（別の章は作らない）。
- 日付と時刻（`2026-10-04 at 18-46-16 AI活用講座`）は飾りとして扱わない。空白と日本語があるので、§3.1 のとおり名前の指定を案内する。
- 外すのは章の名前を作るときだけ。PDF を探すときは、ファイル名をそのまま使う。

## 4. 番号

### 4.1 重なりを止める

使われている番号は、`contents/*.md` の頭の 2 桁と、`catalog.yml` に載っている章の番号（原稿が無いものも含む）から集める。

| 場合 | 扱い |
|---|---|
| 同じ章（番号も名前も同じ）がある | §5 の読み直し |
| 番号が同じで、名前が違う | 止める。どの章が使っているかと、同じ区分（本文・付録など）の空いている番号を示す |
| 名前が同じで、番号が違う | 止める。章のラベル ID（`@ch-<slug>`）が重なるため。その章を読み直すコマンドと、別の名前の例を示す |

```
🔴 97 番は 97-sample が使っています
   → 空いている付録の番号: 98
   → vs pdf:read sources/97-sample-ocr.pdf 98-sample-ocr
```

### 4.2 番号を省いたとき

- **本文（01〜89）でいま使われている一番大きい番号の次**にする。雛形なら `61-developer` の次の 62。目次では本文の末尾に入る。
- 89 まで使われていれば、01〜89 の空いている一番小さい番号にする。空きが無ければ止める。
- 付録やまえがきにしたいときは、著者が番号を指定する。
- 名前が既にある章と同じなら、番号は割り当てない。その章の読み直しとして扱う（§5）。

## 5. 読み直し

- **読む先の章が既にあるときは止める。** 「既にある」とは、§4.1 の「同じ章」のときと、番号を省いて名前が既にある章と同じときを指す。
- `--force` を付けたときだけ、その章の原稿を置き換える。
  - 前回の画像（`images/<章>/`）は消してから書き出す。前回の画像が残って混ざらないようにするため。
  - `catalog.yml` は既に載っているので触らない。

```
🔴 62-gitlab は既にあります（前回 sources/gitlab.pdf から読みました）
   → 読み直して置き換えるなら: vs pdf:read sources/gitlab.pdf --force
   → 別の章として読むなら: vs pdf:read sources/gitlab.pdf 63-gitlab-2
```

- **どの PDF から読んだかを原稿の頭に残す**。

  ```markdown
  <!-- pdf:read: sources/gitlab.pdf（sha256: 3f2a…） -->
  ```

  - 前処理が HTML コメントを除くので、組版には出ない。`pdf:read` は既に `<!-- pdf:read: … -->` の形で注記を書いている。
  - 番号も名前も違う章として読もうとしたとき、中身が同じ PDF（sha256 が一致）から読んだ章があれば、知らせる（止めない）。
    著者が名前を指定しているなら、意図して読んでいるはずなので止めない。

  ```
  🟡 この PDF は 62-gitlab として読み込み済みです（中身が同じです）
  ```

## 6. 94 章に書くこと

- PDF はパスで指定する。`sources/` に置いた PDF は、章と同じ名前なら名前だけで指定できる。
- 章の名前は二つ目の引数で付けられる。省くと、整ったファイル名から作り、本文の末尾の番号にする。
- ファイル名に空白や括弧があるときは、使える名前（§3.1）に変えてから読む。Tab で補えば読めるが、案内は名前を変えるほうに寄せる。
- 読み直すときは `--force`。

## 7. あわせて直したもの・対象外

あわせて直したもの（2026-10-11 実装）:

- **`vs create`・`vs rename` も番号とスラッグの重なりを確かめていなかった**（`97-sample` があるところで `vs create 97-foo`・
  `vs create 01-sample` が通った。`vs rename` は変更先とまったく同じ名前の章しか見ていなかった）。
  別の章（`contents/` の原稿か `catalog.yml` の章）が使っている番号かスラッグなら止め、重ならない番号（同じ区分の空き番号）や
  スラッグ（`-2` を足したもの）で打ち直すコマンドを示す。一度に作る章どうしの重なりも止める（論点 3）。
  `vs rename` は新しく重なりを作るときだけ止める（変えない部分は見ない）。既にある重なりを解く `vs rename 97-sample 97-sample-2` を止めないため。
  確かめ方は `ChapterNames`（`conflicts`・`suggestion`）にまとめた。§4.1 の実装でも使う。
- **目次の読み込みが、番号の重なった章を黙って 1 章に絞っていた**（`TokenResolver#load_catalog_entries` の `uniq(&:number)`）。
  `vs preflight` が「未登録の原稿」と誤って案内し、全体ビルドが片方を外して組んでいた。
  同じ章を二度書いた行だけをまとめる（`uniq(&:basename)`）ようにし、`DuplicateNumberCheck` を警告からエラーにした（論点 4）。
  数えるのは `contents/` の原稿と `catalog.yml` の章。2 つめ以降を同じ区分の空き番号へ振り直す `vs rename` のコマンドを添える。
  番号だけの指定（`vs build 97`）は、重なった章があれば解決しない。
- **スラッグが同じで番号の違う章を止めていなかった**（`01-sample` と `97-sample`）。番号で指せば組めるが、`vs build sample` は
  片方だけを黙って組み、章のラベル ID（`@ch-sample`）が重なっていた。著者もどちらを書けばよいか迷う。
  新しい検査 `DuplicateSlugCheck` がビルドの前に止め、2 つめ以降のスラッグを変える `vs rename` のコマンドを添える。
  大文字と小文字の違いだけのスラッグも同じとみなす。スラッグだけの指定（`vs build sample`）は、同じスラッグの章が 2 つあれば解決しない。
- **章のファイル名の決まりを確かめていなかった**。決まりは `vs create` の作る形（`ChapterNames::VALID_BASENAME`。2 桁の番号と、
  英小文字・数字・ハイフンのスラッグで、数字だけにはしない）。点を含む名前は章の解決が点から後ろを拡張子として削り
  （`01-vol.53_09_482` → `01-vol`）、全体ビルドが `Errno::ENOENT` で異常終了していた。`_` で番号を区切った名前（`97_sample-x`）は
  存在しない `97-sample-x.md` を指し、番号の重なりの検査もすり抜けていた。手の `mv`・`cp`（Finder の複製「97-sample のコピー.md」、
  版を付けた控え「97-sample.v2.md」）でも起きる。
  - ビルドの前の検査 `ChapterFileNameCheck` が止める（著者が選んだ厳しさ: 大文字・`_`・日本語もエラー。2026-10-11）。
    番号で始まる原稿と catalog.yml の章が対象で、番号で始まらない原稿（メモ）は見ない。
  - 直す名前は、使えない字をハイフンにし、重なれば空き番号・`-2` を当てる（`ChapterNames.suggestion`）。
    コマンドは catalog.yml に載っていれば `vs rename`、載っていない原稿は `mv`（`ChapterNames.rename_command`）。
    空白などシェルで意味を持つ ASCII の記号だけをエスケープし、引用符を求めない（`Shellwords.escape` は日本語にも `` を付ける）。
    番号とスラッグの重なりの検査も同じ直し方を示す（残すのは決まりの形の名前）。
  - 章の解決が除く拡張子を、章のファイルのもの（`.md`・`.markdown`・`.html`・`.pdf`）だけにした。
  - `vs create`・`vs rename` は大文字と `_` を整えて作り（§2.2 と同じ）、点・空白・日本語を含む名前は止める。
- **`vs pdf:read` が壊れた章を作っていた**（§1 の 1〜4 のうち、§2〜§5 を待たずに直せるもの）。
  - 章の名前を決まりの形に整え（大文字と `_`）、整えられなければ止める。番号かスラッグがほかの章と重なれば止める（§4.1）。
    今の `pdf:read` は章の名前を PDF のファイル名から決めるので、PDF の名前を変えて読み直すコマンドを示す。
  - 同じ章が既にあれば、別の番号でもう一章作らずに止め、`vs delete` を案内する（§5 の置き換え `--force` は未実装）。
  - `sources/` の PDF を名前で指定したとき、打ったとおりの名前を先に探す（§2.1 の一部。§1 の 5）。
  - エラーの 2 行目以降（探したパス・打ち直すコマンド）を字下げした。

対象外:

- **OCR の出力が、行頭の `:::` でビルド前の検査を止める**（`97-sample-ocr` で、記法の一覧表を読んだ行）。ファイル名とは別の件。

## 8. 論点

| # | 論点 | 決定（2026-10-11） |
|---|---|---|
| 1 | 空白で分かれた引数をつなぎ直して読むか | つなぎ直さない。不正なファイル名として止め、使える名前に変えるよう案内する（§2.3）。著者に引用符を求めない |
| 2 | 名前が作れないときの案内に出す名前の例 | 決まりを言葉で書き、`awesome` と `my-reference_2021` の二つを例に添える。ファイル名の英数字から候補は作らない（§3.1） |
| 3 | 番号の重なりの確かめを `vs create` にも当てるか | 当てる。本書の §7 として実装済み |
| 4 | 目次の読み込みで番号が重なったときの扱い | `uniq(&:number)` をやめ、`DuplicateNumberCheck` をエラーにしてビルドを止める。本書の §7 として実装済み |

## 9. テスト

`test/vivlio_starter/cli/pdf_read_command_test.rb` に足す。PDF は Prawn で作る。

- パスで見つからず `sources/` にあるとき、正しいコマンドを示して止まる。
