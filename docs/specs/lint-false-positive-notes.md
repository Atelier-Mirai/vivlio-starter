# 校正辞書の誤検出の知見メモ

> 対象: `vs lint` が出す誤った指摘と、その真偽の確かめ方。`--fix` が表示と食い違うとき（§7）
> 位置づけ: 実測で確定した事実を残す恒久メモ。仕様書ではないので archives へは移さない

## 1. 誤検出のほとんどは「複合語の継ぎ目」で起きる

### 症状

書いた覚えのない語について指摘が出る。

```
1件  [spellcheck-tech-word] レビューア => レビュア
     行: 124
```

該当行は「macOS では、ビルド完了後に自動的に**プレビューアプリ**で PDF を開きます」。
校閲者（レビュア）の話などどこにもない。

### 原因

prh も `spellcheck-tech-word` も、**語の切れ目を見ずに部分文字列で照合する**。
日本語は語を空白で区切らないので、複合語の継ぎ目に見出し語と同じ並びが偶然現れる。

```
プレビューアプリ
   └─────┘
   プレビュー ＋ アプリ の継ぎ目に「レビューア」が現れる
```

実測した例（いずれも上流 `technical-word-rules` 由来）。

| 書いた語 | 出る指摘 | 継ぎ目 |
|---|---|---|
| プレビューアプリ | `レビューア => レビュア` | プレビュー＋アプリ |
| レビューワークフロー | `レビューワー => レビュア` | レビュー＋ワークフロー |
| 対処方法 | `対処方 => 対処法` | 対処＋方法 |
| マスターファイル | `マスターフ => マスタフ` | `マスター([^.])` が続く 1 字を巻き込む |
| 言語芸術 | `語芸 => 語彙` | 言語＋芸術 |

### 規則

**語を 1 つずつ除外リストへ足してはいけない。** 追いつかない。
実測では 5 語を登録してあるのに同型の指摘が 4 件残っていた（`プレビューアプリ` 2 件・
`マスターファイル`・`マスターは`）。`マスター([^.])` のように「続く任意の 1 字」を叩く
項目もあり、語を数え上げてもきりがない。**継ぎ目の形**を正規表現で書く。

## 2. どの層で直すかを、出どころで決める

誤検出を見たら、まず**出どころ**を特定する。直し方が層ごとに違う。

| 出どころ | 直し方 | 置き場 |
|---|---|---|
| **自前の辞書が誤っている** | 辞書のパターンを絞る（先読み等）＋`specs` で固定 | `config/textlint_dictionaries/` |
| **上流が誤っている**（項目単位で切れない） | 打ち消す | `LintRunner::BUILTIN_ALLOWLIST`（`lint.rb`） |
| **本の方針と違うだけ**（誤りではない） | そのまま通す | `config/textlint_allowlist.yml`（著者のもの） |

判別の勘どころ。

- **`spellcheck-tech-word` は `context.options` を一切読まない。** 項目単位で無効化する術が
  無いので、打ち消すほかない（雛形の `skip:` は効かないので外した）。
- **prh 辞書は当方で編集できる。** 誤っている項目は allowlist で覆わず辞書から直す。
  `specs` を必ず添える——prh は辞書を読むたびに自己検査し、期待を壊すとその場で lint が止まる。
- **`BUILTIN_ALLOWLIST` に本の方針を書かない。** `マスター => マスタ` のような長音の扱いは
  逆の方針を採る本が実在する。ツールが決めてよい話ではない。
- **黙らせて終わりにしない。** 上流と逆の立場を採るなら、逆向きの規則を自前の辞書に置いて
  **正しい綴りを主張する**。`チェーン => チェイン` は打ち消したうえで
  `チェイン => チェーン` を `prh_web_technology.yml` に置いた。単に黙らせると、
  誤って `チェイン` と書いたときに何も言われなくなる。

## 3. 真偽の確かめ方——安上がりな順に

### ① 除外リストを空にして本書全体に当てる（推奨）

**誤警報ゼロの地の真実。** 実際に効いたのはこの方法である。

```bash
printf '%s\n' '- "__絶対にマッチしない語__"' > config/_probe_allow.yml
ruby -e 'src = File.read("config/.textlintrc.yml")
         File.write("config/_probe.textlintrc.yml",
                    src.sub("./textlint_allowlist.yml", "./_probe_allow.yml"))'
npx textlint --config config/_probe.textlintrc.yml --format json contents/*.md
rm -f config/_probe_allow.yml config/_probe.textlintrc.yml
```

**probe 設定は `config/` の中に置く。** 外に置くと textlint がルールを解決できず
"No rules found" になる。`BUILTIN_ALLOWLIST` は実行時設定に注がれるので、この経路では
そもそも効いていない（つまり著者側とツール側の両方を外した状態が見られる）。

なお**この出力には、実行時に無効化しているルールの指摘も混ざる**
（`SUPERSEDED_TEXTLINT_RULES`・`trim_long_vowel`・`allow_space_*`）。
`ja-spacing` や `ja-no-mixed-period` が大量に出ても、それは除外リストの話ではない。

### ② 一般語彙と総当たりで突き合わせる（精度は低い）

本書に出てこない語まで見たいとき——雛形は他の著者にも渡るので、意味はある。
`lib/vivlio_starter/cli/lint/data/mazegaki-source.tsv`（SudachiDict 由来）に
本書から MeCab で抜いた複合名詞を足すと 6 万語ほどの語彙になる。辞書の見出し語が
その「内側」に現れるかを総当たりで見る。

**期待値を誤らないこと。実測の精度は 3% だった。**

| | 候補 | 実際に発火 | 新規の収穫 |
|---|---|---|---|
| 上流辞書 | 17 件 | 8 件 | **2 件** |
| 自前辞書 | 49 件 | **0 件** | 0 件 |

自前辞書の 49 件が全滅したのは、**見出し語から先読みを落として抽出したため**である
（`/わか(る|り|ら|っ)/` を `わか` として扱えば「わかめ」「わかば」に当たって見える）。
自前の辞書はいずれも適切な先読みを持っており、実物では 1 件も発火しない
（`テーマスタイル`・`カスタマイズ`・`レンダリング結果` で確認）。

**候補は必ず実物の textlint で当て直す。** ①の probe 設定に候補語を並べた
Markdown を食わせればよい。

## 4. 実測で片付けた項目（再調査しないための記録）

2026-09-18 の総当たり監査で発火を確認した上流 8 件の内訳。

| 項目 | 処置 |
|---|---|
| `対処方 => 対処法` | `BUILTIN_ALLOWLIST` に `/対処方法/` |
| `レビューア\|レビューワー => レビュア` | 同 `/プレビューア/` `/レビューワーク/` |
| `%([^0-9]) => ％$1` | 同 `/[0-9]+%/` |
| `(?:…\|最強\|常識的\|知らない\|酷い) => 使うべきではない言葉…` | 同 `/知らない\|知らなさそう\|常識的\|酷い\|最強\|最も優れた/`（§5） |
| `チェーン => チェイン` | 同 `/チェーン/` ＋ 逆向きの規則を `prh_web_technology.yml` へ |
| `リーダ([^ー]) => リーダー$1` | 同 `/リーダビリティ/`（可読性の用語の頭に当たる。読み手の「リーダー」とは別語） |
| `パソコン => PC` | `BUILTIN_ALLOWLIST` に `/パソコン/`。**綴りの誤りでも表記ゆれでもなく語の言い換え**で、指す範囲も語感も違う（「パソコン教室」＝街の学習教室と「PC 教室」＝学校の特別教室は別物、「パソコン・スマホ」を「PC・スマホ」にすると読者への語り口が変わる）。どちらを使うかは本の読者層で決まるので上流が一律に寄せてよい話ではない。チェーンと違い**正しい綴りが一方に決まらない**ため、逆向きの規則は置かない |
| `マスター([^.]) => マスタ$1` | 著者の除外リストに `/マスター/`（長音の方針） |
| 末尾に長音を足す 5 項目（`ディレクタ`・`ベンダ`・`メンバ`・`メーカ`・`リーダ`） | `TRIM_LONG_VOWEL_ALLOWLIST`（`trim_long_vowel` が有効なときだけ効かせる） |
| `既定 => デフォルト` | 著者の除外リストに `既定`（和語で通す方針） |
| `」、「 => 」「` | **見送り**（規則は残す）。列挙（`「整数」、「文字列」` → `「整数」「文字列」`）では正しい直し方を示す。本書の 2 件はどちらも**組を区切る読点**（`（「ユーザ」と「ユーザー」）、（「javascript」と「JavaScript」）`・`（A は B）、（C は D）`）で、落とすと係り受けが壊れるため `vs-lint-disable-next-line` で処理した（31 章 20 行・90 章 3 行）。規則の出どころは WEB+DB PRESS 編集部の用語統一ファイルで、国語の規程に同趣旨の条文は見当たらない |
| `薔薇 => バラ` | **見送り**。`薔薇色 → バラ色`・`野薔薇 → 野バラ` は許容範囲 |

自前の辞書で直したもの。

| 項目 | 処置 |
|---|---|
| `アボガド => アボカド` | `/アボガド(?!ロ)/`（アボガドロ定数に当たっていた） |
| `半角かっこ => 全角かっこ` | 先読みで**中身が半角文字だけ**のかっこを外した（`(1)` `(Matz)` `(0, 0)` `(token => count)` `(Kindle Previewer 3)`）。「英単語を並べた補足だけは全角に」という対の規則も試したが**やめた**——本書の半角は`pdfinfo (poppler)`・`gs (Ghostscript)` のように**コマンド名へ添える併記**で、地の文の補足（全角 174 箇所）とは字面で区別できない。空白の有無で分けると、表の中で揃っている `kindlepreviewer (Kindle Previewer 3)` だけを叩く誤検出になった |
| `プレフィックス => プリフィックス` | **向きを逆にした**（`prh_cho_on.yml`）。IT 分野の慣用は「プレフィックス」で、IT 用語辞典の見出し語・IPv6 の「プレフィックス長」・CSS の「ベンダープレフィックス」がこちら。あわせて英単語を拾う `/prefix/i` を外した——この辞書で唯一の「英単語 => カタカナ」で、`vendor prefix` のように欧文のまま書いた語まで書き換えていた |
| `閏年 => うるう年` | **外した**。交ぜ書きの独自ルールが逆向き（`うるう年 => 閏年`）を提案するので、どちらで書いても片方が叩き、`--fix` のたびに入れ替わっていた。js-primer にだけある項目 |

**辞書どうしが逆を向いていないかは機械的に確かめられる。** 交ぜ書き辞書（`MazegakiDictionary::ALL` と `data/mazegaki.tsv`、計 2,063 語）の漢字側に prh の各項目を当て、置換の結果が交ぜ書き側に戻るものを探す。2026-09-20 に 857 項目と突き合わせ、逆向きは `閏年` の 1 組だけだった。同梱辞書に項目を足したら、同じ突き合わせをかけ直す。

## 5. 「使うべきではない言葉」の項目は `--fix` が文を破壊する

### 症状

```
手酷い失敗でした。
  → 手使うべきではない言葉なので修正してください失敗でした。
```

### 原因

上流 `technical-word-rules` の項目がこうなっている。

```json
{"pattern":"(?:使うべきではない言葉なので修正してください|最強|常識的|最も優れた|知らない|知らなさそう|酷い)",
 "expected":"使うべきではない言葉なので修正してください"}
```

**`expected` が置換語ではなくメッセージ文である。** ところが `spellcheck-tech-word` は
`expected` をそのまま `fixer.replaceTextRange` に渡すので、`--fix` がメッセージを文中へ
差し込む。

加えて `知らない`・`常識的` はごく普通の日本語で、文脈を見ないため
「Rust は知らない」と「知らない記法」を区別できない。本書にも生きた指摘が 1 件あった
（`95-import.md:111`「知らない記法を黙って通しません」）。

### 規則

六語まとめて打ち消してある。**誇大表現を見たいなら、`--fix` を持たない独自ルールとして
実装する**——`kansuji-counter-suffix` が「判定を外した箇所へ黙って書き込むことになるから
`--fix` はしない」という前例である（`ProseChecker::FIXABLE_RULES`）。

## 6. 校正辞書に「校正以外のもの」を置かない

`textlint_rewrite.yml` に `vs pdf:read` の OCR 誤認識補正（`Al => AI` など）が同居していた。
校正辞書は**全原稿**に当たるので、自分で書いた文章まで巻き添えになる。実測では
アルミニウムの元素記号 `Al` と人名 `Al Gore` が `AI` に、「言語芸術」が「言語彙術」に
書き換えられていた。しかも prh 由来の指摘は自動修正を持つので `vs lint --fix` が黙って壊す。

OCR 補正は `config/ocr_corrections.yml` が受け持つ（`vivlio-starter-pdf` が読む）。
**走査の誤りと表記の方針は別物である。**

同じ理由で、`textlint_rewrite.yml` に置くのは「この本ではこう書く」と決めた表記だけにする。
製品名は `prh_corporation.yml`、技術用語は `prh_web_technology.yml`、誤字は `prh_idiom.yml`
——同梱辞書（`config/textlint_dictionaries/`）は `vs upgrade` が追随させるので、
ツール側で保守するものはそちらへ置く。

## 7. 表示で黙らせたものは、`--fix` でも黙らせる

### 症状

`vs lint` は無指摘なのに、`vs lint --fix` が原稿を書き換える。直後の `vs lint` で
指摘が復活したり、目印（`VSMATH0000`）が原稿に残ったり、記法（ふりがな・ラベル）が壊れたりする。

### 原因

`vs lint` の解析パスと修正パスは**経路が違う**。

```
vs lint        原稿 → ①記法の中和 → textlint → ②出力の段で除外 → 表示
                                      ↑ 実行時設定・フィルタ（両方に効く）
vs lint --fix  原稿 → 独自校正の置換 → ③退避 → textlint --fix → 復元 → 書き戻し
```

①（`NotationGuard.strip_notation`）と②（`TextlintFormatter`）は**表示にしか効かない**。
textlint はフィルタで消えた指摘の修正は当てないが、①②は textlint の外にあるので、修正は
そのまま当たる。①は③（`mask_for_fix`）で、②は実行時設定（`generate_runtime_config`）で
受けていないと食い違う。

2026-09 に同じ型が 6 回見つかった。

| 抑止していたもの | 表示だけで効いていた仕掛け | 直し方 |
|---|---|---|
| `lint.trim_long_vowel`（prh 辞書） | 出力段で「X => Xー」を落とす | 同梱辞書の写しから項目を落として読ませる |
| `lint.trim_long_vowel`（上流辞書） | 同上（上流の辞書には手が届かない） | 実行時の除外へ注ぐ（`TRIM_LONG_VOWEL_ALLOWLIST`） |
| `<!-- vs-lint-disable-next-line -->` | 出力段で行ごと落とす（フィルタは `-next-line` 未実装） | 修正パスの間だけ行を目印へ退避（`mask_hushed_lines!`） |
| `lint.disabled_rules` | 出力段でルールを落とす | 実行時 textlintrc でルールを `false` に（`apply_disabled_rules!`） |
| 出力例の囲み（`:::{.output}` など） | `strip_notation` が中和 | `mask_for_fix` で行ごと目印へ退避 |
| 退避の復元順 | —（修正パスだけの不具合） | 退避した逆順に剥がす（`restore_masked`） |

**見出し語の数え落としに注意。** 上流の「末尾に長音を足す」項目を数えるとき、はじめは「見出し語に `ー` を含まないもの」で絞って 3 件としたが、`リーダ` `メーカ` は**語幹自体が `ー` を含む**ため漏れていた（実測で 5 件と判明）。見出し語の綴り（先読みと捕獲を外したもの）に `ー` を足すと期待の綴りになるか、で数える。

表示と修正は一致していても、**`--fix` が記法を壊す**ものも同じ回に見つかった。数式・値つき
属性を守ったのと同じ理由で、修正パスで退避している。

| 記法 | 壊れ方（実測） | 守り方 |
|---|---|---|
| ふりがな `{親\|読み}` | `{沢山\|たくさん}` → `{たくさん\|たくさん}` | 修正パスで記法ごと退避（表示の指摘は残る） |
| 相互参照 `@label` | `@ruby-sample` → `@Ruby-sample` | 解析で `@label` へ置き換え、修正で退避（定義はビルドの `ReferenceReplacer` と共有） |
| 独自校正の出力例 | `:::{.output}` の中の「だ円」→「楕円」 | 交ぜ書き・康煕部首を `machine_data_lines` の外に限る |

囲みの目印行（G2）・クラス属性（G4）・番号付きリストの記号（G6）は、表示だけで中和して
いるが、実測で `--fix` の害は無かった（G6 の記号は英数字だけで、半角かっこの規則が外す）。

### 規則

- **新しく何かを黙らせるときは、表示と修正の両方に効くかを最初に問う。** 効かせる手段は
  二つしかない——**設定で切る**（ルール・辞書・フィルタ）か、**可逆な退避で守る**
  （`mask_for_fix` に足し、`restore_masked` で戻す）。出力段で落とすだけなら、それは
  `--fix` に対して無防備である
- **出力の段で除外を足さない。** `TextlintFormatter` で落としてよいのは次行抑止の行だけで、
  これは修正パスも同じ行を退避している。ルールや語で落とす仕掛けは 2026-09 に撤去した——
  設定の段で効いているものを表示の段でも落とすと、**設定の取りこぼしを隠す**働きしかしない
- **「表示されたのに直らない」は許す。「直ったのに表示されない」は許さない。** 前者は著者が
  気づいて手で直せる（ふりがなの親文字）。後者は著者の知らないところで原稿が変わる
- **退避は重なる。** 数式の目印を入れた行を、さらに行ごと退避することがある。
  `restore_masked` は spans を**退避した逆順**に剥がすので、退避を足すときは
  spans へ**退避した順に**積むこと
- **解析パスで中和するときは、消さずに形の同じ語へ置き換える。** 消すと周りの空白の形が
  変わり、原稿に無い指摘が生まれる（実測: ラベルを消して `（@auto / @omakase）` が `（ /  ）` に
  なり、「全角かっこの前の空白を消せ」に当たった。表示は `␣） => ）`）
- **中和（`strip_notation`）は非可逆なので修正パスには使えない。** 修正パスで守りたい
  ものは、必ず目印へ逃がして戻す

### 再発を捕まえる仕掛け

`test/vivlio_starter/cli/lint/fix_invariant_test.rb` が、記法と抑止を網羅した見本原稿
（`fixtures/lint_fix_invariant/before.md`）に、**出荷している雛形の設定**で実物の textlint を
当て、結果を期待値（`after.md`）と突き合わせる。単体テストは textlint を差し替えているので、
この型の食い違いはここでしか捕まらない。textlint が無い環境では skip する。

**守りを足したら、見本原稿に 1 行足して期待値を作り直す。** 期待値は手で書かず、実際に
走らせた結果を目で確かめてから保存する（変わってよい行だけが変わっているか）。

**テストが本当に落ちるかは、守りを 1 つずつ外した版で確かめる**（2026-09 に 7 つとも確認済み）。
その際、`bin/vs` は起動時に自分自身を再実行するので、**コマンドラインの `-I` は捨てられ、
`bin/` の隣の `lib/` が読まれる**。変異を当てた `lib/` を `-I` で渡しても一度も読まれない
（全変異が「検出できない」に見える）。`bin/` と `lib/` を組にして複製し、その `bin/vs` を
走らせること。変異は構文を壊さない形で入れる——行を消して構文が壊れると `vs` ごと落ち、
間違った理由で「検出した」に見える。

### 確かめ方（手で）

捨て章（`contents/98-tmpprobe.md` など）に書いて、表示と修正を突き合わせる。
**`--fix` で変わった行が、表示された指摘に含まれていれば正しい。**
表示に出ていない行が変わったら、この型の穴である。

```bash
cp contents/24-cross-reference.md contents/98-tmpprobe.md
cp contents/98-tmpprobe.md /tmp/before.md
vs lint 98                          # 表示された指摘を控える
vs lint 98 --fix >/dev/null
diff /tmp/before.md contents/98-tmpprobe.md   # 変わった行 ⊆ 表示された指摘 か
rm contents/98-tmpprobe.md
```

**`lib/` を直したら `rake reinstall` してから確かめる。** `vs` はインストール済みの gem を
読むので、`bin/vs` で緑でも著者の `vs` は古いままである。
