# 単章ビルドと全章ビルドの結果を一致させる（build mode parity）

> 作成日: 2026-08-11
> ステータス: **実装待ち**
> 対象: `vs build <章>`（single mode）と `vs build`（full mode）で章本文の組版結果が食い違う問題。ステップ表がモードごとに手で維持されているため、差分が構造的に増え続ける
> 関連: `lib/vivlio_starter/cli/build/pipeline.rb`（ステップ表）, `lib/vivlio_starter/cli/pre_process/markdown_preprocessor.rb`, `lib/vivlio_starter/cli/pre_process/cross_reference_processor.rb`, `lib/vivlio_starter/cli/post_process/heading_processor.rb`
> 先行: `build-target-parallelization-spec.md`（**相**（`:shared`/`:pdf`/`:epub`/`:join`）を導入した仕様。本仕様書はそれと**直交する第 2 の軸**を足す）
> 従属: `index-markup-plain-fallback-spec.md`（本仕様書を先に入れると、あちらの §4.2 は不要になる。§8 参照）

## 0. なぜこの仕様書があるか

単章ビルドは**プレビューとして使われる**。ところが全章ビルドと結果が一致しないため、「単章では ○○ だったが全章では ×× だった」という報告が繰り返し起きる。そのたびに個別の補償を足してきた。

```
markdown_preprocessor.rb:537   「単章ビルドでは Step 4 がスキップされるため、ここで記法を除去して…」
cross_reference_processor.rb:269「単章/選択ビルドの override があればそれを、無ければ catalog.yml から…」
heading_processor.rb:37, 477, 493「単章/選択ビルドは chapter_tokens_override で与えられ…」
```

**実測 5 箇所・3 ファイル。** いずれも「全章にしかない情報を、単章のために各所で埋め合わせる」形をしている。個別対応を続ける限り、新しいステップを足すたびに同じ穴が開く。

原因は実装の不注意ではなく**構造**にある。ステップ表がモードごとに 2 つあり、手で維持されているため、片方への追加はもう片方に自動では届かない。

## 1. 現状（実測）

| | ステップ数 |
| --- | --- |
| 全章モード（`register_full_mode_steps`） | 22 |
| 単章モード（`register_single_mode_steps`） | 7 |

前処理そのものは既に共通で、**両モードとも `PreProcessCommands.execute_pre_process` を呼ぶ**。分岐しているのはその外側である。

全章にあって単章に無い 15 ステップのうち、**章本文を書き換えるのは 2 つだけ**だった。

| ステップ | 性質 |
| --- | --- |
| `index scan and build` | **意図しない差分**。索引・用語集タグが単章に出ない |
| `techbook post-process` | **意図的な差分**。単章では Type 3 対策をしない（著者判断・2026-08-11） |

残る 13 は目次・部扉・前付奥付・PDF 結合・EPUB など、全書籍を単位とする成果物である。

**つまり実害のある差分は 1 つしかない。** それでも本仕様書を書くのは、差分が 1 つで済んでいるのは偶然であり、構造がそのままなら増え続けるからである。

## 2. 設計：第 2 の軸「単位（unit）」

### 2.1 既存の軸との違い

パイプラインは既に**相**を持つ。

```ruby
PHASE_ORDER = %i[shared pdf epub join]   # どの出力枝が必要とするか
```

これは PDF 枝と EPUB/Kindle 枝を並列に走らせるための区分で、**出力形式**の話である。

本仕様書が足すのは**入力単位**の軸で、両者は直交する。

|  | `:shared` | `:pdf` | `:epub` | `:join` |
| --- | --- | --- | --- | --- |
| **`unit: :chapter`** | 前処理・記法変換・索引タグ付け | — | — | — |
| **`unit: :whole_book`** | 索引ページ・目次・部扉 | PDF 結合・アウトライン | EPUB 生成 | 掃除 |

`:whole_book` は「書籍という**成果物**」ではなく「全章そろわないと答えが出ない**入力単位**」を意味する。名前を `:book` にすると出力形式と読み違えられるため `:whole_book` とする（実際に読み違いが起きた）。

### 2.2 既定は一致、逸脱は宣言制

```ruby
['preprocess sections',   …, unit: :chapter]
['index scan and build',  …, unit: :whole_book]
['techbook post-process', …, unit: :chapter, single: :skip]  # 理由をコメントに書く
```

- 単章モードは「`unit: :chapter` のステップを全部走らせる」と定義する。**モードごとの一覧を手で持たない。**
- 章単位でありながら単章では走らせたくないものは `single: :skip` を**明示**し、**理由をコメントに残す**（`notation-implementation-guide.md` §0-5「順序の理由をコメントに書く」と同じ流儀）。

**既定の向きが反転する点が要である。** いまは「単章に足し忘れる」が既定だが、この設計では「単章にも走る」が既定になり、外すときだけ手を動かす。

## 3. 契約（何を約束し、何を約束しないか）

無条件に「同じ結果」と言うと破綻する。原理的に一致しないものがあるためである。

> **章の本文に効く処理は両モードで必ず走る。差分は「全書籍を単位とする情報」だけ。**

| 一致させる | 一致させない（理由） |
| --- | --- |
| 記法変換・画像パス解決・コード取り込み・脚注 | 索引の**ページ番号**（全書籍を組まないと決まらない） |
| 索引・用語集タグの**有無** | **主要参照**の判定（他章の出現を知る必要がある） |
| † 用語集リンクの位置（§4） | 目次・部扉・前付奥付・奥付 |
| 見た目・行組み | 章番号の**通し番号**（既に override で補償済み） |

### 3.1 既知の逸脱（`single: :skip`）

| ステップ | 理由 | 単章での見え方 |
| --- | --- | --- |
| `techbook post-process` | Type 3 対策は入稿用の関心事で、プレビューには要らない（著者判断） | 絵文字が画像化されず、囲み数字・波ダッシュも素のまま |

逸脱を増やすときは、この表に 1 行足す。**表に無い逸脱は認めない。**

## 4. 索引ステップの分割

`index scan and build` は 2 つの性質を持つため、単位で割る。

```
index scan and build
├─ 章ごとのタグ付け（[404] → <dfn>・† の付与）   unit: :chapter
└─ 索引ページ生成・ページ番号・主要参照の解決     unit: :whole_book
```

前半が `:chapter` になることで、単章ビルドでも索引タグが付く。

### 4.1 † 用語集リンクは「章ごとの初出」に限る

現状は**全出現に †** が付く（実測: `01-computer-journey.md` の `HTML` 5 回すべて）。過剰であり、かつ単章との一致を妨げる。

| 「初出」の定義 | 全章 | 単章 | 判定 |
| --- | --- | --- | --- |
| 書籍全体の初出 | 第 1 章にだけ † | その章が第 1 章でなくても † が付く | **不一致** |
| **章ごとの初出** | 各章の初出に † | 同じ | **一致** |

**章ごとの初出を採る。** 両モードで一致することに加え、第 5 章から読み始めた読者が用語集へ飛べるという読者側の利点がある。

`<dfn>` / `<span>` の使い分け（初出＝定義箇所）は**書籍全体のまま**とする。索引ページで定義箇所のページ番号を太字にするためのメタデータであり、性質上どうしても全書籍が単位である。**見た目には出ない**（`base.css` が `dfn` を透明なアンカーとして組む）ので、単章との差分にはならない。

### 4.2 単章では正しく出せないもの

`main_reference?` は他章の出現を知る必要があるため、単章では判定できない。単章では**主要参照を決めない**（索引ページを作らないので実害がない）。

### 4.3 §4 の先取り実装（2026-08-11 実施済み）

索引の不具合（`index-markup-plain-fallback-spec.md`）を直す過程で、**§4 の分割は先に入れた**。

- `IndexCommands.tag_chapters_for_build!` を新設し、単章モードの `build_target_sections_html` から呼ぶ
- `strip_index_markup!` は「索引・用語集が無効なとき」だけの代替に縮小（モード判定は不要になった）

これにより **`index scan and build` の章スコープ部分は既に単章でも走っている**。本仕様書に残るのは `unit:` 軸そのものの導入と、§4.1 の † 規則である。

## 5. 実装順序

1. **`unit:` を第 5 要素として導入**し、全 22 ステップに付ける。この時点では単章モードの表は据え置き、値が正しいかだけを見る
2. **単章モードの表を `unit: :chapter` からの導出に置き換える**。現状の 7 ステップと突き合わせ、増える分（索引タグ付け）が意図どおりか確認する
3. **索引ステップを分割**（§4）。† を章ごとの初出に限る
4. **補償コードを撤去**する。`strip_index_markup!` は存在理由ごと消える（§8）。`chapter_tokens_override` 系は `:whole_book` 情報なので残る

各段で `rake test` 全緑を確認し、2 と 3 の後は実ビルドで紙面を見る。

## 6. テスト

`notation-implementation-guide.md` §7 の流儀に従う。

1. **単位の宣言漏れ**: 全ステップが `unit:` を持つ（持たないステップがあれば失敗）
2. **導出**: 単章モードのステップ集合＝`unit: :chapter` かつ `single: :skip` でないもの
3. **逸脱の明示**: `single: :skip` を持つステップが §3.1 の表と一致する
4. **†**: 同一章に 3 回出る用語集語で、† が 1 つだけ付く
5. **パリティ（実ビルド）**: 同じ章を単章・全章の両方で組み、**章 HTML を突き合わせて差分が §3 の「一致させない」に限られる**ことを確認する

5 が本仕様書の要である。差分の許容リストを持たせ、そこに無い差分が出たら失敗させる。記法網羅フィクスチャ（`test/vivlio_starter/fixtures/notation/`）をそのまま検体に使える。

## 7. 影響範囲

- **単章プレビューに † が出るようになる。** 索引タグ自体は透明なので、見た目の変化は † だけ
- 全章ビルドでは † が減る（全出現 → 章ごとの初出）。**既存書籍の紙面が変わる**ので実書籍で目視確認が要る
- パイプラインの中核に手を入れるが、**利用者から見た CLI の形は変わらない**（著者確認済み）

## 8. `index-markup-plain-fallback-spec.md` との関係

あちらは「索引スキャンが走るか」の述語を新設し、`strip_index_markup!` にガードを足す案だった。**本仕様書を先に入れると、その述語は不要になる**——単章でも索引タグ付けが走るため、`strip_index_markup!` という代替そのものが消えるからである。

| 実装順 | 結果 |
| --- | --- |
| 本仕様書 → 索引仕様書 | 索引仕様書に残るのは §4.1（`IndexMarkup.plain_text` によるエスケープの正典化）だけ。**推奨** |
| 索引仕様書 → 本仕様書 | 述語を作ってから撤去することになる。無駄だが、索引の不具合を先に止められる |

索引の不具合（`[<h1>]` が本物の見出しになる）は**現に紙面を壊している**ため、リリース時期との兼ね合いで後者を選ぶ余地はある。その場合も §4.1 のエスケープは本仕様書と独立して価値があり、捨てずに残る。
