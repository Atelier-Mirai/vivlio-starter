# 分冊（上下巻・上中下巻・第 N 分冊）を組む

> 状態: 段階 1・2 実装済み（2026-10-20・feature/multivolume）。段階 3・4 は未実装。実装で分かったことは §13
> 発端: `vivlio-starter-multivolume-request.md`（2026-10-17）。2026-10-19〜20 の検討で、巻の数を決め打ちしない形にまとめた。
> 前提: `catalog-section-kind-spec.md`（巻ごとの前書きを置くために、区分で章の種類を決める）。

## 1. いまの姿

### 1.1 回り道

『AIと学ぶモダンWebサイト入門』は、Vivlio Starter の外のスクリプト（`book_ai_web_starter/sources/build_volume.rb`）で上下巻を組んでいる。

- 巻ごとの目次（`config/catalog-upper.yml`・`catalog-lower.yml`）を、組むあいだだけ `config/catalog.yml` へ写す。
- `book.yml` の `project.name`・`output.cover`・`book.main_title`・`book.subtitle` を、巻ごとの値に書き換える（巻の値は `config/volumes.yml`）。
- 巻ごとに違う原稿（下巻の前書き）は `sources/volumes/lower/00-preface.md` に置き、組むあいだだけ `contents/00-preface.md` と入れ替える。
- 組み終えたら（途中で止めても）すべて元に戻す。

### 1.2 回り道で残る不便（要望書 §1.2）

| 不便 | この仕様での扱い |
| :--- | :--- |
| 下巻の章番号が「第1章」から始まる | §5.1（既定で前の巻から続ける） |
| 下巻だけの付録の記号を続けられない | §5.2 |
| 別の巻の章を指す `@chapref` が未定義になる（上巻 2 件・下巻 19 件） | §8（段階 3） |
| 用語集の「ビルド対象章に出現しません」が大量に出る | §6.2 |
| 出力ファイル名が巻によらず同じ | §4.6 |
| `catalog.yml` を書き換えるので、戻し忘れると次の `vs create`・`vs preflight` が片方の巻だけを見る | §3（目次は一つのまま、巻を選ぶ） |
| 巻ごとの前書きを置けない | `catalog-section-kind-spec.md`（段階 1） |
| 全巻の構成を示す目次がない | §9（段階 4・章まで） |

### 1.3 コードの今

- 目次の読み込みは、ほぼすべて `CatalogLoader.load_catalog`・`load_existing_basenames`・`load_labeled_entries` と、その上の `TokenResolver` を通る。
- 「第 N 章」の N は、本文の章の並びでの位置に 1 を足して決める。計算は 3 か所にある（`HeadingProcessor#resolve_main_chapter_display_number`、`CrossReferenceProcessor.display_chapter_number_for_filename`・`chapter_number_text_for`）。図表番号と `@chapref` の文字も、この値から作る。
- 全章ビルドでは、`HeadingProcessor#discovered_main_chapter_tokens` が中間 HTML の置き場（`Common::BUILD_HTML_DIR`）にある HTML から本文の章の並びを起こす。
- 付録の記号は `Common.appendix_number_to_letter` の 1 か所で、付録の並びでの位置から振る。
- 出力ファイル名は `Common.generate_output_filename`・`generate_cover_output_filename` で、`project.name` から作る。
- EPUB の `dc:identifier` は、ISBN がなければ `project.name` から作る UUID である（`EpubBuilder#stable_project_uuid`）。回り道では巻ごとに `project.name` を変えているので、巻ごとに違う識別子になっている。
- 用語集の「ビルド対象章に出現しません」は、走査した章が目次の全章を覆っているとき（`UnifiedIndexManager#full_catalog_scope?`）だけ出る。回り道では目次そのものを巻の分に差し替えているので、巻ごとの組版でも「全章を走査した」と判定されて出る。
- 部（中扉）には番号を振っていない。中扉に出すのは部の題名だけである。

## 2. 方針

- **巻は順番のある並びとして扱う。** 巻の数は 2 以上なら自由（上下巻、上中下巻、第一分冊〜第 N 分冊）。
- **巻の名前は著者が書き、vs はその意味を読まない。** `upper`・`lower`・「最後の巻なら下巻」のような決め打ちをコードに置かない。巻の名前を番号から自動で作る機能（「第三分冊」）は作らない。
- **「前の巻」「最初の巻」「最後の巻」は、並びの順から決める。**
- **巻を書かない `catalog.yml` は、今までどおり一冊として組む。**
- 試験は上中下の 3 巻で行う。2 巻だけで確かめると、「最初の巻でなければ最後の巻」という思い込みが隠れたまま通る。

## 3. 巻を書く（`catalog.yml`）

### 3.1 書き方

```yaml
VOLUMES:
  - name: 上巻
    id: upper
    main_title: AIと学ぶモダンWeb入門　上巻
    subtitle: 花屋のサイトで学ぶ HTML・CSS と JavaScript の基本
    PREFACE:
      - 00-preface
    CHAPTERS:
      - コンピュータとAI、Webへの入り口:
          - 01-computer
          - 02-ai
      # …
    APPENDICES:
      - 90-how-to-ask
      - 93-cheatsheet

  - name: 下巻
    id: lower
    main_title: AIと学ぶモダンWeb入門　下巻
    subtitle: じゃんけんアプリで学ぶ JavaScript と Git・PWA・Canvas
    PREFACE:
      - 20-vol2-intro          # 下巻のはじめに（catalog-section-kind-spec.md）
    CHAPTERS:
      - じゃんけんアプリを育てる:
          - 21-janken-simple
      # …
    APPENDICES:
      - 90-how-to-ask          # 上巻と共通
      - 93-cheatsheet
      - 94-canvas-works        # 下巻だけ
    POSTFACE:
      - 99-postface
```

### 3.2 巻の設定

小文字のキーは巻の設定、大文字のキーはその巻の目次である。

| キー | 必須 | 意味 |
| :--- | :--- | :--- |
| `name` | 必須 | 巻の呼び名（「上巻」「第一分冊」）。巻をまたぐ参照の表示（§8）と、`--volume` の指定に使う |
| `id` | 必須 | ファイル名と `--volume` に使う短い名前。英小文字・数字・`_` だけ。`all` は使えない（§4.2） |
| `main_title`・`subtitle` | 任意 | その巻だけ `book.yml` の `book.main_title`・`book.subtitle` を置き換える |
| `cover` | 任意 | その巻だけ `book.yml` の `output.cover` を置き換える（`covers/frontcover_<cover>.png` などを使う） |
| `chapter_start` | 任意 | その巻の最初の本文の章の番号（§5.1） |
| `appendix_start` | 任意 | その巻の付録を振り直すときの最初の記号（§5.2） |
| `whole_toc` | 任意 | `true` で、その巻に全巻の目次を載せる（§9） |

巻の設定を `book.yml` ではなく `catalog.yml` に置くのは、巻の構成と一体のものだからである。`book.yml` に置くと、分冊でない本の著者にも使わないキーが見えることになる（`config-key-criteria-guidelines.md` §1 は、`book.yml` のキーをすべて `book.yml` に書くことを求めている）。番号の振り方を全巻まとめて選ぶキー（要望書の `volumes.numbering`）は設けない。既定の振り方（§5）で多くの本が済み、違う本は巻の `chapter_start`・`appendix_start` で足りるからである。

### 3.3 止める場合（🔴）

| 場合 | 理由 |
| :--- | :--- |
| `VOLUMES` と、一番上の `PREFACE`・`CHAPTERS` などが同じファイルにある | どちらが目次か決められない。直し方として、一番上の区分を巻の中へ移す書き方を添える |
| `name` か `id` がない、`id` の形が正しくない、`id` が `all` | ファイル名と `--volume` に使えない |
| 二つの巻の `id` または `name` が同じ | `--volume` でどちらを指すか決められない |
| 同じ本文の章を二つの巻に書いた | 章番号が決まらない |
| 同じ原稿を、巻によって違う区分に書いた | 種類が決まらない（`catalog-section-kind-spec.md` §2.1） |

前書き・付録・後書きは、二つ以上の巻に書いてよい（共通の付録）。

### 3.4 巻を選ぶ仕組み

- 組む巻は、処理の始まりに一度だけ決める（`Build::Volumes.current`。巻を選ばないときは `nil`）。
- `CatalogLoader.load_catalog` は、巻が選ばれていればその巻の目次を、選ばれていなければ全巻を合わせた目次（§4.3）を、今と同じ形の Hash（`PREFACE`・`CHAPTERS`・`APPENDICES`・`POSTFACE`）で返す。目次を読むほかの処理（部の中扉、最初の本文の章を探す `BodyClassInjector`、索引の対象など）は、これで直さずに済む見込みである。
- 巻の一覧（設定と目次）は、新しい `CatalogLoader.volumes` で返す。番号の計算（§5）と巻をまたぐ参照（§8）が使う。

## 4. 組む

### 4.1 巻を選んで組む

```
vs build --volume lower      # id で選ぶ
vs build --volume 下巻       # name でも選べる
```

- 巻の `main_title`・`subtitle`・`cover` を、`book.yml` の値に重ねた `CONFIG` で組む（`Common.install_configuration!` と `deep_merge_config` を使う）。扉・奥付・PDF の文書情報・EPUB の書誌情報は、どれも `CONFIG` から読むので、そのまま巻の値になる。
- 前に別の巻を組んだ中間 HTML が残っていると、本文の章の並び（§1.3）に混ざって番号がずれる。巻を切り替えて組むときは、`--no-clean` でも中間 HTML の置き場を空にしてから組む（最後に組んだ巻を置き場に記録して比べる）。

### 4.2 全巻を続けて組む

```
vs build --volume all
```

- 巻の順に、一巻ずつ**別のプロセスで** `vs build --volume <id>` を走らせる。設定（`CONFIG`）や章の並びの記録はプロセスの中に残るので、同じプロセスで巻を切り替えると前の巻の値が混ざる。
- 途中の巻で失敗したら、そこで止め、どの巻で失敗したかを知らせる。それまでに組んだ巻の出力は残す。
- `--no-compress` などのほかのオプションは、各巻の `vs build` へそのまま渡す。

### 4.3 巻を選ばずに組む（合本）

`VOLUMES` のある本で `vs build` とだけ打つと、全巻を一冊にまとめた合本を組む。校正や、電子版の合本に使う。

- 構成: **最初の巻の `PREFACE`** → 全巻の `CHAPTERS`（巻の順） → 全巻の `APPENDICES`（重なりを除く） → **最後の巻の `POSTFACE`**。2 巻目以降の前書き（「下巻のはじめに」）と、最後の巻より前の後書きは、合本では一冊の途中に来ることになるので載せない。
- 番号は全体を通して振る。巻の `chapter_start`・`appendix_start` は使わない。
- 書名・副題・表紙は `book.yml` の値を使う。出力ファイル名に巻の `id` は入らない。

### 4.4 単章ビルド

- `vs build 21` は、その章を載せた巻の番号の振り方で組む（下巻の 21 章なら「第13章」）。
- 付録のように二つ以上の巻に載る原稿は、最初に載せた巻で組む。`--volume` を添えれば選び直せる。
- どの巻にも載っていない原稿は、今と同じく目次の外の原稿として組む。

### 4.5 `--volume` を受け付けない場合（🔴）

- `VOLUMES` のない本で `--volume` を付けた: 直し方として、`VOLUMES` の書き方の例（§3.1 を短くしたもの）を添える。
- 巻の名前が見つからない: 書かれている巻の `id` と `name` を並べて添える。

### 4.6 出力ファイル名

巻を選んで組んだときは、`project.name` の後に巻の `id` を入れる。

| 出力 | 例 |
| :--- | :--- |
| PDF | `book_ai_web_starter_lower_v0.1.0.pdf` |
| 印刷用 PDF | `book_ai_web_starter_lower_print_v0.1.0.pdf` |
| EPUB・KPF | `book_ai_web_starter_lower_v0.1.0.epub`・`.kpf` |
| 表紙 | `book_ai_web_starter_lower_frontcover_v0.1.0.pdf`・`.jpg` |

`vs clean` の消す対象は `project.name` から始まる名前（`clean.rb` の `add_dynamic_filename_patterns`）なので、巻の出力も消える。名前の形を選ぶキーは設けない。

### 4.7 EPUB の識別子

ISBN がないとき、`dc:identifier` の UUID を `project.name` と巻の `id` から作る。同じ識別子だと、電子書籍ストアや読書アプリが上巻と下巻を同じ本の版違いとして扱うためである。合本は今と同じく `project.name` だけから作る。

## 5. 番号

### 5.1 本文の章

- 既定では**前の巻から続ける**。巻 k の最初の本文の章の番号は、それより前の巻の本文の章の数に 1 を足した数である。
- `chapter_start` を書いた巻は、その番号から始める。その後の巻は、`chapter_start` を書いた巻から続ける。
- 図表番号（図 13-2）と `@chapref` の「第13章」も、同じ番号を使う。番号の計算は 3 か所（§1.3）から一か所（`Build::Volumes`）へまとめ、どこからもそれを呼ぶ。

例（上中下巻・本文の章がそれぞれ 12・10・8 章）:

| 書き方 | 上巻 | 中巻 | 下巻 |
| :--- | :--- | :--- | :--- |
| 何も書かない | 第1〜12章 | 第13〜22章 | 第23〜30章 |
| 中巻に `chapter_start: 1` | 第1〜12章 | 第1〜10章 | 第11〜18章 |
| 全巻に `chapter_start: 1` | 第1〜12章 | 第1〜10章 | 第1〜8章 |

### 5.2 付録

- 既定では、**全巻を巻の順に見て、初めて出た付録に次の記号を振る**。別の巻に再び載るときは、同じ記号を使う。
  - 上下巻の例: 上巻は 90〜93 が付録 A〜D。下巻も 90〜93 は A〜D のままで、下巻だけの 94 が付録 E。
- `appendix_start` を書いた巻は、その巻の付録だけを、その巻での並びの順に、指定の記号から振る。ほかの巻の記号には影響しない。
- 付録の原稿は全巻で `90`〜`98` の 9 本までなので（`contents/` は全巻で一つ）、既定の規則では記号は A〜I に収まる。`catalog-section-kind-spec.md` §4.3 で記号を A〜Z まで振れるようにするので、上限には余裕がある。

### 5.3 部とノンブル

- 部には番号を振っていない（§1.3）ので、扱いは変わらない。
- ノンブル（ページ番号）は巻ごとに 1 から振る。回り道と同じ結果である。

## 6. 原稿の検査

### 6.1 `vs preflight`・`vs lint`・`vs metrics`

- `--volume <id|name>` を受け付け、その巻の原稿だけを見る。
- 巻を選ばないときは、**全巻の原稿**（どれかの巻に載っている原稿すべて）を見る。合本（§4.3）とは違い、2 巻目以降の前書きも含める。原稿の検査は、紙面に載るかどうかではなく、書いた原稿すべてが対象だからである。
- `vs metrics` は、巻を選ばないとき、章ごとの表の後に巻ごとの合計（文字数・ページの目安）を足す。

### 6.2 用語集の警告

`full_catalog_scope?` が比べる「目次の全章」を、**全巻の原稿**にする。巻を選んで組むと全章を走査したことにならないので、「ビルド対象章に出現しません」は出ない。全巻を見たとき（合本・巻を選ばない `vs preflight`）にだけ、どの巻にも出てこない語として出る。

### 6.3 索引と用語集のページ

巻を選んで組むと、索引と用語集はその巻の原稿から作る（回り道と同じ結果）。実装では、索引の走査の対象が選んだ巻の原稿になることを確かめる。

## 7. 章の管理コマンド

- `vs create 31-xxx`: 番号が一つ前の本文の章（`30`）を載せた巻の、同じ区分に足す。見つからなければ最後の巻に足す。`--volume` を添えれば巻を選べる。
- `vs delete`: すべての巻から外す。
- `vs rename`: すべての巻で書き換える。今の `CatalogUpdater` は最初に見つけた行だけを書き換えるので（`find_active_entry_line`）、すべての行を書き換えるように直す。
- `CatalogUpdater` は行ごとに書き換える方式で、部の入れ子にはすでに対応している。`VOLUMES` の中は字下げが一段深くなるので、区分の見出しの探し方を巻の中まで広げる。

## 8. 巻をまたぐ参照（段階 3）

- ラベル（`@ch-…`・`@fig-…` など）を、**全巻の原稿から**集める。今は目次に載った原稿だけから集めている（`pre_process.rb` の Phase 1）。集めたラベルには、それを書いた巻を記録する。
- 別の巻のラベルを指す参照は、次のように表す。
  - 表示: 巻の `name` を前に添える。例: `@chapref:ch-dom` →「上巻 第8章「JavaScript でページを操作する」」、`@fig-…` →「上巻 図 8-2」。番号は、その巻の振り方（§5）で決まる。
  - リンクにしない。`@pageref` もページ番号を付けず、章の表示（「上巻 第8章」）にする。
  - 表示の形を選ぶキーは設けない。巻の `name` は自由に書けるので、「第一分冊 第8章」にもなる。
- 合本では、すべてのラベルが同じ一冊にあるので、普通の参照になる。
- 「未定義のラベルID」は、どの巻にもないラベルにだけ出す。
- 「前の章 @ch-x」の検査（`chapter-reference-spec.md` §2.10）は、全巻の並びで判定する。下巻の最初の章の「前の章」は、上巻の最後の章である。

## 9. 全巻の目次（段階 4）

分冊の本で、その巻の目次とは別に、全巻の構成を章まで示す目次を載せる（要望書 §2.7）。

### 9.1 載せる巻

- 巻の設定に `whole_toc: true` を書いた巻にだけ載せる（§3.2）。既定では載せない。全巻に載せる本も、2 巻目以降にだけ載せる本もあるので、巻ごとに選べるようにする。
- 合本（§4.3）には載せない。合本の目次がそのまま全巻の目次になるからである。

### 9.2 載せる内容

```
全巻目次

上巻
  前書き
  コンピュータとAI、Webへの入り口
    第1章 コンピュータとは
    第2章 AI のしくみと付き合い方
    …
  付録 A うまく伝えるための言い方集
  …

下巻                          ← 今の巻は目立たせる
  下巻のはじめに
  じゃんけんアプリを育てる
    第13章 シンプルなじゃんけんゲームを作る
    …
  付録 E Canvas で小さな作品を作る
  後書き
```

- 巻の順に、巻の `name` を見出しにして、その巻の目次（`PREFACE`・部・`CHAPTERS`・`APPENDICES`・`POSTFACE`）を並べる。
- 細かさは**章まで**。節は載せない。
- 章の番号と付録の記号は、§5 の振り方による（下巻の章は「第13章」から）。題名は各原稿の `#` の見出しから取り、`@chapref` と同じく `CrossReferenceProcessor.plain_chapter_title` で整える。
- 部の題名は `catalog.yml` から取る。
- **ページ番号は載せない。** 今の目次は、組み上がった HTML から作り、ページ番号は Vivliostyle が組版のときに数える。他の巻はその場で組まないので、ページ番号がわからない。今の巻の分だけページ番号を付けると見た目がそろわないので、今の巻にも付けない。今の巻のページは、続く詳しい目次で引ける。
- 今の巻は、巻の見出しと項目にクラス（`vs-current-volume`）を付けて目立たせる。Kindle は `var()` を読まないので、`body.vs-kindle` の側ではリテラルの色で書く（`kindle-css-compatibility-notes.md`）。
- 他の巻の項目はリンクにしない。今の巻の項目も、詳しい目次と役目が重なるのでリンクにしない。

### 9.3 置き場所と作り方

- その巻の目次（`_toc`）の**前**に置く。全体の構成を見てから、その巻の詳しい目次へ進む順になる。
- 扉（`_titlepage`）や中扉（`PartTitleGenerator`）と同じく、システムページ `_whole_toc` として `.cache/vs/` に Markdown を書き、HTML に変換する。組み立ての 4 か所（`catalog-section-kind-spec.md` §4.2）で、`_toc` の前に差し込む。
- ページの見出しは「全巻目次」とし、PDF のしおりと EPUB の nav に 1 項目として載せる。
- 章の題名を他の巻の原稿から取り出す処理は、段階 3 のラベルの収集（§8）と共通にする。段階 3 より先に入れる場合も、題名の取り出しは `CrossReferenceProcessor` の同じ処理を使う。

### 9.4 試験

- 上中下の 3 巻の器で、中巻だけに `whole_toc: true` を書く。中巻の PDF・EPUB に、三つの巻の見出しと章が §5 の番号で並び、中巻が目立ち、ページ番号とリンクがないことを確かめる。上巻・下巻と合本には載らない。
- `chapter_start` を書いた巻があるとき、全巻の目次の番号が各巻の章扉と一致する。
- Kindle の器（`epub_kindle_layout_test`）で、今の巻の目立たせ方がリテラルの色で出る。

## 10. この仕様で扱わないもの

実装を終えるときに `PLANNED.md` へ移す。

- 全巻の目次を節まで載せること、ページ番号を載せること（§9）
- 巻ごとの ISBN・発行日・版、背表紙（要望書 §2.8）。`main_title`・`subtitle`・`cover` 以外の `book.yml` の値を巻ごとに置き換える仕組み

- 2 巻目以降の前書きの雛形（要望書 §2.5）と、`vs create` で前書きとして作る指定

## 13. 実装記録

### 13.1 段階 2（2026-10-20）

- **単章ビルドの章扉は、§4.4 と違い「第1章」から数える。** `chapter-reference-spec.md` の決定（2026-09-29）で、単章ビルドの章扉は対象の章だけで数える（`vs build 44` なら「第1章」）。この決定を守り、巻の振り方は全章ビルドと `@chapref` の文字にだけ効かせた。単章ビルドでも、組む範囲はその章を載せた巻になる（`@chapref` の番号が巻の振り方になる）。
- **全章ビルドかどうかを `chapter_tokens_override` で見分けられない。** `SectionBuilder.convert_sections_html!` は、並列変換で章の並びのキャッシュが崩れないよう、全章ビルドでも本文の章の並びを override で渡している。そこで、全章ビルドで「第 N 章」に足す数を `HeadingProcessor.chapter_number_offset` として明示的に渡す（巻を選んだ全章ビルドのときだけ `BuildCommand` が設定する）。最初は override の有無で見分けたため、3 巻の試し組みで中巻の章扉が「第1章」になった。
- **目次の「第 N 章」「付録 A」は CSS のカウンタ（`toc.css`）で 1 から数えている。** 章扉の番号を HTML に書いても目次には届かない。目次の最上位の `<ul>` に `counter-reset: toc-list-counter N` を与え、付録は記号が巻の中で飛ぶ（下巻の付録が A・C）ので、付録の `<li>` ごとに章扉と同じ記号の位置を `counter-reset` で与える。巻の無い本では何も足さない（出力は変わらない）。
- **PDF のしおりは、番号の範囲から「第 N 章」を補う予備の経路を持っていた**（`OutlineExtractor#resolve_chapter_number_display`。11〜89 を「第 N−10 章」）。下巻の前書き `20-vol2-intro` が「第20章 下巻のはじめに」になったので、本文の章にだけ使うようにした。
- 確かめたこと: 雛形から作った本を上中下の 3 巻に分け（巻ごとの前書き・共通の付録・一つの巻だけの付録・部・後書き）、`--volume all`・合本・単章ビルドで組んだ。章番号（1〜2・3〜4・5〜6）、付録の記号（中巻 A・B、下巻 A・C）、書名、出力ファイル名、目次、PDF のしおりが、それぞれ巻の振り方どおりになった。
