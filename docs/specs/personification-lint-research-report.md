# 報告書：擬人法（「黄金比が顔を出す」）を `vs lint` で指摘できるか

> 作成日: 2026-09-01
> ステータス: **調査のみ。実装・仕様化は未着手**（後日検討用の資料）
> 起票: 「黄金比が顔を出す」「再帰が顔を出す」「アルゴリズムの問題が顔を出す」は避けたいが、
> 「太陽が顔を出す」は許したい——この線引きを機械にやらせられるか、という相談から。
> **既製データが存在するかの確認**が主目的（`mazegaki` が SudachiDict から作れたので、
> 同じように種データがあるなら話が早い、という見込みだった）
> 対象: `lib/vivlio_starter/cli/lint/prose_checker.rb`（実装するならここ）
> 関連: `lint-japanese-prose-rules-spec.md`（ProseChecker の設計）・
> `mazegaki-two-tier-spec.md`（辞書を外部データから作った前例）・
> `config-key-criteria-guidelines.md`（opt-in にするなら判断軸はこちら）

---

## 1. 要旨

**結論は 3 つ。**

1. **技術的には実装できる。** `ProseChecker` に 30 行程度で、既存の `ambiguous-comparison`
   と同じ形（文脈依存・`--fix` しない・`disabled_rules` で切れる）に収まる。
2. **既製データは存在しない。** 「擬人法かどうか」を教えてくれるデータセットは無く、
   隣接する資料（分類語彙表・日本語 WordNet・Wiktionary）もこの判定には直接使えない。
   **`mazegaki` のように外部辞書から機械抽出する道は無い**（理由は §4.3）。
3. **これは誤りではなく文体の選択である。** 文法的に正しい表現なので、gem 本体へ
   既定 ON で入れるのは筋が悪い。入れるなら `book.yml` の opt-in（§5）。

---

## 2. 何を指摘したいのか

| 文 | 判定 | 理由 |
| :--- | :--- | :--- |
| 黄金比が顔を出す | NG | 主語が抽象概念。擬人法 |
| 再帰が顔を出す | NG | 同上 |
| アルゴリズムの問題が顔を出す | NG | 同上 |
| 太陽が顔を出す | OK | 字義どおり。比喩ではない |
| 会に顔を出す | OK | 別の慣用句（出席する）。格助詞が「に」 |

線引きは**主語が字義どおり「顔を出せる」ものか**にある。

---

## 3. 判定の設計

### 3.1 述語側は直積で書く

列挙すると必ず漏れる。実際、最初の検討で `顔を出す` `姿を見せる` `頭をもたげる`
`息づく` `顔をのぞかせる` を並べたところ、**その組み合わせである「顔を見せる」が
抜けていた**。部位と動詞の直積にすれば埋まる。

```ruby
APPEARANCE_NOUN = /顔|姿|頭|首|鎌首/
APPEARANCE_VERB = /出[すしせさ]|見せ|のぞかせ|覗かせ|もたげ|現[すしせさ]/
PERSONIFICATION = /([^\s、。「」]{1,12})が(#{APPEARANCE_NOUN})を(#{APPEARANCE_VERB})/
```

|  | 出す | 見せる | のぞかせる | もたげる | 現す |
| :--- | :---: | :---: | :---: | :---: | :---: |
| 顔を | ✓ | ✓ | ✓ | — | — |
| 姿を | ✓ | ✓ | — | — | ✓ |
| 頭を | — | — | — | ✓ | — |

動詞は語幹で当てるので活用も吸収する（`顔を出した` / `顔を出して` / `顔を出しています`）。
直積は「頭を見せる」のような不自然な組み合わせも生むが、**原稿に出てこない以上、
過剰生成に実害はない**。

### 3.2 主語側は許可リストで持つ

**品詞では判定できない。** 「太陽」も「黄金比」も Sudachi では `名詞,普通名詞,一般` で、
形態素解析器は両者を区別しない。意味の情報が要る。

```ruby
# 字義どおり「顔を出す」ことができるもの
LITERAL_SUBJECTS = %w[太陽 日 朝日 夕日 月 星 雲 芽 新芽 双葉 猫 犬 鳥 彼 彼女 さん 氏 先生].freeze
```

主語の**末尾**が許可リストにあれば通し、なければ指摘する。末尾で見るのが要点で、
これにより修飾語が付いても効く。

| 文 | 切り出される主語 | 末尾一致 | 判定 |
| :--- | :--- | :--- | :--- |
| 朝の太陽が顔を出す | 朝の太陽 | 太陽 | 通す |
| 黄金比が顔を出す | 黄金比 | — | 指摘 |
| アルゴリズムの問題が顔を出す | アルゴリズムの問題 | — | 指摘 |

### 3.3 残る誤検知は人名

「山田さんが顔を出す」は指摘されてしまう。接尾辞（`さん` `氏` `くん` `先生`）を
許可リストへ入れれば大半は防げるが、姓名を直接書く場合（「漱石が顔を出す」）は残る。
技術書では頻度が低いので許容範囲と見る。

## 4. 既製データの調査（本報告の主目的）

### 4.1 擬人法そのもののデータセットは無い

日本語の慣用句オープンデータ、機械可読な形式、ライセンス明記——という条件で探した範囲では、
**慣用句に特化した公開データそのものが乏しく、「擬人法」の印が付いたものは見つからなかった**。
修辞技法の分類は学術的にも機械可読な形で整備されていない。

### 4.2 隣接するデータ源は 3 つある

| 資料 | 内容 | この用途での可否 |
| :--- | :--- | :--- |
| **分類語彙表－増補改訂版DB**（国語研） | 意味分類シソーラス。CSV 101,070 レコード。「抽象的関係」「自然物」等の部門コードを持つ | **商用利用は要問い合わせ**。MIT の gem へ同梱できない。ここで脱落する |
| **日本語 WordNet**（NICT） | 上位語（hypernym）をたどれる。「太陽 → 物理的実体」「黄金比 → 抽象」の判定が原理的に可能。**ライセンスを保持すれば無償で使用・複写・改変・頒布可** | ライセンスは通る。ただし約 100MB あり、主語の切り出しに形態素解析も要る |
| **Wiktionary 慣用句カテゴリ** | CC BY-SA。慣用句は集まる | 「擬人法」の印が無い。結局は手で選別する |

**日本語 WordNet だけが候補として残る。** 使うなら `MazegakiScanner` と同じ
「MeCab があるときだけ動く第 2 層」の構成になる。ただし得られるのは
「顔を出す」系の指摘だけで、**費用対効果は低い**（§6 の限界と併せて判断すること）。

### 4.3 `mazegaki` と決定的に違う点 — なぜ機械抽出できないのか

**交ぜ書きは「表記」の問題だった。** だから SudachiDict の正規化表記から機械的に
抽出でき、3.2MB の元データ（`mazegaki-source.tsv`・35,714 行）を
43KB・1,930 語（`mazegaki.tsv`）まで絞り込めた。**辞書に答えが書いてあった**わけである。

**擬人法は「意味と文脈」の問題である。** 「顔を出す」という見出し語はどの辞書にも
載っているが、**「主語が抽象名詞のときは不適切」とはどこにも書かれていない**。
辞書の見出しをいくら集めても、この判定には届かない。

この差は、今後「辞書から作れそうだ」と考えたときの判断材料になる——
**表記の問題なら外部辞書が使える。意味の問題なら使えない。**

## 5. どこに置くか

`ProseChecker` の既存ルールはすべて**誤りか曖昧さ**である。

| ルール | 性質 |
| :--- | :--- |
| `mazegaki` | 表記の誤り |
| `ambiguous-comparison` | 二通りに読める |
| `stray-index-markup` / `indented-code-block` / `setext-heading` | 記法の取り違え |

一方「黄金比が顔を出す」は**文法的な誤りではなく擬人法という表現**である。技術書で
避けるのは妥当な判断だが、文芸寄りの本では正しい表現になる。gem 本体へ既定 ON で
入れると全ユーザーの本に適用される点が引っかかる。

- **A. `ProseChecker` に既定 ON** — `disabled_rules` で切れる。他のルールと同じ扱い
- **B. `ProseChecker` に入れて `book.yml` で opt-in** — `trim_long_vowel: true` と
  同じ流儀。既定は黙る。**推奨**
- **C. プロジェクト固有の prh 辞書** — `config/` に置く。ただし prh は `expected` 必須で
  `--fix` が機械的に当たる。`ProseChecker` 冒頭のコメントが同じ理由で prh を却下しており、
  この種の文脈依存ルールには向かない

**B を推す。** 誤りではなく文体の選択なので既定で黙るべきで、かつ「使いたい人は
1 行で有効にできる」形が実態に合う。ただし `book.yml` へキーを 1 本足すことになるので、
着手時に `config-key-criteria-guidelines.md` の 5 軸へ照らすこと。

## 6. 限界 — 網羅は原理的に不可能

この方式で拾えるのは**体の部位を使う擬人法だけ**である。

```
アルゴリズムが微笑む
バグが潜んでいる
再帰が息を吹き返す
メモリが悲鳴を上げる
```

擬人的な述語は無限にあり、リストで囲い込めない。**「よくある型を拾う」ルールと
割り切る**設計になる。それでも「顔／姿／頭」系は頻度が高く、実用価値はあると見る。

---

## 7. 決めていないこと・着手時の出発点

- **語群をどう持つか。** `MazegakiDictionary` が語をコードから分けているのと同じで、
  この語群も**データとして外に出す**のがよい。書いているうちに気づいた表現を、
  コードを触らずに足せる形にしておく。
- **許可リストの初期値。** §3.2 の 18 語は思いつきで並べたもので、実測に基づかない。
- **本書に用例が無い。** 起票時点で `contents/*.md` に「顔を出」は **0 件**である。
  つまりこのルールは、既存原稿の不具合を直すものではなく、**これから書く文章のための
  ものである**。優先度を [Low] としたのはこのため。
- **育て方。** 既製データが無い以上、**実際の原稿で出会った表現を足していくのが
  唯一の現実的なデータ収集経路**になる。著者自身の文体で出た擬人法が、いちばん
  精度の高い種になる。
