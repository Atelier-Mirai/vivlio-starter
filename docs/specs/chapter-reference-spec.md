## 0. 背景

本書は、ほかの章へ案内するとき「詳しくは「ビルド」の章を参照してください」のように、**章題を地の文に手で書いている**。2026-09-29 時点で 15 章ぶん、39 か所ある。この書き方には弱点が二つある。

- **章題を変えると取り残される。** 2026-09-29 に章名からコマンド名を外したとき（改善案.md #61）、引用箇所を grep で探して手で直した。見落としても警告は出ない。
- **ページ番号がない。** 紙の本では、離れた章へ案内するときにページ番号があると探しやすい。

見出しにはすでにラベルを付けられ（`## インストール @install`）、`@pageref:install` でページ番号つきの参照になる（`at-directive-tier1-spec.md`）。章題（第 1 レベルの見出し）にも同じ書き方でラベルを付けられることは、2026-09-29 に試験用のプロジェクトで確かめた（章扉・目次・参照の表示に問題なし）。

ただし章ごとに手でラベルを書く方式には、次の難点がある。

- 全章の章題を書き換える必要があり、名前の付け方が書き手によって揺れる。
- 原稿から章題を直接読む処理にラベルが残る。`vs metrics` の章一覧に「はじめの一歩 @ch-intro」と出た（`metrics/chapter_parser.rb` の `H1_PATTERN`）。

そこで、**章のラベルはファイル名から暗黙に付ける**。著者は章題に何も書かず、参照する側だけを書く。

### 1.2 参照の書き方と表示

参照は、見出しラベルと同じ二通りに、章番号を添える `@chapref:` を加えた三通りで書く。

```markdown
詳しくは @chapref:ch-build を参照してください。
詳しくは @pageref:ch-build の章を参照してください。
コマンドの一覧は @ch-command-cheatsheet の章にまとめています。
```

| 書き方 | PDF | EPUB・Kindle |
| :--- | :--- | :--- |
| `@chapref:ch-build` | 第7章「ビルド」（p.123） | 第7章「ビルド」（章へのリンク） |
| `@chapref:ch-notation-cheatsheet` | 付録 A「記法早見表」（p.400） | 付録 A「記法早見表」（章へのリンク） |
| `@pageref:ch-build の章` | 「ビルド」（p.123）の章 | 「ビルド」の章（章へのリンク） |
| `@ch-build の章` | 「ビルド」の章 | 「ビルド」の章（章へのリンク） |

`@chapref:` は章番号を添えるので「の章」は要らない（§2.11）。`@pageref:` と `@ch-` では「の章」を著者が書く（§2.3）。`@ch-` という記法が単独であるのではなく、`@ch-<スラッグ>` 全体が一つのラベルを指す（見出しの `@install` と同じ）。

**ページ番号を付けるか（`@chapref:`・`@pageref:`）付けないか（`@ch-`）は、読者がその章を探すのにページ番号が役立つかで決める。** 離れた章への案内は `@chapref:` か `@pageref:` にする。「〜を参照してください」のように章そのものを案内するなら `@chapref:`、「「ビルド」で説明します」のように章題を文に組み込むなら `@pageref:` が収まりやすい。「前の章」「次の章」は、ページ番号がなくてもめくって探せるので `@ch-` にする。章題を出さない書き方（「前の章では、○○について紹介しました」）なら、参照を書く必要はない。

| 原稿 | 紙面 |
| :--- | :--- |
| `前の章 @ch-new では、○○について紹介しました。` | 前の章「新規プロジェクトの作成」では、○○について紹介しました。 |
| `次の章 @ch-lint では、○○に触れる予定です。` | 次の章「文章校正」では、○○に触れる予定です。 |
| `詳しくは @pageref:ch-build の章を参照してください。` | 詳しくは「ビルド」（p.123）の章を参照してください。 |

**同じ段落で同じラベルを二度 `@chapref:`・`@pageref:` したら、二度目以降はページ番号を付けない**（§2.9。決定 2026-09-29）。著者は段落の組み立てを気にせず、離れた章を引くときは常に `@chapref:` か `@pageref:` と書けばよい。文章が育って段落を二つに分ければ、後半の最初の参照にはまたページ番号が付く。

### 1.3 書き誤りの知らせ

未定義のラベルは、いまと同じく 🟡 で場所を添えて知らせ、ビルドは止めない。これに**綴りの近いラベルを 1 つ添える**（§2.7）。

```text
🟡     - contents/41-book-yml.md:317 - 未定義のラベルID: @pageref:ch-further-inspration
          もしかして: ch-further-inspiration
```

紙面には、いまと同じく `@pageref:ch-further-inspration` が文字のまま残る（知らせを見落としても、読み返せば気づける）。

## 2. 論点（決めること）

各項目の **推奨** は草案としての提案。

### 2.1 ラベルの名前

| 案 | 例 | `vs renumber` | `vs rename` でスラッグ変更 |
| :--- | :--- | :--- | :--- |
| **A. `ch-` ＋ スラッグ（推奨）** | `@ch-metrics` | 変わらない | 変わる（§2.2） |
| B. ファイル名そのまま | `@32-metrics` | **変わる** | 変わる |
| C. 著者が章題に書く | `# … @metrics` | 変わらない | 変わらない |

- A を推す。改番（`vs renumber`）はスラッグの変更よりずっと多く行われ、B はそのたびに参照が切れる。C は §0 のとおり手間と揺れが出る。
- `ch-` を付けるのは、見出しや図表の手書きラベル（`@install` など）と名前がぶつからないようにするため。24 章の例の `@install` と、93 章の暗黙のラベル `@ch-install` が共存できる。
- ファイル名の綴りがそのままラベルに出る。22 章は綴りの誤り（`extentions`）があったので、2026-09-29 に `22-extensions` へ改名した。

### 2.2 `vs rename` でスラッグを変えたとき

| 案 | 動き |
| :--- | :--- |
| **A. 本文の参照も書き換える（推奨）** | `ChapterRename::FOLLOWERS` に追随処理を 1 つ足し、`contents/*.md` の `@ch-<旧>`・`@pageref:ch-<旧>` を新しいスラッグへ書き換える（コードの中は対象外）。確認の画面に件数を出す |
| B. 案内だけ出す | 書き換えず、参照している箇所の一覧を 🟡 で出す |
| C. 何もしない | 次のビルドで「未定義のラベルID」が出る |

- A を推す。`chapter-rename-followers-guidelines.md` §1 の「章名を写して持つデータは追随処理を登録する」に当たる。本文の参照は著者が書いたものだが、機械的に一意に書き換えられるので、索引辞書の `main:` と同じ扱いにできる。
- `vs renumber` はスラッグを変えないので、この追随は動かない（§2.1 で A を選んだ場合）。

**スラッグを外す改名（`vs rename 11-intro 11`）**（決定 2026-09-29）: 新しいラベルがないので書き換える先がない。参照は書き換えず、確認の画面で先に知らせる。

```text
🟡 @ch-intro は 3 か所から参照されています。スラッグを外すと、これらの参照は解決できなくなります。
     contents/12-new.md:40
     …
```

- 参照を文字の章題へ書き換えることはしない。著者が書いた参照が知らないうちに消えるため。
- 改名したあとも参照は原稿に残り、`vs preflight`・`vs build` が「未定義のラベルID」として場所つきで知らせる（§1.3）。400 ページの原稿から探し直す必要はない。
- 直すには、スラッグを付け直す（`vs rename 11 11-information`。追随処理が参照を書き換える）か、参照を文字の章題に書き直す。

### 2.3 表示の形

| 案 | `@pageref:ch-build` の表示 |
| :--- | :--- |
| **A. 章題だけ（推奨）** | 「ビルド」（p.123） ＋ 著者が「の章」を書く |
| B. 「の章」まで自動 | 「ビルド」の章（p.123） |
| C. 章番号も付ける | 第 7 章「ビルド」（p.123） |

- A を推す。見出しラベルと同じ表示（`link_text` の `:sec` と同じ）なので、実装も説明も共通にできる。「「ビルド」の章を参照」「「ビルド」で説明します」のように文に合わせて書き分けられる。
- C は `@pageref:` の形としては採らず、別の記法 `@chapref:` として本仕様で足す（§2.11）。

### 2.4 スラッグのない章（`11.md`）

**推奨**: 暗黙のラベルを付けない。`@ch-11` のように参照された場合は、未定義のラベルの知らせに「スラッグのない章には章ラベルが付きません（`vs rename 11 11-intro` で名前を付けられます）」と添える。番号でラベルを作ると、改番で切れるため（§2.1 の B と同じ問題）。

### 2.5 `ch-` の予約

**推奨**: `ch-` で始まるラベルを著者が手で付けたら 🔴 で知らせる（予約マクロ ID と同じ扱い。`reserved_macro_id?` の隣で判定する）。暗黙のラベルと衝突すると、どちらが参照されるかが並び順で決まり、気づけないため。

### 2.6 孤立ラベルの警告

2026-09-29 の試験では、参照されていない章ラベルに「孤立ラベル '…' は未参照です」の 🟡 が出た。暗黙のラベルは全章に付くので、**暗黙の章ラベルは孤立ラベルの検査から外す**（推奨）。

### 2.7 誤記の候補

**推奨**: 未定義のラベルに、綴りの近いラベルを 1 つ添える（`DidYouMean::SpellChecker`。章の指定の `ChapterTargetCheck#suggestion_for` と同じ作法）。章ラベルだけでなく、図表・見出しのラベルにも効かせる。候補を 1 件に絞る理由は `ChapterTargetCheck` のコメントのとおり。

### 2.8 章題に記法が入っている場合

97 章の章題は `挑戦することの<br>贈り物` で、HTML タグを含む。ラベルの表示文字列（「」の中）には、タグと Markdown の記法を取り除いた文字（`挑戦することの贈り物`）を使う（推奨）。目次の表示と同じ文字にそろえる。

### 2.9 同じ段落での二度目のページ番号（決定 2026-09-29）

同じ段落で同じラベルを二度以上 `@pageref:` したら、二度目以降はページ番号を付けない（`@` と同じ表示にする）。

- 草案では「二度目は著者が `@ch-` だけにする」としていた。この書き方は段落の組み立てに左右され、文章が育って段落を分けると、後半の段落の参照にページ番号がなくなる。処理の側で判断すれば、分けたあとも正しく付く。
- 章ラベルに限らず、見出し・図表のラベルの `@pageref:` にも同じ規則を当てる。
- 段落は空行で区切られたまとまりとする。箇条書きの各項目と表の各行は、読者が一つずつ読むので、別のまとまりとして扱う。

### 2.10 「前の章」「次の章」と章の並びの食い違い

章の順番を入れ替えると、「前の章 @ch-new」の章題は参照から自動で差し替わるが、「前の」は著者が書いた文字なので追随せず、実際の並びと食い違う。

**推奨**: 「前の章」「前章」「次の章」「次章」の直後に `@ch-x`・`@chapref:ch-x`・`@pageref:ch-x` のいずれかがあれば、`catalog.yml` で x が本当に隣の章かを確かめ、違えば 🟡 で知らせる。章を入れ替えたあとの「前の」「次の」の食い違いは、読み返しても見落としやすい。

### 2.11 章番号を添える参照 `@chapref:`（2026-09-29 追加）

「付録 A「記法早見表」（p.400）を参照してください」のように、章番号・章題・ページ番号をまとめて出す記法。

| 参照先 | PDF | EPUB・Kindle |
| :--- | :--- | :--- |
| 本文の章（01〜89） | 第7章「ビルド」（p.123） | 第7章「ビルド」 |
| 付録（90〜98） | 付録 A「記法早見表」（p.400） | 付録 A「記法早見表」 |
| 前書き・後書き（00・99） | 「はじめに」（p.3） | 「はじめに」 |

- **章番号の文字は章扉と同じにする。** `heading_processor.rb` の `build_h1_number_text` が章扉に出す「第7章」「付録 A」を使う。本文の章は `catalog.yml` の本文の章の並び順、付録は付録の並び順で決まる（ファイル名の番号ではない）。前書き・後書きは章扉に番号がないので、章題だけにする。
- **番号は常に `catalog.yml` の全体から決める。** 単章ビルド（`vs build 41`）でも、参照先の章番号は全章ビルドのときと同じにする（参照先は単章ビルドの対象に入っていないため）。
- **引数は章ラベルに限る。** `@chapref:ch-build` と書く（`@chapref:build` ではない）。ラベルの名前を三つの記法でそろえ、grep と `vs rename` の追随（§2.2）を一つの名前で済ませるため。`@chapref:install` のように章ラベルでないものを指したら 🟡 で「`@chapref:` には章のラベル（`ch-…`）を指定してください。見出しには `@pageref:` を使います」と知らせ、文字のまま残す。
- ページ番号の出し方・同じ段落の二度目（§2.9）・EPUB での劣化は `@pageref:` と同じ。二度目は「第7章「ビルド」」になる。

**確認したいこと**: 例示いただいた「付録A 記法早見表（p.400）」は章題を「」で括っていない。推奨は、`@pageref:`・`@ch-` の表示（「ビルド」）とそろえて「」で括る形（付録 A「記法早見表」）。番号と「付録」のあいだの空白は章扉（「付録 A」）に合わせる。

## 3. 実装（案）

### 3.1 ラベルの収集

`CrossReferenceProcessor.collect_labels` で、章ファイルの最初の第 1 レベルの見出しを見つけたら、`type: :chap` の `Label` を足す。

- `id`: `ch-<スラッグ>`（スラッグは `TokenResolver::Entry#slug`。スラッグがなければ足さない。§2.4）
- `title`: 見出しの文字から、タグ・記法・手書きの見出しラベルを除いたもの（§2.8）
- 章番号の文字: 「第7章」「付録 A」。前書き・後書きには付けない（§2.11）
- 手書きの `@ch-…` は予約違反として 🔴（§2.5）

`pre_process.rb` の Phase 1（`catalog.yml` の全章からラベルを集める）がそのまま使えるので、単章ビルドでも他の章のラベルは解決される。

### 3.2 アンカー

章題の見出しの**内側**に `<span id="ch-<スラッグ>" class="vs-sec-anchor"></span>` を置く。見出しラベルと同じ規約（`try_heading_label` のコメント：見出しの前の行に置くと、改ページでアンカーだけが前のページに落ち、ページ番号が 1 ずれる）。章題は原稿から書き換えず、変換後の出力にだけ足す。

### 3.3 表示

`link_text` で `:chap` を `:sec` と同じ「「章題」」にする（§2.3 の A）。`@pageref:` のページ番号は、既存の CSS（`a.pageref::after` の `target-counter`）がそのまま付ける。EPUB・Kindle は `target-counter` を解さないので、章へのリンクだけになる（見出しラベルと同じ劣化）。

`@chapref:` は `PAGEREF_PATTERN` の隣に `CHAPREF_PATTERN` を足し、`:chap` のラベルに持たせた章番号の文字（§3.1）を「」の前に置いて、`pageref` クラスのリンクにする。章番号の文字は、`HeadingProcessor` の `resolve_main_chapter_display_number`・`resolve_appendix_letter` と同じ規則を、単章ビルドの絞り込み（`chapter_tokens_override`）を見ずに `catalog.yml` 全体へ当てて求める。規則を二か所に書かないよう、catalog 全体から番号を求める関数を一つ置き、両方から使う。

同じ段落での二度目（§2.9）は、`ReferenceReplacer#replace` が行ごとに回しているところで、段落の中で `@pageref:` 済みのラベル ID を集合に持つ。空行・コードブロックの行・箇条書きの項目の始まり・表の行で集合を空にする。集合にある ID の `@pageref:`・`@chapref:` は、`pageref` クラスを付けないリンクにする。

### 3.4 検査

- 孤立ラベルの検査から `:chap` を外す（§2.6）
- 未定義のラベルに候補を添える（§2.7）
- `vs lint` の記法ガード（`notation_guard.rb`）が `@ch-…` と `@pageref:ch-…` を記法として扱い、表記の指摘や `--fix` の対象にしないことを確かめる（既存の `@id` と同じ扱いのはず）

### 3.5 `vs rename` の追随

`ChapterRename::FOLLOWERS` に「本文の章参照」を足す（§2.2 の A）。`contents/*.md` を、コードブロックとインラインコードを除いて走査し、`@ch-<旧>`・`@chapref:ch-<旧>`・`@pageref:ch-<旧>` を置き換える。置き換えた件数を確認の画面と結果に出す。

## 5. テスト

- 章ラベルが `ch-<スラッグ>` で集まる／スラッグのない章には付かない
- 章題に `<br>` を含む章の表示文字列からタグが除かれる
- `@ch-x` と `@pageref:ch-x` が「「章題」」のリンクになり、`@pageref:` には `pageref` クラスが付く
- 手書きの `@ch-…` が 🔴 になる
- 暗黙の章ラベルが孤立ラベルとして知らされない
- 未定義のラベルに近い候補が 1 つ添えられる（章ラベル・図表ラベルの両方）
- `vs rename` でスラッグを変えると、本文の `@ch-旧`・`@pageref:ch-旧` が書き換わる（コードの中は残る）
- `vs rename` でスラッグを外すと、確認の画面に参照の件数と場所が出て、参照は書き換わらない
- 同じ段落の二度目の `@pageref:` にページ番号が付かない／空行で分けた次の段落の最初には付く／箇条書きの別の項目・表の別の行では付く
- 「前の章 @ch-x」の x が隣の章でなければ 🟡 になる（§2.10）
- `@chapref:` が本文の章で「第N章「章題」」、付録で「付録 X「章題」」、前書き・後書きで「「章題」」になり、`pageref` クラスが付く
- 単章ビルドでも `@chapref:` の章番号が全章ビルドと同じになる
- `@chapref:` に章ラベルでないものを書くと 🟡 になり、文字のまま残る
- 章題の見出しの内側にアンカーが入り、改ページでページ番号がずれない（実ビルドで確かめる）

## 6. 実装前に確かめること

- 単章ビルド（`vs build 41`）で他の章を `@pageref:` したとき、ページ番号の欄がどう表示されるか（参照先が同じ PDF にないため）。空になるなら、単章ビルドでは `@pageref:` を `@` と同じ表示に落とすかを決める。
- 単章ビルドの章扉の番号の付け方（`chapter_tokens_override` による）と、`@chapref:` の全体からの番号が食い違わないか。単章ビルドは確認用なので食い違ってよいとするか、章扉の番号も catalog 全体に合わせるかを決める。
- 章扉を画像にするスタイル（`theme.style: image`）で、章題の中のアンカーが章扉の組版を崩さないか。2026-09-29 の試験（手書きラベル）では問題なかったが、暗黙のラベルでも確かめる。
- EPUB・Kindle で、別の章のファイルへのリンクが正しく飛ぶか。

## 7. スコープ外

- 節（第 2 レベル以下の見出し）への暗黙のラベル。節は数が多く、見出しの文字の変更も多いので、いまの手書きの見出しラベルのままとする。
- 早見表の「解説章」の列の参照化（§4）。
