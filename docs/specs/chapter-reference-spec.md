# 章への相互参照（暗黙の章ラベル）仕様書

> 作成日: 2026-09-29
> ステータス: **草案**（§2 の論点の決定待ち）
> 対象: 改善案.md #1「章の相互参照にページ番号を添える」
> 関連: `at-directive-tier1-spec.md`（見出しラベルと `@pageref:id`）, `at-directive-ideas.md`（章参照が `@pageref` の主用途という整理）, `chapter-rename-followers-guidelines.md`（章名を持つデータの追随）, `lib/vivlio_starter/cli/pre_process/cross_reference_processor.rb`, `contents/24-cross-reference.md`

## 0. 背景

本書は、ほかの章へ案内するとき「詳しくは「ビルド」の章を参照してください」のように、**章題を地の文に手で書いている**。2026-09-29 時点で 15 章ぶん、39 か所ある。この書き方には弱点が二つある。

- **章題を変えると取り残される。** 2026-09-29 に章名からコマンド名を外したとき（改善案.md #61）、引用箇所を grep で探して手で直した。見落としても警告は出ない。
- **ページ番号がない。** 紙の本では、離れた章へ案内するときにページ番号があると探しやすい。

見出しにはすでにラベルを付けられ（`## インストール @install`）、`@pageref:install` でページ番号つきの参照になる（`at-directive-tier1-spec.md`）。章題（第 1 レベルの見出し）にも同じ書き方でラベルを付けられることは、2026-09-29 に試験用のプロジェクトで確かめた（章扉・目次・参照の表示に問題なし）。

ただし章ごとに手でラベルを書く方式には、次の難点がある。

- 全章の章題を書き換える必要があり、名前の付け方が書き手によって揺れる。
- 原稿から章題を直接読む処理にラベルが残る。`vs metrics` の章一覧に「はじめの一歩 @ch-intro」と出た（`metrics/chapter_parser.rb` の `H1_PATTERN`）。

そこで、**章のラベルはファイル名から暗黙に付ける**。著者は章題に何も書かず、参照する側だけを書く。

## 1. 著者向け仕様（案）

### 1.1 章ラベルは自動で付く

`catalog.yml` に載っている章には、ファイル名のスラッグから **`ch-<スラッグ>`** というラベルが自動で付く（§2.1）。章題には何も書かない。

### 1.2 参照の書き方と表示

参照は、見出しラベルと同じ二通りで書く。

```markdown
詳しくは @pageref:ch-build の章を参照してください。
コマンドの一覧は @ch-command-cheatsheet の章にまとめています。
```

| 書き方 | PDF | EPUB・Kindle |
| :--- | :--- | :--- |
| `@pageref:ch-build の章` | 「ビルド」（p.123）の章 | 「ビルド」の章（章へのリンク） |
| `@ch-build の章` | 「ビルド」の章 | 「ビルド」の章（章へのリンク） |

「の章」は著者が書く（§2.3）。**離れた章への案内は `@pageref:`、「次章」「前章」のように近い章は `@ch-` だけ**、を目安にする。

### 1.3 書き誤りの知らせ

未定義のラベルは、いまと同じく 🟡 で場所を添えて知らせ、ビルドは止めない。これに**綴りの近いラベルを 1 つ添える**（§2.7）。

```text
🟡     - contents/41-book-yml.md:317 - 未定義のラベルID: @pageref:ch-further-inspration
          もしかして: ch-further-inspiration
```

紙面には、いまと同じく `@pageref:ch-further-inspration` が文字のまま残る（知らせを見落としても、読み返せば気づける）。

## 2. 論点（決めること）

各項目の **推奨** は草案としての提案。

### 2.1 ラベルの名前

| 案 | 例 | `vs renumber` | `vs rename` でスラッグ変更 |
| :--- | :--- | :--- | :--- |
| **A. `ch-` ＋ スラッグ（推奨）** | `@ch-metrics` | 変わらない | 変わる（§2.2） |
| B. ファイル名そのまま | `@32-metrics` | **変わる** | 変わる |
| C. 著者が章題に書く | `# … @metrics` | 変わらない | 変わらない |

- A を推す。改番（`vs renumber`）はスラッグの変更よりずっと多く行われ、B はそのたびに参照が切れる。C は §0 のとおり手間と揺れが出る。
- `ch-` を付けるのは、見出しや図表の手書きラベル（`@install` など）と名前がぶつからないようにするため。24 章の例の `@install` と、93 章の暗黙のラベル `@ch-install` が共存できる。
- ファイル名の綴りがそのままラベルに出る。22 章は綴りの誤り（`extentions`）があったので、2026-09-29 に `22-extensions` へ改名した。

### 2.2 `vs rename` でスラッグを変えたとき

| 案 | 動き |
| :--- | :--- |
| **A. 本文の参照も書き換える（推奨）** | `ChapterRename::FOLLOWERS` に追随処理を 1 つ足し、`contents/*.md` の `@ch-<旧>`・`@pageref:ch-<旧>` を新しいスラッグへ書き換える（コードの中は対象外）。確認の画面に件数を出す |
| B. 案内だけ出す | 書き換えず、参照している箇所の一覧を 🟡 で出す |
| C. 何もしない | 次のビルドで「未定義のラベルID」が出る |

- A を推す。`chapter-rename-followers-guidelines.md` §1 の「章名を写して持つデータは追随処理を登録する」に当たる。本文の参照は著者が書いたものだが、機械的に一意に書き換えられるので、索引辞書の `main:` と同じ扱いにできる。
- `vs renumber` はスラッグを変えないので、この追随は動かない（§2.1 で A を選んだ場合）。

### 2.3 表示の形

| 案 | `@pageref:ch-build` の表示 |
| :--- | :--- |
| **A. 章題だけ（推奨）** | 「ビルド」（p.123） ＋ 著者が「の章」を書く |
| B. 「の章」まで自動 | 「ビルド」の章（p.123） |
| C. 章番号も付ける | 第 7 章「ビルド」（p.123） |

- A を推す。見出しラベルと同じ表示（`link_text` の `:sec` と同じ）なので、実装も説明も共通にできる。「「ビルド」の章を参照」「「ビルド」で説明します」のように文に合わせて書き分けられる。
- C は、付録（「付録 A」）と前書き・後書き（番号なし）で形が変わるので、必要になったら別の記法（例 `@chapref:`）で足す。本仕様の範囲外（§7）。

### 2.4 スラッグのない章（`11.md`）

**推奨**: 暗黙のラベルを付けない。`@ch-11` のように参照された場合は、未定義のラベルの知らせに「スラッグのない章には章ラベルが付きません（`vs rename 11 11-intro` で名前を付けられます）」と添える。番号でラベルを作ると、改番で切れるため（§2.1 の B と同じ問題）。

### 2.5 `ch-` の予約

**推奨**: `ch-` で始まるラベルを著者が手で付けたら 🔴 で知らせる（予約マクロ ID と同じ扱い。`reserved_macro_id?` の隣で判定する）。暗黙のラベルと衝突すると、どちらが参照されるかが並び順で決まり、気づけないため。

### 2.6 孤立ラベルの警告

2026-09-29 の試験では、参照されていない章ラベルに「孤立ラベル '…' は未参照です」の 🟡 が出た。暗黙のラベルは全章に付くので、**暗黙の章ラベルは孤立ラベルの検査から外す**（推奨）。

### 2.7 誤記の候補

**推奨**: 未定義のラベルに、綴りの近いラベルを 1 つ添える（`DidYouMean::SpellChecker`。章の指定の `ChapterTargetCheck#suggestion_for` と同じ作法）。章ラベルだけでなく、図表・見出しのラベルにも効かせる。候補を 1 件に絞る理由は `ChapterTargetCheck` のコメントのとおり。

### 2.8 章題に記法が入っている場合

97 章の章題は `挑戦することの<br>贈り物` で、HTML タグを含む。ラベルの表示文字列（「」の中）には、タグと Markdown の記法を取り除いた文字（`挑戦することの贈り物`）を使う（推奨）。目次の表示と同じ文字にそろえる。

## 3. 実装（案）

### 3.1 ラベルの収集

`CrossReferenceProcessor.collect_labels` で、章ファイルの最初の第 1 レベルの見出しを見つけたら、`type: :chap` の `Label` を足す。

- `id`: `ch-<スラッグ>`（スラッグは `TokenResolver::Entry#slug`。スラッグがなければ足さない。§2.4）
- `title`: 見出しの文字から、タグ・記法・手書きの見出しラベルを除いたもの（§2.8）
- 手書きの `@ch-…` は予約違反として 🔴（§2.5）

`pre_process.rb` の Phase 1（`catalog.yml` の全章からラベルを集める）がそのまま使えるので、単章ビルドでも他の章のラベルは解決される。

### 3.2 アンカー

章題の見出しの**内側**に `<span id="ch-<スラッグ>" class="vs-sec-anchor"></span>` を置く。見出しラベルと同じ規約（`try_heading_label` のコメント：見出しの前の行に置くと、改ページでアンカーだけが前のページに落ち、ページ番号が 1 ずれる）。章題は原稿から書き換えず、変換後の出力にだけ足す。

### 3.3 表示

`link_text` で `:chap` を `:sec` と同じ「「章題」」にする（§2.3 の A）。`@pageref:` のページ番号は、既存の CSS（`a.pageref::after` の `target-counter`）がそのまま付ける。EPUB・Kindle は `target-counter` を解さないので、章へのリンクだけになる（見出しラベルと同じ劣化）。

### 3.4 検査

- 孤立ラベルの検査から `:chap` を外す（§2.6）
- 未定義のラベルに候補を添える（§2.7）
- `vs lint` の記法ガード（`notation_guard.rb`）が `@ch-…` と `@pageref:ch-…` を記法として扱い、表記の指摘や `--fix` の対象にしないことを確かめる（既存の `@id` と同じ扱いのはず）

### 3.5 `vs rename` の追随

`ChapterRename::FOLLOWERS` に「本文の章参照」を足す（§2.2 の A）。`contents/*.md` を、コードブロックとインラインコードを除いて走査し、`@ch-<旧>` と `@pageref:ch-<旧>` を置き換える。置き換えた件数を確認の画面と結果に出す。

## 4. 原稿の移行

2026-09-29 時点で、章題を「」で引いている箇所は 15 章ぶん 39 か所（`contents/[0-9]*.md` を「「章題」の章」の形で数えた）。

| いまの書き方 | 移行後 |
| :--- | :--- |
| 詳しくは「ビルド」の章を参照してください | 詳しくは @pageref:ch-build の章を参照してください |
| 次章「新規プロジェクトの作成」で説明します | 次章 @ch-new で説明します |
| （「索引・用語集機能」の章を参照） | （@pageref:ch-index-glossary の章を参照） |
| 早見表の「解説章」の列（90・91 章） | **移行しない**（表の中の短い案内。ページ番号を足すと列が崩れる） |

- 同じ章を同じ段落で二度引くときは、二度目を `@ch-` だけにする。
- 移行したら `vs build` の「未定義のラベルID」が 0 件であることと、24 章に章ラベルの説明（§1）を足したことを確かめる。

## 5. テスト

- 章ラベルが `ch-<スラッグ>` で集まる／スラッグのない章には付かない
- 章題に `<br>` を含む章の表示文字列からタグが除かれる
- `@ch-x` と `@pageref:ch-x` が「「章題」」のリンクになり、`@pageref:` には `pageref` クラスが付く
- 手書きの `@ch-…` が 🔴 になる
- 暗黙の章ラベルが孤立ラベルとして知らされない
- 未定義のラベルに近い候補が 1 つ添えられる（章ラベル・図表ラベルの両方）
- `vs rename` でスラッグを変えると、本文の `@ch-旧`・`@pageref:ch-旧` が書き換わる（コードの中は残る）
- 章題の見出しの内側にアンカーが入り、改ページでページ番号がずれない（実ビルドで確かめる）

## 6. 実装前に確かめること

- 単章ビルド（`vs build 41`）で他の章を `@pageref:` したとき、ページ番号の欄がどう表示されるか（参照先が同じ PDF にないため）。空になるなら、単章ビルドでは `@pageref:` を `@` と同じ表示に落とすかを決める。
- 章扉を画像にするスタイル（`theme.style: image`）で、章題の中のアンカーが章扉の組版を崩さないか。2026-09-29 の試験（手書きラベル）では問題なかったが、暗黙のラベルでも確かめる。
- EPUB・Kindle で、別の章のファイルへのリンクが正しく飛ぶか。

## 7. スコープ外

- 章番号を添える参照（「第 7 章「ビルド」」）。付録・前書き・後書きで形が変わるので、要るなら別の記法として検討する（§2.3 の C）。
- 節（第 2 レベル以下の見出し）への暗黙のラベル。節は数が多く、見出しの文字の変更も多いので、いまの手書きの見出しラベルのままとする。
- 早見表の「解説章」の列の参照化（§4）。
