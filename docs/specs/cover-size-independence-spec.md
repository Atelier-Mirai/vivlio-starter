## 1. 範囲と前提

### 1.1 今の作り

- `CoverCommands::SIZES` が、A4・B5・A5 の 3 つについて、350dpi の画素数と mm を持つ。画像の表紙も SVG の表紙も、寸法をここから引く（`SIZES.fetch(page_size)`）。
- 判型は、`page.use` の名前の最初の 2 字で決める（`detect_page_size`）。`a4`・`a5` のほかは、何であっても `:b5` になる。`a6_standard` は `a6` → B5、`shinsho_standard` は `sh` → B5 として、誤った寸法の表紙が、エラーも警告も無く組まれる。
- 著者の画像は、判型の画素数へ `-resize WxH!` で引き伸ばす（比が違っても合わせる）。
- 同梱のひな形（`covers/bundled/frontcover.svg`・`backcover.svg`）は、viewBox が `0 0 595 842`（A 列の比）の 1 枚である。A 列と B 列は比がほぼ同じ（1.414 と 1.412）なので、3 つの判型で同じひな形が使えている。地の矩形は `-60` から外へ描いてあり、入稿用は viewBox を塗り足しの分だけ広げて見せる（`expand_svg_viewbox_for_bleed`）。上下の金の帯は、viewBox の上端と下端に合わせて置いてある。
- 下敷きの画像は、`covers/templates/` に A4・A5・B5 の表と裏の 6 枚がある（`scripts/make_cover_templates.rb` が作る）。

### 1.2 足される判型

| 判型 | 寸法（mm） | 高さ ÷ 幅 | 足す段階 |
| :--- | :--- | :--- | :--- |
| A4・A5・B5（今ある） | 210×297・148×210・182×257 | 1.41 | — |
| 文庫（A6）・B6 | 105×148・128×182 | 1.41・1.42 | S8-3 |
| 四六 | 127×188 | 1.48 | S8-3 |
| 新書 | 103×182 | 1.77 | S8-3 |
| B5 の横・A4 の横 | 257×182・297×210 | 0.71 | S9-1 |
| 正方形（210mm） | 210×210 | 1.00 | S9-1 |

### 1.3 範囲の外

- くるみ表紙の組み方（`cover-spread-spec.md`）。この仕様の寸法の窓口（§2.1）を使う。
- 同梱のひな形の絵柄を、判型ごとに作り分けること（新書のための別のひな形など）。§4 の割り振りで足りないと分かったら、そのときに考える。
- 表紙のテーマの追加。

## 2. 寸法の出どころを 1 つにする

### 2.1 窓口

表紙の寸法を返す窓口を 1 つ作る（名前の案 `CoverCommands.trim_size`。内部の名前なので Opus が決める）。返すのは、仕上がりの幅と高さ（mm）・350dpi の画素数・ファイル名に使う判型の名前の三つである。

- mm は、本文の `@page` の大きさと同じ出どころ（`Common.resolve_page_size` に、判型のプリセットを解いた後の `page` の設定を渡したもの）から引く。**本文と表紙が別の表を持たない**ことが、この仕様の中心である。
- 画素数は `(mm ÷ 25.4 × 350).round`。今の `SIZES` の値（A4 で 2894×4093 など）と同じになることを、テストで確かめる（1px でも違うと、今の本の表紙の出力が変わる）。違う判型があれば、丸め方を今の値に合わせる。
- `Common::PAGE_SIZES` に S8-3 で 4 つ、S9-1 で 3 つ足す（`novel-vertical-spec.md` §4.1・`picture-book-spec.md` §4.1）。表紙の側に足すものは無い。
- `SIZES`・`detect_page_size`・`book_page_size` を読んでいる箇所（`cover.rb` の 8 か所ほどと `svg_cover.rb` の 2 か所）を、全部この窓口に替える。くるみ表紙（S8b）もこの窓口を使う。

### 2.2 ファイル名の判型の部分

生成物の名前（`frontcover_light_b5_cmyk.pdf` など）の判型の部分は、次で決める。

| 本の設定 | 名前 | 例 |
| :--- | :--- | :--- |
| プリセットの `size:` が `PAGE_SIZES` にある | `size:` を小文字にしたもの（`-` は取る） | `a6`・`b6`・`shinsho`・`shiroku`・`b5l`・`a4l`・`sq210` |
| `page.width`・`page.height` を直接書いて、プリセットの寸法と違う | `<幅>x<高さ>`（mm を四捨五入した整数） | `120x180` |

- 今の 3 つの判型の名前（`a4`・`b5`・`a5`）は変わらない（今の本の出力のファイル名が変わらない）。`JIS-B5` は `b5` にする（今と同じ）。
- 判型の名前（`shinsho`・`b5l` など）は、S8-3・S9-1 で `PAGE_SIZES` に足すキーの名前で決まる。著者から見える名前（生成物のファイル名に出る）なので、了承待ちの一覧に載せる（`v2-migration-plan.md` §4.1）。

### 2.3 寸法が引けないとき

`page.use` のプリセットが無い・`size:` が `PAGE_SIZES` に無く `width`・`height` も無いときは、表紙を作らずに 🔴 で止める。今の「黙って B5 にする」は無くす。この状態は、本文のビルドでも設定の検査が先に止めるはずなので、表紙の側の文面は短くてよい（「表紙の寸法が決まりません。`page.use` を確かめてください」と、使える名前）。

## 3. 著者の画像と著者の SVG

### 3.1 著者の画像（`covers/<side>cover_<テーマ>.png` など）

| 画像の比と判型の比の差 | 扱い |
| :--- | :--- |
| 1% 以下 | 今と同じ（判型の画素数へ合わせる）。A 列の絵を B 列の本に使う今の使い方は、この中に入る |
| 1% より大きい | **引き伸ばさない。** 判型を覆うように縮めて、中央で切る。🟡 で、切られる向きと量、判型に合う画素数を示す |

```
🟡 covers/frontcover_master.png の縦横比が、判型（新書・103 × 182 mm）と違います
        左右を 8mm ずつ切り落として使いました
        → 1419 × 2508 px の画像に差し替えると、切らずに使えます（新書を 350dpi で刷る寸法）
```

- 差の測り方は「（画像の高さ ÷ 幅）÷（判型の高さ ÷ 幅）− 1」の絶対値。
- 切る位置は中央だけとする（寄せる向きを選ぶキーは置かない。切られて困る絵は、判型に合わせて作り直すのが正しい手で、🟡 がその寸法を示す）。
- 入稿用の塗り足し（`cover_bleed`・`*_bleed` の画像）の決まりは変えない。`*_bleed` の画像の比は「仕上がり ＋ 塗り足し」の比と比べる。
- 解像度の警告（`warn_low_print_resolution`）は、窓口の寸法で今のとおり出す。

### 3.2 著者の SVG（`covers/<side>cover_<テーマ>.svg`）

- vs は、著者の SVG の viewBox と中身を書き換えない（今と同じく、文字の置き換えだけを当てる）。
- viewBox の比が判型と違うとき、PDF と画像への変換は、SVG の `preserveAspectRatio` に従わせる（書いていなければ既定の `xMidYMid meet`＝切らずに収め、余りは地が見える）。今のコードが幅と高さを両方渡して引き伸ばしていないかを、実装の最初に確かめる（引き伸ばしていたら、渡し方を直す）。
- 差が 1% より大きいときは 🟡 で、判型の比（viewBox の例つき）を示す。

### 3.3 電子書籍の表紙（`cover_<テーマ>.jpg`）

- 判型の比のまま、長い辺を 2,560px にする（今の縦長の本では、高さ 2,560px で今と同じ）。横長の判型は幅が 2,560px になる。
- `write_ebook_cover` の「知らない判型は B5 の比にする」（`SIZES.fetch(page_size, SIZES[:b5])`）は、窓口に替えて無くす。

## 4. 同梱の SVG のひな形

### 4.1 考え方

ひな形は、幅 595 の縦長の面に、上の飾り・題名と副題の欄・著者名・下の飾りを置いた 1 枚である。題名と副題の欄の幅（`TEXT_FIELD_WIDTH` の 495）と字の大きさは、幅 595 を前提に決めてあり、字が欄に収まるかの計算（`fit_scale`）もこの数に依る。

そこで、**幅は 595 のまま変えず、高さだけを判型の比に合わせる**。viewBox の高さを「595 × 判型の高さ ÷ 判型の幅」にし、今の 842 との差（Δ）を、ひな形の中の要素に割り振る。字の大きさ・欄の幅・収まりの計算は、どの判型でも変わらない。

| 判型 | viewBox の高さ | Δ |
| :--- | :--- | :--- |
| A4・A5・A6 | 842 | 0（今と同じ） |
| B5・B6 | 840〜846 | ±4 以内 |
| 四六 | 881 | ＋39 |
| 新書 | 1051 | ＋209 |

### 4.2 ひな形に付ける印

ひな形の SVG の要素（か、要素をまとめた `g`）に、属性で印を付ける。印の無い要素は動かさない（上端からの位置が保たれる）。

| 印 | 意味 | 当てるもの（見込み） |
| :--- | :--- | :--- |
| `data-vs-anchor="bottom"` | Δ だけ下へ動かす（下端からの位置を保つ） | 下の金の帯・下の飾り・著者名の塊 |
| `data-vs-anchor="middle"` | Δ の半分だけ下へ動かす | 題名と副題の塊（上の飾りと下の塊の間で、釣り合いを保つ） |
| `data-vs-stretch="y"` | 高さを Δ だけ伸ばす | 地の矩形・地のグラデーション・面の全体に掛かる枠 |

- 動かし方は、要素に `transform="translate(0, Δ)"` を足す（既に `transform` があれば前に足す）。伸ばし方は、`rect` の `height` に Δ を足す。処理は `render_svg` の中の 1 段で、パレットと文字の置き換えの前に行う。
- Δ が 0 の判型（A 列）では、何も書き換えない。**今の 3 つの判型の出力が変わらないこと**が、この作りの条件である（B5 は Δ が −2 ほどになるので、|Δ| が viewBox の高さの 1% 以下なら 0 として扱い、今と同じく比の小さな違いは変換に任せる）。
- 印は「デザイナーが Inkscape で編集できる」というひな形の決まりを壊さない（属性は編集しても残る）。ひな形の冒頭の説明に、印の意味を 3 行で書き足す。
- 裏表紙のひな形（`backcover.svg`）にも同じ印を付ける。

### 4.3 入稿用の塗り足し

今の `expand_svg_viewbox_for_bleed` は、viewBox を塗り足しの分だけ広げる。高さを変えた後の viewBox に対して、今のとおり働く。地の矩形が外へ 60 の余裕を持って描いてあることは変わらない（伸ばすのは下の端だけなので、上の余裕はそのまま、下の余裕も Δ と一緒に動く）。

### 4.4 使える判型の範囲

| 判型の比（高さ ÷ 幅） | 同梱のひな形 |
| :--- | :--- |
| 1.35 以上（A 列・B 列・四六・新書） | 使える |
| 1.35 未満（正方形・横長） | 使えない。`book.cover` が `light`・`dark` なら 🔴 |

```
🔴 同梱の表紙（light）は、横長・正方形の判型（B5 の横）では作れません
        表紙の画像を置いて、config/book.yml の book.cover を master にしてください
        covers/frontcover_master.png（3541 × 2508 px）
        下敷きは covers/templates/frontcover_b5l.png にあります
```

- 理由: 横長の面に縦長の構図を収めると、欄の幅も字の大きさも作り直しになり、ひな形を別に 1 枚作るのと同じ手間になる。絵本の表紙は絵であり、同梱の文字だけの表紙を使う場面が少ない。
- 絵本の雛形（`scaffolds/picture_book/`）は、スクリプトで作った表紙の画像を `covers/` に持ち、`book.cover` を自分の画像の名前にする（`picture-book-spec.md` §5.4・§8）。`vs new --type picture_book` の直後に組める。
- 縦長だが比が大きい判型（新書）では、題名の塊と下の塊の間が広く空く。S8-3 の確かめで紙面を見て、空きが目立つなら、`middle` の割り振りを「Δ の半分」から変える（Opus が決めて記録する。軸: 題名の塊が、面の上から 3 分の 1 から 2 分の 1 の間に入ること）。

### 4.5 確かめ（S8-3 の最初に行う）

ひな形の全部の要素を読んで、§4.2 の表の「当てるもの」を確定する。確かめる点は三つ。

1. 上端・下端に合わせて置いてある要素を、全部挙げられるか（金の帯のほかに、角の飾りや枠が無いか）。
2. 縦の位置が「面の高さに対する割合」で決まっている要素が無いか（グラデーションの `y2`・クリップの矩形など。あれば `data-vs-stretch` の対象にするか、値を書き換える）。
3. 文庫（A6）・四六・新書の 3 つで、表と裏を組み、目で見る（題名が 1 行の本と、2 行で副題つきの本）。

印で割り振れない要素が 3 つを超えるようなら、割り振りをやめて、**新書と四六では同梱のひな形を「上下に地を足して、A 列の構図を中央に置く」形に落とす**（viewBox を上下に広げるだけ。上下の金の帯は面の端から離れて、構図の一部として見える）。見た目は劣るが、崩れない。どちらを取ったかを、実装記録に書く。

## 5. 下敷きの画像（`covers/templates/`）

- `scripts/make_cover_templates.rb` を、`Common::PAGE_SIZES`（か `config/page_presets.yml` の `size:` の一覧）を回して作る形に直す。判型を足すと、下敷きも増える。名前は `<side>cover_<判型の名前>.png`（§2.2 の名前）。
- 種類ごとの雛形に入れるのは、その種類の本が選べる判型のぶんだけにする（技術書は A4・A5・B5、小説は文庫・B6・新書・四六と A5・B5、絵本は B5・A4 と横長・正方形）。全部を全部の雛形に入れると、gem の大きさが増える（`v2-migration-plan.md` §2.4 の 11）。分け方の表は、`copy_to_scaffold.rb` の種類ごとの複製（S8-7）で持つ。
- `vs upgrade` が `covers/templates/` を更新する決まり（雛形の管理の対象）は変えない。
- 著者への案内の文面（`master の画像が足りないとき`）は、その本の判型の下敷きの名前を示す（今は「判型ごとに covers/templates/ にある」とだけ書いている）。

## 6. 段階ごとの完了の条件と確かめ方

S8-3（判型のプリセットと `BookProfile`）の中で、次の順に行う。1 と 2 は判型を足す前に済ませ、今の本の出力が変わらないことを先に確かめる。

| 順 | 作るもの | 確かめ |
| :--- | :--- | :--- |
| 1 寸法の窓口 | §2 の窓口。`SIZES`・`detect_page_size` を無くし、読んでいた箇所を全部替える。ファイル名の判型の部分。寸法が引けないときの 🔴 | **本書の表紙が前後で同じ。** `vs cover` を前後のコードで走らせ、表と裏の閲覧用 PDF・入稿用 PDF・電子書籍の JPEG を比べる（PDF は全ページの画素、JPEG は画素。ファイル名も同じ）。A4・B5・A5 の 3 つで行う（`light` と、著者の画像の `guide`）。窓口の画素数が、今の `SIZES` の 3 つの値と同じであるテスト |
| 2 画像と SVG の比 | §3.1 の切り方と 🟡・§3.2 の SVG の渡し方と 🟡・§3.3 | 比の合う画像（今の `guide` の表紙）で、出力が 1 と同じ。比の違う材料の画像（正方形の絵を B5 の本に）で、引き伸ばされずに中央で切られ、🟡 が出る。文面のテスト |
