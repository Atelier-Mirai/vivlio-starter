# 索引の主要参照 — 節への降ろし込みと入力の簡素化

> 作成日: 2026-08-04
> ステータス: **実装待ち**
> 対象: 主要参照が章扉を指してしまう問題（粒度）と、1 語ずつ子行を書く手間（入力）
> 前提: `index-main-reference-spec.md`（`docs/archives/`）が実装済みであること。本仕様はその §1.3「節指定は対象外・RC 後に検討」を引き取る
> 決定事項:
> - **章題（h1）は主要参照にしない。** 章の名前であって、その語を説明している箇所ではない
> - 自動で節へ降ろす。指定が無くても過半（実測 25/44 件）は正しい位置に落ちる
> - 手動の節指定は**見出しの文言**で書く。節番号（`4-1`）は組版時に振られるもので原稿に無い
> - 壊れた指定は**黙って無視しない**。値も勝手に消さない——推敲の途中で組版を止めない
> - フラグ欄 `[igm33]` を生成側の既定にする。子行 `- 主要参照:` も引き続き受ける

## 0. 背景

### 0.1 章扉を指してしまう（粒度）

`main: 21-markdown-tutorial` と指定すると、その章での**初出**が主要参照になる。
ところが 21 章の h1 は「Markdown 執筆チュートリアル」で、**章題そのものが初出**になる。
結果、索引は章扉のページ（35）を太字にする。著者が指したいのは
「## Markdown とは」がある 36 ページである。

**章題は「章の名前」であって、その語を腰を据えて説明している箇所ではない。**

### 0.2 1 語ずつ子行を書く手間（入力）

現在の記法は用語の下に 1 行足す形で、指定のたびに行が増える。

```markdown
- [ig] **用語集** (ようごしゅう) - スコア: 353.0
  - 主要参照: 33
```

110 語の索引で全語に指定すると 110 行増え、レビューファイルの一覧性が落ちる。

### 0.3 推測が弱い（実測 45%）

著者が手で決めた 44 語を正解として現在の推測（見出しヒット数）を測ると **45%**。
しかも **44 語中 14 語には候補を出せない**（見出しに現れない語）。

## 1. 実測

すべて本書（全 26 章・索引語 110 語・`main:` 指定済み 44 語）での実測。

### 1.1 推測アルゴリズムの比較

| 方式 | 一致率 | 候補を出せない語 |
|---|---|---|
| 見出しヒット数（現行） | 45% | 14 語 |
| 出現回数 | 61% | 0 語 |
| 出現密度 | 56% | 0 語 |
| h1 優先＋見出し数 | 43% | 14 語 |
| **見出し（h1×3 h2×2 h3×1）＋出現回数** | **65%** | **0 語** |

定義パターンの加点は精度に寄与しない（重み 0 / 3 / 8 のいずれでも 65%）。
**落とす**——効かない要素を残すと、後から触る人が「効くはず」と誤解する。

### 1.2 節へ降ろせるか

著者が指定した 44 件について、その章でのその語の現れ方:

| | 件数 | 扱い |
|---|---|---|
| 節見出し（h2〜h6）に含まれる | **25 件** | 節へ降ろせる |
| 章題（h1）にだけ含まれる | 1 件 | 降ろし先が無く本文初出 |
| 見出しに無い（本文のみ） | 18 件 | 現状どおり本文初出 |

### 1.3 見出しの重複

| | 件数 |
|---|---|
| 見出し総数（h2〜h6） | 655（h2=167 / h3=429 / h4=56 / h5=3） |
| **同一章内**で文言が重複 | **7 件（1%）** |
| 章をまたいで重複 | 20 件 |

`main:` は必ず章を指定するので、**章をまたぐ重複は問題にならない**。
効くのは章内の 7 件だけで、そこだけ階層指定で絞れればよい。

### 1.4 候補を出す対象

| | 語数 |
|---|---|
| 索引語 | 110 |
| 2 章以上に出る | 94 |
| 1 章にしか出ない | 16（うちその章で複数回出る **15**） |
| その章で 1 回だけ出る | **1** |

**「1 章にしか出ない」と「太字にする意味がない」は別**である。1 章でも複数回出れば
索引に複数のページ番号が並び、初出だけが太字になって意味を持つ（実測 15 件）。
意味がないのは「ページ番号が 1 つしかない語」で、実測 **1 語**。

## 2. 要件

### R1: 章題を主要参照にしない（自動で節へ降ろす）

指定章の中で、主要参照にする出現を次の順で決める。

1. **節見出し（h2〜h6）にその語が現れる最初の箇所**
2. 無ければ **本文の初出**（章題での出現は数えない）
3. 本文にも無ければ（章題にしか無い）章題での出現

`IndexMatchScanner` は現在「章内の 1 回目」を機械的に主要参照にしている。
出現の**何番目**を主要参照にするかを、章ファイルを読んだ時点で先に決める。

```ruby
# 章内での出現順（1 始まり）のうち、どれを主要参照にするか
def main_occurrence_index(term, pattern, lines)
```

### R2: 節指定の記法

```markdown
- 主要参照: 21#Markdown とは
- 主要参照: 21#主な用途                    # 語を含まない見出しでもよい
- 主要参照: 23#章の削除（vs delete）#基本的な使い方   # 曖昧なとき親を添える
```

- **文言で書く。** 節番号（`4-1`）は組版時に振られるもので原稿に無い
- **レベルを問わない**（h2〜h6）。実測で h4 は 56 個、h5 は 3 個ある
- **語を含まない見出しも指せる。** 自動推測は語を含む見出しを探すが、
  手動指定は文言の一致だけを見る
- 階層は上位から `#` でつなぐ。**中間は省略できる**（祖先のいずれかに一致すればよい）
- 章トークンは従来どおり番号・範囲・章名のいずれでもよい（`TokenResolver`）

比較は正規化してから行う。見出しには強調 `**…**`・インラインコード `` `…` ``・
ルビ `{漢字|よみ}`・索引タグが混ざる。

### R3: 曖昧なときは候補を並べて促す

```
🟡 「vs delete」の主要参照 23#基本的な使い方 は 4 箇所あります
        親の見出しを添えて絞ってください:
          23#章ファイルの作成（vs create）#基本的な使い方
          23#章の削除（vs delete）#基本的な使い方
          …
```

**最初の 1 件を黙って採らない。** 著者が意図した箇所と違えば、索引が静かに
間違った場所を指す。ただし組版は止めず、最初の 1 件で先へ進む。

### R4: 見出しが見つからないときは注意を促す

見出しの文言は推敲で変わる（「主な用途」→「さまざまな用途」）し、節ごと消えることもある。
**壊れた指定を黙って無視しない。**

```
🟡 「Markdown」の主要参照が指す見出しが見つかりません: 21#主な用途
        21-markdown-tutorial の見出し: Markdown とは / Markdown の概要 /
        開発者と歴史 / Markdown の特徴 / さまざまな用途 …
        近いもの: さまざまな用途
        見出しを書き換えたなら主要参照も直してください。章だけの指定（21）に
        戻すと、その章で最初に説明している節を自動で選びます
```

- **値は保存する。** 勝手に消すと、推敲の途中で著者の判断が失われる
  （章名が実在しないときと同じ立場・`index-main-reference-spec.md` R1）
- **章単位の指定として扱って先へ進む**（R1 の自動選択が働く）。組版は止めない
- 「近いもの」は編集距離と部分一致で 1〜2 件だけ挙げる。候補を並べ立てない

### R5: 推測アルゴリズム

```
スコア = h1 に含む数 × 3 + h2 に含む数 × 2 + h3 に含む数 × 1 + 章内の出現回数
```

**h4 以下は重みを持たない**（出現回数として 1 回ぶん数えるだけ）。§1.1 の実測は
h1〜h3 のみを見出しとして数えており、そのとおりに実装する。細かい手順の見出しまで
重み付けすると、手順の並ぶ章がどの語でも勝ってしまう。

最大の章を選ぶ。同点なら章番号の若い方（実行ごとに順位が揺れると差分が読めない）。

- 実測 65%（現行 45%）、**全語に候補を出せる**
- 定義パターンの加点は**しない**（§1.1 のとおり効果がない）
- `DEFINITION_PATTERNS` への依存が消え、`MainReferenceSuggester` が単純になる

### R6: フラグ欄での指定 `[igm33]`

```markdown
- [igm33] **用語集** (ようごしゅう) - スコア: 353.0
- [igm21,22] **Markdown** (まーくだうん) - スコア: 228.3
```

- 生成側の既定をフラグ欄にする（1 行で完結し、行数が増えない）
- 子行 `- 主要参照:` も**引き続き受ける**。章名や節指定など長い値はそちらのほうが読める
- 両方あれば**子行を優先**（後から書き足した細かい指定が勝つ）

**前提: フラグの綴りを 1 箇所へ集約する。** 現在フラグを読む正規表現が
**9 箇所**に散っており（`parse_index_approved` `parse_unreject` `parse_yomi_changes` …）、
`m33` を足すと `(?:i|ig|gi|x)` が軒並みマッチしなくなる。

```ruby
# レビューファイルの用語行。フラグの綴りはここが唯一の定義元。
TermLine = Data.define(:flags, :main, :term, :yomi, :label, :trailer)
#   [igm33]     → flags: 'ig', main: ['33']
#   [igm21,22]  → flags: 'ig', main: %w[21 22]
#   [-i]        → flags: '-i', main: nil
```

既存 9 個の正規表現はこれに置き換わって消える。

### R7: 候補を出す対象

**索引語すべて**。ただし**出現が 1 回だけの語は除く**（実測 1 語）。

索引項目にページ番号が 1 つしか出ない語を太字にしても、読者に伝わる情報が増えない。

## 3. テスト

| 対象 | 検証 |
|---|---|
| `IndexMatchScanner` | 章題の出現を主要参照にしない／節見出しがあればそこ／無ければ本文初出／章題にしか無ければ章題 |
| 節指定の解決 | 文言一致／語を含まない見出し／h4・h5／階層指定／中間の省略／正規化（強調・コード・ルビ） |
| 曖昧・不在 | 複数一致で候補を並べる／不在で近い見出しを示す／どちらも組版を止めない／値を消さない |
| `MainReferenceSuggester` | 重み付けの順位／同点は章番号順／全語に候補が出る |
| `TermLine` | `[igm33]` `[igm21,22]` `[-i]` `[ ]` の解釈／既存 9 パーサの回帰／子行が優先 |

## 4. 実装フェーズ

| Phase | 内容 | 単独で価値があるか |
|---|---|---|
| 1 | R1（章題を外して節へ降ろす） | ○ 指定済み 44 語の太字位置がすぐ改善する |
| 2 | R2 + R3 + R4（節指定と、曖昧・不在の案内） | ○ 自動で外したときに直せる |
| 3 | R5（推測 65%）＋ R7（対象を全語へ） | ○ 予め入る |
| 4 | R6（`[igm33]` とフラグ集約） | ○ 入力と一覧性 |

Phase 4 は触る範囲が広い（9 パーサ）ので最後に単独で入れる。ここで詰まっても
Phase 1〜3 の価値は毀損しない。
