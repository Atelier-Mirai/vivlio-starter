## 0. 背景

章リードは `.chapter-lead { font-size: larger }` で、本文の基準の大きさ（判型の `base_font_size`）の 1.2 倍に決まっている。`image` の章扉では `theme.frontispiece.lead_chars` が 1 行の字数を決める（幅 = 字数 × 1 字の大きさ）が、文字の大きさそのものは選べない。`simple` の章と付録はリードが版面の幅いっぱいで、こちらも大きさは選べない。

spiral-ruby はリードが 460〜650 字と長い。`lead_chars: 28` でも、第7部の元の文（653 字）は章扉に収まらず、最後の 1 文が次のページへ送られた。2 行縮めて（618 字）収めた今も、下の数行が右下の飾りの絵に重なる。どちらも、組み上がった PDF を見て初めて分かった。

リードの短い本は今の 1.2 倍がちょうどよく、長い本は小さくしたい。本ごとに答えが違う体裁の判断なので、設定で選べるようにする。

## 1. 実測 — `image` の章扉では、倍率を下げても行数は変わらず、高さだけが縮む（2026-10-28）

spiral-ruby の 33 章（第7部・618 字・A4・`base_font_size` 10.5pt・`lead_chars: 28`）を、スクラッチへ複製して倍率だけ変えて組んだ。幅と文字の大きさは `custom.css` で上書きした（幅 = 字数 × 10.5pt × 倍率）。

| 倍率 | 1 行の字数 | 1 行の幅 | 行数 | リードの上端 | リードの下端（ページの高さ比） | 右下の飾りの絵 |
| :--- | ---: | ---: | ---: | ---: | :--- | :--- |
| 1.2（今） | 28 | 124.5mm | 24 | 264.6pt | 775.2pt（0.92） | 下の 5 行ほどが重なる |
| 1.1 | 28 | 114.1mm | 24 | 264.5pt | 732.6pt（0.87） | 下の数行の右端が花びらに触れる |
| 1.0 | 28 | 103.7mm | 24 | 264.3pt | 689.8pt（0.82） | 重ならない |
| **1.1** | **30** | 122.2mm | **21** | — | 673.7pt（**0.80**） | 重ならない |

最後の行は、倍率を 1.1 にしたうえで、幅を今（124.5mm）とほぼ同じに保つよう 1 行の字数を 28 → 30 に増やしたもの。

### 1.1 行数が変わらない理由

`lead_chars` が決めているのは**幅ではなく 1 行の字数**だからである。

- `image` の章扉のリードの幅は「`lead_chars` × 1 字の大きさ」で決まる。文字を 1.1 倍にすると、幅も同じ比で狭くなる（124.5mm → 114.1mm）
- 1 行は 28 字のままなので、618 字のリードは倍率に依らず 24 行に折り返される
- 変わるのは行送り（文字の大きさ × 1.7）だけで、そのぶん高さが倍率に比例して縮む
- 章扉の側から見れば、同じ高さに入る行数が増える。1.2 倍 → 1.0 倍なら、10 行分の高さに 12 行入る（1.1 倍なら約 10.9 行）。「リードの行数は変わらず、章扉に入る行数が増える」の両方がそろうので、§4 の「収まる倍率」を比で計算できる

幅が版面いっぱいに決まっている `simple` の章では事情が違う。文字を小さくすると 1 行に入る字数が増えるので、行数は**減る**。

### 1.2 分かったこと

- **リードの上端は動かない。** 章番号・章題・その下の余白は倍率と無関係なので、リードの始まる高さは同じ。行数が変わらないことと合わせて、§4 で「収まる倍率」を計算できる
- 幅も狭くなるので、右下の飾りから横にも離れる。1.0 倍では本文と同じ大きさになるが、太さ（`font-weight: 500`）と字下げでリードと分かる
- **章扉に入る字数は、字数を据え置くと倍率に反比例し、幅を据え置くと倍率の 2 乗に反比例する。** 1.2 → 1.1 なら、`lead_chars` 据え置きで約 9%（1.2 ÷ 1.1）、幅を保って `lead_chars` を増やすと約 19%（(1.2 ÷ 1.1)²）多く入る。33 章は 1.1 倍・30 字で 24 行が 21 行になり、1.0 倍・28 字より下端が上がった
- したがって長いリードには、**倍率を少し下げて字数を増やす**組み合わせがいちばん効く。文字を本文より一回り大きく保ったまま（1.1 倍）、章扉の余裕は 1.0 倍より大きくなる

## 2. 設定 — `theme.lead_size` と `theme.frontispiece.lead_size`

```yaml
theme:
  style: image
  lead_size: 1.2       # 章リード文の文字の大きさ（本文に対する倍率・1.0〜2.0）
                       # simple の章・付録にも効く。image の章扉は frontispiece.lead_size で変えられる

  frontispiece:
    heading_chars:  10   # 章題を 1 行に何文字入れるか（全角換算）
    lead_chars:     24   # 章リード文を 1 行に何文字入れるか（全角換算）
    lead_size:           # 章扉のリード文の文字の大きさ（空欄なら theme.lead_size に従う）
```

spiral-ruby（長いリードの image の本）なら、章扉だけを小さくして、字数を増やす。

```yaml
  frontispiece:
    lead_chars:     30
    lead_size:     1.1
```

### 2.1 判断軸に当てる（`config-key-criteria-guidelines.md`）

| 軸 | 当てはまるか |
| :--- | :--- |
| 手法パラメータか | いいえ。変えても比べる先の基準は動かない |
| 重複した入口か | いいえ。`lead_chars` は 1 行の字数、`base_font_size` は本文すべて、`heading_offset` は位置。リードの大きさだけを変える窓口は無い。2 つの `lead_size` は効く範囲が違い（本全体の既定と、`image` の章扉の上書き）、同じ目的の二重の窓口ではない（§2.2） |
| CLI が一次か | いいえ。本の体裁で、毎回同じ値を使う |
| 選ぶ理由のない選択肢か | いいえ。spiral-ruby（リード 460〜650 字）は下げたい、本書（100〜200 字）は今のままがよい |
| 正しい警告を黙らせるだけか | **一部は該当する。** はみ出しを「文字を小さくして隠す」のは、長すぎるリードを直す代わりにならない。そこで下限を本文と同じ 1.0 に置く（§3）。§4 の警告も、リードを縮める案を先に出す |

残す理由（§3 の「編集判断」）: リードの長さの方針は本ごとに違い、それに合わせた文字の大きさは著者が決める体裁である。

### 2.2 効く範囲と、キーを置く場所

| 対象 | 使う倍率 | 備考 |
| :--- | :--- | :--- |
| `image` の章扉（PDF・前書きの扉も含む） | `theme.frontispiece.lead_size` → 無ければ `theme.lead_size` → 無ければ 1.2 | 幅も倍率に合わせて動く（§1.1） |
| `image` の章の、扉絵の次に流れるリード（EPUB・Kindle） | 同上 | 幅は画面いっぱい。扉絵には焼き込まない（§2.2.1） |
| `simple` の章・付録（PDF・EPUB・Kindle） | `theme.lead_size` → 無ければ 1.2 | 幅は版面（画面）いっぱいのまま。文字が小さくなると行数が減る。`image` の本の付録もこちら |

2 つに分けるのは、`image` の章扉と、`simple` の章・付録とで、リードの置かれ方が違うからである。

- **`image` の章扉**は、1 行の字数で幅が決まり、扉絵の飾りもある 1 ページに収める紙面。長いリードの本は、ここだけ小さくしたい
- **`simple` の章・付録**は、幅が版面いっぱいで、リードの後に本文が続く。章扉ほど窮屈ではなく、今の 1.2 倍のままでよいことが多い。`image` の本でも、付録はいつも `simple` で組まれる

キーを置く場所は、効く範囲に合わせる。

- `theme.lead_size` は `theme` の直下。`simple` の本の著者が `frontispiece` の中を探さずに済む
- `theme.frontispiece.lead_size` は `lead_chars` の隣。`image` の章扉で、字数と大きさを並べて合わせられる（1.1 倍・30 字のように、一緒に動かすことが多い。§1）。`theme.frontispiece` は「`style: image` のときのみ有効」な設定の集まり（`41-book-yml.md`）で、その約束も崩れない
- 上書きの形は `theme.color` と `theme.preface_color`・`theme.appendix_color`（改善案 #73）にそろえる。**`theme.frontispiece.lead_size` の既定は空（nil）**にする。既定値を持たせると、行を消しても空欄にしても既定値が入り、`theme.lead_size` に従わなくなる（`config_keys.rb` の `appendix_color` のコメントと同じ理由）

#### 2.2.1 EPUB の章扉

EPUB（クリーン・Kindle）の章扉は、横長の扉絵に章番号と章題だけを焼き込んだ 1 枚の画像にする。節絵の帯と同じ作りである。リードは焼き込まず、扉絵の次に本文の文字として流す。

- **扉絵**は `theme.frontispiece.image` の横長版（節絵と同じ 2.39:1。無ければ作る）。番号と章題の塊は、左上・右下の飾りの間（中央 60%）の上下中央に置く。1 行の字数は `heading_chars` で、PDF と同じ
- **リード**は画面いっぱいの幅で流す（`body.vs-epub .chapter-lead { inline-size: auto }`。今までと同じ）。大きさは `lead_size` に従う。§6.2 の規則を EPUB にも出す。既定の 1.2 倍は `chapter-common.css` の `larger` で、Kindle でも効く
- **節題の大きさ**は、章題に対する比を PDF にそろえる。帯の章題は、左右の飾りを避けるぶん PDF より小さい（画像の幅の 6%）。節題を book.yml の字数（14 字）のまま組むと、章題の 0.94 倍で、ほぼ同じ大きさに見えた。PDF（A4）では、節題は章題の 0.73 倍である（48Q と 35Q）。そこで EPUB の節題は、PDF の比になる字数へ置き換える（A4・章題 10 字・節題 14 字なら 18 字。`EpubBuilder#epub_ornament_chars`）。比は判型から毎回計算する。代わりに、EPUB の長い節題は、行の切れ目が PDF と変わる
- リードの中の数式・索引のアンカーは、本文のものとしてそのまま扱われる。焼き込むために alt の文字を取り出す処理と、その警告は無くなった

**経緯（2026-10-28・spiral-ruby の第7部を Kindle Previewer で確認）。** 合成画像の中の字は、端末の文字サイズの設定に従わず、画面に合わせて画像ごと縮む。この性質のため、リードを画像に入れる形はどれも崩れた。

| 試した形 | 結果 |
| :--- | :--- |
| 縦長の扉絵にリードを焼き込む（以前の形）。字の下限を倍率に合わせて縮める | 618 字のリードが下端で切れた。左右の余白が広すぎ、字は本文より小さい |
| 字を縮めずに入るリードだけを焼き込み、長いリードは全部を文字にする | 章によって、リードが扉絵の中にあったり無かったりする |
| 入るところまで段落単位で焼き込み、残りを文字で続ける | 画像の字と続きの字の大きさがそろわない。phone では、扉絵の下の同じ画面に、大きな字の続きが入り込む |
| 縦長の扉絵に、見出しだけを焼き込む | tablet では章題の下に大きな空白が残り、phone では扉絵の下にリードが入り込む |
| **横長の扉絵に、見出しだけを焼き込む（採用）** | 扉絵のすぐ下にリードが続き、端末を問わず崩れない |

`epub-frontispiece-facsimile-spec.md`（リードまで焼き込む縦長の章扉）は、この節で改めた。

### 2.3 値の受け方

- 2 つのキーとも、受け方は同じ。警告には、どちらのキーかを省略しない名前で出す
- 数値（`1.2`）と、`em` を付けた値（`1.2em`）で受ける。どちらも同じ意味で、本文の基準の大きさに対する倍率。**刻みは自由**で、`1.05`・`1.15` も書ける（10.5pt なら 1.05 倍は約 11.0pt）。`110%` は受けない
- キーの名前は、文字の大きさを決める他のキー（判型の `base_font_size`）にそろえて `size` とする。倍率は `em` を単位と見れば大きさの一種で、`lead_scale` のように倍率を名前で言う必要は無い
- `12pt`・`4mm`・`16Q` のような**直接の大きさは、今は受けない**。判型を変えて `base_font_size` が変わったとき、リードだけが取り残されるため。今の判型での倍率へ直して 🟡 で知らせ、書かなかったものとして扱う（例: 10.5pt の本で `12pt` → `lead_size: 1.14`）。名前が `size` なので、将来受けることにしても名前を変えずに済む
- 1.0 より小さい値は 1.0 にし、🟡 で知らせる。

  ```
  🟡 theme.lead_size は 1.0 以上にしてください（本文より小さいリードは読みにくくなります）
     book.yml: lead_size: 0.9 → 1.0
     リードが章扉に収まらないときは、リードを縮めてください
  ```

- 数でも大きさでもない値（`large` など）は書かなかったものとして扱い（`theme.lead_size` は 1.2、`theme.frontispiece.lead_size` は `theme.lead_size` に従う）、🟡 で知らせる（`normalize_char_count` と同じ扱い）。`12pt` のような直接の大きさも同じ
- 2.0 より大きい値は 2.0 にし、🟡 で知らせる。リードが章題・節題と張り合わない大きさに留める（2.0 倍でも 10.5pt の本なら 21pt で、章題の 34〜50Q ≒ 24〜35pt より小さい）
- `image` の章扉では、大きくすると幅も広がる。版面より広くなれば、今の `warn_if_wider_than_text_area` が 🟡 を出す

## 3. 下限を 1.0 に置く理由

- リードは章の入口で、本文より小さくすると、本文より軽い扱いに見える
- 1.0 倍でも、太さ（500）と字下げでリードと分かる（§1 の実測の 1.0 倍）
- 1.0 倍でも収まらないリードは、文字の大きさでは直らない。リードを縮めるのが本筋（§2.1 の軸 2.5）。§4 の警告はそこへ案内する

## 4. はみ出したリードを知らせる

### 4.1 何を知らせるか

`image` の章扉に収まらず、リードの終わりが次のページへ送られた章。今は、組み上がった PDF を開いて見るまで気づけない。

`simple` の章は対象外。章題・リードの後にそのまま本文が続くので、リードがページをまたいでも崩れない。

```
🟡 33 章のリードが章扉に収まらず、最後の 2 行が次のページへ送られています（contents/33-networks-and-systems.md）
   リードを 50 字ほど縮めるか、
   book.yml: theme.frontispiece.lead_size: 1.2 → 1.1
```

- 案は「縮める字数」と「収まる倍率」の 2 つ。縮める字数 = 送られた行数 × `lead_chars`（2 行 × 28 字 ≒ 50 字。10 字単位に丸める）
- **収まる倍率** = 今の倍率 × 章扉に収まった行数 ÷ リードの全部の行数。§1.1 のとおり行数は倍率で変わらず、上端も動かないので、この比で収まる。案として見せる値は 0.05 刻みに切り下げる（読みやすさのため。設定に書ける値の刻みは自由、§2.3）。1.0 を下回るときは倍率の案を出さず、縮める案だけにする
- 倍率の案は**いつも `theme.frontispiece.lead_size` で出す**。はみ出しは章扉の問題なので、直しても `simple` の章・付録のリードは小さくならない。`theme.frontispiece.lead_size` が空欄（`theme.lead_size` に従っている）なら、「`theme.frontispiece.lead_size: 1.1` を書き足す」と出す
- 章扉の倍率はすべての章扉に効く。ほかの章扉のリードも小さくなることは、警告には書かない（著者は book.yml のコメントで分かる）

### 4.2 調べ方

1. 組んだ HTML から、章ごとにリードの文（`.chapter-lead` の段落）を取る。対象は `theme.style: image` の章だけ（付録は常に `simple` なので入らない）
2. 組んだ PDF を `pdftotext` で読み（`OutlineExtractor` が既に使っている）、リードの**最初の 15 字ほど**があるページと、**最後の 15 字ほど**があるページを探す。照合は、空白・改行・脚注の記号を除いた字の並びで行う（PDF の文字には行の折り返しと、用語の印「†」が混ざる）
3. 2 つのページが違えば、はみ出している。`pdftotext -bbox-layout` で、章扉のページと次のページにあるリードの行数を数え、§4.1 の数を出す

- 900 ページの合本でも数秒で終わること。しおり（`OutlineExtractor`）から章の最初のページを引き、そのページと次のページだけを読めば、全ページを読まずに済む
- 見つからない章（リードの文が PDF の文字と一致しない）は、黙って飛ばす。誤った警告を出すより、ここは見逃す方を選ぶ（はみ出しの判定を間違えると、収まっている章に「縮めて」と言うことになる）

### 4.3 いつ走らせるか

- **全章ビルド（`:full`）と単章ビルド（`:single`）の両方。** Type 3 の確かめと違い、単章でも章扉の組み方は同じなので結果が当てになる。リードを推敲する著者は単章で組み直すので、単章で出る方が役に立つ
- PDF を作るときだけ。EPUB の章扉にはリードを焼き込まず、リードは本文の文字として流れるので、はみ出しは起きない（§2.2.1）
- `theme.style: simple` の本では走らせない
- ステップは `check chapter leads`。`:full` では `check type 3 fonts` の隣、`:single` では `entries.js + pdf` の後

## 5. 飾りの絵との重なりは知らせない

はみ出さなくても、§1 の 1.2 倍のように飾りの絵に重なることがある。だが知らせない（2026-10-28 ユーザー判断）。

- **どの絵を使うかで、飾りの位置が違う。** 同梱の 12 枚でも、独自の扉絵ならなおさら
- **重なっているかの判別そのものが難しい。** 扉絵の不透明な画素を行の枠に写して量る方法も考えたが、扉絵の置き方（中央寄せ・`edge_inset`・綴じの寄せ）を再現する必要があり、しきい値の根拠も持てない
- **どこまで許すかが著者によって違う。** 数文字重なる程度なら許す著者もいる。境界線を引けない

代わりに、42 章で「扉絵ごとに飾りの位置が違うので、組んで見て `lead_size`・`lead_chars`・`heading_offset` で合わせる」と書く（§6.5）。§1 の表が、その合わせ方の手がかりになる。

## 6. 実装

### 6.1 設定

- `ConfigKeys`: `%i[theme lead_size] => Spec[default: 1.2]` と `%i[theme frontispiece lead_size] => Spec[default: nil]`（nil の理由は §2.2。`appendix_color` と同じコメントを添える）
- `FrontmatterGenerator#parse_theme_settings`: `lead_size_value:`（本全体）と `frontispiece_lead_size_value:`（章扉。空なら `lead_size_value` を入れて返す）を返す。検証は §2.3（`normalize_lead_size(value, label:)` を新設し、2 つのキーで共用）。章扉の側は `parse_frontispiece_config` で読む
- `config/book.yml`（ルート）: `theme.style` の下に `lead_size: 1.2`、`frontispiece` の `lead_chars` の下に空欄の `lead_size:` を足す（§2 の例）。雛形はユーザーが `copy_to_scaffold.rb` で同期する

### 6.2 PDF

- `BookSettingsCss#chapter_lead_advance_mm(page_cfg, lead_size = DEFAULT_LEAD_SIZE)`: `base_mm * lead_size`。今の `* 1.2` を置き換える。渡すのは章扉の倍率（`frontispiece_lead_size_value`）。`image` の章扉の幅（`--frontispiece-lead-width`）はこれで倍率に従う
- 文字の大きさは、`book-settings.css` へ**リテラルの規則**で焼き込む。2 つの倍率を 2 つの規則で出す（例: `theme.lead_size: 1.2`・`theme.frontispiece.lead_size: 1.1`）。

  ```css
  body .chapter-lead { font-size: 1.2em; }
  body.vs-header-image .chapter-lead { font-size: 1.1em; }
  ```

  - 1 つ目は本全体、2 つ目は `image` の章扉。付録の `<body>` には `image` の本でも `vs-header-simple` が付く（`body_class_injector.rb`）ので、2 つ目は付録に当たらない
  - EPUB（クリーン・Kindle）にも同じ規則が効く。EPUB の章扉はリードを焼き込まず、リードは本文の文字として流れる（§2.2.1）
  - `var()` を使わないのは、Kindle が `var()` を含む宣言を丸ごと捨てるため
  - 特異度は `.chapter-lead`（`chapter-common.css`）より高いので、読み込みの順に依らず勝つ
- `chapter-common.css` の `.chapter-lead { font-size: larger }` は残す（既定の 1.2 倍）
- `line-height: 1.7` は単位の無い倍率なので、行送りも倍率に比例して縮む（何もしなくてよい）

### 6.3 EPUB

- `HeadingImageComposer#frontispiece_svg`: 横長の扉絵に、章番号と章題だけを焼き込む（§2.2.1）。リードの焼き込み（`lead_layout`・`lead_fits?`・字の下限 `LEAD_FONT_FLOOR`・8% ずつ縮める処理）は取り除く。`LAYOUT_VERSION` を 5 に上げ、`--no-clean` で縦長の古い画像を掴まないようにする
- `EpubBuilder#inject_frontispiece_headings!`: リードを取り出さず、HTML に残す。扉絵の画像は `theme.frontispiece.image` の横長版（`frontispiece_landscape_path`。節絵と同じ `ThemeImageResolver.resolve_ornament_path` で探し、無ければ作る）
- `EpubBuilder#epub_heading_metrics`: 節題の字数を `epub_ornament_chars` で置き換える（§2.2.1）。PDF の章題の大きさは `BookSettingsCss#chapter_title_font_q`、節題は `section_title_font_q` から取る
- リードの大きさは §6.2 の規則で決まる（EPUB 専用の処理は無い）

### 6.4 はみ出しの検出

- `Build::ChapterLeadCheck`（新設・`type3_font_check.rb` と同じ形の `check!(pdf_path)`）
- 章ごとのリードの文は、組んだ HTML（`.cache` の章の HTML）から Nokogiri で取る
- PDF の読み取りは `pdftotext`（poppler・`doctor` が確かめている依存）

### 6.5 原稿

- `contents/41-book-yml.md`: `theme` のキーの一覧に、`style` の下の `lead_size` と、`frontispiece` の下の `lead_size` を足す
- `contents/42-frontispiece.md`: リードの大きさの節を足す。`theme.lead_size` が本全体、`theme.frontispiece.lead_size` が `image` の章扉だけの上書きであること、リードが長い本で下げるという使いどころ、はみ出しの警告が出たらまずリードを縮めるという順序。`image` では倍率を下げると幅も狭くなるので、**幅を保ちたいときは `lead_chars` を増やす**（例: 1.2 倍・28 字 → 1.1 倍・30 字。§1）ことも書く。飾りの絵との重なりは知らせないので、組んで見て `lead_size`・`lead_chars`・`heading_offset` で合わせることも書く（§5）

## 8. 決まったこと

### 8.1 決まったこと（2026-10-28 ユーザー判断）

1. **キーの名前は `lead_size`。** `1.2` と `1.2em` を受ける。直接の大きさ（`12pt`）は、名前の上では余地を残し、今は受けない（§2.3）
2. **範囲は 1.0〜2.0。** 上限は章題・節題との兼ね合いで 2 倍を目安とする（§2.3）
3. **飾りの絵との重なりは知らせない**（§5）
4. **spiral-ruby は `theme.frontispiece` に `lead_size: 1.1`・`lead_chars: 30`**（§7 の 3）
5. **既定値は 1.2 のまま。** 既定を変えると、`vs upgrade` した既存の本のリードが断りなく変わる。本書のリード（100〜200 字）は 1.2 倍で章扉に余裕がある
6. **置き場所は両方に持たせる。** `theme.lead_size`（本全体）と `theme.frontispiece.lead_size`（`image` の章扉だけの上書き・空欄なら前者に従う）（§2.2）
7. **EPUB の章扉は、横長の扉絵に章番号と章題だけを焼き込む。** リードは焼き込まず、扉絵の次に本文の文字として流す。縦長の扉絵とリードの組み合わせを 4 通り試し、Kindle Previewer の tablet・phone で見比べて決めた（§2.2.1）
8. **EPUB のリードは画面いっぱいの幅で、大きさは `lead_size` に従う**（§2.2.1）
9. **EPUB の節題は、章題に対する大きさの比を PDF にそろえて小さくする**（§2.2.1）

## 11. 考慮した代替案（不採用）

- **飾りの絵との重なりを、扉絵の不透明な画素で判定して知らせる。** 不採用の理由は §5
- **`lead_scale` という名前。** 倍率と名前で分かるが、文字の大きさのキーは `size`（`base_font_size`）でそろっている。`em` を単位と見れば倍率も大きさである（§2.3）
- **`lead_size` を 1 か所にだけ置く。** `theme` の直下だけ、`theme.frontispiece` の下だけ、`theme.lead:` にまとめる、の 3 案を比べた（§8.1 の表）
- **PDF で、収まるまでリードを自動で縮める。** CSS には「収まるまで縮める」が無く、Vivliostyle で組む前に高さを見積もると、章題の行数・脚注の印・禁則で外れる。章ごとにリードの大きさが変わるのも、本として不揃いになる
- **`lead_chars` だけを増やして行数を減らす。** 幅が広がり、飾りの絵へ横から近づく。版面の幅で頭打ちにもなる。倍率と組み合わせると効く（§1）が、字数だけでは長いリードの解にならない
- **章ごとに大きさを変える記法（`:::{.chapter-lead .small}`）。** リードの体裁が章ごとに不揃いになる。長すぎる章はリードを縮めるのが本筋
- **PDF でも、リードを章扉から外して本文の頭へ回す。** PDF の章扉は 1 ページの紙面で、章題とリードの塊が意匠になっている。EPUB で外したのは、画像の中の字が端末の文字サイズに従わないためで（§2.2.1）、PDF にその事情は無い
- **EPUB の章扉に、リードの全部か一部を焼き込む。** 試した 4 通りと結果は §2.2.1 の表
- **EPUB の帯の章題を大きくして、節題との差をつける。** 帯では左上と右下の飾りに章題がかかりやすくなる。節題を小さくする方を選んだ（§2.2.1）
