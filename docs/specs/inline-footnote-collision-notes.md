# inline-footnote-collision-notes

インライン脚注 `^[短い補足]` が本文中で脚注にならない。仕様書を起こすときの一次資料。

- 状態: **不具合を確認しただけ（原因の切り分けは未了）**
- 見つけた経緯: 2026-07-30、`contents/33-index-glossary.md` の記述を直す際にインライン脚注を書いたら脚注にならなかった
- 優先度: 低（回避策あり・実害は原稿 1 箇所）

---

## 1. 症状

原稿に

```markdown
…356 枚目にあたります^[この 49 ページというずれは本書での値です。…安全です。]。
```

と書くと、生成 HTML は次のようになる。

```html
…356 枚目にあたります^この 49 ページというずれは本書での値です。…安全です。。
```

- `^` が**そのまま本文に出る**
- ブラケット `[` `]` が**消える**
- 脚注の本体が本文に流れ込むので、脚注末尾の `。` と本文の `。` が**重なる**（`安全です。。`）
- `<a class="footnote-ref">` も `.page-footnote` も生成されない

## 2. 確認できていること

**VFM 自体はインライン脚注に完全対応している。** 素の VFM に通すと参照形式と同じように変換される（2026-07-30 実測）。

```
$ npx @vivliostyle/vfm fn.md
<p>参照形式です<a id="fnref1" href="#fn1" class="footnote-ref" role="doc-noteref"><sup>1</sup></a>。</p>
<p>インライン形式です<a id="fnref2" href="#fn2" class="footnote-ref" role="doc-noteref"><sup>2</sup></a>。</p>
…
<li id="fn2" role="doc-endnote">短い補足<a href="#fnref2" class="footnote-back" role="doc-backlink">↩</a></li>
```

つまり**壊しているのは VFM より手前（本プロジェクトの前処理）**。

参照形式 `[^label]` は正常に動く（同日、同じ章で置き換えて確認済み。`<a class="footnote-ref">` ＋ 同一ページ下部の `.page-footnote` が出る）。

## 3. 疑っている箇所（未検証）

索引の手動マークアップ記法 `[用語]` と綴りが衝突している可能性が高い。

`lib/vivlio_starter/cli/index/index_match_scanner.rb`:

```ruby
INDEX_TERM_PATTERN = /\[([^\[\]\n]+)\](?!\()/     # :68

def skip_term?(term_text)                          # :258
  return true if term_text.nil? || term_text.empty?
  # 脚注構文 [^id] のみ除外
  return true if term_text.start_with?('^')
  false
end
```

- 除外しているのは **`[^id]`（参照形式）だけ**。`^[本文]` はブラケットの中身が `^` で始まらないので除外条件に当たらない
- ただし `process_term` は必ず `<dfn>` / `<span>` を返すので、**このパスを通ったなら症状 §1 にタグが現れるはず**。実際にはタグが無い → **この経路とは別の何かがブラケットを落としている可能性がある**
- したがって「`skip_term?` に一行足せば直る」と決めつけないこと。**まず犯人を特定する**

### 犯人特定の手順（次にやること）

1. テスト用の章に `^[補足]` を 1 行入れて `vs build <章>` を実行
2. **VFM 前の中間 Markdown**（`.cache/vs/build/html/<章>.md`）を見る
   - ここで既にブラケットが消えていれば前処理が犯人 → どのステップかを `--log=debug` で絞る
   - ここでは無傷なら VFM 呼び出し側の設定（フロントマターの `vfm` オプション等）を疑う
3. 犯人が確定してから修正方針を決める

## 4. 影響範囲

**インライン脚注は「使える記法」として案内している。**

| 場所 | 記述 |
|---|---|
| `contents/21-markdown-tutorial.md:530-531` | 「#### インライン脚注 / `^[簡単な補足]` のように記述し、その場で内容を完結させます」 |
| `contents/90-notation-cheatsheet.md:92` | 記法早見表に「脚注（インライン） \| `^[短い補足]`」 |

いま原稿が壊れていないのは、**21 章の使用例が ```` ```markdown ```` フェンスの中にあり前処理を通らない**ため。フェンス外での実使用は今のところ無い（`grep '\^\[' contents/*.md` で確認）。

## 5. 回避策

参照形式を使う。

```markdown
…356 枚目にあたります[^folio-offset]。

[^folio-offset]: この 49 ページというずれは本書での値です。…
```

同一ページ下部の脚注として正しく組まれる（`33-index-glossary.md` で採用済み）。

## 6. 決めるべきこと

- **直すのか、記法を取り下げるのか。** 直すなら §3 の手順で犯人を特定してから。取り下げるなら 21 章と 90 章の早見表から削る
- 直す場合、`[...]` を使う他の記法（コメント強調マーカー `[!]`・`[&&]`・`[<h1>]` など）と同じ土俵に載るので、**「索引マークアップと綴りが衝突する記法」の扱いを一箇所に集約する**のが筋。個別に `skip_term?` へ条件を足していくと同型の抜けが再発する
- 著者が気づけるようにするなら、`vs preflight` の記法ガードで「インライン脚注は現在使えません」を 🟡 で案内する手もある（`warning-messages-actionable` の方針）
