## A. リリース判断に関わる大きめの論点

コードの細部とは別レイヤーの「意思決定」であり、後から覆りにくいため、
正式版の検討時にまず決めておきたい3点。

### A-1. Ruby 4.0 必須という前提（最大の検討点）— **2026-08-06 決着: `>= 3.4` へ緩和**

**Ruby 4.0 固有の機能は 1 つも使っていなかった。** 調査と実走の結果:

- **構文**: Prism のバージョン指定パースで全 421 ファイルを解析。4.0.0 / 3.4.0 / **3.3.0**
  いずれも構文エラー 0 件。
- **実際の下限は 3.4 で、決めているのは `it`（暗黙ブロック引数）単独**。1,024 箇所 / 189 ファイル。
  **これは静的解析では見えない**——`it` は 3.3 でも構文エラーにならず「`it` メソッドの呼び出し」
  として通り、実行時 `NameError` になる（Prism も 3.3 では `CallNode`、3.4 では
  `ItLocalVariableReadNode` と別物に解析する）。だから実走が要った。
- **Ruby 3.4.10 で `rake test` 実走 → 2,399 件すべて通過**（4.0.3 の結果と一致）。
- `it` を除けば次の縛りは `Data.define`（71 箇所）と匿名 `**` フォワーディング（4 箇所）で、
  いずれも 3.2。ただし `it` を捨てるのは本標準（`ruby-development-standard.md`）と衝突するため採らない。

**本体のコード変更はゼロ**（gemspec 1 行のみ）。`require 'set'` の追加も**不要だった**——
Ruby 3.4 では core が `Set` を autoload する（`Object.autoload?(:Set)` が `"set"` を返す。
`--disable-gems` でも通る）。むしろ既存の不要な `require 'set'` 3 件を削除した。

**判断の根拠（利用者層）**: Ruby 3.4 は 4.0 と並ぶ現行メンテナンス対象。RubyKaigi 2026 の
調査（約 400 回答）では本番利用が 3.4 約 145 / 4.0 約 140 で、**3.4 が依然として最大勢**。
かつ本 gem の利用者は「Rails を運用する Ruby 開発者」ではなく**技術同人誌の書き手**であり、
手元の Ruby を能動的に上げない層が想定される。`>= 4.0` はその層を丸ごと締め出していた。

**付随して緩和が必要だった自作 gem**: `query-stream` / `vivlio-starter-pdf`（どちらも `>= 4.0`
を宣言しており、本体だけ緩めても入らない）。

### A-2. 外部バイナリ依存のオンボーディング体験

本 gem は内部で以下をシェル経由で利用する。これらは `gem install` では導入されない。

- Vivliostyle (npm)
- Ghostscript
- poppler (`pdfinfo`)
- qpdf
- MeCab (`natto` 経由・要 libmecab)

確認すべき点:

- `vs doctor` が**全依存を漏れなく検査**し、不足時に**インストール手順を提示**できているか。
- README「追加ツールのインストール」が上記を**網羅**しているか。
- 依存が無い場合に**クラッシュではなく親切なエラー**で停止するか。

CLI として最も「正式版らしさ」が表れる部分。

### A-3. RubyGems.org への公開可否

- 現状: homepage は GitHub を指す。
- 決定すべきこと: **rubygems.org へ push するか／GitHub からの直接インストール運用にするか**。
- 公開する場合の付随作業:
  - `rubygems_mfa_required` を `false` → **`true`** へ（公開 gem のセキュリティ既定）。
  - バージョンを `1.0.0-beta` → **`1.0.0`** に確定
    （`config/book.yml` の `project.version` は既に `1.0.0`。gem 側のみ beta が残存）。

## まとめ

「細部の修正を積む」方向性は正しい。加えて正式版では、コードの細部とは別レイヤーの
意思決定として **A-1 Ruby 要件の妥当性 / A-2 外部依存のオンボーディング / A-3 公開先と
バージョン確定** の 3 点を一度確定させておくと、後から覆りにくい。

**A-1 は 2026-08-06 に `>= 3.4` で決着**（上記）。残るのは A-2 と A-3、および B の 5 件。

**この調査から得た一般則**: 「その機能を使っているか」を grep や構文解析で確かめるだけでは
足りない。`it` のように**旧版でも構文が通り、意味だけが変わる**機能は、実際にその版で
走らせないと分からない。バージョン要件を動かすときは実走を必須にすること。
