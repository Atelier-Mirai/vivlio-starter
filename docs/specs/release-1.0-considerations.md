## A. リリース判断に関わる大きめの論点

### A-1. Ruby 要件 — **2026-08-06 決着: `>= 3.4`**

Ruby 4.0 固有の機能は 1 つも使っていなかった。実際の下限を決めているのは `it`（暗黙ブロック引数）単独で、1,024 箇所 / 189 ファイル。

**この調査から得た一般則**: 「その機能を使っているか」を grep や構文解析で確かめるだけでは足りない。`it` のように**旧版でも構文が通り、意味だけが変わる**機能は、実際にその版で走らせないと分からない（3.3 では `CallNode`、3.4 では `ItLocalVariableReadNode` と別物に解析される）。バージョン要件を動かすときは実走を必須にすること。`rake test:versions` が 3.4.10 / 4.0.6 の両方で回す。

付随して `query-stream` / `vivlio-starter-pdf` も `>= 3.4` へ緩和済み。

### A-2. 外部バイナリ依存のオンボーディング体験 — **未決**

本 gem は内部で以下をシェル経由で利用する。これらは `gem install` では導入されない。

- Vivliostyle (npm) / Ghostscript / poppler (`pdfinfo`) / qpdf / MeCab (`natto` 経由・要 libmecab)
- ImageMagick / librsvg / libvips / mathjax-full / mermaid-cli (`mmdc`)

確認すべき点と、2026-08-16 の点検結果:

- [x] **`vs doctor` が全依存を漏れなく検査しているか** — **漏れが 2 つあった。** ①`vfm`（Markdown → HTML 変換そのもの）②`pdftotext`（PDF のしおり生成。同じ poppler の `pdfinfo` / `pdftoppm` だけ見て 3 つ目を見ていなかった）。どちらも追加し、検査は 19 種になった。`vs upgrade` の更新計画にも `@vivliostyle/vfm` を追加し、初回の `--dry-run` で 2.7.0 → 2.7.2 の未適用更新が実際に見つかっている。
- [x] **README が網羅しているか** — **誤りがあった。** `npm install --save-dev @vivliostyle/cli vfm` と書いていたが、npm の `vfm` は "Form Validation for Vue3" という無関係のパッケージ（本開発機に実際に入っており、この手順を踏んだ痕跡だった）。加えて `--save-dev` はローカル導入でコマンドが PATH に現れない。グローバル導入へ直し、依存表に Vivliostyle CLI / VFM / pdftotext を追加した。
- [x] **依存が無いときクラッシュせず親切に止まるか** — **VFM だけが「静かに壊れる」経路だった。** 変換はシェルのリダイレクトなので、不在でも 0 バイトの HTML が残り、本文が空のまま本が組み上がる。`Guards::VfmCheck` を新設して 🔴 で止め、変換の成否も終了コードでなく出力の中身で判定するようにした（VFM は読み込み失敗でも exit 0 を返す）。他の主要ツール（gs / qpdf / rsvg-convert / magick / pdftotext / mmdc）は不在チェックと対処の案内をすでに持っていた。
- [ ] **macOS + Homebrew 以外の環境での体験**をどこまで謳うか — 未決。現状は macOS 主対象、`vs doctor --fix` はこの環境でのみ動作。

**この点検自体が「1.0.0 前にやってよかった」類の作業だった**——3 つの穴（検査・導入手順・失敗時の挙動）は独立に空いており、揃っていない環境では「`vs doctor` がすべて OK と言うのにビルドが白紙になる」が成立していた。開発機は VFM が入っているため、テストでも実ビルドでも永久に露見しない。

### A-3. RubyGems.org への公開 — **公開済み。MFA は見送り、鍵のスコープで代替（2026-08-22 決着）**

2026-08-10 に `1.0.0.pre.rc.2`、2026-08-22 に `1.0.0.pre.rc.3` を公開した。**初公開ではない**——`1.0.0.pre.beta` が 2026-04-25 に出ている。

rc.3 の公開に合わせて **rc.2 を yank した**。単に新しい版が出たからではなく、rc.2 には `vs index:apply` が著者の手書きの定義文を黙って消す不具合（時限式のデータ損失）が入っていたためである（`index-apply-rejected-consistency-spec.md`）。**yank は「動く版を整理する」ためには行わない**——版番号は再利用できず、その版を固定している環境の `bundle install` が失敗する。

> **注意**: `gem list -r vivlio-starter` はプレリリース版を既定で隠す。公開状況は
> `curl -s https://rubygems.org/api/v1/versions/vivlio-starter.json` で確認すること
> （この見落としで一度「未公開」と誤認した）。CDN のキャッシュで応答が揺れるので、
> 直後に確かめるときは `-H 'Cache-Control: no-cache'` を付ける。

#### `rubygems_mfa_required` は `false` のままにする

**当初は「3 本まとめて 1.0.0 で `true`」の方針だったが、見送ることにした。** 3 本とも `false` 相当のまま（`vivlio-starter` / `query-stream` は `'false'`、`vivlio-starter-pdf` は未設定）。

理由は 3 つ。

- **規模が見合わない。** rubygems.org が MFA を強制するのはダウンロード数 1.65 億超の gem で、本 gem は累計 300 台である
- **摩擦が質的に効く。** `gem push` / `gem yank` のたびにワンタイムコードが要る。年 5〜6 回のリリースでも、**手順をスクリプト化できなくなる**のは別種の負担である
- **代替がある。** 下記の鍵スコープで、被害の中で最も復旧が困難な「乗っ取り」だけは塞げる

#### 代わりに行うこと: API キーの権限を絞る

全権の鍵を、**`Push rubygem` と `Yank rubygem` の 2 つだけ**に絞った鍵へ差し替える。有効期限も付ける（放置した鍵が永久に有効な状態を避けるため）。

| 鍵が漏れたとき | 全権 | push + yank のみ |
|---|---|---|
| 悪意ある版の push | できる | **できる**（MFA でしか塞げない） |
| 公開済みの版を yank | できる | **できる** |
| **所有者を奪う**（自分を追加し本人を削除） | できる | **できない** |

**塞げるのは乗っ取りだけだが、そこが最も復旧が困難**なので割に合う。摩擦はゼロで、`gem push` の手順は一切変わらない。

**`index_rubygems` は付けない。** これは `/api/v1/gems.json`（**自分が所有する gem の一覧**）を引く権限で、リリース作業には出てこない（`gem push` / `gem yank` 以外の `gem` コマンドは公開 API を使う）。用途の分からないスコープは付けない側に倒す。

**手順は「作る → 差し替えて確認 → 古い鍵を消す」の順。** 先に消すと、新しい鍵に問題があったとき余計な往復が要る。なお 2026-08-22 時点で **gem を push する自動化は存在しない**（GitHub Secrets は空、3 リポジトリのどこにも `gem push` のワークフローが無い）ので、鍵を使っているのは開発機の `~/.gem/credentials` だけである。

#### 再検討する条件

次のいずれかに当てはまったら `true` を検討し直す。

- ダウンロード数が桁違いに増える（他人の本番ビルドが依存する規模になる）
- 共同メンテナを迎える（鍵の管理者が 2 人以上になる）
- CI からの自動公開を入れる（そのときは MFA より **Trusted Publishing**（OIDC）のほうが筋。鍵そのものが不要になる）

## E. リリース手順で得た教訓（1.0.0 でも効く）

### `rake test:release` を必ず通す

rc.2 のリリース作業で、**リリースゲートが実在の回帰を 4 件捕まえた**（epubcheck の RSC-005 / RSC-012）。索引の主要参照 89 件のうち **27 件が EPUB でリンクを失っていた**。

重要なのは 2 点。

- **`rake test` では 1 件も出なかった。** 検出したのは `test:manual` の epubcheck だけ。
- **原因は機能追加ではなく「修正」だった。** 索引の `\b` 取りこぼしを直した結果、新たに拾えるようになった語が、章題・章リードという**アンカーの消える場所**へ着地して初めて露見した。

**fix しか入れない期間でも回帰は起きる。** 1.0.0 の前にも必ず全 6 段を通すこと。

### version.rb が上がっている ≠ 出荷済み

rc.1 は `version.rb` と CHANGELOG の節（6/21 付）だけが先に進み、**タグも公開もされないまま**約 2 か月ぶんが `unreleased` に積まれていた。リリースノートも rc.1 用に 8/9 付で書かれていたが、rc.2 へ統合して削除した。

**次に切るときは `git tag` を先に確認すること。**
