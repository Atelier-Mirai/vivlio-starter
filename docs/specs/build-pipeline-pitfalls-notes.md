## 0. なぜこのメモがあるか

`STATUS.md` の「メモ（依存関係・実装順序）」に置かれていたが、あの節の役割は**実装待ちの仕様書どうしの依存**を書くこと（`STATUS.md` 冒頭の運用ルール）で、下の 4 件はそれに当たらない。`STATUS.md` は「実装済みか？」を引くファイルなので、ビルド実装の落とし穴を探しに来る人はいない。恒久参照のメモとしてここへ移した。

各項目の実測と詳細は、末尾に挙げた archives の仕様書にある。ここは**症状から引くための索引**である。

## 1. 枝をまたぐ待ち合わせは「2 段構え」で解放する

ビルドは **PDF 枝と EPUB/Kindle 枝が並列に走る**。片方の成果物を他方から読むならラッチが要る。

**ラッチの解放は「作り終えた瞬間」と「枝の終わり（保険）」の 2 段構えにすること。**

- 前者だけ → 取りこぼしたときに**永久に待つ**
- 後者だけ → 待ちすぎて**並列の利得が消える**

→ `kindle-rotate-table-image-spec.md` §8.2 に実測。

## 2. プロセス全体に効く API を疑う

並列化で取りこぼしたのは、いずれも「プロセス単位で共有される」ものだった。

- `Dir.chdir` — cwd はプロセス共有。枝ごとに別ディレクトリのつもりでも互いを壊す
- スピナー — `$stdout` へ直書きするため、2 枝から同時に書くと出力が混ざる

**`Common::` や `.cache/` を grep しても出てこない**のが厄介なところ。「この API はプロセス全体に効くか？」を明示的に問うこと。

→ `build-target-parallelization-spec.md` §9.2。

## 3. モジュール状態を持つ機構はテスト間で漏れる

ラッチのようなモジュール状態は、解放漏れが**後続テストが永久に待つ**形で現れる。テスト順がランダムなので**再現しない**——「たまに CI が止まる」の典型的な正体。

機構を足したら、テストの teardown で状態を戻す。

→ `kindle-rotate-table-image-spec.md` §8.3。

## 4. PDF の `/Dests` に出るのは「リンクの飛び先になっている id」だけ

id を持つだけの要素は `/Dests` に現れない。PDF から「この要素は何ページ目か」を引きたいなら、**リンクを 1 本埋める**必要がある。

→ `front-back-matter-single-render-spec.md` §3.4 に実測表。

## 5. 前処理で生 HTML にしたものは、後段のすべてから隠れる

パイプラインは `pre_process（Markdown）→ 索引（Markdown）→ VFM（HTML 化）→ post_process（HTML）` の順に進む。**前処理のどこかで Markdown を生 HTML に変えると、その中身は以降の工程から見えなくなる。**

2026-09-12 に定義リストで実害が出た。`transform_definition_lists!` が Kramdown に `<dl>` を作らせていたため、

- Kramdown は VFM 固有の記法を知らない → ルビ `{漢字|よみ}` が文字のまま紙面に出る
- 索引スキャナ（Step 4）は生 HTML を「触らない領域」として飛ばす → `[語|読み]` も残る

という二重の取りこぼしになっていた。定義リストの中でだけ記法が死ぬので、**書いた本人も紙面を見るまで気づけない**。数式とキー表示がたまたま効いていたのは、変換の順序が定義リストより前だったからにすぎない。

`.text-*` を前処理で生 HTML 化して中の Markdown が壊れた件（`markdown-notation-collision-spec.md`）と同じ構図である。

**判断の指針。** ある記法を HTML へ落とすとき、その中に**著者が書いた他の記法が入りうるなら、HTML 化は後処理へ置く**。VFM が組み終えた HTML を受け取って組み直すほうが、前処理で先回りするより取りこぼしが少ない。定義リストは `post_process/definition_list_converter.rb` へ移し、`<p>用語<br>: 説明</p>` を `<dl>` へ組み直す形にした。

**ただし「行の見た目」は後処理まで残らない。** VFM は行頭の空白を落とすので、HTML の側からは

```
Ruby              用語A
: 説明            : 説明A
  続きの行        用語B          ← 字下げの有無が消え、
: 別の説明        : 説明B           どちらも <br> 区切りの 1 行になる
```

の左右が区別できない。「次の行が定義行か」で決めようとすると**どちらも次が定義行**なので破れる（実際に一度そう実装して、継続行が `<dt>` に化けた）。

こういうときは、**前処理に残すのは印だけにして、HTML 化はしない**。定義リストでは継続行の頭へ幅ゼロの WORD JOINER（U+2060）を置き、後処理がそれを見て判断してから取り除く。行の中身は素の Markdown のままなので、ルビも索引もこれまでどおり効く。印を選ぶときは**取りこぼしても紙面に出ない側**（幅ゼロ・不可視）にしておく。
