# 索引ライブラリを説明文の蓄えとして持ち運ぶ 仕様（草案）

> 作成日: 2026-10-03
> ステータス: **実装済み**（2026-10-03。論点はすべて推奨どおりに決定。論点 5 は `--prefer-import` の廃止。同日に雛形を同期し archives へ移した）
> 対象: `vs index:export` / `vs index:import`（`IndexCommands::IndexLibrary`）、レビューファイルの 5 節、33 章「索引ライブラリを別の本へ持ち運ぶ」
> 関連: `index-library-portability-spec.md`（export/import の元の仕様）、`index-glossary-registration-spec.md`（登録の仕組みの整理・§3.3 使っていない語）、改善案 #104

## 背景

`index-glossary-registration-spec.md` で、索引・用語集の登録の仕組みを整理した。その中で「使っていない語」ができた。索引にも用語集にも載せず、説明文だけを辞書に残した語で、原稿にもう一度書くと、以前の説明文を添えて候補に出る（§3.3.2）。

export/import はこの整理より前に作られたので、新しい考え方と噛み合っていない。ライブラリが運ぶものの中心は**著者が書いた説明文**であり、それは「使っていない語」とほぼ同じ性格をしている。本書（210 語）では問題が出ていないが、ライブラリを別の本へ持ち込んだときに表に出る。

## 1. いまの仕組み

### 1.1 書き出し（`vs index:export`）

| 区分 | 書き出すもの | 書き出さないもの |
| :--- | :--- | :--- |
| `glossary` | 辞書で `g` を含む語の `term`・`yomi`・`definition` | 索引の印（`i`）・主要参照（`main`）・照合の綴り（`pattern`）・出どころ（`source`） |
| `reject` | 棄却した語の一覧のすべての語（`term`、あれば `reason`） | 棄却した日時・スコア |
| `yomi` | `g` を含む語と手動登録の語の読み（読みが語と同じものを除く）＋ `config/index_yomi_overrides.yml` | — |

索引の印と主要参照を運ばないのは、本ごとの判断だからである（元の仕様 §背景）。本書の辞書では、`g` を含む 53 語のうち 50 語が `ig`（索引にも載せる）で、ライブラリでは `g` だけになる。

**使っていない語（`flags: ''`）は書き出さない。** 説明文があっても運ばれない。

### 1.2 取り込み（`vs index:import`）

- `glossary` の語を `merge_terms!(flags: 'g', source: 'imported')` で辞書に足す。辞書にすでにある語は飛ばす（`--prefer-import` なら上書き）。
- `reject` の語を棄却した語の一覧に足す。すでに棄却している語と、辞書にある語は飛ばす。
- `yomi` を `config/index_yomi_overrides.yml` に足す。

`--prefer-import` で辞書にある語を上書きすると、`merge_term_data` が印を足し合わせる。索引だけの語（`i`）は `ig` になる。

### 1.3 取り込んだ語のその後

- **用語集のページ**: `UnifiedPageBuilder#build_glossary!` は、辞書の `g` の語を出現の有無に関係なくすべて載せる。取り込んだ直後は、新しい本の原稿に出てこない語まで用語集に並ぶ。
- **レビューファイル**: 次の `vs index:auto` で、原稿に出てこない取り込んだ語は 5 節に `[ ]` の印で並ぶ（いまの登録: `[g]`）。そのまま `vs index:apply` すると用語集から外れ、説明文があるので使っていない語として残る。
- **棄却した語**: 取り込んだ棄却した語のうち原稿に出てこないものも、5 節に「棄却した語」として並ぶ。本書では棄却した 87 語のうち 7 語がこれに当たる。ライブラリを本から本へ引き継ぐと、この数は増えていく。
- **新しい本で棄却した語との重なり**: 取り込みは、新しい本ですでに棄却した語でも用語集の語として足す。登録と棄却の両方に載った状態になり、次の apply で棄却の一覧から外れる（§2.3 の矛盾の解消）。新しい本での判断が、黙って取り込みに負ける。

### 1.4 呼び名

ログは「reject」（`reject +3（スキップ 1）`）、33 章のこの節は「候補から外した語」「外した語の一覧」、ヘルプは「棄却語」と書いている。レビューファイルと 33 章のほかの節は「棄却した語」にそろえた。

## 2. 噛み合わない点

1. **原稿に無い語が用語集に載る**（§1.3）。取り込みの直後に組むと、用語集のページに新しい本と関係のない語が並ぶ。5 節で外せるが、取り込むたびに同じ手間がかかる。
2. **使っていない語の説明文が運ばれない**（§1.1）。ある本で使わなかった語の説明文は、その本のライブラリから消える。本 A → 本 B → 本 C と引き継ぐと、本 B で使わなかった語は本 C に届かない。
3. **5 節が取り込んだ語で埋まる**（§1.3）。ライブラリを重ねるほど、原稿に出てこない使っていない語と棄却した語が増え、本に固有の「片付けるべき語」が埋もれる。
4. **新しい本の棄却を取り込みが覆す**（§1.3）。既存優先の原則に反する。`--prefer-import` で上書きすると、印まで変わる（§1.2）。
5. **呼び名がそろっていない**（§1.4）。

## 3. 方針（論点）

### 3.1 論点 1: 取り込んだ用語集の語をどう登録するか

| 案 | 内容 | 長所 | 短所 |
| :--- | :--- | :--- | :--- |
| **A（推奨）** | **使っていない語として登録する**（`flags: ''`・説明文つき） | 原稿に書いた時点で、説明文を添えた候補として出る（§3.3.2 の仕組みをそのまま使う）。用語集のページには載らない。新しい仕組みを足さない | 原稿に出てくる語も、本ごとに `[g]` か `[ig]` を付け直す（説明文は入っているので印だけ） |
| B | `g` のまま登録し、用語集のページは原稿に出てくる語だけを載せる | 印を付け直さずに用語集に載る | 5 節の「そのまま apply すると外れる」と食い違う（取り込んだ語は外れてしまう）。ビルドの挙動が変わり、取り込みと関係のない本にも効く |
| C | 取り込む時点で原稿に出てくる語は `g`、出てこない語は使っていない語 | 書き始めた本に取り込むときは手間が少ない | 新しい本は原稿が無いことが多く、ほとんどが使っていない語になる。分岐が増える |

A を推奨する。索引に載せるかどうかは、もともと本ごとに決めている（`ig` の語も `g` だけで運ぶ）。用語集に載せるかどうかも、原稿にその語が出てきたときに決めれば足りる。取り込んだ語が候補に出るときは、説明文が入っているので、印を書くだけで済む。

### 3.2 論点 2: 書き出す用語集の範囲

- **使っていない語も書き出す**（推奨）。説明文のある語は、`g` の語と同じく `glossary` に書き出す。§2 の 2 が解消する。
- **説明文の無い `g` の語**: 案 A では、取り込むと説明文の無い使っていない語になる。これは辞書の決まり（説明文の無い語は使っていない語として残さない・`remove_flag!`）に合わない。
  - 推奨: **書き出さない**。読みは `yomi` で運ばれるので、失うのは「用語集に載せた」という判断だけで、論点 1 の案 A ではもともと運ばない。本書には該当する語が無い（0 語）。
- ライブラリの書式（`version: 1`・`glossary` のキー）は変えない。これまでに書き出したライブラリも、そのまま取り込める。

### 3.3 論点 3: 5 節に、取り込んだ語を並べるか

5 節は、本に固有の「片付けるべき語」を見つけるための節である（Step のような誤登録を `[DELETE]` で消す）。取り込んだ語のうち、原稿に出てこない使っていない語と棄却した語は、新しい本では片付ける対象ではない。

| 案 | 内容 |
| :--- | :--- |
| **a（推奨）** | **取り込んだ記録は 5 節に並べない**。取り込むときに出どころを `source: imported` と記録し（棄却した語の一覧にも足す）、5 節はその記録を除く。原稿に出てくれば 1〜4 節に並ぶので、そこで判断する |
| b | 5 節の末尾に語数だけ示す（「ライブラリから取り込んだ使っていない語 180 語・棄却した語 64 語は省いています」） |
| c | いまのまま全部並べる |

a を推奨する。b の 1 行を a に添えてもよい（並べない理由が著者に分かる）。取り込んだ語の誤りは、ライブラリの側（`index_library.yml`）で直す。

### 3.4 論点 4: 新しい本で棄却した語と、ライブラリの用語集の語が重なるとき

- 推奨: **取り込まない**（新しい本の判断を優先し、スキップの件数に数える）。
- 逆向き（ライブラリの棄却した語が、新しい本の辞書にある）は、いまどおり取り込まない。

### 3.5 論点 5: `--prefer-import` を廃止する（決定 2026-10-03）

**決定**: `--prefer-import` を廃止する（ユーザーの判断）。取り込みはいつも追記だけで、辞書にある語・新しい本で棄却した語・すでにある読みには触れない。

- **理由**: オプションで規則が分かれると、著者に分かりにくい。必要になるのは「すでに取り込んだ本の説明文を、ライブラリの新しい説明文で上書きしたい」ときだけで、場面が狭い。いまの実装は上書きのときに印まで足し合わせ（`merge_term_data`）、索引だけの語が用語集にも載る、という分かりにくさも抱えていた。
- **代わりの手段**: 説明文はレビューファイルで書き直せる。ライブラリの説明文で入れ直したい語は、`[DELETE]` で辞書から消してから取り込み直す。
- 読みの補正（`YomiOverrides.merge!` の `prefer_import:`）も同じく、すでにある読みを残す一通りにする。

### 3.6 論点 6: 呼び名

ログ・ヘルプ・33 章・91 章を「棄却した語」にそろえる。

| 場所 | いま | 直した後 |
| :--- | :--- | :--- |
| ログ | `reject +3（スキップ 1）`、`書き出す用語集[g]・reject・読みがありません` | `棄却した語 +3（スキップ 1）`、`書き出す用語集の語・棄却した語・読みがありません` |
| ヘルプ | `用語集[g]・棄却語 を index_library.yml に書き出す` | `用語集の語・棄却した語・読みを index_library.yml に書き出す` |
| 33 章 | 「候補から外した語」「外した語の一覧」 | 「棄却した語」 |

## 4. 実装の範囲（論点を推奨どおりに決めた場合）

| 対象 | 変更 |
| :--- | :--- |
| `IndexLibrary#export_glossary` | `g` の語に加えて、説明文のある使っていない語を書き出す。説明文の無い語は書き出さない |
| `IndexLibrary#import_glossary` | 使っていない語（`flags: ''`・`source: imported`）として登録する。辞書にある語と、新しい本で棄却した語は飛ばす |
| `IndexLibrary#import_reject` | 棄却した語の一覧に `source: imported` を記録する |
| `UnifiedIndexManager#absent_entries` まわり | 5 節から `source: imported` の使っていない語・棄却した語を除く（論点 3 で b を添えるなら、語数の 1 行を出す） |
| `IndexImportCommand`・`IndexLibrary#import!`・`YomiOverrides.merge!` | `--prefer-import` と `prefer_import:` を外す（論点 5） |
| ログ・ヘルプ | 呼び名をそろえる（論点 6） |
| 33 章・91 章 | 取り込んだ語は使っていない語として待ち、原稿に書くと説明文を添えた候補に出ることを書く。`--prefer-import` の説明を消す。呼び名をそろえる |

`build_glossary!`（用語集のページ）は変えない。

### 4.1 すでに取り込んだ本

これまでの取り込みで `g` として入った語は、そのまま残る。原稿に出てこないものは、いまどおり 5 節に `[g]` で並び、そのまま apply すれば使っていない語になる。特別な移行は設けない。

### 4.2 テスト

- export: 使っていない語（説明文あり）を書き出す。説明文の無い語は書き出さない。
- import: 用語集の語が使っていない語として入り、用語集のページの対象（`glossary_terms`）に入らない。原稿に書くと、説明文を添えた候補として `vs index:auto` のレビューファイルに出る。
- import: 辞書にある語と、新しい本で棄却した語は飛ばす（印・説明文・読みが変わらない）。
- `--prefer-import` を使っていたテスト（`index_library_test.rb`・`yomi_overrides_test.rb`）は、オプションごと消す。
- 5 節: 取り込んだ使っていない語・棄却した語が並ばない。本で棄却した語は並ぶ。
- 往復: 本 A で export → 本 B で import（原稿に一部だけ出る）→ 本 B で export すると、本 B で使わなかった語の説明文も残る。

## 5. 実装記録

- **2026-10-03**: §4 の範囲を実装した。論点 1〜3・6 は推奨どおり（1=A・2=使っていない語も書き出す・3=a に語数の 1 行を添える）、論点 5 は `--prefer-import` の廃止（ユーザーの判断）。
  - `IndexLibrary`: `export_glossary` は説明文のある語（`g` の語と使っていない語）だけを書き出す。`import_glossary` は使っていない語（`flags: ''`・`source: imported`）として登録し、辞書にある語・取り込む前に棄却していた語・説明文の無い語を飛ばす。`import_reject` は `source: imported` を付ける。
  - `ReviewQueueManager#save_rejected_terms` が決まったキーしか残さず、取り込んだ `reason` が保存で落ちていた（元の仕様 §2.4 では保持するはずだった）。`source` と一緒に残すようにした。
  - 5 節: `auto_process!` で、使っていない語と棄却した語のうち `source: imported` のものを除き、語数を `absent_imported` で渡す。`build_absent_section` が「並べていません」の 1 行を出す。
  - `vs index:auto` の最後の報告の「棄却した語」が全件を数え、4 節の見出しと食い違っていた（`index-glossary-registration-spec.md` §3.3 で原稿に出てこない語を 5 節へ移したときの取り残し）。4 節に並ぶ語だけを数える。
  - ヘルプの手順と `ReviewMarkdownGenerator#generate!` のログが `[x]` で承認と案内していたので、いまの印に直した。91 章の早見表の `vs index:plan`（「候補の分布を表示」）も直した。
  - 検証: 本書の辞書を書き出し（用語集の語 53・棄却した語 87・読み 32）、21 章だけを置いた空の辞書のプロジェクトへ取り込んだ。53 語はすべて使っていない語になり、用語集の語は 0。`vs index:auto 21` で、原稿に出てくる「Markdown」が説明文つきで推奨する語に並び、5 節は「原稿に出てこない 94 語は並べていません」の 1 行だけになった。
- **採用した語の出どころ**: 取り込んだ語をこの本で採用しても、出どころが `imported` のまま残り、後で使っていない語に戻すと 5 節に並ばず `[DELETE]` で消せなかった。`UnifiedTermsManager#merge_term_data` で、`imported` の語に印が付いたら出どころを書き換える（レビューファイルで採用したら `review`、原稿の `[語]` で採用したら `manual_markup`）。索引の承認は新しい語を `auto_extracted` として渡すが、預かっていた語は機械が拾った語ではないので `review` にそろえる。印を足さない更新（主要参照だけの書き込み）では書き換えない。
