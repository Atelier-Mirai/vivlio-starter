# 画像の余白を切り詰めて大きく載せる（`trim=on`）・余白の多い画像を知らせる

> 状態: 実装済み（2026-10-15。§8 の論点 7 件はすべて推す案で決定。実装で分かったことは §9）
> 発端: 改善案.md #111（2026-10-14 決定: A＋C）。本書と雛形の画像を測って、残っていた値（fuzz・余白・知らせる割合）と方式を決める。

## 1. いまの姿

- SVG は `width="100%"` でも、`viewBox` の中に余白があると、その分だけ小さく載る。
  1 章「全体の流れ」の図は `viewBox="0 0 680 600"` のうち絵が幅の 83.2% しか使っておらず、10/14 に手で `31 21 583 567` へ詰めた（約 1.17 倍）。
- 余白を削る手段は `crop`（上・右・下・左。無単位はパーミル、`px` は元画像の画素）だけで、値は著者が測るしかない。
- `crop` は元画像を新しい SVG に `<image>` として埋め込み、その `viewBox` で窓を決める（`ShowcaseTransformer#crop_assets`）。
  **元が SVG でも埋め込む前に PNG へ焼く**（`ImageTools#data_uri` が `magick fig.svg png:-` を呼ぶ）。
  実測: `workflow.svg` に `crop` を付けると、583×567 px の PNG になって埋め込まれる。紙面の幅 162mm では約 91 dpi で、図の文字がぼやける。
  さらに出力は `img.vs-cropped` なので、SVG には付かないはずの既定の枠（0.5mm）が付く。

## 2. 測った結果（2026-10-15）

### 2.1 本書の画像

`images/` の 107 枚（SVG 31・WebP 75・PNG 1）を測った。SVG は透明な背景に描き、ラスターはそのまま、ImageMagick の trim の範囲（`%@`）を求めた。

- **幅の 92% 未満しか使っていない画像は 4 枚だけ**（fuzz 2%）。

  | 画像 | 幅の使用率 | 原稿での使われ方 |
  |---|---:|---|
  | `00-preface/kauplan.webp` | 80.0% | 前書きの `:::{.sideimage-right}` の中・`width=15%` |
  | `11-workflow/no_image.svg` | 82.1% | 画像が見つからないときの代わりの絵（原稿からは参照しない） |
  | `95-sample/evolution_of_physics.webp` | 87.3% | `data/physics_books.yml` の表紙（書籍紹介カード） |
  | `23-figures/vivlio_starter_guidebook.webp` | 89.0% | `:::{.book-card}` の表紙 |

- 手で詰める前の `workflow.svg`（`0 0 680 600`）は **83.2%**。絵の範囲は x 39.8〜605.2・y 29.8〜579.5 で、10/14 に手で測った値（x 39〜606・y 29〜580）と一致した。
- 写真（Einstein・note・kilogram など 1408×768 の 15 枚）は、四隅の色がそろわないので fuzz 3% までは 1 画素も削られない。
- ロゴ（`71-emoji/`）は幅の 92〜98% を使っている。横長のロゴには高さの 62〜88% しか使っていないものがあるが、上下の余白は幅で載せる図の大きさには効かない。
- 節見出しの帯（`42-frontispiece/*.svg`）は、全面の四角を外しても枠線（`stroke` 付きの四角）が全面に残るので、100% のまま。`trim=on` を付けても何も変わらない。

### 2.2 fuzz（どこまでを同じ色とみなすか）

紙面のスクリーンショットに見立てた画像（800×1129 の紙面＋白い余白 120×90）を、保存の形式を変えて測った。正しい範囲は `800x1129+120+90`。

| 画像 | fuzz 0% | 1% | 2% | 3% | 5% |
|---|---|---|---|---|---|
| PNG（可逆） | 正しい | 正しい | 正しい | 正しい | 正しい |
| WebP 品質 75 | 余白が 5〜9 px 残る | 1 px 残る | **正しい** | 正しい | 正しい |
| JPEG 品質 80 | 7 px 残る | 3 px 残る | **正しい** | 正しい | 正しい |
| JPEG 品質 60 | 7 px 残る | 2 px 残る | 2 px 残る | 2 px 残る | 正しい |
| 余白に ±7% の揺れ（スキャンした紙面相当） | 削れない | 削れない | 削れない | 削れない | 正しい |

fuzz を上げすぎると、絵の側を削る。

| 画像 | 削られる量 |
|---|---|
| `relativity.webp`（古い本の表紙の写真） | 3% までは 0、**5% で左右 8 px** |
| `feynman.webp`（写真） | 2〜3% で 1 px、5% で 3 px |
| `quantum.webp`（写真） | 5% までは 0、10% で幅の 18% |
| `vivlio_starter_guidebook.webp`（影の付いたカード） | 1% で 90.5%、2% で 89.0%、5% で 86.3%（影を削り始める） |
| `no_image.webp`（淡いグラデーションの背景） | 1% で背景を上下に削る（四隅の色と違う色を絵とみなすため） |

### 2.3 詰めた後に残す余白

| 案 | `workflow.svg` の余白 | 原寸に対する倍率 | 版面の全幅（A4・162mm）に載せたときの余白 |
|---|---:|---:|---:|
| 10/14 の手作業（8 単位） | 8.0 | 1.170 | 約 2.2mm |
| 幅の 1.5% | 8.5 | 1.168 | 約 2.4mm |
| **幅の 2%** | 11.3 | 1.157 | **約 3.1mm** |

23 章の SVG の雛形は「上下の余白は 12（3mm）」としている（全幅 640 に対して 1.9%）。幅の 2% はこれとそろう。

### 2.4 測る時間

107 枚を 1 回ずつ測るのに 15.5 秒（1 枚あたり約 0.15 秒。SVG は描く時間を含む）。

## 3. `trim=on` の規則

### 3.1 書き方

```markdown
![全体の流れ](workflow.svg){trim=on}
![](screenshot.webp){width=60% trim=on}
```

- 値は `on`／`off`。**既定は `off`**。`book.yml` の設定は置かない。
- 効く場所は `crop` と同じ。段落に単独で置いた画像（`:::{.sideimage-*}` の中のように、1 行に画像だけを書いたものを含む）と、`:::{.showcase}` の中の画像。
  文中に置いた画像には効かない。`:::{.book-card}` の表紙など、ほかの記法が消費する画像にも効かない。
- `trim=off` は既定と同じ動きだが、**余白を意図して残したという印**になり、§5 の 💡 を出さない。

### 3.2 範囲の測り方

1. SVG は、書体を寄せた派生（`DerivedSvg`。PDF と EPUB が実際に使う SVG）から §3.3 の背景の四角を外した写しを、`rsvg-convert` で**透明な背景に、長い辺 2000 px で、書籍の書体で**描く（§9.1）。ラスターはそのまま使う。
2. `magick <画像> -fuzz 2% -format '%@' info:` で、四隅の色を背景とみなした絵の範囲を得る。
3. 範囲を元画像の単位（SVG は `viewBox` の単位、ラスターは画素）へ戻し、上・右・下・左の削る量にする。
4. 四辺に、詰めた後の絵の幅の 2% の余白を足し戻す。ただし元の余白より大きくはしない（画像の外へは広げない）。

測った値は「`crop` に `px` で書いた値」と同じ意味を持つ。

### 3.3 SVG の全面の背景の四角

次のすべてに当てはまる `<rect>` を、測るときだけ取り除く。紙面ではそのまま残り、詰めた窓の大きさで切り取られる。

- `<defs>`・`<clipPath>`・`<mask>`・`<pattern>`・`<symbol>`・`<marker>` の中に**無い**（描かれない定義を外さないため。実測で節見出しの帯の `clipPath` の四角を拾った）。
- `viewBox` の全面を覆う（`x`・`y` が `viewBox` の原点で `width`・`height` が `viewBox` と同じ、または `100%`）。
- 塗りがある（`fill="none"` でない）。
- 線が無い（`stroke` が無いか `none`）。線のある四角は枠なので、絵として残す。

### 3.4 SVG は `viewBox` を書き換える

SVG は `<image>` に埋め込まず、写しの `viewBox` を詰めた窓へ書き換える（10/14 に手でしたことと同じ）。ベクタのまま、書体も Type 3 対策もそのまま運べる。

- 出力は `<img src="…svg">`。`vs-cropped` を付けないので、枠の有無は元の SVG と同じ（既定で枠なし。`border=on` で付く）。
- ルートの `width`・`height`:
  - `width="100%"`（雛形の書き方）はそのまま。詰めた分だけ大きく載る。
  - 絶対値（`width="600" height="400"` など）は、`viewBox` の縮みと同じ比で縮める。描く縮尺は変わらず、余白だけが消える。
  - どちらも無ければ足さない（今の振る舞いを変えない）。
- **書体を抱かせる。** PDF の画像の差し替え（`PdfBuilder#swap_images_for_pdf!`）は `asset_prefix` で始まる参照だけを `DerivedSvg` へ回し、ビルドの生成物は外す。
  詰めた SVG は生成物になるので、そのままでは書体が SVG に入らず、Type 3 が戻る。生成するときに `DerivedSvg` を通す（または差し替えの対象に入れる）。
  受け入れ条件は、全章ビルドで Type 3 が 0 件のままであること。
- EPUB は今の SVG と同じ経路を通る（クリーン EPUB は `DerivedSvg` の派生、Kindle は `stage_author_svg_for_epub!` で焼く）。

### 3.5 ラスターは `crop` の経路に渡す

PNG・WebP・JPEG は、§3.2 の値を `crop` の値（`px`）として `ShowcaseTransformer#crop_assets` に渡す。著者が同じ値を `crop` に書いた場合と、出力は 1 バイトも変わらない。

### 3.6 `crop` と一緒に書いたとき

`crop` を優先し、`trim` は使わない。`crop` は図の一部だけを見せる指定で、`trim` で範囲を広げ直すと著者の意図を崩すため。

```text
🟡 23-figures.md:120 画像に crop と trim=on の両方があります。crop を使い、trim=on は使いません
   → 切り抜く範囲を自分で決めるなら trim=on を消してください: ![](fig.webp){crop="30 100"}
```

### 3.7 効かないとき

| 状況 | 動き |
|---|---|
| 余白が無い（削る量が四辺とも 0） | 元の画像をそのまま使う。知らせない |
| 画像が一色だけ（範囲が求まらない） | 元の画像をそのまま使い、🟡 で知らせる |
| `magick`・`rsvg-convert` が無い | 元の画像をそのまま使い、🟡 で `vs doctor --fix` を案内する（`crop` と同じ文面） |
| 外部 URL の画像 | 元の画像をそのまま使い、🟡 で知らせる（`crop` と同じ） |
| 範囲の測り方が合わない画像（グラデーションの背景・揺れの大きいスキャン） | 測ったとおりに詰める。結果が意図と違えば、著者が `crop` に切り替える（23 章に書く） |

### 3.8 キャッシュ

- 測った値は `GeneratedAssetCache`（`.cache/vs/trim/`）に、画像の中身のハッシュ・fuzz・余白の割合・版をキーにした小さな JSON で残す。§5 の 💡 も同じ値を使う。
- 詰めた SVG も同じキーで残す。PDF・EPUB・Kindle は同じ 1 枚を使う。
- 著者の原本には触れない。

## 4. `crop` を SVG に使ったときも `viewBox` を書き換える

§1 のとおり、今の `crop` は SVG を PNG に焼いて埋め込み、文字がぼやけ、既定で付かない枠が付く。
SVG への `crop` も §3.4 と同じ `viewBox` の書き換えにそろえる。

- 本書と雛形に、SVG へ `crop` を書いた箇所は無い（2026-10-15 に確かめた）。今の原稿の紙面は変わらない。
- `:::{.showcase}` の中の SVG は、注釈を重ねるために今までどおり埋め込む（変えない）。

## 5. 余白の多い画像を知らせる（`vs preflight` の 💡）

- 対象は §3.1 で `trim=on` が効く画像のうち、`trim`・`crop` のどちらも書いていないもの。`trim=off` と書いた画像は外す。
- **絵が画像の幅の 85% 未満しか使っていない**とき、1 画像につき 1 回知らせる。高さは見ない（幅で載せる図の大きさには効かないため）。
- 知らせは 💡 で出す。終了コードにも、🟡 の件数にも数えない。既定のログの水準（`warn`）でも表示する。
- 文面には、出現箇所・使用率・詰めたときの倍率・before → after を添える。

```text
💡 11-workflow.md:58 workflow.svg は、絵が画像の幅の 83% しか使っていません。余白を詰めると約 1.16 倍で載ります
   → ![](workflow.svg) を ![](workflow.svg){trim=on} に
     （余白を意図して残すときは {trim=off} と書くと、この知らせは出ません）
```

- 本書で知らせる画像は、2.1 の表から `kauplan.webp`（80%）の 1 枚の見込み。
- 時間: 初回は対象の画像の数 × 約 0.15 秒（本書は単独の画像が 37 か所。同じ画像の重複を除くとそれ以下）。2 回目からは §3.8 のキャッシュで測らない。

## 8. 論点（2026-10-15 にすべて推す案で決定）

| # | 論点 | 推す案 | 根拠 |
|---|---|---|---|
| 1 | fuzz | **2% 固定**（著者は変えられない） | WebP・JPEG の圧縮の揺れは 2% で消え、写真は 3% まで削られない（§2.2）。スキャンの揺れ（5% 要る）は `crop` で扱う |
| 2 | 残す余白 | **詰めた後の幅の 2%** | 全幅で約 3mm。23 章の雛形の上下の余白（12＝3mm）とそろう。10/14 の手作業（8 単位）に近いのは 1.5%（§2.3） |
| 3 | 知らせる割合 | **85% 未満** | 85% で詰めると約 1.13 倍。本書では 1 枚（§2.1）。90% にすると `guidebook`（89%）・`evolution_of_physics`（87%）も入る |
| 4 | `crop` を SVG に使ったとき | **`viewBox` の書き換えにそろえる**（§4） | 今は PNG に焼かれて約 91 dpi・既定外の枠が付く。原稿への影響は無い |
| 5 | `crop` と併記したとき | **`crop` を優先し 🟡**（§3.6） | 改善案.md #111 の案のまま |
| 6 | `:::{.showcase}` の中の `trim=on` | **受け付ける** | `crop` を受け付けており、`trim` は `crop` の値を測るだけなので追加の仕組みが要らない。座標は元画像の基準のままなので注釈もずれない |
| 7 | 💡 を黙らせる手段 | **`{trim=off}`** | 余白を意図した図（雛形どおりの図）で毎回知らせないため。新しい記法を足さずに済む |

## 9. 実装記録（2026-10-15）

### 9.1 SVG の字は、紙面と同じ書体で描いて測る

最初は SVG をそのまま `rsvg-convert` で描いて測った。試しのプロジェクトで、`width="600" height="400"` の SVG（`font-family="Arial, sans-serif"`・72px の太字の欧文）に `trim=on` を付けると、**紙面で字の上と左右が切れた**。

- PDF と EPUB は、書体を寄せた派生（`DerivedSvg`）を使う。この図では `Noto Sans JP, Arial, sans-serif` に書き換わり、Noto Sans JP で組まれる。
- macOS の rsvg は、既定で CoreText を使う。**書体名を見ずに、どの名前でも同じ OS の書体で描く**（`Arial`・`Noto Sans JP`・存在しない名前で、範囲が 1 画素も変わらなかった。違ったのはヒラギノ角ゴだけ）。fontconfig に書体のフォルダを足しても効かない。
- 紙面（Chromium で描いた派生）と比べると、字は幅で 7%（986 → 1,057 画素）、上へ 12 単位はみ出していた。残す余白（幅の 2% ≒ 10 単位）では足りない。

`PANGOCAIRO_BACKEND=fc` で pango を fontconfig 経由の描き方に切り替え、`FONTCONFIG_FILE` に「OS の既定の設定＋`stylesheets/fonts/`」を渡すと、rsvg が書籍の書体で描くようになった。

| 描き方 | 範囲（2 倍の画素） |
|---|---|
| 紙面（Chromium・派生の書体） | `1057x393+70+201` |
| rsvg（既定） | `986x376+105+226` |
| rsvg（fontconfig 経由・派生） | `1049x393+74+213` |

左右の差は 2 単位に縮んだ。上下は 6 単位ずれたままだが、余白の内側に収まる。和文中心の 1 章の図は、既定の描き方でも Chromium と 1 画素差で一致していた（和文の字は書体を問わず 1 字 1em のため）。

- `FONTCONFIG_FILE` は**絶対パスで渡す**。相対パスは作業ディレクトリでなく fontconfig の設定の置き場から引かれ、見つからないと黙って OS の既定へ落ちる。
- 測った値のキーに書籍の書体の設定を入れた（書体を変えたら測り直す）。
- Chromium で直接測る案も試した。起動だけで 1 回約 10 秒かかり、画像ごとに測る道具には向かなかった。

### 9.2 詰めた SVG の経路

- 詰めた SVG は `html/images/trim/<章>/<キー>.svg` に置き、`<img>` に `data-vs-source`（`.cache/vs/trim/` の実体）を付ける。PDF の差し替え（`PdfBuilder#swap_images_for_pdf!`）は `data-vs-source` を先に見るので、生成物でも `DerivedSvg` が書体を抱かせる。試しのプロジェクトの全ターゲットのビルドで Type 3 は 0 件だった。
- EPUB は消費者 dir へ写すときに `data-vs-source` を外す（`EpubBuilder.stage_consumer_htmls!`）。クリーン EPUB は詰めた窓の派生 SVG を使っていた（パッケージを開いて `viewBox` を確かめた）。Kindle は焼いた画像を使う。KPF は開いて確かめておらず、変換の警告が増えなかったことだけを確かめた（W14016×1 は詰める前から出ていた）。
- ラスターの `crop` は、値をそのまま `crop_assets` へ渡す（既存のテストの差し替えの位置を変えないため、分かれ目は拡張子で決める）。
