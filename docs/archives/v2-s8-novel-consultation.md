## 2. 問い

### 2.1 S8 の範囲・小段階・S7 との順

S8 は、縦組みの本文（テーマと部品）と、2.0 に含める 5 件の全部を抱えています。5 件のうち `vs furigana` と背表紙・くるみ表紙は、縦書きと独立に作れます（`vs furigana` は絵本でも使う。背表紙は技術書の分冊でも要望がある）。

決めてほしいこと:

1. S8 の小段階の表（`theme-contract-spec.md` §9 の S6 の表と同じ「小段階・作るもの・確かめ」の 3 列）。S6 と同じく、各小段階の完了のコミットが本書（技術書）の出力を r3 と同じに保つかどうかも、小段階ごとに書いてください（物理方向の書き直しは画素が変わらないはず、`bunko` の追加は本書に触れないはず、など）。
2. 5 件のうち、S8 から外して別の段階（S8 の後・S9 の中・S11 の前など）に回すものがあるか。
3. S7 と S8 の順。S7 の入口の実験（`theme-bunko` を vs の HTML に当てる）の結果は、`bunko` を書くときの手本の読み方に役立つ一方、S8 を止めないと決めてあります。どちらを先にするか。

### 2.2 小説の既定のテーマ（`theme-contract-spec.md` §10 の論点 1・4・5）

1. **名前。** 仮の名前は `bunko`。公式の `theme-bunko` を取り込んだテーマ（S7 で `vs theme:add @vivliostyle/theme-bunko` が作るもの）と、本の `themes/` の中で名前がぶつかります（取り込んだ側のディレクトリの名前は `theme.yml` の `name:` から決まる。S6-8 の `theme:add` の決め）。
2. **中身。** `styles:` の CSS の分け方、`options:`（著者が `book.yml` の `theme:` で変えられる項目。たとえば章扉の形・柱の有無・段落の字下げ）、`features:`（`frontispiece`・`ornament` は使わない見込み。小説に要る組み込みの機能があるか。挿絵の配置などを機能として足すか）、`supports:`（`writing_mode: [vertical]` だけか、横書きの小説にも対応するか）、`tokens:`（`standard` との値の違い。§4 の「中立の既定値と `standard` の値を分けるのは、2 つ目の組版のテーマが値を決めるとき」の決め）。
3. **部品の扱い（論点 5）。** vs の部品（`parts` 層。見出し・段落・囲み・コード・表・脚注・相互参照など）のうち、小説の本が読むもの。縦書きで崩れる部品を「直す」「`bunko` で打ち消す」「`standard` へ移す」「縦書きでは使えないとして lint か検査で知らせる」のどれにするか。`parts/preface.css` が `standard` へ移すいちばんの候補とされています。
4. **ページの種類。** 縦書きで、目次・奥付・本扉・権利ページ・部扉・前書き・後書きを、どう組むか（縦か横か）。索引と用語集は `novel` では無効だが、著者が有効にした場合の扱い（縦書きの索引を作るか、🔴/🟡 で止めるか）。
5. **節の改ページの既定**（`v2-s6-10-consultation.md` §4.3 から送られた点）。小説は節で改ページしないのが普通です。`bunko` の `tokens:` に `section-break-before: auto` を書くと、雛形の `book.yml` の `page.section_pagebreak: true`（今の決まりでは何も書き出さない）が効かなくなります。`BookProfile` の `novel` で `section_pagebreak: false` を既定にするか、`true` のときも値を書き出すように決まりを変えるか、など。
6. **`theme-epub3j` を土台にしたテーマを同梱するか（論点 4）。** 電書協の様式を求める著者向け。

### 2.3 判型のプリセット（`v2-architecture-spec.md` §9 の論点 2）

今の `config/page_presets.yml` は、A5・B5・A4 のそれぞれに `standard`・`airy`・`compact`・`custom` を持ち、値は基準の字の大きさ・行送り・字間・天地ノド小口の余白です。文庫・新書・四六・B6 は無く、`BookProfile` の `novel` の `page.use: a6_standard` は形を示すための仮の値です。`theme-bunko` は、判型を行数と字数から `calc()` で求めます（`theme-contract-spec.md` §6.1）。

決めてほしいこと:

1. 小説のために足すプリセット（判型と名前）と、`novel` の既定。
2. 縦書きの版面を、今の形（字の大きさ・行送り・余白）で決めるか、行数と字数で決める形を足すか。足す場合のキーの形と、`page_presets.yml` との関係（横書きの技術書にも開くか）。
3. 余白の名前。今の `margin_top`・`margin_bottom`・`margin_inner`・`margin_outer`（天・地・ノド・小口）は、縦書きでもそのまま意味が通るか。

### 2.4 縦書きの記法の細目

1. **縦中横の自動。** architecture §7.1 は「本文の中の半角の数字 1〜2 桁と `!?`・`!!` を `span.tcy` で包む。桁数の上限と対象の字は小説の仕様で確定する」としています。桁数の上限（3 桁・4 桁の西暦をどうするか）・対象の字（`!?`・`!!`・`??`・全角の数字・英字の略語）・除外（コード・数式・ルビの読み・`span.tcy` の中・URL・見出しの番号）。全角の数字を本文で使うか半角に寄せるかの表記の方針（lint で扱うか）も含めて。
2. **投稿サイトの記法の範囲。** 受けるのは `|漢字《かんじ》`（縦棒あり）と傍点 `《《…》》` と決まっています。縦棒の無い `漢字《かんじ》`（直前の漢字の並びに掛かる）、`（かんじ）` を使うルビ、なろうの傍点の書き方（ルビに `・` を並べる）、全角の縦棒 `｜` を受けるか。vs の今の記法（`{漢字|かんじ}`・`[用語]` の索引・`《` を地の文に書く場合）とぶつかる場合の扱い。
3. **小説の lint の 4 規則の向き。** とくに「段落の頭を字下げする」。vs は CSS で段落の頭を 1 字下げる（`parts/prose.css` の `p { text-indent: 1em; }`）ので、原稿に全角空白を書くと 2 字下がります。一方、投稿サイトの原稿は全角空白で字下げしてあり、会話文（`「` で始まる段落）は字下げしないのが慣習です。lint が「全角空白が無いこと」を見るのか「あること」を見るのか、会話文の段落の字下げを CSS とテーマでどう扱うか（`theme-bunko` は `「` で始まる段落の字下げをどうしているか）、投稿サイトの記法を読む前処理が先頭の全角空白を落とすか、を一緒に決めてください。残りの 3 規則（「……」「――」の二つ重ね・「！」「？」の後の全角空白・閉じ括弧の前の句点）の誤検出を避ける条件（文末の `！」` や、`？` の直後が閉じ括弧のとき）も。

### 2.5 `vs furigana`

`furigana-level-spec.md` は対象の水準（L0〜L4・学年）だけを決め、読みの生成は「`vs furigana` の仕様書で決める」としています。`PLANNED.md` の項に、半自動にする理由（MeCab が稀な漢字ほど誤読する）・補助辞書の種（交ぜ書き辞書から表外漢字の読み 125 字）・安全性（二重化しない・`--dry-run`・退避）が書かれています。

決めてほしいこと:

1. S8 で作るか、別の段階か（§2.1 の 2）。
2. 作る時期に関わらず、仕様書を別に立てるか、小説の仕様の 1 節にするか。
3. 骨格: 基準の水準の指定（`book.yml` のキーか引数か）・読みの出どころの順（MeCab・補助辞書・著者の辞書）・語単位か字単位か・初出だけに振るか全部に振るか（章ごとの初出など）・確かめの一覧の形（`vs index:auto` のようなレビューのファイルにするか）。

### 2.6 背表紙とくるみ表紙

今の表紙は `covers/` の表 1（表紙）・表 4（裏表紙）の画像か、テンプレートから作る SVG で、巻ごとに作れます（`cover_spec.md`・`cover_auto_generation_spec.md`・分冊は `multivolume-spec.md`）。背表紙を作る機能は無く、くるみ表紙（表 4＋背＋表 1 を 1 枚に）も非対応です（`PLANNED.md`）。architecture §7.1 は「`build cover spread` の段・背幅はページ数と紙の厚さから求める・紙の厚さは `book.yml` のキー・個別の仕様で決める」としています。

決めてほしいこと:

1. S8 で作るか、別の段階か（§2.1 の 2）。仕様書を別に立てるか。
2. 骨格: 出力の形（くるみ表紙を `print_pdf` と一緒に出すか、別の出力先・別のコマンドにするか）・背幅の求め方（ページ数 × 紙の厚さ＋表紙の厚さ。入稿先ごとの値を著者が書く形）・塗り足しと背の文字（縦書きの書名と著者名）・右綴じの並び（表 1 が右）・分冊。
3. 技術書（横書き・左綴じ）でも使えるようにするか。

### 2.7 確かめ方

技術書の段階は、本書の出力を基準と比べることで完了を確かめてきました。小説には基準がありません。

決めてほしいこと:

1. S8 の完了の条件（architecture §8 の S8 は「`scaffolds/novel/` の本が四つの出力先で組め、Kindle が KPF になる（Enhanced Typesetting が Supported）。紙面の条件は小説の仕様に書く」）の「紙面の条件」の中身。何を見て「組めた」とするか（目で見る箇所の一覧・Vivliostyle の作例との見比べ・`pdftotext` や画素での検査など）。
2. 小説の基準を作るか。作るなら、何を（`scaffolds/novel/` の本の四つの出力先）・いつ（S8 のどの小段階の後）。S9 以降に小説の出力を守る手段になる。
3. `scaffolds/novel/` の本の原稿。著作権の切れた作品（青空文庫）を使うか、架空の短い原稿を書くか。挿絵・ルビ・傍点・縦中横・会話文・投稿サイトの記法・前書きと後書きを含める範囲。
4. 本書（技術書）の出力を守る確かめ（物理方向の書き直しなど）を、どの小段階で r3 と比べるか。

## 3. 答えの形

- §2 の各問いの決定と理由を、`v2-s6-consultation.md` §4 と同じく、この文書の末尾に「答え」の節として書く。
- 答えは、小説の仕様書（新しい文書。名前は Fable が決める。案は `novel-vertical-spec.md`）の骨格として、Opus がそのまま節へ移せる形にする。仕様書に入れる節の並び（目次）を最初に示し、各決定がどの節に入るかを書く。

### 4.4 縦書きの経路（問い 2.2 の 4 の一部・2.8）

- **組方向を書くのは vs で、テーマではない。** テーマは `supports:` で対応する組方向を宣言するだけにする。組方向は軸（`page.writing_mode`）で、テーマを替えても変わらない値だからである。
- **書く場所は `stylesheets/base/vertical.css`（base 層）で、`EntryWriter` が、`traits.vertical?` の本の「縦に組むページの種類」の入口にだけ入れる。** 中身は `:root { writing-mode: vertical-rl; }` と、EPUB 向けの接頭辞つきの同じ宣言（`-webkit-writing-mode`・`-epub-writing-mode`）である。`book-settings.css` に書かないのは、全部の種類が同じ 1 枚を読み、settings 層がページの CSS（pages 層）に勝つので、横に組むページで打ち消せないためである。入口は種類ごとに作っているので、入れる・入れないで分けるのがいちばん単純で、詳細度の取り合いが起きない。

| ページの種類 | 縦書きの本での組方向 | 理由 |
| :--- | :--- | :--- |
| 章・付録・前書き・後書き・本扉・部扉・目次・全巻目次 | 縦 | |
| 奥付・権利ページ | 横 | URL・英数字・版の表記が中心で、縦書きの本でも横に組むのが普通である。今の CSS がそのまま使える |
| 索引・用語集 | 作らない | 縦書きの本の索引は、横組みにして巻末から逆向きに綴じる形が要り、2.0 では扱わない。`page.writing_mode: vertical` と `index_glossary.enabled: true` の組み合わせは、`TraitCombinationCheck` が 🟡 で「縦書きでは索引と用語集のページを作りません」と示し、段を止める（固定レイアウトの行と同じ形） |

- **余白の箱（柱とノンブル）は、`base/page.css` の余白の箱の規則に `writing-mode: horizontal-tb` を足す。** 横書きでは何も変わらないので、条件を付けずに書く。ノンブルは算用数字のまま横に組む。漢数字にはしない。
- **OPF** は `v2-architecture-spec.md` §2.4 の表のとおり（`spine` の `page-progression-direction="rtl"`、Kindle は `primary-writing-mode` の `meta`）。
- **EPUB と Kindle 向けの接頭辞つきの書き方**（`-webkit-text-combine`・`-webkit-text-emphasis` など）は、`parts/inline.css` に、標準の書き方の前の行として手で書く。生成で足す仕組みは作らない（対象が 3 つのプロパティだけのため）。
- **Kindle で論理方向が正しく解されるか（`css-layer-restructure-spec.md` §9 の論点 2）** は、S8-4 の材料の本を KPF にして見る。崩れる箇所が少なければテーマと `targets/kindle.css` に物理方向で書き、多ければ `LiteralResolver` で書き直す。境目は「手で書く箇所が 20 を超えるか」とし、超えたら相談する。
- **確かめが要る点。** `v2-feasibility-notes.md` §3.1 の実験は `html { writing-mode }` で行った。1 冊の中に縦の文書と横の文書（奥付）が混ざる形は確かめていない。S8-4 の最初に、材料の本で、奥付が横に組まれ、ページの進む向きと奇数ページの側が前後の文書と同じであることを見る。崩れる場合は、奥付と権利ページも縦に組み、中の英数字の箱だけを `horizontal-tb` にする。

### 4.5 小説のテーマ `novel`（問い 2.2）

**名前。** `novel` にする。`bunko` は文庫という判型の名前で、このテーマは新書や四六判でも使う。公式テーマを取り込んだものとも区別がつく。公式テーマの側は、パッケージの名前 `@vivliostyle/theme-<x>` から `vivliostyle-<x>` を作る（`theme-contract-spec.md` §6.2・S7 の仕様に足す）。`BookProfile` の表と `theme-contract-spec.md` §4 の「種類ごとの既定のテーマ」の表の `bunko` を `novel` に替える。

**形。**

```yaml
# themes/novel/theme.yml
name: novel
title: 小説（縦書き）
version: 2.0.0
contract: 1
supports:
  writing_mode: [vertical]
  layout: [reflowable]
features: []
tokens:            # standard と違う値だけ（下の表）
styles:
  - prose.css      # 段落・会話文・引用・区切り・挿絵
  - headings.css   # 章題・節題・本扉・目次の見た目
  - page.css       # 柱とノンブルの見た目
```

- **`supports.writing_mode` は `[vertical]` だけ。** CSS は論理方向で書くので横書きにも開けるが、2.0 では確かめる面を増やさない。横書きの小説は、`book.type: novel`・`page.writing_mode: horizontal`・`theme.name: standard`・`theme.style: simple` で組める（`v2-architecture-spec.md` §2.3 の「種類の既定値から軸を一つ変えた本」）。
- **`features:` は空。** 挿絵は CSS だけで組めるので、機能にしない。
- **`options:` は最初は置かない。** S8-5 で紙面を見て、著者が変えたくなる項目が出たら足す。候補は柱の中身（章題・書名・無し）だけである。色は `custom.css` と配色のテーマで変えられる。迷う項目は足さない（足すのは後からできるが、消すのは契約の変更になる）。
- **出力先の CSS**（`epub.css`・`kindle.css`）は、要る規則が出たときに置く。
- **会話文の字下げ**は、手本の `theme-bunko` が `hanging-punctuation: first allow-end` で行っている。この書き方は EPUB と Kindle に届かないので、`novel` は使わず、4.7 の括弧の段落の印（`p.vs-open-bracket`）に `text-indent: 0` を当てる。開き括弧の字は左半分（縦では上半分）が空いているので、見た目は二分下げになり、三つの出力先で同じになる。行末の句読点のぶら下げ（`allow-end`）は PDF だけに `prose.css` で書いてよい（届かない出力先では、ぶら下がらないだけで崩れない）。

**`tokens:`。** `stylesheets/tokens.css` の中立の既定値は動かさない。`novel` は違う値だけを書く。値は S8-5 で紙面を見て決めるが、向きは次のとおりとする。

| 変数 | `novel` の向き |
| :--- | :--- |
| 見出しの書体 | 本文と同じ明朝（太さで区別する） |
| テーマ色と見出しの色 | 黒に近い色（飾りの色を使わない） |
| 行送り | 判型のプリセットの値をそのまま使う（テーマでは書かない） |
| 章リードの倍率・見出しの印 | 使わない（印は空の文字列） |

**部品の 3 段（論点 5）。** 小説の本文の入口は、技術書と同じ部品の束を読む（読む部品を種類で減らさない。小説にコードを載せる著者を妨げない）。そのうえで、縦書きで何を保証するかを 3 段に分ける。

| 段 | 部品 | 扱い |
| :--- | :--- | :--- |
| 縦で保証する | 段落・見出し・ルビ・傍点・縦中横・強調・リンク・引用・区切り線・箇条書き・脚注・`@pagebreak`・相互参照の印・章リード・節リード | S8-1 で論理方向へ直し、S8-5 で `novel` の見た目を決める。4.11 の目で見る箇所に入れる |
| 横組みの箱として置く | 図と挿絵・表・コード・数式（ブロック）・Mermaid の図・囲み（`.note` など）・出力例 | 箱に `writing-mode: horizontal-tb` を指定する（`stylesheets/base/vertical.css` にまとめて書く）。保証は「箱の中が横組みで崩れずに読める」まで。箱の幅と高さの上限は版面に合わせる。行内のコードと行内の数式は、横倒しのまま（欧文と同じ扱い） |
| 縦書きでは使えない | 左右に並べる記法（side-by-side）・会話のアバター・book-card・表の回転・行番号つきのコードの折り返しの印 | 原稿に書いてあれば 🟡 で場所を示す（原稿の場所を指す指摘）。組み上がりは保証しない。一覧は S7 の入口の実験と S8-4 の材料の本で確かめて確定し、仕様書の表にする |

- **脚注**は、Vivliostyle の `float: footnote` のまま使う。縦書きではページの左端（行の進む先の端）に組まれる。合印と注番号は縦中横にする（`theme-bunko` と同じ）。EPUB と Kindle は今の脚注の変換のまま。S8-4 の材料の本で、3 つの出力先の脚注を見る。
- **前書きの飾り（`parts/preface.css`）は `standard` へ移す**（S8-5）。小説の前書きと後書きは本文と同じ見た目で組むので、部品に残すと `novel` が全部を打ち消すことになる。移すのは飾りの規則だけで、構造の規則（S2-4 でそろえた部分）は部品に残す。ほかの部品の飾りは、`novel` を書いて打ち消しが要ったものだけを移す。移した規則は仕様書の表に記録する。
- **目次**は縦に組み、ページ番号は算用数字を縦中横にする（3 桁まで 1 字分に収める。`text-combine-upright: all`）。相互参照が作る番号（「第 3 章」など）も同じにする。

**`theme-epub3j`（論点 4）は同梱しない。** 電書協の様式は EPUB の作り全体（ファイルの分け方・OPF・クラスの体系）の決まりで、CSS を土台にしても「電書協の様式の EPUB」にはならない。vs が合わせるのはクラス名（`tcy`・`sesame`）までとする。要望が出たら、S7 の経路で `vs theme:add @vivliostyle/theme-epub3j` として取り込める。

### 4.6 判型のプリセットと `BookProfile`（問い 2.3・2.2 の 5）

**足す判型。** `Common::PAGE_SIZES` に 4 つ足し、`page_presets.yml` に次のプリセットを足す。

| プリセット | 判型 | 寸法 | 目安（字数 × 行数。縦書き） |
| :--- | :--- | :--- | :--- |
| `a6_standard`・`a6_custom` | 文庫（A6） | 105 × 148 mm | 9pt・38 字 × 15〜16 行 |
| `b6_standard`・`b6_custom` | B6 | 128 × 182 mm | 9.5pt・42 字 × 17 行前後 |
| `shinsho_standard` | 新書 | 103 × 182 mm | 9pt・2 段にしない。44 字 × 15 行前後 |
| `shiroku_standard` | 四六 | 127 × 188 mm | 9.5pt・43 字 × 17 行前後 |

- `novel` の既定は `a6_standard`。同人誌の小説でいちばん多い判型で、`v2-architecture-spec.md` §2.2 の仮の値のままである。
- 値（字の大きさ・行送り・四つの余白）は、S8-3 で Opus が上の目安から求め、S8-5 で `novel` を当てた紙面をユーザーが見て確定する。求め方は「天と地の余白の和 ＝ 紙の高さ − 字の大きさ × 字数」「ノドと小口の和 ＝ 紙の幅 −（行送り ×（行数 − 1）＋ 字の大きさ）」で、版面が字の大きさの整数倍になるように余白を決める。ノドは 13mm 以上にする（無線綴じで読める幅）。`airy`・`compact` は小説には置かない（行数を変えたい著者は `*_custom` を使う）。

**版面の決め方は今の形のままにし、行数と字数のキーは足さない。**

- 紙の寸法が決まっていれば、「字数と行数」と「余白」は同じ値の二つの言い方である。両方をキーにすると、どちらが勝つかの決まりが要り、著者が片方だけを直して食い違う。
- 印刷所が確かめるのは余白（とくにノド）なので、正典は余白の側に置く。
- `theme-bunko` が行数と字数から求めるのは紙の寸法のほう（紙が版面にぴったりの大きさになる）で、vs の「紙の寸法は判型で決まる」とは向きが逆である。
- 代わりに、縦書きの本では、`vs build --log` と `vs preflight` が版面の字数と行数を 1 行で示す（💡「版面: 38 字 × 16 行」）。`*_custom` で余白を変えた著者が、結果を数で確かめられる。字数が整数にならないとき（端数が 0.2 字以上）は、同じ行で天地の余白の直し方を示す。
- 行数と字数で指定するキーは、要望が出たら足す。`PLANNED.md` に 1 行残す。

**余白の名前は変えない。** `margin_top`・`margin_bottom`・`margin_inner`・`margin_outer`（天・地・ノド・小口）は紙の上の位置の名前で、組方向に依らない（`css-layer-restructure-spec.md` §6 の表の 1 行目と同じ理由）。

**`BookProfile` の `novel` に足す行。**

```ruby
%i[page use]                => 'a6_standard',
%i[page section_pagebreak]  => false,
%i[page chapter_pagebreak]  => 'any',
%i[theme name]              => 'novel',
```

- 節の改ページは、テーマの `tokens:` ではなく種類の既定値で決める。`v2-s6-10-consultation.md` §4.3 の食い違い（著者が `true` と書いてもテーマの値が通る）が起きず、「書かない条件では宣言しない」の決まりも変えずに済む。`novel` の雛形の `book.yml` には `section_pagebreak: false` を書く（「載せると決めたキーは全部書く」）。
- `chapter_pagebreak: any` は、小説の章が改ページ（面を問わない）で始まるのが普通なためである。改丁にしたい著者は `recto` と書く。

### 4.7 記法（問い 2.4 の 1・2 と 2.8）

**挿絵。** 新しい記法は 1 つだけ足す。

| 書き方 | 契約 HTML | 組み方 |
| :--- | :--- | :--- |
| `![題](images/x.png)`（今と同じ） | 今の `figure` | 横組みの箱として行の間に置く。幅の指定（`width=50%`）は箱の中の横幅として働く |
| `![題](images/x.png){.full-page}` | `figure.vs-full-page` | 1 ページを使う。前後で改ページし、版面の中央に、縦横比を保って収める（`object-fit: contain`）。キャプションは出さず、代替テキストにする |

- `figure.vs-full-page` は vs の部品（`parts/figure.css`）に置き、どのテーマでも働く。横書きの本でも使える。クラス名は、S8-2 で今のクラスと衝突しないことを確かめて確定する。
- 塗り足しまで使う全面の挿絵（裁ち落とし）は 2.0 では作らない。絵本の固定レイアウト（S9）の領分である。

**縦中横の自動**（L3 の後処理の一段。条件は `traits.vertical?`）。

| 対象 | 扱い |
| :--- | :--- |
| 半角の数字 1〜2 桁（前後が半角の英数字・小数点・桁区切りでない） | `span.tcy` で包む |
| 半角の `!?`・`?!`・`!!`・`??`（ちょうど 2 字） | `span.tcy` で包む |
| 半角の数字 3 桁以上 | 包まない（横倒しのまま組まれる）。lint が全角か漢数字への書き換えを勧める（4.8 の規則 5） |
| 全角の数字・全角の「！」「？」 | 触らない（もともと 1 字ずつ立つ） |
| 半角の英字 | 触らない（欧文として横倒しに組む。1〜2 字の略語を立てたいときは、手で `[AI]{.tcy}` と書く） |

- 対象にしない場所: コード・数式・ルビの読み（`rt`）・`span.tcy` の中・`a` の中の URL の文字・横組みの箱として置く部品（4.5）の中・奥付と権利ページ。
- 見出しと目次の中も対象にする。
- 入り切りのキーは置かない。包みたくない箇所は全角で書けば済む。

**投稿サイトの記法**（前処理 `transform_web_novel_marks!`。条件は `features.web_novel`）。

| 書き方 | 置き換え先 | 条件 |
| :--- | :--- | :--- |
| `|漢字《かんじ》`・`｜漢字《かんじ》` | `{漢字|かんじ}` | 縦棒から `《` までが親文字。親文字と読みの字の種類は問わない |
| `漢字《かんじ》`（縦棒なし） | `{漢字|かんじ}` | 親文字は `《` の直前の漢字の並び（`々`・`〆`・`ヶ` を含む）。**読みが平仮名・片仮名・長音だけのとき**に限る（小説家になろうの自動のルビと同じ条件） |
| `《《文字》》` | `[文字]{.sesame}` | カクヨムの傍点 |
| `|《` ・`｜《` | `《`（ルビにしない） | 投稿サイトの打ち消しの書き方 |
| 段落の頭の全角空白 1 つ | 落とす | 字下げは CSS が行う（4.8 の「字下げ」） |

- 受けないもの: 括弧のルビ（`漢字(かんじ)`・`漢字（かんじ）`）。地の文の括弧と区別できず、誤って変わる箇所が多い。なろうの「ルビに `・` を並べる傍点」は、特別に扱わない（ルビとして組まれ、見た目は傍点に近い）。
- コードの中は置き換えない（`Masking`）。vs のルビ `{漢字|かんじ}` と索引の `[用語]` には触れない（縦棒の形は、`{` の中にある縦棒を親文字の始まりと読まない）。
- 地の文に `《` を書いて、前が漢字で中が仮名だけのときは、ルビになる。投稿サイトでも同じに読まれるので、「投稿サイトと同じに読む」を決まりにし、避けるには `|《` と書く、と文書に書く。
- 置き換えは原稿を書き換えない（ビルドの中だけ）。`vs lint` も、置き換えた後の文で見る。

### 4.8 小説の lint と字下げ（問い 2.4 の 3）

**字下げの扱い。** 字下げは CSS が行う。原稿の書き方は 2 通りを認め、どちらも同じ組み上がりにする。

| 原稿 | 扱い |
| :--- | :--- |
| 段落の頭に全角空白を書かない（Markdown の書き方） | そのまま。CSS が 1 字下げる |
| 段落の頭に全角空白を書く（投稿サイトの書き方） | `notation.web_novel` が有効なら、前処理が 1 つ落とす。無効なら 2 字下がるので、規則 4 が知らせる |
| 開き括弧（`「`・`『`・`（`・`〈`・`《`・`【`・`〔`）で始まる段落 | L3 の後処理が `p` に `vs-open-bracket` を付け（条件は `traits.vertical?`。縦中横の自動と同じ段）、`novel` が `text-indent: 0` にする |

- 括弧の段落の印を縦書きの本に限るのは、本書の契約 HTML を変えないためである。横書きの本にも要ると分かったら、条件を外して契約の表を直す（足すだけの変更）。`theme-contract-spec.md` §2.5 の表に `p.vs-open-bracket`（付く条件: 縦書き）を足す。

**規則の組 `novel`**（`minimal` の規則に、次の 5 つを足す。どれも原稿の場所を指すので 🟡）。

| # | id（案） | 知らせるもの | 知らせないもの |
| :--- | :--- | :--- | :--- |
| 1 | `novel-ellipsis-pair` | 「…」の並びが奇数個。「・・・」「。。。」（三点リーダーの代わり） | 偶数個の並び |
| 2 | `novel-dash-pair` | 「―」「—」が 1 つだけ | 2 つ以上の並び。数字や英字にはさまれたもの（範囲の表記） |
| 3 | `novel-space-after-mark` | 全角の「！」「？」「⁉」「‼」の直後に全角空白が無い | 直後が閉じ括弧（`」`・`』`・`）` など）・別の「！」「？」・「…」「―」・行末のとき |
| 4 | `novel-paragraph-indent` | `notation.web_novel` が無効: 段落の頭の全角空白（2 字下がる）。有効: 1 つの章の中で、頭に全角空白のある段落と無い段落（括弧で始まる段落を除く）が混ざっているとき、少ない側 | 括弧で始まる段落。全部がそろっている章 |
| 5 | `novel-halfwidth-digits` | 縦書きの本で、半角の数字が 3 桁以上並ぶ（横倒しに組まれる） | コード・数式・URL・横組みの箱の中。横書きの本 |

- 閉じ括弧の前の句点（「。」」「。』」）は、規則 3 の隣に `novel-period-before-bracket` として置く（合わせて 6 つ）。丸括弧の前の句点（「。）」）は知らせない（地の文の補足では普通に使う）。
- 規則 4 の「有効のとき」は、投稿サイトへ出す原稿の字下げの書き忘れを見つけるためのものである。本の組み上がりは変わらないので、要らない著者は `lint.disabled_rules` で外せる。
- 規則 5 は組方向を読む（`Common.traits.vertical?`）。`book.type` は読まない。
- 誤検出の確かめは 4.3 の S8-6 のとおり。指摘の数が多すぎる規則（1 作品で 50 件を超える）は、条件を見直してから入れる（「見逃すより検出」だが、常に出る指摘は読まれなくなる）。

### 4.10 背表紙とくるみ表紙の骨格（問い 2.6）

別の仕様書 `cover-spread-spec.md` に書き、S8b で作る。技術書（左綴じ）でも使えるようにする。違いは並びだけで、`traits.binding` を読めば済む。

| 項目 | 決定 |
| :--- | :--- |

| 確かめ | 寸法（幅 ＝ 判型の幅 × 2 ＋ 背幅 ＋ 塗り足し）を `pdfinfo` で、並びを `pdftotext -bbox` で見るテスト。入稿先の検査は、ユーザーが実際の印刷所のテンプレートと重ねて見る |

### 4.11 雛形と確かめ方（問い 2.7）

**雛形 `scaffolds/novel/` の原稿。** 青空文庫の著作権の切れた短い作品を 1 つと、記法の見本の章を 1 つ置く。

- 作品は宮沢賢治「注文の多い料理店」を候補にする。短く（約 6 千字）、会話文・地の文・ルビの要る字がそろい、挿絵を入れる場面を選びやすい。目指す紙面の作例（「銀河鉄道の夜」）と同じ作者で、見比べやすい。底本と入力者の表記を権利ページに載せる（青空文庫の取り扱いの決まり）。**作品の選び方はユーザーが確かめる**（雛形は `vs new` で著者の手元に写るので、別の作品や架空の原稿がよければ替える）。
- 記法の見本の章には、ルビ・傍点・縦中横（手と自動）・投稿サイトの記法・行の間の挿絵・全面の挿絵・脚注・`@pagebreak` を載せる。前書きと後書きも置く。
- 挿絵は、vs で作った簡単な図（著作権の問題が無いもの）を 2 枚置く。
- `book.yml` は小説で意味のあるキーだけを載せる（`v2-architecture-spec.md` §2.6）。

**S8 の完了の条件（紙面の条件）。** `scaffolds/novel/` の本で見る。

機械で見るもの:
