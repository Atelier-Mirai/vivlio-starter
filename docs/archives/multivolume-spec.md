## 1. いまの姿

### 1.1 回り道

『AIと学ぶモダンWebサイト入門』は、Vivlio Starter の外のスクリプト（`book_ai_web_starter/sources/build_volume.rb`）で上下巻を組んでいる。

- 巻ごとの目次（`config/catalog-upper.yml`・`catalog-lower.yml`）を、組むあいだだけ `config/catalog.yml` へ写す。
- `book.yml` の `project.name`・`output.cover`・`book.main_title`・`book.subtitle` を、巻ごとの値に書き換える（巻の値は `config/volumes.yml`）。
- 巻ごとに違う原稿（下巻の前書き）は `sources/volumes/lower/00-preface.md` に置き、組むあいだだけ `contents/00-preface.md` と入れ替える。
- 組み終えたら（途中で止めても）すべて元に戻す。

### 1.2 回り道で残る不便（要望書 §1.2）

| 不便 | この仕様での扱い |
| :--- | :--- |
| 下巻の章番号が「第1章」から始まる | §5.1（既定で前の巻から続ける） |
| 下巻だけの付録の記号を続けられない | §5.2 |
| 別の巻の章を指す `@chapref` が未定義になる（上巻 2 件・下巻 19 件） | §8（段階 3） |
| 用語集の「ビルド対象章に出現しません」が大量に出る | §6.2 |
| 出力ファイル名が巻によらず同じ | §4.6 |
| `catalog.yml` を書き換えるので、戻し忘れると次の `vs create`・`vs preflight` が片方の巻だけを見る | §3（目次は一つのまま、巻を選ぶ） |
| 巻ごとの前書きを置けない | `catalog-section-kind-spec.md`（段階 1） |
| 全巻の構成を示す目次がない | §9（段階 4・章と節まで） |

### 1.3 コードの今

- 目次の読み込みは、ほぼすべて `CatalogLoader.load_catalog`・`load_existing_basenames`・`load_labeled_entries` と、その上の `TokenResolver` を通る。
- 「第 N 章」の N は、本文の章の並びでの位置に 1 を足して決める。計算は 3 か所にある（`HeadingProcessor#resolve_main_chapter_display_number`、`CrossReferenceProcessor.display_chapter_number_for_filename`・`chapter_number_text_for`）。図表番号と `@chapref` の文字も、この値から作る。
- 全章ビルドでは、`HeadingProcessor#discovered_main_chapter_tokens` が中間 HTML の置き場（`Common::BUILD_HTML_DIR`）にある HTML から本文の章の並びを起こす。
- 付録の記号は `Common.appendix_number_to_letter` の 1 か所で、付録の並びでの位置から振る。
- 出力ファイル名は `Common.generate_output_filename`・`generate_cover_output_filename` で、`project.name` から作る。
- EPUB の `dc:identifier` は、ISBN がなければ `project.name` から作る UUID である（`EpubBuilder#stable_project_uuid`）。回り道では巻ごとに `project.name` を変えているので、巻ごとに違う識別子になっている。
- 用語集の「ビルド対象章に出現しません」は、走査した章が目次の全章を覆っているとき（`UnifiedIndexManager#full_catalog_scope?`）だけ出る。回り道では目次そのものを巻の分に差し替えているので、巻ごとの組版でも「全章を走査した」と判定されて出る。
- 部（中扉）には番号を振っていない。中扉に出すのは部の題名だけである。

## 2. 方針

- **巻は順番のある並びとして扱う。** 巻の数は 2 以上なら自由（上下巻、上中下巻、第一分冊〜第 N 分冊）。
- **巻の名前は著者が書き、vs はその意味を読まない。** `upper`・`lower`・「最後の巻なら下巻」のような決め打ちをコードに置かない。巻の名前を番号から自動で作る機能（「第三分冊」）は作らない。
- **「前の巻」「最初の巻」「最後の巻」は、並びの順から決める。**
- **巻を書かない `catalog.yml` は、今までどおり一冊として組む。**
- 試験は上中下の 3 巻で行う。2 巻だけで確かめると、「最初の巻でなければ最後の巻」という思い込みが隠れたまま通る。

## 3. 巻を書く（`catalog.yml`）

### 3.1 書き方

```yaml
VOLUMES:
  - name: 上巻
    id: upper
    main_title: AIと学ぶモダンWeb入門　上巻
    subtitle: 花屋のサイトで学ぶ HTML・CSS と JavaScript の基本
    cover: upper               # covers/frontcover_upper.png・backcover_upper.png
    PREFACE:
      - 00-preface
    CHAPTERS:
      - コンピュータとAI、Webへの入り口:
          - 01-computer
          - 02-ai
      # …
    APPENDICES:
      - 90-how-to-ask
      - 93-cheatsheet

  - name: 下巻
    id: lower
    main_title: AIと学ぶモダンWeb入門　下巻
    subtitle: じゃんけんアプリで学ぶ JavaScript と Git・PWA・Canvas
    cover: lower
    release: 令和九年一月十日  # 上巻と発行日が違う（book.yml の値は上巻のもの）
    PREFACE:
      - 20-vol2-intro          # 下巻のはじめに（catalog-section-kind-spec.md）
    CHAPTERS:
      - じゃんけんアプリを育てる:
          - 21-janken-simple
      # …
    APPENDICES:
      - 90-how-to-ask          # 上巻と共通
      - 93-cheatsheet
      - 94-canvas-works        # 下巻だけ
    POSTFACE:
      - 99-postface
```

### 3.2 巻の設定

小文字のキーは巻の設定、大文字のキーはその巻の目次である。

| キー | 必須 | 意味 |
| :--- | :--- | :--- |
| `name` | 必須 | 巻の呼び名（「上巻」「第一分冊」）。巻をまたぐ参照の表示（§8）と、`--volume` の指定に使う |
| `id` | 必須 | ファイル名と `--volume` に使う短い名前。英小文字・数字・`_` だけ。`all` は使えない（§4.2） |
| `book.yml` の `book:` の下のキー | 任意 | その巻だけ、`book.yml` の同じ名前の値を置き換える（下の「書誌情報の上書き」） |
| `chapter_start` | 任意 | その巻の最初の本文の章の番号（§5.1） |
| `appendix_start` | 任意 | その巻の付録を振り直すときの最初の記号（§5.2） |
| `whole_toc` | 任意 | `true` で、その巻に全巻の目次を載せる（§9） |

巻の設定を `book.yml` ではなく `catalog.yml` に置くのは、巻の構成と一体のものだからである。`book.yml` に置くと、分冊でない本の著者にも使わないキーが見えることになる（`config-key-criteria-guidelines.md` §1 は、`book.yml` のキーをすべて `book.yml` に書くことを求めている）。番号の振り方を全巻まとめて選ぶキー（要望書の `volumes.numbering`）は設けない。既定の振り方（§5）で多くの本が済み、違う本は巻の `chapter_start`・`appendix_start` で足りるからである。

#### 書誌情報の上書き（段階 5）

一冊の本は `book.yml` の `book:` に書名・表紙などを書く。分冊の本では、`book.yml` の値が全巻の既定になり、巻ごとに違う値だけを巻の中に書いて上書きする。

```yaml
# config/book.yml（全巻の既定）
book:
  main_title: "AIと学ぶモダンWeb入門"
  author: "早乙女 遙香"
  release: "令和八年十月一日"
  cover: master

# config/catalog.yml（巻ごとに違う値だけ）
VOLUMES:
  - name: 上巻
    id: upper
    main_title: "AIと学ぶモダンWeb入門　上巻"
    isbn: "978-4-xxxx-xxxx-1"
    cover: upper
  - name: 下巻
    id: lower
    main_title: "AIと学ぶモダンWeb入門　下巻"
    isbn: "978-4-xxxx-xxxx-2"
    release: "令和九年一月十日"
    cover: lower
```

- **書けるキー**は、`book.yml` の `book:` の下のキーすべてである。今は `main_title`・`subtitle`・`subtitle_style`・`series`・`release`・`publisher`・`contact`・`author`・`language`・`isbn`・`cover`（`cover` は §3.5 で `book:` へ移す）。
- **名前は `book.yml` と同じにし、`book:` の一段を省いて平らに書く。** `book.yml` の `book:` の下も平らなので、行をそのまま写せば巻の設定になる。`book.yml:` や `book:` のような入れ子のキーは設けない。入れ子が二段深くなり、著者には何を書く場所かわからなくなるからである。
- **書いたキーは上書きし、書かないキーは `book.yml` の値を使う。** 空の値も書いたとおりに使う（`isbn: ""` は「この巻には ISBN がない」）。
- **合本（§4.3）は、いつも `book.yml` の値で組む。**
- **書けるキーの一覧は、コードに書き並べず `ConfigKeys::KEYS` から作る**（`book` で始まる現役のキー）。`book:` にキーを足せば、巻でもそのまま上書きできる。キーごとに重ねる処理を書き足さない。
- `book:` の下には、巻の設定（`name`・`id`・`chapter_start`・`appendix_start`・`whole_toc`）と同じ名前のキーや、大文字のキー（区分）を足さない。巻の中で区別がつかなくなる。名前が重ならないことはテストで確かめる。
- `page`・`targets` のように `book:` の下にないキーを巻に書いたときは、今と同じく打ち間違いとして 🟡 で知らせる（`VolumeDefinitionCheck`）。添える「書けるキー」には、`book:` のキーも並べる。

### 3.3 止める場合（🔴）

| 場合 | 理由 |
| :--- | :--- |
| `VOLUMES` と、一番上の `PREFACE`・`CHAPTERS` などが同じファイルにある | どちらが目次か決められない。直し方として、一番上の区分を巻の中へ移す書き方を添える |
| `name` か `id` がない、`id` の形が正しくない、`id` が `all` | ファイル名と `--volume` に使えない |
| 二つの巻の `id` または `name` が同じ | `--volume` でどちらを指すか決められない |
| 同じ原稿を、巻によって違う区分に書いた | 種類が決まらない（`catalog-section-kind-spec.md` §2.1） |

前書き・付録・後書きは、二つ以上の巻に書いてよい（共通の付録）。本文の章も、二つ以上の巻に書いてよい（§3.6。段階 6 で 🔴 をやめた）。

### 3.4 巻を選ぶ仕組み

- 組む巻は、処理の始まりに一度だけ決める（`Build::Volumes.current`。巻を選ばないときは `nil`）。
- `CatalogLoader.load_catalog` は、巻が選ばれていればその巻の目次を、選ばれていなければ全巻を合わせた目次（§4.3）を、今と同じ形の Hash（`PREFACE`・`CHAPTERS`・`APPENDICES`・`POSTFACE`）で返す。目次を読むほかの処理（部の中扉、最初の本文の章を探す `BodyClassInjector`、索引の対象など）は、これで直さずに済む見込みである。
- 巻の一覧（設定と目次）は、新しい `CatalogLoader.volumes` で返す。番号の計算（§5）と巻をまたぐ参照（§8）が使う。

### 3.5 `book.yml` の `cover` を `book:` へ移す（段階 5）

表紙のテーマ（`master`・`light`・`dark`・独自の名前）を、`output.cover` から `book.cover` へ移す。

```yaml
book:
  main_title: "はじめての技術書づくり"
  # …
  isbn: ""

  # ------- 表紙・裏表紙設定 -------
  cover: master  # covers/内の著者用意画像(frontcover_master.png, backcover_master.png)を指定
  # cover: light # 標準添付 light 表紙・裏表紙を指定
  # cover: dark  # 標準添付 dark 表紙・裏表紙を指定
```

- **理由**: どの表紙を使うかは、書名や発行日と同じく「その本が何であるか」の一部で、巻ごとに変わる。`output:` の下は出力の仕方を決める値（ターゲット・圧縮・埋め込み）の置き場である。移すと、巻の上書き（§3.2）が「`book:` のキーなら何でも」の一つの決まりになり、`cover` だけの例外がなくなる。
- 表紙の**出し方**の値は `output:` に残す: `output.pdf.combined`（PDF に綴じるか）・`output.print_pdf.cover_bleed`（塗り足し）・`output.epub.embed`・`output.kindle.embed`。
- 既定値は今の `output.cover` と同じ `master`。
- 読む場所は `Common.cover_theme` の一か所なので、そこを `book.cover` にする。`vs import`（`import.rb`・`import/yaml_processor.rb`）が書く場所も `book.cover` にする。

#### 古い `book.yml` の扱い

- `output.cover` は廃止キーにする（`config-retirement-guidelines.md` §1）。`book.yml` に残っていれば、ほかの廃止キーと同じく値を読まずに 🟡 で知らせる。案内には、移す先と `vs upgrade` を添える。

  ```
  🟡 config/book.yml の output.cover は book.cover へ移りました
          巻ごとに表紙を変えられるよう、書名と同じ book: の下に置きます
          → vs upgrade で移せます（手で移すなら、book: の下に cover: master と書き、output: の下の行を消します）
  ```

- **`vs upgrade` は、`output.cover` を消さずに `book.cover` へ移す。** 今の `vs upgrade` は廃止キーの行を消すだけである（`RetiredKeyRemover`）。消すと `cover: master` で組んでいた著者の表紙が黙って既定に戻るので、値を移す。
  - `book.cover` がまだなければ、`book:` の下の最後に `cover: <値>` の行を足し、`output.cover` の行を消す。
  - `book.cover` がすでにあれば（手で移した後など）、`book.cover` を残し、`output.cover` の行だけを消す。値が違うときは、残した値と消した値を知らせる。
  - `output:` の下に残る `# cover: light` のような注釈の行は、消さずに残す（著者の書いた注釈かどうか見分けられない）。
- 移す先を持つ廃止キーは、`ConfigKeys::RETIRED` の宣言に移す先を書く（`Spec[retired: '…', moved_to: %i[book cover]]`）。`vs upgrade` と案内文は、この宣言から移し方を決める。`config-retirement-guidelines.md` に「移す」手順を書き足す。

### 3.6 本文の章を二つ以上の巻に載せる（段階 6）

下巻だけを手に取る読者のために、インストールの章のような本文の章を、上巻と下巻の両方に載せたいことがある。段階 2 では、章番号が決まらないとして 🔴 で止めていた（§3.3）が、次の決まりで載せられるようにする。

```yaml
VOLUMES:
  - name: 上巻
    id: upper
    CHAPTERS:
      - 11-install        # 上巻 第1章
      - 12-basics         # 第2章 … 第10章まで
  - name: 下巻
    id: lower
    CHAPTERS:
      - 11-install        # 下巻 第11章（上巻の 10 章の次）
      - 21-advanced       # 第12章
```

1. **番号**: 載った巻ごとに、巻の中の位置で振る（巻の中の本文の章は、ほかの章と同じく番号の順に並べて数える）。巻の最初の章の番号は、前の巻までの本文の章の数（共通の章も、載った巻ごとに数える）に 1 を足した数（§5.1 のまま）。上の例では、上巻で第1章、下巻で第11章になる。図表番号（図 1-2・図 11-2）と `@chapref` の番号も、組む巻の番号になる。章番号を付けない扱いにはしない（その巻の中で番号が抜けて、かえって目立つ）。
2. **参照**: 組む巻にその章が載っていれば、その巻の章として参照する（番号はその巻のもの・リンクにする）。載っていない巻から指したときは、最初に載せた巻の章として「上巻 第1章「…」」と示す（`Volumes.containing`・§8 のまま）。
3. **全巻目次**: 載った巻ごとに、その巻の番号で載せる（§9 のまま）。
4. **合本**: 一度だけ、最初に載せた位置で載せる（共通の付録と同じ）。部の中に書いた場合も、原稿の名前で見て一度だけにし、中身の無くなった部は載せない。
5. **単章ビルド**: `vs build 11` は、最初に載せた巻で組む。`--volume` を添えれば選び直せる（§4.4 のまま）。
6. **「前の章」の検査**（§8）: 共通の章は、載った巻ごとに章の並びに現れる。参照する章か参照される章のどれか一つの載り方で隣になっていれば、食い違いとして知らせない。

`vs create`・`delete`・`rename` は、すでにすべての巻の行を書き換える（§7）ので、変えない。

## 4. 組む

### 4.1 巻を選んで組む

```
vs build --volume lower      # id で選ぶ
vs build --volume 下巻       # name でも選べる
```

- 巻に書いた `book:` のキー（§3.2）を、`book.yml` の値に重ねた `CONFIG` で組む（`Common.install_configuration!` と `deep_merge_config` を使う）。扉・奥付・表紙・PDF の文書情報・EPUB の書誌情報は、どれも `CONFIG` から読むので、そのまま巻の値になる。
- 前に別の巻を組んだ中間 HTML が残っていると、本文の章の並び（§1.3）に混ざって番号がずれる。巻を切り替えて組むときは、`--no-clean` でも中間 HTML の置き場を空にしてから組む（最後に組んだ巻を置き場に記録して比べる）。

### 4.2 全巻を続けて組む

```
vs build --volume all
```

- 巻の順に、一巻ずつ**別のプロセスで** `vs build --volume <id>` を走らせる。設定（`CONFIG`）や章の並びの記録はプロセスの中に残るので、同じプロセスで巻を切り替えると前の巻の値が混ざる。
- 途中の巻で失敗したら、そこで止め、どの巻で失敗したかを知らせる。それまでに組んだ巻の出力は残す。
- `--no-compress` などのほかのオプションは、各巻の `vs build` へそのまま渡す。

### 4.3 巻を選ばずに組む（合本）

`VOLUMES` のある本で `vs build` とだけ打つと、全巻を一冊にまとめた合本を組む。校正や、電子版の合本に使う。

- 構成: **最初の巻の `PREFACE`** → 全巻の `CHAPTERS`（巻の順） → 全巻の `APPENDICES`（重なりを除く） → **最後の巻の `POSTFACE`**。2 巻目以降の前書き（「下巻のはじめに」）と、最後の巻より前の後書きは、合本では一冊の途中に来ることになるので載せない。
- 番号は全体を通して振る。巻の `chapter_start`・`appendix_start` は使わない。合本は一冊の本なので、途中で「第1章」に戻らないのが正しい形である。巻に `chapter_start` を書かなければ、巻の番号も前の巻から続くので、合本と各巻の番号は同じになる。
- 書名・副題・表紙・ISBN など `book:` の値は、`book.yml` の値を使う。出力ファイル名に巻の `id` は入らない。

### 4.4 単章ビルド

- `vs build 21` は、その章を載せた巻の番号の振り方で組む（下巻の 21 章なら「第13章」）。
- 付録のように二つ以上の巻に載る原稿は、最初に載せた巻で組む。`--volume` を添えれば選び直せる。
- どの巻にも載っていない原稿は、今と同じく目次の外の原稿として組む。

### 4.5 `--volume` を受け付けない場合（🔴）

- `VOLUMES` のない本で `--volume` を付けた: 直し方として、`VOLUMES` の書き方の例（§3.1 を短くしたもの）を添える。
- 巻の名前が見つからない: 書かれている巻の `id` と `name` を並べて添える。

### 4.6 出力ファイル名

巻を選んで組んだときは、`project.name` の後に巻の `id` を入れる。

| 出力 | 例 |
| :--- | :--- |
| PDF | `book_ai_web_starter_lower_v0.1.0.pdf` |
| 印刷用 PDF | `book_ai_web_starter_lower_print_v0.1.0.pdf` |
| EPUB・KPF | `book_ai_web_starter_lower_v0.1.0.epub`・`.kpf` |
| 表紙 | `book_ai_web_starter_lower_frontcover_v0.1.0.pdf`・`.jpg` |

`vs clean` の消す対象は `project.name` から始まる名前（`clean.rb` の `add_dynamic_filename_patterns`）なので、巻の出力も消える。名前の形を選ぶキーは設けない。

### 4.7 EPUB の識別子

ISBN がないとき、`dc:identifier` の UUID を `project.name` と巻の `id` を `_` でつないだ名前（`mybook_lower`）から作る。巻ごとに `project.name` を変えていた回り道と同じ識別子になる。同じ識別子だと、電子書籍ストアや読書アプリが上巻と下巻を同じ本の版違いとして扱うためである。合本は今と同じく `project.name` だけから作る。

ISBN があるとき（段階 5）は、今と同じく `urn:isbn:…` を使い、巻の `id` は足さない。ISBN は巻ごとに取るものなので、巻の `isbn`（§3.2）に書く。

- **🟡 巻が ISBN を共有している**: `book.yml` の `book.isbn` に値があり、`isbn` を書いていない巻が二つ以上あるとき。それらの巻は同じ `urn:isbn` になり、ストアや読書アプリが同じ本とみなす。`VolumeDefinitionCheck` が知らせる（`vs build`・`vs preflight` で同じものを出す）。巻の名前と `catalog.yml` の行番号を添え、直し方を示す。

  ```
  🟡 上巻・下巻が、book.yml の ISBN（978-4-xxxx-xxxx-1）を共有しています
          config/catalog.yml:2 上巻 / config/catalog.yml:20 下巻
          → 巻ごとに ISBN を書いてください。ISBN の無い巻は isbn: "" と書きます
            - name: 下巻
              id: lower
              isbn: "978-4-…"
  ```

- `isbn` を書いていない巻が一つだけのときは知らせない（`book.yml` の ISBN をその巻のものとして使う書き方）。合本の ISBN は `book.yml` の値で、巻の ISBN と重なりうるが、合本は校正用でもあるので知らせない。

### 4.8 表紙だけを作る（`vs cover`。段階 5）

`vs build` は巻の表紙で組む（§4.1。巻に `cover` を書けば巻ごとの画像を使い、`light`・`dark` なら巻の書名を当てる）。表紙だけを作り直す `vs cover` にも、`vs build` と同じ巻の選び方を足す。

```
vs cover --volume lower   # 下巻の表紙（id でも name でも選べる）
vs cover --volume all     # 全巻の表紙を、巻の順に
vs cover                  # 合本の表紙（book.yml の値）
```

- 巻を選んだときは、巻の値（§3.2）を重ねた `CONFIG` で作る。出力ファイル名には巻の `id` が入る（§4.6。`mybook_lower_frontcover_v0.1.0.pdf`・`.jpg`）。
- `--volume all` は、巻ごとに選び直して設定を重ね直し、同じプロセスで続けて作る。表紙が読むのは `CONFIG` だけで、`vs build` のように章の並びの記録が残らないからである。作り終えたら設定を `book.yml` の値へ戻す。
- 何も付けないときは、`vs build` と同じく合本の表紙（`book.yml` の値・ファイル名に `id` なし）を作る。
- `VOLUMES` のない本で `--volume` を付けたとき、巻の名前が見つからないときは、`vs build` と同じく 🔴 で止める（§4.5）。
- 生成キャッシュ（`.cache/vs/covers/`）の名前はテーマごと（`frontcover_light_b5_rgb.pdf`）のままにする。二つの巻が同じ `light` を使うと書名の違う表紙が同じ名前に書かれるが、`vs build`・`vs cover` は表紙を毎回作り直してから使う・写すので、取り違えは起きない。

## 5. 番号

### 5.1 本文の章

- 既定では**前の巻から続ける**。巻 k の最初の本文の章の番号は、それより前の巻の本文の章の数に 1 を足した数である。
- `chapter_start` を書いた巻は、その番号から始める。その後の巻は、`chapter_start` を書いた巻から続ける。
- 図表番号（図 13-2）と `@chapref` の「第13章」も、同じ番号を使う。番号の計算は 3 か所（§1.3）から一か所（`Build::Volumes`）へまとめ、どこからもそれを呼ぶ。

例（上中下巻・本文の章がそれぞれ 12・10・8 章）:

| 書き方 | 上巻 | 中巻 | 下巻 |
| :--- | :--- | :--- | :--- |
| 何も書かない | 第1〜12章 | 第13〜22章 | 第23〜30章 |
| 中巻に `chapter_start: 1` | 第1〜12章 | 第1〜10章 | 第11〜18章 |
| 全巻に `chapter_start: 1` | 第1〜12章 | 第1〜10章 | 第1〜8章 |

### 5.2 付録

- 既定では、**全巻を巻の順に見て、初めて出た付録に次の記号を振る**。別の巻に再び載るときは、同じ記号を使う。
  - 上下巻の例: 上巻は 90〜93 が付録 A〜D。下巻も 90〜93 は A〜D のままで、下巻だけの 94 が付録 E。
- `appendix_start` を書いた巻は、その巻の付録だけを、その巻での並びの順に、指定の記号から振る。ほかの巻の記号には影響しない。
- 付録の原稿は全巻で `90`〜`98` の 9 本までなので（`contents/` は全巻で一つ）、既定の規則では記号は A〜I に収まる。`catalog-section-kind-spec.md` §4.3 で記号を A〜Z まで振れるようにするので、上限には余裕がある。

### 5.3 部とノンブル

- 部には番号を振っていない（§1.3）ので、扱いは変わらない。
- ノンブル（ページ番号）は巻ごとに 1 から振る。回り道と同じ結果である。

## 6. 原稿の検査

### 6.1 `vs preflight`・`vs lint`・`vs metrics`

- `--volume <id|name>` を受け付け、その巻の原稿だけを見る。
- 巻を選ばないときは、**全巻の原稿**（どれかの巻に載っている原稿すべて）を見る。合本（§4.3）とは違い、2 巻目以降の前書きも含める。原稿の検査は、紙面に載るかどうかではなく、書いた原稿すべてが対象だからである。
- `vs metrics` は、巻を選ばないとき、章ごとの表の後に巻ごとの合計（文字数・ページの目安）を足す。

### 6.2 用語集の警告

`full_catalog_scope?` が比べる「目次の全章」を、**全巻の原稿**にする。巻を選んで組むと全章を走査したことにならないので、「ビルド対象章に出現しません」は出ない。全巻を見たとき（合本・巻を選ばない `vs preflight`）にだけ、どの巻にも出てこない語として出る。

### 6.3 索引と用語集のページ

巻を選んで組むと、索引と用語集はその巻の原稿から作る（回り道と同じ結果）。実装では、索引の走査の対象が選んだ巻の原稿になることを確かめる。

## 7. 章の管理コマンド

- `vs create 31-xxx`: 番号が一つ前の本文の章（`30`）を載せた巻の、同じ区分に足す。見つからなければ最後の巻に足す。`--volume` を添えれば巻を選べる。
- `vs delete`: すべての巻から外す。
- `vs rename`: すべての巻で書き換える。今の `CatalogUpdater` は最初に見つけた行だけを書き換えるので（`find_active_entry_line`）、すべての行を書き換えるように直す。
- `CatalogUpdater` は行ごとに書き換える方式で、部の入れ子にはすでに対応している。`VOLUMES` の中は字下げが一段深くなるので、区分の見出しの探し方を巻の中まで広げる。

## 8. 巻をまたぐ参照（段階 3）

- ラベル（`@ch-…`・`@fig-…` など）を、**全巻の原稿から**集める。今は目次に載った原稿だけから集めている（`pre_process.rb` の Phase 1）。集めたラベルには、それを書いた巻を記録する。
- 別の巻のラベルを指す参照は、次のように表す。
  - 表示: 巻の `name` を前に添える。例: `@chapref:ch-dom` →「上巻 第8章「JavaScript でページを操作する」」、`@fig-…` →「上巻 図 8-2」。番号は、その巻の振り方（§5）で決まる。
  - リンクにしない。`@pageref` もページ番号を付けず、章の表示（「上巻 第8章」）にする。
  - 表示の形を選ぶキーは設けない。巻の `name` は自由に書けるので、「第一分冊 第8章」にもなる。
- 合本では、すべてのラベルが同じ一冊にあるので、普通の参照になる。
- 「未定義のラベルID」は、どの巻にもないラベルにだけ出す。
- 「前の章 @ch-x」の検査（`chapter-reference-spec.md` §2.10）は、全巻の並びで判定する。下巻の最初の章の「前の章」は、上巻の最後の章である。

## 9. 全巻の目次（段階 4）

分冊の本で、その巻の目次とは別に、全巻の構成を章と節まで示す目次を載せる（要望書 §2.7）。

### 9.1 載せる巻

- 巻の設定に `whole_toc: true` を書いた巻にだけ載せる（§3.2）。既定では載せない。全巻に載せる本も、2 巻目以降にだけ載せる本もあるので、巻ごとに選べるようにする。
- 合本（§4.3）には載せない。合本の目次がそのまま全巻の目次になるからである。

### 9.2 載せる内容

```
全巻目次

上巻
  前書き
  コンピュータとAI、Webへの入り口
    第1章 コンピュータとは
    第2章 AI のしくみと付き合い方
    …
  付録 A うまく伝えるための言い方集
  …

下巻                          ← 今の巻は目立たせる
  下巻のはじめに
  じゃんけんアプリを育てる
    第13章 シンプルなじゃんけんゲームを作る
    …
  付録 E Canvas で小さな作品を作る
  後書き
```

- 巻の順に、巻の `name` を見出しにして、その巻の目次（`PREFACE`・部・`CHAPTERS`・`APPENDICES`・`POSTFACE`）を並べる。
- 細かさは、その巻の詳しい目次と同じく `page.toc_depth` に従う。`1` なら章まで、`2`・`3` なら**節（`##`）まで**（項は載せない）。節を載せるのは本文の章と付録だけで、前書き・後書きは題名だけ（詳しい目次と同じ決まり）。全巻目次の深さを選ぶキーは設けない（要望書の `volumes.toc.whole`）。詳しい目次と違う深さにしたい理由が描けるまで足さない。
- 節の番号は、章扉の節と同じ「13-2」「A-1」（`HeadingProcessor.build_h2_number_text`）。
- 節は、ほかの巻を組まないので HTML が無く、原稿の Markdown の `## ` の行から取る。コードブロックの中の `##`（記法の説明）は拾わない。見出しの属性（`{.class}`）と見出しのラベル（`@sec-…`）は外す。
- 章の番号と付録の記号は、§5 の振り方による（下巻の章は「第13章」から）。題名は各原稿の `#` の見出しから取り、`@chapref` と同じく `CrossReferenceProcessor.plain_chapter_title` で整える。
- 部の題名は `catalog.yml` から取る。
- **ページ番号は載せない。** 今の目次は、組み上がった HTML から作り、ページ番号は Vivliostyle が組版のときに数える。他の巻はその場で組まないので、ページ番号がわからない。今の巻の分だけページ番号を付けると見た目がそろわないので、今の巻にも付けない。今の巻のページは、続く詳しい目次で引ける。
- 今の巻は、巻の見出しと項目にクラス（`vs-current-volume`）を付けて目立たせる。Kindle は `var()` を読まないので、`body.vs-kindle` の側ではリテラルの色で書く（`kindle-css-compatibility-notes.md`）。
- 他の巻の項目はリンクにしない。今の巻の項目も、詳しい目次と役目が重なるのでリンクにしない。

### 9.3 置き場所と作り方

- その巻の目次（`_toc`）の**前**に置く。全体の構成を見てから、その巻の詳しい目次へ進む順になる。
- 扉（`_titlepage`）や中扉（`PartTitleGenerator`）と同じく、システムページ `_whole_toc` として `.cache/vs/` に Markdown を書き、HTML に変換する。組み立ての 4 か所（`catalog-section-kind-spec.md` §4.2）で、`_toc` の前に差し込む。
- ページの見出しは「全巻目次」とし、PDF のしおりと EPUB の nav に 1 項目として載せる。
- 章の題名を他の巻の原稿から取り出す処理は、段階 3 のラベルの収集（§8）と共通にする。段階 3 より先に入れる場合も、題名の取り出しは `CrossReferenceProcessor` の同じ処理を使う。

### 9.4 試験

- 上中下の 3 巻の器で、中巻だけに `whole_toc: true` を書く。中巻の PDF・EPUB に、三つの巻の見出しと章が §5 の番号で並び、中巻が目立ち、ページ番号とリンクがないことを確かめる。上巻・下巻と合本には載らない。
- `chapter_start` を書いた巻があるとき、全巻の目次の番号が各巻の章扉と一致する。
- Kindle の器（`epub_kindle_layout_test`）で、今の巻の目立たせ方がリテラルの色で出る。

## 10. この仕様で扱わないもの

2026-10-22 に、次の 5 つを `PLANNED.md` の「分冊」へ移した。

- 背表紙（要望書 §2.8）
- 索引の主要参照（「- 主要参照: 11, 12」）を別の巻の章へ向けること、全巻を通した索引（要望書 §2.9）
- 全巻の目次にページ番号を載せること（§9.2）
- ノンブルを全巻で通すこと（要望書 §2.11）
- 2 巻目以降の前書きの雛形（要望書 §2.5）と、`vs create` で前書きとして作る指定

次の 3 つは、作らないと決めた（または、すでに満たしている）。

- **巻ごとの版**: 読者が見る版の表記（「第2版第1刷発行」）は奥付にあり、奥付は `book.release` の文字をそのまま出す。`release` は巻で上書きできる（§3.2）ので、巻ごとの版はすでに書ける。`project.version` は配布ファイルを見分ける名前（`mybook_v1.0.1.pdf`）と本文の `@version` にだけ使うので、全体で一つにする。一つの巻だけを加筆したときも、`project.version` を上げる（加筆していない巻のファイル名も上がる）。巻ごとの `version` は、必要になったときに巻のキーに足す。`book:` の外の値（判型・ターゲットなど）は巻ごとに変えない。
- **`vs renumber` が巻の区切りを保つこと**（要望書 §2.10）: 今の `vs renumber` は、番号の順に詰め直し、`catalog.yml` も追随するので、巻の前書き・章・付録の並びは保たれる（3 巻の試しの本で、中巻の前書き `20-vol2-intro` が `15-vol2-intro` に、続く `21-markdown-tutorial` が `16-markdown-tutorial` になり、どの巻も正しく組まれた）。「中巻は 20 番台」のような番号の帯は保たないが、帯を保つ指定は設けない。
- **合本で巻ごとの章番号を保つこと**: 合本は一冊の本なので、通し番号が正しい形である（§4.3・論点 2）。

段階 6 の確認:

- 3 巻の試しの本で、本文の章を上巻と下巻（部の中）の両方に書き、🔴 が出ない。上巻・下巻の章扉・目次・全巻目次・PDF のしおりで、それぞれの巻の位置の番号になる（下巻の番号は、上巻の章の数に共通の章を含めた次から）。
- 中巻から共通の章を `@chapref` で指すと「上巻 第1章「…」」、下巻の中から指すと下巻の番号のリンクになる。
- 合本では共通の章が一度だけ載り、番号が通しで飛ばない。部の中にしか無かった共通の章で、部が空になる場合は部を載せない。
- 下巻で共通の章の次の章が「前の章 @ch-共通の章」と書いても知らせない。

段階 5 の確認:

- 3 巻の試しの本で、上巻・下巻に独自の表紙（`cover: upper`・`lower`）、中巻に `light` を書き、`vs build --volume all` と `vs cover --volume all` で、PDF の表と裏・EPUB の表紙・直下の成果品（`_frontcover` の PDF と JPEG）が巻ごとの画像になる。中巻の `light` には中巻の書名が入る。
- 巻に書いた `release`・`isbn` が、奥付・PDF の文書情報・EPUB の `dc:identifier`（`urn:isbn`）に出る。書かない巻は `book.yml` の値になる。
- `book.yml` に ISBN があり、`isbn` を書かない巻が二つあると 🟡 が出る。一つなら出ない。`isbn: ""` と書いた巻は数えない。
- `output.cover: master` だけを書いた `book.yml` で、組むと 🟡 の案内が出る。`vs upgrade` の後は `book.cover: master` になり、組むと `master` の表紙になる。`book.cover` がすでにある `book.yml` では `output.cover` の行だけが消える。
- 巻の設定の名前（`name`・`id` など）と `book:` のキーが重ならないことを、`ConfigKeys::KEYS` から確かめるテストを置く。
- `VOLUMES` のない本（本書・雛形）の全章ビルドが、`cover` を移す前後で一致する。

各段階の確認:

- 試験の器（fixture）は上中下の 3 巻で作る。巻ごとの前書き・共通の付録・一つの巻だけの付録・`chapter_start` を書いた巻を含める。
- 『AIと学ぶモダンWebサイト入門』を、段階 2 の後に `vs build --volume all` で組み、回り道で組んだ PDF と比べる。ページ数と内容が一致し、違うのは意図した所（下巻の章番号・図表番号、出力ファイル名）だけであることを確かめる。
- `VOLUMES` のない本（本書・雛形）の全章ビルドが、変更の前後で一致する。

## 12. 論点

| # | 論点 | 推す案 | 代わりの案 |
| :--- | :--- | :--- | :--- |

## 13. 実装記録

### 13.1 段階 2（2026-10-20）

- **単章ビルドの章扉は、§4.4 と違い「第1章」から数える。** `chapter-reference-spec.md` の決定（2026-09-29）で、単章ビルドの章扉は対象の章だけで数える（`vs build 44` なら「第1章」）。この決定を守り、巻の振り方は全章ビルドと `@chapref` の文字にだけ効かせた。単章ビルドでも、組む範囲はその章を載せた巻になる（`@chapref` の番号が巻の振り方になる）。
- **全章ビルドかどうかを `chapter_tokens_override` で見分けられない。** `SectionBuilder.convert_sections_html!` は、並列変換で章の並びのキャッシュが崩れないよう、全章ビルドでも本文の章の並びを override で渡している。そこで、全章ビルドで「第 N 章」に足す数を `HeadingProcessor.chapter_number_offset` として明示的に渡す（巻を選んだ全章ビルドのときだけ `BuildCommand` が設定する）。最初は override の有無で見分けたため、3 巻の試し組みで中巻の章扉が「第1章」になった。
- **目次の「第 N 章」「付録 A」は CSS のカウンタ（`toc.css`）で 1 から数えている。** 章扉の番号を HTML に書いても目次には届かない。目次の最上位の `<ul>` に `counter-reset: toc-list-counter N` を与え、付録は記号が巻の中で飛ぶ（下巻の付録が A・C）ので、付録の `<li>` ごとに章扉と同じ記号の位置を `counter-reset` で与える。巻の無い本では何も足さない（出力は変わらない）。
- **PDF のしおりは、番号の範囲から「第 N 章」を補う予備の経路を持っていた**（`OutlineExtractor#resolve_chapter_number_display`。11〜89 を「第 N−10 章」）。下巻の前書き `20-vol2-intro` が「第20章 下巻のはじめに」になったので、本文の章にだけ使うようにした。
- 確かめたこと: 雛形から作った本を上中下の 3 巻に分け（巻ごとの前書き・共通の付録・一つの巻だけの付録・部・後書き）、`--volume all`・合本・単章ビルドで組んだ。章番号（1〜2・3〜4・5〜6）、付録の記号（中巻 A・B、下巻 A・C）、書名、出力ファイル名、目次、PDF のしおりが、それぞれ巻の振り方どおりになった。

### 13.2 段階 3・4（2026-10-20）

- 巻をまたぐ参照は、ラベルを全巻の原稿から集め、組む範囲に入らない原稿（`PreProcessCommands.other_volume_files`）のラベルを、その巻を選んだ状態（`Volumes.with_selection`）で数える。組んでいる巻の章の並びでは別の巻の章を数えられないので、図表番号の頭は `CrossReferenceProcessor.catalog_chapter_number_for` で目次から数える。二つ以上の巻に載る付録は、組む巻にも載っていれば組む巻の原稿として扱う。
- 別の巻への参照は `<span class="cross-ref-other-volume">` にし、リンクにしない。鉤括弧で始まる文字（「節題」）には巻の名前との間に空白を入れない（「上巻「節題」」）。
- 「前の章 @ch-x」の検査は、全巻の並び（区分ごとに巻の順につないだもの）で判定するので、下巻の最初の章の「前の章」は上巻の最後の章になる。
- 全巻目次は `toc.css` で組む（`stylesheet: toc.css` を前付けの Markdown に書く）。`body.whole_toc` に `page: front` を与え、目次と同じくローマ数字のノンブルにする。今の巻とほかの巻の色はリテラル（`#000`・`#666`）。
- PDF のしおりは、目次の始まりを「前書きの終わりの次」で決めていた。全巻目次が間に入ると前書きの終わりが全巻目次の手前で切られ、目次が全巻目次と同じページを指したので、全巻目次があるときは目次の見出しをその後ろで探す（`OutlineExtractor#page_range_toc`）。
- 確かめたこと: 3 巻の試しの本で、下巻から中巻・上巻を指す `@chapref`・図の参照・`@pageref` が「中巻 第 4 章「…」」「中巻 図 4-1」「上巻 第 1 章「…」」になり、中巻の最初の章の「前の章 @ch-new」（上巻の最後の章）が食い違いとして知らされなかった。中巻に `whole_toc: true` を書くと、前書きの後・目次の前に全巻目次が入り、PDF のしおりも「中巻のはじめに p4 → 全巻目次 p5 → 目次 p6」となった。

### 13.3 段階 5（2026-10-21）

- 巻で上書きできるキーは `ConfigKeys.book_keys`（`book` で始まる現役のキー）から作り、`Build::Volumes::BOOK_KEYS` に置いた。巻の設定は `VOLUME_KEYS`（`name`・`id`・`chapter_start`・`appendix_start`・`whole_toc`）と分け、知らないキーの 🟡 には「巻の設定」「書誌情報」「目次の区分」を分けて並べる。`apply_config!` は巻に書いた値を `book:` にだけ重ねる。空欄（`isbn:` だけ）は `deep_merge_config` の決まりで上書きしない。`isbn: ""` は上書きする。
- `vs cover --volume all` は同じプロセスで巻ごとに作る。作り終えたら、`reload_configuration!` で読み直すのではなく、作る前の `CONFIG` を入れ直す。読み直すと `page_presets.yml` などを読み直すことになり、試験の器で止まった。
- `RetiredKeyRemover.move` は、移した先の親（`book:`）のブロックの最後の行の後ろに、親の下の最初のキーと同じ字下げで足す。値の後ろの注釈も写す。書き換えた後に YAML として読み直し、移した先の値が元の値と同じで、ほかのキーが変わっていないことを確かめる。確かめられなければ書き込まない。値がブロック（`|`・`>`・次の行からの入れ子）なら移さない。
- 雛形の `config/catalog.yml` の Tips の例を、例の行を選んで `# ` を外せばそのまま YAML として使える形にした（それまでは字下げしたまま書いてあり、外すと読めなかった）。
- 確かめたこと: 3 巻の試しの本で、上巻 `cover: upper`（PNG）・中巻 `light`・下巻 `cover: lower` を書き、`vs build --volume all` と `vs cover --volume all` で、PDF の表と裏・EPUB の表紙・直下の JPEG が巻ごとの画像になった（EPUB の中の JPEG と直下の JPEG が一致）。中巻の `light` には中巻の書名が入った。上巻・中巻に書いた ISBN が `urn:isbn` に、`isbn: ""` の下巻は `urn:uuid` になり、下巻に書いた `release` だけが奥付に出た。ISBN を書かない巻が二つのとき 🟡（`config/catalog.yml:16 中巻 / …:31 下巻`）が出た。`output.cover: master` だけの `book.yml` で 🟡 の案内が出て、`vs upgrade` の整理で `book.cover: master` へ移った。book_ai_web_starter の `book.yml` も同じ整理で移した。

### 13.4 全巻目次の節（2026-10-21）

- 6 分冊の本（プログラミング練習帳）で、ほかの巻の課題（`##`）まで見たいという要望から、§9.2 の「章まで」を `page.toc_depth` に従う形に改めた。
- 節の番号の材料は `CrossReferenceProcessor.heading_number_context_for` に切り出し、章の番号の文字（`chapter_number_text_for`）と共通にした。巻を選んだ状態（`Volumes.with_selection`）で数えるので、ほかの巻の章も、その巻の振り方の番号になる。
- 本の `stylesheets/toc.css` は雛形の写しなので、段階 4 より前に作った本には全巻目次の規則（`.whole-toc-*`）が無く、黒丸の付いた素の箇条書きで組まれる。3 巻の試しの本と book_ai_web_starter がそうだった。`vs upgrade` で雛形を追えば入る。
- 確かめたこと: 3 巻の試しの本の中巻（`whole_toc: true`・`toc_depth: 3`）で、上巻・中巻・下巻の各章の下に節が「1-1」「3-2」「B-4」のように字下げして並び、前書き・後書きは題名だけになった。

### 13.5 本文の章を二つ以上の巻に載せる（2026-10-22）

- 番号・参照・全巻目次・単章ビルドは、段階 2〜4 の作り（巻を選んだ状態で、巻の中の位置から数える・載っていない巻からは `Volumes.containing` の最初の巻を指す）のままで §3.6 の決まりになった。直したのは三つ。
  - `VolumeDefinitionCheck` の「同じ本文の章を二つの巻に書いた」の 🔴 を外した。
  - `Volumes.merged_sections`（全巻・合本の目次）は項目を `uniq` で一つにしていたので、部の中に書いた共通の章が部ごとに別物として残り、合本に二度載った。原稿の名前で見て最初に載った所に一度だけ残し、中身の無くなった部は外す（`first_appearances`）。
  - 「前の章」の検査の並びは `Volumes.reading_order` で作り、共通の章を巻ごとに現す。並びに何度か現れる章は、どれか一つの載り方で隣なら正しいとする。
- 巻の中の本文の章は、`catalog.yml` に書いた順ではなく番号の順に数える（`ChapterConfig.htmls_for_kind`。組版・目次と同じ）。インストールの章（11）を下巻（21〜）にも載せる使い方では、下巻の最初の章になる。
- 確かめたこと: 3 巻の試しの本で、上巻の `11-workflow` を下巻の本文の先頭にも書くと、下巻の章扉・PDF のしおり・中巻の全巻目次で第5〜7章（上巻 2 章・中巻 2 章の次）になり、合本では 6 章が一度ずつ載った。中巻の `@chapref:ch-workflow` は「上巻 第 1 章「…」」、下巻の `@pageref:ch-workflow` は下巻の章としてページ付きで示された。
