# vs pdf:read の PDF の指定と章の名前 仕様書（案）

> **状態**: 実装済み（2026-10-11）。論点 7 件はすべて決定。§2〜§5（PDF の指定・章の名前・飾り外し・番号の割り当て・`--force`）、§7、§10（ページの指定）を実装した。
> 関連: `pdf-read-structure-spec.md`（読み取りの中身。本書は入口のファイル名と出口の章の名前だけを扱う）。

## 0. 結論（先出し）

- **PDF のファイル名と章の名前を切り離す。** PDF のファイル名は「どこから読むか」を指すだけで、自由な名前でよい。
  章の名前（`NN-slug`）は `vs create` と同じ決まりに従う。これまでは PDF のファイル名を章の名前へそのまま流し込んでいたので、
  点・日付・日本語の名前で壊れた章ができていた（§1）。
- **章の名前は、二つ目の引数で指定できる**（`vs pdf:read sources/講座.pdf 21-ai-course`）。
  省いたときは、整ったファイル名（`gitlab.pdf`）からだけ自動で作る。作れなければ止めて、そのまま打てるコマンドを示す（§3）。
- **ファイル名の飾りは外す。** Mac・Windows が複製やダウンロードで付ける「 (1)」「のコピー」「 copy」「 - コピー」は、章の名前に含めない（§3.2）。
- **番号の重なりは必ず止める**（§4.1）。番号を省いたときは、本文の最後の章の次の番号にする（§4.2）。
- **同じ章を読み直すときは止める。** `--force` を付けたときだけ置き換える（§5）。
- **`sources/` は省ける。** `/` を含まない指定（`vs pdf:read 97-sample`・`vs pdf:read 97-sample.pdf`）は `sources/97-sample.pdf` だけを探す。
  `/` を含むパス（`vs pdf:read path/to/name.pdf`）は、そのパスだけを探す（§2.1）。
- **ページを指定して読める**（`vs pdf:read gitlab.pdf 22-git-branch --pages 31-48,52`）。章の名前は著者が決める（§10）。
- 空白を含むファイル名を引用符なしで打ったときは読まない。シェルが止める（括弧）か、空白で分かれて届くので、不正なファイル名として止め、名前を変えるよう案内する（§2.3）。

## 1. 現状（2026-10-10 の洗い出し）

`vs new` で作った一時プロジェクトに、`docs/pdf-samples/` の 30 本を `sources/` へ置いて、4 通りの指定で試した。
問題の出た名前は、実際に変換して `vs build` まで通した。

| 指定の仕方 | 例 | 結果 |
|---|---|---|
| A. パス | `vs pdf:read sources/245.pdf` | 30 本とも読める |
| B. 絶対パス | `vs pdf:read ~/Downloads/245.pdf` | 30 本とも読める |
| C. 名前だけ | `vs pdf:read 245` | 11 本で止まる |
| D. 名前.pdf（`sources/` の中） | `vs pdf:read 245.pdf` | 10 本で止まり、1 本は壊れた章を作る |

見つかった不具合:

| # | 起きること | 例 |
|---|---|---|
| 1 | 点を含む名前で章を作ると、ほかのコマンドが点から後ろを拡張子と読む。`vs build` 全体が `Errno::ENOENT` で止まる | D で `Vol.53_09_482.pdf` → `01-vol.53_09_482.md`。以後は `01-vol` と読まれる |
| 2 | 名前だけの指定で、数字で始まる名前を整えずに使う。空白・日本語・4 桁の番号の章ができる | C で `2026-10-04 at 18-46-16 AI活用講座` → `contents/2026-10-04 at 18-46-16 AI活用講座.md` |
| 3 | 番号の重なりを確かめない。単章ビルドは「catalog.yml に登録されていません」と誤った案内で止まる。全体ビルドは片方の章をエラーにせず外して組む | `97-sample` があるところで `vs pdf:read 97-sample-ocr` |
| 4 | 同じ PDF を読み直すと、別の番号でもう一章作る。付録の番号を指定しても本文の 01 番になり、部のある目次では最後の部の頭に入る。名前が同じ 2 章は章のラベル ID が重なる（🔴） | `vs pdf:read 97-sample` → `01-sample.md`。`@ch-sample` が重なる |
| 5 | 名前だけの指定で、日本語・空白・括弧を含む名前が見つからない。案内に出る「探索パス」は整えた後の実在しない名前 | `GPUの育てかた` → `sources/gpu.pdf` を探す |
| 6 | 名前だけの指定で、大文字の名前を小文字にして探す。大文字と小文字を区別するファイルシステム（Linux・WSL）では見つからない（コードからの判断。実機は未確認） | `Network_no_Ehon` → `sources/network_no_ehon.pdf` |
| 7 | 数字だけの名前で、状況に合わない案内が出る | `245` → 「slug を含む章トークンを指定してください」 |
| 8 | 同じ PDF でも、指定の仕方で章の名前が変わる | `73-4-218` は C・D で `73-4-218`（73 番）、A・B で `01-pdf-73-4-218` |
| 9 | 日本語の名前から意味のある章の名前を作れない | `コンピュータネットワークのエッセンス` → `imported`、`データ解析に強くなるRustレシピ` → `rust` |
| 10 | 複製・ダウンロードの印が章の名前に残る。元の名前の PDF とは別の章になる | `IPSJ-MGN621105 (1).pdf`・`IPSJ-MGN621105 (1)のコピー.pdf` → どちらも `ipsj-mgn621105-1` |

原因は四つにまとまる。

1. **名前の整え方が二通りある。** `PdfReadCommand#normalize_slug` は英数字とハイフンだけを残す。
   名前だけの指定が通る `TokenResolver` は `.` と `_` も残す（1・8）。
2. **番号の重なりを確かめていない。** 確かめているのは、同じファイル名があるかだけ（3）。
3. **読み直したときの方針が無い**（4・10）。
4. **章の名前を著者が決める手段が無い**（2・9）。

## 2. 引数の読み方

```
vs pdf:read <PDF> [<章の名前>] [--pages SPEC] [--force] [--images-from DIR]
```

### 2.1 一つ目の引数：読む PDF

`sources/` は省ける。読み分けは、一つ目の引数が `/` を含むかどうかだけで決める。

| 一つ目の引数 | 探す PDF |
|---|---|
| `/` を含まない | **`sources/` の中だけ**。`.pdf`（大文字小文字を問わない）で終わらなければ `.pdf` を足す |
| `/` を含む | **そのパスだけ**（今いるディレクトリからの相対、または絶対パス） |

| 打つコマンド | 読む PDF |
|---|---|
| `vs pdf:read gitlab` | `sources/gitlab.pdf` |
| `vs pdf:read gitlab.pdf` | `sources/gitlab.pdf` |
| `vs pdf:read sources/gitlab.pdf` | `sources/gitlab.pdf` |
| `vs pdf:read ~/Downloads/gitlab.pdf` | `~/Downloads/gitlab.pdf` |
| `vs pdf:read ./gitlab.pdf` | プロジェクト直下の `gitlab.pdf` |

- 一つ目の引数は、どの PDF を読むかを指すだけ。章の名前は §3 で決める。
  `/` を含まない引数も、章の名前としてではなく、`sources/` の中のファイル名として探す。
- ファイル名は打ったとおりに探す。整えた後の名前で探すこと（`97-sample` → `sources/sample.pdf`、大文字を小文字にして探すこと）はやめる（§1 の 5・6）。
  日本語の名前（`vs pdf:read データ解析に強くなるRustレシピ.pdf`）でも PDF は見つかる。章の名前を作れなければ、§3.1 の案内で止まる。
- `/` を含まない引数は、今いるディレクトリを探さない。今のコードは、今いるディレクトリに `foo.pdf` があればそれを読むが、これをやめる。
  探す場所を一つにして、同じ名前の PDF が二か所にあっても、どちらを読むか迷わないようにする。
- 見つからないときは、探したパスを示す。今いるディレクトリに同じ名前の PDF があれば、`./` を付けたコマンドを添える。

```
🔴 PDF が見つかりません: sources/IPSJ-MGN621105.pdf
   → 今いるディレクトリの PDF なら: vs pdf:read ./IPSJ-MGN621105.pdf
```

### 2.2 二つ目の引数：章の名前

- 形は `NN-slug`（番号を決める）か `slug`（番号は §4.2 で決める）。
  - `NN` は 2 桁の数字。
  - `slug` は英小文字・数字・ハイフンで、数字だけにはしない（`01-245` は章の範囲と読まれる）。
- 大文字と `_` は `vs create` と同じく整える（`Hajimete_no_Rust` → `hajimete-no-rust`）。整えて形が変わったときは、どの名前にしたかを知らせる。
- 点・空白・日本語を含む名前は、整えずに止める。案内には、使える名前の例を添える。
- 二つ目の名前は、ファイル名から作る名前より優先する（`vs pdf:read gitlab 21-git` は `sources/gitlab.pdf` を `21-git.md` へ読む）。
- 番号だけ（`21`）なら、番号はそれにし、名前はファイル名から作る（`vs pdf:read gitlab.pdf 21` は `21-gitlab.md`）。ファイル名から名前を作れなければ、§3.1 の案内で止める。

### 2.3 シェルとの境目

- 括弧（`(1)`）を含む名前を引用符なしで打つと、zsh も bash も `vs` を起動せずに止める。**これは扱わない。**
  94 章では、使える名前に変えるよう案内する（§6）。名前を途中まで打って Tab で補えば `IPSJ-MGN621105\ \(1\).pdf` と書かれて読めるが、そちらは勧めない。
- 括弧の無い、空白だけの名前（`2026-06-10 at 10-08-42 AI活用講座.pdf`）は、シェルが空白で分けて `vs` に渡す。
  今は `Could not parse token "at"` と言って、コマンド一覧を丸ごと出している。
  **分かれた引数はつなぎ直さず、不正なファイル名として止める**（論点 1）。名前を変えれば、引用符も Tab も要らなくなる。
- 分かれて届いたと見なすのは、引数が 3 つ以上あるとき、または二つ目以降に `.pdf` で終わる引数があるとき。
  案内には、つなげた名前（どのファイルのことか分かるように）と、使える名前の決まりを示す（§3.1 と同じ文言）。

```
🔴 ファイル名に空白があるため、読み込めません: sources/2026-06-10 at 10-08-42 AI活用講座.pdf
   ファイル名を、英字で始まる半角の英小文字・数字・ハイフン（-）・アンダースコア（_）だけの名前に変えてから読んでください
   （例: awesome.pdf、my-reference_2047.pdf）
```

- `&` を含む名前（`データ構造&アルゴリズム.pdf`）を引用符なしで打つと、シェルが `&` の所で分ける。前の部分（`vs pdf:read データ構造`）を裏で走らせ、
  後ろの部分（`アルゴリズム.pdf`）をコマンドとして実行する（`command not found`）。`vs` には前の部分しか届かないので、PDF が見つからずに止まる。
  そのとき、打った名前に `&` が続く PDF が同じフォルダにあれば、それを示して名前を変えるよう案内する。全角の `＆` はシェルが分けないので、§3.1 の案内になる。

```
🔴 PDF が見つかりません: sources/データ構造.pdf
   sources/データ構造&アルゴリズム.pdf があります。& を含むファイル名は、シェルが & の所で分けて渡すので読み込めません
   ファイル名を、英字で始まる半角の英小文字・数字・ハイフン（-）・アンダースコア（_）だけの名前に変えてから読んでください
   （例: awesome.pdf、my-reference_2047.pdf）
```

### 2.4 案内に出すコマンド

- 止めたときに示すコマンドは、**著者が打った形のまま返す**。
  `sources/` を省いて打った人には省いた形で、パスで打った人には同じパスで返す。案内のコマンドは、そのまま貼り付けて打ち直すものなので、打った形と違うと「`sources/` が要るのか」と迷わせる。
- どのファイルのことかを示す行（🔴 の行）には、実際の場所（`sources/` を付けたパス）を書く。
- 例は §3.1・§4.1・§5 を参照。

## 3. 章の名前の決め方

### 3.1 決める順

1. 二つ目の引数があれば、それ（§2.2）。
2. 無ければ、PDF のファイル名から作る。`sources/` を省いたときも、パスで指定したときも同じ（§1 の 8）。
   - 拡張子を除き、飾りを外す（§3.2）。
   - 残りが**整った名前**なら、`vs create` と同じく整えて章の名前にする。
   - 整った名前でなければ、止めてコマンドを示す。

**整った名前**は、英字で始まり、英字・数字・`-`・`_` だけでできた名前。頭に `NN-` があればそれを番号とする（今の `CHAPTER_FILE_NAME`）。
日本語を落とすこと（`imported`・`rust`）や、数字で始まる名前に語を足すこと（`pdf-245`）は、自動ではしない。

手元の 30 本での分かれ方:

| 分類 | 本数 | 例 | 扱い |
|---|---|---|---|
| 整った名前 | 18 | `gitlab`・`heidelberg`・`IPSJ-MGN621105`・`Hajimete_no_Rust` | そのまま読める（`hajimete-no-rust` など） |
| 数字で始まる・点を含む | 3 | `245`・`73-4-218`・`Vol.53_09_482` | 止めて、名前の指定を案内する |
| 日本語・空白を含む | 9 | `GPUの育てかた`・`Exercise D エンジニア脳を鍛える究極の演習集` | 止めて、名前の指定を案内する |

案内には、名前を変える道と、章の名前を添える道の両方を示す。どちらも、**使える名前の決まりを言葉で書き、例を二つ添える**（論点 2）。
例は、いちばん短く分かりやすい `awesome` と、使える字（英小文字・数字・ハイフン・アンダースコア）を全部含む `my-reference_2047` の二つ。
ファイル名の英数字から候補を作ること（`データ解析に強くなるRustレシピ` → `rust`）はしない。中身を表さない名前を、そのまま打たせてしまうため。
大文字は案内には書かないが、受け付けて小文字にする（`IPSJ-MGN621105.pdf` → `ipsj-mgn621105`）。

```
$ vs pdf:read コンピュータネットワークのエッセンス.pdf
🔴 ファイル名から章の名前を作れません: sources/コンピュータネットワークのエッセンス.pdf
   使える名前: 英字で始まる半角の英小文字・数字・ハイフン（-）・アンダースコア（_）（例: awesome、my-reference_2047）
   → ファイル名を変える: awesome.pdf にしてから vs pdf:read awesome.pdf
   → 章の名前を添える:   vs pdf:read コンピュータネットワークのエッセンス.pdf 62-awesome
   （番号を省くと 62 番になります）
```

パスで指定したときは、コマンドもパスの形で返す（§2.4）。

```
$ vs pdf:read ~/Downloads/コンピュータネットワークのエッセンス.pdf
   …
   → ファイル名を変える: awesome.pdf にしてから vs pdf:read ~/Downloads/awesome.pdf
   → 章の名前を添える:   vs pdf:read ~/Downloads/コンピュータネットワークのエッセンス.pdf 62-awesome
```

章の名前ではアンダースコアをハイフンに整える（`vs create` と同じ）ので、`my-reference_2047.pdf` から作る章は `62-my-reference-2047` になる。

### 3.2 外す飾り

ファイル名の末尾から、次の印を外す（重なっていれば繰り返す。大文字小文字を問わない）。

| 付く場面 | 例 | 外した後 |
|---|---|---|
| ブラウザで同じファイルを二度ダウンロード（Mac・Windows） | `IPSJ-MGN621105 (1).pdf` | `IPSJ-MGN621105` |
| Finder で複製（日本語） | `IPSJ-MGN621105のコピー.pdf`・`IPSJ-MGN621105のコピー 2.pdf` | `IPSJ-MGN621105` |
| Finder で複製（英語） | `IPSJ-MGN621105 copy.pdf`・`IPSJ-MGN621105 copy 2.pdf` | `IPSJ-MGN621105` |
| エクスプローラーで複製（Windows） | `IPSJ-MGN621105 - コピー.pdf`・`IPSJ-MGN621105 - Copy (2).pdf` | `IPSJ-MGN621105` |
| 重なったもの | `IPSJ-MGN621105 (1)のコピー.pdf` | `IPSJ-MGN621105` |

- 外した結果、既にある章と同じ名前になることが多い。そのときは §5 の読み直しとして扱う（別の章は作らない）。
- 日付と時刻（`2026-06-10 at 10-08-42 AI活用講座`）は飾りとして扱わない。空白と日本語があるので、§3.1 のとおり名前の指定を案内する。
- 外すのは章の名前を作るときだけ。PDF を探すときは、ファイル名をそのまま使う。

## 4. 番号

### 4.1 重なりを止める

使われている番号は、`contents/*.md` の頭の 2 桁と、`catalog.yml` に載っている章の番号（原稿が無いものも含む）から集める。

| 場合 | 扱い |
|---|---|
| 同じ章（番号も名前も同じ）がある | §5 の読み直し |
| 番号が同じで、名前が違う | 止める。どの章が使っているかと、同じ区分（本文・付録など）の空いている番号を示す |
| 名前が同じで、番号が違う | 止める。章のラベル ID（`@ch-<slug>`）が重なるため。その章を読み直すコマンドと、別の名前の例を示す |

```
$ vs pdf:read 97-sample-ocr
🔴 97 番は 97-sample が使っています
   → 空いている付録の番号: 98
   → vs pdf:read 97-sample-ocr 98-sample-ocr
```

### 4.2 番号を省いたとき

- **本文（01〜89）でいま使われている一番大きい番号の次**にする。雛形なら `61-developer` の次の 62。目次では本文の末尾に入る。
- 89 まで使われていれば、01〜89 の空いている一番小さい番号にする。空きが無ければ止める。
- 付録やまえがきにしたいときは、著者が番号を指定する。
- 名前が既にある章と同じなら、番号は割り当てない。その章の読み直しとして扱う（§5）。

## 5. 読み直し

- **読む先の章が既にあるときは止める。** 「既にある」とは、§4.1 の「同じ章」のときと、番号を省いて名前が既にある章と同じときを指す。
- `--force` を付けたときだけ、その章の原稿を置き換える。
  - 前回の画像（`images/<章>/`）は消してから書き出す。前回の画像が残って混ざらないようにするため。
  - `catalog.yml` は既に載っているので触らない。

```
$ vs pdf:read gitlab.pdf
🔴 62-gitlab は既にあります（前回 sources/gitlab.pdf から読みました）
   → 読み直して置き換えるなら: vs pdf:read gitlab.pdf --force
   → 別の章として読むなら: vs pdf:read gitlab.pdf 63-gitlab-2
```

- **どの PDF から読んだかを原稿の頭に残す**。

  ```markdown
  <!-- pdf:read: sources/gitlab.pdf（sha256: 3f2a…） -->
  ```

  - 前処理が HTML コメントを除くので、組版には出ない。`pdf:read` は既に `<!-- pdf:read: … -->` の形で注記を書いている。
  - 番号も名前も違う章として読もうとしたとき、中身が同じ PDF（sha256 が一致）から読んだ章があれば、知らせる（止めない）。
    著者が名前を指定しているなら、意図して読んでいるはずなので止めない。

  ```
  🟡 この PDF は 62-gitlab として読み込み済みです（中身が同じです）
  ```

## 6. 94 章に書くこと

- `sources/` に置いた PDF は、ファイル名だけで指定できる（`vs pdf:read gitlab.pdf`）。ほかの場所の PDF は、`/` を含むパスで指定する（`./gitlab.pdf`・`~/Downloads/gitlab.pdf`）。
- 章の名前は二つ目の引数で付けられる。省くと、整ったファイル名から作り、本文の末尾の番号にする。
- ファイル名に空白や括弧があるときは、使える名前（§3.1）に変えてから読む。Tab で補えば読めるが、案内は名前を変えるほうに寄せる。
- 読み直すときは `--force`。
- 一部のページだけ読むときは `--pages`（§10）。ページ番号は PDF の 1 枚目から数え、紙面のノンブルとはずれることがある。

## 7. あわせて直したもの・対象外

あわせて直したもの（2026-10-11 実装）:

- **`vs create`・`vs rename` も番号とスラッグの重なりを確かめていなかった**（`97-sample` があるところで `vs create 97-foo`・
  `vs create 01-sample` が通った。`vs rename` は変更先とまったく同じ名前の章しか見ていなかった）。
  別の章（`contents/` の原稿か `catalog.yml` の章）が使っている番号かスラッグなら止め、重ならない番号（同じ区分の空き番号）や
  スラッグ（`-2` を足したもの）で打ち直すコマンドを示す。一度に作る章どうしの重なりも止める（論点 3）。
  `vs rename` は新しく重なりを作るときだけ止める（変えない部分は見ない）。既にある重なりを解く `vs rename 97-sample 97-sample-2` を止めないため。
  確かめ方は `ChapterNames`（`conflicts`・`suggestion`）にまとめた。§4.1 の実装でも使う。
- **目次の読み込みが、番号の重なった章を黙って 1 章に絞っていた**（`TokenResolver#load_catalog_entries` の `uniq(&:number)`）。
  `vs preflight` が「未登録の原稿」と誤って案内し、全体ビルドが片方を外して組んでいた。
  同じ章を二度書いた行だけをまとめる（`uniq(&:basename)`）ようにし、`DuplicateNumberCheck` を警告からエラーにした（論点 4）。
  数えるのは `contents/` の原稿と `catalog.yml` の章。2 つめ以降を同じ区分の空き番号へ振り直す `vs rename` のコマンドを添える。
  番号だけの指定（`vs build 97`）は、重なった章があれば解決しない。
- **スラッグが同じで番号の違う章を止めていなかった**（`01-sample` と `97-sample`）。番号で指せば組めるが、`vs build sample` は
  片方だけを黙って組み、章のラベル ID（`@ch-sample`）が重なっていた。著者もどちらを書けばよいか迷う。
  新しい検査 `DuplicateSlugCheck` がビルドの前に止め、2 つめ以降のスラッグを変える `vs rename` のコマンドを添える。
  大文字と小文字の違いだけのスラッグも同じとみなす。スラッグだけの指定（`vs build sample`）は、同じスラッグの章が 2 つあれば解決しない。
- **章のファイル名の決まりを確かめていなかった**。決まりは `vs create` の作る形（`ChapterNames::VALID_BASENAME`。2 桁の番号と、
  英小文字・数字・ハイフンのスラッグで、数字だけにはしない）。点を含む名前は章の解決が点から後ろを拡張子として削り
  （`01-vol.53_09_482` → `01-vol`）、全体ビルドが `Errno::ENOENT` で異常終了していた。`_` で番号を区切った名前（`97_sample-x`）は
  存在しない `97-sample-x.md` を指し、番号の重なりの検査もすり抜けていた。手の `mv`・`cp`（Finder の複製「97-sample のコピー.md」、
  版を付けた控え「97-sample.v2.md」）でも起きる。
  - ビルドの前の検査 `ChapterFileNameCheck` が止める（著者が選んだ厳しさ: 大文字・`_`・日本語もエラー。2026-10-11）。
    番号で始まる原稿と catalog.yml の章が対象で、番号で始まらない原稿（メモ）は見ない。
  - 直す名前は、使えない字をハイフンにし、重なれば空き番号・`-2` を当てる（`ChapterNames.suggestion`）。
    コマンドは catalog.yml に載っていれば `vs rename`、載っていない原稿は `mv`（`ChapterNames.rename_command`）。
    空白などシェルで意味を持つ ASCII の記号だけをエスケープし、引用符を求めない（`Shellwords.escape` は日本語にも `` を付ける）。
    番号とスラッグの重なりの検査も同じ直し方を示す（残すのは決まりの形の名前）。
  - 章の解決が除く拡張子を、章のファイルのもの（`.md`・`.markdown`・`.html`・`.pdf`）だけにした。
  - `vs create`・`vs rename` は大文字と `_` を整えて作り（§2.2 と同じ）、点・空白・日本語を含む名前は止める。
- **`vs pdf:read` が壊れた章を作っていた**（§1 の 1〜4 のうち、§2〜§5 を待たずに直せるもの）。
  - 章の名前を決まりの形に整え（大文字と `_`）、整えられなければ止める。番号かスラッグがほかの章と重なれば止める（§4.1）。
    今の `pdf:read` は章の名前を PDF のファイル名から決めるので、PDF の名前を変えて読み直すコマンドを示す。
  - 同じ章が既にあれば、別の番号でもう一章作らずに止め、`vs delete` を案内する（§5 の置き換え `--force` は未実装）。
  - `sources/` の PDF を名前で指定したとき、打ったとおりの名前を先に探す（§2.1 の一部。§1 の 5）。
  - エラーの 2 行目以降（探したパス・打ち直すコマンド）を字下げした。

対象外:

- **OCR の出力が、行頭の `:::` でビルド前の検査を止める**（`97-sample-ocr` で、記法の一覧表を読んだ行）。ファイル名とは別の件。

| # | 論点 | 決定（2026-10-11） |
|---|---|---|
| 1 | 空白で分かれた引数をつなぎ直して読むか | つなぎ直さない。不正なファイル名として止め、使える名前に変えるよう案内する（§2.3）。著者に引用符を求めない |
| 2 | 名前が作れないときの案内に出す名前の例 | 決まりを言葉で書き、`awesome` と `my-reference_2047` の二つを例に添える。ファイル名の英数字から候補は作らない（§3.1） |
| 3 | 番号の重なりの確かめを `vs create` にも当てるか | 当てる。本書の §7 として実装済み |
| 4 | 目次の読み込みで番号が重なったときの扱い | `uniq(&:number)` をやめ、`DuplicateNumberCheck` をエラーにしてビルドを止める。本書の §7 として実装済み |
| 5 | `/` を含まない指定で、今いるディレクトリも探すか | 探さない。`sources/` の中だけを探す。プロジェクト直下の PDF は `./gitlab.pdf` と打つ。資料の置き場を `sources/` と案内しているので、その代わりとして受け入れる。プロジェクト直下にファイルを増やさない（§2.1） |
| 6 | ページを指定したとき、柱・ノンブルをどう見分けるか | 指定のページの前後 2 ページも見分けにだけ使い、出力は指定のページだけにする（§10.3）。1 ページだけ読むときこそ柱が残ると目立つため。OCR では前後のページの分も時間がかかるが受け入れる |
| 7 | 最後のページを越えた指定と、範囲の端の省略 | 越えた分は外して読み、🟡 で知らせる。一枚も残らなければ止める。`-11`（1 ページから）と `238-`（最後まで）を受け付け、`vs pdf:pages` と読み取りを共用する（§10.1・§10.2） |

## 9. テスト

`test/vivlio_starter/cli/pdf_read_command_test.rb` に足す。PDF は Prawn で作る。

- 一つ目の引数の読み分け：`/` を含む → そのパス。含まない → `sources/` の中（`.pdf` が無ければ足す）。大文字・日本語の名前を打ったとおりに探す。
- `/` を含まない指定は、今いるディレクトリに同じ名前の PDF があっても読まない。見つからないとき、`./` を付けたコマンドを示して止まる。
- 二つ目の引数：`NN-slug`・`slug`・整える名前（`Foo_Bar`）・止める名前（点・空白・日本語・数字だけ）。
- 飾りを外す：§3.2 の表の 5 種類と、外した後に既存の章と同じ名前になる場合。
- 整った名前でないファイル名（`245.pdf`・`Vol.53_09_482.pdf`・日本語）で止まり、案内に番号と名前の例が出る。
- 番号の重なり：番号が同じで名前が違う／名前が同じで番号が違う、で止まる。
- 番号を省いたとき：本文の一番大きい番号の次になる。89 まで使われているとき。
- 空白で分かれた引数（3 つ以上、または二つ目以降が `.pdf` で終わる）で止まり、つなげた名前と使える名前の決まりが出る。
- `&` の前の部分だけが届いたとき、`&` を含む PDF を示して名前を変えるよう案内する（ファイル名の濁点が NFD でも）。
- 案内のコマンドが打った形で返る（`sources/` を省いた形・`sources/` 付き・`~/Downloads/` のパスの 3 通り）。
- 読み直し：止まる。`--force` で置き換え、前回の画像が消える。頭の注記に PDF の名前と sha256 が入る。中身が同じ PDF を別の名前で読むと 🟡。
- ページ指定（§10）：
  - `--pages 2-3,5` で、そのページの文字と図だけが原稿に入る。頭の注記にページが入る。
  - 章の名前を省くと止まり、名前の決まりと、名前を添えたコマンド（`--pages` 付き）が出る。
  - `-11` で 1 ページから、`238-` で最後のページまで読む。`--pages -11`（空白区切り）・`--pages=-11` のどちらも通る。`vs pdf:pages` も同じ。
  - 最後のページを越えた分（`238-260`・`10,260`）は外して読み、🟡 が出る。頭の注記は実際に読んだページになる。
  - 読めるページが残らない（`260`・`250-260`）と止まり、総ページ数が出る。書き方の誤り（`5-3`・`0`・`a`・`-`）でも止まる。
  - `OptionTokenNormalizer`：`-` と数字で始まる値を受け取る。`-h` はフラグのまま。
  - 1 ページだけ指定しても、前後のページで柱とノンブルが落ちる。前後のページの文字は原稿に入らない。
  - 飛んだ範囲（`2-3,5`）の境目で段落がつながらない。
  - 中身が同じ PDF から読んだ章があり、ページが重なれば 🟡、重ならなければ出ない。

§1 の 30 本で、4 通りの指定を試す確かめ方は、一時プロジェクトで行う（`docs/pdf-samples/` を `sources/` へ写して、
`PdfReadCommand` の解決だけを呼ぶ。変換はしない）。実装の後に同じ表を作り直し、§1 の不具合 10 件が出ないことを確かめる。

## 10. ページを指定して読む

### 10.1 書き方

```
vs pdf:read gitlab.pdf 21-git-basics --pages 12-30
vs pdf:read gitlab.pdf 22-git-branch --pages 31-48,52
vs pdf:read gitlab.pdf 20-git-intro --pages -11
vs pdf:read gitlab.pdf 23-git-appendix --pages 238-
```

- 書き方は `vs pdf:pages --pages 1,3,5-8` と同じ。読み取りは `PdfToJpeg#parse_page_spec` を共用する（重なりは除き、小さい順に並べる）。
- **始めを省くと 1 ページから、終わりを省くと最後のページまで**（`-11` は `1-11`、`238-` は 238 ページから最後まで）。`vs pdf:pages` も同じ書き方を受け付ける（論点 7）。
  終わりを決めるには総ページ数が要るので、`parse_page_spec` に最後のページ番号を渡す。両方の省略（`-`）は書き方の誤りとして止める。
- `-11` は `-` で始まるので、今の引数の並べ替え（`OptionTokenNormalizer`）は `--pages -11` の `-11` を値と見なさず、位置引数へ回す。
  値を取るオプションの次が `-` と数字で始まるときは、値として受け取るよう直す（`--pages=-11` は今でも通る）。
  今も `vs pdf:read a.pdf --images-from -x` は、`a.pdf` を `--images-from` の値と取り違える。直すのは数字で始まる値だけにし、`-h` などのフラグはこれまでどおりフラグとして読む。
- ページ番号は、**PDF の 1 枚目から数えた番号**。紙面に印刷されたノンブルとは、表紙や前付けの分だけずれることがある。ヘルプと 94 章に書く。
- 原稿の中の記法（`include:sample.rb:10-20` のような形）にはしない。`include:` は元のファイルを毎回そのまま写すので、ビルドのたびに取り込んでも同じ結果になる。
  `pdf:read` の出力は、原本と見比べて直す下書きなので、ビルドのたびに作り直すと直した所が消える。変換も遅い（OCR は 1 ページ数秒）。
- 構造を読む経路・Enhanced・Standard・OCR の、どの経路でも同じに効く。図も、指定のページからだけ抜き出す。

### 10.2 章の名前は著者が決める

- `--pages` を付けたときは、**章の名前（二つ目の引数）を必ず求める**。ファイル名から作ると、同じ PDF のどの範囲も同じ名前になり、§5 の読み直しとぶつかる。
  日本語のファイル名で名前を求める（§3.1）のと同じく、何の章かは著者が決める。
- 省いたときは止めて、名前を添えたコマンドを示す。コマンドは打った形で返す（§2.4）。番号は §4.2 で決まる番号を示す。

```
$ vs pdf:read gitlab.pdf --pages 31-48,52
🔴 ページを指定して読むときは、章の名前を添えてください: sources/gitlab.pdf
   使える名前: 英字で始まる半角の英小文字・数字・ハイフン（-）・アンダースコア（_）（例: awesome、my-reference_2047）
   → vs pdf:read gitlab.pdf 62-awesome --pages 31-48,52
   （番号を省くと 62 番になります）
```

- **最後のページを越えた分は外して読み、🟡 で知らせる。** `238-260` と打つ人は、多くの場合「238 ページから最後まで」のつもりで、大きめの数を打っている。
  打ち間違い（`206` のつもりで `260`）でも、読む範囲は 🟡 と頭の注記（`p.238-248`）に出るので、原本と見比べる段階で気づける。

```
$ vs pdf:read gitlab.pdf 23-git-appendix --pages 238-260
🟡 ページ 249〜260 はありません。238〜248 を読みます（sources/gitlab.pdf は 248 ページです）
```

- 一覧の一部だけが越えるとき（`10,260`）も同じ。越えたページを外して、残り（10）を読む。
- **読めるページが一枚も残らないときは止める**（`260`・`250-260`）。原稿が空になり、打ち間違いの見込みが高いため。総ページ数を添える。

```
🔴 ページ 250〜260 はありません（sources/gitlab.pdf は 248 ページです）
```

- 書き方の誤り（`5-3`・`0`・`a`・`-`）は、読む前に止める。

### 10.3 柱とノンブルの見分け方

- 柱とノンブルは、同じ高さに同じ文字列が出るページの数で見分けている（`LayoutStructure#drop_running_heads`。少なくとも 2 ページ）。
  指定のページだけで見分けると、1〜2 ページのときに柱が本文に残る。
- そこで、**指定のページの前後 2 ページも読み、見分けにだけ使う**（論点 6）。出力（原稿の文字・図）は指定のページだけにする。
  - 前後のページは、PDF の 1〜最後のページの内に限る。`31-48,52` なら、29・30・49〜51・53・54 を見分けに使う。
  - 柱・ノンブルのほか、ページをまたいで見る手がかり（`LayoutStructure` の「文書全体の手がかり」）も、同じ範囲で見る。
  - OCR では前後のページも読み取るので、範囲ごとに最大 4 ページ分の時間が増える。
- 飛んだ範囲（`31-48` と `52`）の境目では、段落も図のキャプションもつながない。間のページを読んでいないので、続きかどうか分からないため。

### 10.4 読み直しと頭の注記

- 頭の注記にページを残す。

  ```markdown
  <!-- pdf:read: sources/gitlab.pdf p.31-48,52（sha256: 3f2a…） -->
  ```

- 読み直し（§5）は、ページ指定があっても同じ。同じ章があれば止め、`--force` で置き換える。置き換えるときは、今回の `--pages` で読む。
  案内のコマンドには、打った `--pages` をそのまま付ける（§2.4）。
- §5 の「中身が同じ PDF から読んだ章がある」という 🟡 は、**ページが重なるときだけ**出す。ページを指定せずに読んだ章は、全ページを読んだものとして扱う。
  同じ本を章ごとに分けて読むのは、ふつうの使い方なので知らせない。
