# 語の途中に入った強調記法で校正がすり抜ける

## 1. 症状

`vs lint` の交ぜ書き検出は原稿の生の行に正規表現を当てている。強調記法が語の途中に
入ると、**読者が見る文字列**と**辞書を当てる文字列**が食い違い、両方向に壊れる。

| 原稿 | 読者が見る | 期待 | いまの結果 |
|---|---|---|---|
| `結**合し**直した処理` | 結合し直した処理 | 指摘なし | 🔴 `合し => 合祀` |
| `使**う回**数を減らす` | 使う回数を減らす | 指摘なし | 🔴 `う回 => 迂回` |
| `だ**円**の面積` | だ円の面積 | `だ円 => 楕円` | 🔴 指摘なし |
| `あいさつ**文**を差し込む` | あいさつ文を差し込む | `あいさつ文 => 挨拶文` | 🔴 指摘なし |
| `か**ぎ括弧**を使う` | かぎ括弧を使う | `かぎ括弧 => 鉤括弧` | 🔴 指摘なし |

**誤検出だけの問題ではない。** 前 2 行は前後を制約するガード（`(?<![一-龥])合し`）が
`合` の直前に `*` を見てすり抜けたもの、後 3 行は語が記法で分断されて当たらなくなった
ものである。原因は同じ——**判定の入力が、読者の見る文字列になっていない。**

MeCab を使う第 2 層も同様にすり抜ける（`使**う回**数` は記号のせいで
`使|**|う回|**|数` と切れ、`う回` の両端が形態素の境界に揃ってしまう）。

## 2. 直し方

コードを退避する `Masking.protect_code` と同じ流儀で、**強調記法を外した文字列で
判定し、位置を元の行へ戻す**。

```ruby
plain, map = Masking.strip_emphasis(line)
# plain      … 記法を外した文字列
# map[i]     … plain[i] が元の行の何文字目だったか
```

対象は CommonMark の強調と GFM の打ち消し線。開き・閉じが揃っている対だけを外す。

- `**bold**` / `__bold__`
- `*italic*` / `_italic_`
- `***both***` / `___both___`
- `~~strike~~`

アンダースコアだけ前後に **ASCII の** 英数字を許さない（`snake_case_name` を壊さない）。
和文は制限しない——**判断の根拠は VFM の実際の出力**である。厳密な CommonMark なら
`__太字__の語` は強調にならない（閉じ記号が左右とも文字に挟まれる）が、VFM は
`<strong>太字</strong>の語` を出す。仕様書ではなくレンダラに合わせる。

記号の内側に空白がある形（`2 * 3 * 4`）は外さない。VFM はここも強調と解釈するが
（`2 <em>3 </em>4`）、markdown-it の flanking 規則の再実装になるうえ、外さなくても
失うのは「まれな取りこぼし」だけで、誤って外すより安全側に倒れる。

## 3. `--fix`

置換は元の行に対して行う。マッチした語が元の行で**連続している**とき（＝語の内側に
記法が無い）だけ置換する。

- `結**合し**直した` … `合し` は元の行で連続（4〜5 文字目）→ `結**合祀**直した` ✔
- `だ**円**の面積` … `だ円` は 0 文字目と 4 文字目に分かれる → **置換しない**

後者を置換すると `**` が黙って消える。**著者の書いた記法を lint が勝手に落とすのは、
交ぜ書きを直さないより悪い。**指摘は出すので、著者が手で直せばよい。

## 4. 適用範囲

交ぜ書き（第 1 層・第 2 層）に適用する。**二通りに読める対比（ambiguous-comparison）
には今回入れない**——同じ露出はあるが（`A **と同様に** X しない`）、あちらは段落単位で
読んでおり位置の対応づけが別の作りになる。別の仕様書で扱う。

ルビ記法（`{逞|たくま}しき`）も語を分断するが、あれは文字を**外す**のではなく
**片方を選ぶ**変換なので、同じ仕組みでは扱えない。これも別。

## 5. 受け入れ条件

1. §1 の表 5 行がすべて「期待」どおりになる
2. `2 * 3 * 4` `a_b_c` `**強調**` `*斜体*` が壊れない（記法の外にある語は今までどおり）
3. `--fix` が §3 のとおりに振る舞い、行数と記法を保つ
4. コード領域（`` `結**合し**直した` ``）は今までどおり触らない

## 実装記録

2026-08-19 実装。`Masking.strip_emphasis`（新規）＋ `ProseChecker` の検出・置換を
位置ベースへ作り替え。受け入れ条件 4 つとも満たした。テストは EM-01〜05。

### 分かったこと

- **仕様書ではなくレンダラが正典。** `__太字__の語` を厳密な CommonMark の
  flanking 規則で書いたら、VFM の出力と食い違った。`node -e` で VFM に
  実際に食わせて挙動を確かめてから規則を決めた。
- **穴は両方向にあった。** 報告は誤検出（`結**合し**直した`）だったが、
  取りこぼし（`だ**円**`・`あいさつ**文**`・`か**ぎ括弧**`）のほうが件数は多い。
  原因は 1 つ——判定の入力が読者の見る文字列になっていなかった。
- **`--fix` を位置ベースへ作り替えたことで、収束が構造的に保証された。**
  以前は辞書を順に `gsub` していたので、置換後の文字列が次のパターンに当たりうる
  （PC-10 が見張っていた性質）。いまは 1 回の走査で得た位置だけを後ろから置くので、
  再走査が起きない。

### 残っている制限

- 記号の内側に空白がある強調（`2 * 3 * 4`）は外さない。§2 の理由。
- **二通りに読める対比（ambiguous-comparison）には入れていない。** 同じ露出はあるが
  （`A **と同様に** X しない`）、あちらは段落単位で読んでおり位置の対応づけが別の作りになる。
- ルビ記法（`{逞|たくま}しき`）は文字を**外す**のではなく**片方を選ぶ**変換なので、
  この仕組みでは扱えない。
