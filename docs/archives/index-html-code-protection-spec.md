# 索引スキャンが HTML 化されたインラインコードを保護しない不具合の修正

**状態**: 実装済み（2026-08-22・§7）
**発端**: 2026-08-22、rc.3 のビルド結果を見ていて、索引の「その他」に **`用語`** という項目が現れているのを発見した（`用語集ページ` は正しく「や」行にある）。

---

## 0. 何が起きたか

**記法の説明が、本物の索引語として登録されていた。**

`90-notation-cheatsheet.md` の早見表にはこう書いてある。

```markdown
| 索引・用語集に登録する | `[用語\|読み]`（読みは省略可） | 索引・用語集機能 |
```

`[用語|読み]` は**索引記法そのものを読者へ見せている**だけで、索引語ではない。だからバッククォートで囲んである。ところがビルド結果の `_index_matches.yml` はこうなっていた。

```yaml
用語:
  - yomi: 読み
    link: 90-notation-cheatsheet.html#idx-57c8b4b7eb46-1
```

**用語「用語」・読み「読み」として登録されている。** 読みが漢字なので五十音のどの行にも入らず、索引の「その他」に落ちて紙面に出ていた。

---

## 1. 原因: 保護がバッククォートしか知らない

索引スキャナはインラインコードを保護している。

```ruby
mask.protect!(Masking::INLINE_CODE_SPAN)   # /(?<!`)(`+)(?!`).+?(?<!`)\1(?!`)/m
```

**この正規表現はバッククォートを探す。** ところがスキャンが走る時点で、原稿の一部は既に HTML になっている。

| 段 | 状態 |
|---|---|
| Step 3 前処理 | `:::{.long-table}` の表を**生 HTML の `<table>` へ変換**する |
| Step 4 索引スキャン | ここで走る。表のセルは `<td><code>[用語\|読み]</code></td>` |

`<code>` になった時点でバッククォートは残っておらず、エスケープしていた `\|` も `|` へ戻っている。スキャナから見れば、地の文に裸で置かれた `[用語|読み]` と区別が付かない。

### 1.1 二か所ある

保護は 2 か所で行われ、**どちらも同じ穴を持つ**。

| 場所 | 用途 | 現在の保護 |
|---|---|---|
| `process_line`（`index_match_scanner.rb:362`） | 手動マークアップ `[用語]` の処理 | `INLINE_CODE_SPAN` のみ |
| `protect_untouchable_regions!`（同 :534-541） | 辞書由来の自動タグ付け・用語集 †リンク | `/<[^>]+>/` で**タグは**退避するが、**タグの中身は保護しない** |

後者の `/<[^>]+>/` は `<code>` という開始タグと `</code>` という終了タグを個別に退避するだけで、**その間のテキストは素通し**である。

### 1.2 `vs index:auto` はすり抜けない

辞書登録（`index:auto`）は**生の原稿**を走査するのでバッククォートが残っており、保護が効く。実際 `用語` は `config/index_glossary_terms.yml` に入っていない。**ビルド時のスキャンだけが誤登録している。**

同じ入力が、経路によって別の結果になっていた。

---

## 2. 何が正しいか

**同じ内容は、表現形式によらず同じ扱いになるべきである。**

`` `foo` `` と `<code>foo</code>` は「リテラルとして見せる」という同一の意図で、前者を保護して後者を保護しないことに理由はない。前処理の変換順という**実装の都合**が紙面に漏れている。

インラインコードの中の語を索引に載せないのは既存の方針である（`process_line` のコメントが「リテラル表示が目的なので索引対象から外す」と明記している）。本仕様はその方針を HTML 側へ広げるだけで、方針そのものは変えない。

---

## 3. 修正

### 3.1 `Masking` に HTML のインラインコードを足す

コード領域の解釈は `Masking` が唯一の実装である（P1）。スキャナ側に正規表現を書かない。

```ruby
# HTML 化されたインラインコード（<code>…</code>）。
# 前処理が表やコンテナを生 HTML へ変換した後は、バッククォートが残らないため
# INLINE_CODE_SPAN では保護できない。属性つき（<code class="language-ruby">）も受ける。
HTML_INLINE_CODE = %r{<code\b[^>]*>.*?</code>}m
```

**非貪欲にする。** 1 行に複数の `<code>` がある早見表で、貪欲だと最初の開始から最後の終了までを 1 つと見なし、間の地の文まで保護してしまう。

### 3.2 2 か所とも保護する

```ruby
# process_line
mask.protect!(Masking::HTML_INLINE_CODE)
mask.protect!(Masking::INLINE_CODE_SPAN)

# protect_untouchable_regions!
mask.protect!(TAGGED_TERM_PATTERN)
mask.protect!(Masking::HTML_INLINE_CODE)   # ← タグより先。中身ごと退避する
mask.protect!(/<[^>]+>/)
…
```

**`/<[^>]+>/` より先に置く。** 後にすると `<code>` と `</code>` が個別に退避され、中身を囲む対が消えて保護できない（`TAGGED_TERM_PATTERN` を先頭に置いてあるのと同じ理由）。

### 3.3 やらないこと

- **前処理の順序は変えない。** 表の HTML 化をスキャンの後ろへ動かす案もあるが、依存が広く RC 直前に触る範囲ではない。保護側で解けるなら、そちらが小さい。
- **`<pre>` は対象外。** ブロックのコードは既にフェンスとして `Masking` が扱っており、前処理後も `<pre>` の中身が索引語になった実例は無い。必要になってから足す。

---

## 4. 影響（実測）

`<code>` の中でタグ付けされていた索引語は **23 件**（`90-notation-cheatsheet.md` 19 件・`91-command-cheatsheet.md` 4 件）。修正後はこれらが索引から外れる。

**減るのは正しい。** いずれも「記法を見せている箇所」であって、その語の説明がある場所ではない。索引の役割は説明の在り処への案内なので（`index-main-reference-spec.md`）、記法見本を指すページ番号は読者の役に立たない。

ただし**語そのものが索引から消えるわけではない**——同じ語が地の文で使われていれば、そちらは従来どおり拾う。消えるのは「早見表のセルを指す 1 件」だけである。実装後にこの点を実測で確かめる（§6）。

---

## 5. テスト

`test/vivlio_starter/cli/index/index_match_scanner_test.rb`。

| ID | 内容 |
|---|---|
| HC-01 | `<code>[用語\|読み]</code>` を含む行で、手動マークアップとして登録されない |
| HC-02 | `<code>` の中の辞書語がタグ付けされない（`<code>vs build</code>` に `ビルド` を当てない） |
| HC-03 | `<code>` の**外**にある同じ語は従来どおりタグ付けされる（保護が広がりすぎていない） |
| HC-04 | 1 行に `<code>` が複数あるとき、その間の地の文が保護されない（非貪欲の確認） |
| HC-05 | 属性つき `<code class="language-ruby">` も保護される |
| HC-06 | バッククォート形式の保護が従来どおり効く（回帰） |

**HC-04 が要。** 貪欲な正規表現にすると早見表の 1 行が丸ごと保護され、「索引が静かに減る」形で壊れる。

## 6. 検証

1. 全章ビルドし、`_index_matches.yml` に **`用語`（yomi=読み）が無い**こと
2. 索引ページに「その他」の群が出ないこと
3. 索引語の総数を修正前後で比べ、**減少が 23 件の範囲に収まる**こと。それ以上減っていたら保護が広すぎる
4. 用語集の †リンク数が変わらないこと（`protect_untouchable_regions!` は用語集側からも呼ばれる）

## 7. 実装記録（2026-08-22）

§3 のとおり実装した。設計を変えた箇所は無い。

### 7.1 変更したもの

| ファイル | 変更 |
|---|---|
| `cli/masking.rb` | `HTML_INLINE_CODE`（`%r{<code\b[^>]*>.*?</code>}m`）を追加 |
| `cli/index/index_match_scanner.rb` | `process_line` と `protect_untouchable_regions!` の 2 か所で、`INLINE_CODE_SPAN` より前・`/<[^>]+>/` より前に保護を足した |

### 7.2 検証（実測）

**誤登録が消え、巻き添えも無かった。**

| | 修正前 | 修正後 |
|---|---|---|
| 索引語 | 176 種 | **173 種** |
| 出現 | 2,399 件 | **2,379 件**（−20） |
| 紙面の「その他」群 | あり（`用語`） | **無し** |
| yomi が かな/ASCII でない語 | 1 件 | **0 件** |

消えた 3 語は `用語`・`!`・`id` で、**いずれも辞書に登録が無い**——すべて記法見本から拾われた誤登録である。減少 20 件は §4 の見込み（23 件）の範囲に収まった。

**`!` と `id` は当初気づいていなかった。** 早見表のセルにある `[!]`（コメント強調マーカー）と、HTML 属性の `id` が同じ経路で索引語になっていた。1 件を追ううちに同種の誤登録が 3 件見つかった形で、**症状が 1 つでも原因は共通**だったことの裏づけになる。

### 7.3 テスト

修正を戻すと 6 件中 3 件が落ちる（HC-01・HC-02/03・HC-05）。HC-04（非貪欲）と HC-06（バッククォート回帰）は修正前でも通るので、**回帰を捕まえるのは前者 3 件**である。

### 7.4 テストの書き方で 1 つ踏んだ（実装のバグではない）

タグ数を `scan('index-term').size + scan('<dfn ').size` で数えたら、1 つのタグ（`<dfn id="…" class="index-term">`）を 2 回数えて期待値と合わなかった。`id="idx-` で数えれば 1 タグ 1 件になる。**実装は最初から正しく、数え方だけが誤っていた。**
