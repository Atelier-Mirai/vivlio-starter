# 索引の主要参照が別の巻にある語 — 巻の名前で案内し、副次参照を絞る

> 関連: `index-main-reference-spec.md`（主要参照・R6 の間引き）、`multivolume-spec.md` §8（別の巻を指す参照）

## 0. 背景

分冊の本で、主要参照（辞書の `main:`）の章を**組んでいない巻**の索引では、語の出現が全部並ぶ。

`index-main-reference-spec.md` R6 の間引き（`max_sub_references`）は、**主要参照の無い語を間引かない**。
「まずここを読めばよい」という案内が無いまま出現を削ると、語が索引から実質消えるからである。
一冊の本ではこの決まりで困らない。主要参照の無い語は、辞書に `main:` を書いていない語だけだったからである。

分冊では、`main:` を書いた語にも「この巻には主要参照が無い」ことが起きる。実測（book_ai_web_starter・上下巻・索引語 293 語のすべてに `main:` あり・`max_sub_references: 8`）:

| 語 | 主要参照 | 長くなる巻 | 並んだ項目（範囲は 1 つと数える） |
| :--- | :--- | :--- | ---: |
| 状態 | `22-janken-state`（下巻） | 上巻 | 約 40 |
| HTML | `05-first-html`（上巻） | 下巻 | 約 60 |
| 関数 | `07-first-javascript`（上巻） | 下巻 | 約 50 |
| コンソール | `07-first-javascript`（上巻） | 下巻 | 約 20 |

著者の言葉では「本文に出現している箇所を列挙しただけの、役に立たない索引」になる。
しかも、その巻だけを手に取った読者には、説明がどこにあるかを知るすべがない。

## 1. 要件

### R1: 別の巻の主要参照を、巻の名前と章で案内する

巻を選んで組むとき、次の両方を満たす語の索引項目の頭に、主要参照の章を巻の名前を添えて置く。

- 組む巻に、その語の主要参照の出現が無い
- 辞書の `main:` に、別の巻の章がある

```
コンソール　→ 上巻 第7章　12, 19, 55, 128, 157, 221
```

- 章の呼び名は、その巻を組んだときの章扉と同じにする（`第7章`・`付録 A`）。
  `@chapref` が別の巻の章を指すときと同じ数え方である（`multivolume-spec.md` §8）。
- 章番号を振らない章（前書きなど）は、章題を「」で囲んで出す（`→ 上巻「はじめに」`）。
- `main:` に別の巻の章が二つ以上あれば、目次の順に「・」でつなぐ。
- 節を名指しした `main:`（`07-first-javascript#コンソール`）も、章で案内する。別の巻の節のページはわからない。
- リンクにしない（別の巻へは飛べない）。

### R2: 案内を置いた語は、主要参照のある語と同じく副次参照を絞る

案内が「まずここを読めばよい」の代わりになるので、R6 の間引きの前提が満たされる。

- `main_and_sub`: 副次参照を `max_sub_references` 件まで絞る（章をまたいで公平に残す、既存の `trim_across_chapters`）。
- `main_only`: 案内だけを載せ、ページ番号は載せない。
- `all`: 案内も間引きもしない（従来どおり。逃げ道の意味を保つ）。
- 絞った語は、既存の「💡 索引の副次参照を N 語で 8 件までに絞りました」に数える（no silent caps）。

### R3: 合本・分冊でない本は変えない

合本（巻を選ばない `vs build`）は全巻の章を組むので、主要参照が別の巻に出ることはない。
`VOLUMES:` の無い本も同じ。どちらも出力は今と同じ。

### R4: 組版の後段で案内を落とさない

PDF では、重複除去の段（`BacklinkDeduplicator`）がページ範囲を畳むとき、`<dd>` の子を作り直す（`rebuild_dd!`）。
案内の要素はリンクではないので、作り直しても先頭に残す。

EPUB は `<dd>` の中のリンクにだけ章番号を入れるので、案内の要素はそのまま通る。

### R5: 見た目

```html
<dd><span class="index-other-volume">→ 上巻 第7章&#x3000;</span><a href="…"></a><a href="…"></a></dd>
```

- 案内とページ番号の間を全角 1 字ぶん空ける。空きは CSS でなく、案内の末尾の全角空白で持つ。CSS は雛形から本へ写したものなので、`vs upgrade` するまで古いまま残り、新しい規則が効かない。
- 案内の要素は `<a>` を含まない。ページ番号の区切りを作る CSS（`a:not(:last-child)::after`）は `<a>` どうしの並びしか見ないので、先頭に要素が増えても区切りは変わらない。

## 2. テスト

- 単体（`UnifiedPageBuilder`）
  - 別の巻の主要参照を持ち、組む巻に主要参照の出現が無い語に、案内が付き、副次参照が上限まで絞られる
  - 組む巻に主要参照の出現がある語には、案内を付けない
  - `main_only` は案内だけ、`all` は案内も間引きもしない
  - 案内の無い語（`main:` 無し）は従来どおり全部載る
- 単体（案内の文字を作る処理）: 第N章・付録・章番号の無い章・複数の巻・組む巻の章を含む `main:`
- 単体（`BacklinkDeduplicator`）: 範囲を畳んでも案内が先頭に残る
- 実機: book_ai_web_starter の上巻・下巻で索引を組み、§0 の語の項目を見る

## 3. 実装記録（2026-10-24）

- 案内の文字は `IndexCommands::OtherVolumeMain.guides`（`other_volume_main.rb`）が作り、`UnifiedIndexManager#build_index!` が `UnifiedPageBuilder` へ渡す。章の呼び名は、その巻を選んだ状態で `CrossReferenceProcessor.chapter_number_text_for` を呼んで得る（`@chapref` の別の巻と同じ道）。
- **案内とページ番号の間の空きは、最初 CSS（`index.css` の `margin-inline-end`）で付けたが、実機では効かなかった。** 本の `stylesheets/` は雛形を写したもので、`vs upgrade` するまで古い `index.css` のまま残る。案内の末尾の全角空白（`&#x3000;`）で持つことにし、CSS の規則は足していない。CSS に頼らないので、EPUB・Kindle でも同じに空く。
- 実機（book_ai_web_starter の写しで `vs build --volume all`）:
  - 下巻: 96 項目に案内が付き、絞った語は 80 語。「HTML」は約 60 項目 → 「→ 上巻 第5章」＋ 8 項目、「コンソール」は約 20 項目 → 「→ 上巻 第7章」＋ 8 項目。
  - 上巻: 「状態」は約 40 項目 → 「→ 下巻 第14章」＋ 8 項目（下巻は上巻の 12 章の続きから数える）。絞った語は 65 語。
  - 組む巻に主要参照がある語（下巻の「Git」）は、これまでどおり太字の主要参照が先頭に立つ。
