> 作成日: 2026-09-29（同日改訂: 推定器を Guesslang の二段構えに決定）

> 関連: `plain-math-notation-spec.md` §6（言語名のないフェンスの数式判定）, `notation-implementation-guide.md`, `lib/vivlio_starter/cli/pre_process/math_span_detector.rb`, `lib/vivlio_starter/cli/import/re_renderer.rb`（`guess_language`）, `lib/vivlio_starter/cli/lint.rb`, `contents/21-markdown-tutorial.md`, `contents/22-extensions.md`, `contents/31-lint.md`

## 0. 背景

言語名を書かないコードブロック（```` ``` ```` だけのフェンス）は、色分けされずに行番号だけが付く。22 章にはかつて「言語名がない場合には自動推測されます」と書いてあったが、推定はビルドに実装されたことがなく、2026-09-29 に記述を実態（「色分けされません」）へ直した（改善案.md #70）。

当初の意図は「言語名がなくても推定して色分けする」だった（ユーザー、2026-09-29）。改善案.md #70 では、`vs import` と同じ Rouge の推定を前処理でかける案を立てていた。この仕様書では、まず推定器の実力を実際の原稿で測り（§1）、その結果から方式を決めた（§3）。

## 1. 実測（2026-09-29）

### 1.1 対象にした原稿と試料

言語名のないフェンスのうち、`.output`・`.terminal`・`.diagram` の囲みの中にあるものを除いて数えた。

| 原稿 | 言語名なしフェンス | 中身の傾向 |
| :--- | ---: | :--- |
| 本書（`vivlio-starter/contents`） | 24 | ディレクトリの木・ログ・コマンドの書式・画面の文言。コードはほぼ無い |
| `book_ai_web_starter/contents` | 566 | JavaScript・HTML・CSS が半分強。残りは AI への質問文・出力・木 |
| `workbook`（練習帳、全 `.md`） | 635 | ほぼすべて実行結果（表・盤面・計算の経過）。数式 42 件を含む |

**著者によって、言語名なしフェンスの使い道がまったく違う。** 本書と練習帳では「色を付けたくない文字」の置き場で、ai_web_starter では「言語名を書き忘れたコード」である。

推定器は、次の 3 種類の試料で測った。

- **きちんとしたコード**: 16 言語を 10 行前後ずつ書いた試料 16 本。推定器が言語を見分けられるかを見る。
- **言語名の付いたフェンス（正解つき）**: 練習帳 659 件・本書 378 件。言語名を外して推定させ、著者の書いた言語名と比べる。本の中の実物（1〜5 行の断片・日本語のコメント・疑似コード）でどれだけ当たるかを見る。
- **言語名なしフェンス**: 上の表の 3 冊。実行結果や木を言語と取り違えないかを見る。

### 1.2 Rouge（`vs import` と同じ推定）は中身から言語を当てられない

`Rouge::Lexer.guess(source:)` は、中身だけが手がかりのときは各字句解析器の `detect?` に頼る。`detect?` を持つのは shebang（`#!/usr/bin/env ruby`）・`<!DOCTYPE html>`・`<?xml` のような**先頭の宣言**だけで、それが無いコードはすべて `plaintext` になる。きちんとしたコード 16 本のうち当たったのは、shebang つきの bash 1 本だけだった。

言語名なしフェンスでは、本書 24 件中 0 件、ai_web_starter 566 件中 31 件（すべて `<!DOCTYPE html>` で始まる HTML）、練習帳 635 件中 1 件に言語が付いた。`vs import` の `guess_language` が役に立っているのも、`$ ` で始まる行を先に見る前段のほうである。

### 1.3 highlight.js は言語を見分けられるが、実行結果も言語と見る

highlight.js（10.7.2）の `highlightAuto` は、推定言語と関連度（relevance）を返し、候補の言語を限定して呼べる。

- **きちんとしたコード**: 候補を 15 言語に絞ると 16 本中 15 本が当たった（C を python と判定）。
- **正解つき**: 15 言語で固定すると練習帳 68%・本書 35%。候補を「同じ章で著者が明示している言語」に絞ると練習帳 97%・本書 68%。外れの多くは本の中の断片の難しさによる（`if (条件) {` のような疑似コードの C を javascript と判定、`vs build` のようなコマンドの羅列を ruby と判定）。
- **言語名なしフェンス**: 関連度が 10 以上の判定だけを見ても、練習帳では 17 件すべてが誤りだった（実行結果を yaml・sql・css・shell・markdown と判定）。候補を 7 言語に絞って閾値を 30 に上げても、盤面 `.......##` を ruby（関連度 32）と判定した。

関連度は「その言語の書き方に何回当たったか」の数であって、「コードであるか」は測らない。正しく当てたコードの関連度（7〜24）と、実行結果を取り違えた関連度（10〜54）が重なるので、閾値で分けられない。

### 1.4 Guesslang は確信度が当たり外れをよく表す

Guesslang は、GitHub のソースコードで学習した機械学習のモデルで、54 言語を見分ける。VS Code が言語の自動判定に使っており、Node.js からは Microsoft の `@vscode/vscode-languagedetection` で呼べる（MIT・1.8 MB・依存なし。PrismJS の issue #3846 で紹介された guesslang-js は同じモデルのブラウザ向けフォークで、README 自身が Node.js ではこちらを勧めている）。各言語の確信度（0〜1）を返す。566 件の判定は 1.7 秒で終わった。

**日本語をそのまま渡すと判定が崩れる。** 日本語のコメントを含むコードは、`ini` と高い確信度で判定される。

```text
// 配列の宣言と初期値設定
let scores = [85, 95, 85, 75]
console.log("配列表示", scores)
→ ini 0.76（javascript は上位 3 位に入らない）
```

ai_web_starter で JavaScript の断片 219 件を渡すと、165 件が `ini` になった。**日本語の連なりを `x` に置き換えてから渡すと、この偏りは消える。** 以下の数字はすべて置き換えたうえでのものである。

- **きちんとしたコード**: 16 本すべてが当たった。
- **正解つき**（候補は同じ章で著者が明示している言語）: 確信度を問わなければ練習帳 98%・本書 67%。確信度 0.3 以上に限ると、練習帳 82 件すべて・本書 38 件中 37 件が当たった。
- **言語名なしフェンス**（候補を絞らず、除外の段も通さない）: 確信度 0.3 以上で、本書 3 件・練習帳 2 件に言語が付き、5 件とも誤りだった（ディレクトリの木を yaml 0.52、BASIC の字句解析の経過を sql 0.70、`【】` つきの表を yaml 0.56 など）。いずれも §3.5 の除外の段で除ける。

### 1.5 二段構えにすると、実行結果に言語が付かない

一段目で言語でなさそうなものを自前の規則で除き（§3.5）、二段目で残りを推定器にかけた。候補は同じ章で著者が明示している言語に絞り、章に 1 つも無ければ本全体で明示している言語に戻した。

| 方式 | 本書（24 件） | 練習帳（635 件） | ai_web_starter（566 件） |
| :--- | :--- | :--- | ---: |
| 二段構え＋Guesslang（確信度 0.3 以上） | 0 件 | 0 件 | 108 件 |
| 二段構え＋Guesslang（確信度 0.1 以上） | 0 件 | 11 件（うち誤り 8） | 169 件 |
| 二段構え＋highlight.js（関連度 10 以上） | 1 件（誤り） | 2 件（誤り） | 209 件 |
| 自前の規則だけ（試作・§1.6） | 0 件 | 2 件（誤り） | 337 件 |

- **確信度 0.3 以上では、本書と練習帳の実行結果・木・盤面に 1 件も言語が付かなかった。** ai_web_starter の 108 件は、HTML 47・CSS 40・JavaScript 17・Ruby 3・JSON 1。0.5 以上の判定を目視した範囲では、JavaScript を typescript と判定した 1 件のほかは当たっていた。
- **確信度 0.1〜0.3 は誤りが多い。** 練習帳では `ruby scripts/check.rb` のようなシェルのコマンドを ruby、`：` で揃えた表を yaml と判定した。ai_web_starter で候補を本全体へ戻さないと、JavaScript を rust・go と判定した。
- **拾える件数は少なめである。** ai_web_starter で言語名を書き忘れたコードは約 330 件あるが、確信度 0.3 以上で拾えるのは 108 件。短い JavaScript（`let price` の数行など）は確信度が上がらない。

### 1.6 自前の規則だけの試作

`MathSpanDetector` と同じく「除外のしるしを 1 つでも含めば推定しない。そのうえで言語のしるしが 1 言語だけに当たったときに付ける」規則を 8 言語ぶん試作した。ai_web_starter で 337 件に付き（無作為の 21 件中誤り 1）、練習帳では 2 件に付けて 2 件とも誤りだった。きちんとしたコードでは、Go を css と判定し、Java・Rust・SQL・YAML・Markdown は見分けられなかった。**言語を見分ける役には向かないが、言語でなさそうなものを除く役（一段目）には使える。**

## 2. 著者向け仕様

### 2.1 `vs lint` が、言語名のないコードを知らせる

言語名のないフェンスの中身がコードらしいとき、`vs lint` が 💡 で知らせる。

```text
💡 42-javascript.md:219 - コードブロックに言語名がありません。javascript と推定しました
        ```javascript と書くと色分けされます（vs lint --fix で書き込めます）
        色を付けない文字なら ```text と書くと、この指摘は出なくなります
```

### 2.2 `vs lint --fix` で言語名を書き込む

`--fix` を付けると、推定した言語名をフェンスの開始行へ書き込む（```` ``` ```` → ```` ```javascript ````）。書き込んだ結果は原稿の差分として残るので、誤りは差分で見つけて直せる。

### 2.3 ビルドは原稿の言語名だけを見る

ビルドは推定しない。言語名のないフェンスは、今までどおり色分けせずに行番号だけを付ける。

### 2.4 色を付けたくないフェンスは ```` ```text ```` と書く

実行結果・ディレクトリの木・画面の文言のように色を付けたくないものは ```` ```text ```` と書く（本書ですでに 48 か所で使っている書き方）。`text` と書いたフェンスは推定の対象にならない。`.output`・`.terminal`・`.diagram` の囲みの中は、言語名が無くても対象にならない。

### 2.5 推定に使う道具は `vs doctor --fix` で入る

推定には Guesslang（npm パッケージ `@vscode/vscode-languagedetection`）を使う。textlint・mermaid-cli と同じく、`vs doctor --fix` が `npm install -g` で入れる。入っていないときは、この検査だけを飛ばして 1 行で案内する（§3.7）。

## 3. 決定事項

### 3.1 いつ推定するか — `vs lint` が知らせ、`--fix` で書き込む（決定 2026-09-29）

| 案 | 内容 | 判断 |
| :--- | :--- | :--- |
| A | ビルドのたびに推定して色を付ける（原稿は変えない） | 採らない。誤った色に気づくには組版結果を見るしかなく、数行足しただけで色が変わりうる |
| **B** | `vs lint` が知らせ、`--fix` で原稿へ書き込む | **採る** |
| C | 推定しない | 採らない。ai_web_starter の約 330 か所は手で言語名を書くことになる |

理由は §1.1 の「著者によって使い道がまったく違う」にある。本書と練習帳では、言語名なしフェンスは「色を付けない」という意思表示として使われている。案 A はそれを機械の推測で上書きする。`MathSpanDetector` が掲げる「明示は尊重し、推測は保守的に」（`plain-math-notation-spec.md` §3.4）とも、案 B が合う。推測は著者に見せたうえで確定させ、以後は著者の明示として扱う。

### 3.2 推定器 — 自前の規則で除き、Guesslang で見分ける（決定 2026-09-29）

1. **一段目（自前の規則）**: 言語でなさそうなもの（木・ログ・盤面・地の文）を除く（§3.5）。
2. **二段目（Guesslang）**: 日本語を置き換えてから言語を推定する（§3.3）。候補は同じ章で著者が明示している言語に絞る（§3.4）。

Rouge は中身から当てられず（§1.2）、highlight.js は関連度で実行結果と本物のコードを分けられない（§1.3）。Guesslang は確信度が当たり外れをよく表し（§1.4）、二段構えにすると本書と練習帳の実行結果に 1 件も言語を付けなかった（§1.5）。二段構えは、一段目が「コードかどうか」、二段目が「どの言語か」を受け持つ分担である。

### 3.3 日本語は `x` に置き換えてから渡す

日本語（ASCII でない文字の連なり）を 1 文字の `x` に置き換えて渡す（§1.4）。コメントや文字列の中の日本語を消すのではなく置き換えるのは、`"配列表示"` が `""` になると文字列の形が変わるためである。置き換えるのは推定器へ渡す文字列だけで、原稿は変えない。

### 3.4 候補は、同じ章で著者が明示している言語に絞る

著者が同じ章で ```` ```ruby ```` と明示していれば、その章の言語名なしのコードも Ruby である見込みが高い。候補の決め方は次の順とする。

1. 同じ章のフェンスで著者が明示している言語（`text` は除く）
2. 1 が無ければ、本全体で明示している言語
3. 2 も無ければ、既定の候補（`html` `css` `javascript` `typescript` `ruby` `python` `c` `cpp` `java` `go` `rust` `json` `yaml` `sql` `bash` `markdown`）

候補に入る言語は、Guesslang が見分けられて Prism が色分けできるもの（§4.3 の対応表）に限る。§1.5 のとおり、2 へ戻さないと ai_web_starter で JavaScript を rust・go と判定した。

### 3.5 一段目で除くもの

次のどれかに当てはまるフェンスは推定しない。

- `.output`・`.terminal`・`.diagram` の囲みの中にある
- 数式と判定される（`MathSpanDetector.display_math` が式を返す）
- 中に入れ子のフェンス（```` ``` ````・`~~~`・`:::`）がある（記法の説明）
- 除外のしるしがある: 木の罫線（`└` `├` `│`）・矢印（`←` `→` `⇒` `↑`）・`【】`・ログの絵文字（🔴 🟡 💡 ✅）・行頭の `[pdf:read]` のようなログの接頭辞・`error[E0382]` のようなコンパイラの出力
- 地の文が多い（行頭が日本語の行が 3 分の 1 を超える）

### 3.6 `$ ` で始まるフェンスは `shell-session` にする

すべての行、または最初の行が `$ ` か `% ` で始まるフェンスは、Guesslang にかけずに `shell-session` とする。`$ vs pdf:read three-elements` の下に出力が続くフェンス（本書 `94-pdf-read.md`）に `bash` を付けると、出力の行までコマンドとして色が付く。Prism の `shell-session` は `$ ` の行だけをコマンドとして色分けし、出力の行はそのまま残す（2026-09-29、VFM で確かめた）。

### 3.7 Guesslang が入っていないとき

この検査だけを飛ばし、`vs lint` の最後に 1 行で案内する（「言語名のないコードブロックの言語推定は、`vs doctor --fix` で Guesslang を入れると使えます」）。一段目だけで推定することはしない（§1.6 のとおり、自前の規則は言語を見分ける役に向かない）。ほかの検査は止めない。

### 3.8 実装時に実測で決めること

- **確信度の閾値**: 0.3 から始める（§1.5 で本書・練習帳の誤りが 0 件）。候補の中だけで確信度を割り直す（候補の確信度の合計で割る）と、短い断片も拾える見込みがある。§4.5 の基準を満たす範囲で下げる。
- **一段目の除外のしるしの過不足**: §4.5 の 3 冊で目視して足す。

## 4. 実装

### 4.1 一段目 — `CodeLanguageDetector`

`lib/vivlio_starter/cli/lint/code_language_detector.rb`（新規）。言語名のないフェンスを走査し（`Masking.replace_top_level_fences`）、フェンスごとに次のどれかを返す。

- 除外（§3.5）
- `shell-session`（§3.6）
- 推定待ち（二段目へ渡す本文と候補の言語）

候補の言語（§3.4）は、同じ走査で集めた言語名つきフェンスから決める。本全体の言語は、`vs lint` が対象にする全章から集める。

### 4.2 二段目 — Guesslang を呼ぶ Node のスクリプト

`lib/vivlio_starter/cli/lint/guess_code_language.mjs`（新規・gem に同梱）。標準入力で JSON（フェンスごとの本文と候補）を受け取り、標準出力に JSON（言語と確信度）を返す。`vs lint` 1 回につき 1 回だけ起動し、全章の推定待ちをまとめて渡す（モデルの読み込みは 1 回で済む）。日本語の置き換え（§3.3）はこちらで行う。Guesslang は `npm root -g` の下から読み込む（textlint と同じくグローバルに入る）。

### 4.3 言語名の対応表

Guesslang の言語 ID を、Prism の言語名へ読み替える。

| Guesslang | Prism | Guesslang | Prism |
| :--- | :--- | :--- | :--- |
| `html` | `html` | `java` | `java` |
| `css` | `css` | `go` | `go` |
| `js` | `javascript` | `rs` | `rust` |
| `ts` | `typescript` | `json` | `json` |
| `rb` | `ruby` | `yaml` | `yaml` |
| `py` | `python` | `sql` | `sql` |
| `c` | `c` | `sh` | `bash` |
| `cpp` | `cpp` | `md` | `markdown` |

原稿の言語名から候補を作るときは、別名をそろえる（`js` → `javascript`、`sh`・`zsh`・`shell` → `bash`、`yml` → `yaml`、`md` → `markdown`）。表に無い言語（Guesslang の 54 言語のうち上の 16 以外、または原稿の `mermaid`・`math`・`text` など）は候補に入れない。

### 4.4 lint の検査と `--fix`

`vs lint` に検査を 1 つ足す（textlint・スペルチェックと並ぶ段。置き場所は実装時に `lint.rb` を読んで決める）。指摘は 💡 で、書き直し後の形と `text` の逃げ道を添える（§2.1）。`--fix` はフェンスの開始行だけを書き換え、フェンス記号の種類と長さ・字下げ・閉じ行は変えない。`vs lint --spellcheck-only`・`--textlint-only` のときは走らせない。

### 4.5 受け入れの基準

§1.1 の 3 冊で走らせ、推定の結果をすべて目視する。**本書と練習帳では誤りを 0 件にする。** ai_web_starter では付けた件数と誤りの件数を実装記録に残す。閾値や除外のしるしを変えたら、前の版との差をすべて突き合わせる（`lint-change-full-diff` の型）。

## 5. テスト

- `test/vivlio_starter/cli/lint/code_language_detector_test.rb`（新規）: 一段目の除外（ディレクトリの木・ログ・盤面・Rust のエラー・日本語の質問文・入れ子のフェンス・囲みの中・数式）、`shell-session`、候補の決め方（章 → 本全体 → 既定）、別名のそろえ方。二段目は差し替えられるようにし（DI）、Node なしで走らせる。
- lint の検査: 指摘の文面、`--fix` の書き換え（開始行だけが変わる）、`text` と囲みの中は指摘しないこと、Guesslang が無いときの案内。二段目は差し替えたものを使う。

| 案 | 結果 | 判断 |
| :--- | :--- | :--- |

### 8.6 JavaScript のしるしを足し、候補に加える条件を絞る（2026-09-30）

- **`alert(`・`constructor(`・`class 名前 {` を JavaScript のしるしに足した。** 入門書の短い例（`alert("こんにちは")` の 2 行、クラスの宣言）が、しるしに当たらず取りこぼされていた。ai_web_starter の言語名つきフェンスから言語名を外して当てさせる試験で、JavaScript の検出率が 44/58（75%）→ 49/58（84%）に上がった（CSS 34/38・HTML 38/46 は変わらず、誤った言語は 0）。
