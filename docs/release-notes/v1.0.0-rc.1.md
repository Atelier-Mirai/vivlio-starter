# vivlio-starter v1.0.0-rc.1

**Release Candidate 1**（2026-08-09）

ベータ版から約 100 日にわたる改善を積み重ね、いよいよ 1.0 の正式版に向けたリリース候補版です。
EPUB / Kindle 出力の本格対応、執筆記法の拡充、索引・分量分析の全面刷新、印刷入稿グレードのフォント品質が今回のハイライトです。

> RC 版は正式版の前段です。利用感の最終確認を目的としており、`config/book.yml` の `project.version` など正式版固有の確定作業は次段で行います。

---

## ✨ ハイライト

### 📚 EPUB / Kindle ターゲット分離
電子書籍出力を配信先ごとに最適化された 2 ターゲットへ分離しました。

- **`epub`（クリーン EPUB）** — Kobo / Apple Books 向け。WebP・高画質 SVG・テーマ色をそのまま維持。
- **`kindle`（KPF）** — Amazon KDP 向け。Kindle（KFX）の CSS 制約に合わせて自動劣化させた中間 EPUB を、`kindlepreviewer` で `.kpf` へ自動変換。
- WebP → JPEG/PNG 変換、数式・扉絵/節絵の SVG / JPEG 出し分け、コードの行ブロック化、`::before` ラベルの実体化などを Kindle フレーバ限定で適用。
- **クリーン EPUB・Kindle 中間 EPUB の双方で epubcheck ERROR 0 / WARNING 0 を達成。**
- フォントを埋め込まない既定へ変更し、**EPUB サイズを 322MB → 25MB へ削減**。総称ファミリ（`serif` / `sans-serif` / `monospace`）を指定するため、明朝・ゴシック・等幅という書体の系統はどの端末でも保たれます。
- Kindle は `var()` も `color-mix()` も解釈しないため、テーマ色を**具体色として焼き込み**ます。前書き・後書きの専用色（`preface_color`）まで含めて、紙面と同じ配色が出ます。
- 横に広い表は、Kindle では**組んだ PDF ページを画像として差し替え**ます。リフロー型では再現できないレイアウトを、見た目そのままで届けるための割り切りです。

### ✍️ 執筆記法の拡充
本を書くうえで「あると助かる」記法を、この期間にまとめて実装しました。

- **図解注釈 `:::{.showcase}`** — スクリーンショットの「ここを見てほしい」を**原稿に文字で書く**記法。枠・矢印・丸数字を座標で指定すると、ビルド時に 1 枚の画像へ焼き込まれます。画像編集ソフトを開かずに済み、注釈は原稿と一緒にバージョン管理できます。座標は千分率なので、画像を差し替えてもずれません。
- **ダイアグラム ` ```mermaid `** — フローチャートやシーケンス図をテキストで描けます。PDF はベクタ、EPUB・Kindle はラスターで、すべてのターゲットに同じ図が出ます。
- **会話文 `:::{.talk}`** — 「キー: 発話」を並べるだけの対話記法。話者の色・アバター・左右の振り分けは `config/talk.yml` で定義します。アバター画像が無くても、頭文字を白抜きした簡易アバターを自動生成できます。
- **拡張テーブル** — セルの横結合（`||`）と複数行ヘッダーが、素のパイプテーブルのまま書けます。横に広い表の 90 度回転（`.rotate-table`）は、倍率と位置が**自動で決まる**ようになりました。
- **箇条書きの拡張** — 英字・ローマ数字のマーカー（`a.` `(A)` `iv)`）と、`1.1` 形式の複合番号に対応。
- **`@` ディレクティブ** — `@vspace` / `@hspace` で余白を微調整、`@pagebreak:recto` で右起こし、`@qr:URL` で QR コード、`@version` / `@today` でビルド時の値を差し込み。
- **コードの取り込み** — 範囲指定（`include:foo.rb:10-20`）で取り込むと、**元ファイルでの実際の行番号**が表示されます。紙面を見ながら元ファイルの該当箇所を探せます。

### 🔍 索引・用語集の刷新
「索引をどう作ればよいか分からない」を解きほぐす方向へ、機能全体を作り直しました。

- **`vs index:plan`** — 索引づくりの下見コマンド。本文の分量から**索引語数の目安**を算出し、いまの語数が多いか少ないかを示します。辞書もレビューファイルも書き換えません。
- **採否をスコアの閾値でなく「目安語数の帯」で決める** — 登録済みの語と候補を同じ土俵に並べ、枠に入るかで判断します。「スコア 300 以上を採用」のような閾値は、本の分量で意味が変わってしまうためです。
- **主要参照** — その語を腰を据えて説明している章（や節）を指定すると、索引でそのページが**太字＋先頭**に並びます。機械が候補を下書きするので、著者は確認するだけで済みます。
- **一般語の提示** — 本の広い範囲に散らばっていて索引として役に立たない語を、外す候補として挙げます。
- **索引ライブラリの持ち運び** — 用語集の定義・棄却の判断・読みの補正を `vs index:export` / `vs index:import` で次の本へ引き継げます。同じ分野の本を続けて書くときに効きます。
- 索引スキャンは **8.3 倍**高速化しました。

### 📊 分量と読みやすさの分析（vs metrics）
- **分量を「本文」で数えます** — コードブロックと記法を除いた地の文の量。コード込みで数えると、コードが多い章ほど「足りている」と判定されてしまうためです。
- **刊行書の実測に基づく 5 プリセット** — 章 128 件・節 408 件を実測し、`compact` / `handy` / `standard` / `commercial` / `heavy` の帯を引きました。本の総字数から選べます。
- **`use: relative`** — 機能ごとに章を立てるリファレンス寄りの本では、絶対の目安だとほとんどの章が「加筆検討」になります。その本自身の章の中央値と比べる方式に切り替えられます。
- **記号の使い分け** — 分量は 💡（提案）、文章の質は 🤔（気になる点）、理想の帯に収まれば ✅。分量の指摘を 💡 にしているのは、それが欠陥ではなく提案だからです。
- **推敲の手掛かり**（`--all`）— 章間のばらつき、見直したい長い文、文末表現のリズム、よく使う言葉、漢字レベル（ルビ候補）。読解難度は建石式、語彙多様度は MATTR という定評ある指標を使っています。

### 🔧 環境の更新（vs upgrade）
新設した `vs upgrade` は、プロジェクトの直下で 1 回実行するだけで次の 3 つを順に最新化します。

1. **vivlio-starter 本体** — 新版があれば更新し、**新しい版で続きを自動実行**します（古い雛形で取り込む二度手間がありません）
2. **プロジェクトの雛形** — 改良されたスタイルシートやテンプレートを取り込みます。著者が手を入れたファイルは diff を出して 1 件ずつ確認し、原稿・画像・辞書は**構造的に対象外**です
3. **外部ツール** — Homebrew・npm・gem に散らばるツールを、更新計画の確認後にまとめて更新します

`vs doctor` も、ツールの存在を見るだけでなく**実際に起動して機能するか**を確かめる方式へ全面移行しました。

### ⚡ ビルドの高速化
- **入稿用 PDF を閲覧用から導出** — 本文を二度組まないため大幅に短縮され、閲覧用で確認した本文がそのまま入稿物になります（紙端まで届く要素がある本は `full_bleed: true` で従来どおり個別レンダリング）。
- **PDF 枝と EPUB 枝の並列実行** — 両方を出力するとき、互いに独立な処理を同時に走らせます。
- **前付・奥付を本文と 1 回のレンダで組む** — 約 71 秒短縮。
- **生成資産の永続キャッシュ** — mermaid の図・数式 SVG・扉絵の合成画像は、クリーンビルドをまたいで再利用されます。

### 🔠 印刷入稿グレードのフォント品質（Type 3 フォントの根絶）
印刷所は **Type 3 フォント**（字形がそのまま PDF に焼き込まれる埋め込み方式）を嫌い、入稿時の事故や文字のにじみの原因になります。本 RC では PDF 内のフォントを**すべて通常の埋め込み・Type 3 ゼロ**に揃えました。

同梱書体だけでなく、**著者が Google Fonts の書体を選んだ場合も 0 件**です。日本語 Google Fonts 55 書体を調査したところ **31 書体が太字を持たない**と分かったため、合成太字（faux-bold）を止め、本文書体に太字が無いときだけ強調を見出し書体へ振る仕組みを入れました。生成 SVG（図解注釈・mermaid）は独立文書で本文の CSS が届かないため、**その SVG に出る字だけ**を抜き出したフォントを埋め込んでいます（8 文字で 3.3KB）。

### ⚙️ 設定ファイルの整理
- `config/book.yml` を **671 行 → 437 行**へスリム化。方式が確定して動かす必要のなくなったキー、実装が無いまま残っていたキーなど 28 個を撤去しました。撤去したキーは書いてあっても静かに無視されるのではなく、**移行先を案内**します。
- 既定値の宣言を `ConfigKeys` の 1 表へ集約。「book.yml から消した瞬間だけ誰も宣言していない値で動く」状態を無くし、表と雛形の食い違いはテストが落とします。
- 章の改丁を `page.chapter_pagebreak`（`recto` / `any` / `verso`）で選べるようにしました。既定の右起こしは製本らしい体裁になりますが、章の変わり目に白紙が入ります（本書では全体の約 5%）。ページ単価で刷る同人誌では `any` が効きます。
- 見出しの寸法を mm ではなく**文字数**で指定する方式へ（`heading_chars` / `lead_chars`）。判型を変えても指定の意味が変わりません。

### 🖥️ 使い勝手
- **設定ファイル不要の直接ビルド** — `vs build myawesome.md` で、プロジェクトの外にある 1 枚の Markdown をそのまま組めます。書き捨てのメモや企画書向け。
- **オプションの位置が自由** — `vs build --no-resize 21` でも `vs build 21 --no-resize` でも動きます。
- **打ち間違いに「もしかして」を添える** — 章指定・設定キーの綴りが違うとき、近い候補を示します。
- 全公開コマンドが実行結果を 1 行で報告し、ビルド中は進捗をスピナーで示すようになりました。

## 📥 インストール / 動作要件
- Ruby **3.4 以上**（3.4.10 と 4.0.6 で動作確認）。
- macOS + Homebrew 環境を主対象としています。外部ツールの自動導入（`vs doctor --fix`）はこの環境でのみ動作します。

```bash
gem install vivlio-starter --pre   # rubygems.org 公開時
# もしくは GitHub から直接インストール
```

導入後は `vs new mybook` を実行すれば、必要な外部ツールの診断とセットアップまで自動で進みます。
