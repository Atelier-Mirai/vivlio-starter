# vivlio-starter v1.0.0

**正式版**（2026-10-20）

Vivlio Starter の最初の正式版です。Vivlio Starter は、Markdown で書いた原稿から、印刷所に入稿できる PDF と、EPUB・Kindle 向けの電子書籍を作るツールです。組版には CSS 組版エンジンの Vivliostyle を使い、執筆から校正・索引づくり・入稿用の出力までを `vs` コマンドで進められます。

このノートは二部に分かれています。前半は、はじめて使う方に向けた**できることの概要**です。後半は、RC3 をお使いの方に向けた **RC3 からの変更**です。

> 正式版になったので、インストールと更新に `--pre` は要りません。

---

## 📖 Vivlio Starter でできること

### 原稿から本を作る

`vs new mybook` でプロジェクトを作り、`vs create 10-intro` で章を足し、`vs build` で本に組みます。章ごとに組んで確かめることもでき、Markdown 1 ファイルだけを `vs build memo.md` で PDF にすることもできます。

出力は `config/book.yml` の `output.targets` で選び、併記もできます。

| 頒布先 | 指定する値 | 作られるもの |
| :--- | :--- | :--- |
| 印刷所への入稿（技術書典・コミケなど） | `print_pdf` | トンボ・塗り足し付きの PDF（CMYK の表紙は PDF/X-1a） |
| ダウンロード販売・PDF での配布 | `pdf` | 閲覧用の PDF（表紙を結合済み） |
| 楽天 Kobo・Apple Books・BOOTH | `epub` | EPUB |
| Amazon Kindle（KDP） | `kindle` | KPF（Kindle Previewer で変換） |

判型（B5・A5・A4 など）・本文の書体・テーマの色・扉絵は `book.yml` で選びます。表紙は同梱のテンプレート、自作の SVG、PNG のいずれからでも作れます。

### 本に要る記法で書く

ふつうの Markdown に、技術書で使う記法を足しています。

- **数式**は `x²`・`√(a+b)`・`Σ` のように素のまま書けば、LaTeX に直して組みます。LaTeX で書くこともできます
- **相互参照**は `@chapref:` や `@pageref:` で書き、章番号・図番号・ページ番号を組むときに埋めます
- **図解注釈**（`:::{.showcase}`）で、スクリーンショットに付ける枠・矢印・丸数字を原稿に文字で書けます
- **ダイアグラム**（```` ```mermaid ````）、**会話文**（`:::{.talk}`）、セルを結合できる表、ソースファイルからの**コードの取り込み**（元のファイルの行番号で表示）が使えます
- 改ページ・余白・QR コード・ビルドした日付などは、`@pagebreak`・`@vspace`・`@qr:URL`・`@today` のような 1 行の指示で入れます

巻末の付録に、記法・コマンド・数式のチートシートがあります。

### 原稿を整える

- **`vs lint`** は、表記の揺れ・冗長な表現・文体の混在・交ぜ書き（`だ円` → `楕円`）・英単語の綴りを指摘し、`--fix` で直せる指摘は直します
- **`vs metrics`** は、刊行された技術書の実測から決めた目安で、章ごとの分量と読みやすさを測ります
- **`vs index:plan` → `vs index:auto` → `vs index:apply`** で、索引と用語集を作ります。候補を機械が挙げ、著者はレビューファイルで採否を決めます。辞書は `vs index:export` で次の本へ持ち越せます
- **`vs preflight`** は、PDF を組まずに、原稿が参照する画像やコードの置き忘れを短時間で見つけます

### ほかの形式から取り込む

- **`vs import`** は、Re:VIEW Starter のプロジェクトを Vivlio Starter のプロジェクトに変換します
- **`vs pdf:read`** は、PDF を読み、見出し・表・コードを含む Markdown の章に戻します。スキャンした PDF は、`vivlio-starter-pdf` を入れると OCR で読めます

### 環境を整える

- **`vs doctor`** は、外部ツール（Vivliostyle CLI・qpdf・ImageMagick など）が実際に動くかを確かめます。macOS では `--fix` で足りないものを入れます
- **`vs upgrade`** は、本体の gem・プロジェクトの雛形・外部ツールを、まとめて新しい版にします。著者が手を入れたファイルは差分を見せて確かめ、原稿・画像・辞書には触れません

### 出力の品質

- PDF に Type 3 フォントを入れません。印刷所の検査で指摘されやすい埋め込み方で、Google Fonts の書体を選んだ本でも 0 件にしています
- EPUB は epubcheck の ERROR が 0 件になるように出します（リリースゲートで毎回検査しています）
- 画像は、出力ごとに適した形式と解像度に変えてから入れます。`images/` に置いた元の画像は書き換えません
- Kindle が読まない CSS（`var()`・`::before` のラベル）は、Kindle 向けの出力でだけ、実際の色や文字に置き換えます

## 🆕 RC3 からの変更

RC3（2026-08-21）から約 2 か月、約 330 コミットの改善です。柱は、**索引と用語集のレビューの作り直し**、**`vs lint` の精度の向上**、**`vs pdf:read` の読み取りの強化**、**Kindle Previewer 4 への対応**の四つです。ほかに、記法と画像まわりの細かな改修を重ねました。

### 📇 索引と用語集のレビューを作り直しました

`vs index:auto` が書き出すレビューファイルを、「登録済みの語」「推奨する語」「残りの語」「棄却した語」「原稿に出てこない語」の 5 節に整理しました。各行の印は**いまの辞書の登録**を示すので、そのまま `vs index:apply` しても辞書は変わりません。変えたい語の印だけを書き換えます。

**候補の質を上げました。** 節の見出しに出る語をいちばん重く見て、2 字の語（扉絵・表紙・脚注・数式など）も見出しに出るものは候補にします。表の列に並ぶ値・決まり文句の中の語・「前章の」のような断片・数と単位は外し、出現数は語の境目を見て数えます（以前は「ファイ」が「ファイル」の出現まで自分の数に入れていました）。本書で測ると、手で選んだ索引語が目安の語数までに入る割合は 48.9% から 55.2% に上がりました。

**レビューの手間を減らしました。**

- 文脈を、前後 40 字の切り抜きから**語を含む 1 文**にしました。記法を外し、長い文は読点で詰めます
- まだ登録していない候補にも主要参照の推測を `[m?95]` の形で書きます。採るときは `[im95]` と `i` を書き足すだけで、主要参照も一緒に登録されます
- 「主要参照を付けない」と決めた語は、次の `vs index:auto` で推測を付け直しません
- 誤って登録した語は、新しい印 `[DELETE]` で辞書から消せます
- 辞書の見出し語の綴りは、`- 綴り: ラベル ID` と書いて直せます。原稿に古い綴りが残っていれば、原稿も直すかを尋ねます

**章を索引の対象から外せるようにしました**（`index_glossary.exclude_chapters`）。記法の見本を集めた章のように、本文と同じ語を使うが読者を案内したくない章に使います。

**索引ライブラリは「説明文の蓄え」になりました。** 取り込んだ用語集の説明文は辞書で待機し、原稿にその語を書いたときに説明文を添えた候補として並びます。これまでは取り込んだ語がすべて用語集に載り、新しい本の原稿に出てこない語まで並んでいました。

あわせて、`vs lint` に辞書の語と空白だけ違う書き方を知らせるルール `index-term-spacing` を足しました。「Type 3 フォント」に対する「Type3 フォント」のような箇所は索引に載らないため、`--fix` で辞書の綴りへ直せます。

### ✍️ `vs lint` の指摘が正確になりました

**誤検出を出どころから直しました。** 指摘が出るたびに除外リストへ書き足す運用をやめ、辞書の項目そのものを公用文の定めと照らして直しています。

- `分かる => わかる`・`並びに => ならびに`・`付ける => つける` のように公用文と逆を向いていた項目を、外すか向きを直しました
- 二つの辞書が互いに逆を向き、どちらに直しても指摘される組（`インターフェイス`・`チェーン`）を総当たりで洗って解消しました。配る辞書の矛盾はリリースゲート（`DC-01`）で毎回検査します
- 文末の句点の検査を独自ルール `missing-period` に置き換えました。上流のルールは体言止めを知らず、定義やキャプションにまで句点を求めていました（本書で 39 件 → 26 件、新しく出た指摘は 0 件）
- 一文の長さは、インラインコード・丸かっこの中・欧文を除いた**和文の字数**で測ります
- 誤検出の多い `no-doubled-joshi`（本書で 8 割が誤検出）と `ja-no-successive-word`（同じく 20/21 件）は既定で切りました

**`--fix` と表示を一致させました。** 「表示では指摘が出ないのに、`--fix` だけが書き換える」不具合を洗い出して直しました。`lint.disabled_rules` で切ったルール、抑止コメントで守った行、`:::{.output}` の中、ふりがなの親文字、相互参照のラベル（`@ruby-sample` が `@Ruby-sample` に）、数式（抑止した行で数式が原稿から消えていました）のいずれも、`--fix` が触らなくなりました。実物の textlint で不変条件を確かめる統合テストも足しています。

**新しいルールを足しました。**

| ルール | 知らせること |
|---|---|
| `affix-spacing`・`hiragana-spacing` | 英字の語と和文の間の空白（`EPUB用 => EPUB 用`・`IDの => ID の`）。`--fix` で直せます |
| `kansuji-counter-suffix` | 数と「つ」の表記（数は `一つ`、記号の個数は `空白 2 つ`） |
| `long-parenthetical` | 丸かっこの中だけが長く伸びた文 |
| `multiple-chapter-headings` | 一つの章ファイルに 2 つ目の `#` |
| `indented-code-block`・`setext-heading` | 4 字下げのコードや、改ページのつもりの `---` が見出しになる取り違え |
| コードブロックの言語名 | 言語名を書き忘れたコードブロック。Guesslang で推定し、`--fix` で書き込みます |
| `unclosed-suppression` | 閉じ忘れた抑止コメント（原稿の終わりまで指摘がすべて止まるため） |

**指摘を読みやすくしました。** 原稿 1 ファイルにつき一つの表にまとめ、英文のまま返していた上流ルールの指摘を日本語にしました。違いが空白や字幅だけの指摘には「（空白を削除）」「（半角 → 全角）」と添えます。出現行はクリックでエディタに開けます（`lint.line_links`）。

**抑止コメントは `no-lint` 系に一本化しました。**

```
<!-- no-lint -->          次の 1 行だけ
<!-- no-lint-start -->    ここから
<!-- no-lint-end -->      ここまで
```

旧形式（`vs-lint-disable-next-line` など）はもう指摘を止めません。原稿に残っていると、行番号と置き換え先を添えて 🟡 で知らせます。

### 📄 `vs pdf:read` が見出し・表・コードまで戻すようになりました

これまで `vs pdf:read` が戻すのは文字の並びだけで、見出し・コードの囲み・表はどのモードでも 0 件でした。今回、PDF の種類ごとに紙面の構造を読み取る経路を作りました。

| PDF の種類 | 読み方 |
|---|---|
| タグ付き PDF（`vs build` の出力など） | 構造ツリーから戻します |
| タグの無い PDF | 文字の大きさ・位置・書体から推定します |
| スキャンした PDF | OCR の語の位置から推定します（Enhanced Mode） |

`vs build` で組んだ 97 章の PDF では、見出し 33/33・コードの囲み 5/5・表の行 43/43・脚注 4/4・リスト 20/20 が戻り、文字の一致（F 値）は 95.5% から 97.0% になりました。この二つの経路は本体（MIT）だけで動くので、Standard Mode でも同じ結果になります。コードはキャプションのファイル名から ```` ```ruby:photoelectric.rb ```` の形にし、行番号を外します。

**市販の日本語 PDF の文字化けを直しました。** ToUnicode の無いヒラギノや新ゴの PDF では、「MOSFET」が「.04'&5」に、「図」が「ਤ」になっていました。PDF の仕様どおり Adobe-Japan1 の対応表で字に戻し、題材 23 本のうち 16 本で字が戻りました。Word が書き出した Shift_JIS の論文、dvips の TeX の書体、pLaTeX のコード（『実践 Rust Web 開発 5』でコードの囲みが 0 → 658 個）も読めます。2 段組み、目次のリーダー、線で描いた図、平方根・否定の線・筆算などの数式も戻します。

**スキャンした PDF を読む精度を上げました**（Enhanced Mode）。

- 写真や絵を画像として切り出し、Markdown の該当位置に置きます（97 章の図 15 枚のうち、以前は 1 枚 → 14 枚）
- 斜体の引用文を読み、スキャンの傾きを直します
- 英字の多いページは英語でも読み直し、取り違えた英字の語（`Ftoat` → `Float`）はスペルチェックの辞書で直します
- 形の似た字（`6` と `も`、`力` と `カ`）を、MeCab で前後の文のつながりを確かめてから直します
- `--log` で「OCR しています（5/24 ページ）」と経過を出します

**指定のしかたを整えました。**

```bash
vs pdf:read gitlab                          # sources/ を省けます
vs pdf:read gitlab.pdf 21-git               # 二つ目の引数で章の名前を決めます
vs pdf:read gitlab.pdf 22-git-branch --pages 31-48,52   # 指定のページだけを章にします
vs pdf:read scan.pdf 97-scan --images-from images/originals   # 切り出した図を元の画像に差し替えます
```

ファイル名に付いた `(1)`・`のコピー` は章の名前から外します。同じ章を読み直すときは止め、`--force` を付けたときだけ置き換えます。

> **Enhanced Mode には `vivlio-starter-pdf` 1.2.0 が要ります。** 1.1.x までのプラグインでは、本体からの呼び出しが `Unknown option 'read'` で失敗し、Enhanced Mode は一度も動いていませんでした（本体のテストが呼び出しを差し替えていたため、見つかりませんでした）。古いプラグインのままだと、更新の方法と Standard Mode で読むコマンドを案内します。

### 📱 Kindle Previewer 4 に対応しました

**Kindle Previewer 4 で KPF が作れなくなっていた問題を直しました。** `.kpf` ではなく `.mobi` が出て、ビルドは「Kindle 変換に失敗しました」で終わっていました。原因は同梱していた SVG で、Previewer 4 は manifest に SVG があるだけで Enhanced Typesetting を無効にします。参照の切れた SVG を外し、参照されている SVG は画像に焼くようにしました。Previewer 4 では、EPUB に空のディレクトリがあると変換そのものが失敗し、CSS の `data:` URI も警告になるため、どちらも取り除きます。全 36 章で `ET=Supported / Error=0` を確かめています。

- Previewer 4 が変換の入口で落ちることがあるため（macOS の競合で、約 12 回に 1 回）、そのときは変換を 1 回やり直します
- `vs doctor` が入っている版を表示し、3 のままなら 4 への更新を促します。Apple Silicon では、変換の本体が Intel 向けのため Rosetta 2 の有無も確かめます
- Kindle Previewer は Amazon KDP の配布ページから入れる案内にしました。Homebrew の配布は Amazon の最新版より遅れるため、`vs doctor --fix` はアプリを入れず、コマンドのラッパーだけを作ります

**KDP へ上げる表紙を、プロジェクト直下に用意します。** KDP の決まりでは、Kindle の本には表紙を入れず、登録画面で別に上げます。`<project>_frontcover_v<版>.jpg`（1,600 × 2,560 px・品質 95・sRGB）を直下に置くので、そのまま登録画面へ上げられます。EPUB と Kindle で同じ 1 枚を使います。

**異体字を Kindle でも正しい字形で出します。** Kindle は異体字セレクタを読まず、`禰󠄀`（ネ偏）は示偏の「禰」に戻っていました。原稿に出た異体の字形だけを本文の書体から取り出した小さな書体（1 字あたり約 2KB）を、Kindle 用の出力にだけ埋め込みます。本文は文字のままなので、文字の大きさの変更と検索に従います。

あわせて、Kindle に焼き込む色を、gem の色の表ではなくプロジェクトの `theme.css` から引くようにしました。`theme.css` の色を変えた本でも、PDF と Kindle の色がそろいます。

#### 色
- `theme.color` の既定色を green にそろえました（以前は書き方によって yellow になっていました）。`preface_color`・`appendix_color` を省略すると `color` と同じ色になります
- パレットの `blue` を一段深い青（`#0186d8`）にしました。以前の値は白地とのコントラスト比が 2.77 しかなく、モノクロで刷ると太字が本文より薄く見えました

#### 不具合修正
- 見出しに異体字セレクタ付きの字や絵文字があると、PDF のビルドが止まっていたのを直しました
- 目次で、見出しのインラインコードが化けていたのを直しました（`` `〘 〙` `` がキーキャップに、`` `@pagebreak` `` が改ページになっていました）
- PDF の後処理で、qpdf が更新の一部を捨てることがあったのを直しました（リンク先の名前の付け替えで 1,504 件のリンクが切れていました）
- 著者の SVG の図や Google Fonts の書体で、Type 3 フォントが入る経路を塞ぎました
- 番号付きの箇条書き（fancy list）で、2 段落目・ルビ・画像の `width` が崩れていたのを直しました
- 前書き・後書きの `@pageref:` にページ番号が出なかったのを直しました
- 言語名 `zsh`・`sh` のコードブロックが色分けされていなかったのを直しました
- 古い `Gemfile.lock` を持つプロジェクトで `vs` が起動できなくなる不具合を直しました。`vs doctor` も `vs upgrade` も使えなくなっていました

### ⚠️ 互換性に関わる変更

既存の原稿や設定に影響するものです。多くは、残っていると 🟡 で知らせます。

| 変更 | 対応 |
|---|---|
| 抑止コメントの旧形式（`vs-lint-disable-next-line`・`vs-lint-disable`・`vs-lint-enable`）を廃止 | `vs lint` が示す置き換え先（`no-lint` 系）に書き換えます |
| 画像の `{.bordered}`・`:::{.bordered}` を撤去 | 画像には既定で枠が付くので、たいていは消すだけで足ります。外すときは `border=off` |
| `--no-verify` と `book.yml` の `verify.images`・`verify.bare_urls` を撤去 | キーを消します。画像の実在と裸 URL は常に確かめます |
| `@omakase` を撤去 | `@auto` を使います |
| レビューファイルの印で、マイナスは直後の 1 文字にだけ掛かる | `[-ig]` は「索引から外し、用語集には残す」の意味になりました。両方外すときは `[r]` |
| 古い形式のレビューファイルで `vs index:apply` を止める | `vs index:auto` で作り直します |
| `lint.sentence_length_max` が和文の字数を指す | 上限を書いている本は、実質的に緩くなります |
| `vs cover` の判型の引数・`vs create:cover`・`vs delete --yes`・`vs index:import --prefer-import`・`vs new --add-missing` を撤去 | 判型は `book.yml` の `page.use` に従います。確認を省くときは `--force`、既存のプロジェクトの更新は `vs upgrade` を使います |
| `vs resize` を内部コマンドに | `vs build` が出力ごとに適した画像を用意するので、手で変換する必要はありません |

## 🔄 RC3 から更新するには

```bash
gem update vivlio-starter
vs upgrade
```

`vs upgrade` が、雛形のスタイルシート・校正の設定と辞書・`Gemfile.lock` を新しい版に合わせます。fancy list の崩れの修正・`border=off`・校正の既定の見直しは、この更新で効きます。そのあと `vs lint` と `vs build` を一度通し、🟡 で知らされた旧形式の記法や設定を直してください。

`vivlio-starter-pdf` を入れている場合は、`gem update vivlio-starter-pdf` で 1.2.0 に上げてください。1.1.x のままでは `vs pdf:read` の Enhanced Mode が動きません。

## ⚠️ 既知の不具合
- 長い見出しの折返し位置が PDF と EPUB / Kindle で一致しません（組むエンジンが異なるため。`heading_chars` を実長以上にすれば差は出ません）。
- `vs lint --fix` は文脈を見ないので、辞書の置換が語の途中に当たって文を壊すことがあります。`--fix` は章ごとにかけ、直後に `git diff` で確かめてください。
- 本文の最初の章が 1 ページだけだと、次の章からノンブルがずれます（章が 2 ページ以上あれば起きません）。
- EPUB の表紙画像が一回り小さく見える場合があります（カバーの想定比 1:1.6 と本文の判型比の差によるもの）。
- Kindle Previewer 4 での変換（Enhanced Typesetting の対応）は確認済みです。Previewer での目視と、Kindle 実機での最終確認は継続中です。

## 📥 インストール / 動作要件
- Ruby **3.4 以上**（3.4.10 と 4.0.7 で動作確認）。
- Node.js **22.12 以上**（Vivliostyle CLI 11 系の要求）。
- macOS + Homebrew 環境を主対象としています。外部ツールの自動導入（`vs doctor --fix`）はこの環境でのみ動作します。Linux と Windows は動作を検証できておらず、公式のサポート対象外です。
- Kindle 向けの出力には Kindle Previewer が要ります（4 を推奨。[Amazon KDP の配布ページ](https://kdp.amazon.co.jp/ja_JP/help/topic/G202131170)から入れます）。Apple Silicon では Rosetta 2 も必要です。

```bash
gem install vivlio-starter
vs new mybook        # プロジェクトを作り、足りない外部ツールを入れます
cd mybook
vs build
```

PDF のしおりや、スキャンした PDF の読み取り（`vs pdf:read` の Enhanced Mode）を使う場合は、`gem install vivlio-starter-pdf` も実行してください。
