# vivlio-starter v1.0.0

**正式版**（2026-11-01）

Vivlio Starter の最初の正式版です。Vivlio Starter は、Markdown で書いた原稿から、印刷所に入稿できる PDF と、EPUB・Kindle 向けの電子書籍を作るツールです。組版には CSS 組版エンジンの Vivliostyle を使い、執筆から校正・索引づくり・入稿用の出力までを `vs` コマンドで進められます。

このノートは二部に分かれています。前半は、はじめて使う方に向けた**できることの概要**です。後半は、RC3 をお使いの方に向けた **RC3 からの変更**です。

> 正式版になったので、インストールと更新に `--pre` は要りません。

---

## 📖 Vivlio Starter でできること

### 環境を用意する

macOS では、次の 1 行で Homebrew・Ruby・Vivlio Starter・`vivlio-starter-pdf`・執筆に使うツール一式が入ります。

```bash
zsh -c "$(curl -fsSL https://raw.githubusercontent.com/Atelier-Mirai/vivlio-starter/master/bin/install.zsh)"
```

### 原稿から本を作る

`vs new mybook` でプロジェクトを作り、`vs create 10-intro` で章を足し、`vs build` で本に組みます。章ごとに組んで確かめることもでき、Markdown 1 ファイルだけを `vs build memo.md` で PDF にすることもできます。

出力は `config/book.yml` の `output.targets` で選び、併記もできます。

| 頒布先 | 指定する値 | 作られるもの |
| :--- | :--- | :--- |
| 印刷所への入稿（技術書典・コミケなど） | `print_pdf` | トンボ・塗り足し付きの PDF（CMYK の表紙は PDF/X-1a） |
| ダウンロード販売・PDF での配布 | `pdf` | 閲覧用の PDF（表紙を結合済み） |
| 楽天 Kobo・Apple Books・BOOTH | `epub` | EPUB |
| Amazon Kindle（KDP） | `kindle` | KPF（Kindle Previewer で変換） |

判型（B5・A5・A4 など）・本文の書体・テーマの色・扉絵は `book.yml` で選びます。表紙は書名の入った `light`・`dark` のテンプレート、自作の SVG、PNG のいずれからでも作れます。

**上下巻などの分冊**も組めます。`config/catalog.yml` に巻を書くと、巻ごとの本、全巻を順に組む本、全巻を一冊にまとめた合本を作れます。

### 本に要る記法で書く

ふつうの Markdown に、技術書で使う記法を足しています。

- **数式**は `x²`・`√(a+b)`・`Σ` のように素のまま書けば、LaTeX に直して組みます。LaTeX で書くこともできます
- **相互参照**は `@chapref:` や `@pageref:` で書き、章番号・図番号・ページ番号を組むときに埋めます
- **図解注釈**（`:::{.showcase}`）で、スクリーンショットに付ける枠・矢印・丸数字を原稿に文字で書けます
- **ダイアグラム**（```` ```mermaid ````）、**会話文**（`:::{.talk}`）、セルを結合できる表、ソースファイルからの**コードの取り込み**（元のファイルの行番号で表示）が使えます
- **データ展開**（QueryStream）で、YAML・JSON のデータから書籍紹介カードや表を作れます
- 改ページ・余白・QR コード・ビルドした日付などは、`@pagebreak`・`@vspace`・`@qr:URL`・`@today` のような 1 行の指示で入れます

巻末の付録に、記法・コマンド・数式のチートシートがあります。

### 原稿を整える

- **`vs lint`** は、表記の揺れ・冗長な表現・文体の混在・交ぜ書き（`だ円` → `楕円`）・英単語の綴りを指摘し、`--fix` で直せる指摘は直します
- **`vs metrics`** は、刊行された技術書の実測から決めた目安で、章ごとの分量と読みやすさを測ります
- **`vs index:plan` → `vs index:auto` → `vs index:apply`** で、索引と用語集を作ります。候補を機械が挙げ、著者はレビューファイルで採否を決めます。辞書は `vs index:export` で次の本へ持ち越せます
- **`vs preflight`** は、PDF を組まずに、原稿が参照する画像やコードの置き忘れ、本の書体にない字、組めない数式を短時間で見つけます

### ほかの形式から取り込む

- **`vs import`** は、Re:VIEW Starter のプロジェクトを Vivlio Starter のプロジェクトに変換します
- **`vs pdf:read`** は、PDF を読み、見出し・表・コードを含む Markdown の章に戻します。スキャンした PDF は、`vivlio-starter-pdf` を入れると OCR で読めます

### 環境を保つ

- **`vs doctor`** は、外部ツール（Vivliostyle CLI・qpdf・ImageMagick など）が実際に動くかを確かめます。macOS では `--fix` で足りないものを入れます
- **`vs upgrade`** は、本体の gem・プロジェクトの雛形・外部ツールを、まとめて新しい版にします。著者が手を入れたファイルは差分を見せて確かめ、原稿・画像・辞書には触れません
- **`vs config:book`** などのコマンドで、設定ファイルの書き方を引けます

### 出力の品質

- PDF に Type 3 フォントを入れません。印刷所の検査で指摘されやすい埋め込み方で、全章のビルドのたびに検査し、混ざっていればページと字を知らせます
- EPUB は epubcheck の ERROR が 0 件になるように出します（リリースゲートで毎回検査しています）
- 画像は、出力ごとに適した形式と解像度に変えてから入れます。`images/` に置いた元の画像は書き換えません
- Kindle が読まない CSS（`var()`・`::before` のラベルなど）は、Kindle 向けの出力でだけ、実際の色や文字に置き換えます

## 🆕 RC3 からの変更

RC3（2026-08-21）から約 2 か月半、約 570 コミットの改善です。柱は、**分冊への対応**、**導入と更新の作り直し**、**索引と用語集のレビューの作り直し**、**`vs lint` の精度の向上**、**`vs pdf:read` の読み取りの強化**、**Kindle の組み上がりの改善**の六つです。

### 📚 分冊を組めるようになりました

上下巻・上中下巻・第 N 分冊の本を組めます。`catalog.yml` に `VOLUMES:` を書き、巻ごとに名前・`id`・目次を書きます。巻の数に制限はなく、`VOLUMES:` の無い本はこれまでどおり一冊として組みます。

```bash
vs build lower   # 下巻を組む（巻の id を指定する）
vs build all     # 全巻を、巻の順に一巻ずつ組む
vs build         # 全巻を一冊にまとめた合本を組む
```

- 章番号は前の巻から続きます（`chapter_start` で変更できます）。図表番号・`@chapref`・目次・PDF のしおりも同じ番号になります
- 書名・発行日・ISBN・表紙などを、巻ごとに上書きできます。出力ファイル名には巻の `id` が入ります（`mybook_lower_v1.0.0.pdf`）
- 別の巻の章や図は、「上巻 第8章「…」」「上巻 図 8-2」のように巻の名前を添えて参照します
- 巻に `whole_toc: true` を書くと、全巻の構成を示す「全巻目次」を載せます
- `catalog.yml` の `VOLUMES:` と同じ高さに `PREFACE:`・`POSTFACE:` を書くと、本全体の前書き・後書きになります
- 索引では、主要参照が別の巻にある語に `12, 29, 221, 上巻 第7章` のように案内を添えます
- `vs cover`・`vs preflight`・`vs lint`・`vs metrics` でも巻を指定できます

### 🚀 導入と更新を作り直しました

**導入スクリプト `bin/install.zsh` を用意しました。** 何も入っていない Mac でも、Ruby からツール一式まで 1 回の実行で入ります。確認は最初にまとめて尋ね、パスワードも 1 回だけ尋ねます。Kindle Previewer を入れるかどうかも、最初の確認で選べます。Ruby 3.4 以上がすでにあれば、それをそのまま使います。

**`vs config` で設定の書き方を引けます。** 読むだけのコマンドで、プロジェクトの外でも使えます。

```bash
vs config:book                      # book.yml の区分の一覧
vs config:book index.target_terms   # キーの説明と今の値
vs config:book 目次                 # 言葉で探す
vs config:catalog                   # catalog.yml の書き方と、この本の章立て
vs config:talk                      # talk.yml の書き方と、この本の話者
```

**雛形の更新が著者に届くようになりました。** `gem update` の後、全章の `vs build`・`vs preflight` の最後に、新しい CSS や `book.yml` の設定があることを知らせます。

**`vs upgrade` が設定まで整えるようになりました。**

- 増えたキーを、コメントごと `book.yml` に足します
- 廃止キーを `book.yml` から消し、`output.cover` のように移ったキーは新しい場所へ移します
- `contents/` に残った、今の版では読まない原稿（`_titlepage.md` など）を消します
- `Gemfile.lock` が指す版を新しい版に合わせます
- 外部ツールに加えて、`vivlio-starter-pdf` と `query-stream` も更新の対象にします
- プロジェクトの外で実行すると、本体と外部ツールだけを更新します

**`vs new` の既定の表紙を `light` にしました。** 書名と著者名の入った表紙がすぐにできます。自作の表紙の雛形（A4・B5・A5 の表と裏）を `covers/templates/` に用意しました。

### 📇 索引と用語集のレビューを作り直しました

`vs index:auto` が書き出すレビューファイルを、「登録済みの語」「推奨する語」「残りの語」「棄却した語」「原稿に出てこない語」の 5 節に整理しました。各行の印は**いまの辞書の登録**を示すので、そのまま `vs index:apply` しても辞書は変わりません。変えたい語の印だけを書き換えます。

**候補の質を上げました。** 節の見出しに出る語をいちばん重く見て、2 字の語（扉絵・表紙・脚注・数式など）も見出しに出るものは候補にします。表の列に並ぶ値・決まり文句の中の語・「前章の」のような断片・数と単位・数式の断片は外し、出現数は語の境目を見て数えます。

**レビューの手間を減らしました。**

- 文脈を、前後 40 字の切り抜きから**語を含む 1 文**にしました。記法を外し、長い文は読点で詰めます
- まだ登録していない候補にも主要参照の推測を `[m?95]` の形で書きます。採るときは `[im95]` と `i` を書き足すだけで、主要参照も一緒に登録されます
- 「主要参照を付けない」と決めた語は、次の `vs index:auto` で推測を付け直しません
- 誤って登録した語は、新しい印 `[DELETE]` で辞書から消せます
- 辞書の見出し語の綴りは、`- 綴り: ラベル ID` と書いて直せます。原稿に古い綴りが残っていれば、原稿も直すかを尋ねます

**副次参照を、語を見出しに掲げた節に絞りました。** 名前が出ているだけの箇所は載せません。本書では、主要参照のある 205 語の副次参照が 1,176 件から 149 件になりました。用語集のページ番号も、索引にも載る語は索引と同じ参照を指します。

**章を索引の対象から外せるようにしました**（`index_glossary.exclude_chapters`）。記法の見本を集めた章のように、本文と同じ語を使うが読者を案内したくない章に使います。

**索引ライブラリは説明文を持ち運ぶものにしました。** 取り込んだ用語集の説明文は辞書で待機し、原稿にその語を書いたときに、説明文を添えた候補として並びます。

あわせて、`vs lint` に辞書の語と空白だけ違う書き方を知らせるルール `index-term-spacing` を足しました。「Type 3 フォント」に対する「Type3 フォント」のような箇所は索引に載らないため、`--fix` で辞書の綴りへ直せます。

### ✍️ `vs lint` の指摘が正確になりました

**辞書の項目そのものを直しました。** 指摘が出るたびに除外リストへ書き足すのをやめ、公用文の定めと照らして項目を直しています。

- `分かる => わかる`・`並びに => ならびに`・`付ける => つける` のように公用文と逆を向いていた項目を、外すか向きを直しました
- 二つの辞書が互いに逆を向き、どちらに直しても指摘される組（`インターフェイス`・`チェーン`）を総当たりで調べて解消しました。配る辞書の矛盾はリリースゲート（`DC-01`）で毎回検査します
- 文末の句点の検査を独自ルール `missing-period` に置き換えました。定義やキャプションのような体言止めに句点を求めなくなりました
- 一文の長さは、インラインコード・丸かっこの中・欧文を除いた**和文の字数**で測ります
- 誤検出の多い `no-doubled-joshi` と `ja-no-successive-word` は既定で切りました

**新しいルールを足しました。**

| ルール | 知らせること |
|---|---|
| `affix-spacing`・`hiragana-spacing` | 英字の語と和文の間の空白（`EPUB用 => EPUB 用`・`IDの => ID の`）。`--fix` で直せます |
| `kansuji-counter-suffix` | 数と「つ」の表記（数は `一つ`、記号の個数は `空白 2 つ`） |
| `long-parenthetical` | 丸かっこの中だけが長く伸びた文 |
| `multiple-chapter-headings` | 一つの章ファイルに 2 つ目の `#` |
| `indented-code-block`・`setext-heading` | 4 字下げのコードや、改ページのつもりの `---` が見出しになる取り違え |
| `accidental-emphasis` | 英数字の直後の `*`・`_` が対になってできる強調（`A*探索` で `*` が紙面から消える） |
| コードブロックの言語名 | 言語名を書き忘れたコードブロック。Guesslang で推定し、`--fix` で書き込みます |
| `unclosed-suppression` | 閉じ忘れた抑止コメント（原稿の終わりまで指摘がすべて止まるため） |

**指摘を読みやすくしました。** 原稿 1 ファイルにつき一つの表にまとめ、英文のまま返していた上流ルールの指摘を日本語にしました。違いが空白や字幅だけの指摘には「（空白を削除）」「（半角 → 全角）」と添えます。出現行はクリックでエディタに開けます（`lint.line_links`）。

**抑止コメントは `no-lint` 系に統一しました。**

```
<!-- no-lint -->          次の 1 行だけ
<!-- no-lint-start -->    ここから
<!-- no-lint-end -->      ここまで
```

旧形式（`vs-lint-disable-next-line` など）はもう指摘を止めません。原稿に残っていると、行番号と置き換え先を添えて 🟡 で知らせます。

### 📄 `vs pdf:read` が見出し・表・コードまで戻すようになりました

PDF の種類ごとに、紙面の構造を読み取る経路を作りました。

| PDF の種類 | 読み方 |
|---|---|
| タグ付き PDF（`vs build` の出力など） | 構造ツリーから戻します |
| タグの無い PDF | 文字の大きさ・位置・書体から推定します |
| スキャンした PDF | OCR の語の位置から推定します（Enhanced Mode） |

文字の層のある PDF の経路は本体（MIT）だけで動くので、Standard Mode でも同じ結果になります。コードはキャプションのファイル名から ```` ```ruby:photoelectric.rb ```` の形にし、行番号を外します。2 段組み、目次のリーダー、線で描いた図、平方根・否定の線・筆算などの数式も戻します。

**スキャンした PDF を読む精度を上げました**（Enhanced Mode）。

- 写真や絵を画像として切り出し、Markdown の該当位置に置きます
- 斜体の引用文を読み、スキャンの傾きを直します
- 英字の多いページは英語でも読み直し、取り違えた英字の語（`Ftoat` → `Float`）はスペルチェックの辞書で直します
- 形の似た字（`6` と `も`、`力` と `カ`）を、MeCab で前後の文のつながりを確かめてから直します
- `--log` で「OCR しています（5/24 ページ）」と経過を出します

**指定のしかたを整えました。**

```bash
vs pdf:read handbook                        # sources/ を省けます
vs pdf:read handbook.pdf 21-guide           # 二つ目の引数で章の名前を決めます
vs pdf:read handbook.pdf 22-advanced --pages 31-48,52   # 指定のページだけを章にします
vs pdf:read scan.pdf 97-scan --images-from images/originals   # 切り出した図を元の画像に差し替えます
```

ファイル名に付いた `(1)`・`のコピー` は章の名前から外します。同じ章を読み直すときは止め、`--force` を付けたときだけ置き換えます。

> **Enhanced Mode には `vivlio-starter-pdf` 1.2.0 が要ります。** 古いプラグインのままだと、更新の方法と Standard Mode で読むコマンドを案内します。

### 📱 Kindle と EPUB の組み上がりを改善しました

**Kindle Previewer 4 に対応しました。** 全章で `ET=Supported / Error=0` を確かめています。

- Previewer 4 が変換の入口で失敗したときは、変換を 1 回やり直します
- `vs doctor` が入っている版を表示し、3 のままなら 4 への更新を促します。Apple Silicon では Rosetta 2 の有無も確かめます
- Kindle Previewer は Amazon KDP の配布ページから入れる案内にしました。`vs doctor --fix` はコマンドのラッパーを作ります

**章扉を、横長の扉絵に章番号と章題だけを入れた形にしました。** リードは画像に入れず、扉絵の下に本文の文字として組みます。読者の文字サイズの設定に従い、長いリードも切れません。

**Kindle 向けの表示を、Kindle Previewer の画面で確かめて直しました。** 回り込み、画像の中央・右寄せ、`(1)` 形式のリスト、見出しの印、枠の中の横並び、用語集の見出しの帯、奥付、表の中の数式、2 列の索引です。EPUB と Kindle の索引の番号は、章の短い名前（序章・第7部 など）で示します。

**KDP へ上げる表紙を、プロジェクト直下に用意します。** KDP の決まりでは、Kindle の本には表紙を入れず、登録画面で別に上げます。`<project>_frontcover_v<版>.jpg`（1,600 × 2,560 px・品質 95・sRGB）を直下に置きます。EPUB と Kindle で同じ 1 枚を使います。

**異体字を Kindle でも正しい字形で出します。** 原稿に出た異体の字形だけを本文の書体から取り出した小さな書体を、Kindle 用の出力にだけ埋め込みます。本文は文字のままなので、文字の大きさの変更と検索に従います。

あわせて、Kindle に焼き込む色を、プロジェクトの `theme.css` から引くようにしました。`theme.css` の色を変えた本でも、PDF と Kindle の色がそろいます。

### 🖨 PDF の品質を上げました

**Type 3 フォントを検査するようにしました。** 全章の `vs build` が、仕上がった PDF に Type 3 が混ざっていないかを調べ、ページ・章や節の題・字・直し方を 🟡 で知らせます。

**本の書体にない字を、組む前に知らせます。** `vs build` と `vs preflight` の前処理が、原稿の行と直し方を添えて知らせます。

**本の書体にない字を補うようにしました。**

- 本文・見出し・コードの字は HackGen → DejaVu Sans Mono → DejaVu Sans の順に補います
- 図の SVG の字も同じ順に補い、絵文字は同じ位置・大きさの図形に差し替えます。白く縁取った字も Type 3 になりません
- 本の書体にない漢字は、その字を持つ書体から字の形を取り出して図形で組みます
- 地の文の数学用英数字（`ℝ`・`𝔽`）は、数式として組みます

**組めない数式を知らせます。** MathJax が組めなかった式と無い命令を、`vs build`・`vs preflight` が原稿の行番号と直し方を添えて知らせます。

- **章をラベルで参照できるようにしました。** `44-build.md` には `@ch-build` のラベルが自動で付き、`@chapref:ch-build` は 第7章「ビルド」（p.123）と出ます。`vs rename` でスラッグを変えると本文の参照も書き換わります
- 出典・参考資料を小さめに組む `:::{.references}`、補足を小さめに組む `.small` を足しました
- `**強調**` だけで一段落をなす行を、小見出しとして組みます
- 書籍紹介カード（`:::{.book-card}`）に、著者・出版社・発行年の段落を足せます
- 会話文のアバターの直径を話者ごとに `avatar_size:` で、簡易アバターの字を `initial:` で 1〜2 文字指定できます
- キーの組み合わせを `<kbd>Ctrl + S</kbd>` とまとめて書けます
- `crop` が普通の画像でも効き、`width` に `40mm`・`4em` を書け、文中の画像の `width` も効きます。枠は `border=on` / `border=off` で指定し、QR コードは `@qr:URL{width=25mm}` で 1 個ずつ大きさを変えられます。`:::{.showcase}` にもキャプションと図番号を付けられます
- 記法の見本帳（`templates/markdown_snippet.md`）を、付録「記法早見表」と同じ並びで作り直しました
- データ展開（QueryStream）で、抽出条件の `OR`、数の桁区切り（`9_000_000`）、和暦の日付（`R06-01-01`）が使えます

#### 見出し・目次・章扉
- **見出しの番号を `page.heading_numbering` で選べます。** `chapter_and_section`（既定）・`chapter`・`none` です。見出しに自分で番号を書く本で、番号が二重になりません
- **目次に載せる見出しの深さを `page.toc_depth` で選べます。** 変わるのは PDF の目次ページだけです
- **章のリード文の大きさを、本文に対する倍率で選べます**（`theme.lead_size`）。章扉に収まらないリードは、`vs build`・`vs preflight` が直し方を添えて知らせます
- 目次の前書き・付録・後書きにもページ番号を付けました
- 節見出しの飾りの帯を低くし、目見出し（h4）の上に半行あけました

#### 原稿の構成
- **本を `catalog.yml` に書いた順に組みます。** 並びを変えるときは `catalog.yml` の行を移します。番号を付け替える必要はありません
- **原稿の種類（前書き・本文の章・付録・後書き）を、`catalog.yml` に書いた区分で決めます。** 分冊の巻ごとの前書き（`20-vol2-intro`）を置けます
- **章の範囲の指定（`vs build 00-11`）は、その番号の間にある章を指します。** どのコマンドも同じ読み方です
- `vs build file.md`（設定ファイルなしのビルド）で、一つのファイルに書いた複数の章を章ごとに組みます。章が一つなら章番号を付けず、節ごとの改ページもしません。既定の色は blue です

#### 速さ
- PDF を組むたびにプロジェクトの素材を複製するのをやめました。本書の全体ビルドが 350.9 秒 → 302.5 秒になりました
- 原稿を直さずに組み直すと、索引の重複を除くための 2 回目の組版を省きます（本書で 146.6 秒 → 90.2 秒）
- PDF にしおりを付ける段が 19.5 秒 → 5.0 秒になりました
- 数式やコードの多い本の前処理を速くしました（数式 3,221 個の本の `vs preflight` が 64 秒 → 18 秒）
- 辞書の語が多い本の索引の走査が 9.7 秒 → 3.9 秒になりました

#### ビルド
- **同梱の書体を Noto Serif JP・Noto Sans JP に替えました。** 異体字セレクタの表を持つので、「禰」と「禰󠄀」のように書き分けた原稿が、そのとおりに組まれます。`book.yml` に `font: Zen Old Mincho` などと書いた本は、これまでどおり Zen で組まれます
- 章番号・スラッグが重なる原稿や、`vs create` の作る形でないファイル名を、ビルドの前に止めて、直すコマンドを示します
- PDF のリンク先の名前からビルドした場所のパスを外し、短い名前へ付け替えます
- PDF のコードの行番号が、読み上げや `vs pdf:read` の結果に混ざらなくなりました
- `vs import` が Re:VIEW の `.re` から直接変換するようになりました。Re:VIEW 2.5 に依存しなくなり、`//list` のコードは `include:` で `codes/` を参照します
- `vs doctor` が Node.js の版も確かめます（Vivliostyle CLI 11 系は 22.12 以上が必要）

#### 表紙・色
- 表紙を作る処理を `vs cover` の一つの入口にまとめ、入稿用の表紙のトンボを本文の入稿用 PDF と同じ描き方にしました
- `theme.color` の既定色を green にそろえました。`preface_color`・`appendix_color` を省略すると `color` と同じ色になります
- パレットの `blue` を一段深い青（`#0186d8`）にしました。白地とのコントラストを上げるためです

### ⚠️ 互換性に関わる変更

既存の原稿や設定に影響するものです。多くは、残っていると 🟡 で知らせます。`book.yml` の廃止キーは `vs upgrade` が整理します。

| 変更 | 対応 |
|---|---|
| `book.cover` の既定を `light` に変更 | `cover:` を書いていない本は表紙が変わります。元の画像を使うなら `cover: master` と書きます |
| `output.cover` を `book.cover` へ移動 | `vs upgrade` が移します |
| `catalog.yml` の番号の範囲（`- 21-23`）・並び（`- 21, 25`）・一行の形を廃止 | 章を 1 行ずつ書きます。一部の章だけを組むときは `vs build 11 21-23` と指定します |
| 章のファイル名を `vs create` の作る形に限定 | 2 桁の番号と、英小文字・数字・ハイフンのスラッグにします。ビルドの前に直すコマンドを示します |
| 組む順を `catalog.yml` に書いた順に変更 | 区分の中で番号と違う順に書いている本は、並びが変わります |
| 原稿の種類を `catalog.yml` の区分で決定 | `CHAPTERS` に `90-x` を書いていた本は、付録から本文の章に変わります |
| 抑止コメントの旧形式（`vs-lint-disable-next-line`・`vs-lint-disable`・`vs-lint-enable`）を廃止 | `vs lint` が示す置き換え先（`no-lint` 系）に書き換えます |
| 画像の `{.bordered}`・`:::{.bordered}` を撤去 | 画像には既定で枠が付くので、たいていは消すだけで足ります。外すときは `border=off` |
| `--no-verify` と `book.yml` の `verify.images`・`verify.bare_urls` を撤去 | キーを消します。画像の実在は常に確かめます |
| `index.max_sub_references`・`typography.column.font_size` を撤去 | キーを消します。コラムの大きさは `stylesheets/custom.css` に書きます |
| `@omakase` を撤去 | `@auto` を使います |
| レビューファイルの印で、マイナスは直後の 1 文字にだけ掛かる | `[-ig]` は「索引から外し、用語集には残す」の意味になりました。両方外すときは `[r]` |
| 古い形式のレビューファイルで `vs index:apply` を止める | `vs index:auto` で作り直します |
| `lint.sentence_length_max` が和文の字数を指す | 上限を書いている本は、実質的に緩くなります |
| `vs delete`・`vs rename`・`vs renumber`・`vs import` の `--force` を撤去 | 確認は省けません。`vs rename`・`vs renumber` をスクリプトから動かすときは `yes \| vs rename 11 12` のように答えを渡します |
| `vs cover` の判型の引数・`vs create:cover`・`vs delete --yes`・`vs index:import --prefer-import`・`vs new --add-missing` を撤去 | 判型は `book.yml` の `page.use` に従います。既存のプロジェクトの更新は `vs upgrade` を使います |
| `vs resize` を内部コマンドに | `vs build` が出力ごとに適した画像を用意するので、手で変換する必要はありません |

## 📥 インストール / 動作要件
- Ruby **3.4 以上**（3.4.10 と 4.0.9 で動作確認）。
- Node.js **22.12 以上**（Vivliostyle CLI 11 系の要求）。
- macOS + Homebrew 環境を主対象としています。外部ツールの自動導入（`vs doctor --fix`）はこの環境でのみ動作します。Linux と Windows は動作を検証できておらず、公式のサポート対象外です。
- Kindle 向けの出力には Kindle Previewer が要ります（4 を推奨。[Amazon KDP の配布ページ](https://kdp.amazon.co.jp/ja_JP/help/topic/G202131170)から入れます）。Apple Silicon では Rosetta 2 も必要です。

macOS では、導入スクリプトで必要なものがすべて入ります。

```bash
zsh -c "$(curl -fsSL https://raw.githubusercontent.com/Atelier-Mirai/vivlio-starter/master/bin/install.zsh)"
vs new mybook
cd mybook
vs build
```

Ruby が入っている環境では、gem から入れることもできます。

```bash
gem install vivlio-starter
vs new mybook        # プロジェクトを作り、足りない外部ツールを入れます
cd mybook
vs build
```

PDF のしおりや、スキャンした PDF の読み取り（`vs pdf:read` の Enhanced Mode）を使う場合は、`gem install vivlio-starter-pdf` も実行してください（導入スクリプトでは一緒に入ります）。
