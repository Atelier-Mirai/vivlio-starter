# 🎉 Vivlio Starter 1.0.0 を公開しました！

㊗️ **祝・正式版公開！** 🎊

**Vivlio Starter** は、Markdown で書いた原稿から、印刷所へ入稿できる PDF と、Kobo・Apple Books・Kindle 向けの電子書籍を作る執筆ツールです。

著者が書くのは原稿だけです。目次・図表番号・ページ参照・索引・トンボ付きの入稿データは、`vs build` のコマンド一つで生成されます。はじめての 1 冊にも、300 ページを超える本にも、上下巻に分けた本にも使えます。同梱のガイドブックも、Vivlio Starter で組んでいます。

ぜひ使ってみてください！

---

## 🚀 1 行で始められます

macOS では、ターミナルに次の 1 行を入力すると、Homebrew・Ruby・Vivlio Starter・執筆に使うツール一式がインストールされます（15 分ほどかかります）。

```bash
zsh -c "$(curl -fsSL https://raw.githubusercontent.com/Atelier-Mirai/vivlio-starter/master/bin/install.zsh)"
```

続けて次の 3 行を実行すると、最初の PDF ができます。

```bash
vs new mybook
cd mybook
vs build
```

Ruby 3.4 以上があれば、`gem install vivlio-starter vivlio-starter-pdf` でもインストールできます。不足しているツールは、最初の `vs new` がインストールします。

## ✨ できること

### 📖 一つの原稿から、四つの形式へ

`config/book.yml` に書いた形式を、まとめて出力できます。

| 頒布先 | 指定する値 | 作られるもの |
| :--- | :--- | :--- |
| 印刷所への入稿（技術書典・コミケなど） | `print_pdf` | トンボ・塗り足し付きの PDF（表紙は CMYK の PDF/X-1a） |
| ダウンロード販売・PDF での配布 | `pdf` | 閲覧用の PDF |
| 楽天 Kobo・Apple Books | `epub` | EPUB |
| Amazon Kindle（KDP） | `kindle` | KPF |

### 🎨 デザインは設定で選べます

判型は A4・B5・A5、テーマカラーは 12 色、扉絵と節見出しの装飾は花の画像 12 種類から選べます。表紙は、同梱の `light`・`dark` に書名と著者名が入ります。自作の SVG・PNG・JPEG・WebP も使えます。

### 📚 上下巻も、全巻の合本も作れます

`config/catalog.yml` に巻を書くと、巻ごとの本と、全巻を一冊にまとめた合本を組めます。

```bash
vs build lower   # 下巻を組む
vs build all     # 全巻を、巻の順に一巻ずつ組む
vs build         # 全巻を一冊にまとめた合本を組む
```

章番号は巻をまたいで続き、別の巻の章や図は「上巻 第8章」のように参照できます。全巻の構成を示す「全巻目次」も載せられます。

### ✍️ 技術書に必要な記法がそろっています

- 🧮 **数式**：`x²`・`√(a+b)`・`Σ` のように見たままの形で書けます。LaTeX でも書けます
- 🔗 **相互参照**：`@chapref:` や `@pageref:` と書くと、章番号・図番号・ページ番号はビルド時に決まります
- 📌 **図解注釈**（`:::{.showcase}`）：スクリーンショットの枠・矢印・丸数字を、原稿に文字で書けます
- 📊 **ダイアグラム**：フローチャートやシーケンス図を ```` ```mermaid ```` で描けます
- 💬 **会話文**（`:::{.talk}`）：話者ごとに色分けした吹き出しを組めます
- 💻 **コードの取り込み**：`codes/` のファイルを掲載でき、紙面と実行するコードを一致させられます
- 🗂 **データ展開**：YAML のデータから、書籍紹介カードや表を生成できます

巻末の付録には、記法・コマンド・数式の早見表があります。

### 🔍 書いた原稿を点検できます

- **`vs lint`**：表記の揺れ・冗長な表現・文体の混在・交ぜ書き（`だ円` → `楕円`）・英単語の綴りを検出します。修正方法が一つに決まる指摘は、`--fix` で自動修正できます
- **`vs metrics`**：刊行された技術書の実測から定めた基準で、章ごとの分量と読みやすさを測定します
- **`vs preflight`**：PDF を組まずに、画像やコードの置き忘れ、本の書体にない字、組めない数式を数秒で検出します

### 📇 索引と用語集も作れます

`vs index:auto` が原稿から索引語の候補を抽出します。著者はレビューファイルで採否を決めるだけです。その語を説明しているページは、索引で太字になり、先頭に並びます。辞書の説明文や棄却した語は、次の本へ引き継げます。

### 📥 今ある原稿から始められます

- **`vs pdf:read`**：PDF を読み取り、見出し・表・コードを含む Markdown の章へ変換します。`vivlio-starter-pdf` をインストールすると、スキャンした PDF も OCR で読み取れます
- **`vs import`**：Re:VIEW Starter のプロジェクトを、Vivlio Starter のプロジェクトへ変換します

### 🛠 環境の確認と更新もコマンドで行えます

- **`vs doctor`**：必要な外部ツールを確認します。macOS では `--fix` で不足分をインストールします
- **`vs upgrade`**：本体の gem・プロジェクトの雛形・外部ツールをまとめて更新します。原稿・画像・辞書は上書きしません
- **`vs config:book`**：`book.yml` の設定の説明と今の値を確認できます

### ✅ 入稿と配信に備えた検査を行います

- 全章のビルドのたびに、PDF に Type 3 フォントが含まれていないかを検査します。含まれていれば、ページと字を報告します
- EPUB は epubcheck の ERROR が 0 件であることを、リリースのたびに検査しています
- Kindle 向けには、KFX が対応していない CSS を実際の色や文字に置き換えて出力し、Kindle Previewer 4 の画面で表示を確認しています
- 4,000 件を超えるテストと、実際に本を組むリリースゲートを、対応する Ruby（3.4.12・4.0.9）で通しています

使い方の全体は [README](https://github.com/Atelier-Mirai/vivlio-starter#readme) と、`vs new` で生成されるプロジェクトのガイドブックを参照してください。

## 🔄 RC3 をお使いの方へ

次の 2 行で更新できます。正式版になったので、`--pre` は不要です。

```bash
gem update vivlio-starter
vs upgrade
```

`vs upgrade` が、雛形のスタイルシート・校正の設定と辞書・`book.yml`・`Gemfile.lock` を更新し、`vivlio-starter-pdf` と `query-stream` も更新します。そのあと `vs lint` と `vs build` を一度実行し、🟡 の警告に従って旧形式の記法や設定を修正してください。

RC3 からの変更は約 770 コミットです。主なものは次のとおりです。

- 📚 **分冊**に対応しました
- 🚀 **導入スクリプト**（`bin/install.zsh`）と **`vs config`** を追加し、`vs upgrade` が `book.yml` の新しいキーと廃止キーも整理するようになりました
- 📇 **索引のレビューファイル**を 5 節に整理し、候補の精度を上げました。副次参照は、語を見出しに掲げた節に絞ります
- ✍️ **`vs lint`** の辞書を公用文に照らして見直し、コードブロックの言語名の推定など、新しいルールを追加しました
- 📄 **`vs pdf:read`** が、見出し・表・コードまで復元するようになりました
- 📱 **Kindle Previewer 4** に対応し、章扉と各種の表示を改善しました
- 🖨 **Type 3 フォントの検査**と、本の書体にない字の補完を追加しました

変更と修正の全体は [CHANGELOG](https://github.com/Atelier-Mirai/vivlio-starter/blob/master/CHANGELOG.md) に記載しています。

既存の原稿や設定に影響するものです。多くは、残っていると 🟡 で警告します。`book.yml` の廃止キーは `vs upgrade` が整理します。

| `catalog.yml` の番号の範囲（`- 21-23`）・並び（`- 21, 25`）・一行の形を廃止 | 章を 1 行ずつ書きます。一部の章だけを組むときは `vs build 11 21-23` と指定します |
| 章のファイル名を `vs create` の作る形に限定 | 2 桁の番号と、英小文字・数字・ハイフンのスラッグにします。ビルドの前に修正用のコマンドを表示します |
| 組む順を `catalog.yml` に書いた順に変更 | 区分の中で番号と違う順に書いている本は、並びが変わります |
| 原稿の種類を `catalog.yml` の区分で決定 | `CHAPTERS` に `90-x` を書いていた本は、付録から本文の章に変わります |
| 抑止コメントの旧形式（`vs-lint-disable-next-line`・`vs-lint-disable`・`vs-lint-enable`）を廃止 | `vs lint` が示す置き換え先（`no-lint` 系）に書き換えます |
| 画像の `{.bordered}`・`:::{.bordered}` を廃止 | 画像には既定で枠が付くので、多くは削除するだけで済みます。枠を外すときは `border=off` と書きます |
| `--no-verify` と `book.yml` の `verify.images`・`verify.bare_urls` を廃止 | キーを削除します。画像の実在は常に確認します |
| `index.max_sub_references`・`typography.column.font_size` を廃止 | キーを削除します。コラムの大きさは `stylesheets/custom.css` に書きます |
| `@omakase` を廃止 | `@auto` を使います |
| レビューファイルの印で、マイナスは直後の 1 文字にだけ掛かる | `[-ig]` は「索引から外し、用語集には残す」の意味になりました。両方から外すときは `[r]` と書きます |
| 古い形式のレビューファイルでは `vs index:apply` を中止 | `vs index:auto` で作り直します |
| `lint.sentence_length_max` が和文の字数を指す | 上限を書いている本は、実質的に緩くなります |
| `vs delete`・`vs rename`・`vs renumber`・`vs import` の `--force` を廃止 | 確認は省略できません。`vs rename`・`vs renumber` をスクリプトから実行するときは `yes \| vs rename 11 12` のように答えを渡します |
| `vs cover` の判型の引数・`vs create:cover`・`vs delete --yes`・`vs index:import --prefer-import`・`vs new --add-missing` を廃止 | 判型は `book.yml` の `page.use` に従います。既存のプロジェクトの更新には `vs upgrade` を使います |
| `vs clean` の `--cache`・`--cover`・`--generated-images`・`--all` を廃止 | `vs clean` でキャッシュを、`vs clean --purge` でキャッシュと生成物を削除します |
| `vs pdf:rasterize` を廃止 | Type 3 フォントは全章の `vs build` が検査し、ページと字を報告します |
| `-v` / `--verbose` を廃止 | 詳しいエラーは `VS_DEBUG=1` を付けて実行すると表示されます |
| `vs resize` を内部コマンドに変更 | `vs build` が出力ごとに適した画像を用意するので、手動の変換は不要です |
| Kindle Previewer 3 での変換を廃止 | Kindle Previewer 4 へ更新し、`vs doctor --fix` を実行します |

## ⚠️ 既知の不具合

- 長い見出しの折り返し位置が、PDF と EPUB / Kindle で一致しません。組版エンジンが異なるためです（`heading_chars` を実際の長さ以上にすると差は出ません）
- `vs lint --fix` は文脈を考慮しないので、辞書の置換が語の途中に一致して文を壊すことがあります。`--fix` は章ごとに実行し、直後に `git diff` で確認してください
- 本文の最初の章が 1 ページだけだと、次の章からノンブルがずれます（章が 2 ページ以上あれば発生しません）
- Kindle の確認は Kindle Previewer 4 の画面（Tablet と Phone）までです。Kindle の実機では確認していません

## 📥 動作要件

- Ruby **3.4 以上**（3.4.12 と 4.0.9 で動作確認）
- Node.js **22.12 以上**（Vivliostyle CLI 11 系の要件）
- macOS と Homebrew の環境を主な対象としています。外部ツールの自動インストール（`vs doctor --fix`）は、この環境でのみ動作します。Linux と Windows は動作を検証できておらず、公式のサポート対象外です
- Kindle 向けの出力には Kindle Previewer 4 が必要です（[Amazon KDP の配布ページ](https://kdp.amazon.co.jp/ja_JP/help/topic/G202131170)から入手できます）。Apple Silicon の Mac には Rosetta 2 も必要です。
