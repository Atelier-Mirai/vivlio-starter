# 記法網羅フィクスチャ（notation coverage fixture）

## なぜ作ったか

**本書（マニュアル）に書かれていない記法は、どのテストも守れない。**

2026-08-11 に、この死角を 2 件続けて踏んだ。

| 事故 | 素通りした理由 |
| --- | --- |
| 前書き・後書きの `###` で入稿用 PDF に Type 3 が混入 | 本書の前書きに `###` が 1 つも無い |
| 引用（`>`）内のコードブロックが地の文扱いになり、索引タグがコードへ注入 | 本書が引用の中にコードフェンスを書いていない |

どちらも **`rake test` 2,400 件も全章ビルドの Type 3 ラチェットも通過した**。実装は正しく動いており、ただ「その書き方の原稿が無かった」だけである。発見はいずれも別の書籍をビルドして初めて起きた。

このフィクスチャは、その穴を原稿の側から埋める。

## 設計：2 つの軸

### 軸 1 — 記法そのもの

CommonMark が認めるものと、Vivlio Starter 独自のものの両方を並べる。`01-commonmark.md` と `02-vivlio.md`。

### 軸 2 — 文脈（入れ子）

**平坦な網羅では上記 2 件目は捕まらない。** `> ```html` は新しい記法ではなく、既存の記法が別の文脈に入っただけだからである。

Markdown で「他のブロックを内側に持てる」入れ物は 3 つしかない。

| 入れ物 | 行頭に足すもの |
| --- | --- |
| 引用 | `> ` |
| リスト項目 | 字下げ |
| `:::` コンテナ | なし（行単位） |

事故はすべて**行頭の見え方が変わったとき**に起きる。`Masking.fence_marker` は `line.lstrip` の先頭しか見ないため `> ```html` を取りこぼした——字下げ（リスト）には強く、引用には弱い、という非対称がそのまま穴だった。

そこで `03-nesting.md` は、この 3 つを深さ 3 まで組み合わせ、末端に各記法を置く。組み合わせは全網羅（3³＝27）ではなく、**行頭が変わる経路**を通るものを選ぶ。

さらに **フェンスの中に記法を書いた場合**（＝解説として書いたとき、変換されずに素通しされること）も末端として扱う。ここを取り違えると、記法を解説する本が自分自身で壊れる。

### 軸 3 — 置き場所

前書き・本文・付録・後書きで body クラスが変わり、当たる CSS が変わる。📚 の事故はまさにここだった。同じ内容を 4 箇所に置いて差を見る（`00-preface.md` / `01`〜`03` / `90-appendix.md` / `99-postface.md`）。

## 検査（不変条件）

原稿だけ置いても、見る人がいなければ意味がない。**今回の 2 件はどちらもビルドが成功したまま壊れていた**ので、「落ちること」ではなく「黙って劣化していないこと」を見る。

| 不変条件 | 捕まえる事故 |
| --- | --- |
| Type 3 フォントが 0 件 | CSS の `content:` に書いた絵文字・未埋め込み書体へのフォールバック |
| `<code>` / `<pre>` の中に `index-term` / `<dfn` が無い | コード領域の取りこぼし |
| 本文テキストに `:::` や ` ``` ` が生で残っていない | コンテナ・フェンスの変換漏れ |
| 使ったコンテナクラスが `<div class>` として実在する | 未知クラスの素通し |
| 生 HTML タグ（`<button` 等）が本文に印字されていない | フェンス誤認による生 HTML の流出 |

## 使い方

```bash
rake test:notation
```

実ビルドを伴うため `rake test` からは除外し、`rake test:release` に載せる。生成資産（mermaid / 数式 / showcase）は `.cache/vs/` の内容アドレスキャッシュが効くので、**2 回目以降の所要時間は増えない**（実測: 生成資産あり 32.0s / なし 32.0s。キャッシュが冷えているときのみ 1 件あたり約 2.5 秒）。

## 書くときの約束事

**検査が探す文字列を、解説文の中に書かないこと。** 実際に踏んだ。「索引タグが注入されるのも失敗です」と説明するつもりで `` `<span class="index-term">` `` と書いたところ、不変条件がその一文に反応した。フィクスチャが自分自身に引っかかる形になる。

失敗の説明は、文字列を再現せずに書く。

| 書かない | 書く |
| --- | --- |
| `` `<span class="index-term">` `` | 索引タグ |
| `` `<dfn id="idx-…">` `` | 索引のアンカー |

例外は**フェンスの中**である。フェンス内は「変換されないこと」の検体そのものなので、記法を literal で書いてよい。検査はコード領域を除いて見る。

## 増やすときの流儀

- **記法を追加したら、ここにも 1 例足す。** `notation-implementation-guide.md` のチェックリストに入っている。
- **事故を踏んだら、その組み合わせを `03-nesting.md` に足す。** 再発の番人になる。
- 網羅の証明ではなく**回帰の器**である。全組み合わせを尽くすことは目的にしない。
