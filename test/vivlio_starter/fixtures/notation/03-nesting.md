## 深さ 1：引用の中

### 引用の中のフェンス

> **あなた**: これが 2026-08-11 に踏んだ形です。
>
> ```html
> <button id="btn">色を変える</button>
> <p id="message">このテキストが赤くなるはず</p>
> ```
>
> 何が問題でしょうか？

上のボタンのタグが**本物のボタンとして組まれていたら失敗**です。コードとして印字されなければいけません。索引語（テキスト・テスト）が拾われて索引タグが注入されるのも失敗です。

（この段落は、検査が探す文字列そのものを書かないようにしています。書くと自分自身に引っかかります。README の「書くときの約束事」を参照してください。）

### 引用の中のフェンスに、明示の索引記法を書く

**ここが回帰の要です。** 索引の明示記法をコードとして書いたとき、コードのまま印字されなければいけません。自動索引は辞書に載っている語しか拾わないため引き金として不確実ですが、明示記法は必ず変換対象になります——**引用の中のフェンスが保護されていなければ、ここが確実にタグ化されます。**

> ```markdown
> 索引の明示記法 [引用内コード|いんようないこーど] は、コードなので変換されません。
> 用語集の記法も同じです。
> ```

同じものを、引用の外のフェンスにも置いて比べます。こちらは以前から保護されていました。

```markdown
索引の明示記法 [フェンス内コード|ふぇんすないこーど] は、コードなので変換されません。
```

## フェンスの中に書いた記法（変換されないこと）

**記法を解説する本は、自分自身で壊れやすい場所です。** 以下はすべて「そのまま印字される」のが正解で、変換されたら失敗です。

````markdown
:::{.note}
これは解説であって、コンテナではありません。
:::

> 引用の中にコードを書く例
> ```js
> console.log("hi")
> ```

索引語 [解説用|かいせつよう] も、脚注^[これも解説です。] も、変換されてはいけません。
````

### インラインコードの中

`:::{.note}` と `[解説用索引|かいせつようさくいん]` と `@dummy-label` は、インラインコードの中なので変換されません。
