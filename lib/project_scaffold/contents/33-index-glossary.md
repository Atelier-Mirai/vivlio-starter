# 索引・用語集機能

:::{.chapter-lead}
Vivlio Starter では、`vs index` コマンドを使用して、書籍の索引と用語集を効率的に作成できます。本章では、用語の登録から自動抽出、レビュー、索引・用語集ページ生成までの一連のワークフローを解説します。
:::

`vs index` コマンドは、原稿内の手動マークアップと自動抽出を組み合わせて、索引・用語集候補を統合管理します。TF-IDF スコアリングによる候補の優先順位付けと、Markdown ベースのレビューワークフローにより、効率的な索引・用語集作成を実現します。

## 索引・用語集作成の概要

:::{.section-lead}
索引・用語集作成は、用語の登録、候補の抽出、レビュー、ページ生成という4つのステップで構成されます。
:::

### 基本的なワークフロー

```bash
# 0. 原稿にタグを付与する
# contents/01-intro.md などを編集して [用語|読み] を追加

# 1. 索引の現況を確認する（任意）
vs index:plan

# 2. 索引・用語集候補の自動抽出とレビューファイル生成
vs index:auto

# 3. _index_glossary_review.md を編集して承認・棄却
# エディタで開いて [i]=索引, [g]=用語集, [ig]=両方, [r]=棄却

# 4. レビュー結果を適用
vs index:apply

# 5. 索引・用語集ページを含む本文 PDF 生成
vs build
```

手順 1 の `vs index:plan` は**下見のためのコマンド**です。本文の分量・すでに登録されている索引語の数・候補のスコア分布を表示するだけで、辞書もレビューファイルも書き換えません。

```bash
vs index:plan          # 全章を対象に現況を表示
vs index:plan 21-23    # 章を絞ることもできる
```

索引づくりを始める前に「この本にはどれくらいの索引語がふさわしいか」を掴んだり、設定を変えた効果を辞書を壊さずに試したりするのに使います。急ぐときは飛ばして `vs index:auto` から始めても構いません。

#### 索引語数の目安

`vs index:plan` は、本文の文字数から**索引語数の目安**を算出して表示します。

```
■ いまの目安（index.target_terms: standard）
    244〜356 語 ＝ 約 362〜528 字に 1 語
    現在 153 語は目安を 91 語下回っています（約 843 字に 1 語）

■ 設定を変えるとこうなります
    light      132〜183 語      約 704〜977 字に 1 語
    standard   244〜356 語      約 362〜528 字に 1 語   ← 現在
    thorough   458〜468 語      約 275〜281 字に 1 語

    語数を直接決める場合は config/book.yml に:
      index:
        target_terms: 300        # 約 430 字に 1 語
```

**「約 N 字に 1 語」の欄**が目印になります。「500 字に 1 語くらいの密度で拾いたい」と考えているなら、その数字に近い行を選べば良いわけです。

目安は `config/book.yml` の `index.target_terms` で変えられます。

```yaml
index:
  target_terms: light       # light / standard / thorough
  # target_terms: 260       # 語数を直接指定することもできる
```

| 値 | 意味 |
| :--- | :--- |
| `light` | 控えめ。主要な語だけを拾う（既定） |
| `standard` | 標準 |
| `thorough` | 丁寧。初学者向けに広く拾う |
| 整数（例 `260`） | その語数を目安にする |

:::{.memo}
目安の数値は、刊行済みの技術書 10 冊の索引を実測して定めたものです。索引語数は本文の分量に比例せず、分量が 3 倍になっても索引語は約 2.3 倍にしかなりません（既出の語が繰り返し現れるためです）。目安もこの逓減を織り込んで算出しています。
:::

#### 推奨候補・一般候補・見直し候補

`vs index:plan` は、**すでに登録した索引語と、まだ登録していない候補を同じ土俵に並べて**スコア順に評価します。

```
登録済み 153 語と同じ土俵でスコア順に並べた結果:
  推奨候補   上位 357 位以内の未登録語      248 件
  一般候補   358〜1,071 位の未登録語   673 件
  見直し候補 357 位より下の登録済み語     43 件
  推奨候補の例: 拡張リファレンス / Mode / Step / Command / アバター …他 243 語
  見直し候補の例: オプション / 設定ファイル / セットアップ / ビルド / PDF …他 38 語
```

| 帯 | 意味 |
| :--- | :--- |
| 推奨候補 | 目安の枠内に食い込むほど重要なのに、まだ索引に無い語 |
| 一般候補 | 選ぶ幅。推奨には届かないが検討に値する語 |
| 見直し候補 | 枠外へ押し出された登録済みの語。外すことを検討できる |

**語数が目安に達していても推奨候補は出ます。**判定しているのは語数の過不足ではなく重要度だからです。推奨候補と見直し候補が同時に出ていれば、**語数を変えずに入れ替える**という選択もできます。

なお、原稿に `[用語|読み]` と書いて手動で登録した語は見直し候補に出ません。著者が明示した意図を機械が覆さないためです。

一般候補として提示する範囲は `candidate_pool` で変えられます。

```yaml
index:
  candidate_pool: 3.0    # 目安語数の 3 倍の順位まで候補として提示する
```

#### 一般語の提示

レビューファイルの「1. 登録済み用語の確認」には、**本の広い範囲に散らばっている語**が別枠で並びます。

```markdown
### 一般語（索引から外すことを推奨・16語）

本の広い範囲に散らばっている語です。索引から引いても読者が「どこを読めばよいか」を
判断できないため、外すことを推奨します。

ただし本の主題そのものである語は、広く出ていて当然です。その場合は外すのではなく、
説明している章を指定してください。

- 外す場合: [-i] のまま `vs index:apply`
- 残す場合: [i] に戻す
- 説明箇所を指定する場合: [i] に戻したうえで `m` の章番号を整える

- [-im?25] **ファイル** (ふぁいる) - スコア: 254.0 - 一般語: 23/27 章（85%）に出現
- [-im?24] **コード** (こーど) - スコア: 247.0 - 一般語: 20/27 章（74%）に出現
```

索引の役割は所在の網羅ではなく**説明の在り処への案内**です。「ファイル」で 23 章ぶんのページ番号が並んでも、それは羅列であって案内になりません。

**外すかどうかは著者が決めます。**機械は「広く散らばっている」という事実を示すだけで、勝手に外すことはありません。本の主題そのものである語（たとえば Markdown の解説書における「Markdown」）は、広く出ていて当然です。

判定の基準は `common_term_ratio` で変えられます。

```yaml
index:
  common_term_ratio: 0.5    # この比率以上の章に出る語を一般語とみなす
```

:::{.memo}
章数の少ない本では判定しません（全 6 章未満）。5 章の本では 3 章に出るだけで比率 0.6 になり、誤検出ばかりになるためです。出現章数が 3 未満の語も対象外です。判定はコードブロックを除いた地の文で行います。
:::

#### 主要参照の指定

一般語として提示された語でも、**本の主題そのもの**であれば外す必要はありません。本書における「Markdown」や「PDF」のように、広く出てくるのが当然の語です。

そうした語には、**その語を腰を据えて説明している章**を指定してください。指定はレビューファイル `_index_glossary_review.md` のフラグ欄で行います。フラグの後ろに `m` と章番号を足すだけです。

```markdown
- [im21] **Markdown** (まーくだうん) - スコア: 228.3 - 一般語: 22/27 章（81%）に出現
- [igm21,22] **拡張記法** (かくちょうきほう) - スコア: 310.5
```

複数の章で説明しているなら `m21,22` とカンマで並べます。**行が増えない**ので、語数が多くても一覧性が落ちません。

章名や**節**まで指したいときは、用語の下に子行として書きます。子行はフラグ欄より優先されます。

```markdown
- [i] **Markdown** (まーくだうん)
  - 主要参照: 21#Markdown とは
```

指定した章での**初出**が主要参照になり、索引ページで**太字＋先頭**に並びます。

```
Markdown ……… 156, 12, 24, 38, 51, 66, 88, 102, …
             ↑太字（21 章の説明箇所）
```

「まずここを読めばよい」が一目で伝われば、頻出語でも索引として機能します。

**候補は機械が下書きします。** `vs index:auto` は、主要参照が未指定の語すべてについて章の候補を提示します。

```markdown
- [im?21] **Markdown** (まーくだうん) - スコア: 228.3
```

`m?` の `?` が「機械の推測」の目印です。そのまま `vs index:apply` すれば採用されます。違う章なら数字を書き換え、指定したくなければ `m?21` ごと消してください。

候補は次の式で決めます。

```
スコア = h1 に含む数 × 3 ＋ h2 に含む数 × 2 ＋ h3 に含む数 × 1 ＋ 章内の出現回数
```

最大の章が選ばれます（同点なら章番号の若い方）。索引に出るページ番号が 1 つしかない語には、太字にしても伝わる情報が増えないため候補を出しません。

:::{.memo}
この式は実測で決めました。著者が手で決めた 44 語を正解として突き合わせると、見出しの数だけを見る方式は 45%、出現回数だけなら 61%、この式で 65% です。「〜とは」という定義文への加点は精度を変えなかったので入れていません。

候補どまりにしているのは、自動判定だけでは頻出語を救えないからです。索引語 153 語のうち 120 語は何らかの見出しに現れますが、「ファイル」は 42 の見出しに当たります。当たりすぎて絞れないのは、主要参照がいちばん必要な語のほうでした。
:::

#### 説明箇所を節まで絞る

章を指定すると、**その章の中で最初にその語を説明している節**が主要参照になります。章題（h1）は「章の名前」であって説明箇所ではないため、対象になりません。

自動で選ばれた節が違うときは、節を名指しできます。

```markdown
  - 主要参照: 21#Markdown とは
  - 主要参照: 21#主な用途                       ← その語を含まない見出しでもよい
  - 主要参照: 23#章の削除（vs delete）#基本的な使い方  ← 同じ文言が複数あるとき
```

見出しは**文言**で書きます（`4-1` のような節番号は組版時に振られるもので、原稿にはありません）。レベルは問いません。「CSS 組版」と「CSS組版」のような空白の揺れは吸収します。

同じ文言の見出しが章内に複数あるときは、親の見出しを `#` でつないで絞ります。間の見出しは省略できます。

:::{.note}
**見出しを書き換えたときは**

指定した見出しが見つからないと、ビルド時に知らせます。

```
🟡 「Markdown」の主要参照が指す見出しが見つかりません: 21#主な用途
        21-markdown-tutorial の見出し: Markdown とは / Markdown の概要 / …
        近いもの: さまざまな用途
```

指定は消えず、章だけを指定した場合と同じ動きに戻って組版は続きます。推敲の途中でビルドが止まらないようにするためです。
:::

主要参照が未指定のまま広く散らばっている語があると、ビルドの最後に要約が出ます。

```
🟡 主要参照が未指定の索引語が 30 語あります（索引が引きにくくなります）
🟡  vs index:auto を実行すると、章の候補付きでレビューファイルに一覧できます
```

この機能を使わない場合は、次に述べる `reference_style` を `all` にしてください。候補の提示もこの促しも止まります。

:::{.memo}
主要参照は著者の判断そのものなので、辞書 `config/index_glossary_terms.yml` に `main:` として保存されます（毎回導出されるスコアや文脈とは扱いが違います）。章の番号を変えても `vs rename` / `vs renumber` が追随するので、指定し直す必要はありません。
:::

#### 索引の出し方を選ぶ

主要参照を指定すると、副次参照（説明箇所以外の出現）をどこまで載せるかを選べます。

```yaml
index:
  reference_style: main_and_sub   # 既定
  max_sub_references: 8           # 副次参照の上限（0 で無制限）
```

| `reference_style` | 出力 |
|:---|:---|
| `main_and_sub` | 主要参照を太字で先頭に置き、副次参照を `max_sub_references` 件まで続けます（既定） |
| `main_only` | 主要参照だけを載せます。ページ数を詰めたい本向けです |
| `all` | 太字も並べ替えも間引きもしません。**候補の提示とビルド時の促しも止まります**（この機能を丸ごと使わないための設定です） |

**主要参照が指定されていない語は、どの設定でも間引きません。** 「まずここを読めばよい」を示せないまま出現箇所だけ削ると、その語は索引から実質消えてしまうためです。

間引いたときは、ビルドの最後に件数が出ます。

```
💡 索引の副次参照を 14 語で 8 件までに絞りました（index.max_sub_references: 8）
```

#### 連続するページを範囲でまとめる

同じ語が連続したページに出るとき、番号を並べる代わりに範囲で示します。

```
ビルド ……… 105–107, 128–130, 213, 222, 223
```

まとめる最小の連続数は `page_range_min` で変えられます。

```yaml
index:
  page_range_min: 3   # 3 ページ以上の連続を範囲にする
```

`2` にすると「12, 13」も「12–13」になりますが、二つ並べたほうが読みやすいので既定は `3` です。

:::{.memo}
範囲表記は PDF だけの機能です。ページ番号は組版してはじめて決まるため、EPUB・Kindle では連続しているかどうかを判断できません。前付け（ローマ数字）と本文（アラビア数字）をまたぐ範囲は作らず、主要参照も範囲には含めません（太字の一点であることに意味があるためです）。
:::

## 手動マークアップ

:::{.section-lead}
原稿内で索引に載せたい用語を明示的にマークアップできます。手動マークアップは最も確実な索引登録方法です。
:::

### 基本的な記法

原稿内で `[用語|読み]` または `[用語]` の形式でマークアップします。

```markdown
[Ruby|るびー]は素晴らしいプログラミング言語です。

[JavaScript]を使ってウェブページに動きを付けます。
```

- `[用語|読み]` - 用語と読み（ひらがな）を指定
- `[用語]` - 用語のみ（読みは MeCab で自動推測）

:::{.note}
**読みの指定について**

日本語の用語は、索引で五十音順に並び替えるために読みが必要です。読みを省略した場合、MeCab（形態素解析エンジン）で自動推測されますが、固有名詞や専門用語は誤認識される場合があります。重要な用語は読みを明示することを推奨します。
:::

### 実例——この章に仕込んであります

記法の説明だけでは手応えがないので、本物をひとつ置いておきました。次の一文がそれです。

索引の見出しは[五十音順|ごじゅうおんじゅん]に並びます。読みを添えたのは、並び順を決めるのが表記ではなく読みだからです。

巻末の索引で「五十音順」を引いてみてください。このページの番号が載っているはずです。紙面の見た目は何も変わりません——`[`・`|`・`]` はビルド時に取り除かれ、「五十音順」だけが組まれます。

自動抽出との違いは確実さです。スコアが低くても必ず索引に載り、`vs index:auto` の見直し候補にも挙がりません。著者が手で書いた意図を機械が覆さないためです。

### 特殊文字のマークアップ

記号や HTML タグなども索引に登録できます。

```markdown
[!]は否定演算子です。
[&&]は論理積演算子です。
[||]は論理和演算子です。
[<h1>]は見出しタグです。
```

:::{.note}
**短い半角語の辞書登録について**

半角の英数字・記号のみで 2 文字以下の用語（`[g]`・`[eV]`・`[Hz]` など）は、単位やフラグ表記との誤検出を防ぐため、`vs index:auto` では辞書に登録されません（スキップした旨の警告が表示されます）。こうした用語を辞書に登録して本文全体を自動タグ付けしたい場合は、読み付きの `[eV|電子ボルト]` の形式でマークアップしてください。
:::

### マークアップの除外

以下の記法は索引として認識されません。

- `[リンクテキスト](URL)` - Markdown リンク
- `[^1]` - 脚注参照
- コードブロック内の `[...]` - コードフェンス内は無視

## 自動抽出とレビュー

:::{.section-lead}
`vs index:auto` コマンドは、原稿から索引候補を自動抽出し、レビュー用の Markdown ファイルを生成します。
:::

### 自動抽出の実行

```bash
vs index:auto
```

このコマンドは以下の処理を行います。

1. **手動マークアップの検出** - 原稿内の `[用語]` 記法を検出
2. **候補の自動抽出** - 定義パターン、専門用語、名詞連続を検出
3. **TF-IDF スコアリング** - 候補に重要度スコアを付与
4. **レビューファイル生成** - `_index_glossary_review.md` を生成

#### 章を指定して抽出する

長い本では全章を一度に見直すのは大変です。章を指定すると、その章だけを対象に候補を抽出できます。

```bash
vs index:auto 21          # 21 章だけを対象に候補抽出
vs index:auto 21-23,25    # 範囲・複数指定も可
```

用語の登録は追記マージなので、章を指定して実行しても、他の章で登録済みの用語が消えることはありません（非破壊）。`catalog.yml` に未登録の章でも、`contents/` にファイルがあれば指定できます。なお、レビューファイル §1「登録済み用語」の文脈プレビューは、辞書に保存された抜粋ではなく、そのつど原稿から拾い直したものです。章を指定して実行した場合、その章に出てこない用語は他の章から抜粋を拾い、「（走査対象外）」と注記します。判断材料が空にならないようにするためです。

### スコアリングの仕組み

候補のスコアは**TF-IDF**と**性質ボーナス**の合計です。

| 要素 | 説明 |
|:---|:---|
| TF-IDF | 出現の偏りを見る。**特定の章に集中している語ほど高く**なる |
| 定義パターン | 「〜とは」「〜について」などの定義文に現れた（+30） |
| 専門用語パターン | カタカナ語・英語・略語（+15） |
| 名詞連続 | 複数の名詞が連なった語（+10） |

大事な性質が 2 つあります。

**出現回数がそのままスコアにならない。** TF は対数で効きます。10 倍出てきてもスコアは 10 倍にはなりません。索引語は分量に比例して増えるものではないからです。

**性質ボーナスは語ごとに 1 回だけ。** 「〜とは」の文が 5 回あっても 30 点が 5 回加算されることはありません。

この 2 つがないと、「ファイル」「コード」のようにどの章にも大量に出てくる語がスコア上位を独占してしまいます。索引として引きにくい語ほど高評価になる、という逆転が起きるためです。

:::{.memo}
索引語の採否は**スコアの絶対値では決めません**。「スコア 300 以上を採用」のような閾値は、本の分量や語彙量で意味が変わってしまうためです。代わりに、登録済みの語と候補を同じ土俵で並べ、`target_terms` で決まる目安語数の枠に入るかどうかで判断します。
:::

### 候補を自動で登録するか

既定では、候補は**辞書に自動登録されません**。レビューファイルに提示されるだけで、採用するかどうかは著者が決めます。

```yaml
index:
  auto_approve: false    # 既定。レビューファイルで著者が選ぶ
  # auto_approve: true   # 推奨候補を自動で辞書へ登録する
```

`true` にすると推奨候補（目安の枠内に入った未登録語）が自動登録されます。素早く索引の骨格を作りたいときに使えますが、**内容の確認は結局必要**です。

### レビューファイルの構成

生成される `_index_glossary_review.md` は4つのセクションで構成されます。

```markdown
# 索引・用語集レビュー
※ フラグ: [i]=索引のみ、[g]=用語集のみ、[ig]=両方、[r]=棄却、[-i]=索引から除外、[-g]=用語集から除外
※ 読みの修正は ( ) 内を編集。用語集の説明文は空行の後にインデントして記述。

## 1. 登録済み用語の確認 (Terms: N語)
- [ig] `Today` **Ruby** (るびー) - [手動登録]
  - 01-intro: Rubyは素晴らしい...

  まつもとゆきひろが作成したプログラミング言語。

## 2. 推奨候補 (High Candidates: N語)
- [ ] `NEW!` **JavaScript** (じゃばすくりぷと) - スコア: 250.5
  - 02-basics: JavaScriptを使って...

## 3. 一般候補 (Low Candidates: N語)
- [ ] `NEW!` **変数** (へんすう) - スコア: 150.2
  - 03-variables: 変数とは...

## 4. 除外済みリスト (Rejected: N語)
※ 復帰させたいものは [i], [g], [ig] を入れると候補に戻ります。
- [ ] `Today` **フォー** (フォー) - スコア: 340.7
  - 00-preface: お問い合わせフォーム...
```

| 節 | 中身 | 見るときの気持ち |
|:---|:---|:---|
| 1. 登録済み用語 | すでに辞書にある語 | 誤りがないか流し読みする |
| 2. 推奨候補 | スコアの高い未登録語 | ここを中心に採否を決める |
| 3. 一般候補 | 推奨には届かないが検討に値する語 | 余裕のあるときに見る |
| 4. 除外済みリスト | 過去に棄却した語 | 復帰させたいものだけ拾う |

:::{.note}
**用語の頭に付くラベル**

ラベルは「その語がいつ入ってきたか」を示します。前回のレビューから何が増えたのかを追うのに使ってください。

| ラベル | 意味 |
|:---|:---|
| `NEW!` | 今回の抽出ではじめて挙がった候補 |
| `Today` | 今日、辞書に登録した語 |
| なし | それ以前から辞書にある語 |
:::

### レビューの操作

| フラグ | 説明 |
|:---|:---|
| `[i]` | 索引のみに登録 |
| `[g]` | 用語集のみに登録（説明文を記述可能） |
| `[ig]` | 索引と用語集の両方に登録 |
| `[r]` | 両方から棄却（除外リストに追加） |
| `[-i]` | 索引からのみ除外 |
| `[-g]` | 用語集からのみ除外 |
| `[ ]` | 保留（次回のレビューまで保持） |

:::{.note}
**読みの修正**

読みを修正したい場合は、括弧内を直接編集します。

```markdown
- [ig] **Ruby** (るびー)  →  - [ig] **Ruby** (ルビー)
```
:::

:::{.note}
**用語集の説明文**

用語集に登録する場合、出現箇所のリストの後に空行を入れ、インデントして説明文を記述します。

```markdown
- [g] `NEW!` **非同期処理** (ひどうきしょり) - スコア: 295.6
  - 00-preface: 非同期処理はJavaScriptを日々利用して
  - 01-life: プログラミングでは非同期処理を行います

  処理の完了を待たずに*次のタスクを実行*する方式。
  `JavaScript`の`Promise`などで利用されます。
```

空行により、出現箇所と説明文の境界を判別しています。
:::

:::{.note}
**主要参照の指定**

その語を腰を据えて説明している章は、フラグの後ろに `m` と章番号で書きます。

```markdown
- [im21,22] **Markdown** (まーくだうん) - スコア: 228.3
  - 00-preface: Vivlio Starter は Markdown で書いた原稿から
```

`m21,22` を消せば指定なしに戻ります。章名や節を指したいときは、出現箇所のリストより前に `- 主要参照: 21#Markdown とは` の子行を書きます。詳しくは「主要参照の指定」をご覧ください。
:::

### レビュー結果の適用

編集が完了したら、結果を適用します。

```bash
vs index:apply
```

このコマンドは以下の処理を行います。

- `[i]` `[ig]` マークされた候補を `config/index_glossary_terms.yml` に索引用語として追加
- `[g]` `[ig]` マークされた候補を `config/index_glossary_terms.yml` に用語集用語として追加
- `[-i]` マークされた用語から索引フラグを除去
- `[-g]` マークされた用語から用語集フラグを除去
- `[r]` `[-ig]` マークされた候補を `config/index_glossary_rejected.yml` に追加
- 読みの変更を反映
- フラグの `m21` と子行 `- 主要参照:` を辞書の `main:` へ反映（どちらも無い語は指定なしに戻す）

## 索引ライブラリの持ち運び

:::{.section-lead}
自分で書いた用語集の定義や、誤検出として棄却した語の判断、読みの補正は、同じ分野の次作でも役立つ知的資産です。`vs index:export` / `vs index:import` で、書籍をまたいで引き継げます。
:::

`config/index_glossary_terms.yml` などは、この本固有のデータ（各語の出現章・行やバックリンク）と、作者の資産（用語集の定義・棄却の判断・読みの補正）が混在しています。ライブラリ機能は、**持ち運べる分だけ**を1ファイルに抜き出します。

- `vs index:export` … 用語集の定義（`[g]`）・reject 一覧・読みの個人辞書を `index_library.yml` に書き出す
- `vs index:import` … 別の本で書き出した `index_library.yml` を取り込む

```bash
# 現在の本から書き出す
vs index:export

# 新しい本のプロジェクトで取り込む
vs index:import
```

書き出されるのは用語集の `term` / `yomi` / `definition`、reject 一覧、読みの個人辞書（`term => yomi`）だけで、出現箇所やバックリンクなどの本固有情報は含みません。取り込みは追記マージで、既存の語は既定で温存します（`--prefer-import` を付けるとライブラリ側で上書き）。すでに索引・用語集に採用済みの語は reject には追加しません。

取り込んだ読みは `config/index_yomi_overrides.yml` に蓄積され、MeCab の自動推測より優先して使われます（読みの優先順位は、記法 `[用語|読み]` → `index_glossary_terms.yml` の読み → 個人辞書 → MeCab）。「碍子」を「がいし」と読ませたい、といった補正を本ごとに登録し直す手間がなくなります。

パスに設定は要りません。引数を省略すると `index_library.yml` を読み書きし、別の場所を使いたいときは引数で渡します。

```bash
# 既定のパス（プロジェクト直下の index_library.yml）
vs index:export
vs index:import

# 別名で書き出す／共有ライブラリから取り込む
vs index:export mybook_library.yml
vs index:import ~/vivlio/shared_library.yml
```

## ビルド時に何が起きるか

:::{.section-lead}
`vs build` は、原稿をスキャンして索引用語にタグを付け、索引ページと用語集ページを組み立てて本文 PDF に綴じ込みます（内部の仕組みに興味がある人向けの情報です）。
:::

ビルド時、内部では次の処理が行われます。

1. `config/index_glossary_terms.yml` の用語（`flags` に `i` を含むもの）を原稿から検索
2. マッチした箇所に HTML タグを付与
3. 索引・用語集データを生成

### 生成されるタグ

原稿内の用語は以下のタグに変換されます。

```html
<!-- 初出（定義） -->
<dfn id="idx-ruby-1" class="index-term" data-yomi="るびー">Ruby</dfn>

<!-- 2回目以降 -->
<span id="idx-ruby-2" class="index-term" data-yomi="るびー">Ruby</span>
```

- **初出**: `<dfn>` タグ（定義を示す）
- **2回目以降**: `<span>` タグ

### 索引ページ

生成される `_indexpage.html` は次の特徴を持ちます。

- **五十音順ソート** - 読みに基づいて「あ行」「か行」などでグループ化
- **英数字対応** - `A-Z`、記号、数字も適切にグループ化
- **CSS target-counter 対応** - ページ番号は CSS で自動挿入
- **重複排除** - 同一ページ内の複数出現は1つにまとめる

### 用語集ページ

用語集ページは、登録された用語とその説明文、本文へのバックリンクを一覧表示します。生成される `_glossarypage.html` は次の特徴を持ちます。

- **五十音順ソート** - 「あ行」「か行」などでグループ化（カタカナ語も対応）
- **Markdown 対応** - 説明文内の `##` 記法や `*` リストを HTML に変換
- **バックリンク** - 本文での出現箇所へのリンク（ページ番号表示）
- **重複排除・昇順ソート** - バックリンクはページ番号の昇順で表示、同一ページは1つにまとめる

#### バックリンクの表示

用語集ページの各用語には、本文での出現ページが表示されます。

```
→ p.1, 5, 12, 45
```

- ページ番号のみ表示（章名は省略）
- 重複するページは自動的に排除
- ページ番号の昇順でソート
- クリックで本文の該当箇所へジャンプ

#### 索引ページの構造

```html
<section class="index">
  <h1>索引</h1>
  <div class="index-section" data-initial="あ">
    <h2>あ</h2>
    <dl class="index-list">
      <dt>アルゴリズム</dt>
      <dd><a href="03-basics.html#idx-algo-1"></a></dd>
    </dl>
  </div>
  <!-- 他の行も同様 -->
</section>
```

## 設定のカスタマイズ

:::{.section-lead}
`book.yml` の `index` セクションで、索引機能の動作をカスタマイズできます。
:::

### 索引設定

索引と用語集で共通の設定は `index_glossary` に、索引だけの設定は `index` に置きます。

```yaml
index_glossary:
  enabled: true                  # 索引・用語集の両方を有効化（false で両方無効）
  use_mecab: true                # MeCab による読みの自動推測を使う
  timezone: 'Asia/Tokyo'         # タイムゾーン（レビュー時の新着判定に利用）
  context_width: 40              # 文脈の表示幅（キーワード前後の文字数）

index:
  auto_discovery: true           # 自動抽出を有効化（false で手動登録の語のみ）
  title: '索引'                  # 索引ページのタイトル
  target_terms: light            # 索引語数の目安（後述）
  candidate_pool: 3.0            # 目安語数の何倍までを候補として提示するか
  auto_approve: false            # true: 推奨候補を自動で辞書へ登録する
  common_term_ratio: 0.5         # この比率以上の章に出る語は「一般語」として除外を推奨
```

### 用語集設定

```yaml
glossary:
  title: '用語集'                # 用語集ページのタイトル
  require_definition: false      # true: [g] フラグで説明文がないとエラー
  max_definition_length: 500     # 説明文の最大文字数（超過したら警告）
```

用語集そのものの有効・無効は `index_glossary.enabled` で索引とまとめて切り替えます。

:::{.note}
**用語集リンクについて**

本文中の用語集登録語には、自動的に上付きの `†`（ダガー）記号が付与されます。この記号はアクセント色（`book.yml` の `theme.color` 設定に連動）で表示され、クリックすると用語集ページの該当項目へジャンプします。

例: コンピュータ<sup>†</sup> → クリックで用語集へ
:::

### 候補の量を決める設定

語数はスコアの絶対値ではなく、**本文の分量から導く目安語数**で決めます。スコアの閾値を直接指定する必要はありません。

| 設定 | 既定 | 説明 |
|:---|:---|:---|
| `target_terms` | `light` | 目安語数。`light` / `standard` / `thorough` から選ぶか、`260` のように直接指定する |
| `candidate_pool` | 3.0 | 目安語数の何倍までを候補として提示するか |
| `auto_approve` | false | true にすると推奨候補を自動で辞書へ登録する |

いまの設定で何語が目安になるかは `vs index:plan` で確認できます（本章のはじめの「索引語数の目安」を参照）。

## トラブルシューティング

:::{.section-lead}
索引機能の実行時によくある問題とその解決方法を紹介します。
:::

### MeCab が利用できない

**症状**: 読みの自動推測が動作しない

**解決方法**:

Vivlio Starter では、次のコマンドで MeCab と natto を自動的にインストールできます。

```bash
vs doctor --fix
```

または手動でもインストールできます。

```bash
brew install mecab mecab-ipadic

# Ruby gem
gem install natto
```

### 索引が五十音順にならない

**症状**: 索引ページで用語が正しくソートされない

**原因**: 読みが正しく設定されていない

**解決方法**:
1. `_index_glossary_review.md` を確認
2. 読みが誤っている用語の ( ) 内を修正
3. `vs index:apply` を実行し修正を適用
4. `vs build` を実行してPDFを確認

### コードブロック内の用語が抽出される

**症状**: コード内の変数名などが候補に含まれる

**原因**: コードブロックの記法が正しくない

**解決方法**:
- コードブロックは ` ``` ` で正しく囲む
- インラインコードは `` ` `` で囲む

### 用語が索引に載らない

**症状**: 原稿中に頻出する用語なのに、索引ページに表示されない

**原因**: 自動索引機能が有効になっていない

索引システムは以下の2つの方法で用語をタグ付けします。

1. **手動マークアップ**: 原稿内で `[用語]` や `[用語|読み]` と明示的に記述
2. **自動タグ付け**: `config/index_glossary_terms.yml` に登録された用語を自動検出

`vs index:auto` や `vs index:apply` を実行していない場合、`config/index_glossary_terms.yml` が生成されず、手動マークアップした用語のみが索引に載ります。

**解決方法**:

```bash
# 1. 自動抽出を実行してレビューファイルを生成
vs index:auto

# 2. _index_glossary_review.md を開いて [i]/[g]/[ig] で承認
# （エディタで編集）

# 3. 承認結果を適用
vs index:apply

# 4. 再ビルド
vs build
```

:::{.column}
**ヒント**: `vs build` 実行時に `config/index_glossary_terms.yml` が見つからない場合、警告メッセージが表示されます。自動索引機能を活用するには、まず `vs index:auto` を実行してください。
:::

### 登録した用語が原稿から消えたとき

推敲で語を言い換えたり、節ごと削ったりすれば、辞書に残った語は原稿のどこにも無くなります。**辞書から自動で消えることはありません。**著者が承認した語を機械が勝手に取り下げるべきではないからです。代わりに、消えたことが二段階で知らされます。

`vs index:auto` を実行すると、その語はレビューファイルで `[原稿に出現しません]` と注記されます。文脈の抜粋も付きません。用語集に載せていた語なら `vs build` でも警告が出ます。

:::{.output}
```
🟡 用語集語がビルド対象章に出現しません: 電子ボルト
   （原稿のどこにも出現しません（語の変更・削除？））
```
:::

綴りを変えただけなら辞書の側を直し、本当に不要になったならレビューファイルで `[r]` を付けて外してください。索引だけに登録していた語は、出現がなければ索引ページに行が立たないので、放っておいても紙面には影響しません。

### 章を `catalog.yml` から外したとき

「開発者向けの章は一般の読者には要らない」「ページ数の都合で見送る」といった判断で、`contents/` にファイルを残したまま `catalog.yml` から外すことがあります。このとき索引まわりは次のように動きます。

まず、その章は `vs index:auto` の対象から外れます。走査する章は既定で `catalog.yml` が決めるからです。章の中に書いた `[用語|読み]` の手動マークアップも登録されなくなります。すでに辞書へ入っている語は、そのまま残ります。

外した章にしか出てこなくなった語は、レビューファイルで出どころがわかるように注記されます。

:::{.output}
```
- [ig] `Today` **インストルメンテーション** (いんすとるめんてーしょん)
       - [catalog 未登録の章に出現]
  - 61-developer（catalog 未登録）: 開発者だけが読む…
```
:::

「（走査対象外）」との違いは行き先です。走査対象外は本には載る章なので直す点はありませんが、**`catalog 未登録` はその章が本に入らない**ということで、その語には索引のページ番号が付きません。章を `catalog.yml` へ戻すか、語を索引から外すかを決めてください。

#### 紙面はどうなるか

外した章にしか出てこなくなった語は、登録先によって紙面での消え方が違います。

| 登録先 | 索引ページ | 用語集ページ |
| :--- | :--- | :--- |
| `[i]` 索引のみ | 消える | — |
| `[g]` 用語集のみ | — | 残る（`→ p.` は消える） |
| `[ig]` 両方 | 消える | 残る（`→ p.` は消える） |

索引は「本文のここにある」ことだけを伝える案内なので、出現がなければ項目そのものが成り立ちません。だから黙って消えます。一方、用語集の説明文は「その語が何か」を伝えるもので、本文の何ページに出るかとは独立した価値があります。そこで**掲載は維持し、本文へのページ参照だけを落とします**。

:::{.output}
```
CLI
Command Line Interface の略。ターミナルからコマンドを打ち込ん
で操作するインターフェイスです。
```
:::

用語集はリンクの無い項目として紙面に痕跡が残るので、`vs build` が知らせます。

:::{.output}
```
🟡 用語集語がビルド対象章に出現しません: インストルメンテーション
   （catalog 未登録の 61-developer に出現）
```
:::

:::{.notice}
索引だけに登録した語は、紙面に痕跡が残らないぶん `vs build` も黙ります。章を外したあとに気づく手段は `vs index:auto` のレビューだけです。`catalog.yml` を編集したら一度実行しておくと確実です。
:::

なお、消えるのは**その語が出るすべての章を外したとき**です。たとえば `CLI` が 6 章に出ているなら、そのうち 1 章を外しても減るのはその章ぶんのページ番号だけで、項目も残りの参照もそのままです。

## ページ番号は紙面のノンブルと一致します

:::{.section-lead}
用語集・索引に並ぶページ番号は、その本を開いたときに実際に印字されているノンブルと同じ数字です。読者が「p.307」を見てそのページを開けば、そこに目的の語があります。
:::

書籍全体のビルドでは、すべての章がひとつづきの流れとして組まれます。ページ番号を数えるカウンタも本の先頭から通しで進み、本文の最初の章で 1 に振り直されます。用語集のバックリンクはこのカウンタを参照するため、**前書きや目次などの前付はローマ数字（`p.ii`）、本文はアラビア数字（`p.307`）**と、紙面の表記そのままで並びます。

```
CSS 組版
    HTML と CSS を使って書籍の紙面を設計・組版する手法。
    → p.307
```

ひとつだけ意識しておくと良いことがあります。**PDF ビューアが数える「何枚目のページか」とは一致しません。**表紙・扉・権利ページ・前書き・目次が前に入るため、たとえば本書では紙面のノンブル 307 が PDF ファイルとしては 356 枚目にあたります[^folio-offset]。ビューアの「ページ番号を入力して移動」欄に用語集の数字をそのまま打ち込むと違う場所へ飛ぶので、その場合はリンクをクリックしてください。リンク自体は正しい位置へ飛びます。

[^folio-offset]: この 49 ページというずれは本書での値です。前付の枚数は書籍ごとに違い、とくに目次は章や節が増えるほど長くなるため、ずれの大きさもそれに応じて変わります。特定の数を覚えて差し引くのではなく、「紙面のノンブルと PDF の枚数は別物」と捉えておくのが安全です。

なお、単一の章だけをビルドしたとき（`vs build 12` のように章を指定した場合）は、その章だけを 1 ページ目として組むため番号も章の中で数えた値になります。通し番号で確認したいときは書籍全体をビルドしてください。

## まとめ

:::{.section-lead}
`vs index:auto` コマンドを活用することで、索引作成作業を大幅に効率化できます。
:::

本章で学んだ内容は次のとおりです。

- ✅ 手動マークアップによる索引用語の登録 `[用語|読み]`
- ✅ `vs index:auto` による自動抽出とスコアリング
- ✅ `_index_glossary_review.md` でのレビューワークフロー
- ✅ `vs index:apply` による承認・棄却の適用
- ✅ `book.yml` でのカスタマイズ

索引は書籍の利便性を大きく向上させる重要な要素です。`vs index:auto` コマンドの自動抽出機能とレビューワークフローを活用することで、漏れのない索引を効率的に作成できます。

:::
