# 章の管理

:::{.chapter-lead}
執筆を進めていると、章を増やす、順番を変える、いったん外すといった構成の見直しが何度も起こります。Vivlio Starter では、章ファイルの作成・削除・名前変更・連番整理をコマンドから行えます。原稿だけでなく、`catalog.yml` や画像ディレクトリも一緒に更新されるため、章立てを変えるたびに関連箇所を探して直す必要がありません。本章では、まずコマンドで章を指定する方法を説明し、続いて構成を変更するための四つのコマンドを紹介します。
:::

## コマンドで章を指定する @chapter-targets

:::{.section-lead}
`vs build`・`vs lint`・`vs metrics`・`vs delete` など、章を受け取るコマンドは、どれも同じ規則で章の指定を解釈します。ここで一度まとめて説明し、各コマンドの章ではこの節を参照します。
:::

### 章の書き方

章は、ファイル名のほか、番号だけ・スラッグだけでも指定できます。

| 書き方 | 例 | 指す章 |
| :--- | :--- | :--- |
| ファイル名 | `11-intro` | `contents/11-intro.md` |
| 番号だけ | `11` | 番号が 11 の章 |
| スラッグだけ | `intro` | スラッグが `intro` の章 |
| 範囲 | `11-13` | 11〜13 番の間にある章 |

`contents/11-intro.md` のようにパスと拡張子を付けて書いても構いません。複数の章は、空白かカンマで区切って並べます（`vs build 11 12`・`vs build 11,12`）。範囲は `13-11` のように大きい番号から書いても同じです。

範囲の間に、章のない番号があっても構いません。章の番号は飛び飛びに振るので、`vs build 00-11` は、間にある章だけを組みます。何章を組むかは、次のように示されます。

:::{.output}
```text
💡 00-11 のうち、原稿のある 2 章（00-preface, 11-intro）をビルドします
```
:::

処理を中止するのは、範囲に章が一つもないときだけです。そのときは、範囲の手前と後ろにある章が表示されます。`vs build`・`vs preflight` が組むのは、`catalog.yml` に登録した章だけです。範囲の中に未登録の草稿があれば除外し、そのことを同じ行に表示します。`vs lint`・`vs metrics` は読むだけなので、未登録の原稿も対象にします。番号や名前を一つずつ書いた指定は、見つからなければ入力の誤りとみなして処理を中止します。

:::{.memo}
**「スラッグ」とは**、ファイル名のうち、章番号に続く短い識別名です。`11-intro` なら、`11` が章番号、`intro` がスラッグにあたります。半角の英小文字・数字・ハイフンで、章の内容を短い英単語で表します（例：`intro`、`setup`、`appendix-a`）。章題が後から変わっても扱いやすい、ファイル上の名前として使います。

章のファイル名は、2 桁の番号と、この形のスラッグで付けます。大文字・アンダースコア・点・空白・日本語を含む名前は、章を指すときに別の章と取り違えるため使えません。Finder で複製した `95-sample のコピー.md` のように手で付けた名前があると、ビルドの前に処理を中止し、修正後の名前とコマンドが表示されます。
:::

### 番号は 0 を補って解釈する

章番号は 2 桁で扱います。`1` と書いても `01` と解釈するので、`vs build 1` と `vs build 01` は同じ意味です。範囲も同じで、`1-3` は `01`・`02`・`03` を指します。

### 対象になるのは `catalog.yml` に載った章

章を指定しないと、`config/catalog.yml` に載っているすべての章が対象になります。コメントアウトした章や、載せていない章は対象から外れるので、実際に収録する原稿だけを扱えます。

```yaml
# config/catalog.yml
CHAPTERS:
  - 11-intro
  - 12-basics
  # - 13-advanced  # コメントアウトした章は対象外
```

`catalog.yml` の書き方（章の書き方・分冊）は @pageref:catalog-yml で説明します。

`catalog.yml` に載っていない章を `vs build` や `vs preflight` で指定すると、何もせずに処理を中止し、`catalog.yml` へ追加するよう案内します。指定した章の一部だけが処理されたことに気づかないまま進むのを防ぐためです。綴りを誤った指定には、近い章名を一つ添えて案内します。

## `vs create` — 章ファイルを作成する

:::{.section-lead}
`vs create` は、章の Markdown ファイルと画像ディレクトリを同時に作り、`config/catalog.yml` へ章を登録します。新しい章を書くための置き場所が、一度の操作でそろいます。
:::

### 基本的な使い方

```bash
vs create 11-intro
```

`contents/11-intro.md` と `images/11-intro/` が生成され、`config/catalog.yml` に `11-intro` が追記されます。複数の章も一度に作れます。

```bash
vs create 11-intro 12-basics 13-advanced
```

別の章が使っている番号やスラッグを指定したときは、章を作らずに処理を中止します。代わりに、重ならない番号（同じ区分で空いている番号）やスラッグ（`-2` を追加したもの）を使ったコマンドが表示されるので、それを実行してください。番号が重なっていると `vs build 95` が、スラッグが重なっていると `vs build sample` や章の参照が、どちらの章を指すか決められなくなります。

:::{.output}
```text
🔴 エラー: 以下の章は、番号かスラッグが既に使われています:
🔴   - 95-foo（95 番は 95-sample が使っています） → vs create 96-foo
🔴   - 02-sample（スラッグ sample は 95-sample が使っています） → vs create 02-sample-2
```
:::

`vs rename` で番号やスラッグを変えるときも、同じように確かめます。

### 番号だけ・スラッグだけで作成

章の内容を表すスラッグがまだ決まっていないときは、番号だけでも作成できます。この場合は `11.md` のようなファイル名になります。

```bash
vs create 11
```

反対に、番号を省いてスラッグだけを書くと、本の最後に章を追加します。

```bash
vs create intro basics advanced
```

:::{.notice}
割り当てられるのは、**本文の最後の章の次の番号**です。`12-basics` まである本で `vs create advanced` とすると `13-advanced` になります。分冊の本では、最後の巻の末尾に入ります。本文の番号が 89 まで埋まっているときは、空いているもっとも小さい番号を使います。章の間に挿入するときは、`vs create 12-basics` のように番号も書いてください。
:::

### テンプレートの自動選択

章ファイルの初期内容は、`templates/` ディレクトリにあるテンプレートから作られます。前書き・本文・付録・後書きでは必要な構成が異なるため、章番号の範囲に応じて使うテンプレートも切り替わります。

| 章番号の範囲 | 使用テンプレート | 用途 |
|-------------|----------------|------|
| 00 | `templates/preface.md` | 前書き・はじめに |
| 01-89 | `templates/chapter.md` | 通常の章 |
| 90-98 | `templates/appendix.md` | 付録 |
| 99 | `templates/postface.md` | 後書き・おわりに |

テンプレートはプロジェクト内の `templates/` ディレクトリにあり、その本の書き方に合わせて編集できます。`{{TITLE}}` には、作成時に指定したスラッグ（番号だけで作ったときは番号）が入ります。テンプレートが見つからない場合は、最小限の骨子が生成されます。

### 生成されるファイルの中身

通常章の雛形 `templates/chapter.md` には、一章分の骨組みが用意されています。リード文・節・小見出し・箇条書き・コード・表・図・補足の囲みが並んでいるので、不要な部分を削除し、見出しと本文を書き換えて使います。

:::{.tip}
いつも置く節や注意書き、章末の案内などを `templates/chapter.md` に加えておくと、以後 `vs create` で作る章に同じ構成が入ります。複数の章に共通する型をここへ集めると、書籍全体の調子もそろえやすくなります。
:::

### 記法の見本をコピーして使う

使える記法は、すぐに使える形で `templates/markdown_snippet.md` にまとめています。並びは @chapref:ch-notation-cheatsheet と同じで、早見表の各行の例がそろっています。使いたい記法を見つけたら、その例を原稿へコピーし、内容だけを書き換えてください。このファイルは `catalog.yml` に登録されていないので、ビルドの対象になりません。

## `vs delete` — 章を削除する

:::{.section-lead}
`vs delete` は、章の Markdown ファイル・画像ディレクトリ・`catalog.yml` の登録をまとめて削除します。原稿と関連ファイルを一緒に扱う操作なので、削除前には確認が表示されます。
:::

```bash
vs delete 11-intro
```

`contents/11-intro.md`、`images/11-intro/`、`catalog.yml` のエントリが削除され、索引辞書の主要参照（`main:`）がこの章を指していれば削除されます。章は前の節の書き方で指定できるので、`vs delete 11` や、範囲を指定した `vs delete 11-13` も使えます。

確認は、原稿と画像ディレクトリについて別々に表示されます。原稿の削除に「いいえ」と答えると、`catalog.yml` の登録と索引辞書の主要参照もそのまま残ります。原稿が無く `catalog.yml` にだけ載っている章は、登録を削除してよいかを確認します。

削除した原稿は復元できないので、`vs delete` は端末から実行します。確認に答えられないスクリプトからは実行できません。

## `vs rename` — 章のスラッグと番号を変更する

:::{.section-lead}
`vs rename` は、章の Markdown ファイル名・画像ディレクトリ名・`catalog.yml` の登録を一括で変更します。章番号とスラッグのどちらか一方だけを変えることもできます。
:::

```bash
vs rename 11-intro 12-introduction
```

`11-intro.md` → `12-introduction.md`、`images/11-intro/` → `images/12-introduction/` に変更し、`catalog.yml` も更新されます。片方だけを変えるときは、変える側だけを書きます。

| 書き方 | 変更後 |
| :--- | :--- |
| `vs rename 11 12` | `12-intro.md`（番号だけ変える） |
| `vs rename 11-intro introduction` | `11-introduction.md`（スラッグだけ変える） |

スクリプトから実行するときは、`yes | vs rename 11 12` のように、確認の答えを標準入力から渡します。

### 章名の変更に追随するもの

`vs rename` と `vs renumber` は、章のファイル名だけでなく、その名前を参照している関連箇所も更新します。

| 追随するもの | 内容 |
| :--- | :--- |
| `config/catalog.yml` | 章の並び順の定義 |
| `images/<章名>/` | 章専用の画像ディレクトリ |
| 索引辞書の主要参照 | `main:` が指す章名（→ @ch-index-glossary） |
| 索引から外す章 | `book.yml` の `index_glossary.exclude_chapters` に書いた章番号（範囲は書き換えない） |

## `vs renumber` — 章番号を一括で付け直す

:::{.section-lead}
`vs renumber` は、通常章と付録の番号を、それぞれの範囲内で連続するように付け直します。章の追加や削除を重ねて番号の間隔が不ぞろいになったときに、書籍全体をまとめて整理できます。
:::

```bash
vs renumber
```

通常章（01〜89）を先頭の章の番号から順に、付録（90〜98）を 90 から順に振り直します。番号が変わらない章も含めて全件を並べたうえで、確認を求めます。本に載せる順は `catalog.yml` に書いた順なので、番号を付け直しても変わりません。

:::{.output}
```text
章の刻み幅: 1
対象ファイル:
通常の章:
  11-intro      →  11-intro
  13-basics     →  12-basics
  15-advanced   →  13-advanced
付録:
  91-appendix-a →  90-appendix-a
❓ 連番付け直しを実行しますか？ [y/N]:
```
:::

この例では先頭の章が `11` なので、そこを起点に `11, 12, 13` と詰められます。`01` から振り直されるわけではありません。付録の `appendix-a` のようなスラッグは、新しい番号に合わせて `appendix-a`〜`appendix-i` へ付け替わります。

### 刻み幅を指定する（`--step`）

```bash
vs renumber --step 2
```

章番号を `11, 13, 15, ...` のように二つずつ空けて振り直します（短縮形は `-s 2`）。番号の間に余地ができるため、後から章を挿入しても、その後ろをすぐに改番せずに済みます。章が多く、この刻み幅では 89 を超えるときは、刻み幅が自動で小さくなります。

### 別の番号帯へ移す

`vs renumber` は番号帯の区切りを保ち、前書き（00）と後書き（99）は変更しません。別の番号帯へ移すときは、`vs rename` で移動先の番号を明示します。

```bash
vs rename 00-preface 11-preface   # 前書きを本文に移す
vs rename 45-utility 91-utility   # 本文を付録に移す
```

## 注意事項

- ファイルを手作業で移動・削除した場合は、その変更を `catalog.yml` にも反映してください。章管理コマンドを使えば、原稿と `catalog.yml` の対応は保たれます。
- 画像ディレクトリが移動先にすでに存在する場合は、手動での統合が必要です。
