# 原稿の分量と難度の計測

:::{.chapter-lead}
書いている最中の原稿は、章ごとの長短や文章の硬さに気づきにくいものです。metrics 機能は、Markdown 原稿の分量・語彙・読解難度を数値で示し、いつもの読み返しとは違う角度から原稿を眺める手がかりを与えます。本章では、数値の意味と、推敲へつなげるときの読み方を説明します。
:::

## metrics とは

:::{.section-lead}
metrics は、執筆中の原稿を統計的に分析するツールです。漢字比率、語彙多様度、読解難度などを計算し、章ごとの違いや、全体から外れている箇所を見つけやすくします。
:::

ただし、数値だけで文章の良し悪しが決まるわけではありません。短い章にも役割があり、専門書には難しい語が必要です。metrics は原稿を採点するものではなく、「ここは意図した偏りだろうか」と立ち止まるための材料です。確認できる指標には、次のものがあります。

### metrics の主な機能

- **基本統計**: 文字数、行数、文の数、節の数を集計
- **語彙難度**: 漢字比率と平均語長から文章の「硬さ」を測る
- **語彙多様度**: MATTR（移動平均 Type-Token Ratio）で語彙の重なり方を見る
- **読解難度**: 建石式リーダビリティー（RS）で読みやすさの目安を示す
- **章別バランス**: 各章の分量を可視化し、構成の偏りを見つける

## metrics コマンドの基本

:::{.section-lead}
原稿の統計分析には、`vs metrics` コマンドを使います。まず全章の概要を眺め、気になった章だけを詳しく調べることもできます。
:::

```bash
# catalog.yml に載っている全章の概要
vs metrics

# 11-intro だけを節まで詳しく
vs metrics 11

# 範囲と個別指定の組み合わせ
vs metrics 11-13 15
```

章を指定すると、その章は節まで展開して表示されます。章は、ファイル名・番号・範囲のどれでも指定できます。書き方は @ch-chapter-management の章の @pageref:chapter-targets で説明しています。

## コマンドオプション

:::{.section-lead}
見たい範囲や推敲の段階に合わせて、出力内容をオプションで切り替えられます。
:::

### `--all` — 推敲用の参考資料も表示する

通常の `vs metrics` は「解析結果」（章別分量・基本情報・文構造・詳細分析）までを表示します。`--all` を付けると、これに加えて推敲用の参考資料（章間のばらつき・見直したい長い文・文末表現のリズム・よく使う言葉・漢字レベル）も続けて表示します。情報量が多いので、通常は解析結果だけを見て、推敲に入るときに `--all` を使う、といった使い分けができます。

```bash
vs metrics --all
```

### `--sections` — 全章を節まで展開する

全章を節まで展開して表示します。章別リストのすべての章が節まで開かれ、節ごとの分量推移が確認できます。

```bash
vs metrics --sections
```

### `--warn` — 警告のある章だけを展開する

警告がある章のみを節まで展開して表示します。分量が基準から外れている章や、表現が単調・やや難解と評価された章を素早く特定できます。

```bash
vs metrics --warn
```

### `--json` / `--yaml` — 構造化データで出力する

統計情報を構造化データとして出力します。章ごとの基本統計 `stats`、全体集計 `totals`（語彙・読解難度を含む）に加え、`--all` で表示される参考資料も `advice` として出力するため、外部ツールで再計算する必要がありません。

`stats` の各章には、画面表示と同じ警告が `warnings` として並びます。警告のない章でも空の配列が入るため、キーの有無を気にせず読み取れます。

```json
{ "path": "contents/12-basics.md", "chars": 15890,
  "warnings": ["やや長い", "表現が単調"] }
```

```bash
vs metrics --json
vs metrics --yaml
```

JSON/YAML 出力時は章別リストの逐次表示を省き、結果を一括で返します。出力の全体の形は @ch-developer の章の @pageref:metrics-json に載せています。

## 実行結果の見方

:::{.section-lead}
metrics の出力は、章別分量・基本情報・文構造・詳細分析の四つに分かれます。画面では章別分量が先に現れますが、ここでは数値の土台が分かるよう、基本情報から順に見ていきます。
:::

### 基本情報

文章全体の基礎的な統計を表示します。

:::{.output}
```text
📊 文章統計 — 基本情報
- 文字数: 12,345 文字（本文。ほかに コード 8,200 文字、記法 1,100 文字）
- 行数: 123 行

📊 文章統計 — 文構造
- 文の数: 45 文（平均 274 文字/文）
- 節の数: 134 節（平均 92 文字/節）
- 読点数: 89 個
```
:::

### 詳細分析

語彙難度、語彙多様度、読解難度を分析します。語彙難度には、本文を構成する文字種の割合（漢字・ひらがな・カタカナ・英字・その他）も併記します。

:::{.output}
```text
📈 詳細分析

【語彙難度】
- 漢字比率: 適切（28.5%） — 理想的な範囲 25〜35%
- 平均語長: 2.3 文字
- 文字種構成: 漢字 28.5% ／ ひらがな 45.2% ／ カタカナ 12.1% ／ 英字 5.7% ／ その他 8.5%

【語彙多様度】
- 使用語彙数: 3,900 語（異なり語）／ 総語数 54,000 語
- 語彙の豊かさ: 標準的（MATTR: 0.58）
  - 評価基準: 0.7 以上=非常に豊富、0.6〜0.7=豊富、0.5〜0.6=標準的、0.5 未満=単調

【読解難度】
- 評価: Standard（一般的なビジネス・実用書）
- スコア: 45.2 点
```
:::

:::{.note}
**コードは分析対象から除外されます。**漢字比率・語彙多様度・読解難度は、文章としての読みやすさを測る指標です。コードブロック（` ``` ` で囲んだ部分）やインラインコードは、英数字・記号の塊が指標を実態より平易側に歪めるため、これらの分析からは除かれます。**章別分量の文字数もコードと記法を除いた「本文」で数えます。**コード込みで数えると、コードが多い章ほど「分量が足りている」と判定されてしまい、読者が読む文章の量を見誤るためです。基本情報では、除いたコードと記法の量をカッコ内に外数で併記します。
:::

#### 漢字比率

漢字が本文に占める割合から、文章の「硬さ」を見ます。技術書では 25〜35% を基準の範囲としていますが、読者層や扱う分野によって適切な値は変わります。

| 範囲 | 評価 |
|------|------|
| 20% 未満 | 平易すぎる |
| 20〜25% | やや平易 |
| 25〜35% | 適切 |
| 35〜45% | やや難解 |
| 45% 超 | 難解 |

#### 文字種構成

本文（コード除去後）を構成する文字の種別ごとの割合を示します。漢字・ひらがな・カタカナ・英字、および「その他」（数字・記号・句読点）に分けて表示します。漢字の割合は前述の「漢字比率」と同じ値です。

一般に、読みやすい和文はひらがなが多めで漢字が3割前後とされます（漢字3:ひらがな7 などの目安）。カタカナや英字が多い場合は、専門用語・外来語が多いことを示します。技術書では自然に高くなりますが、入門書で初学者向けに書くなら、カタカナ語の言い換えや補足のヒントになります。

#### MATTR（語彙多様度）

語彙の重なり方は、MATTR（Moving-Average Type-Token Ratio／移動平均 TTR）で測定します。値が高ければ常に優れているという指標ではなく、同じ言葉へ頼りすぎていないかを見るための目安です。

素朴な TTR（異なり語数 ÷ 総語数）は、**文章が長いほど機械的に低くなる**という弱点があります。語彙（異なり語）は語数の平方根程度でしか増えないため、同じ書き手・同じ多様性でも、長い章ほど TTR が下がってしまい、章どうしを比較できません。

MATTR は、一定語数の「窓」を 1 語ずつずらしながら各窓の TTR を求め、その平均をとる指標です（Covington & McFall, 2010）。これにより**文書の長短に依存せず**、章をまたいだ語彙の多様性を公平に比較できます。窓幅は 100 語です。

| 範囲 | 評価 |
|------|------|
| 0.7 以上 | 非常に豊富 |
| 0.6〜0.7 | 豊富 |
| 0.5〜0.6 | 標準的 |
| 0.5 未満 | 単調 |

:::{.note}
窓付き移動平均という性質上、MATTR は素朴な TTR より高め・安定した値域になります。上表の境界は、実用書原稿の実測分布をもとにした目安です。
:::

#### 読解難度

読解難度は、建石由佳・小野芳彦・山田尚勇による評価式（1988 年「日本文の読みやすさの評価式」）でスコア（RS）を算出します。文長や、漢字・ひらがな・カタカナ・アルファベットの「連（同じ文字種の連なり）」の平均長、句読点の比率といった、形態素解析に頼らず決定的に測れる量から導かれる、日本語リーダビリティー研究の代表的な指標です。

**RS は値が大きいほど読みやすい**ことを意味します。漢字の連なりが長いほど、また一文が長いほどスコアは下がります。

| RS スコア | 評価 | 対象読者 |
|-----------|------|----------|
| 60 以上 | Easy | 小中学生向け |
| 40〜60 | Standard | 一般的なビジネス・実用書 |
| 40 未満 | Professional | 専門家・技術者向け |

技術書は元々漢字や専門用語の密度が高く、Standard〜Professional に収まるのが自然です。バンドの境界値は `config/book.yml` で調整できます（後述）。

:::{.note}
metrics の評価基準は、Web 文書や技術書で用いられる目安をもとにしています。対象読者や書籍の性格に合わない場合は、`config/book.yml` で調整できます。
:::

### 章別分量

各章の文字数を棒グラフで示します。基準から大きく外れた章や、読み返しておきたい傾向がある章には印が付きます。

:::{.output}
```text
📚 章別の解析結果

第1章 はじめに              [##########  ] 2,500 文字 ✅ ちょうどよい
第2章 基本の実装            [############] 4,800 文字 💡 やや長い ／ 🤔 表現が単調
第3章 まとめ                [###         ]   600 文字 💡 加筆検討
第4章 内部構造              [#####       ] 3,100 文字 ✅ ちょうどよい ／ 🤔 やや難解

📚 合計 3 章 ／ 平均 2,633 文字
```
:::

記号は 3 種類あり、**分量が先・文章の質が後ろ**の順で並びます。

| 記号 | 系統 | 意味 |
|------|------|------|
| ✅ | 分量 | プリセットの理想的な範囲に収まっている |
| 💡 | 分量 | 加筆や分割を検討してはどうか、という提案 |
| 🤔 | 文章の質 | 気になる点がある |

分量の指摘を 💡 にしているのは、これが「直すべき欠陥」ではなく提案だからです。同じ系統に複数該当したときは `・` で連結し、系統をまたぐときは `／` で並べます。

#### 何も付かない章がある理由

分量の判定は 5 段階で、**両端と真ん中にだけ印を付けます**。

:::{.diagram}
```text
       min 未満   💡 加筆検討
  min 〜 ideal    （無印）
       ideal      ✅ ちょうどよい
  ideal 〜 max    （無印）
       max 超過   💡 やや長い
```
:::

`ideal` は刊行書の実測分布の**真ん中半分**（25〜75 パーセンタイル）から、`min` と `max` は**両裾の 10%**から引いてあります。つまり `ideal` を外れても `min`〜`max` の内側にいるかぎり、それは「刊行書によくある分量」です。

無印は「測り損ねた」でも「どちらでもない」でもなく、**理想の帯からは外れているが、手を入れるほどではない**という判定です。帯の引き方から、およそ 4 章に 1 章がここに入ります（刊行書 128 章での実測）。

すべての章に印を付けることもできますが、そうすると印そのものが目立たなくなり、**本当に手を入れたい章を見つけにくくなります**。手が空いているときに ✅ を増やしにいくのはよいことですが、無印を減らすこと自体を目的にする必要はありません。

自分の章がどちらの無印帯にいるかは、文字数を使用中のプリセットの値と見比べれば分かります。値は `config/book.yml` の `metrics` セクションに書いてあります。たとえば `standard`（`min: 4200` / `ideal: [4800, 8500]` / `max: 9700`）なら、4,746 文字の章は理想の帯まであと 54 文字、9,483 文字の章は「やや長い」まで 217 文字、という位置関係です。

分量判定から除外した章（後述）には、✅ も含めて何も付きません。

文言の種類は次の五つです。分量の三つは `too_short` / `just_right` / `too_long` と対になっています（無印は文言を持たないので、表では判定の位置づけだけを示しています）。

| 文言 | 意味 | 発火条件 | 調整するキー |
|------|------|----------|--------------|
| 加筆検討 | 分量が少なすぎる | 章（節）の文字数がプリセットの `min` 未満 | `metrics.use` / 各プリセット |
| ちょうどよい | 分量がちょうどよい | 章（節）の文字数がプリセットの `ideal` の範囲内 | `metrics.use` / 各プリセット |
| やや長い | 分量が多すぎる | 章（節）の文字数がプリセットの `max` 超過 | `metrics.use` / 各プリセット |
| （無印） | 手を入れるほどではない | `min`〜`ideal` または `ideal`〜`max` の間 | — |
| 表現が単調 | 同じ言い回しの繰り返しが多い | 章の MATTR（語彙多様度）が 0.5 以下 | 文言のみ `metrics.labels.monotonous` |
| やや難解 | 読み進めるのに負荷が高い | 章の読解難度が Professional（RS が `metrics.readability.standard` 未満） | `metrics.readability.standard` |

文言はすべて `metrics.labels` で変更できます。

「表現が単調」「やや難解」は、詳細分析の【語彙多様度】【読解難度】がその章を単調・難解と評価したときに、まったく同じ条件で出ます。一覧と詳細が食い違うことはありません。

ただし、統計として当てにならない章では判定しません。総語数が MATTR の窓幅（既定 100 語）に満たない章は「表現が単調」を、10 文に満たない章は「やや難解」を出しません。`metrics.exclude_chapters` に挙げた章（既定では前書き・付録・後書き）は、分量警告と同じくすべての警告の対象外です。節（`##`）には分量警告のみが付きます。語彙多様度と読解難度は章単位で算出しており、節の分量では母数が足りないためです。

章別リストの直後には、対象が全部で何章あり、1 章あたり平均何文字なのかをまとめた集計行が表示されます。

### 章間のばらつき

ここから先の「章間のばらつき〜漢字レベル」は、`--all` を付けたときに表示される推敲用の参考資料です。

漢字比率と平均文長について、章ごとの値が全体平均からどれだけばらついているかを示します。平均と標準偏差（ばらつきの幅）を表示し、平均から大きく外れた章を「高め／低め（長め／短め）」に分けて挙げます。

:::{.output}
```text
📐 章間のばらつき（本文の章のみ）

- 漢字比率: 平均 27.3% ／ ばらつき ±4.3
  高め: 第33章 35.2%、第32章 34.4%
  低め: 第51章 17.9%、第12章 18.9%
- 平均文長: 平均 61.5字 ／ ばらつき ±19.0
  長め: 第33章 97.8字、第51章 97.0字、第21章 92.4字
  短め: 第12章 37.5字、第13章 41.3字、第22章 41.8字
```
:::

全体の平均だけでは、どの章がほかと違う調子になっているかまでは分かりません。この一覧は、漢字の多い章や文の長い章を見つけ、難しさや読み進めやすさを確かめる入口になります。高い値や低い値が、そのまま欠点を意味するわけではありません。前書き・付録・後書き（`exclude_chapters` の章）と、本文のない章は比較対象から除き、対象が 2 章以上あるときだけ表示します。

### 見直したい長い文

とくに長い文（80 文字以上）の上位を、出現位置（章・行番号）と冒頭の抜粋つきで最大 5 件まで挙げます。

:::{.output}
```text
📝 見直したい長い文（ワースト5）

1. 第 3章 L274（118字）: 索引候補の抽出では見出し語とその読みを判定し…
2. 第21章 L 88（ 92字）: Markdown では段落の途中で改行しても整形時…
```
:::

行番号から、エディタの該当箇所へ移動できます。長い文には、条件や補足が一文へ重なっていることがあります。意味のまとまりで二文に分けられないか、主語と述語が離れすぎていないかを確かめてください。長いこと自体に意味のある文まで、短くする必要はありません。コードブロックや見出し・表などの構造行は対象から除き、本文の文だけを評価します（文字数はインラインコードを除いた本文基準です）。

### 文末表現のリズム

文末表現の内訳（です・ます／体言止め／だ・である／その他）と、同じ文末が続いて単調になっている箇所を示します。

:::{.output}
```text
🎶 文末表現のリズム

- 文末の内訳: です・ます 89%／体言止め 1%／だ・である 0%／その他 11%
- 同じ文末の連続（5 つ以上、多い順）:
    第61章 L538 付近（ます。が32連続）
    第42章 L115 付近（ます。が28連続）
    第61章 L220 付近（ます。が17連続）
    （ほか 70 箇所）
```
:::

同じ文末が長く続く箇所は、説明の運びまで一様になっていることがあります。内訳で全体の傾向を見たうえで、連続箇所を実際に読み、文の組み立てを変えたほうがよいところだけを直します。体言止めや問いかけを数合わせで加える必要はありません。段落の役割に合わせて文を組み直した結果として、自然なリズムになることが大切です。連続は、同じ文末（例 `ます。`）が五つ以上続いた箇所を、先頭の行番号で示します。

:::{.note}
文末の分類は形態素解析を使わない簡易判定です。「です・ます」「だ・である」は確実に判定しますが、「体言止め」は文末がひらがな以外（漢字・カタカナなど）で終わるものを名詞止めと見なす近似です。
:::

### よく使う言葉

本文に頻出する内容語（名詞・固有名詞・形容動詞・動詞・形容詞）を、品詞ラベルつきで上位 15 語まで挙げます。

:::{.output}
```text
🔤 よく使う言葉（内容語 上位15）

 1. 画像      名詞  306回
 2. ファイル  名詞  235回
 3. 生成      名詞  225回
 4. 設定      名詞  173回
 …
10. PDF       名詞  126回
```
:::

頻出語を見ると、章の中心になっている概念や、無意識に重ねている評価語が分かります。専門用語は一貫した呼び方を保つ必要があるため、回数が多くても安易に言い換えません。一方、`便利`・`重要` のような語が繰り返されていれば、具体的な理由へ書き換えられないかを検討できます。品詞ラベルは、製品名などの固有名詞（`Vivliostyle` など）と形容動詞も区別して表示します。助詞・助動詞などの機能語、`する`・`なる`・`ある`・`いる`・`できる` のような汎用動詞、記号は除外します。品詞の判定には形態素解析（MeCab）を使うため、MeCab を導入していない環境ではこのセクションは表示されません（導入状況は `vs doctor` で確認できます）。

:::{.note}
MeCab は単漢字（「章」など）を固有名詞と誤判定することがあるため、単漢字の固有名詞は集計から除いています（`Vivliostyle` のような正しい固有名詞は 2 文字以上なので残ります）。
:::

### 漢字レベル（ルビ候補）

本文の漢字を難易度レベルに分け、対象読者より上位の漢字＝ルビ（振り仮名）を振るべき候補を把握できます。

| レベル | 内容 |
|--------|------|
| 教育 (L0) | 小学校で習う漢字（学年別配当表） |
| 中学 (L1) | 中学で習う常用漢字 |
| 一般 (L2) | JIS第一水準の常用外漢字（人名・地名など） |
| 専門 (L3) | JIS第二水準の漢字（専門的・旧字体） |
| JIS 外 (L4) | JIS X 0208 にない漢字 |

:::{.output}
```text
🈂 漢字レベル（ルビ候補）

- レベル内訳: 教育 91% ／ 中学 9% ／ 一般(L2) 0% ／ 専門(L3) 0%
- 中学漢字（多い順）: 稿(77) 換(70) 索(61) …（ほか 164 字）
- 一般漢字(L2)（多い順）: 揃(10) 雛(9) 梱(8) …
- 専門漢字(L3)（多い順）: 敲(3) 俯(1) 閾(1) …
- 一般・専門漢字の出現箇所:
    敲 → 第22章 L161, 第32章 L178, L191
    閾 → 第33章 L384
```
:::

小学生向けに書く場合、中学以上の漢字にはルビが要ります。稀に出る一般・専門漢字は**出現箇所（章・行）**つきで示されるので、その場所を開いて `{漢字|よみ}` のルビ記法を書き足せます。並びは**初出の章・行順**なので、原稿を頭から順に開いていけば往復せずに直せます（挙げる漢字は 15 字までで、出現の少ない＝ルビが要る漢字から選ばれます）。

## 設定のカスタマイズ

:::{.section-lead}
`config/book.yml` の `metrics` セクションでは、分量や読解難度の基準を、その書籍の構成と読者に合わせて調整できます。
:::

### プリセットの選択

6 種類のプリセットから選択できます。

```yaml
metrics:
  use: standard  # 下の表の名前か relative
```

**選ぶ目安は本全体の本文字数です。**ページ数は判型・余白・書体・図版の量で大きく変わるため、それだけでは決まりません（参考として併記しています）。

| プリセット | 本全体の本文字数 | 参考ページ数 | 章の理想分量 |
|------------|------------------|--------------|--------------|
| compact | 〜3.5 万字 | 20〜50ページ | 1,100〜3,400 文字 |
| handy | 3.5〜6.5 万字 | 50〜100ページ | 3,400〜5,700 文字 |
| standard | 6.5〜9 万字 | 100〜200ページ | 4,800〜8,500 文字 |
| commercial | 9〜15 万字 | 200〜350ページ | 7,800〜14,600 文字 |
| heavy | 15 万字〜 | 350ページ以上 | 11,000〜16,000 文字 |
| author_custom | カスタム | — | 自由に設定 |

数値は刊行済みの技術書を実際に測って引いたものです（章 128 件・節 408 件）。節の基準はプリセット共通で、理想は 1,000〜2,800 文字です。

### 自分の本の中で比べる（relative）

上のプリセットは刊行書の実測に基づく指標です。機能ごとに章を立てるリファレンス寄りの本では、章がどうしても細かくなり、ほとんどの章が「加筆検討」になってしまいます。**章立ての粒度は著者の設計判断**であって、直すべき欠陥ではありません。

そこで `relative` を選ぶと、**その本自身の章の中央値**と比べる形に切り替わります。

```yaml
metrics:
  use: relative
```

| 中央値との比 | 表示 |
|---|---|
| 0.65 倍未満 | 💡 加筆検討 |
| 0.80〜1.20 倍 | ✅ ちょうどよい |
| 1.50 倍超 | 💡 やや長い |

自分の本の中で目立って短い章・長い章だけが挙がるので、章立ての粒度に左右されません。倍率は刊行書 128 章の分布から引いたもので、`min` と `max` は互いに逆数の関係（1 ÷ 1.5 ≒ 0.65）になっています。

:::{.memo}
**基準に入る章・入らない章**

中央値を求めるのは、分量判定の対象となる章だけです（`exclude_chapters` に挙げた前書き・付録・後書きは短いことが多く、混ぜると基準が下へ引っ張られます）。

章が五つに満たない本では、1 章の増減で中央値が動いてしまうため、総本文字数から選んだ絶対のプリセットへ自動的に切り替わります。

節はどちらのモードでも絶対の基準です。節は大きさのばらつきが元々大きく、相対にすると普通の長さの節まで「やや長い」と出てしまうためです。
:::

:::{.memo}
**「本文字数」とは**

コードブロックと Markdown 記法を除いた、地の文の文字数です。`vs metrics` が「文字数: ○○ 文字（本文）」として表示する数字と同じなので、そのまま見比べてプリセットを選べます。

分量をコード込みで数えると、コードが多い章ほど「分量が足りている」と判定されてしまいます。読者が読むのは地の文なので、そちらで測ります。
:::

### 除外章の設定

前書き、付録、後書きなどを分量警告から除外できます。

```yaml
metrics:
  exclude_chapters: [00, 90-98, 99]
```

### カスタム基準の設定

プリセットを上書きして独自の基準を設定することも可能です。

```yaml
metrics:
  use: author_custom
  author_custom:
    chapter:
      min: 2000
      ideal: [4000, 8000]
      max: 12000
    section:
      min: 500
      ideal: [1000, 2000]
      max: 3000
```

### 読解難度バンドの調整

読解難度のラベル（Easy / Standard / Professional）を分ける RS の閾値も調整できます。`easy` 以上を Easy、`standard` 以上を Standard、それ未満を Professional と判定します（既定値はそれぞれ 60 と 40）。

```yaml
metrics:
  readability:
    easy: 60     # この値以上を Easy（やさしい）
    standard: 40 # この値以上を Standard（標準）
```

## まとめ

:::{.section-lead}
metrics が示すのは、原稿を別の角度から読み返すための手がかりです。数値を目標にするのではなく、意図していなかった偏りを見つけたときに、推敲の入口として使います。
:::

本章では、次の指標と使い方を見てきました。

- **原稿全体の把握**: 文字数や文の数を集計し、現在の規模を知る
- **章どうしの比較**: 分量や文章の傾向が大きく異なる章を見つける
- **推敲箇所の発見**: 長い文、文末の連続、頻出語を行番号から確かめる
- **読者に合わせた調整**: 漢字比率や読解難度を、対象読者に照らして読む

最初は `vs metrics` で全体を眺め、気になる章があれば章番号を指定して詳しく見てください。数値に合わせて文章を均すのではなく、そこに表れた違いが著者の意図どおりかを確かめる。その使い方なら、metrics は書き手の感覚を奪わず、原稿を読み直す視点を一つ増やしてくれます。
