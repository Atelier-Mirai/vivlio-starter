# 原稿の分量と難度の計測

:::{.chapter-lead}
書いている最中の原稿は、章ごとの長短や文章の硬さに気づきにくいものです。metrics 機能は、Markdown 原稿の分量・語彙・読解難度を数値で示し、いつもの読み返しとは違う角度から原稿を眺める手がかりを与えます。本章では、数値の意味と、推敲へつなげるときの読み方を説明します。
:::

## vs metrics とは

:::{.section-lead}
`vs metrics` は、執筆中の原稿を統計的に分析するコマンドです。漢字比率や読解難度などを章ごとに計算し、章どうしの違いや、全体から外れている章を見つけやすくします。
:::

数値だけで文章の良し悪しが決まるわけではありません。短い章にも役割があり、専門書には難しい語が必要です。数値は原稿の採点ではなく、「ここは意図した偏りだろうか」と確かめるための材料として使います。確認できる項目は次のとおりです。

- **章別分量**: 各章の文字数と、基準から外れた章の印
- **基本統計**: 文字数、行数、文の数、読点の数
- **語彙難度**: 漢字比率と平均語長
- **語彙多様度**: 同じ言葉の繰り返しの度合い（MATTR）
- **読解難度**: 建石式リーダビリティー（RS）による読みやすさの目安

## 基本的な使い方

:::{.section-lead}
引数なしで全章の概要を表示し、気になった章は番号を指定して節まで詳しく調べます。
:::

```bash
# catalog.yml に載っている全章の概要
vs metrics

# 11-intro だけを節まで詳しく
vs metrics 11

# 範囲と個別指定の組み合わせ
vs metrics 11-13 15
```

章を指定すると、その章は節（`##`）まで展開して表示します。章は、ファイル名・番号・範囲のどれでも指定できます。書き方は @ch-chapter-management の章の @pageref:chapter-targets を参照してください。分冊の本では、`vs metrics upper` のように巻の `id` を指定できます。

### 全章を節まで展開する — `--sections`

すべての章を節まで展開し、節ごとの文字数を表示します。

```bash
vs metrics --sections
```

### 印の付いた章だけを表示する — `--warn`

💡 または 🤔 の印が付いた章（節に印がある章を含む）だけを、節まで展開して表示します。分量が基準から外れた章や、表現が単調・やや難解と評価された章を素早く特定できます。

```bash
vs metrics --warn
```

## 実行結果の見方

:::{.section-lead}
画面には、章別分量、基本情報と文構造、詳細分析の順に表示されます。ここでも、その順に見ていきます。
:::

### 章別分量

各章の文字数を棒グラフで示し、基準から外れた章と、理想的な範囲に収まった章に印を付けます。次は `compact` のプリセットを選んだ本の例です。

:::{.output}
```text
📚 章別の解析結果

第11章 はじめに                [######......]  2,500 文字 ✅ ちょうどよい
第12章 基本の実装              [############]  4,800 文字 💡 やや長い ／ 🤔 表現が単調
第13章 まとめ                  [##..........]    600 文字 💡 加筆検討
第14章 内部構造                [########....]  3,100 文字 ✅ ちょうどよい ／ 🤔 やや難解

📚 合計 4 章 ／ 平均 2,750 文字
```
:::

文字数は、コードと Markdown 記法を除いた**本文**（地の文）で数えます。コードを含めて数えると、コードの多い章ほど分量が足りていると判定され、読者が読む文章の量を見誤るためです。最後の行には、章の数と 1 章あたりの平均文字数を表示します。分冊の本で巻を指定せずに実行したときは、巻ごとの章の数と文字数も表示します。

**章別分量の印と表示条件**

| 印と文言 | 系統 | 表示条件 |
|------|------|----------|
| ✅ ちょうどよい | 分量 | 文字数がプリセットの `ideal` の範囲内 |
| 💡 加筆検討 | 分量 | 文字数がプリセットの `min` 未満 |
| 💡 やや長い | 分量 | 文字数がプリセットの `max` を超える |
| 🤔 表現が単調 | 文章の質 | 詳細分析の語彙多様度が「単調」 |
| 🤔 やや難解 | 文章の質 | 詳細分析の読解難度が Professional |

💡 は直すべき欠陥ではなく、加筆や分割を検討する提案です。印が複数付くときは、分量の印を先に、文章の質の印を後に置き、`／` で区切ります。同じ系統の指摘が複数あるときは `・` でつなぎます。

表現が単調とやや難解は、詳細分析の評価と同じ条件で判定します。印に添える文言は、`metrics.labels` で変更できます。

節（`##`）に付くのは、分量の印だけです。語彙多様度と読解難度は、節では語や文の数が足りないため、章単位で判定します。章でも、総語数が 100 語に満たなければ「表現が単調」を、文が 10 に満たなければ「やや難解」を付けません。`metrics.exclude_chapters` に挙げた章（既定では前書き・付録・後書き）には、✅ を含めて印を一つも付けません。

#### 印の付かない章

分量の判定は 5 段階で、印が付くのは両端と真ん中だけです。

:::{.diagram}
```text
       min 未満   💡 加筆検討
  min 〜 ideal    （印なし）
       ideal      ✅ ちょうどよい
  ideal 〜 max    （印なし）
       max 超過   💡 やや長い
```
:::

プリセットの `ideal` は、刊行済みの技術書の章の分量のうち、真ん中の半分にあたる範囲です。`min` と `max` は、短いほう・長いほうの 1 割を分ける値です。印のない章は、理想的な範囲からは外れていても、刊行書によくある分量に収まっています。手を入れるほどではないという判定なので、印のない章を減らす必要はありません。

たとえば `standard`（`min: 4200`／`ideal: [4800, 8500]`／`max: 9700`）では、4,500 文字の章に印は付きません。プリセットの値は、`config/book.yml` の `metrics` セクションで確かめられます。

### 基本情報と文構造

本全体の文字数・行数と、文の組み立てを表示します。次は本書の例です。

:::{.output}
```text
📊 文章統計 — 基本情報
- 文字数: 142,893 文字（本文。ほかに コード 80,256 文字、記法 12,235 文字）
- 行数: 9,360 行

📊 文章統計 — 文構造
- 文の数: 3,182 文（平均 48.6 文字/文）
- 節の数: 3,333 節（平均 46.3 文字/節）
- 読点数: 3,307 個
```
:::

文字数は本文の文字数で、除いたコードと記法の文字数を括弧の中に添えます。行数は、コードを含めた原稿ファイルの行数です。文構造の「節」は、本文を読点で区切った一つ一つの区間を指し、見出しの節とは別のものです。

### 詳細分析

語彙難度、語彙多様度、読解難度を表示します。どれも本文だけで測ります。コードの英数字や記号を含めると、指標が実態より平易な側へずれるためです。

:::{.output}
```text
📈 詳細分析

【語彙難度】
- 漢字比率: 適切（27.7%） — 理想的な範囲 25〜35%
- 平均語長: やや平易（1.8 文字） — 理想的な範囲 2.0〜2.5 文字
- 文字種構成: 漢字 27.7% ／ ひらがな 37.4% ／ カタカナ 9.9% ／ 英字 10.7% ／ その他 14.3%

【語彙多様度】
- 使用語彙数: 4,490 語（異なり語）／ 総語数 82,862 語
- 語彙の豊かさ: 標準的（MATTR: 0.57）
  - 評価基準: 0.7 以上=非常に豊富、0.6〜0.7=豊富、0.5〜0.6=標準的、0.5 未満=単調

【読解難度】
- 評価: Standard（一般的なビジネス・実用書）
- スコア: 51.1 点
```
:::

#### 漢字比率

:::{.text-table}
本文に占める漢字の割合から、文章の硬さを見ます。技術書では 25〜35% を理想的な範囲としていますが、読者層や扱う分野によって適切な値は変わります。範囲は `metrics.kanji_ratio` で変更できます（@pageref:metrics-vocabulary-config）。

| 範囲 | 評価 |
|------|------|
| 20% 未満 | 平易 |
| 20〜25% | やや平易 |
| 25〜35% | 適切 |
| 35〜45% | やや難解 |
| 45% 超 | 難解 |
:::

#### 平均語長

本文を語に区切ったときの、1 語あたりの平均文字数です。熟語や長いカタカナ語が多いほど大きくなります。理想的な範囲は 2.0〜2.5 文字で、1.5 文字未満を平易、3.0 文字超を難解と評価します。範囲は `metrics.word_length` で変更できます。

#### 文字種構成

本文を、漢字・ひらがな・カタカナ・英字・その他（数字・記号・句読点）に分けた割合です。漢字の割合は、漢字比率と同じ値です。カタカナや英字の割合が高いほど、外来語や専門用語が多いことを示します。技術書では自然に高くなりますが、初学者向けの入門書なら、カタカナ語を言い換えたり補足したりする手がかりになります。

#### 語彙多様度（MATTR）

語彙多様度は、MATTR（Moving-Average Type-Token Ratio、移動平均 TTR）で測ります。値が高いほど優れているという指標ではなく、同じ言葉へ頼りすぎていないかを見るための目安です。

:::{.text-table}
TTR は、異なり語数を総語数で割った値です。文章が長いほど同じ語が再び現れるため、TTR は低くなります。そのため、長さの違う章どうしを TTR で比べることはできません。MATTR は、100 語の範囲を 1 語ずつずらしながら各範囲の TTR を求め、その平均をとります（Covington & McFall, 2010）。章の長さに左右されないので、章どうしを比べられます。

| 範囲 | 評価 |
|------|------|
| 0.7 以上 | 非常に豊富 |
| 0.6〜0.7 | 豊富 |
| 0.5〜0.6 | 標準的 |
| 0.5 未満 | 単調 |
:::

#### 読解難度

読解難度は、建石由佳・小野芳彦・山田尚勇による評価式（1988 年「日本文の読みやすさの評価式」）でスコア（RS）を求めます。文の長さ、漢字・ひらがな・カタカナ・英字がそれぞれ続く長さ、句点あたりの読点の数から算出する、日本語の読みやすさを測る代表的な指標です。

RS は、値が大きいほど読みやすいことを示します。漢字が長く続くほど、また一文が長いほど、スコアは下がります。

| RS スコア | 評価 | 表示される説明 |
|-----------|------|----------|
| 60 以上 | Easy | 小中学生向け |
| 40〜60 | Standard | 一般的なビジネス・実用書 |
| 40 未満 | Professional | やや難解 |

技術書は漢字や専門用語が多いので、Standard〜Professional に収まるのが自然です。評価の境界の値は `metrics.readability` で変更できます（@pageref:metrics-readability-config）。

## book.yml で調整する

:::{.section-lead}
`config/book.yml` の `metrics` セクションで、分量や読解難度の基準を、本の構成と読者に合わせて調整できます。
:::

### 本の規模に合うプリセットを選ぶ — `use`

分量の基準は、プリセットから選びます。

```yaml
metrics:
  use: standard  # 下の表の名前か relative
```

選ぶ目安は、本全体の本文字数です。`vs metrics` の基本情報に「文字数: ○○ 文字（本文。…）」と表示される数で、そのまま見比べて選べます。ページ数は判型・余白・書体・図版の量で大きく変わるため、参考として併記しています。

| プリセット | 本全体の本文字数 | 参考ページ数 | 章の理想分量 |
|------------|------------------|--------------|--------------|
| compact | 〜3.5 万字 | 20〜50ページ | 1,100〜3,400 文字 |
| handy | 3.5〜6.5 万字 | 50〜100ページ | 3,400〜5,700 文字 |
| standard | 6.5〜9 万字 | 100〜200ページ | 4,800〜8,500 文字 |
| commercial | 9〜15 万字 | 200〜350ページ | 7,800〜14,600 文字 |
| heavy | 15 万字〜 | 350ページ以上 | 11,000〜16,000 文字 |
| author_custom | — | — | 自由に設定 |

数値は、刊行済みの技術書を実際に測って定めたものです。節の基準はプリセット共通で、理想は 1,000〜2,800 文字です。

### 自分の本の中で比べる — `relative`

機能ごとに章を立てるリファレンス寄りの本では、章が細かくなり、プリセットで判定するとほとんどの章が「加筆検討」になります。章立ての粒度は著者が設計で決めることで、直すべき欠陥ではありません。

:::{.text-table}
`relative` を選ぶと、その本自身の章の文字数の中央値と比べます。

```yaml
metrics:
  use: relative
```

| 中央値との比 | 表示 |
|---|---|
| 0.65 倍未満 | 💡 加筆検討 |
| 0.80〜1.20 倍 | ✅ ちょうどよい |
| 1.50 倍超 | 💡 やや長い |

本の中で目立って短い章・長い章だけに印が付くので、章立ての粒度に左右されません。
:::

:::{.memo}
**中央値の求め方**

中央値は、分量判定の対象となる章だけで求めます。`exclude_chapters` に挙げた前書き・付録・後書きは短いことが多く、含めると基準が下がるためです。

判定の対象となる章が五つに満たない本では、1 章の増減で中央値が大きく動きます。そのため、本全体の本文字数から選んだプリセットで判定します。

節は、`relative` でもプリセット共通の基準で判定します。節は分量のばらつきが大きく、中央値と比べると、普通の長さの節まで「やや長い」になるためです。
:::

### 基準を自分で決める — `author_custom`

`use: author_custom` を選ぶと、`author_custom` に書いた値で判定します。

```yaml
metrics:
  use: author_custom
  author_custom:
    chapter:
      min: 2000
      ideal: [4000, 8000]
      max: 12000
    section:
      min: 500
      ideal: [1000, 2000]
      max: 3000
```

### 判定から除外する章 — `exclude_chapters`

前書き・付録・後書きのように、短いことに意味がある章は判定から除外できます。挙げた章も章別分量には表示され、基本情報と詳細分析の集計にも含まれますが、印は付きません。

```yaml
metrics:
  exclude_chapters: [00, 90-98, 99]
```

### 語彙難度の基準 — `kanji_ratio`・`word_length` @metrics-vocabulary-config

漢字比率と平均語長の評価の範囲を変更できます。分量と同じく、`min`・`ideal`・`max` で書きます。

```yaml
metrics:
  kanji_ratio: { min: 20, ideal: [25, 35], max: 45 }
  word_length: { min: 1.5, ideal: [2.0, 2.5], max: 3.0 }
```

`min` 未満は平易、`ideal` の範囲内は適切、`max` 超は難解と評価します。対象読者が小中学生なら範囲を下げ、専門家なら上げます。

### 読解難度の境界 — `readability` @metrics-readability-config

読解難度の評価（Easy／Standard／Professional）を分ける RS の値を変更できます。`easy` 以上を Easy、`standard` 以上を Standard、それ未満を Professional と評価します。

```yaml
metrics:
  readability:
    easy: 60     # この値以上を Easy
    standard: 40 # この値以上を Standard
```

「🤔 やや難解」の付く章が多い技術書では、`standard` を 35 程度へ下げます。
