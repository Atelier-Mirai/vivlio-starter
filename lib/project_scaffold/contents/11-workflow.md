# 執筆ワークフローとクイックスタート

:::{.chapter-lead}
Vivlio Starter は「CSS 組版」という方法で本を作ります。本章では、まずそれがどのような方法なのかを押さえたうえで、「プロジェクト作成 → 執筆 → 整える → ビルド → 入稿・配布」という5つのステップを俯瞰します。そのうえで、実際にインストールから最初の PDF を出すところまでを一緒にたどります。各ステップの詳細は、対応する章を参照してください。
:::

## CSS 組版という方法

本を作る方法は一つではありません。目的や好みに応じて、いくつもの道具が使われてきました。

- **ワープロソフト**（Word・Pages） — 画面で見たとおりが紙になります。手軽な反面、長い本では図表の位置や改ページが崩れやすくなります
- **DTP ソフト**（InDesign） — 紙面を自由に設計でき、商業出版の現場で使われています。習得にも費用にも相応の負担があります
- **組版システム**（LaTeX） — 数式と相互参照に強く、学術書で長く使われてきました。独自の記法を覚える必要があります
- **CSS 組版**（Vivliostyle） — Web の技術で紙面を設計します。原稿は Markdown で書けます

Vivlio Starter が採っているのは、いちばん下の **CSS 組版**です。

### Web の技術で、紙の本を組む

CSS は本来、Web ページの見た目——文字の大きさ、色、余白——を指定するための言語です。ところが Web ページには「ページ」がありません。画面をスクロールすれば、文章はどこまでも続いていきます。

一方、紙の本には終わりがあります。決まった大きさの紙に文字を流し込み、収まらなくなったら次のページへ送る。ページの下にノンブル（ページ番号）を、上に柱（章題）を置く。脚注は、参照した行と同じページの下に置く。

こうした「紙のための指定」を CSS に加える仕様が、Web の標準化団体 W3C によって定められています。それを解釈して実際に紙面を組み上げるのが **CSS 組版エンジン**で、Vivlio Starter は日本発のエンジン **Vivliostyle** をコアに据えています。

### 原稿が本になるまで

Vivlio Starter の中では、原稿が **Markdown → HTML → CSS 組版 → 出力** という順に姿を変えていきます。

- **Markdown（あなたが書く）** — 見出しや箇条書きを簡単な記号で書く記法です。あなたが直接触れるのはここだけです
- **HTML（構造に変換）** — 「ここは見出し」「ここは本文」という構造を持った形式へ変換されます
- **CSS 組版（紙面を設計）** — その構造に、判型・余白・書体・ノンブルといった紙面の設計を当てはめます
- **出力（読者に届く形）** — 閲覧用 PDF・印刷入稿用 PDF・EPUB・Kindle が生成されます

**一つの原稿から複数の形式を出せる**のは、この流れを採っているからです。紙の本と電子書籍とで、原稿を書き分ける必要はありません。

### Vivlio Starter は、その全部をまとめる道具

Vivliostyle は組版エンジンですから、原稿の前処理や目次の生成、表紙の作成までは引き受けません。そこを埋めて、一冊の本ができるまでを一続きにするのが Vivlio Starter です。

Vivlio Starter は **CLI ツール**——ターミナルにコマンドを打ち込んで使う道具です。ボタンの並んだ画面はありませんが、そのぶん手順が文字として残り、同じ操作を何度でも正確に繰り返せます。本書で何度も登場する `vs` が、そのコマンドです。

```bash
vs new mybook   # プロジェクトを作る
vs build        # 本を組み上げる
```

:::{.memo}
**CLI と GUI**

CLI は Command Line Interface の略で、文字で命令を伝える方式です。対してマウスで操作する画面を GUI（Graphical User Interface）と呼びます。CLI は最初こそ取っつきにくいものの、「書き直してはビルドし直す」を何度も繰り返す書籍制作とは相性のよい方式です。
:::

## 各ステップの概要

### ① プロジェクト作成

`vs new` コマンドで書籍プロジェクトの雛形を生成します。書籍名・著者名などを対話形式で入力すると、必要なファイル一式が自動的に用意されます。さらに内部で `vs doctor --fix` が自動的に呼び出され、Vivliostyle や ImageMagick など、書籍制作に必要な外部ツールが一括でセットアップされます。

```bash
vs new mybook   # 雛形生成 + 必要ツールの自動セットアップ
cd mybook
```

**参照:** 「インストール詳細」「新規プロジェクトの作成（vs new）」「環境診断（vs doctor）」

### ② 執筆

`contents/` ディレクトリ内の Markdown ファイルに原稿を書きます。章ファイルの追加・削除・番号の振り直しには専用のコマンドが用意されており、ファイルの手動操作は不要です。

```bash
vs create 10-intro   # 新しい章を追加
vs build  10-intro   # その章だけ素早くビルドして確認
```

章単位でビルドすると、全体を組版するより速く結果を確認できます。書きながら `vs build <章名>` でこまめに確認するのが、Vivlio Starter での執筆スタイルです。

**参照:** 「Markdown 執筆チュートリアル」「章の管理」

### ③ 整える

原稿が一段落したら、文章の品質を確認します。

`vs lint` は textlint を使って表記揺れや冗長表現を検出します。`vs metrics` は文字数・漢字比率・語彙多様度などを数値化し、読みやすさの目安を示します。

```bash
vs lint       # 文章を校正する
vs metrics    # 原稿の統計を確認する
```

**②と③は何度でも繰り返せます。** 書いては整え、また書く——この往復が、読みやすい技術書を仕上げる近道です。

**参照:** 「文章校正（vs lint）」「Metrics」

### ④ ビルド

執筆が完了したら、`vs build` で書籍全体を組版します。閲覧用 PDF・印刷入稿用 PDF・EPUB・Kindle の四形式を、一度のコマンドで生成できます。

```bash
vs build   # 書籍全体をビルドする
```

カバー画像がまだ生成されていない場合、`vs build` が内部で自動的に `vs cover` を呼び出すため、別途実行する必要はありません。カバーのデザインを細かく調整したいときや、カバーだけを単独で生成・確認したい場合には `vs cover` を直接実行します。

```bash
vs cover   # カバーを個別に生成・調整したい場合
```

出力形式は `config/book.yml` の `output.targets` で指定します。技術書典向けには `pdf`、印刷所入稿には `print_pdf`（トンボ・塗り足し付き）、電子書籍配信には `epub` または `kindle` を選びます。

**参照:** 「ビルド（vs build）」「カバー画像の生成」「config/book.yml リファレンス」

### ⑤ 入稿・配布

生成された PDFやEPUBなどを、頒布チャネルに合わせて提出・アップロードします。

| 頒布先 | 使用するファイル |
| :--- | :--- |
| 技術書典・ダウンロード販売・PDF 配布 | `pdf`（閲覧用） |
| コミケ（印刷所入稿） | `print_pdf`（トンボ付き） |
| Apple Books, Kobo | `epub`|
| Kindle | `kindle`（専用） |

## やってみる — 最初の PDF ができるまで

:::{.section-lead}
ここからは実際に手を動かします。インストールから最初の PDF が開くまで、コマンドをいくつか入力するだけです。早速、一緒に取り組んで参りましょう。
:::

### Ruby を用意する

Vivlio Starter は Ruby で動作します。まず、入っているかどうかを確かめます。

```bash
ruby -v
```

`ruby 4.0.6` のようにバージョンが表示されれば準備完了です。次の「Vivlio Starter をインストールする」へ進んでください。

表示されなければ、同梱のスクリプトで一式を導入します。Xcode コマンドラインツール・Homebrew・rbenv・Ruby 本体・bundler までを自動で揃えてくれます。

```bash
bin/install-ruby.zsh
```

:::{.column}
**💡 ターミナルの開き方（macOS）**

- Spotlight から: `Cmd + Space` →「Terminal」と入力 → `Enter`
- Finder から: アプリケーション → ユーティリティ → Terminal.app
:::

完了したらシェルを読み込み直し、もう一度バージョンを確認します。

```bash
exec zsh -l
ruby -v   # ruby 4.0.2 (2026-03-16 ...) と表示されれば OK
```

macOS 以外の環境へ入れたい方や、何が導入されるのかを把握しておきたい方は、付録「インストール詳細」を参照してください。将来 Ruby を新しくするときも、同じスクリプトにバージョンを渡すだけです（`bin/install-ruby.zsh -v 4.1.0`）。

### Vivlio Starter をインストールする

Ruby の準備ができたら、gem を入れます。

```bash
gem install vivlio-starter
```

### プロジェクトを作る

新しい書籍プロジェクトを作成します。`mybook` はプロジェクト名なので、お好きな名前に変えてください。

```bash
vs new mybook
cd mybook
```

雛形が一式生成されます。

```
mybook/
  contents/          ← 原稿（Markdownファイル）
  images/            ← 画像ファイル
  covers/            ← 表紙・裏表紙用の画像ファイル
  data/              ← 書籍内で展開したいQueryStream用データ（YAML形式）
  templates/         ← 各種雛形ファイル置き場
  sources/           ← 執筆資料やPDFファイル置き場
  codes/             ← 書籍内で掲載するサンプルコード
  stylesheets/       ← CSSスタイルシート
  config/
    book.yml         ← 書籍の設定ファイル
    catalog.yml      ← 章構成
    page_presets.yml ← ページレイアウト設定
    index_glossary_terms.yml     ← 用語集
  package.json
  Gemfile
```

まずは `contents/` に注目してください。ここに原稿となる Markdown ファイルが収まっています。サンプルの章が最初から入っており、どんな Markdown を書けばどんな紙面になるのかを、実物を見ながら確かめられます。各ディレクトリの役割やオプションの詳細は、次章「新規プロジェクトの作成（vs new）」で説明します。

### はじめてのビルド

さっそく PDF を生成してみましょう。

```bash
vs build
```

しばらく待つと、`mybook_v0.1.0.pdf` が生成されて自動的に開きます。これがあなたの最初の技術書です！

### 新しい章を作る

続けて、自分の章を追加してみます。

```bash
vs create 10-awesome
```

`contents/10-awesome.md` と `images/10-awesome/` が生成されます。ファイルを開いて自由に書いたら、その章だけをビルドして確認します。

```bash
vs build 10-awesome
```

章を指定すると、全体を組むより速く結果を見られます。執筆中はこれを繰り返し、すべて書き終わったら最後にもう一度 `vs build` を実行してください。表紙・目次・索引・奥付まで揃った、完成した本が出来上がります。

```bash
vs build
```

## コマンド早見表

たくさんのコマンドがありますが、**全部を覚える必要はありません**。まずは各ステップの主役だけで十分です。

| ステップ | 主なコマンド | 内容 |
| :--- | :--- | :--- |
| ① プロジェクト作成 | `vs new` | 雛形生成＋必要ツール自動セットアップ |
| ② 執筆 | `vs create` | 章ファイルを追加 |
| | `vs build <章名>` | 章単位で素早く確認 |
| ③ 整える | `vs lint` | 文章を校正 |
| | `vs metrics` | 原稿の統計を確認 |
| ④ ビルド | `vs build` | 書籍全体をビルド（カバー未生成時は自動生成） |
| | `vs cover` | カバーを個別に生成・調整したい場合 |
| ⑤ 入稿・配布 | — | 生成済みファイルを提出 |

これ以外にも、章の削除や番号の振り直し、索引の作成、PDF の圧縮といったコマンドが揃っています。全体は `vs --help`、個々の使い方は `vs <コマンド> --help` で確認できます。

```bash
vs --help
vs build --help
```
