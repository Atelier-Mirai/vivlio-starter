# 執筆ワークフローとクイックスタート

:::{.chapter-lead}
Vivlio Starter は、「CSS 組版」という方法で本を作ります。本章では、その仕組みを入り口にして、「プロジェクト作成 → 執筆 → 整える → ビルド → 入稿・配布」という五つのステップを見渡します。後半では、インストールから最初の PDF を開くところまで、実際のコマンドをたどります。まずは本づくりの全体像を掴み、細かな機能は必要になったときに対応する章で確かめていきましょう。
:::

## CSS 組版という方法

本を作る道具には、それぞれ得意なことがあります。原稿の長さや紙面の複雑さ、どの形式で届けたいかに応じて、これまでさまざまな方法が使われてきました。

- **ワープロソフト**（Word・Pages） — 画面で確認しながら、そのまま紙面を作れます。始めやすい一方、原稿が長くなると、図表の位置や改ページの調整に手間がかかります。
- **DTP ソフト**（InDesign） — 紙面を細部まで設計でき、商業出版の現場でも広く使われています。使いこなすまでの学習と、導入費用が必要です。
- **組版システム**（LaTeX） — 数式や相互参照に強く、学術書の制作を長く支えてきました。利用するには、独自の記法を学びます。
- **CSS 組版**（Vivliostyle） — Web の技術を使って紙面を設計します。原稿には、読み書きしやすい Markdown を使えます。

Vivlio Starter が採用しているのは、最後の **CSS 組版**です。Web 制作で培われた技術を、本のための組版へつなげています。

### Web の技術で、紙の本を組む

CSS は、Web ページの文字の大きさや色、余白などを指定するために生まれた言語です。Web ページには、紙のような決まった境界がありません。画面をスクロールするかぎり、文章は下へ続いていきます。

紙の本では、決まった大きさのページに文字を収め、入りきらない分を次のページへ送ります。ページの下にはノンブル（ページ番号）を、上には柱（章題）を置き、脚注は参照箇所と同じページに配置します。画面では意識しなかった「ページの境界」が、紙面設計の基準になります。

こうした紙面固有の指定を CSS で表すための仕様は、Web の標準化団体 W3C によって定められています。その指定を解釈し、実際のページへ組み上げるソフトウェアが **CSS 組版エンジン**です。Vivlio Starter は、日本発の組版エンジン **Vivliostyle** を中核に据えています。

### 原稿が本になるまで

Vivlio Starter に渡した原稿は、**Markdown → HTML → CSS 組版 → 出力** の順に変換されます。執筆者が書く内容と、紙面を整える仕組みを分けることが、この流れの大切なところです。

- **Markdown（原稿を書く）** — 見出しや箇条書きを、簡単な記号で表す記法です。執筆中に主に触れるのは、この形式です。
- **HTML（構造を与える）** — Markdown を、「ここは見出し」「ここは本文」と区別できる構造へ変換します。
- **CSS 組版（紙面を設計する）** — HTML の構造に、判型・余白・書体・ノンブルといった紙面の設計を適用します。
- **出力（配布形式に仕上げる）** — 閲覧用 PDF・印刷入稿用 PDF・EPUB・Kindle を生成します。

原稿と紙面設計が分かれているため、**一つの原稿から複数の形式を出力できます**。紙の本と電子書籍のために、同じ内容を別々に書き直す必要はありません。原稿に手を入れれば、その変更をどの形式にも反映できます。

### Vivlio Starter は、その全部をまとめる道具

Vivliostyle が担うのは、HTML と CSS から紙面を組む部分です。原稿の前処理、目次や索引の生成、表紙の作成、用途ごとのファイル出力には、別の処理が必要になります。それらをまとめ、一冊の本ができるまでの流れをつなぐのが Vivlio Starter です。

Vivlio Starter は、ターミナルへコマンドを入力して使う **CLI ツール**です。操作画面のボタンを押す代わりに、実行した手順が文字として残ります。同じ本を何度組み直しても同じ操作を再現できるので、修正と確認を重ねる書籍制作に向いています。本書で繰り返し使う `vs` が、その入り口となるコマンドです。

```bash
vs new mybook   # プロジェクトを作る
vs build        # 本を組み上げる
```

:::{.memo}
**CLI と GUI**

CLI は Command Line Interface の略で、文字で操作を伝える方式です。対して、マウスやタッチ操作を中心とする画面は GUI（Graphical User Interface）と呼ばれます。CLI は見慣れない印象を持たれがちですが、一度入力したコマンドを再利用できます。「書き直して、もう一度ビルドする」という書籍制作の日常的な作業を、短い操作で繰り返せます。
:::

## 各ステップの概要

### (1) プロジェクト作成

`vs new` コマンドで、書籍プロジェクトの雛形を生成します。画面に表示される質問に沿って書籍名や著者名を入力すると、原稿・画像・設定を置くためのファイル一式が作られます。続いて `vs doctor --fix` が実行され、Vivliostyle や ImageMagick など、書籍制作に必要な外部ツールもまとめてセットアップされます。

```bash
vs new mybook   # 雛形生成 + 必要ツールの自動セットアップ
cd mybook
```

**参照:** @chapref:ch-install、@chapref:ch-new、@chapref:ch-doctor

### (2) 執筆

原稿は、`contents/` ディレクトリにある Markdown ファイルへ書きます。章の追加・削除・番号の振り直しには専用のコマンドがあり、章立てを変えたときも関連する設定が一緒に更新されます。

```bash
vs create 10-intro   # 新しい章を追加
vs build  10-intro   # その章だけ素早くビルドして確認
```

章単位のビルドなら、書籍全体を組版するより短い時間で結果を確認できます。数段落を書いたところで紙面を開き、見出しの位置や図の大きさを確かめる。この短い往復を重ねると、文章と紙面を同時に育てていけます。

**参照:** @chapref:ch-markdown-tutorial、@chapref:ch-chapter-management

### (3) 整える

原稿がある程度まとまったら、読み手の視点に切り替えて文章を整えます。内容を理解している書き手ほど見落としやすい表記の揺れや、章ごとの読み味の違いを、専用のコマンドで確かめられます。

`vs lint` は textlint を使い、表記揺れや冗長な表現の候補を検出します。`vs metrics` は文字数・漢字比率・語彙多様度などを数値化し、章どうしを見比べる手がかりを示します。どちらも文章を自動で完成させる機能ではなく、著者が推敲するための判断材料です。

```bash
vs lint       # 文章を校正する
vs metrics    # 原稿の統計を確認する
```

**(2) の執筆と (3) の推敲は、何度でも往復できます。** 書いている最中に校正してもよく、章を書き終えてからまとめて確かめても構いません。原稿に合った間隔で確認を重ねるうちに、書籍全体の調子が揃っていきます。

**参照:** @chapref:ch-lint、@chapref:ch-metrics

### (4) ビルド

原稿が揃ったら、`vs build` で書籍全体を組版します。表紙・目次・索引・奥付までを含め、各章がこの段階で一冊につながります。設定に応じて、閲覧用 PDF・印刷入稿用 PDF・EPUB・Kindle の四形式を一度のコマンドで生成できます。

```bash
vs build   # 書籍全体をビルドする
```

カバー画像がまだ生成されていない場合、`vs build` が内部で自動的に `vs cover` を呼び出すため、別途実行する必要はありません。カバーのデザインを細かく調整したいときや、カバーだけを単独で生成・確認したい場合には `vs cover` を直接実行します。

```bash
vs cover   # カバーを個別に生成・調整したい場合
```

出力形式は `config/book.yml` の `output.targets` で指定します。技術書典向けには `pdf`、印刷所入稿には `print_pdf`（トンボ・塗り足し付き）、電子書籍配信には `epub` または `kindle` を選びます。

**参照:** @chapref:ch-build、@chapref:ch-cover、@chapref:ch-book-yml

### (5) 入稿・配布

最後に、生成した PDF や EPUB を、頒布先の仕様に合わせて提出・アップロードします。同じ原稿から作った本でも、画面で読む PDF、印刷所へ渡す PDF、電子書店へ登録するデータでは、適した形式が異なります。

| 頒布先 | 使用するファイル |
| :--- | :--- |
| 技術書典・ダウンロード販売・PDF 配布 | `pdf`（閲覧用） |
| コミケ（印刷所入稿） | `print_pdf`（トンボ付き） |
| Apple Books, Kobo | `epub`|
| Kindle | `kindle`（専用） |

## やってみる — 最初の PDF ができるまで

:::{.section-lead}
ここからは、実際に小さな書籍プロジェクトを作ります。インストールから最初の PDF が開くまでに使うコマンドは、まだ数えるほどです。意味を一つずつ確かめながら進めれば、先程見た全体の流れが手元のファイルとして見えてきます。
:::

### Ruby を用意する

Vivlio Starter は Ruby で動作します。最初に、現在の環境で Ruby を使えるか確かめます。

```bash
ruby -v
```

`ruby 4.0.7` のようにバージョンが表示されれば準備完了です。次の「Vivlio Starter をインストールする」へ進んでください。

バージョンが表示されなければ、同梱のスクリプトで必要な環境を導入します。Xcode コマンドラインツール・Homebrew・rbenv・Ruby 本体・bundler が順にセットアップされます。

```bash
bin/install-ruby.zsh
```

:::{.memo}
**ターミナルの開き方（macOS）**

- Spotlight から: `Cmd + Space` →「Terminal」と入力 → `Enter`
- Finder から: アプリケーション → ユーティリティ → Terminal.app
:::

完了したらシェルを読み込み直し、もう一度バージョンを確認します。

```bash
exec zsh -l
ruby -v
```

:::{.output}
```text
ruby 4.0.7 (2026-09-15 revision 229531a6cf) +PRISM [arm64-darwin27]
```
:::

macOS 以外の環境へ入れたい方や、何が導入されるのかを把握しておきたい方は、@chapref:ch-install を参照してください。将来 Ruby を新しくするときも、同じスクリプトにバージョンを渡すだけです（`bin/install-ruby.zsh -v 4.1.0`）。

### Vivlio Starter をインストールする

Ruby の準備ができたら、gem を入れます。

```bash
gem install vivlio-starter
```

### プロジェクトを作る

Ruby と gem の準備ができたので、新しい書籍プロジェクトを作成します。`mybook` はプロジェクト名です。これから書く本に合わせた名前へ変更できます。

```bash
vs new mybook
cd mybook
```

雛形が一式生成されます。

```
mybook/
  contents/          ← 原稿（Markdownファイル）
  images/            ← 画像ファイル
  covers/            ← 表紙・裏表紙用の画像ファイル
  data/              ← 書籍内で展開したいQueryStream用データ（YAML形式）
  templates/         ← 各種雛形ファイル置き場
  sources/           ← 執筆資料やPDFファイル置き場
  codes/             ← 書籍内で掲載するサンプルコード
  stylesheets/       ← CSSスタイルシート
  config/
    book.yml         ← 書籍の設定ファイル
    catalog.yml      ← 章構成
    page_presets.yml ← ページレイアウト設定
    index_glossary_terms.yml     ← 用語集
  package.json
  Gemfile
```

この中で、執筆中にもっとも長く過ごすのが `contents/` です。ここに、原稿となる Markdown ファイルが収まっています。最初から入っているサンプルの章を開けば、Markdown の記述と、そこから生まれる紙面を見比べられます。ほかのディレクトリにも役割がありますが、今すべてを把握する必要はありません。詳しくは、次章 @ch-new で説明します。

### はじめてのビルド

雛形のまま、一度 PDF を生成します。原稿を書き始める前にビルドが通ることを確かめておくと、その後の変更点を追いやすくなります。

```bash
vs build
```

しばらく待つと、`mybook_v0.1.0.pdf` が生成され、自動的に開きます。まだ中身は雛形ですが、原稿から一冊の PDF ができるところまで、制作の流れがつながりました。ここから文章や図を置き換えるたびに、本は少しずつ自分のものになっていきます。

### 新しい章を作る

続いて、自分の原稿を書くための章を追加します。

```bash
vs create 10-awesome
```

`contents/10-awesome.md` と `images/10-awesome/` が生成されます。ファイルを開いて自由に書いたら、その章だけをビルドして確認します。

```bash
vs build 10-awesome
```

章を指定すると、書籍全体を組むより短い時間で結果を確認できます。執筆中は、原稿を書くことと章単位のビルドを往復します。すべての章が揃ったら、最後にもう一度 `vs build` を実行してください。表紙・目次・索引・奥付を含む、一冊の本として出力されます。

```bash
vs build
```

## コマンド早見表

Vivlio Starter には多くのコマンドがありますが、最初からすべてを使いこなす必要はありません。まずは、各ステップで中心となるコマンドだけを押さえておけば、執筆を始められます。

| ステップ | 主なコマンド | 内容 |
| :--- | :--- | :--- |
| (1) プロジェクト作成 | `vs new` | 雛形生成＋必要ツール自動セットアップ |
| (2) 執筆 | `vs create` | 章ファイルを追加 |
| | `vs build <章名>` | 章単位で素早く確認 |
| (3) 整える | `vs lint` | 文章を校正 |
| | `vs metrics` | 原稿の統計を確認 |
| (4) ビルド | `vs build` | 書籍全体をビルド（カバー未生成時は自動生成） |
| | `vs cover` | カバーを個別に生成・調整したい場合 |
| (5) 入稿・配布 | — | 生成済みファイルを提出 |

このほかにも、章の削除や番号の振り直し、索引の作成、PDF の圧縮などを行うコマンドがあります。必要になったときに、全体は `vs --help`、個々の使い方は `vs <コマンド> --help` で確認できます。コマンドを先に学び尽くすのではなく、本を作る過程で一つずつ使い方を身につければ十分です。

```bash
vs --help
vs build --help
```
