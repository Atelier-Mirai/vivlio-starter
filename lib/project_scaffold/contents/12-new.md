# 新規プロジェクトの作成

:::{.chapter-lead}
前章では、`vs new` で作った雛形から最初の PDF を出力しました。本章では、そのときに生成されたディレクトリや設定ファイルを、もう少し詳しく見ていきます。新しい本を作るときだけでなく、構成を確かめたくなったときにも参照できます。すぐに原稿を書き始めたい場合は、必要な箇所だけ拾い読みして @chapref:ch-markdown-tutorial へ進んでください。
:::

## 基本的な使い方

:::{.section-lead}
`vs new` にプロジェクト名を渡すと、書籍情報を順に尋ねます。答えた内容は、表紙や奥付にも使われます。
:::

```bash
vs new mybook
```

`mybook` はプロジェクト名で、ディレクトリ名と PDF のファイル名になります。英数字・ハイフン・アンダースコアで付けてください。実行すると、次の質問が順に表示されます。答えが決まっていない項目は、何も入力せずに Enter を押せば既定値を使えます。

:::{.output}
```text
Vivlio Starter へようこそ！新しい書籍プロジェクトを作成します。

書籍名を入力してください（例: はじめての技術書づくり）: はじめての技術書づくり
副題を入力してください（任意。Enter でスキップ）:
著者名を入力してください（原稿を書いた人。例: 早乙女 遙香）: 早乙女 遙香
発行者・サークル名を入力してください（本を世に出す主体。お一人なら著者と同じでも可。例: アトリヱ未來）: アトリヱ未來

以下の設定でプロジェクトを作成します。

  プロジェクト名: mybook
  書籍名:         はじめての技術書づくり
  副題:           （なし）
  著者:           早乙女 遙香
  発行者:         アトリヱ未來

❓ よろしいですか？ [Y/n]:
```
:::

最後に入力内容を確認し、Enter または `Y` を押すとプロジェクトが作成されます。修正したい項目があれば、`n` を入力していったん中断し、もう一度実行できます。

:::{.memo}
**著者と発行者の違い**

- **著者** — 原稿を書いた人（執筆者）。奥付の著者欄と著作権表示（&copy; …）に使われます。
- **発行者** — その本を世に出す主体（刊行の責任者）。商業出版なら出版社、同人・自費出版ならサークル名や屋号にあたります。

お一人で発行する場合は、著者と発行者が同じでも構いません。「著者＝本名・ペンネーム、発行者＝サークル名」のように使い分けることもできます。なお、印刷を依頼した印刷所は発行者とは別物です。
:::

## 生成されるプロジェクトの構成

`vs new mybook` を実行すると、原稿・画像・設定を分けて管理するために、次のディレクトリ構造が生成されます。ファイルの種類ごとに置き場所が決まっているため、原稿が増えても必要なものを探しやすくなります。

:::{.diagram}
```text
mybook/
  contents/       ← 原稿（Markdown ファイル）
  images/         ← 画像ファイル
  covers/         ← 表紙・裏表紙用の画像ファイル
  data/           ← 本文へ展開するデータ（YAML 形式）
  templates/      ← 章の雛形とデータ展開テンプレート
  sources/        ← 執筆資料や PDF ファイル置き場
  codes/          ← 本文へ取り込むサンプルコード
  stylesheets/    ← CSS スタイルシート
  config/         ← 各種設定ファイル
    book.yml      ← 書籍の設定
    catalog.yml   ← 章構成
    scaffold.lock ← 雛形マニフェスト（自動生成）
  README.md
  Gemfile
  package.json
  .gitignore
```
:::

入力した書籍名や著者名は、`config/book.yml` に書き込まれます。どの項目も、後から `book.yml` を編集して変更できます。

`config/scaffold.lock` は、プロジェクトへ展開した雛形の内容を記録する自動生成ファイルです。`vs upgrade` はこの記録と現在のファイルを比べ、著者が編集したファイルと、雛形のままのファイルを判別します。内容は手で編集せず、ほかの設定ファイルと一緒に Git へコミットしてください。

## 各ディレクトリの役割

:::{.section-lead}
ここでは、各ディレクトリの役割を順に説明します。日々の執筆でよく使うのは `contents/` と `images/` で、ほかは必要な機能に応じて触れる場所です。今の段階で細部まで把握するより、「原稿はここ、画像はここ、設定はここ」と置き場所を掴んでおけば十分です。各ディレクトリの `_README.md` と本書後半の各章にも、必要なときに確認できる説明があります。
:::

### contents/

:::{.text-table}
書籍の本文となる Markdown ファイルを置くディレクトリです。ファイル名には `NN-slug.md` 形式（例: `11-intro.md`）を使い、先頭の数字で、ファイル一覧での章の並び順を表します。番号と内容を表す短い名前が並ぶので、ファイル一覧から章の位置を把握できます。本に載せる順は、`config/catalog.yml` に書いた順です。

| 範囲 | 用途 |
|------|------|
| `00` | 前書き・はじめに |
| `01-89` | 通常の章 |
| `90-98` | 付録 |
| `99` | 後書き・おわりに |
:::

```bash
vs create 11-intro     # 章ファイルと画像ディレクトリを生成
vs delete 11-intro     # 章を削除
vs rename 11 12        # 章番号を変更
vs renumber            # 章番号を一括で整列
```

ビルドの対象になるのは、`config/catalog.yml` に登録された章だけです。`catalog.yml` は本の**目次（章立て）を定義するファイル**で、どのファイルを、どの順番で、どの部に配置するかを記録します。登録していない Markdown は、ビルドの対象になりません。そのため、構想中の下書きや一時的に外した原稿も、`contents/` に残しておけます。

ファイルは `PREFACE`（前書き）・`CHAPTERS`（本文）・`APPENDICES`（付録）・`POSTFACE`（後書き）の四つに分かれ、各章は拡張子 `.md` を省いたファイル名で登録します。`CHAPTERS` の下へ末尾に半角コロン `:` を付けたタイトルを置くと、その配下の章が一つの「部」にまとまり、部扉ページも生成されます。

```yaml:config/catalog.yml
PREFACE:
  - 00-preface

CHAPTERS:
  - 第一部 はじめる:        # 末尾の「:」で「部」になる
      - 11-workflow
      - 12-new
  - 第二部 書く:
      - 21-markdown-tutorial

APPENDICES:
  - 93-install

POSTFACE:
  - 99-postface
```

通常は、`catalog.yml` を手で編集する必要はありません。`vs create`・`vs delete`・`vs rename` で章を操作すると、対応する項目も更新されます。章の順番を細かく入れ替えるときや、部の名称を変更するときは、構造を確認しながら直接編集できます。

章の操作は @chapref:ch-chapter-management で、`catalog.yml` の書き方は @ch-book-yml の章の @pageref:catalog-yml で詳しく説明します。

### images/

書籍内で使う画像ファイルを置くディレクトリです。画像は章ごとのサブディレクトリに分けて管理します。`vs create` で章を作成すると対応する画像ディレクトリも生成されるため、原稿と図版の関係を保ったまま整理できます。

画像の形式は PNG・JPG・WebP・SVG のどれでも構いません。`vs build` が PDF・EPUB・Kindle それぞれに適した形式へ変換して使います。変換した画像は作業用のフォルダ（`.cache/`）に作られるので、`images/` に置いた画像が書き換えられることはありません。画像の置き方と原稿での書き方は、@chapref:ch-figures で詳しく説明します。

### covers/

書籍の表紙・裏表紙に使う画像ファイルを置くディレクトリです。設定に基づくカバー画像は、`vs cover` または `vs build` の実行時に生成されます。

`config/book.yml` の `book.cover` でテーマ名を指定します。既定は `light` で、同梱のテンプレートに書名と著者名が入ります。`dark` も選べます。著者が用意した画像（PNG・JPEG・WebP）や SVG を使う場合は、`covers/frontcover_<theme>.png` などを配置してください。画像の雛形は、判型ごとに `covers/templates/` にあります。

```bash
vs cover    # book.yml の設定に従ってカバー画像を生成
```

テーマの選び方や、著者が用意した画像の使い方は @chapref:ch-cover で詳しく説明します。

### data/

原稿内へ展開する外部データを、YAML 形式で置くディレクトリです。同じ形の書誌情報や製品情報を何件も掲載するときに、QueryStream 記法と組み合わせて使います。本文へ同じ書式を繰り返し書かず、データと見せ方を分けて管理できます。

```markdown
= books                    # 全件展開
= books | tags=ruby        # タグで絞り込み
= books | -year | 3        # 年度降順・3件
```

データの展開テンプレートは `templates/` ディレクトリに配置します（`data/books.yml` → `templates/_book.md`）。記法とデータファイルの書き方は @chapref:ch-querystream で詳しく説明します。

### templates/

章ファイルの雛形と、QueryStream のデータ展開テンプレートを置くディレクトリです。`vs create` で章を作ると、章番号の範囲に応じて `chapter.md`・`preface.md`・`appendix.md`・`postface.md` のいずれかが選ばれます。テンプレート内の `{{TITLE}}` は、章のスラッグへ置き換えられます。

`markdown_snippet.md` は章の雛形ではなく、利用できる記法を実例とともに並べた見本です。書き方を確かめたいときに開き、必要な部分を原稿へコピーして使えます。

章テンプレートを自分の執筆手順に合わせる方法は @chapref:ch-chapter-management で、QueryStream テンプレートの仕組みは @chapref:ch-querystream で詳しく扱います。

### sources/

執筆の参考資料や素材を置くためのディレクトリです。ここに置いたファイルはビルドされないので、読者へ配布する原稿と手元の資料を分けて保管できます。`vs pdf:read` で PDF から Markdown を抽出するときには、入力ファイルの置き場所としても使えます。

```bash
vs pdf:read reference        # sources/reference.pdf を自動探索
```

使い方は @chapref:ch-pdf-read で詳しく説明します。

### codes/

書籍に掲載するサンプルコードを置くディレクトリです。原稿へコードを貼り付ける代わりに、`include` 記法でファイルを参照できます。実行するコードと掲載するコードを一つのファイルに保てるため、修正の反映漏れを防げます。

`codes/sample.rb` を全文取り込むには次のように書きます。

````markdown
```include:sample.rb```
````

`codes/ruby/hello.rb` の 10〜20 行目だけを取り込むこともできます。

````markdown
```include:ruby/hello.rb:10-20```
````

書き方の詳細は @ch-extensions の章の @pageref:code-and-output で解説します。

### stylesheets/

書籍のレイアウトとデザインを定義する CSS ファイルを置くディレクトリです。テーマカラーや扉絵などの基本設定は、`config/book.yml` の `theme` セクションで行います。独自の調整は `custom.css` に記述してください。ほかの CSS は `vs upgrade` で新しい雛形へ更新されるので、役割を分けておくと、更新してもカスタマイズが残ります。`custom.css` の書き方は @ch-utility の章の @pageref:custom-css で詳しく説明します。

### config/

書籍プロジェクトの設定ファイルをまとめるディレクトリです。書籍名から出力形式、章の順番、校正ルールまで、本の作り方を決める情報がここに集まっています。主なファイルは次のとおりです。詳しい項目は `config/_README.md` で確認できます。

| ファイル | 役割 |
|----------|------|
| `book.yml` | 書籍のメタデータ・ビルド設定（最重要） |
| `catalog.yml` | ビルド対象の章リスト（章の順序を定義） |
| `page_presets.yml` | 用紙サイズ等のプリセット定義 |
| `index_glossary_terms.yml` | 索引・用語集の登録済み用語 |
| `.textlintrc.yml` | textlint の校正ルール設定 |

`book.yml` と `catalog.yml` の項目は @chapref:ch-book-yml で、索引・用語集は @chapref:ch-index-glossary で、校正ルールは @chapref:ch-lint で詳しく説明します。

## 作成後の次のステップ

プロジェクトを作成すると、続けて `vs doctor --fix` が実行されます。npm パッケージのインストールなど、原稿をビルドするために必要な環境がここでセットアップされます。`vs new` が終わった時点で、すぐに `vs build` で PDF を生成できます。

`vs doctor --fix` が完了しなかった場合も、作成済みのプロジェクトは残り、警告が表示されます。警告のとおり、プロジェクトの中で同じコマンドを実行すると、足りないツールのインストールをやり直します。

```bash
cd mybook
vs doctor --fix
```

それでも揃わないときは、`vs doctor` で足りないツールを表示し、@ch-install の章の @pageref:install-troubleshooting で解決策を探してください。

書籍名や判型、出力形式などは、`config/book.yml` を編集して変えます。キーの説明と今の値は、`vs config:book` で確認できます。
